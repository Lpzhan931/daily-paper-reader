## 摘要
基于大语言模型（LLM）的智能体应用通常具有较高的响应时间。推测性解码是一种在不影响生成质量的前提下提高LLM智能体推理效率的可行方案。然而，最先进的推测性解码算法在大批量数据下会表现出显著的性能下降，限制了它们在真实智能体应用中的部署效果。在本工作中，我们首先对面向LLM智能体的推测性解码进行了系统分析，并确定了导致加速效果退化的两个主要因素：推测token的高拒绝率和动态token预算的利用不足。基于这些观察，我们提出了AgentSpec，一种针对现有LLM智能体方法局限性的推测性解码算法。AgentSpec采用了结构隔离的草稿生成方法，将推测限制在智能体工作流的语义连贯片段内，减少无关语义路径的草稿生成，从而实现了极低的拒绝率。此外，AgentSpec采用冗余感知的预算分配策略，利用智能体级别的信息，在智能体推理过程中更好地利用动态空闲token预算。我们在vLLM中基于五种不同的工作负载和来自四个不同LLM家族的四种模型对AgentSpec进行了实现和评估。我们的结果证明了AgentSpec相对于最先进方法的优越性。

## Abstract
Large language model (LLM)-based agent applications often incur high response time. Speculative decoding is a promising solution to improve the inference efficiency of LLM agents without impacting generation quality. However, state-of-the-art speculative decoding algorithms exhibit substantial speed degradation under large batch sizes, limiting their effectiveness to deploy in real-world agent applications. In this work, we first present a systematic analysis of speculative decoding for LLM agents and identify two dominant factors of speedup degradation: high rejection rate of speculative tokens, and under-utilization of dynamic token budgets.B ased on these observations, we propose AgentSpec, a speculative decoding algorithm that addresses the limitations of existing methods for LLM agents. AgentSpec incorporates structure-isolated drafting that constrains speculation to semantically coherent segments of the agent workflow, reducing the drafts of irrelevant semantic paths and achieving an extremely low rejection rate. Moreover, AgentSpec adopts redundancy-aware budget allocation that exploits agent-level information to better utilize the dynamically-free token budget during the agent inference. We implement and evaluate AgentSpec on five different workloads and four different models from four different LLM families in vLLM. Our results demonstrate the superiority of AgentSpec over state-of-the-arts.

## 2. 论文提出的方法论

AgentSpec 是**无草稿模型（draft-model-free）**的推测性解码算法，包含两个核心组件：

### 2.1 结构隔离草稿（Structure-Isolated Drafting）

核心思想：智能体应用中，同一用户查询往往跨多个请求，且属于不同语义块（如推理、工具执行、结果解释）。重复 token 段绝大多数出现在**同一用户查询的同一语义块内**，跨块/跨查询的重复很少。因此，将投机草稿限制在语义连贯的历史片段中可以显著降低拒绝率。

关键技术细节：
- 智能体应用需为每个生成请求提供语义结构标识符 `Si = {ai, qi, Bi}`，其中 `ai` 是智能体应用 ID，`qi` 是用户查询索引，`Bi` 是语义块列表（由开始/结束字符串标签对定义）。
- 为应对子词 tokenization 导致的 token-字符串边界不对齐问题，AgentSpec 维护一个**缓存的 token 到字符串映射** `M`，类似 XGrammar 的设计，高效在线转换 token 为字符串而无需调用 tokenizer。
- 采用轻量级**字符串下推自动机（PDA）** `P` 增量跟踪当前语义块；每个语义块维护独立的**结构隔离缓存**，仅从匹配的语义块中检索草稿候选。
- 效果：如表 1 所示，AgentSpec 将拒绝率降至 26.4%，比 EAGLE-3 降低约 50%。

### 2.2 冗余感知预算分配（Redundancy-aware Budget Allocation）

核心思想：在智能体工作负载中，请求与历史生成的重复程度（冗余度）越高，草稿被接受的可能性越大。基于此，论文引入冗余度评分来指导 token 预算的分配。

关键公式：
- **冗余度评分**：
  ```
  g(c, n) = (c/n) · p(n)
  p(n) = gmin + (1 − gmin)(1 − e^(1−n))
  ```
  其中 n 为从同一语义块和查询中检索到的候选延续数量，c 为赞同最频繁前缀的延续数量，c/n 衡量候选一致性，p(n) 为饱和项，用于在历史支持不足时降低置信度，gmin 为最小置信度超参数。
- **批量 token 预算**：`Bt = ⌊α·bz⌋`，其中 bz 为批大小，α 控制整体推测预算。
- **每请求草稿长度分配**：
  ```
  Li = max( |CT_i|, Bt · gi / Σ gj )
  ```
  优先为高冗余请求分配更多 token，同时保证每个请求至少草稿其最自信的前缀。

算法流程（文字说明）：
1. 对每个新生成的 token，通过缓存映射转换为字符串，增量更新 PDA 以识别当前语义块。
2. 从对应的结构隔离缓存中检索候选历史延续，形成草稿候选集合。
3. 对批次中每个请求计算冗余度评分。
4. 根据冗余度评分分配每请求的草稿长度。
5. 提交草稿进行批量验证，接受与目标模型分布一致的 token。

## 6. 论文的主要结论与发现

1. **AgentSpec 在所有智能体工作负载和所有 4 个模型上一致优于 EAGLE-3、NGram、SuffixDecoding**，最高相对最优基线提升 104% 的 goodput。
2. **现有推测性解码算法在智能体大批量推理下严重退化**，甚至在 batch size 超过 32 后普遍慢于自回归解码；而 **AgentSpec 始终快于自回归解码**，最高 2.02× 加速（GPT-OSS-20B 上的 Code Generation）。
3. AgentSpec 在**非智能体基准 Spec-Bench** 上也有效：整体 1.14× 加速，检索增强子集最高 1.40×。
4. AgentSpec 在 MiMo-7B 上**超越 MTP**（1.29× vs 0.73× speedup），说明即使面对联合训练的专用草稿模块，AgentSpec 依然有优势。
5. **结构隔离草稿是主要贡献者**（单独带来 1.25×/1.05×），冗余感知预算分配带来额外增益（1.30×/1.07×），两者结合最佳。
6. AgentSpec 将拒绝率降至 26.4%（相比 EAGLE-3 的 53.3%、NGram 的 88.7%、SuffixDecoding 的 65.9%），并将验证时间降低约 21%。
7. AgentSpec 在大批量和非思考模式下依然保持加速（w/o think 下最高 2.5×+），但加速幅度会随语义结构缺失而有所下降。

## 7. 优点

- **问题定位准确**：通过理论建模和系统分析，将大批量退化归因于拒绝率和 token 预算利用两个具体可量化的因素，逻辑清晰。

## 8. 不足与局限

- **依赖语义结构元数据**：结构隔离草稿需要智能体应用显式提供语义块边界信息（structure 字段），尽管 AgentSpec(N)（无结构变体）仍有提升，但要求应用方适配接口会增加实际集成成本。若工作负载中不暴露语义结构，或结构标签设计不当，加速可能受限。
- **加速幅度依赖重复模式**：在没有足够重复历史（如一次性任务或高度非重复的生成）时，草稿质量会下降，加速效果有限（如 Spec-Bench 中部分子集仅 1.01×）。
- **推理初期可能无草稿可用**：对于每个新查询的第一个请求，历史缓存为空，结构隔离草稿无法提供候选，此时退化为自回归解码。
- **实验细节不足**：
  - GPU 数量与总算力未报告，无法评估资源成本；
  - 每个配置仅报告均值，无方差/置信区间，统计显著性未验证；
  - MTP 仅一个模型对比，泛化结论有限；
  - H100 实验仅一个模型覆盖。
- **批大小上限实际是 256**：虽覆盖了典型服务配置，但未验证更大批量（如 512、1024）下表现，论文中分析指出 FFN 在 batch 256 时已接近算术强度拐点，更大批次的验证缺失。
- **AgentSpec 的预算分配假设冗余度可预测接受率**：该假设基于 Qwen 模型的分析数据，在其他类型模型或高度非标准化的智能体工作流上是否依然成立未充分验证。
- **方法适用边界**：非对话类的"无结构"智能体任务（如纯自由格式工具输出）可能需要对语义块定义做额外设计；论文虽提供了无结构变体，但其效果仍依赖重复模式存量。
