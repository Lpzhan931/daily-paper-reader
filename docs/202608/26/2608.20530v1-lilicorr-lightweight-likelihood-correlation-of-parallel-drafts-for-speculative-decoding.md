## 摘要
推测解码通过草拟未来标记并由目标模型并行验证，从而加速语言模型推理。像DFlash这样的扩散式块头是一个有吸引力的草稿模型，可在一次前向传播中预测整个未来标记块。然而，它是在逐位置边际分布而非联合块分布上训练的，因此其生成的标记在个体上看似合理，但联合起来却不连贯。我们提出LiLiCorr——一个轻量级的基于似然的模型，用于关联草稿模型已生成的逐位置边际分布。它保留每个位置的前k个标记作为候选，并联合处理它们，为每个候选生成入向量和出向量。当较前候选的出向量与较后候选的入向量具有高余弦相似度时，相邻候选对即匹配。这些匹配捕获了块的整体结构，而无需具体化完整的联合分布。一次轻量级网络传递即可生成所有向量，随后成对分数作为批量矩阵操作并行计算，仅剩一次廉价的贪心遍历需串行进行。我们进一步将草稿模型与LiLiCorr协同训练，使其学会提出可关联为更长接受序列的候选。与原始DFlash草稿模型相比，LiLiCorr将每个基准的接受长度提高了9%至19%，而其评分头仅占每块延迟的约2.8%。与DFlash及另外两种在草稿阶段同样恢复连贯性的方法相比，LiLiCorr在72种设置中的70种中实现了最高吞吐量：在贪婪解码和温度1解码下，涵盖两个目标大小的九个基准，以及跨越六种并发度、两种输入长度和三个熵层的吞吐量扫描，所有系统均在公共服务栈上得到同等优化。将LiLiCorr扩展至比训练输入长一个数量级的输入时，这一优势得以保持。

## Abstract
Speculative decoding accelerates language-model inference by drafting future tokens that the target model verifies in parallel. A diffusion-style block head such as DFlash is an attractive drafter, predicting an entire block of future tokens in one forward pass. However, it is trained on per-position marginals rather than the joint block distribution, so the tokens it emits are individually plausible yet jointly incoherent. We introduce LiLiCorr, a Lightweight Likelihood-based model that Correlates the per-position marginal distributions a drafter already produces. It keeps the top-k tokens at each position as candidates and processes them jointly, producing for each an in and an out vector. A pair of adjacent candidates matches when the earlier one's out vector has high cosine similarity with the later one's in vector. These matches capture the block's joint structure without ever materializing the full joint distribution. One lightweight network pass produces all the vectors, and the pairwise scores are then computed in parallel as batched matrix operations, leaving only a cheap greedy walk sequential. We further co-train the drafter with LiLiCorr, so it learns to propose candidates that correlate into longer accepted sequences. Over the vanilla DFlash drafter, LiLiCorr raises acceptance length on every benchmark by 9 to 19%, while its scoring head accounts for about 2.8% of the per-block latency. Against DFlash and two concurrent methods that also restore coherence at draft time, LiLiCorr delivers the highest throughput in 70 of 72 settings: nine benchmarks at two target sizes under greedy and temperature-one decoding, and a throughput sweep over six concurrencies, two input lengths and three entropy tiers, with all systems equally optimized on a common serving stack. Extending LiLiCorr to inputs an order of magnitude longer than it was trained on preserves that lead.

# LiLiCorr 论文总结

## 1. 核心问题与研究动机

推测解码（Speculative Decoding）通过小型草稿模型生成候选 token 块、再由目标大模型并行验证，从而加速自回归推理。由于解码是显存带宽受限的，一次验证多个 token 的额外代价远小于逐个生成。

- **关键矛盾**：扩散式块草稿器（如 DFlash）虽可一次前向预测整块 token，但其训练目标是**逐位置边际分布**（per-position marginals），而非整块的联合分布。这导致模型在每个 slot 上单独看都很合理，但拼成整块后**语义不连贯**（marginals problem）。
- **组合爆炸**：联合分布有 V^B 种可能，显式建模不可行；已有方案（迭代重掩码、树重排序、逐 slot 自回归修正）要么增加额外的草稿器前向次数，要么把相关性负担转嫁给目标模型，都抵消了并行草稿的加速收益。
- **本文目标**：在**不增加额外网络前向**的前提下，以极低开销从逐位置边际分布中恢复连贯的草稿块，从而提升接受长度（acceptance length）与吞吐。

## 2. 方法论：LiLiCorr

### 2.1 总体思路

在 DFlash 的每个 slot 保留 **top-K 候选 token**，构成 (B−1)×K 的候选格（lattice）；用一个轻量网络为每个候选生成两个向量（in 向量与 out 向量），用**相邻候选间的余弦相似度**作为匹配分数，捕获块的局部联合结构；解码时按贪心规则从左到右提交 token。

### 2.2 候选表示（Node）

每个候选节点由四项等宽向量求和构成：
- 目标模型（冻结）的输入 token 嵌入（投影降维）；
- 该 slot 的 DFlash 隐状态（投影，K 个候选共享）；
- 一个小 MLP，输入 5 个标量置信度特征（log 概率、全词表概率、与 top-1 的 log 概率差、归一化排名、是否为该 slot 最优）；
- 可学习的 slot 位置编码与候选排名编码。

### 2.3 打分网络

- 两层双向 Transformer 处理整个候选格（宽度 1024、8 头、FFN 2048、RMSNorm + SiLU），全部候选之间相互交换信息；
- 每个候选再与目标模型上一个已验证 token 的隐状态做融合（拼接 + 逐元素乘积 + 线性映射）；
- 每个候选输出 de=1024 维、归一化的 out 向量 o 和 in 向量 i；锚点（slot 0）单独输出一个 out 向量。

### 2.4 配对分数

相邻 slot 的匹配分数定义为：

```
φ(s, k, k') = σ · cos(o_{s,k}, i_{s+1,k'})
```

σ 为固定缩放常数（8.0）。配对只看相邻 slot，但向量本身由整个格的自注意力计算而来，因此非相邻证据也会影响配对判断。

### 2.5 训练目标

- **Oracle 前缀监督**：仅当某 slot 的 ground-truth token 出现在 top-K 候选、且其前所有 slot 均被覆盖时，才施加监督信号，与"前缀接受"的推理结构对齐。
- **逐位置交叉熵**（局部链式分解）：

```
P(c_s | c_{s-1}) = softmax_k(z_s[k]),  z_s[k] = φ(s−1, c_{s−1}, k)
```

- **目标加权干扰项惩罚**（distractor penalty）：

```
Ω_s = Σ_k P_θ(k) · ReLU(log q_{gs} − log q_k)
```

利用目标模型的 logits 作为候选兼容性的分级度量，将"目标模型低分、但容易干扰决策"的竞争者往下压；与交叉熵形成互补梯度。

- **联合训练**：损失为 L = L_DFlash + γ[L_CE + λ L_dist]，使草稿器学会提出更容易被关联成长序列的候选集（top-K 选择不可微，但梯度可经候选的 log 概率与隐状态回传）。

### 2.6 解码流程

- **并行阶段**：一次网络前向生成所有 in/out 向量，所有相邻 slot 对的 K×K 配对分数化为**批量矩阵乘法**并行计算；
- **串行阶段**：仅剩贪心 argmax 游走，逐位置选择与已提交前驱匹配分数最高的候选，不触碰任何网络权重；
- 附录对比了用 Viterbi 动态规划求全局最优路径的方案，结果显示全局最优在推测解码下反而更差（贪心平均高 2.44% 接受长度）。

## 4. 主要结果与分析

### 4.1 端到端加速效果

- LiLiCorr 在所有 9 个基准上一致优于 DFlash 及其他扩散式草稿方法，平均接受长度相比 DFlash 提升约 **0.5~1 个 token**，在数学与代码任务上尤其明显。
- 在 Qwen3-8B 上，LiLiCorr 相对自回归解码实现约 **2.2~2.8×** 的吞吐加速；相对标准投机采样提升约 **15~25%**；相对 DFlash 提升约 **8~12%**，同时额外前向次数与 DFlash 相同（每轮仅一次草稿前向 + 一次模型验证）。
- 在更强的 Qwen3-8B 上，当目标模型推理模式关闭时，LiLiCorr 依然保持显著优势，说明其收益不依赖模型内部推理链标注。

### 4.2 接受长度统计

- 按草稿块长度（B 从 3 到 8）分解，LiLiCorr 在高位 slot 的接受率显著高于 DFlash。例如在 B=5 时，第 4、5 个 slot 的接受率约为 DFlash 的 **1.4~1.8×**，表明候选格上的配对相关性确实修复了 “marginals problem”。
- 贪心游走相比 Viterbi 全局最优路径平均高出 2.44% 接受长度，说明在推测解码框架下，局部贪心选择的“承诺”（commitment）行为更有利于后续接受率。

### 4.3 消融实验

- **移除 in/out 向量配对（改用 logit 点积）**：接受长度下降约 6~10%，证明学习到的语义向量配对优于原始 logits 匹配。
- **移除目标模型上下文融合**：在接受长度上下降约 3~5%，说明融合已验证 token 的隐状态有助于消歧。
- **移除 distractor penalty**：在 GSM8K 与 HumanEval 上接受长度分别下降 0.32 与 0.27 个 token，同时验证延迟略有上升；说明该惩罚项通过压低“误导性竞争项”提升了解码稳定性。
- **降低 K 值**：K 从 16 降到 8，接受长度下降约 0.2~0.3 token，但内存与计算开销也相应减少；K=16 是速度与质量的较好平衡点。

## 5. 结论

LiLiCorr 提出了一种**轻量级、无额外前向的联合候选选择机制**，用极小的打分网络在扩散式草稿器生成的 top-K 格上建立相邻 token 之间的语义关联，从而在不增加草稿器前向次数的前提下显著提升草稿块的整体连贯性。该方法与逐位置的自回归解码兼容，贪心解码即可获得稳定收益，并在多个代码、数学与对话基准上验证了其相对于现有扩散式推测解码方法的优越性。其核心思想——用“局部配对 + 全局注意力”来逼近不可分解的联合分布——也为未来高效推测解码设计提供了新思路。
