## 摘要
在边缘设备上部署大语言模型日益受到模型规模与可用内存之间不断扩大的差距的限制。现有方法如量化、小型化模型和卸载可以提升有效内存上限，但它们仍假设模型可以压缩或分片以适应某个预算。我们针对更困难的模型超出内存场景，即整个执行过程中模型始终大于常驻内存，存储成为关键路径上权重的活跃来源。我们观察到自回归解码过程中的MLP活动具有强烈的时间局部性：大约82-85%的活跃神经元会从当前token延续到下一个token。这意味着当前token所需的大部分稀疏权重已经常驻，只有新需要的行必须从存储中获取。我们提出NeuroPrefetcher，一个利用这一特性的存储后盾大语言模型推理系统，通过预测性增量预取实现。在第0层之后，单个GPU驻留预测器（占用基础模型参数的2.86%）在前向传播中预测所有下游MLP层的稀疏活动。运行时将这些预测与GPU驻留缓冲区进行比较，仅对新增行发出应用调度的NVMe读取，将反应式操作系统按需分页替换为显式的、模型感知的权重移动。在真实统一内存边缘硬件上，NeuroPrefetcher在受限内存预算下相对llama.cpp实现了7.9-12.0倍的加速。

## Abstract
Deploying large language models on edge devices is increasingly limited by a widening gap between model size and available memory. Existing approaches such as quantization, smaller models, and offloading can raise the effective memory limit, but they still assume that the model can be compressed or partitioned to fit within some budget. We target the harder model-exceeds-memory setting, in which the model remains larger than resident memory throughout execution and storage becomes an active source of weights on the critical path. We observe that MLP activity during autoregressive decoding has strong temporal locality: approximately 82-85% of active neurons persist from one token to the next. This means that most sparse weights needed for the current token are already resident, and only the newly needed rows must be fetched from storage. We present NeuroPrefetcher, a storage-backed LLM inference system that exploits this property through predictive delta prefetching. After layer 0, a single GPU-resident predictor, occupying 2.86% of base model parameters, predicts sparse activity for all downstream MLP layers in one forward pass. The runtime compares these predictions against resident GPU buffers and issues application-scheduled NVMe reads only for incoming delta rows, replacing reactive operating-system demand paging with explicit, model-aware weight movement. On real unified-memory edge hardware, NeuroPrefetcher achieves 7.9-12.0x speedup over llama.cpp across constrained memory budgets.

- **整体含义**：本文提出 NeuroPrefetcher，通过**预测性增量预取（predictive delta prefetching）** 将存储流量从“反应式整页搬运”转变为“应用调度的稀疏行增量读取”，在统一内存边缘硬件上实现 7.9–12.0× 相对 llama.cpp 的端到端加速，显著提升模型超内存场景下的推理性能。

## 2. 方法论：核心思想与关键技术

### 2.1 系统架构
- 将模型 N 层 transformer 划分为两部分：
  - **密集前缀（dense prefix）**：前 d 层 MLP 权重完全常驻 GPU 内存；
  - **稀疏后缀（sparse suffix）**：剩余 N−d 层 MLP 以固定容量（K max 行）的活跃行缓冲区运行，完整稀疏权重存于 NVMe。
- 其他常驻组件：token embedding、语言模型头、最后归一化、所有层注意力投影、LayerNorm 参数、共享预测器、质心表。
- 每 token 执行流程：
  1. 第 0 层密集执行，提取特征；
  2. 共享预测器一次性输出第 1–31 层 gate 和 up 投影的质心 ID，得到预测活跃神经元集合；
  3. 将预测集合与驻留缓冲区比较，得到 delta（新增行）；
  4. 后台线程通过 io_uring + O_DIRECT 发起批量 NVMe 读取，数据落到 pinned staging buffer；
  5. CUDA scatter 内核将各行写入对应层 GPU 缓冲区，与密集前缀计算重叠执行稀疏后缀。

### 2.2 离线稀疏质心准备
- **激活阈值化**：对每一层收集激活值，按 α 百分位阈值（公式 1）将低幅度神经元置零，强制稀疏。注意力块不变。
- **聚类**：将高维二值掩码聚类为 K 个稀疏二值质心（质心通过聚合簇成员并剪枝回目标稀疏度构造）。运行时只需预测质心 ID，而非逐神经元判断。

### 2.3 共享激活预测器
- 输入特征（来自第 0 层）：token embedding、注意力前 LayerNorm、注意力头 sketch、注意力后 RMS norm、第 0 层 gate 激活对应的质心 ID。
- 架构：四个语义特征各自经过投影块（线性+LayerNorm+SiLU+Dropout）得到 512 维嵌入；质心 ID 经嵌入和投影网络；两者拼接后进入残差 MLP 主干；最后两组 31 个线性头分别预测各层 gate/up 质心 logits。
- 参数量：206.8M（占基础模型 2.86%，FP16 下 414 MB），其中输出头占大部分。
- 训练：交叉熵损失（L=L_gate^CE + L_up^CE），AdamW，batch 2048，梯度裁剪 1.0，K=512 个质心。
- 关键优势：仅在第 0 层之后一次前向传播即可获得全部下游层的稀疏 I/O 计划（对比 DejaVu 等逐层预测器，无法提供存储预取所需的提前量）。

### 2.4 预测性增量预取（Delta Prefetching）
- 每层活跃集合 A_t^(l) 由 gate 与 up 质心掩码的交集确定（SwiGLU 神经元仅在 gate 和 up 均激活时参与）。
- 计算集合差：
  - D_in^(l) = A_t^(l) \ A_{t-1}^(l)（需从 NVMe 获取）；
  - D_out^(l) = A_{t-1}^(l) \ A_t^(l)（释放缓冲区槽位）。
- 每层使用槽位映射 S^(l) 跟踪神经元驻留位置；首 token 冷启动加载完整预测活跃集，之后仅更新 delta。

### 2.5 I/O 路径
- 离线重排权重为“神经元连续记录”：每个记录（24.5 KiB）包含某中间神经元的 gate、up、down^T 三行，单次存储读取即可获得全部投影；相邻神经元 ID 聚合为连续读范围。
- 运行时用 io_uring（队列深度 256）+ O_DIRECT 提交批量读取。
- 统一内存平台（Jetson）上，直接 I/O 可能绕过 CPU 缓存一致性导致 CUDA 读到过期数据，因此使用 cudaHostRegisterMapped 的 pinned staging buffer，CUDA scatter 内核通过一致映射路径直接读取记录并去交织写入三块投影专用缓冲。
- 若 token delta 超过 staging 容量，则分块提交，不终止执行。

### 2.6 内存自适应密集/稀疏划分
- 通过自动扫描选择最大可驻留的密集前缀 d*（一次校准）。d 较小时存储流量大、吞吐低；d* 处吞吐峰值；超过 d* 后稀疏层失去缓冲区回退为整层 NVMe 读取，吞吐骤降。

## 6. 主要结论与发现

- **能力边界**：在 14 GiB 内存上限、11.9 GiB CUDA 可用时，20 个系统中仅 4 个可运行（NeuroPrefetcher、llama.cpp、FlexGen、Ollama）；12 个因分配失败或统一内存架构不匹配而无法生成，4 个缺少 ARM/JetPack 版本。NeuroPrefetcher 是最快的可运行系统（3.22 tok/s vs llama.cpp 0.34 tok/s）。
- **吞吐提升**：在模型超内存区间（9.0–13.2 GiB CUDA），NeuroPrefetcher 相对 llama.cpp 实现 7.9–12.0× 加速，最高 3.7 tok/s；内存交叉点（模型可完全驻留）后优势缩小至 1.1–1.2×，符合设计目标。
- **I/O 缩减**：62% 稀疏度下，82–85% 的稀疏后缀行被跨 token 复用，每 token 仅需读取 15–18% 新增行；内存差距近 6 GiB 时，每 token NVMe 读取量仅从 103 MiB 增至不到 1 GiB，未退化为整层读取。
- **延迟构成**：NVMe I/O 占每 token 延迟的 80–87%（即便经过 delta 预取），计算与预测器开销次要；预测器不是瓶颈。
- **模型质量**：预测器质心选择准确率约 99%；质量损失主要来自聚类而非预测错误。Mistral-7B 在 d=20、31% 稀疏度下困惑度接近密集基线；HellaSwag 保留率在 d=20 时 Mistral 约 95–96%，Llama-3-8B 约 92–93%，且无需按任务重训练即可迁移到 HellaSwag 领域，表明模式泛化性良好。

## 7. 优点

- **问题定位准确**：聚焦现有方法未覆盖的“模型持续超内存”真实场景，而非继续沿用“压缩至可驻留”的假设。
- **核心洞察新颖**：利用 MLP 活跃神经元跨 token 的时间局部性（82–85% 复用），将稀疏性从“计算优化”拓展为“I/O 流量优化”，提出 delta 预取机制。
- **预测器设计高效**：单次前向传播预测所有下游层稀疏 I/O 计划（而非逐层预测），提前量充分；参数量仅占 2.86%，且复杂度不随 MLP 中间维度增长。
- **工程实现完整**：处理了统一内存平台的一致性陷阱（staging + cudaHostRegisterMapped）、连续权重布局、io_uring 异步批量 I/O、CUDA scatter 去交织等实际问题。
- **评估全面且诚实**：包含 20 系统的能力研究、多种内存预算、稀疏度与密集前缀的消融扫描、延迟分解和跨模型质量验证；明确指出性能优势仅在模型超内存区间显著，交叉点后减弱，未过度声称。
- **可部署性**：除统一内存 staging 外，预测器、delta runtime、权重布局和异步 I/O 均与平台无关，易迁移到其他架构。

## 8. 不足与局限

- **实验覆盖有限**：仅测试了 Mistral-7B 与 Llama-3-8B 两种模型，且质量任务只有 WikiText-2 困惑度和 HellaSwag；未涉及量化版本、更大模型（如 13B/70B）或更长上下文场景。
- **I/O 仍是瓶颈**：延迟分解显示 NVMe 读取占 80–87%，即使 delta 预取后存储流量依然主导；未来需要更强预取流水线、更激进的读合并、量化稀疏行格式和更深的计算/存储重叠。
- **冷启动与异常 delta 代价未充分评估**：首 token 需加载完整活跃集，超过 staging 容量时大 delta 会降低重叠度，论文未给出这些情况的详细性能影响。
- **对比基线有限**：llama.cpp 是唯一直接数值对比的强基线；其他稀疏推理系统（如 PowerInfer、DejaVu、LLM in a Flash）因平台不可用被归入“无法运行”，缺乏同条件下与同类稀疏方法的直接吞吐/质量对照，可能低估或高估相对优势。
