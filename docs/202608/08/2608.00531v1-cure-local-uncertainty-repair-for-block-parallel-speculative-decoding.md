## 摘要
推测解码通过将草稿生成与目标验证交错进行，缓解了自回归大型语言模型（LLM）中顺序生成的延迟。然而，现有的并行草稿后端在长距离生成中往往面临精度快速下降的问题，导致验证期间拒绝率较高，并使得端到端加速效果不佳。我们观察到，草稿错误并非均匀分布，而通常源于局部高不确定性令牌，这些令牌会破坏下游生成轨迹的稳定性。基于这种令牌错误模式，我们提出了CURE，一种预算感知的动态修复树，旨在在不引入过高树验证开销的情况下，修复不确定性焦点处的错误。具体而言，我们的方法利用预测置信度边际在块并行草稿中动态定位候选错误令牌，仅在这些脆弱节点上扩展有界修复路径，并采用一种新颖的修复重同步机制，在验证后重新对齐草稿状态。在代码生成基准测试（HumanEval、MBPP 和 LiveCodeBench-lite）以及数学推理基准测试（GSM8K）上的评估表明，与无修复的并行基线相比，CURE 将平均接受长度提高了 4.2-7.5%，相对于仅目标解码实现了 2.66-3.49 倍的端到端加速。此外，我们提供了一个即插即用的修复模块，与标准并行草稿框架兼容。我们还刻画了草稿计算与验证效率之间的权衡。

## Abstract
Speculative decoding mitigates the latency of sequential generation in autoregressive Large Language Models (LLMs) by interleaving draft generation with target verification. However, existing parallel drafting backends often suffer from rapid accuracy degradation over long horizons, leading to high rejection rates during verification and suboptimal wall-clock speedups. We observe that drafting errors are not uniformly distributed but typically stem from localized high-uncertainty tokens that destabilize downstream generation trajectories. Motivated by this token error pattern, we propose CURE, a budget-aware dynamic repair tree designed to repair errors at uncertainty focal points without incurring prohibitive tree-verification overheads. Specifically, our method uses predictive confidence margins to dynamically locate candidate error tokens within a block-parallel draft, expands bounded repair paths only at these fragile nodes, and employs a novel repair resynchronization mechanism to realign draft states post-verification. Evaluations on code-generation benchmarks (HumanEval, MBPP, and LiveCodeBench-lite) and mathematical reasoning benchmark (GSM8K) demonstrate that CURE increases the average accepted length by 4.2-7.5% over parallel baselines without repair, translating to an end-to-end speedup of $2.66-3.49\times$ over target-only decoding. Furthermore, we provide a plug-and-play repair module compatible with standard parallel drafting frameworks. We also characterize the trade-off between draft compute and verification efficiency.

## 论文总结：CURE：块并行推测解码的局部不确定性修复

### 1. 论文的核心问题与整体含义（研究动机与背景）

自回归大型语言模型（LLM）在推理时因逐 token 顺序生成而面临高延迟问题。推测解码（Speculative Decoding）通过轻量草稿模型生成候选 token，再由目标模型并行验证，有效缓解了内存带宽瓶颈。近年来的**块并行草稿（Block-Parallel Drafting）**技术虽能在单次前向传播中生成多 token 块、避免顺序草稿开销，但其长程生成中草稿精度常快速衰减，导致验证拒绝率飙升，端到端加速收益不佳。

论文观察到一个关键模式：**草稿错误并非均匀分布，而是集中出现在少数局部高不确定性 token 上**——这些"不确定性焦点"（Uncertainty Focal Points, UFPs）会破坏下游生成轨迹的稳定性，使标准前缀验证拒绝后续所有 token（即便它们语义正确）。基于此，论文提出 **CURE（Local Uncertainty Repair）**，一个预算感知的动态修复树框架，在不引入昂贵全树验证开销的前提下，精准修复局部错误。

### 2. 论文提出的方法论

#### 2.1 核心思想

CURE 将候选树扩展问题形式化为**有约束的预算分配问题**：保留原始块并行路径为 branch 0（安全兜底），仅在置信度低的 UFP 处稀疏地扩展有界修复分支，而非均匀或无条件地扩大树结构。整个流程**无需重训练或微调**，是即插即用的推理阶段模块。

#### 2.2 关键技术细节

- **局部不确定性门控（Local Uncertainty Gating）**：对草稿块中每个位置 i，计算 top-1 与 top-2 对数概率的置信度边际 mᵢ = ℓᵢ,₁ − ℓᵢ,₂。边际越小表示草稿对该位置越不确定；将 mᵢ < τ_margin 的位置标记为 UFP，并按边际升序优先选择。每个位置最多扩展 B=5 个替代分支。
- **动态分支机制（Dynamic Branching）**：通过归一化不确定性指数 uᵢ = clip(1 − mᵢ/s, 0, 1) 映射到局部分支预算 bᵢ = clip(round(b_min + uᵢ(b_max − b_min)), b_min, b_max)，其中 b_min=1、b_max=5，使分支分配自适应于置信度分布。
- **候选树构建（Candidate Tree Construction）**：在每个 UFP 处，保留原前缀、替换脆弱 token 为高分替代候选，并对后缀重新采样。共享前缀的路径自然合并为共享父节点，使目标模型可通过 **Tree Attention** 在一次前向传播中验证所有路径。单次迭代默认只修复一个低边际位置，以集中验证预算。
- **单次验证与缓存重同步（Joint Verification & Cache Resynchronization）**：目标模型一次性验证所有候选路径并计算各路径接受长度 a(π)，选择最长接受前缀 π* = argmax a(π)。若 branch 0 获胜则保持草稿缓存不变；若修复分支获胜，则将选定路径的 token 重放到草稿模型的 KV-cache 中，重新对齐后续草稿状态。

#### 2.3 算法流程（Algorithm 1 概述）

1. 块并行草稿模型 q 生成 K 长度草稿路径和每个位置的 top-1/top-2 对数概率；
2. 计算每位置边际 mᵢ，识别低于阈值 τ_margin 的 UFP；
3. 在满足总验证预算 V_max 的前提下，为选定 UFP 计算分支数并采样替代 token，扩展修复树；
4. 目标模型通过单次 Tree Attention 验证树中所有路径；
5. 选择最长接受前缀 π*；若 π* ≠ π₀，则重放所选路径至草稿模型 KV-cache 以重同步状态。

### 6. 论文的主要结论与发现

- **核心收益**：CURE 在代码生成基准上使平均接受长度较无修复并行基线提升 **4.2%–7.5%**，在 GSM8K 上提升 **32.0%**；相对目标-only 自回归解码实现 **2.66×–3.49×** 端到端加速；相对 Naive SD 加速 **4.38×–5.43×**。
- **功能一致性**：Pass@1 与目标-only 解码基本持平（HumanEval 79.9% 一致，MBPP 和 LCB-lite 完全一致），表明修复机制未损害下游任务正确性。
- **组件必要性**：Branch 0 作为低成本兜底路径移除后平均接受长度下降 5.7%；缓存重同步机制至关重要，移除后接受长度暴跌 40.1%、TPOT 比率从 1.776 恶化至 2.642。
- **可预测性**：离线评分器在仅选择 10% 的块时即可捕获 39.6% 的额外修复 token，表明有效修复高度集中在少数可预测的块中。
- **权衡分析**：树修复在熵高、错误密集的子序列中收益最大；在简单 token 分布上，额外验证延迟可能抵消接受长度收益。

### 7. 优点

- **问题洞察深刻**：明确了"草稿错误呈局部聚集"这一关键实证模式，区别于全树均匀扩展的通用做法，为推测解码的候选构建提供了更精准的理论切入点。
- **预算感知的局部修复设计**：将树扩展问题形式化为有约束优化，搭配置信度边际门控和动态分支数分配，将额外验证开销集中在最需要的节点，避免了 Dense Tree 的昂贵验证成本。
- **训练无关的即插即用架构**：不修改草稿或目标模型参数，零额外参数零重训练，可无缝接入现有块并行框架，实用性强。
- **缓存一致性设计**：提出 KV-cache 重同步机制解决修复分支获胜后草稿状态漂移问题，消融实验中显示该机制是系统性能的关键保障。
- **多维度的实验分析**：不仅报告延迟和接受率，还评估了功能正确性（Pass@1）、组件消融、离线可预测性分析，并刻画了 acceptance–compute 帕累托权衡，分析视角较多元。

- **与外部方法的对比不够公平**：表 2 中 EAGLE-3、DART、DFlash、Domino 的数据来自各自论文的 A100 环境和 2048-token 限制，与本文单 GPU、256-token 限制的设置无法构成严格的同条件对比，作者也承认这是"系统级上下文定位"而非直接对比。
