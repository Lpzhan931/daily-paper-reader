## 摘要
推测解码通过使用目标模型并行验证草稿块来加速自回归生成。在标准贪婪验证下，解码在第一个与目标 argmax 不同的草稿 token 处停止，并丢弃剩余的由目标评分的后缀。虽然接受这种不匹配会改变解码轨迹，但当其 token 在已实现的前缀下仍保持目标贪婪时，可以使连续后缀可复用。本文提出近似推测解码（ASD），一种免训练的验证器，它用有预算的最长前缀选择替换二元首次不匹配截断。ASD 接受选定的不匹配，受限于局部目标 logit 遗憾门、每块异常上限和持久请求级遗憾预算，然后重用连续的目标贪婪后缀，而无需额外的近似决策或目标模型前向传递。ASD 既不需要新的草稿模型，也不需要微调；当预算为零时，它完全简化为标准贪婪验证。实验表明，与匹配的严格验证相比，ASD 将固定工作负载的吞吐量提高了 3.05%–15.26%，并在七个 Qwen3-14B + DSpark-14B 任务上平均获得 7.78% 的提升。在 DeepSeek-V4-Flash (284B) 上，使用 DSpark，在 FP4 到 FP8 兼容设置中，它还将 GSM8K 和 MATH-500 上的验证器端接受率提高了约 10%–16%。源代码公开于：https://github.com/Kissmetothemoon/ASD

## Abstract
Speculative decoding accelerates autoregressive generation by verifying a draft block with a target model in parallel. Under standard greedy verification, decoding stops at the first draft token that differs from the target argmax, discarding the remaining target-scored suffix. Although accepting such a mismatch changes the decoding trajectory, it can make a contiguous suffix reusable when its tokens remain target-greedy under the realized prefix. In this paper, we introduce \textbf{Approximate Speculative Decoding (ASD)}, a training-free verifier that replaces binary first-mismatch truncation with budgeted longest-prefix selection. ASD accepts selected mismatches subject to a local target-logit regret gate, a per-block exception cap, and a persistent request-level regret budget, then reuses the contiguous target-greedy suffix without additional approximate decisions or target-model forward passes. ASD requires neither a new draft model nor fine-tuning, and exactly reduces to standard greedy verification when the budget is zero. Experiments show that ASD improves fixed-workload throughput by $3.05\%$--$15.26\%$ over matched strict verification and averages a $7.78\%$ gain across seven Qwen3-14B + DSpark-14B tasks. On DeepSeek-V4-Flash (284B) with DSpark it also raises verifier-side acceptance by roughly $10\%$--$16\%$ on GSM8K and MATH-500 in an FP4-to-FP8 compatibility setting. The source code is publicly available at: https://github.com/Kissmetothemoon/ASD

## 1. 核心问题与整体含义（研究动机与背景）

自回归大语言模型（LLM）逐个 token 生成，需反复执行大规模目标模型，解码成为主要推理瓶颈。推测解码（Speculative Decoding）用轻量草稿模型并行提议多个 token，再由目标模型并行验证，以保持目标行为的同时加速生成。然而，**标准贪婪验证存在结构性浪费**：

- 验证器只在草稿 token 与目标 argmax 完全一致时接受，一旦遇到第一个不匹配即停止，并丢弃该块中剩余的、**已经被目标模型评分的后缀 token**；
- 这种二元截断策略将"几乎持平的草稿 token"与"被目标强烈排斥的 token"同等对待，过于粗糙；
- 在 teacher-forced 验证中，后续目标行的计算实际上依赖于包含此前不匹配的前缀。若接受较早的不匹配，其后连续的、在实现前缀下仍保持目标贪婪的草稿后缀便可以被复用，无需额外目标前向传递。

论文由此提出核心研究问题：**能否在严格控制近似累积的条件下，允许少量低 regret 的例外不匹配，以复用已评分后缀，从而在不训练、不引入新模型的前提下提升推测解码的端到端吞吐量？**

## 2. 方法论：ASD 的核心思想与技术细节

**整体框架。** 论文提出 **Approximate Speculative Decoding（ASD）**，一种免训练、仅作用于验证器端的方法，将"首个不匹配即截断"替换为"**有预算的最长连续前缀选择**"（budgeted longest-prefix selection）。

**核心概念定义：**
- 局部目标 logit 遗憾（local target-logit regret）：\( r_i = z_i(y^*_i) - z_i(x_i) \geq 0 \)，即目标模型对 argmax 与草稿 token 的条件对数概率偏好差；
- 不匹配指示：\( d_i = \mathbb{I}[x_i \neq y^*_i] \)；
- 剩余提议长度（机会代理）：\( q_i = K - i + 1 \)。

**三层约束机制（ASD 的关键）：**
1. **局部 regret 门控**：\( r_i / q_i \leq g \)，拒绝局部代价过高的不匹配，仅当例外成本与其后缀复用潜力相称时接受；
2. **每块异常上限（block cap）**：\( N_t \leq M \)，防止例外在单个草稿块内过度集中；
3. **请求级持久后悔预算**：\( C_t \leq B - s \)，其中 \( C_t \) 为累计 regret，\( s \) 为已花费 regret，\( B \) 为总预算，保证整个请求生命周期内近似累积有界。

**可行性判定与算法流程（Algorithm 1）：**
- 逐位置计算可行性掩码 \( f_i = (1-d_i) \vee \left[ (r_i/q_i \leq g) \wedge (C_i \leq B-s) \wedge (N_i \leq M) \right] \)；
- 接受长度为 f 的最长全真前缀长度 \( a_{ASD} \)；
- 更新账本 \( s' = s + C_{a_{ASD}} \)；
- 若 \( a < K \)，输出接受前缀 + 目标恢复 token \( y^*_{a+1} \)；若 \( a = K \)，追加 bonus token \( y^*_{K+1} \)；
- 计算开销仅 O(K) 算术与临时存储，**无额外目标模型前向传递**；
- 当 \( B=0 \) 时，ASD 精确退化为标准 token-ID 贪婪验证（包括平局时的严格行为）。

**关键命题（Realized-prefix suffix reuse）：** 若被接受的连续位置 j 满足 \( x_j = y^*_j \)，则该 token 在 ASD 实现的历史下仍是目标贪婪的，可无额外 regret 花费地直接复用。注意它不恢复与严格目标贪婪轨迹的等价性（此前的不匹配已改变后续条件历史），但保证了后续目标贪婪后缀可被批量提交。

## 6. 主要结论与发现

- **吞吐量提升系统且一致**：Qwen3-14B + DSpark-14B 上 7 个任务全部正增益，固定工作负载 TPS 提升 3.64%–11.73%（平均 7.78%）；跨家族 10 个 cell 中增益 3.05%–15.26%（平均 7.52%），全部 95% 置信区间严格大于零；
- **机制验证**：平均接受长度在每个 cell 均增加（+0.07 至 +0.52 token），与"低 regret 例外解锁目标贪婪后缀复用"的机制预测一致；
- **速度-质量权衡明确**：ASD 是受控近似而非输出保持优化——GSM8K 与 MATH-500 的哈希分歧 >95%，但准确率未下降；部分任务有小幅准确率波动（最大下降 1.52 个百分点）；
- **预算控制是有效的操作旋钮**：B=0 时严格等价标准验证；增益随预算先升后平，说明后缀复用机会有限；草稿视野越大增益越大；
- **验证器开销可忽略**：verifier 逻辑仅增加 0.045–0.083 ms/token，而目标验证减少约 1.5 ms/token；
- **在 284B 大模型上**：gate ∈ {2, 3} 时 GSM8K 与 MATH-500 的 A/P 提升约 10%–16%，准确率变化 ≤0.30 个百分点。

## 7. 优点

- **即插即用、兼容性广**：纯验证器端修改，无训练、无新草稿模型，对 DSpark、EAGLE3、Medusa 三类草稿架构均有效；
- **三层互补约束设计新颖**：局部门控 + 块级上限 + 请求级持久账本，分别应对不同粒度的近似累积风险，比纯局部或纯重置式控制更完备；
- **理论与实现闭环**：形式化定义"实现前缀后缀复用"命题；验证器仅增加 O(K) 开销，无额外目标前向传递（不物化 K×|V| logit 缓冲）；
- **退化为严格验证**：B=0 时精确恢复标准贪婪行为（含平局处理），安全性下限明确；
- **评估协议严谨**：严格-ASD-严格三元组、哈希匹配、漂移控制、分离超参数发现、哈希分歧与准确率双轨审计，将"速度提升"与"行为保持"明确区分。

## 8. 不足与局限

- **不保证输出等价与任务正确性**：ASD 明确不是无损优化；哈希分歧率高，可能改变解码轨迹，对安全敏感或格式严格要求场景不适用；
- **遗憾度量是记账量而非校准概率**：局部 regret 不构成错误概率或下游质量保证；\( r_i/q_i \) 门控仅是启发式代理，非最优性声明；
- **准确率变化不稳定**：若干任务出现负向准确率波动（如 HumanEval −0.61、MT-Bench −0.64、Llama-3.1-8B+EAGLE3 GSM8K −1.17、Medusa −1.52 个百分点），方向因任务而异，需逐部署审计；
- **超参数需按部署校准**：控制参量需在分离数据上冻结并从 Pareto 前沿选择，论文承认其选点是保守配置而非最优找查结果；
- **DeepSeek 大规模实验覆盖有限**：由于 FP4 与 H20 原生 FP8 不兼容产生额外量化/反量化操作，实验仅刻画准确率与验证器端接受率，**未给出端到端吞吐量增益**，结论外推受限；
- **会议版本为 8 页短文**：详细配置与逐次实验记录仅在补充材料中，正文对部分消融细节（如每任务的哈希分歧率数值）呈现有限。
