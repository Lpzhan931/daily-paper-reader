## 摘要
大语言模型智能体日益通过有状态工具行动，然而在每个步骤中，模型生成与环境执行仍保持串行。随着解码加速，工具执行成为日益增长的瓶颈。现有的仅动作或仅观察推测暴露了大量此类延迟：价值集中在少数慢速调用上，某些结果仅能通过执行显现，而更长的前瞻通常需要越来越不可能的动作预测链。我们提出AOSpec，一个在完整智能体-环境循环中进行动作与观察协同推测的无损框架。期望值解码（EVD）将观察推测导向具有最大期望延迟收益的结果，优化期望隐藏时间而非命中率。对于仅能通过执行揭示的结果，AOSpec在包含其效果的隔离分叉中启动延迟关键的目标动作，而联合动作-状态验证（JASV）在重用前同时验证动作及其来源状态与已提交执行的一致性。JASV将长视界动作依赖从全链预测重构为目标动作-状态验证，打破了前瞻-准确性权衡，并在不牺牲串行语义的情况下解锁长距离重叠。在跨越四种测试框架、五个行动者模型和五种服务速度的Terminal-Bench服务设置中，AOSpec优于所有实际基线，平均端到端延迟降低11.8%-32.5%，p99延迟降低高达42.8%。其收益随解码加速而增加，且其观察模型无需重新训练即可从Terminal-Bench迁移到SWE-bench Verified。

## Abstract
Large language model agents increasingly act through stateful tools, yet model generation and environment execution remain serialized at every step. As decoding accelerates, tool execution becomes a growing bottleneck. Existing action- or observation-only speculation leaves much of this latency exposed: value is concentrated in a few slow calls, some outcomes emerge only through execution, and longer lookahead typically requires an increasingly unlikely chain of action predictions. We present AOSpec, a lossless framework that co-speculates actions and observations across the full agent-environment loop. Expected Value Decoding (EVD) directs observation speculation toward outcomes with the greatest expected latency benefit, optimizing expected time hidden rather than hit rate. For outcomes only execution can reveal, AOSpec launches latency-critical target actions in isolated forks that contain their effects, while Joint Action-State Verification (JASV) verifies both the action and its origin state against committed execution before reuse. JASV recasts long-horizon action dependency from full-chain prediction into target action-state verification, breaking the lookahead--accuracy tradeoff and unlocking long-range overlap without sacrificing serial semantics. Across Terminal-Bench serving settings spanning four harnesses, five actor models, and five serving speeds, AOSpec outperforms every practical baseline, reducing mean end-to-end latency by 11.8-32.5% and p99 latency by up to 42.8%. Its gains increase as decoding accelerates, and its observation model transfers from Terminal-Bench to SWE-bench Verified without retraining.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：基于大语言模型（LLM）的智能体在推理循环中越来越依赖有状态的工具（stateful tools），例如文件系统、命令行、进程等，这些工具有查看和修改运行环境的能力。主流的智能体服务框架（如 Claude Code、OpenClaw）将模型推理与工具执行环境解耦，形成“解耦式智能体循环”（disaggregated agent loop）。
- **核心问题**：在标准循环中，模型生成和执行工具调用是严格串行的。随着解码速度不断提升（如 1ms/token），工具执行时间所占端到端延迟比例越来越大，成为新的主要瓶颈。
- **现有方法的不足**：
  - 动作推测（Action Speculation）只预测并提前执行未来的工具调用；
  - 观察推测（Observation Speculation）只从临时观察继续生成；
  - 但二者都无法解决三个关键障碍：
    1. **延迟集中性**：少数慢速调用占据绝大部分工具时间，命中率与延迟节省严重脱钩；
    2. **环境依赖**：很多观察结果只能通过真实执行获得，无法通过模型预测得出；
    3. **前瞻权衡**：延长动作推测的前瞻长度虽能增加重叠时间，但动作链的预测准确率随长度指数下降，收益被错误抵消。
- **整体含义**：需要一种能够覆盖完整智能体-环境循环的协同推测机制，在保持无损（lossless）的前提下同时推测动作和观察，以最大限度隐藏工具执行延迟。

## 2. 方法论

**核心思想**：AOSpec 是一种无损的“动作+观察”协同推测框架，将推测从单一侧扩展到完整循环。

### 2.1 总体流程

- 在每轮已验证的观察边界，actor 开始生成下一个动作时，AOSpec 在隔离沙箱分叉中启动推测性动作。
- 推测候选可指向当前步骤或更晚的步骤。
- 当 actor 发出目标动作 a 时，用 **JASV** 判断某个分叉是否可复用（动作匹配且环境状态一致），否则从已提交环境重新执行。
- 在等待工具执行结果期间，用 **EVD** 起草候选观察，每个候选可启动一个临时 actor 继续生成。
- 真实观察返回后，仅保留与该观察逐字节一致的临时分支，其余全部丢弃。

### 2.2 期望值解码（EVD, Expected Value Decoding）

- 目标：直接优化期望隐藏时间，而不是命中率。
- 对每个候选观察 c，估计其预期工具时间 \(\hat{T}(c)\)：
  \[
  \hat{T}(c) = \frac{\sum_j K(c, o_j) T_j}{\sum_j K(c, o_j)}
  \]
  其中 K 是观察结果相似度函数，可用正则表达式模式或嵌入向量计算。
- 候选按 \(V_o(c) = p_\theta(c | H_t, a_t) \cdot \hat{T}(c)\) 排序，取分值最高的若干个，受分支预算限制。
- 观测模型可选：可微调一个小模型（如 Qwen3-0.6B），训练损失为：
  \[
  L_{obs}(\theta) = -\sum_{(H_t,a_t,o_t)\in D} \log p_\theta(o | H_t, a_t)
  \]
  对耗时长的窗口进行过采样，保证延迟关键结果被保留。
- 观察验证：最终只接受与真实观察逐字节相同的分支。

### 2.3 联合动作-状态验证（JASV, Joint Action-State Verification）

- 每个分叉 f 记录其推测动作 \(\hat{a}_f\) 和来源环境的版本 \(\nu(S_f)\)。
- 当 actor 从已提交环境 \(S_i\) 发出目标动作 \(a_i\) 时，只有满足下面条件才接受分叉：
  \[
  \text{ValidAct}(f,a_i,S_i) = [\hat{a}_f = a_i] \land [\nu(S_f) = \nu(S_i)]
  \]
- 动作相等包括工具名和参数完全一致，环境版本一致性通过沙箱文件系统的根哈希比较实现。
- JASV 将“长链动作预测”改写为“目标动作+源状态验证”，因此：
  - 不需要预测中间动作序列；
  - 当发起动作时，只需在发起边界启动候选，并在目标边界验证状态即可；
  - 通过提交后丢弃失效分叉，语义与串行执行完全相同，保证无损。

### 2.4 状态验证的动作前瞻

- 若在边界 j 发起影响步骤 i 的动作，可用重叠时间（runway）为：
  \[
  R_{j,i} = \sum_{k=j}^{i} D_k + \sum_{k=j}^{i-1} T_k
  \]
  最大隐藏时间为 \(\min(T_i, R_{j,i})\)。
- 在环境不变的情况下，候选可跨越多个中间调用而仍有效，因此无需预测中间动作，能实现长距离重叠。

### 2.5 运行时支持

- 采用沙箱运行时提供快照、分叉、执行、提交、丢弃操作。
- 每个沙箱的 CoW 文件系统镜像具有不可变版本号，以根哈希唯一标识。
- 非文件系统输入与副作用不在本文处理范围。

- **优点**：实验覆盖面广，几乎在所有配置组合下都进行了比较，并且使用了 trace replay 保证公平性（所有方法用相同 actor 轨迹），尾延迟也给出分布数据（p10~p99）。

  - 所选基线并非同一时期的全部 SOTA，例如 SpecHop 以外没有对比其他更新的多步动作推测方法（如 B-PASTE、DualSpec 等只出现在相关工作介绍，未进入实验）。

## 6. 主要结论与发现

- AOSpec 在所有 45 个配置和 TPOT 组合中均优于所有实际基线。
- 平均端到端延迟降低：
  - 20 ms TPOT 时 11.8%；
  - 1 ms TPOT 时 32.5%；
  - 最强基线分别为 4.3% 和 12.2%。
- p99 延迟最高降低 42.8%（在 10 ms TPOT 时），p95 降低 30.3%，中位数降低 10.7%。
- 在 41/45 的设置中，AOSpec 甚至超过 Oracle-action（单步动作推测上限），说明观察推测和跨步动作前瞻的叠加收益显著。
- 收益随解码加速而增加，证明工具执行延迟在更快生成下成为更突出的瓶颈。
- 观察模型不需重新训练即可从 Terminal-Bench 迁移到 SWE-bench Verified，且在 1 ms TPOT 时实现 18.9% 的延迟节省，远超最强基线（4.2%）。
- EVD 相比单纯概率或单纯时间估计，能隐藏更多工具时间（60.5 秒/次 vs 47.6 秒和 39.4 秒/次），并只轻微提升对慢速调用的命中率（18.4% → 21.0%），证明其优化方向与预期一致。
- JASV 使长距离动作预测（10 步）仍可用：虽然目标动作准确率从 23.7%（1 步）降到 7.7%（10 步），但因为不需要预测中间动作链，仍能保留重叠收益。

## 7. 优点

- **设计新颖**：首次将动作推测与观察推测统一到同一无损框架中，并针对两个核心弱点（延迟集中、环境依赖）提出专门机制。
- **理论价值明确**：通过“期望隐藏时间”而非“命中率”来指导推测，具有更强的工程直觉。
- **无损保证**：JASV 严格验证动作和环境状态，保证与串行执行语义一致，不会引入错误副作用。
- **前瞻解耦**：将长链预测转化为目标-状态验证，打破了前瞻深度与准确率之间的传统权衡。
- **实验较扎实**：覆盖多 harness、多模型、多服务速度，并提供了大量消融和迁移实验，结果分析有说服力（特别是延迟分位数提升很明确）。
- **可迁移性**：观察模型无需重新训练就能跨基准迁移，降低实际部署成本。

## 8. 不足与局限

- **在线迹差异风险**：实验基于 trace replay，实际在线时 actor 生成的轨迹可能因推测分支而改变，导致某些推测分支不再匹配，真实收益可能与实验略有偏差。
- **环境依赖强**：完全依赖沙箱提供的快照/分叉/回滚能力。若工具调用产生不可隔离的外部副作用（如网络写操作、持久化状态变更），则无法纳入推测。
- **动作预测模型较弱**：使用的动作 drafter（Qwen3.6-35B-A3B-FP8，宽度 32 时只有 23.7% 准确率）并非强预测器，对长距离目标动作准确率较低（7.7%），虽然 JASV 缓解了链式错误，但若动作预测本身太差，收益仍可能受限。
- **观察模型输入细节不足**：输入消融显示历史信息重要，但论文未分析当前动作中哪些字段最关键，也未讨论格式规范化对命中率的影响。
