## 摘要
在移动设备上部署视觉语言模型（VLM）因其巨大的内存和计算需求而具有挑战性。我们提出了一种在资源受限硬件上对VLM进行量化以实现高效推理的框架。我们的方法结合了一种量化流程，该流程利用模型自身生成训练数据，且无需访问训练设置，并采用一种新颖的每参数2.7位格式，支持在Arm CPU上的高效执行。我们通过将Llama 3.2 11B Vision Instruct模型压缩至3.7 GB（8位激活），在标准视觉问答任务集上保持强劲性能，验证了我们的方法。

## Abstract
Deploying vision-language models (VLMs) on mobile devices is challenging due to their significant memory and compute requirements. We present a framework for quantizing VLMs for efficient inference on resource-constrained hardware. Our approach combines a quantization pipeline that uses the model itself to generate training data and does not require access to the training setup, with a novel 2.7-bit-per-parameter format supporting efficient execution on Arm CPUs. We validate our approach by compressing the Llama 3.2 11B Vision Instruct model to 3.7 GB with 8-bit activations, preserving strong performance on a set of standard visual question answering tasks.

# Llama-Mobile 论文详细总结

## 1. 核心问题与研究动机

- **背景**：视觉语言模型（VLM）将视觉编码器与 LLM 骨干结合，可同时理解图像和文本，非常适合移动应用；但模型规模大、计算与内存需求高，难以在手机等资源受限设备上部署。
- **核心问题**：如何在不访问原始训练数据的前提下，将 VLM 压缩到 **每参数 3 bit 以下**，并在 Arm CPU 上高效执行，同时尽可能保持原有视觉问答能力。
- **难点**：
  - 极低比特量化（sub-3-bit）会造成严重性能退化；
  - 量化感知训练（QAT）的有效性高度依赖训练数据分布，而多模态场景缺少通用的合成数据方案；
  - 数值格式必须兼顾压缩率、模型质量与硬件解码效率。

## 2. 方法论

### 总体框架
论文提出一个三阶段量化框架，核心思想是“模型自身生成数据 + 量化感知蒸馏 + 硬件协同设计格式”：

1. **合成数据生成**：利用原模型自身生成训练样本，不依赖原始训练数据或训练配方；
2. **量化感知训练（QAT）**：以原 bfloat16 模型为教师，量化模型为学生，在合成数据上进行知识蒸馏；
3. **移动端部署**：将训练好的量化权重部署到 Arm CPU，执行高效推理。

### 量化感知训练目标
- 学生模型前向传播使用量化参数 `θ̂_S = Q(θ_S)`，梯度通过**直通估计器（STE）**回传。
- 对每个样本 `(I, x, y)` 的教师生成响应 token 计算 KL 散度损失：

```
L_KD = (1/|y|) * Σ_t KL(p_T^(t) || p_S^(t))
```

- 该目标鼓励量化学生模型保留教师模型的多模态生成行为。

### 合成数据生成细节
- **图像来源**：使用 ImageNet 训练集（128 万张自然图像），与下游评测任务无关。
- **文本来源**：由教师模型（Llama 3.2 11B Vision Instruct）对图像+随机提示生成响应，保存为蒸馏目标。
- **提示采样策略**（核心创新）：
  - 以概率 0.75 应用指令微调模板，否则使用纯文本模板；
  - 问题池包含手写通用问题与组合生成提示（动作、目标、受众、风格），共 495 个；
  - 以概率 0.7 添加指令块，并随机附加格式、长度、遵守性约束；
  - 长度偏向短/中响应，同时保留少量长回答；
  - 全部提示均为通用图像理解类，**不使用下游 benchmark 数据或特定任务提示**，以避免过拟合。

### S3D8 数值格式（2.7-bit/参数）
- **编码方式**：每 8 bit 存储 3 个权重——5 bit 共享质心索引 + 3 bit 符号位。
- **码本**：32×3 的 INT8 质心表，由 Lloyd-Max 算法 + k-means++ 初始化在归一化绝对权重上训练得到；QAT 期间码本冻结，仅更新通道缩放、索引和符号。
- **解码**：
  - 每个输出通道配一个 bfloat16 缩放因子；
  - 利用 Arm SIMD 的 64 项表查找指令（TBL）将“质心索引+符号”融合为查找索引，直接得到带符号 INT8 值；
  - 通过特殊位布局将解码压缩到 5 条逻辑指令，一次处理 48 个元素。
- **推理**：权重解码后以 INT8 格式参与矩阵乘，8-bit 激活，支持 Arm dotprod/i8mm 扩展。

## 6. 主要结论与发现

- **S3D8 在 2.68 bit/参数下**将 Llama 3.2 11B Vision Instruct 压缩至 3.7 GB，平均任务性能从 0.744 降至 0.661（下降 0.083），显著优于同等大小下的 INT（0.347）、student-t（0.565）、lloyd-max（0.436）。
- **QAT 在低位宽下优于 GPTQ 和直接转换**：S3D8 经 GPTQ 仅达 0.340，而 QAT 达 0.661，说明训练过程对极低比特量化至关重要。
- **采样提示比固定提示大幅提升效果**：固定“Describe the image:”仅能生成单一类型响应，导致多任务性能明显下降。
- **S3D8 具有硬件效率优势**：
  - 在 Pixel 8a 上端到端生成速度 3.8 token/s（INT8 因模型过大无法部署）；
  - 在 Graviton4 上为 36.8 token/s，高于 INT8 的 26.4 token/s；
  - 在 autoregressive 的小 batch 矩阵乘中 S3D8 比 INT8 更快，在 prefill 大 batch 场景略慢但接近。
- **S3D8 格式本身比标量格式有更好的率失真权衡**，在同等压缩率下保留更多精度。

- **无需原始训练数据**：数据生成完全由模型自身完成，适用于无法获得训练集的实际部署场景。
