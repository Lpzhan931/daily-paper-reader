## 摘要
低比特量化可减少大型语言模型（LLM）推理的内存占用和计算成本。然而，高幅度的离群点权重可能引发显著的量化误差，降低模型精度。离群点感知量化通过以高精度保留离群点、量化其余权重来解决此问题，从而形成低比特稠密GEMM路径和高精度稀疏SpMM路径。现有实现虽共享激活和输出，却在单独的GPU内核中执行这两条路径，因而错失算子内重用机会，并产生冗余的全局内存访问。这种低效在内存受限的解码工作负载中尤为突出。我们提出FlashQuant，一种用于离群点感知W4A16解码的内容共享执行框架。FlashQuant将稠密GEMM与稀疏离群点SpMM路径融合到单个GPU内核中，实现异构计算间激活和输出瓦片的片上重用。它引入了三项关键技术：稀疏-稠密分块，将离群点处理与稠密GEMM瓦片对齐；Tile-COO离群点编码，实现高效稀疏访问并减少共享内存bank冲突；以及流水线调度，使计算与数据移动重叠。实验表明，FlashQuant降低了离群点处理开销，相比cuBLAS BF16实现2.74倍至4.18倍加速，相比最强的未融合离群点感知基线最高获得1.53倍加速。

## Abstract
Low-bit quantization reduces the memory footprint and computational cost of large language model (LLM) inference. However, high-magnitude outlier weights can induce substantial quantization errors and degrade model accuracy. Outlier-aware quantization addresses this issue by retaining outliers in high precision while quantizing the remaining weights, resulting in a low-bit dense GEMM path and a high-precision sparse SpMM path. Existing implementations execute these paths in separate GPU kernels, despite their shared activations and outputs, thereby missing opportunities for intra-operator reuse and incurring redundant global-memory accesses. This inefficiency is particularly pronounced in memory-bound decoding workloads. We propose FlashQuant, a content-sharing execution framework for outlier-aware W4A16 decoding. FlashQuant fuses the dense GEMM and sparse outlier SpMM paths into a single GPU kernel, enabling on-chip reuse of activation and output tiles across heterogeneous computations. It introduces three key techniques: sparse-dense tiling, which aligns outlier processing with dense GEMM tiles; Tile-COO outlier encoding, which enables efficient sparse access and reduces shared-memory bank conflicts; and pipelined scheduling, which overlaps computation with data movement. Experiments show that FlashQuant reduces outlier-processing overhead, achieving $2.74\times - 4.18\times$ speedup over cuBLAS BF16 and up to $1.53\times$ speedup over the strongest unfused outlier-aware baseline.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）规模不断增长，推理时的内存与计算开销巨大（如 Qwen3-235B 在 BF16 下需超过 470GB 内存）。权重量化（Weight-only Quantization）是降低内存占用和带宽成本的主流手段，例如将权重存为 INT4、激活保持 BF16。
- **痛点**：激进的低比特量化容易受**高幅度离群权重（outlier weights）**破坏，导致严重的量化误差和模型精度下降。离群点感知量化（Outlier-aware Quantization，如 SpQR）通过将少量离群权重保留为高精度（如 BF16）来缓解这一问题——例如 LLaMA3-8B 在 INT4 下保留 1% 离群点，可将 WikiText2 困惑度从 6.896 降至 5.979。
- **引入的新问题**：这使单个矩阵乘法被拆分为两条计算路径——低比特稠密 GEMM 路径 + 高精度稀疏 SpMM 路径。现有系统（如 cuSPARSE、Sputnik）将两条路径**拆分为独立 GPU 内核**执行，但二者共享同一激活矩阵且累加到同一输出矩阵，因此产生了**重复的全局内存访问**（重复加载激活、重复写回部分输出）。在解码（decoding）阶段，batch size 小、访存受限，这种冗余流量会带来不成比例的延迟开销。
- **核心贡献定位**：论文主张"内容共享融合"（content-sharing fusion），将同一算子派生出的异构计算路径（稠密 GEMM + 稀疏 SpMM）融合进**单个 GPU 内核**，从而复用片上数据、消除冗余访存。

## 2. 方法论：核心思想与关键技术

### 2.1 总体框架
- 分解公式：$Y = X \cdot W \approx X \cdot \text{dequant}(W_Q) + X \cdot W_O$
- 两阶段流程：**离线预处理**（离群点感知量化 → 稀疏-稠密统一分块 → Tile-COO 编码与重排序）＋**在线推理**（单一融合内核执行）。
- 融合内核中：Tensor Core 执行低比特 GEMM，CUDA Core 执行高精度 SpMM，激活瓦片在共享内存中复用，部分和在片上累加后再写回全局内存。

### 2.2 关键技术一：稀疏-稠密分块（Sparse-Dense Tiling）
- **CTA 级**：将 $W_Q$ 与 $W_O$ 按输出瓦片对齐分区，每个 CTA 只加载一次激活瓦片 $X_{CTA}$ 供两条路径复用；采用 **Stream-K** 工作分解以平衡负载。
- **Warp 级**：稠密路径使用 Tensor Core MMA 指令，采用 Sliced-K 并行；稀疏路径为每个稀疏 warp 分配不相交的输出列集合，避免原子操作和写冲突，并根据负载动态增配 warp 数量以隐藏访存延迟。
- **线程级**：稠密计算按 MMA 布局映射；稀疏计算按桶（bucket）组织线程，采用 8 元素 swizzle（16 字节、4 bank）的激活布局以缓解共享内存 bank 冲突。

### 2.3 关键技术二：Tile-COO 离群点编码
- 结构包含三个数组：`tile_indptr`（瓦片偏移）、`bucket_info`（桶偏移与桶内非零数）、`packed_outliers`（打包的行索引、列索引、BF16 值）。
- 利用瓦片规模上限（256×256），行/列索引用 **uint8_t** 编码，每 4 个离群点打包为一个 uint4 元组，支持向量化、并行解码。
- 存储开销：$S_{Tile-COO} = (N_{tile}+1)\times4 + N_B\times4 + nnz\times4$ 字节，明显小于 CSR（$(K+1)\times4 + nnz\times12$ 字节）。
- **两级稀疏重排序**：列重排序（按非零数降序排序 + 贪心堆调度）均衡桶间负载；元素重排序（按 bank 组循环顺序排列）减少子 warp 间共享内存 bank 冲突。

### 2.4 关键技术三：流水线调度与高效解码
- 四阶段流水线 + 双缓冲：全局内存加载 → 寄存器暂存 → 反量化/离群点解码 → Tensor Core/CUDA Core 计算，实现数据移动与计算重叠。
- 解码伪代码（Listing 1）要点：按 bucket 顺序处理，双缓冲预取下一个打包条目；一次 swizzle 变换后执行 4 路展开的 FMA，写入共享内存的局部累加结果。
