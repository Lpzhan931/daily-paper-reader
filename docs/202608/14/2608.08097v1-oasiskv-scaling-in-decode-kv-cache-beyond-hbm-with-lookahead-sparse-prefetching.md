## 摘要
大语言模型（LLM）推理服务日益受限于内存而非计算。随着长上下文和长形式推理工作负载变得愈发普遍，键值（KV）缓存在LLM令牌生成（即解码）期间主导了内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批量大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过将完整的KV缓存存储与HBM解码过程解耦来缓解HBM容量压力。由于解码时的注意力天然是稀疏的，OasisKV仅在HBM中保留最相关令牌的KV条目用于注意力计算。我们观察到，使用投机解码（SD）起草的前瞻令牌可以提前准确预测未来的重要令牌。OasisKV采用高效的注意力后台流水线来识别重要的KV块，然后从更高容量的内存层级（例如主机内存或远程内存）预取它们，并在下一步解码使用前将其暂存于HBM中。我们基于vLLM实现了OasisKV。在2,048令牌的KV预算下，前瞻预测的准确性足以将精度保持在完全注意力的0.7个百分点以内。这使得OasisKV能够将稀疏性转化为吞吐量增益：在推理工作负载上，相较于稠密vLLM实现了1.69倍的吞吐量提升，精度损失仅0.1个百分点；在多GPU长上下文服务中，吞吐量提升可达2.1倍。在预填充-解码分离架构下，OasisKV的吞吐量约为稠密方案的2倍，同时每个请求的KV量减少6.5至9.7倍，解码节点主机内存占用比完整KV传输减少2.2至2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）推理服务正从"计算受限"转向"内存受限"。随着长上下文（long-context）和长形式推理（long-form reasoning）工作负载兴起，KV缓存（Key-Value Cache）在解码（decode）阶段同时主导了**内存占用**和**内存流量**。
- **核心矛盾**：HBM（高带宽内存）容量稀缺且昂贵，直接限制了推理的批大小（batch size）和系统吞吐量。例如，32B级GQA模型在FP16/BF16下每token约需256 KiB KV空间；在平均32.7K上下文的编程代理场景中，单个请求的KV缓存高达约8.6 GB，即使用80GB HBM全部作为KV缓存也仅够容纳9个请求。
- **现有方案的局限**：
  - **稀疏注意力**（如Quest、NSA、DSA）降低KV读取量，但未减少HBM中KV缓存所需的容量。
  - **KV检索**（如ShadowKV、RetroInfer）将KV放在CPU/SSD，但按需传输处于解码关键路径上，传输延迟直接拉高TPOT（time-per-output-token）。
  - **KV预取**（如InfiniGen、FreeKV、SpeCache）虽尝试重叠内存传输与计算，但现有的预测信号（如上一token的query）准确率不足，且系统架构缺乏面向生产级多GPU、PD分离场景的跨层内存管理能力，吞吐被CPU-GPU IO带宽天花板限制。
- **论文含义**：OasisKV旨在打破本地和远程"片外"（off-GPU）内存墙，将**稀疏预测、预取重叠、跨层存储管理**视为一个联合系统优化问题，使LLM可以在HBM只保留小规模KV工作集的情况下，从更大容量（CPU DRAM、远程内存）的完整KV缓存中获得高精度、高吞吐的解码服务。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
利用解码期注意力的天然稀疏性，HBM仅保留最相关token的KV条目；通过**投机解码（speculative decoding）的draft token**提前一个解码步预测下一时刻的重要KV块，并通过全异步的后台流水线从CPU DRAM/远程内存预取到HBM中。

### 2.2 前瞻注意力（Look-ahead Attention）
- **预测信号**：复用SD/EAGLE-3的draft token作为前瞻信号。将draft query在正常token的稀疏KV上传播后，与真实下一token query的top-K集合达成平均98.74%、每层最低98.2%以上的一致率。
- **压缩key摘要**：基于Quest风格的per-block min/max pooling，每块存储两个摘要向量，占完整KV缓存仅1/16，使draft query可扫描全局所有块并排序，无需恢复完整key。
- **共享前向路径**：QKV投影同时产出normal和draft query，注意力kernel在同一个resident KV工作集上同时处理二者，避免第二次前向传播的额外开销。

### 2.3 全异步后台流水线（Prefetch Pipeline）
- 每个Transformer层维护独立的压缩key、resident映射和KV存储；按层组织**Top-K预测 → KV选择 → KV传输**三段式流水线。
- 三层之间的任务是独立的，可并发执行：第\(l+1\)层的Top-K预测、第\(l\)层的KV选择、第\(l-1\)层的KV传输并行运行于不同的CUDA stream上。
- 稳态流水线周期为 \(\max\{T_{\mathrm{pred}}, T_{\mathrm{select}}, T_{\mathrm{transfer}}\}\)，因此受最慢阶段（通常是KV传输）限制。

### 2.4 Delta选择与带上限的驱逐策略（Capped Eviction）
- KV选择先求预测集合与resident集合的交集（已驻留的块不产生PCIe流量），再用LRU策略选出驱逐目标，将被预测但缺失的块与驱逐目标一一配对。
- 每KV头每步最多允许 \(C\) 对被替换（即fetch cap），从而将每层每步的PCIe传输量严格限制在 \(C \cdot H\) 个块以内，确保传输不超过单步解码可隐藏的字节预算 \(C_{\mathrm{token}} = B_{\mathrm{link}} \cdot T_{\mathrm{decode}}\)。

### 2.5 KV管理（Head-wise Mapping）
- 在现有GPU/CPU页表之上增加一层**head-wise逻辑到逻辑映射**：每个KV头独立维护GPU逻辑块与CPU逻辑块（全量KV）之间的对应关系，不同头可驻留不同稀疏块集合。
- 保持原始页表不变，注意力kernel（如FlashAttention）以与dense相同的路径处理稀疏工作集，支持在张量并行下各GPU独立更新本地KV头映射，无需跨GPU同步。

### 2.6 远程部分获取（Remote Partial Fetching，PD分离场景）
- **Partial Transfer（准入阶段）**：prefill节点先额外执行一个解码步，用第一个生成token的query确定各层KV头top-K块集合的并集，仅将该并集、压缩key摘要和draft KV状态传输给decode节点（相比全量KV减少6.5–9.7×），prefill GPU无需等待传输完成即可释放。
- **Network Prefetch（解码阶段）**：当top-K选择在解码中漂移且所需块不在decode节点本地时，视为cache miss，通过NIXL/UCX从prefill节点远程读取到decode节点宿主DRAM，再由UVA gather kernel写入GPU，全程与前台注意力重叠执行，并支持批内请求间按层聚合传输。

### 2.7 从密集到稀疏的解码切换
请求在上下文未超过稀疏化阈值前用原始递增页表做dense解码；超过阈值后，将完整KV复制到CPU内存，GPU仅保留选中的历史块和局部窗口，通过Head-wise Mapping切换而无须改动页表。

## 6. 主要结论与发现

1. **吞吐显著提升**：在Qwen3-8B单GPU上，真实AIME24推理工作负载达到dense vLLM的 **1.69×** 吞吐（2,083 vs 1,235 tok/s），精度损失仅0.1点；多GPU长上下文最高达 **2.1×**（16K、并发128时1,398 vs 676 tok/s）。
2. **PD分离场景**：OasisKV两个配置均达dense的 **2.1–2.3×** 吞吐；RPF将每请求准入KV传输量减少 **6.5–9.7×**，解码节点宿主内存占用减少 **2.2–2.6×**；网络带宽利用率更平稳（idle时间从60%降至1–2%）。
3. **精度保持**：在2,048 token KV预算下，整体精度距full attention在 **0.7点以内**（长输出avg@8目标约-0.35，pass@8约-0.66），优于Quest和FreeKV（-2.6至-3.5）。
4. **稀疏→吞吐的转化机制**：小到中等批时由更低TPOT驱动，大batch时由2,048 token KV边界支撑的高并发度驱动。
5. **带宽是真正瓶颈**：fetch cap消融显示吞吐随每步传输字节数从2,178跌到824 tok/s（2.6×），而精度仅从74.9变到77.4——证明在production引擎中PCIe带宽而非注意力计算是限制因素；fetch ratio 0.05为最佳工作点。

## 7. 优点

- **新颖有效的预测信号**：将投机解码的draft token复用为KV访问模式的lookahead信号，无需训练专用预测器、无需第二次前向或全量KV扫描，平均98.7%的top-K一致率在经验上强有力地支持了这一选择。
- **异步流水线设计精细**：层间异步、层内三段式流水线配合CUDA event做层局部同步，使早期层可先行启动；这是在生产级短步骤时隙内隐藏片外传输的关键系统技巧。
- **带宽感知的准入控制**：capped eviction策略显式建模单步可隐藏传输预算（\(C_{\mathrm{token}}\)），将带宽管理落实为系统原语，而非事后优化。
- **与生产引擎的良好集成**：基于vLLM实现，保留原始页表和PagedAttention路径，以head-wise映射层解决稀疏与dense同批共存问题，具备多GPU TP和PD分离的工程完整性。
- **PD分离下的稀疏跨层传输**：RPF同时削减TTFT和decode节点DRAM占用，以较小额外miss流量换取网络时间分布更平坦，对生产部署有现实价值。

## 8. 不足与局限

- **draft token被强制拒绝**：当前实现仅将draft token用于预测并拒绝其产出，draft overhead无法被token接受率摊销；作者将"与投机解码联合解码"列为未来工作，意味着当前对比在计算效率上**未包含SD本身的潜在正收益**。
- **需要EAGLE-3/MTP组件**：虽然免训练，但依赖社区发布的draft head；对没有可用draft模型的模型无法直接适用，且draft模型的额外显存/计算开销未在能耗与延迟报告中单列。
- **当前原型仅支持动态前缀稀疏**：尚未实现prefix caching（论文仅以分析模型估计其TTFT收益），而生产环境中前缀命中率常高，缺少真实测量。
- **PD分离的原型保留全量KV于prefill节点**：只是把DRAM压力从decode转移回prefill侧，未完成端到端的remote memory server/SSD分层，部署形态受限于"两节点一对一"场景。
- **对MoE模型的增益相对较小**：Qwen3-235B在低batch下TPOT高于dense（因KV占比小、稀疏省下来的显存收益有限），需batch≥16–32才反超，说明方法效果对KV/权重内存比敏感。
- **评估覆盖不够全面**：未提供多用户真实生产trace、可变前缀长度混合负载、不同类型agentic任务（Web-use、computer-use）的实测；也未报告能耗、尾部延迟（p99）、故障场景下的行为。
