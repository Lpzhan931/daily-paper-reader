## 摘要
在边缘设备上部署大型语言模型（LLM）进行推理，由于严重的内存和带宽限制而具有挑战性。尽管推测解码和混合专家（MoE）已被提出用于提高推理效率，但简单地将它们结合往往会导致过多的验证开销和较差的专家重用，限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了 S2-MoE，一种针对边缘设备上 MoE 推理的高效自推测解码框架。S2-MoE 通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿和目标执行。在 llama.cpp 中实现，S2-MoE 在边缘设备上的多种 MoE 模型和数据集上，相比于标准自回归解码，实现了高达 5.3 倍的加速（平均约 2.0 倍）。代码可在 https://github.com/angerybob/S2-MoE 获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama.cpp, S2-MoE achieves up to 5.3x speedup (about 2.0x on average) over standard autoregressive de?coding across diverse MoE models and datasets on edge devices.Code is available at https://github.com/angerybob/S2-MoE.

# S2-MoE 论文总结

## 1. 核心问题与整体含义

- **研究背景**：边缘设备上部署大型语言模型（LLM）受到严重的内存与带宽约束。MoE 模型通过稀疏激活降低参数访问，推测解码通过并行验证提高输出密度，但二者简单结合会带来严重的效率问题。
- **核心问题**：在 MoE 模型上应用推测解码时，不同草稿 token 可能激活不同的专家，导致验证阶段专家参数复用率低、冗余验证开销高，甚至使得加速效果不如单独使用其中任意一种技术。
- **整体含义**：本文提出 S2-MoE，一个面向边缘设备 MoE 推理的高效自推测解码框架，通过路由感知自适应扩展、复用感知专家门控和上下文对齐机制，显著降低验证开销并提高专家复用，实现了可比拟甚至超越现有推测解码方法的端到端加速。

## 2. 方法论

### 核心思想
- 从目标 MoE 模型自身构建轻量草稿（自推测解码），避免外部草稿模型带来的对齐困难。
- 针对 MoE 特有的专家激活开销，对推测解码的"扩展—验证"过程进行联合优化。

### 三个关键技术组件

1. **路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）**
   - 定义草稿 token \(i\) 的预期收益：\(B_i = p_i \cdot T_{\text{AR}}\)，其中 \(p_i\) 为前缀置信度，\(T_{\text{AR}}\) 为单步自回归解码延迟。
   - 定义边际验证成本：\(\Delta C_{\text{ver}}(i|S) = |E_i \setminus \bigcup_{j \in S} E_j| \cdot T_{\text{exp}}\)，即新引入的专家数乘以单位专家验证延迟。
   - 效用分数：\(U_i = \frac{B_i}{\Delta C_{\text{ver}}(i|S) + C_i^{\text{draft}}}\)。
   - 贪婪扩展：仅当 \(U_i \ge 1\) 时接受候选，从而动态控制推测宽度，优先选择"高接受概率、低验证成本"的分支。

2. **复用感知专家门控（Reuse-aware Expert Gating）**
   - 跨 token 聚合专家重要性：\(g_e = \sum_{b \in B} w_b \cdot \ell_{b,e}\)，其中 \(w_b\) 为 token 置信度权重。
   - 选择全局偏好专家集合 \(E^*\)，规模上限为 `cap`（通常为 top-k 的 1.5~2.5 倍）。
   - 对偏好专家施加软偏置：\(\ell'_{b,e} = \ell_{b,e} + \lambda_b \cdot \mathbf{1}[e \in E^*]\)，偏置强度基于 top-1 与第 \(k+1\) 个专家评分差动态调整。
   - 效果：提高验证批内跨 token 的专家复用率，减少实际激活专家数量，同时保持高置信 token 的路由偏好。

3. **上下文对齐自推测（Context-aligned Self-speculative Decoding）**
   - 草稿与目标共享同一 KV 缓存，草稿产生的临时 KV 更新在验证前回滚，仅接受 token 才提交。
   - 避免草稿与目标之间上下文漂移导致的误差累积，提高长序列生成中的接受率。

### 系统实现
- 基于 llama.cpp 实现，支持专家级参数 offloading（Jetson 上卸载到 SSD，RTX 4090 上卸载到 CPU 内存），并提供融合 CUDA 核以降低门控开销。
