## 摘要
线性注意力模型通过将成对token交互替换为循环状态更新，消除了softmax注意力的二次前缀计算和上下文增长的KV缓存。然而，现有的解码实现通常在生成每个token后物化并写回完整的循环状态，使得状态维护成为内存流量的主要来源，尤其是在具有大状态和多头数的模型中。本文提出了DeltaLog，一种在不改变模型语义的情况下减少此开销的循环状态解码方案。具体而言，DeltaLog将循环状态表示为稠密基础状态以及近期紧凑更新的有界日志。大多数解码步骤仅将紧凑更新因子追加到此日志，而周期性的合并步骤将累积的更新折叠回稠密基础状态。因此，模型观察到的稠密状态与急切解码相同，但大多数全状态写回被轻量追加操作所取代。我们为GDN、KDA和RWKV6实现了DeltaLog，并将其集成到原型服务栈中。在这些模型上，DeltaLog将循环状态更新内核加速高达1.86倍，将剖析的循环状态写入流量减少高达7.83倍，并相对于稠密循环基线实现了1.05至1.20倍的端到端服务加速。

## Abstract
Linear attention models eliminate the quadratic prefix computation and context-growing KV cache of softmax attention by replacing pairwise token interactions with recurrent state updates. However, existing decoding implementations often materialize and write back the full recurrent state after every generated token, making state maintenance a major source of memory traffic, especially for models with large states and many heads. This paper presents DeltaLog, a recurrent-state decoding scheme that reduces this overhead without changing the model semantics. Specifically, DeltaLog represents the recurrent state as a dense base state together with a bounded log of recent compact updates. Most decode steps append only compact update factors to this log, while periodic merge steps fold the accumulated updates back into the dense base state. Thus, the model observes the same dense state as in eager decoding, but most full-state write-backs are replaced by lightweight append operations. We implement DeltaLog for GDN, KDA, and RWKV6 and integrate it into a prototype serving stack. Across these models, DeltaLog accelerates the recurrent-state update kernel by up to $1.86\times$, reduces profiled recurrent-state write traffic by up to $7.83\times$, and achieves $1.05$--$1.20\times$ end-to-end serving speedups over dense recurrent baselines.

- **背景与问题**：线性注意力模型通过循环状态更新替代了传统Softmax注意力的二次方计算和不断增长的KV缓存，理论上能高效处理长序列。然而，论文指出现有的解码实现存在一个被忽视的低效之处：**在每个token生成后，都会急切地（eagerly）将完整的、稠密的循环状态（dense recurrent state）物化并写回显存（HBM）**。
- **核心矛盾（"状态更新税"）**：每个新token带来的逻辑更新是紧凑的（仅含`O(dk + dv)`个值），但物理上却需要读写整个`dk × dv`的状态矩阵（涉及`O(dk * dv)`个元素）。这种逻辑更新与物理内存流量之间的严重不对称，被作者称为"状态更新税"（State-Update Tax）。
- **问题的严重性**：这种开销在服务大批次（large batch）时尤为突出。论文通过实验（图2）证明，在高并发场景下，循环状态的物化开销可占到整个模型解码延迟的**44.6%（批次大小256）**，成为主要瓶颈。由于状态读写是内存密集型操作，其算术强度远低于现代GPU的机器平衡点（Roofline模型分析），因此性能受限于内存带宽而非计算能力。

## 2. 方法论：DeltaLog的延迟物化策略

- **核心思想**：DeltaLog提出一种名为**延迟物化（Deferred Materialization）**的执行策略。其核心并非改变模型语义，而是改变状态的物理表示和提交（commit）方式。它将"逻辑状态"与"物理存储"解耦，不再每次都写回全量稠密状态。
- **状态表示（Base-Plus-Log）**：DeltaLog将活动状态分解为两个部分：
    - **稠密基态（Dense Base State, S̄）**：存储最近一次合并后的历史信息。
    - **有界更新日志（Bounded Update Log）**：存储自上次合并以来的一系列紧凑更新因子（`Key`和`Value`向量）及对应的日志衰减元数据。
- **关键算法流程（附加-合并循环）**：
    - **附加阶段（Append）**：在周期内的前`M-1`步，新的更新因子`(a_t, b_t)`被简单地追加到日志中，同时更新累计对数衰减`ℓ`。稠密基态保持不变，从而避免了全状态写回。
    - **合并阶段（Merge）**：每`M`步，将所有累积的日志条目以及当前token的更新，通过公式`S̄ ← D(ℓ)S̄ + Σ D(ℓ - Λᵢ)KᵢUᵢᵀ + a_t b_tᵀ`一次性物化回稠密基态，然后清空日志。
- **状态不变量与等价性**：论文证明了无论处于附加还是合并阶段，由`D(ℓ)S̄ + Σ D(ℓ - Λᵢ)KᵢUᵢᵀ`所表示的逻辑状态，在精确算术下与急切解码的状态完全一致，保证了模型语义不变。
- **内核级实现（Tiled Kernel Decomposition）**：
    - 为高效利用GPU并行性，将每个状态沿值维度（value dimension）划分为多个瓦片（tile）。
    - 利用"共享元数据"（如key侧因子、日志长度）和"瓦片本地数据"（如dense base tile）的差异，设计了一个**三阶段执行流程（Shared ReplayPrep -> Parallel AppendDecode -> Single-writer Finalize）**，由`ReplayPrep`预计算可复用的key侧投影系数，避免重复计算，再由各个值瓦片并行执行解码和值侧日志追加。
- **算子实例化**：论文将该方法成功应用于三种不同的线性注意力模型：GDN（标量衰减）、KDA（逐键衰减）、RWKV6（逐键衰减且无delta修正），展示了方法的通用性。
