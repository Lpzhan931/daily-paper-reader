## 摘要
在边缘设备上部署大型语言模型（LLM）进行推理，由于严重的内存和带宽限制而面临挑战。尽管推测解码和混合专家（MoE）已被提出用于提高推理效率，但简单地将它们结合往往会带来过多的验证开销和较差的专家重用，限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿和执行目标。在llama.cpp中实现，S2-MoE在边缘设备上的多种MoE模型和数据集上，相比标准自回归解码实现了最高5.3倍（平均约2.0倍）的加速。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama$.$cpp, S2-MoE achieves up to $5.3\times$ speedup (about $2.0\times$ on average) over standard autoregressive decoding across diverse MoE models and datasets on edge devices. Code is available at https://github.com/angerybob/S2-MoE.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：在边缘设备（如 Jetson Orin 等）上部署大语言模型（LLM）推理，面临严重的内存容量与内存带宽瓶颈。边缘推理通常以极小的 batch size（甚至单 batch）运行，导致参数复用率低，性能主要由“每次参数访问产生的 token 数”决定，即吞吐量 ≈ 输出密度/参数密度 × 带宽。
- **两个互补路径**：推测解码（Speculative Decoding, SD）通过轻量草稿模型先生成候选 token 再由目标模型并行验证，提高“输出密度”；Mixture-of-Experts（MoE）通过稀疏激活（只激活部分专家）降低“参数密度”。两者在理论上互补。
- **核心问题**：将 SD 与 MoE 朴素结合在边缘推理中并不高效：
  - 草稿 token 在 MoE 中可能激活不同的专家集合，导致验证阶段参数复用率低、验证开销高；
  - 被拒绝的草稿 token 仍会触发专家激活，造成大量“冗余验证”；
  - 现有基于置信度的剪枝无法反映专家级别的验证成本；
  - 轻量自推测草稿（专家稀疏/层稀疏）存在保真度损失，独立上下文会导致误差随解码步长累积。
- **论文含义**：提出 S²-MoE，一种面向 MoE 模型的、训练免（training-free）的自推测解码框架，在边缘设备上同时降低冗余验证、提高专家参数复用、并保持草稿-目标模型行为对齐，从而将自推测解码的潜力真正转化为端到端加速。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

论文提出 S²-MoE，由三个互补组件构成（如图 3 所示）：

### 组件一：路由感知的自适应推测扩展（Routing-aware Adaptive Speculative Expansion）

- **动机**：在 MoE 中，两个置信度相近的草稿 token 可能触发差异很大的专家集合，导致验证成本显著不同。仅靠 token 级置信度剪枝无法反映这种差异。
- **预期收益**：对处于深度 k 的草稿 token i，其接受概率用前缀置信度 \(p_i = \prod_{j=1}^{k} p_{i,j}\) 估计，预期收益定义为 \(B_i = p_i \cdot T_{AR}\)（\(T_{AR}\) 为一次目标模型自回归解码的平均延迟）。
- **路由感知代价估计**：定义将 token i 加入已选集合 S 后的边际验证成本：
  \[
  \Delta C_{ver}(i|S) = \left| E_i \setminus \bigcup_{j \in S} E_j \right| \cdot T_{exp}
  \]
  其中 \(E_i\) 为 token i 预测激活的专家集合，\(T_{exp}\) 为引入单个额外专家的硬件校准延迟（通过轻量运行时测量或离线 profiling 获得）。总扩展代价 \(C_i = \Delta C_{ver}(i|S) + C_i^{draft}\)。
- **自适应扩展规则**：效用分数 \(U_i = B_i / C_i\)，贪心地接受 \(U_i \ge 1\) 的候选 token，直到没有候选满足条件。相比固定宽度或纯置信度剪枝，该规则同时考虑接受潜在收益和验证边际成本，推高“接受率 vs. 验证开销”的帕累托前沿。
- **实验验证**：代价模型对实际验证延迟的拟合度高（R²=0.943–0.999，MAPE=0.8%–4.5%）。

### 组件二：重用感知的专家门控（Reuse-aware Expert Gating）

- **动机**：MoE 模型相邻 token 往往激活不同专家，在并行验证下专家参数复用率低，造成高内存流量。
- **核心思想**：在验证阶段，对一组草稿 token 的专家选择进行“软对齐”，促进跨 token 的专家参数复用。
- **具体步骤**：
  1. **跨 token 专家重要性聚合**：每个 token b 有置信度权重 \(w_b\)（高置信度 token 权重更大），对每层每个专家 e 聚合重要性：
     \[
     g_e = \sum_{b \in \mathcal{B}} w_b \cdot \ell_{b,e}
     \]
     其中 \(\ell_{b,e}\) 为目标模型给出的专家门控 logits。
  2. **全局偏好专家选择**：选择“重用奖励专家”集合 \(E^* = \text{TopCap}(\{g_e\})\)，且 \(|E^*| \le cap\)（cap ≥ k），保证原始 top-k 专家始终可被选中。
  3. **软路由偏置注入**：对每个 token b，在门控 logits 上添加偏置：\(\ell'_{b,e} = \ell_{b,e} + \lambda_b \cdot \mathbb{1}[e \in E^*]\)，其中 \(\lambda_b\) 与 token b 的 top-1 专家和 top-(k+1) 专家之间的分数差成正比（即进入 top-k 的边际）。偏置主要影响边界专家，不破坏强偏好专家的相对顺序。
  4. **融合实现**：作为轻量融合 CUDA kernel 实现，开销可忽略。该偏置是“保守的”——实际验证成本不会超过未加偏置时的估计。
- **效果**：在图 5 的示例中，专家激活数量从 6 个降至 4 个，低置信度 token 更倾向于迁移到重用专家，高置信度 token 保留其原始选择。

### 组件三：上下文对齐的自推测解码（Context-aligned Self-speculative Decoding）

- **动机**：自推测草稿（如专家稀疏）在独立维护上下文时，误差会逐解码步累积，导致草稿与目标分布逐渐发散（KL 散度随步数增大）。
- **核心思想**：让草稿模型与目标模型共享同一个 KV Cache：
  - 目标模型先处理 prompt 并建立 KV Cache；
  - 草稿生成阶段直接读取该共享上下文，而非维护独立的解码历史；
  - 草稿产生的 KV 更新视为临时状态，在验证前回滚；
  - 只有被接受的 token 才会写入共享缓存。
- **效果**：草稿误差被限制在单个投机步内，不跨迭代累积；实验显示上下文对齐显著抑制了 KL 散度的增长，接受率提升最高达 79%（OLMoE/GSM8K）。

## 6. 论文的主要结论与发现

- S²-MoE 在边缘设备上显著优于标准自回归解码和多种 SD 基线：
  - Jetson Orin 上加速 1.3×–5.3×（平均约 2.0×）；
  - RTX 4090 上加速 1.2×–2.9×；
  - 相比朴素自推测基线（ES/LS），S²-MoE 的增益尤其显著，说明其有效解决了“低专家复用 + 高冗余验证”这两个核心瓶颈。
- 上下文对齐（共享 KV Cache）能有效防止草稿误差跨步累积，是自推测解码高效运行的关键基础。
- 路由感知的自适应扩展比固定宽度或纯置信度剪枝在“接受长度 vs. 验证成本”之间的权衡上严格更优。
- 重用感知的门控在几乎不损失输出质量的前提下大幅提升专家参数复用率：
  - 专家复用率提升 26%–33%；
  - 任务准确率与长上下文指标与原始模型基本持平（PPL 比 1.012–1.013，Top-1 一致性 > 89%）。
- S²-MoE 是 training-free 的，无需额外训练或微调，可直接应用于现有 MoE 模型。

4. **代价模型可解释且硬件校准**：将“专家激活”转换为“硬件延迟单位”，使期望收益与验证成本可同单位比较；拟合精度高（R²>0.94）。
5. **工程落地完整**：基于 llama.cpp 实现，支持专家级 offloading（适配 MoE 在边缘场景的实际需求），并处理了 Jetson 统一内存与 RTX 4090 分离内存两种硬件拓扑。
6. **实验规范且覆盖面广**：107 个基线+方法组合 × 多种任务；统一超参数、统一框架、公开 checkpoint，对比公平性较好；同时报告了原始吞吐量、接受长度、加速比，透明可复现。

## 8. 不足与局限

1. **实验硬件覆盖有限**：仅评估了 Jetson Orin（16/32/64GB）和 RTX 4090，未覆盖更多移动端 SoC（如 Apple Silicon、高通平台）或更严格的低功耗场景（如 8GB 内存以下设备）。
2. **缺少对超大 MoE 模型的验证**：最大的 GPT-OSS-120B 在 Jetson 上主要依赖 SSD offloading，未测试更大规模（如 300B+）MoE 模型在真实边缘设备上的行为。
3. **LS 基线覆盖不完整**：Qwen3 和 GPT-OSS 上未运行 LS 基线，虽作者给出了合理性说明，但该数据缺失会削弱跨模型对比的一致性。
4. **Cascade 基线实现问题**：Cascade 的官方实现未开源，论文中由作者自行实现，可能存在实现偏差；且 Cascade 在 4090 上的表现显著低于原文报告（如某些任务仅 0.4×–0.6×），该结果是否代表 Cascade 真实能力存在疑问。
5. **GPT-OSS 的质量评估不完整**：省略了 WikiText-2 的 KL/PPL/Top-1 等指标（受 Harmony 训练格式限制），导致无法完全量化 S²-MoE 中重用感知门控对该模型的输出扰动程度。
6. **重用感知门控的非严格无损性**：虽然实验显示质量差异很小（PPL 比 ≤1.013），但该方法在原理上仍是有偏路由，在极端分布偏移或长尾任务中可能引入未知的质量退化风险。
7. **未讨论多请求/并发场景**：论文聚焦单 batch 边缘推理，未涉及 batch size >1 时方法的行为（尽管这符合其边缘定位，但作为局限仍值得提及）。
8. **工程资源的披露缺失**：未说明实现、调试和评测所消耗的总计算资源（GPU 小时数等），不利于复现或估计复现成本。
