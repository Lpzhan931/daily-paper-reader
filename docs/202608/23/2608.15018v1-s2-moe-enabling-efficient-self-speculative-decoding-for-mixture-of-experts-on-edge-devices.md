## 摘要
由于严重的内存和带宽限制，在边缘设备上部署大型语言模型（LLM）进行推理具有挑战性。虽然推测解码和混合专家（MoE）已被提出用于提高推理效率，但简单地将它们结合往往会导致过多的验证开销和较差的专家复用，从而限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少了冗余验证，通过复用感知的专家门控提高了验证效率，并通过共享上下文实现了草稿与目标执行的对齐。在llama.cpp中实现，S2-MoE在边缘设备上的多种MoE模型和数据集上，相较于标准自回归解码实现了高达5.3倍的加速（平均约2.0倍）。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama.cpp, S2-MoE achieves up to 5.3x speedup (about 2.0x on average) over standard autoregressive de?coding across diverse MoE models and datasets on edge devices.Code is available at https://github.com/angerybob/S2-MoE.

## 1. 论文的核心问题与整体含义

### 研究动机与背景
- **边缘设备 LLM 推理瓶颈**：在边缘设备上部署大语言模型（LLM）推理，面临严重的内存和带宽限制。边缘推理通常以小批量甚至单批次运行，参数重用率低，吞吐量主要受限于内存带宽。
- **关键效率分解**：论文将吞吐量分解为 `Output Density（每迭代生成 token 数） / Parameter Density（每迭代访问参数量）× Bandwidth`，由此引出两类优化路径：
  - **推测解码（SD）**：通过轻量草稿模型生成多个 token，再由目标模型并行验证，增加输出密度。
  - **MoE 稀疏激活**：每次仅激活部分专家，降低参数密度。
- **核心矛盾**：SD 与 MoE 在边缘场景下难以有效结合：
  - MoE 中不同草稿 token 可能激活不同专家，验证时参数复用率低，验证开销剧增。
  - 被拒绝的草稿 token 仍可能触发大量专家激活，造成大量冗余计算。
  - 现有置信度引导的剪枝（如 EAGLE-3）只考虑 token 级置信度，无法反映专家级验证成本。

## 2. 论文提出的方法论

### 核心思想
S2-MoE 是一个**训练免费、端到端的自推测解码框架**，通过三个互补组件解决 MoE 场景下推测解码的三大挑战：

### (1) 路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）
- **动机**：MoE 中草稿 token 的验证成本取决于其激活的专家集合，不同候选 token 即使置信度相似，验证开销也可能差异显著。
- **期望收益**：对于草稿 token \(i\)，其接受概率估计为前缀置信度 \(p_i = \prod_{j=1}^{k} p_{i,j}\)，期望收益为 \(B_i = p_i \cdot T_{\text{AR}}\)（其中 \(T_{\text{AR}}\) 为目标模型一步解码的延迟）。
- **路由感知成本估计**：边际验证成本定义为新增专家的数量 × 单专家延迟：
  \[
  \Delta C_{\text{ver}}(i|S) = \left| E_i \setminus \bigcup_{j \in S} E_j \right| \cdot T_{\text{exp}}
  \]
  该成本模型利用草稿阶段的路由信号预测验证开销，与实测延迟良好拟合（\(R^2 = 0.943–0.999\)，MAPE = 0.8–4.5%）。
- **自适应扩展策略**：以效用函数 \(U_i = B_i / C_i\) 为准则，贪心接纳 \(U_i \ge 1\) 的候选扩展节点，同时兼顾接受概率与验证开销。

### (2) 复用感知专家门控（Reuse-aware Expert Gating）
- **动机**：MoE 中相邻 token 常激活不同专家，并行验证时专家参数复用率低，内存带宽压力大。
- **跨 token 专家重要性聚合**：按 token 置信度加权，聚合专家门控 logits：
  \[
  g_e = \sum_{b \in B} w_b \cdot \ell_{b,e}
  \]
  高置信度 token 的专家偏好获得更高权重。
- **全局偏好专家选择**：通过 TopCap 操作选出少量"复用奖励专家"（cap ≥ k），限制偏置范围，避免过度干扰原始 top-k 路由结构。
- **软路由偏置**：为每个 token 的候选专家注入可微偏置，偏置强度基于 token 自身的 top-1 与第 (k+1) 位专家的路由分数差距动态调节，主要影响边界专家，保持高置信 token 的主导路由不变。
- **高效融合实现**：利用轻量级 CUDA kernel 实现，额外开销可忽略。

### (3) 上下文对齐自推测解码（Context-aligned Self-speculative）
- **动机**：独立上下文中草稿模型预测误差会逐步累积，导致与目标模型的 KL 散度随解码步数急剧增长，降低接受率。
- **方案**：草稿与目标模型共享同一 KV Cache。草稿的 KV 更新为临时状态，验证前回滚，仅接受 token 的 KV 被提交。从而将草稿误差限制在单个推测步内，防止跨迭代传播。

## 7. 优点

### 方法层面
- **训练免费、即插即用**：无需额外训练草稿模型或辅助头，可直接适配现有 MoE 推理管线。
- **深入洞察 MoE 特有瓶颈**：首次系统性地将验证成本建模为"新增专家数"的函数，而非简单 token 数目，更符合 MoE 推理的真实开销。
- **成本模型与硬件校准**：将专家激活数转化为硬件标定的延迟单位，使"收益 vs. 成本"的权衡在物理语义上可比较。
- **上下文对齐机制简洁有效**：通过共享 KV Cache 加临时回滚，低成本地抑制草稿误差累积，显著提升接受率。
- **专家级卸载实现**：针对 MoE 参数访问模式优化的卸载粒度，优于 llama.cpp 原生层级卸载。
- **完整系统实现**：在 llama.cpp 中端到端集成，代码开源，可复现性强。

### 实验层面
- **多维度评估**：效率 + 质量 + 消融 + 超参敏感性，覆盖面广。
- **硬件覆盖合理**：同时包含边缘 SoC 和离散 GPU，验证方法在不同内存约束下的泛化能力。
- **与最强基线公平对比**：使用官方 EAGLE-3 checkpoint 和 llama.cpp 实现，Cascade 按论文描述复现，减小对比偏差。

## 8. 不足与局限

### 实验覆盖
- **基线覆盖不完整**：LS 基线仅在小模型（DeepSeek、OLMoE）上评估；GPT-OSS 缺少分布一致性指标，与其他模型对比不完全统一。
- **未与最新 MoE 推理优化全面对比**：论文虽提到与现有专家预取/缓存方法的正交性，但未实际对比此类系统级优化方案。
- **批量规模单一**：实验仅覆盖小批量（edge 场景），未评估中等或大批量场景下 S2-MoE 是否依然有效（论文引文中也指出 SD 在 MoE 中等批量下有不同表现）。

### 偏差风险
- **模型家族有限**：仅覆盖 4 种 MoE 架构；EAGLE-3 在一些非 MoE 模型（如 Llama 系列）表现更好，S2-MoE 在更大范围的 MoE 架构上的普适性尚未验证。
- **自建成本模型的泛化性**：\(T_{\text{exp}}\) 需离线 profiling，不同硬件上重新校准的成本和误差未充分讨论。
- **路由偏置质量影响的长期累积效应**：虽然单步有界，但对超长生成（如长文档）的累积质量影响评估不足。
- **GPT-OSS 的质量评估有特殊处理**：因模型本身训练格式特殊（Harmony），跳过 PPL/KL 是合理的，但也使得不同模型间质量指标可比性下降。

### 应用限制
- **仅适用于推理阶段**：不适用于训练或微调阶段的加速。
- **依赖 MoE 结构可得性**：方法需要访问各层门控 logits 与专家路由信息，对某些封装较深的部署框架可能不友好。
- **草稿专家数仍需人工设定**：draft top-k 与 cap 存在权衡，需要针对不同模型手动调参，虽提供敏感性分析但缺乏自适应选择机制。
