## 摘要
尽管二值量化在理论上为大语言模型（LLMs）带来了极致的压缩与加速，但现有研究往往忽视了专用硬件内核的必要性，因而由于持续依赖昂贵的浮点运算或运行时反量化开销，未能释放全部的加速潜力。为弥补这一差距，我们提出了 FluxBin（基于二进制基数的灵活查找表超低位宽执行），这是一种算法-内核协同设计，将训练后量化与高度优化的 CUDA 内核相结合。在算法层面，我们引入了解耦行列二进制分解以增强表示能力，同时保持硬件效率，并辅以 Hessian 引导的显著性感知混合基来保留关键信息。在内核层面，我们实现了一种基于尺度融合的查找表构建方法，以减少浮点运算，并采用虚拟列映射将不规则、稀疏且显著的矩阵转换为稠密执行。大量评估表明，FluxBin 在不同模型架构上可实现高达 5.92 倍的加速和 10.19 倍的能耗节省，同时提供与深度微调方法相当的精度。这有效地使得 70B 规模模型能够在单张 A100 GPU 上部署，并减少 4 倍内存。代码可在 https://github.com/nicyyyy/FluxBin 获取。

## Abstract
While binary quantization theoretically promises extreme compression and acceleration for Large Language Models (LLMs), existing research often overlooks the necessity of specialized hardware kernels, thus failing to unleash the full acceleration potential due to persistent reliance on expensive floating-point arithmetic or runtime dequantization overheads. To bridge this gap, we propose FluxBin (\textbf{F}lexible \textbf{L}UT-based \textbf{U}ltra-low-bit e\textbf{X}ecution with \textbf{Bin}ary bases), an algorithm-kernel co-design that synergizes post-training quantization with a highly optimized CUDA kernel. Algorithmically, we introduce Decoupled Row-Column Binary Decomposition to enhance representational capacity while maintaining hardware efficiency, complemented by a Hessian-guided saliency-aware hybrid bases that preserve critical information. At the kernel level, we implement a Lookup Table Building Approach with Scale Fusion to reduce floating-point arithmetic, featuring a Virtual Columnar Mapping that transforms irregular, sparse, and salient matrices into dense execution. Extensive evaluations demonstrate FluxBin achieves up to $5.92\times$ speedup and $10.19\times$ energy savings across diverse model architectures, delivering comparable accuracy to heavily fine-tuned methods. This effectively enables the deployment of 70B-scale models on one single A100 GPU with a $4\times$ memory reduction. Code is available at https://github.com/nicyyyy/FluxBin.

- **研究背景**：大语言模型（LLMs）规模急剧膨胀，带来严重存储与带宽压力。训练后量化（PTQ）是标准解决方案，其中二值量化（binary quantization）将压缩推向极致，理论上可实现最大效率。
- **核心问题**：现有二值量化LLM研究多聚焦算法精度（如QBB、PTQTP、DB-LLM等），但普遍忽视专用硬件内核的必要性，导致三大局限：
  - **局限一**：未能利用免乘法硬件潜力——多数方法在推理时仍需反量化为FP16，位运算的硬件优势未充分利用；
  - **局限二**：显著性粒度与硬件效率难以两全——非结构化方法有稀疏内存访问与元数据开销，粗粒度方法则造成比特冗余；
  - **局限三**：低位宽内核实现效率低下——现有W4A16方法虽压缩权重，但动态反量化引入显著运行时开销，未真正发挥加法运算特性。
- **研究意义**：FluxBin旨在弥合理论压缩与实际推理加速之间的鸿沟，通过算法-内核协同设计，将二值表示真正转化为可落地的端到端加速。

### 2. 方法论：核心思想、关键技术细节

FluxBin是一个算法-内核协同设计框架，包含两大核心模块：

#### （1）算法层面：FluxBin量化方法

- **解耦行列二进制分解（Decoupled Row-Column Binary Decomposition）**：
  - 将稠密权重矩阵 W ∈ R^{M×N} 近似为多个二进制基的线性组合，每个基使用Hadamard积结合行缩放向量 α_r 与列缩放向量 α_c：
    \[
    \hat{W}^{(k)} = \left(\alpha_r^{(k)} \alpha_c^{(k)\top}\right) \odot B^{(k)},\quad B^{(k)} \in \{-1,+1\}^{M\times N}
    \]
  - 相比传统的仅行缩放方法，引入列缩放可更好捕捉各向异性的权重分布；
  - 通过交替最小化求解最优缩放因子（式5），对于 K_b ≥ 2 的情况采用联合优化而非贪婪序贯提取，用穷举 2^{K_b} 种符号组合确定最优二值基（式6）。

- **Hessian引导的结构性显著性搜索（Structural Saliency Search）**：
  - 基于最优脑量化（OBQ）框架，利用逆Hessian矩阵 H^{-1} 近似权重敏感度；
  - 定义列方向显著性分数 S_j = Σ_i W_{ij}^2 [H^{-1}]_{jj}^2，将逐元素误差聚合为累积列分数；
  - 按组大小 g 划分列，每组选取 s 个最大显著性列构成掩码 M。

- **显著性感知混合基（Salient-Aware Hybrid Bases）**：
  - 最终量化权重 = 全局基近似 + 基于残差的显著性精炼（仅作用于掩码 M 覆盖的关键列）：
    \[
    \hat{W} = \sum_{k=1}^{K_b} Q(W; \Theta_k) + \sum_{k=1}^{K_s} Q(R_{\text{base}}; \Phi_k) \odot M
    \]
  - 是一种纯PTQ方法，无微调、无蒸馏。

#### （2）内核层面：LUT-based GEMV Kernel

- **LUT构建与尺度融合（LUT-BSF, Lookup Table Building with Scale Fusion）**：
  - 将输入维度划分为大小为 μ 的子向量，将列缩放因子 α_c 直接融合到LUT条目中（式14），从而将 α_c 从GEMV主循环中解耦，消除相关浮点运算；
  - 推理时直接用 μ-bit 二值权重模式作为内存地址，检索预计算的部分和，以查表替代乘法运算。

- **虚拟列映射（VCM, Virtual Columnar Mapping）**：
  - 受操作系统内存虚拟化启发，将逻辑上稀疏的显著性列重映射为物理稠密矩阵（式12），同时维护 Isal 翻译层在运行时收集激活与缩放因子（式13）；
  - 将不规则、稀疏、显著的矩阵转换为稠密执行，使全局基与显著性精炼分支可统一内核执行，实现合并内存访问。

- **矩阵分块（Matrix Tiling）**：将B划分为 M_{tile} × N_{tile} 瓦片映射到线程块，块内共享LUT构建结果，降低全局内存访问。

### 6. 主要结论与发现

- **大幅加速**：FluxBin在LLaMA-2-7B上达到254.39 tokens/s，实现最高5.92×端到端加速；解码阶段（BS=1）获得6.3×–6.6×吞吐提升；
- **显著节能**：相比FP16基线实现10.19×总能耗降低，平均功率从~225W降至~115W（13B模型）；
- **精度保持**：训练-free方法达到与深度微调方法（如QuIP#、AQLM）相当的精度。在LLaMA-2-7B上2b-s16-g128达到59.15%平均准确率，直逼QuIP#的59.41%；
- **内存高效**：最高4×内存降低，使LLaMA-2-70B（FP16需超过80GB）可在单A100上以2-bit配置运行（20.2GB）；
- **跨架构鲁棒性**：在LLaMA-3.1-70B上，FluxBin-2b-s16-g128比AQLM精度高+17.5%，同时在Qwen3（含GQA）上保持高效；
- **加速来源**：三方面——减少内存流量、减少并简化运算（μ/K_b = 4×复杂度降低）、用SRAM查找替代ALU密集型反量化路径；
- **VCM策略有效性**：VCM将混合精度配置的吞吐量维持在纯2-bit基线水平，其翻译开销可忽略不计。

### 7. 优点

- **算法-内核协同设计**：突破性思维——不将量化算法与内核优化分离，而是从端到端视角联合设计，有效弥合了"理论压缩"与"实际加速"之间的鸿沟；
- **纯PTQ框架**：无训练、无蒸馏，可快速部署，同时精度媲美需迭代微调的方法；
- **解耦行列二进制分解**：引入列缩放捕捉各向异性权重分布，相比行缩放-only方法提升表示能力，且在数学上有闭式解，优化高效；
- **Hessian引导的显著性混合基**：将稀疏显著性保护以结构化方式实现，以极小存储开销（s/g=6.25%）换取显著精度提升，兼顾细粒度和硬件效率；
- **LUT-BSF尺度融合**：巧妙将列缩放折叠进LUT预计算中，消除GEMV主循环中的浮点运算；
- **VCM虚拟列映射**：将稀疏运算等价转化为稠密运算，统一内核执行路径，实现合并内存访问，消除访存不规则性；
- **加速是批大小无关的**：得益于查表计算约简特性（而非依赖矩阵乘法），使FluxBin在自回归解码和大批量场景下都能保持优势；
- **实验报告详细**：附录包含严谨的数学推导（最优缩放因子、二值基优化）、复杂度分析、存储分析、共享内存占用分析、tiling参数研究等，工程可复现性高。

### 8. 不足与局限

- **共享内存（SRAM）约束**：LUT大小随子向量大小指数增长（2^μ），且随每块批大小线性增长。A100的164KB/SM足够支持最优配置（μ=8），但在共享内存较小的硬件上需降低μ或批大小，可能影响最优性能；
- **纯PTQ的优化上限**：尽管优于现有PTQ方法、媲美微调基线，但与任务特定深度迭代微调的方法间仍存在微小精度差距；
- **校准过拟合风险**：校准样本数超过512时出现过拟合（性能反而下降），说明Hessian估计对校准集分布敏感，可能影响跨域泛化；
- **实验平台单一**：全部实验仅在A100上完成，未验证在V100、H100、A10/消费级GPU或边缘设备上的表现；
- **对比公平性问题**：基线方法结果多引用各自原文数据，而非统一环境复测，速度与精度数据可能存在软硬件环境差异；
- **未探索更大规模**：最大验证模型为70B，未在更大模型（如LLaMA-3.1-405B）或多GPU分布推理场景下验证；
- **校准数据多样性不足**：仅使用C4单一来源，未验证在不同领域或语言数据上的量化鲁棒性。
