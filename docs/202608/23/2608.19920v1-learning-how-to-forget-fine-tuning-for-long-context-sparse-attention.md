## 摘要
许多先前的工作通过稀疏注意力解决了键值（KV）缓存选择和压缩问题，以便在没有过多硬件预算的情况下实现Transformer语言模型的长上下文推理。我们提出了一种使用稀疏注意力对模型进行微调的新方法。它适用于任何KV缓存策略，在中等硬件预算下运行（例如，单个具有40 GB内存的Nvidia A100 GPU），并允许模型与策略共同适应，通常优于使用精确注意力（序列并行）训练的模型。我们还提供了H2O稀疏注意力（我们实验中领先的策略）的高效实现，并带有专门的缩放点积注意力内核支持。KeysAndValues（https://github.com/awslabs/keys_values）是一个用于长上下文推理和微调的新型开源库，为本文讨论的所有方法提供了易于使用且高性能的代码。

## Abstract
A lot of prior work addressed key-value (KV) cache selection and compression by sparse attention to enable long-context inference for transformer language models without excessive hardware budgets. We provide a new method for fine-tuning models with sparse attention. It works for any KV cache policy, runs on a moderate hardware budget (e.g., a single Nvidia A100 GPU with 40 GB RAM), and allows the model to co-adapt with the policy, often outperforming models trained with exact attention (sequence parallelism). We also provide an efficient implementation of H2O sparse attention (the leading policy in our experiments) with dedicated scaled dot product attention kernel support. KeysAndValues (https://github.com/awslabs/keys_values), a new open source library for long-context inference and fine-tuning, provides easy-to-use and performant code for all methods discussed here.

## 1. 核心问题与研究动机

- **背景**：现代大语言模型需要处理极长上下文（如工具调用、思维链推理、多轮对话），但标准 Transformer 推理的 KV 缓存随上下文长度线性增长，硬件开销巨大（即使几十万 token 的 KV 缓存也远超模型权重大小）。
- **现有方案与瓶颈**：稀疏注意力（Sparse Attention）通过固定大小的 KV 缓存 + 逐出（eviction）策略来压缩缓存，已被大量研究（H2O、SnapKV、Quest 等）。然而，现有长上下文微调方法主要有两类问题：
  - 要么将注意力近似限制为特定形式（如 LongLoRA、NSA/DSA），灵活性差，且仍需完整 KV 缓存；
  - 要么使用精确注意力 + 序列/上下文并行（SP/CP）训练，但**推理时的逐出逻辑在训练中从未被模型感知**，导致训练与推理条件不一致，稀疏推理性能显著下降。
- **核心问题**：能否在中等硬件预算下，让模型与特定的 KV 缓存策略**共同适应（co-adapt）**——即在微调时就把目标稀疏注意力策略嵌入训练过程，使模型"学会遗忘"不重要的缓存内容？
- **整体意义**：论文给出肯定答案，提出一种**与缓存策略无关**的稀疏注意力微调方法，在单张 A100 40GB 级别硬件上即可运行，并在多个长上下文基准上常常优于用序列并行（精确注意力）训练的模型。作者同时开源了 `KeysAndValues` 库。

## 2. 方法论

### 2.1 稀疏注意力与 KV 缓存策略

- 每层 KV 缓存为固定大小数组 `(B, H_k, N_C, d_h)`，`N_C` 为缓存长度；超出后由策略 `π_l(b,h,t)` 决定新 token 写入哪个槽位。
- 推理时序列被切分为 chunk：首个 prefill chunk 长度 `N_C`，后续 chunk 长度 `S < N_C`；缓存内存与序列总长度 `N` 无关。
- 本文改进的 H2O 策略变体：
  - **h2o**：逐 batch 位置独立计分与逐出；
  - **h2o norm**：归一化累计得分（避免长期驻留条目因累计项多而占便宜）；
  - **h2o orig**：复现原版 H2O（得分跨 batch 求和，逐出不区分 batch）；
  - 另含简易策略 **lastrec（lr）** 与 **smart lastrec（slr）**（自适应保护前缀长度）。

### 2.2 微调方法的核心技术

- **总体思路**：在训练时直接运行目标稀疏注意力策略（含逐出决策），使模型适应推理时的记忆限制；所有策略决策记录在 **replay log** 中，反向传播时重放，**避免对策略本身求导**。
- **嵌套激活检查点（nested activation checkpointing）**：外层按层（layer）循环、内层按 cell 循环（cell 为 chunk 分组，`k = ⌊αN_C/S⌋`，默认 α=1），边界信息（层输入、头部梯度、KV 缓存检查点）卸载到 CPU，GPU 上每次只保留单个 cell 的计算图。
- **线性 KV 缓存递推的 delta 编码**：相邻 chunk 的缓存 `keys` 与 `keys'` 仅差 `S·D` 个值，满足
  `keys' = scatter(keys, index, key_new)`，反向递推为
  `keys = scatter(keys', index, delta_key)`，其中 `delta_key = gather(keys, index)`。
  利用 **PyTorch autograd saved tensors hooks** 的 pack/unpack 机制，将 KV 缓存节点替换为 δ 编码存储，使单次 autograd 的 GPU 内存从 `O(k·N_C·D)` 降到 `O(N_C·D)`，与推理相当。
- **其他细节**：
  - KV 缓存 8-bit 量化（torchao）；
  - 分 chunk 与 cell 的处理顺序为"外层 cell、中层 layer、内层 chunk"；
  - 前向共跑三次：首次记录 replay log 并 checkpoint 层输入，第二次为每层重建缓存检查点，第三次在 autograd 内完成 cell 前向与反向。

### 2.3 H2O 高效实现改进

- 现有 FlashAttention 系 SDPA 内核不返回**总和注意力权重**（H2O 计分所需）；作者编写 Triton 代码在 FlashInfer SDPA 内核旁返回该信息，并提供 FlexAttention 双调用方案作为基线。
- 针对稀疏注意力的因果掩码（按 `token_pos` 非单调排列），通过排序重排 KV 后再用标准因果掩码处理。

## 6. 主要结论与发现

- **模型应与推理时使用的缓存策略共同训练**：在稀疏注意力推理下，用本文方法微调的模型常优于用精确注意力（序列并行）训练的模型，尤其在输出需要简短、精确的任务（分类、UUID 检索、单项 QA）上差距显著。
- **sp 的关键失败模式**：用精确注意力训练、稀疏推理的模型输出普遍过长（R 常为 30–60 倍，`p128`≥90%），包含大量随机内容；本文方法训练的模型 `R≈1`、`p128≈0`，学会了正常终止生成。SubEM 指标对多余乱码不敏感，掩盖了 sp 的退化。
- **H2O 是实验中整体最强的策略之一**，且高效实现后其额外开销仅比简单 baseline（lr/slr）高 2–4%；但不同 H2O 变体排序因数据集而异，`h2o orig`（跨 batch 计分）在 json kv 上明显失败。
- **效率结论**：本文方法比精确序列并行训练仅贵约 30%（S=2048），却获得策略协同适应能力；稀疏注意力在推理延迟上与 RingAttention/SP 仍有差距（作者分析了原因并给出 SDPA 内核改进建议）。

## 7. 优点与亮点

1. **通用性**：方法完全与 KV 缓存策略解耦（通过 replay log + delta 编码），任何选择/压缩策略均可直接嵌入训练。
2. **低硬件门槛**：单卡 A100 40GB 即可微调 4B 模型的长上下文稀疏注意力，打破 SP/CP 需要多卡分片的限制，多卡可灵活用于增大 batch 或扩大模型。
3. **内存工程巧妙**：嵌套激活检查点 + 线性递推的 delta 编码 + autograd saved tensors hooks 三者的组合，将每步 autograd 的 KV 内存压到 `O(N_C·D)`，是一次原创性的系统级工程贡献。
4. **H2O 工程改进**：首次在 FlashInfer SDPA 内核旁高效返回总和注意力权重，显著缩小 H2O 与 SotA 推理库的延迟差距。
5. **实验分析深入**：不仅报告指标，还定量（输出长度比、p128）和定性（随机样例）地揭示了失败模式，对指标盲区（SubEM 对乱码不敏感）有清醒讨论。
6. **开源贡献**：发布 `KeysAndValues` 库，提供统一的多头注意力接口（集成 FlexAttention/FlashInfer/FlashAttention），降低稀疏注意力研究门槛。

## 8. 不足与局限

- **实验覆盖有限**：仅在单一模型（Qwen3-4B）、单一微调方式（LoRA）上验证，未测试不同规模模型、全参数微调或其他架构（如 MoE）；结论的外推性有待验证。
- **部分数据集结果不占优**：Table 1 中 4 个 RAG 数据集结果混合，sp 在 nq 和 hotpot qa 上仍更优；论文承认对 H2O 变体的排序"尚无定论"。
- **稀疏注意力推理延迟**：作者明确承认在同等硬件预算下，稀疏注意力的顺序决策特性使其推理延迟仍可能逊于 RingAttention/SP；当前实现尚未做充分的内核融合与异步 CPU 卸载。
- **机制脆弱性**：autograd saved tensors hooks 的"非选择性"匹配机制依赖注释列表与指纹匹配，存在漏匹配/误匹配风险（作者承认安全但不够鲁棒，需靠指纹大小避免误匹配）；PyTorch 内部算子融合可能导致节点不会触发 pack hook。
- **指标盲区**：SubEM 等指标容忍任意长度的额外输出，掩盖了"输出乱码"类退化；作者虽指出该问题，但未提出修正后的评估协议。
- **其他**：`h2o orig` 在 json kv 上的崩溃说明策略选择仍需针对任务调优；Q-Hitter 组合量化的变体效果一致更差，但未深入分析原因；训练数据本身"目标极短"这一信号被 us 捕获，若目标任务本身需要长输出，方法是否仍有效未验证。
