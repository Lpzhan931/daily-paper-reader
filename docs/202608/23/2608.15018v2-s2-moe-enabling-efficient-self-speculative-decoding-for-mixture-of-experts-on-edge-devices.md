## 摘要
由于严重的内存和带宽限制，在边缘设备上部署大型语言模型（LLM）进行推理具有挑战性。虽然推测解码和混合专家（MoE）已被提出以提高推理效率，但简单地将它们结合通常会招致过多的验证开销和较差的专家重用，限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿与目标执行。在llama.cpp中实现，S2-MoE在边缘设备上的多种MoE模型和数据集上，相比标准自回归解码实现了高达5.3倍的速度提升（平均约2.0倍）。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama$.$cpp, S2-MoE achieves up to $5.3\times$ speedup (about $2.0\times$ on average) over standard autoregressive decoding across diverse MoE models and datasets on edge devices. Code is available at https://github.com/angerybob/S2-MoE.

## 2. 方法论：核心思想、关键技术细节与流程

S²-MoE 由三个互补组件构成，整体流程为：草稿阶段（上下文对齐的自推测）→ 自适应扩展草稿树 → 重用感知门控 → 目标模型并行验证。

### 2.1 路由感知的自适应推测扩展（Routing-aware Adaptive Speculative Expansion）

- **核心思想**：在 MoE 验证中，候选 token 的质量不仅取决于接受概率，还取决于其引入的专家激活成本。因此用“效用（utility）”而非单纯置信度来指导扩展。
- **预期收益**：Ｂᵢ = pᵢ · T_AR，其中 pᵢ 为前缀置信度（该 token 被接受的概率），T_AR 为单步自回归解码延迟。
- **边际验证成本**：ΔC_ver(i|S) = |Eᵢ ∖ ∪_{j∈S} Eⱼ| · T_exp，即 token i 新增的专家数乘以单位专家引入延迟，将专家激活转化为硬件校准的延迟单位。
- **效用公式**：Uᵢ = Bᵢ / Cᵢ = (pᵢ · T_AR) / (ΔC_ver(i|S) + C_draft_i)。当 Uᵢ ≥ 1 时贪婪扩展候选，即预期收益超过估计成本才扩展。
- **成本模型可靠性**：该估计使用草稿阶段的路由信号（与目标路由高度相关），离线校准后对实测验证延迟的 R² = 0.943–0.999，MAPE = 0.8%–4.5%。

### 2.2 重用感知的专家门控（Reuse-aware Expert Gating）

- **核心思想**：MoE 模型连续 token 常路由到不同专家，验证时专家激活分散、参数重用低。通过**软性偏置路由**，将低置信度 token 的专家选择向已重复激活的“重用奖励专家”靠拢。
- **跨 token 专家重要性聚合**：gₑ = Σ_{b∈B} w_b · ℓ_{b,e}，其中 w_b 为 token 置信度权重（高置信度 token 权重更高），ℓ 为专家门控 logits。
- **全局优选专家选择**：E★ = TopCap({gₑ})，约束偏置范围（cap ≥ k），保证原 top-k 专家仍可选，避免过度集中。
- **软路由偏置**：ℓ′_{b,e} = ℓ_{b,e} + λ_b · 1[e ∈ E★]，λ_b 与 top-1 专家和 k+1 名专家之间的分数差成比例，主要影响 top-k 边界的边缘专家，不过度扰动强势路由。
- **优势**：将示例中验证激活专家数从 6 个降至 4 个，且偏置使实际验证成本不高于原始路由的估计值（成本估计保守）。实现为轻量级 CUDA 融合核，开销可忽略。

### 2.3 上下文对齐的自推测解码（Context-aligned Self-speculative Decoding）

- **问题**：草稿与目标各自维护独立上下文时，草稿预测误差会跨解码步骤累积，导致 KL 散度随生成增长快速增大（图 2(g)）。
- **方案**：草稿与目标**共享统一 KV cache**——目标先处理 prompt 建立缓存，草稿直接读取共享上下文；草稿的 KV 更新为临时态，验证前回滚，仅接受的 token 提交至共享缓存。
- **效果**：将草稿误差限制在当前推测步骤内，不跨迭代传播，显著提升接受率（GSM8K 上最多提升 79%）。

## 6. 主要结论与发现

- **端到端加速**：S²-MoE 在 Jetson Orin 上较自回归解码实现 **1.3×–5.3× 加速**，RTX 4090 上 **1.2×–2.9× 加速**，平均约 2.0×；在所有模型、任务、内存配置下**一致优于** ES、LS、EAGLE3、Cascade 等基线。
- **对比发现**：
  - 朴素自推测基线（ES/LS）在紧内存预算下常无法超越自回归解码，印证了 MoE 验证开销与专家重用问题的严重性；
  - EAGLE-3 性能随模型族波动大，S²-MoE 虽免训练却更稳定；
  - Cascade 依赖历史效用信号做决策，S²-MoE 的 token 级路由感知成本估计更直接，收益更一致，且紧内存下优势更明显。
- **组件贡献**：上下文对齐将接受率最高提升 79%；自适应扩展在保持接受长度的同时显著降低有效验证成本；重用感知门控将专家重用率提高 25.99%–33.09%。三组件互补叠加，缺一不可。
- **质量保持**：任务准确率差异小且无系统性方向；长上下文分数与原模型相当；PPL 比 1.012–1.013、Top-1 一致率 >89%，表明输出扰动有界且无可见退化。

## 7. 优点

- **问题刻画深入**：通过吞吐量分解公式（输出密度/参数密度）和多项针对性测量（图 2 的逐层冗余、置信度分布、复用率、KL 漂移），清晰定位了 MoE × SD 结合低效的根因。

- **成本建模严谨**：将专家激活转换为硬件校准延迟的边际成本模型，拟合精度高（R²≥0.943），且 gating 偏置使成本估计保持保守。
- **工程实现完整**：实现了专家级参数卸载（解决层级卸载在 MoE 中对不上的问题）、融合 CUDA 核与共享 KV

- **鲁棒性与普适性**：在 4 种不同规模/激活模式的 MoE 模型、7 类任务和多种内存预算下均一致提升，表明方案并非针对某一特定模型或硬件的过拟合。

## 8. 不足与局限性

- **成本模型依赖离线校准**：边际验证成本需要针对具体硬件和模型进行离线标定，将专家激活映射为延迟的 T_exp 参数会随平台变化；若部署环境与校准环境差异较大，效用估计的准确性可能下降。
- **重用感知门控改变了原始路由**：软性偏置虽然旨在不扰动高置信度 token，但本质上仍是对原始路由分布的修改。论文仅在有限基准上验证了质量保持，对于更广泛的知识型任务或长尾分布，仍有潜在质量漂移风险。
- **基线覆盖不完整**：LS 基线未在 Qwen3 和 GPT-OSS 上评估，而 Cascade 是基于 EAGLE-3 的重实现，可能与原文实现存在微小偏差；GPT-OSS 缺少 KL/PPL 分布一致性指标，削弱了跨模型质量分析的完整性。
- **长上下文场景的端到端效率未测**：LongBench 仅报告了质量分数，未报告吞吐或加速比；自推测在长上下文中可能面临更大的 KV 缓存和草稿回滚开销，这部分尚未被实验覆盖。
- **统计细节不足**：论文未报告多次运行的标准差或显著性检验，考虑到解码过程存在采样随机性，个别基准（如 AIME24 题量有限）的结果可能存在噪声。

## 9. 总结

S²-MoE 通过“上下文对齐的自推测 + 路由感知自适应扩展 + 重用感知门控”三组件协同，系统性解决了 MoE 模型在边缘设备上推测解码时草稿保真度低、冗余验证开销大、专家参数重用差三大难题。它免训练、即插即用，在 Jetson Orin 和 RTX 4090 上对多种 MoE 模型取得了稳定且可观的加速，同时保持了输出质量。该工作为资源受限场景下的 MoE 高效推理提供了一套工程完整、理论支撑充分且实证扎实的解决方案。未来可进一步探索与量化、编译优化、更优路由策略的结合，以覆盖更极端的硬件与更长上下文场景。
