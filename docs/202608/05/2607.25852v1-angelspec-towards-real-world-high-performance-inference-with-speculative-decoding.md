## 摘要
推测解码在不改变目标分布的情况下加速大型语言模型推理，但没有单一的草稿结构能在所有现实工作负载中表现最佳。自回归多令牌预测（MTP）是一种轻量、稳定的提案机制，而块并行扩散则将草稿延迟摊分到更长的候选序列上；选择哪种方式在很大程度上取决于输出分布。我们提出了AngelSpec，一个统一的MTP和块并行推测解码训练框架，从三个层面解决这种异质性。在训练层面，我们不是将单一的通用草稿模型拟合到统一的数据混合上，而是将结构与数据共同特化：MTP草稿模型在多样化的对话数据上训练，用于高熵的开放式聊天；块扩散草稿模型在代码和数学数据上训练，用于更长的可预测延续。在架构层面，我们提出了DFly，一个块扩散框架，结合了混合目标条件主干与前驱条件自回归头，提高了目标特征利用率和块内依赖建模，同时保持并行生成。在推理层面，接受长度和验证成本都随领域、请求、在线负载和硬件而变化，因此DFly将验证视为共享的批次级资源：它将计算重新分配给跨请求的高置信度前缀，并将期望效用与性能分析成本模型相结合，以在线调整验证深度。在Hy3系列中，DFly在Hy3-A21B上将平均接受长度提高了约30%，并在测试的每个并发级别（从4到64）上实现了最高的平均吞吐量，相比自回归解码实现了1.98-2.40倍的加速，相比DFlash吞吐量提高了10.5-11.8%。我们发布AngelSpec以支持这些方法的训练和扩展。

## Abstract
Speculative decoding accelerates large language model inference without changing the target distribution, but no single drafting structure performs best across real-world workloads. Autoregressive multi-token prediction (MTP) is a lightweight, stable proposal mechanism, whereas block-parallel diffusion amortizes drafting latency over much longer candidate sequences; the better choice depends strongly on the output distribution. We present AngelSpec, a unified training framework for MTP and block-parallel speculative decoding that addresses this heterogeneity at three levels. At the training level, rather than fitting one universal drafter to a uniform data mixture, we co-specialize structure and data: the MTP drafter is trained on diverse conversational data for high-entropy open-ended chat, and the block-diffusion drafter on code and mathematics data for longer predictable continuations. At the architecture level, we propose DFly, a block-diffusion framework combining a hybrid target-conditioning backbone with a predecessor-conditioned autoregressive head, improving target-feature utilization and intra-block dependency modeling while keeping generation parallel. At the inference level, both acceptance length and verification cost vary with domain, request, online load, and hardware, so DFly treats verification as a shared batch-level resource: it reallocates compute toward high-confidence prefixes across requests and combines expected utility with a profiled cost model to adapt verification depth online. Across the Hy3 series, DFly raises the average accepted length on Hy3-A21B by roughly 30% and attains the highest average throughput at every tested concurrency from 4 to 64, a 1.98-2.40x speedup over autoregressive decoding and 10.5-11.8% higher throughput than DFlash. We release AngelSpec to support training and extending these methods.

## 2. 方法论

### 2.1 总览

AngelSpec的核心思想是**按工作负载特性协同特化模型结构与训练数据**，而不是训练一个通用草稿器：

- **MTP草稿器**：面向高熵开放对话，使用丰富多样的对话数据训练。
- **块扩散草稿器DFly**：面向代码与数学等低熵结构化任务，使用代码/数学强化数据训练。
- **D-cut**：在推理时将验证视为批次级共享资源，根据实时期望效用与耗时成本模型动态调整验证深度。

### 2.2 MTP：共享参数多深度训练 + TTT

- **共享参数多深度结构**：所有逻辑预测深度（k = 0,…,D−1）复用同一物理MTP模块，深度k的输入来自前一个深度自回归预测所选令牌（或ground-truth），每个深度对应对齐不同未来位置的教师分布。
- **关键公式**：深度k的预测 qₖ = softmax( W_lm · h⁽ᵏ⁾ )，其中h⁽ᵏ⁾由前序隐藏状态与最新输入令牌嵌入经归一化、融合、单个Transformer层得到。
- **Training-Time Test (TTT)**：推理时第k≥1深度拿到的是上一深度自生成预测而非ground-truth，导致暴露偏差。TTT在训练中自回归展开同一模块，让每深度以arg max预测作为下一深度输入，同时通过因果前缀+对角草稿注意力模拟推理时的依赖结构，使深层位置学会从真实上游错误中恢复。
- **长上下文支持**：通过Ulysses序列并行切分序列维度，携带D令牌halo使深度位移监督保持rank本地，验证到128k上下文。
- **损失设计（接受对齐蒸馏）**：
  - 基线为前向KL散度（公式3）；
  - 引入**TV距离**（公式4）与接受概率α(p,q)=1−TV(p,q)的直接联系（公式5）；
  - **LK Loss**冷启动目标：λD_KL(p‖q) + (1−λ)TV(p,q)，λ = exp(−η·sg[α])（公式6），或负对数重叠损失 −log(α+ε)（公式7），其梯度方向与TV一致但低重叠时权重更大；
  - **端到端TV损失**：L_e2e = 1 − (1/|I|)Σᵢ Πₘ₌₀^{D−1} αᵢ,ₖ（公式9），即直接优化期望接受长度，浅层因早期拒绝使后续全部失效而权重更高。
- **数据策略三原则**：多样化任务覆盖（对话、知识问答、数学、代码、指令遵循、Agent）；长上下文与代码Agent轨迹（仓库上下文、工具交互、多步反馈）；**目标模型Rollout**（用冻结目标模型生成响应作为训练数据而非原始参考响应，消除教师-数据分布不匹配）。

### 2.3 DFly：块扩散并行草稿框架

- **混合目标条件骨干（Hybrid Target-Conditioning Backbone）**：
  - DFlash分支：多层目标隐藏状态经FC层非线性变换为共享上下文 cₜ（公式10）；
  - DFlare分支：每草稿层i学习对目标层的softmax融合权重，得到层特异视图 fₜ⁽ⁱ⁾（公式11）；
  - 两者经 RMSNorm( cₜ + fₜ⁽ⁱ⁾ ) 逐位置融合（公式12），既保留全局跨层交互又提供深度差异化条件。
- **前驱条件自回归头**：
  - 并行骨干一次前向生成所有块位置，但各位置分布仅为边缘分布，无法感知块内已选前驱。DFly在并行骨干之后添加轻量顺序头，使联合分布因子化为条件分布乘积（公式13）。
  - 对比两种实现：**Markov头**（低秩转移偏置 U_{t+i} + W₁[ x_{t+i−1} ]W₂，公式14）vs **Hidden-correction头**（将前驱嵌入与位置态经SwiGLU融合后修正z，公式15）。后者在所有基准上更优，作为最终选择。
- **损失设计（两阶段）**：
  - **冷启动**：D-PACE加权的LK损失（公式16–18），动态调整各深度贡献权重，避免早期乘积接受项过小导致的梯度消失；
  - **精调**：切换到端到端TV损失（公式9），直接优化多深度联合接受行为。

### 2.4 D-cut：自适应验证预算分配

- **问题**：接受长度随领域、请求、解码步骤动态变化，而验证代价随在线负载与硬件变化。固定验证深度要么在轻载时浪费算力、要么在高并发时挤占批次容量。
- **方法**：
  1. 根据草稿器逐位置置信度估计前缀存活概率 sᵢ,ₖ = Π_{t=1}^{k} cᵢ,ₜ，进而估计每个请求在保留nᵢ深度时的期望进度 Âᵢ(nᵢ)（公式19–21）；
  2. 将各请求的候选前缀按置信度排序，在全局预算下取top-K（同分偏向浅层），保证每请求保留连续前缀不产生空洞；
  3. 预算从离散比率集 R={0.25, 0.50, 0.75, 1.00} 中选择，上限K_ρ(B)=max(B, ⌈ρ·B(D+1)⌉)（公式22）；
  4. 启动时对每个(B,ρ)组合性能分析端到端步延迟C(B,ρ)，运行时选择 ρ* = arg max U(B,ρ)/C(B,ρ)（公式23–24），即最大化预估吞吐。
- **正确性**：只改变验证深度不改变目标模型验证逻辑，保持输出分布不变。

## 6. 主要结论与发现

- **工作负载异质性是真实推测解码的第一等设计考量**：MTP在对话胜出，DFly在代码/数学大幅领先；两者互补而非替代。
- **TTT对MTP收益率高**：T=0下平均接受率从52.8%升至66.4%（+13.6pp），MAL从2.58升至2.99；T=0.9下同样显著。后两位位置接受率提升最明显（p3从0.266→0.524），说明训练修复了推理-训练分布不匹配。
- **DFly在Hy3-A21B上平均接受长度4.79**，比MTP（3.00）高59.7%，比DFlash（3.69）高29.8%。
- **D-cut在验证瓶颈区域有效**：并发48以上DFly饱和（~860 tok/s），D-cut继续提升至981 tok/s（+15.7% @c64）；接受长度仅损失1.5-2.8%，即丢弃的深度位置本来就是低置信度的。
- **端到端性能**：DFly在c4-c64所有并发下平均吞吐最高，较AR加速1.98-2.40×，较DFlash高10.5-11.8%。
- **组件剖析表明**：目标模型执行占主导（19.77-64.16ms vs 草稿+采样0.89-4.49ms），盈亏平衡分析显示DFly所需平均提交长度为5.14令牌，实际测量值超过该阈值，支持其端到端优势。

## 7. 方法/观点的优点与创新点

1. **问题视角新颖**：将工作负载异质性作为核心设计原则，而非追求平均基准上的单一最优草稿器。
2. **训练-结构-推理三层协同**：数据特化（MTP对话/DFly代码数学）、结构特化（共享MTP多深度、DFly混合条件骨干+AR头）、推理自适应（D-cut动态预算），构成完整闭环。
3. **TTT的务实落地**：共享参数多深度展开解决了MTP推理时暴露偏差，且不新增独立草稿模型参数。
4. **损失函数与目标对齐**：从KL→LK Loss→端到端TV的渐进设计，将训练目标直接与推测解码的接受率指标挂钩；D-PACE加权解决并行草稿器早期训练不稳定问题。
5. **DFly的架构创新**：共享FC+层特异融合的目标条件分解清晰合理，Hidden-correction头以极小开销引入块内依赖，保持并行骨干效率。
6. **D-cut的批次级视角**：将验证预算作为跨请求的全局资源分配问题，而非逐请求启发式，且用性能分析成本模型替代纯启发式。
7. **开源框架AngelSpec**：支持解耦的隐藏状态生成、TTT回滚、长上下文训练、在线评估服务器，具有较高工程价值。

## 8. 不足与局限

- **思考模式匹配限制**：no-think与high-think草稿模型需分别训练、分别部署，共享模型会显著掉点（4.79→3.29），增加部署复杂度。
- **D-cut当前实现限制**：只能使用分段CUDA图（piecewise CUDA graphs），预算选择位于关键路径形成同步点，且仅评估了DFly路径；作者承认这些是实现限制，工作还在进行中。
- **实验偏差风险**：训练数据与评测基准同源（如代码Agent数据来自与评测相近的分布），可能高估实际泛化；对评测样例的16-gram去重只防了文本级污染，未严格排除语义级重叠。
- **通用性证据不足**：主要验证在Hy3系列和Qwen3-8B上；对更大模型规模、不同MoE结构（如专家路由差异）、不同硬件（A100/H100）的迁移性未充分覆盖。
- **报告不完整**：未披露训练算力成本、多次运行方差、延迟百分位（P99）等关键指标，异常延迟对在线服务的影响无法评估。
- **对比公平性**：与DFlash/DSpark等的对比使用了作者自行配置的训练流程，基准方法未按各自原始论文的完整最优配置复现。
- **D-cut的收益边界**：仅在验证受限区间（高并发）显著，轻载时几乎无增益，论文也描述了这种条件性。
