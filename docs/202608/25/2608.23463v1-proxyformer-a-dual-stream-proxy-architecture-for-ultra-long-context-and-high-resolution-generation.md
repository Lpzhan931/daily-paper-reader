## 摘要
注意力计算和键值（KV）缓存随序列长度二次增长，是超长上下文语言模型和高分辨率生成模型的核心瓶颈。我们提出ProxyFormer，一种基于代理令牌构建的通用雙流架构。在每一层中，细粒度的局部特征自底向上压缩成少量代理状态；昂贵的全局交互仅在压缩后的代理空间中执行；经过全局上下文化的代理随后被解压缩，并自顶向下注入回局部流。由于局部流在各层之间持续存在，单次压缩未捕获的细粒度信息仍可在后续迭代中获取，从而缓解了传统一次性压缩造成的不可逆信息丢失。我们还引入了因式分解的多级压缩/解压缩、逐层动态压缩比、非对称雙嵌入以及仅代理的KV缓存推理方案。在16GB GPU且批大小为1的情况下，标准仅解码器模型只能训练约20K token的序列，而压缩比为64的ProxyFormer可将可训练序列长度扩展到约0.7M。使用64K窗口训练的模型在包含1,048,576个token的多针检索任务上保持92%-95%的检索准确率，而使用8K窗口训练的模型外推到256K token时准确率超过94%。初步图像生成实验证明了ProxyFormer在像素空间和潜空间流匹配中的可行性。

## Abstract
The quadratic growth of attention computation and key-value (KV) cache with respect to sequence length is a central bottleneck for ultra-long-context language models and high-resolution generative models. We propose ProxyFormer, a general dual-stream architecture built upon proxy tokens. In each layer, fine-grained local features are compressed bottom-up into a small set of proxy states; expensive global interactions are performed only in the compressed proxy space; the globally contextualized proxies are then decompressed and injected top-down back into the local stream. Because the local stream persists across layers, fine-grained information that is not captured by one compression step remains accessible for later refinement, alleviating the irreversible information loss of conventional one-shot compression. We further introduce factorized multi-level compression/decompression, layer-wise dynamic compression ratios, asymmetric dual embeddings, and a proxy-only KV-cache inference scheme. On a 16GB GPU with batch size 1, a standard decoder-only model can train sequences of only about 20K tokens, whereas ProxyFormer with a compression ratio of 64 extends the trainable sequence length to about 0.7M. A model trained with a 64K window retains 92%-95% retrieval accuracy on a multi-needle retrieval task with 1,048,576 tokens, and a model trained with an 8K window exceeds 94% accuracy when extrapolated to 256K tokens. Preliminary image-generation experiments demonstrate the feasibility of ProxyFormer for both pixel-space and latent-space flow matching.

# ProxyFormer 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

标准 Transformer 的注意力机制存在两个随序列长度二次增长的核心瓶颈：
- **计算复杂度**：标准自注意力的计算量为 O(L²d)。
- **KV 缓存规模**：自回归解码阶段需持久缓存历史 token 的 Key/Value，每层缓存量为 O(Ld)。

当上下文长度达到数十万甚至百万级 token 时，注意力计算和 KV 缓存的开销远超模型权重本身，成为制约推理吞吐和训练序列长度的首要因素。

现有解决方案（线性注意力、稀疏注意力、状态空间模型、KV 缓存剪枝/量化/驱逐等）普遍面临一个**结构性矛盾**：压缩/近似过程中丢弃细粒度信息则损害精确的长程检索能力；保留全部细粒度信息则计算和内存优势受限。一次性、不可逆的序列压缩尤其容易出现 "lost in the middle" 现象和 NIAH（大海捞针）性能退化。

**ProxyFormer 的核心思路**：将"信息保真度"与"全局交互成本"解耦——不再让所有 token 直接参与全局注意力，而是通过双流架构（细粒度局部流 + 少量代理向量组成的代理流）在压缩后的代理空间完成全局交互，同时保留局部流的全分辨率信息，避免不可逆的信息损失。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心架构：双流代理架构

每个 ProxyFormer 层执行一个闭环流程，包含五个阶段：

1. **并行输入与分区**：将输入序列分块为 m = ⌈L/P⌉ 个局部块（P 为压缩比/块大小）；
2. **自底向上压缩（Micro Guides Macro）**：每块通过压缩模块 C 映射为低维代理向量，并经残差形式更新跨层代理状态（Hᵢ ← Hᵢ + cᵢ）；
3. **代理空间全局交互**：仅在压缩后的代理序列（长度为 L/P）上执行全局交互函数 F（可插拔：恒等映射、MLP、因果/双向注意力、SSM/RNN、跨模态交叉注意力等）；
4. **自顶向下解压注入（Macro Guides Micro）**：将全局上下文化的代理向量经解压模块 D 还原为局部空间增量 Δᵢ∈R^{P×d}；
5. **局部融合输出**：通过残差相加、门控融合、仿射调制或交叉注意力等机制将增量注入局部流。

**关键设计**：压缩不是对局部流的破坏，而是对局部流的摘要。即使某层压缩遗漏了细节，该细节仍保存在局部流的残差流中，可参与下一层的压缩迭代，从而实现跨层纠错。

### 2.2 关键技术细节

| 技术 | 说明 |
|---|---|
| **非对称双嵌入** | 历史区域使用低维嵌入 E_h: V→R^{dh}（实验中 dh=64），生成区域使用全维嵌入 E_x: V→R^{dmodel}（dmodel=512），历史序列进入网络时就在通道维度上压缩了 8 倍 |
| **因式分解多级压缩/解压** | 将压缩比 P 分解为 M 个因子 P=k₁k₂...k_M，采用"重塑→投影"的级联结构逐级压缩，避免单层大矩阵的参数爆炸（如 P=64 时用三级 kⱼ=4 的级联替代单片大投影） |
| **逐层动态压缩比** | 不同层可使用不同的 P^(l)，相邻层压缩比不一致时从当前层局部流重新初始化/提取代理状态，支持不同时间距离采用不同粒度的历史压缩 |
| **代理 KV 缓存** | 推理时仅缓存长度为 L/P 的代理状态 K_proxy, V_proxy，原始历史局部特征可释放或卸载；解码时只计算当前 token 的自我注意力和与代理缓存的交叉注意力 |
| **语言模型实例化** | 历史代理向量经 ProxyFormer 块压缩后，与生成区域通过门控交叉注意力融合：A = A_x + α⊙A_h，其中 α 由 MLP 基于 RMSNorm 逐注意力头生成，自适应控制从历史读取的信息量 |
| **视觉生成实例化** | 对图像/潜变量张量按 2D 块进行压缩，文本/时间步条件仅在代理空间执行交叉注意力，再经对称解压注入局部流 |

### 2.3 复杂度分析

- 单层计算量：C_proxy(L) = Θ((L/P)²d) + Θ(L·d_fine·d) + Θ(L·d_fine)，当 L ≫ P·d_fine 时约为全注意力的 1/P²；
- 历史缓存：M_proxy(L) = Θ(L_layer·(L/P)·d)，约为标准实现的 1/P；
- 理论速度增益（P=64）：代理注意力加速 4096×，历史 KV 缓存压缩 64×。

### 2.4 核心公式流程（文字版）

每个 ProxyFormer 层的算法：先将输入 X^(l-1) 按块大小 P 分区为 m 个块；对每个块分别执行压缩 C_i 得到代理向量 c_i，并以残差形式更新跨层代理状态 H_i；然后在代理序列上执行全局交互函数 F（如注意力），得到更新后的代理向量；再对每个更新后的代理向量执行解压 D_i 得到局部增量 Δ_i；最后通过融合函数 Φ 将增量注入局部流，输出更新后的局部流和代理流。

## 6. 主要结论与发现

1. **训练长度大幅扩展**：在 16GB GPU 上，标准 decoder-only 仅能训练约 20K token；ProxyFormer（P=64）训练同一长度仅需 2.9GB 显存（标准模型需 15.6GB），且吞吐从 1.3 it/s 提升至 16.10 it/s；历史长度扩展至 716,800（0.7M）时显存 15.1GB，仍可在同一 GPU 上训练；
2. **长上下文外推能力强**：8K 窗口训练的模型外推到 256K token 时保持 >94% 检索准确率；64K 窗口训练的模型外推到 1,048,576 token（训练长度的 16×）时保持 92%–95% 准确率；两种模型均未出现明显"lost in the middle"现象，各深度区间准确率平滑；
3. **压缩历史带来增益而非损失**：WikiText-103 上，ProxyFormer 引入压缩历史后 PPL 从 22.10 降至 21.01，优于无历史的 baseline（21.36），说明代理压缩不仅没有牺牲语言建模能力，反而通过历史建模带来了收益；
4. **多模态通用性初步验证**：同一代理压缩-重建机制可同时应用于像素空间和潜空间的流匹配图像生成；
5. **实现简洁性**：整个架构仅由 reshape、线性投影、卷积和标准注意力等常规算子组成，无需自定义 CUDA 算子或块稀疏注意力核。

## 7. 优点

1. **核心设计理念新颖且优雅**：将"压缩"从不可逆的破坏性操作重构为可纠错的摘要操作——局部残差流跨层保留，使压缩误差可通过深层迭代修正，从根本上区别于现有一次性压缩/驱逐方法；
2. **通用性强**：统一支持 1D 文本、2D 图像、3D 点云/体素/视频及更高维数据；代理交互算子是即插即用的（可用注意力、SSM、RNN 甚至恒等映射），不受特定低秩/核近似假设的约束；
3. **实现友好**：所有算子均为标准深度学习原语（reshape、线性投影、卷积、标准注意力），极大降低了复现和部署门槛，便于主流框架集成；
4. **代理 KV 缓存设计**:将推理期 KV 缓存从 O(L) 降至 O(L/P)，并支持原始历史特征释放/卸载，对长上下文流式解码的显存和延迟都极为友好；
5. **"空间换通道"的重投资机制**：压缩序列轴上节省的算力可重新投入到代理通道维度，为在固定预算下进一步提高压缩比提供了理论依据；
6. **多级因式分解压缩**：有效控制了高压缩比下压缩模块的参数规模和过拟合风险；
7. **不对称双嵌入设计**：历史区域低维嵌入从 token 进入网络的第一步即在通道维度压缩 8 倍，直观且高效。

- 仅评测了 WikiText PPL 和多针 NIAH，**未覆盖** LongBench、RULER、MMLU、对话等更长上下文和更广泛任务的标准基准；
- 图像实验仅限 MNIST/CIFAR-10 这一小规模设定，**未与 DiT/LDM 类模型**进行高分辨率文生图的系统性对比；
- 语言模型规模小（d=512，10 层），属于验证性规模，**尚未验证大模型（1B–7B）上的扩展定律和训练稳定性**。

### 8.2 方法层面的未决问题

- 压缩模块仅测试了固定分区 + 线性/重塑压缩，**缺乏对动态路由、重叠块、注意力压缩、跨层异构维度等变体的消融**；
- 关于代理流对函数类表达能力的影响、压缩误差随深度和压缩比传播的理论上界，**缺乏形式化分析**；
- 局部流的维护成本是线性的，对于短序列或实际应用中"宽局部流"（d_fine≈d）的场景，压缩/解压的线性项可能超过二次项节省，适用范围边界需要更细致的刻画。

### 8.3 潜在偏差风险

- NIAH 任务采用**多针**设计，与经典单针测试不同，但"针"均为独立的 5 位密码，未测试**需要跨针推理或基于位置推理**的更复杂场景，实际推理能力可能被高估；
- NIAH 的"命中"标准是生成的文本包含对应 5 位密码，**判定标准较宽松**，未报告精确位置匹配或部分正确率；
- 8K 与 64K 模型的外推对比并非在同一步骤数/同一数据量下严谨对齐，课程学习的每阶段停止条件为"损失接近稳定"，存在一定主观性；
- 图像实验未设置 baseline 对照，FID 分数仅表明"可行"，无法证明 ProxyFormer 相对传统文本-图像架构的优势。

### 8.4 应用限制

- 专利待批状态和商业使用限制（需单独授权）可能影响该方法在工业界的快速采用；
- 动态压缩比、多级压缩等超参数引入了额外的调优空间，实际部署时配置复杂度会有所增加。
