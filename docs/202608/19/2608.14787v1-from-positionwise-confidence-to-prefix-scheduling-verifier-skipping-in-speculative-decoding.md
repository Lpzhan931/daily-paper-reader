## 摘要
投机解码是一种领先的技术，通过使用小型草稿模型提出多个标记，然后由较大的目标模型并行验证，来降低自回归生成的成本。投机扩散解码（SDD）通过使用离散扩散模型并行生成草稿块中的每个位置，进一步消除了顺序草稿。然而，SDD 仍然在每个块上调用目标模型，使验证成为潜在的瓶颈。本文认识到这创造了一个新的控制点：是否完全调用验证器。因此，我们研究了验证器跳过，这是一种有损策略，直接提交选定的草稿前缀，并询问应该用哪种置信度信号来调度它。有趣的是，我们的研究发现，更好的标记预测器不一定会产生更好的调度器：跳过需要连续的高置信度前缀，而短跳过可能会导致额外的草稿轮次。为了研究这种不匹配，我们在相同策略下比较了原始置信度与学习到的边际和条件生存分数，并使用严格 SDD、宽容策略和 top-k 接受作为基线。在 HumanEval 上，使用 DiffuCoder-7B-Instruct 和 Qwen3-32B，所有三种置信度信号在观察到与严格 SDD 相同的 pass@1 时，节省了 9.6% 到 13.5% 的验证器调用。令人惊讶的是，原始置信度节省最多；边际生存分数在大多数位置上的位置级 AUROC 高于原始置信度，但两种学习信号都没有在在线中占主导地位。我们的分析表明，验证器跳过是一个有用的新有损维度，而且令人惊讶的是，其关键挑战是前缀调度，而不仅仅是标记预测。

## Abstract
Speculative decoding is a leading technique to reduce the cost of autoregressive generation by using a small drafter to propose several tokens, which are then verified in parallel by a larger target model. Speculative diffusion decoding (SDD) further removes sequential drafting by generating every position in a draft block in parallel with a discrete diffusion model. However, SDD still invokes the target on every block, leaving verification as a potential bottleneck. This paper recognizes that this creates a new control handle: whether to invoke the verifier at all. Thus, we study verifier skipping, a lossy policy that commits a selected draft prefix directly, and ask which confidence signal should schedule it. Interestingly, our study finds that better token predictors need not yield better schedulers: skips require contiguous high-confidence prefixes, while short skips can induce additional drafting rounds. To study this mismatch, we compare raw confidence with learned marginal and conditional survival scores under the same policy, using Strict SDD, lenience, and top-$k$ acceptance as baselines. On HumanEval with DiffuCoder-7B-Instruct and Qwen3-32B, all three confidence signals save $9.6\%$ to $13.5\%$ of verifier calls at the same observed pass@1 as Strict SDD. Surprisingly, raw confidence saves the most; marginal survival has higher positionwise AUROC than raw confidence at most positions, yet neither learned signal dominates online. Our analysis shows that verifier skipping is a useful new lossy axis and, surprisingly, its key challenge is prefix scheduling rather than token prediction alone.

# 论文总结

## 1. 核心问题与整体含义

投机解码（Speculative Decoding）通过小型草稿模型生成候选 token，再由大型目标模型并行验证，以降低自回归生成成本。投机扩散解码（SDD）进一步用离散扩散模型并行生成整个草稿块，消除了草稿阶段的顺序依赖。然而，SDD 仍然必须对每个草稿块调用大型目标验证器，导致验证阶段成为新的主要计算瓶颈。

本文提出了一种全新的“有损”优化轴——**验证器跳过（Verifier Skipping）**：在满足一定置信度条件时，直接提交草稿前缀而不调用验证器。这种策略的核心是一个**前缀调度（Prefix Scheduling）**问题：何时、跳过多长的前缀才是安全且高效的。作者发现，更好的 token 预测器并不必然带来更好的调度器，因为跳过需要连续的高置信度前缀，且过短的跳过可能引入额外的草稿轮次，反而降低吞吐量。

## 2. 方法论

### 2.1 验证器跳过策略
- 在每一轮，扩散草稿器并行生成 γ 个候选 token（记为 x̂₁...x̂_γ），并给每个位置一个置信度分数 qᵢ。
- 策略通过两个门控选择候选前缀：
  - **局部门控**：要求前缀内每个位置的置信度不低于阈值 η_b，即 B_k = min_{j≤k} q_j ≥ η_b。
  - **前缀门控**：要求前缀整体的汇总分数 C_k ≥ η_c。
- 最终选择满足两个门控的最长前缀长度 K̂。
- 只有当 K̂ ≥ K_min（最小跳过长度）、未超过 staleness 限制 S_max（自上次验证后累计未验证 token 数）、且通过安全守卫（如 EOS、重复、无效分数等）时，才跳过验证器，直接提交该前缀；否则执行严格验证回合。

### 2.2 三种置信度信号
在相同调度策略下，比较三种不同的位置分数 q_j 和前缀汇总方式 C_k：

1. **原始置信度（Raw Confidence）**：草稿器对所选 token 的输出概率 q_raw_j = p_draft(x̂_j)，前缀分数用几何平均 C_raw_k = (∏ q_raw_j)^(1/k)。局部门控与几何平均门控互补，几何平均可能掩盖单个低分位置，因此局部门控提供额外约束。
2. **边际生存分数（Marginal Survival）**：估计 a_j = Pr(L ≥ j | F)，即草稿块中至少被严格验证接受 j 个 token 的概率。由于预测的 â_j 不一定单调，取前缀内最小值作为两个门控的共同分数，即 C_marg_k = B_marg_k = min_{j≤k} â_j。
3. **条件生存分数（Conditional Survival）**：估计 s_j = Pr(L ≥ j | L ≥ j−1, F)，即“在已接受 j−1 个 token 的条件下继续接受第 j 个 token”的概率，前缀分数为连乘 C_cond_k = ∏ ŝ_j。参数化 η_c = 1−ε，使 ε 可解释为预测的前缀风险。

### 2.3 关键分析命题
- **命题 1**：位置级指标（如 BCE、AUROC）不能确定前缀出现的频率。可以构造两个分数过程，它们在每个位置与标签的联合分布完全一致（因此位置级指标相同），但高置信度前缀的出现概率相差 ρ^{1−K} 倍。这说明在线调度依赖于块内跨位置的联合结构，而位置级指标无法捕捉这一信息。
- **运行时几何**：通过解码时间近似公式 T ≈ c_D·N_blk + c_V·N_ver，推导出局部盈亏平衡条件：只有跳过长度 K > A·c_D/(c_D+c_V) 时，跳过才能提高吞吐量，否则短跳过虽减少验证调用但会增加草稿块数，降低效率。

## 3. 实验设计

### 3.1 数据集与基准
- **主实验**：HumanEval（164 个问题），评估 pass@1（代码正确率）、严格 token 一致性（Strict token agreement）、完整前缀接受率（Full prefix acceptance）、相对验证调用次数和生成吞吐量（tokens/s）。
- **转移实验（附录）**：MBPP+（378 题）和 MATH-500 子集（300 题），使用 DiffuCoder-7B-Instruct + Qwen2.5-72B-Instruct。

### 3.2 模型配置
- 主实验：DiffuCoder-7B-Instruct（草稿器）+ Qwen3-32B（验证器），两块 NVIDIA A100 80GB，γ=32，K_min=6，S_max=64，贪婪解码，2 步扩散，最多生成 512 token。
- 转移实验：同一草稿器 + Qwen2.5-72B-Instruct，γ=16，四块 A100 80GB。
- 训练：5 折交叉验证（3 训练 / 1 验证 / 1 测试），每个 prompt 恰好出现在一次测试折中。预测器为 3 层 MLP（3603→256→256→256→1），用二元交叉熵训练 15 epochs，Adam，lr=1e-3，batch size=4096 tokens。

### 3.3 对比方法
- **Strict SDD**（严格基线，每个块都验证）
- **Lenience**（放宽接受阈值）
- **Top-k acceptance**（只接受目标 logits 前 k 的草稿 token）
- **周期性跳过基线**（无置信度，每隔 P 轮固定跳过 K 个 token）
- 三种置信度信号（原始置信度、边际生存、条件生存）在同一个调度策略框架下比较。

## 4. 资源与算力

- 主实验使用 **2 张 NVIDIA A100 80GB GPU**（一张跑草稿器+预测器，另一张跑验证器 Qwen3-32B，无模型并行）。
- 转移实验使用 **4 张 NVIDIA A100 80GB GPU**（Qwen2.5-72B 分片到 4 张）。
- 模型权重使用 BF16，Qwen 的 logits 转为 FP32 计算 log 概率。
- 论文中**未明确说明训练 MLP 预测器所消耗的具体 GPU 时长**，也未报告每个实验的总 GPU 小时数。所有主实验均只计时一次解码过程（排除加载、热身、评估等开销）。

## 5. 实验数量与充分性

### 5.1 实验数量
- **主实验**：HumanEval 164 个问题，5 折交叉验证，每折都得到一个测试结果，最终汇总五个测试折。
- **阈值扫描**：对每种方法在固定超参网格上扫描（如原始置信度有 η_b ∈ {0.90, 0.95} 与 η_c 的多种组合；边际生存 7 个阈值；条件生存 8 个阈值；Lenience 9 个阈值；Top-k 3 个阈值）。
- **消融与分析实验**：
  - K_min 扫描（0, 3, 6, 9, 12, 16, 24, 32）验证 H2；
  - 门控消融（局部-only、前缀-only 等）验证各门控的作用；
  - 置换诊断（100 次随机置换）验证 H1 的机制；
  - 周期性跳过基线对比；
  - 转移实验到 MBPP+ 和 MATH，共约 678 个生成任务。

### 5.2 充分性与公平性
- **优点**：离线指标与在线指标分开报告，避免了只用 AUROC 选择调度器的偏差；所有置信度信号在相同策略和相同网格下比较，相对公平；使用统一的 pass@1 作为质量基线。
- **不足**：仅有一个主模型对和单一数据集（HumanEval）；每个 prompt 只生成一次，匹配 pass@1 的“等价性”只是观测层面，未做统计显著性检验（仅转移实验用 bootstrap 检查 CI）；吞吐量只计时一次，可能有噪声；学习信号在未见过跳过轨迹的情况下训练，存在分布偏移；无法完全排除实现偏差（如阈值选择未完全固定）。

## 6. 主要结论与发现

- **验证器跳过有效**：在保持与 Strict SDD 相同 observed pass@1 的前提下，原始置信度、条件生存、边际生存分别减少 **13.5%、12.5%、9.6%** 的验证器调用。
- **原始置信度意外最佳**：尽管边际生存分数在大多数位置有更高 AUROC，但两种学习信号并未在在线调度前沿上占优。这说明“更好的位置级预测”≠“更好的前缀调度”。
- **支持 H1**：置换诊断显示，打破块内跨位置相关性后，可行前缀平均长度从 6.86–8.76 骤降至 1.00–2.11，而位置级指标保持不变，证明离线指标无法反映前缀联合结构。
- **支持 H2**：K_min=0 时验证调用最少（相对 0.788），但吞吐量最低（52.83 tokens/s）；提高 K_min 到 6 后调用增至 0.817，但吞吐量升至 58.54 tokens/s。表明最少验证调用不等于最高吞吐。
- **安全性**：在匹配 pass@1 的操作点，三个信号均保持较高的 strict token agreement（约 0.98），且完整前缀接受率高于 0.97。

## 7. 优点

1. **概念创新**：首次明确提出“验证器跳过”这一独立于草稿和接受规则的损失层，并把它形式化为前缀调度问题。
2. **分析严谨**：用命题、置换检验、最小跳过长度分析等工具解释了“离线预测→在线调度”的缺口，不仅报告结果，还解释机制。
3. **公平比较**：所有置信度信号在相同调度策略和相同网格下比较，且用 shadow verifier 审计跳跃结果，不干扰生成，测量设计干净。
4. **实用启示**：指出短跳过会造成草稿块碎片化，为实际部署提供了明确指导（设置合理 K_min）。

## 8. 不足与局限

- **实验覆盖窄**：主实验只在 HumanEval 上用一组模型对，未在更多通用语言数据集或更多模型组合上验证。
- **统计保证弱**：匹配 pass@1 仅基于 164 个问题的观测值，没有正式等价性测试；通过不同操作点发现的“相同 pass@1”可能掩盖质量分布差异。
- **吞吐量测量可重复性低**：每个 prompt/设置只计时一次，未报告方差；且实现中没有使用 verifier KV cache 和全序列重计算，实际服务场景（如缓存）下结果可能不同。
- **预测器无保证**：学习到的生存分数不是经过认证的下界，因此“被跳过前缀至少有 1−ε 概率被接受”只是解释性说法，不具备严格安全性。
- **分布偏移风险**：预测器只在 Strict SDD 轨迹上训练，一旦策略实际跳过 token，草稿分布会发生变化，可能导致后续置信度失真。
- **架构单一**：只评估了一种 MLP 架构和位置级训练目标，未探索更丰富的序列模型或强化学习式调度器。
