## 摘要
在具身场景中准确且高效地回答用户问题面临显著挑战，原因在于视觉语言模型（VLM）推理所需的计算和内存资源有限。现有方法采用视觉搜索的关键帧检索方法来选择与问题相关的关键帧作为VLM输入。然而，视觉搜索方法效率低下，因为它们需要对每个用户查询在数千个视频帧中进行视觉搜索。在本工作中，我们提出了一种记忆树引导的关键帧选择范式，用于具身场景中的高效三维问答。我们的方法利用一种紧凑且可复用的三维场景表示，称为MemTree3D，它支持利用相机六自由度位姿进行实时在线构建。MemTree3D捕获多级三维场景信息，使大型语言模型能够通过我们基于评分的帧选择高效地查询和检索与问题相关的关键帧，而无需重新处理整个视频流。在OpenEQA上，我们的方法将GPT-4o的LLM-Match提升了17.4%，将LLaVA-OneVision-7B提升了5.8%，优于现有视觉搜索方法。我们的代码可在https://github.com/hsiangwei0903/MemTree3D获取。

## Abstract
Answering questions accurately and efficiently in embodied scenarios presents significant challenges due to limited computational and memory resources for Vision Language Model (VLM) inference. Existing methods adopt visual search key frame retrieval method to select critical question-related key frames for VLM input. However, visual search methods are inefficient because they require visual search among thousands of video frames for each individual user query. In this work, we propose a memory tree guided key frame selection paradigm for efficient 3D question answering in embodied scenarios. Our method leverages a compact and reusable 3D scene representation, termed MemTree3D, which supports real-time online construction leveraging camera 6-DoF poses. MemTree3D captures multi-level 3D scene information, enabling a Large Language Model to efficiently query and retrieve question-relevant key frames through our scoring-based frame selection without reprocessing the entire video stream. On OpenEQA, our method improves the LLM-Match of GPT-4o by 17.4%, LLaVA-OneVision-7B by 5.8%, outperforms existing visual search methods. Our code is available at https://github.com/hsiangwei0903/MemTree3D

# 论文中文总结

### 1. 核心问题与研究动机
- **背景**：3D问答（3D Question Answering）是场景理解中的基础任务，广泛应用于具身导航、家庭机器人、AR/VR 和辅助智能体等场景。然而，在具身场景中，VLM 推理受限于计算与 GPU 内存资源。
- **现存三类方法及其瓶颈**：
  1. **多帧 VLM 方法**：将整个 3D 扫描视频输入 VLM，但 Transformer 注意力机制的计算量随输入帧数**平方级增长**，需要时序降采样，造成视觉信息丢失。
  2. **场景图方法**（如 ConceptGraphs）：使用对象级场景表示，内存高效但**只能做对象级理解**，无法进行细粒度视觉识别。
  3. **视觉搜索方法**（如 VLM-Grounder）：先由 LLM 分析查询，再在**所有视频帧中**逐个查询相关对象，主要存在三大缺陷：(1) 每次查询都需遍历全视频，实时性差；(2) 多轮问答场景下无法复用，重复计算严重；(3) 视觉检测失败时没有恢复机制。
- **核心问题**：如何在不牺牲 VLM 视觉理解能力的前提下，**既高效（避免逐查询的全视频扫描）又准确（保留关键视觉信息）** 地实现 3D 问答。

### 2. 方法论述：MemTree3D 引导的关键帧选择
- **整体思路**：引入一种紧凑的、**一次构建、多次复用**的 3D 场景表示 MemTree3D，由 LLM 在树上进行显式的空间与时间推理，生成关键帧检索线索，仅将少量关键帧送入 VLM 作答，从而绕开对全视频的逐查询视觉搜索。
- **MemTree3D 结构（三级树）**：
  - **位置节点（Location Node）**：利用相机 6-DoF 位姿将视频切分为多个空间局部段（当平移超过 1.5 m 或旋转超过 45° 时新建节点），无需额外视觉语义聚类，计算开销极小。
  - **对象节点（Object Node）**：由对象检测器（YOLO-World）和多目标跟踪器（BoT-SORT）生成各位置的对象轨迹，为 LLM 提供语义级场景内容。
  - **检测节点（Detection Node）**：叶子节点，存储每帧检测的时间戳、边界框和置信度，供后续评分式帧选择使用。
- **LLM 空间与时间线索生成**：
  - 将 MemTree3D 前两级（LocNode + ObjNode）序列化为 JSON 文本输入 LLM。
  - **时间线索**：LLM 推理出最可能包含答案的 top-k 个位置节点（默认 k=3），即使在对象检测缺失时也能借助上下文线索推断可能位置。
  - **空间线索**：LLM 生成关键对象集合 O_key 和提示对象集合 O_cue，用于后续帧评分。
- **评分式关键帧选择**：
  - 对候选位置内的每一帧，聚合检测节点中关键对象和提示对象的置信度，并按 10:1 的权重进行加权融合，选出信息量最大的帧作为该位置的代表帧。
  - 该方法对部分对象缺失具有鲁棒性，避免单一对象/最高置信度策略的脆弱性。
- **整体流程**：视频流 → 一次性构建 MemTree3D（25+ FPS 实时在线）→ LLM 查询树生成时间+空间线索 → 评分选帧 → VLM 作答。

### 7. 方法亮点
- **实时在线构建**：仅使用 6-DoF 位姿即可分割场景，无需额外语义聚类，构建速度 25+ FPS，便于直接集成到具身智能体的在线观测阶段。
- **高效可复用**：MemTree3D 只需构建一次，多轮问答中可反复查询，无需重跑视觉模型，特别适合交互式场景。
- **感知失败恢复机制**：传统视觉搜索在检测器漏检时直接失败；本方法通过 LLM 对树中上下文（位置内对象共现关系）的推理，可以合理解读"可能存在但未检测到"的目标区域。
- **打分式帧选择的鲁棒性**：综合关键对象和提示对象的多重证据加权，而非依赖单一检测结果，抗噪声能力强。
- **轻量且通用**：不需要为 3D 任务重新训练 LLM/VLM，直接利用现成模型的零样本能力即可工作。

### 8. 不足与局限
- **新颖对象定位失败**：当问题询问的目标对象在场景中**从未被检测到**且不属于 MemTree3D 的已知对象时（如"纸箱猫抓板"），LLM 只能凭常识猜测最可能的位置，成功率有限（附录已给出失败案例）。
- **小场景增益有限**：在 ScanNet 这类小场景上，均匀采样本身已能覆盖大部分视觉内容，MemTree3D 的优势不明显（+13.6% vs HM3D 的 +24.6%），在小场景中的性价比有待提升。
- **依赖 6-DoF 位姿可用性**：方法假设具身设备能够提供准确的相机 6-DoF 位姿；在位姿信号不稳定或缺失（如某些非导航类视频输入）的场景下，位置节点的构建质量可能受影响。
- **缺少大规模真实机器人验证**：实验均在离线数据集上完成，未涉及真实物理机器人在线部署的端到端评估，对实际干扰（如位姿漂移、检测器漂移、延迟波动）的鲁棒性尚未验证。
- **算力细节不透明**：关于训练/推理总资源消耗、各模块具体耗时占比等信息未详细披露，复现时需要自行摸索资源需求。
