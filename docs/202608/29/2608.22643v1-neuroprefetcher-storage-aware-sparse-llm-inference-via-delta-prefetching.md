## 摘要
在边缘设备上部署大语言模型日益受到模型规模与可用内存之间不断扩大的差距的限制。现有方法如量化、更小模型和卸载可以提高有效内存上限，但它们仍然假设模型可以被压缩或分区以适应某些预算。我们针对更困难的模型超出内存的设置，在此设置中，模型在整个执行过程中仍大于驻留内存，存储成为关键路径上权重的主动来源。我们观察到自回归解码期间的MLP活动具有很强的时间局部性：大约82-85%的活动神经元从一个token持续到下一个token。这意味着当前token所需的大多数稀疏权重已经驻留，只需从存储中获取新需要的行。我们提出了NeuroPrefetcher，一种存储支持的大语言模型推理系统，通过预测性增量预取利用这一特性。在第0层之后，一个占用基础模型参数2.86%的GPU驻留预测器在一次前向传播中预测所有下游MLP层的稀疏活动。运行时将这些预测与驻留GPU缓冲区进行比较，仅对传入的增量行发起应用调度的NVMe读取，用显式、模型感知的权重移动取代反应式的操作系统按需分页。在真实的统一内存边缘硬件上，NeuroPrefetcher在受限内存预算下比llama.cpp实现了7.9-12.0倍的加速。

## Abstract
Deploying large language models on edge devices is increasingly limited by a widening gap between model size and available memory. Existing approaches such as quantization, smaller models, and offloading can raise the effective memory limit, but they still assume that the model can be compressed or partitioned to fit within some budget. We target the harder model-exceeds-memory setting, in which the model remains larger than resident memory throughout execution and storage becomes an active source of weights on the critical path. We observe that MLP activity during autoregressive decoding has strong temporal locality: approximately 82-85% of active neurons persist from one token to the next. This means that most sparse weights needed for the current token are already resident, and only the newly needed rows must be fetched from storage. We present NeuroPrefetcher, a storage-backed LLM inference system that exploits this property through predictive delta prefetching. After layer 0, a single GPU-resident predictor, occupying 2.86% of base model parameters, predicts sparse activity for all downstream MLP layers in one forward pass. The runtime compares these predictions against resident GPU buffers and issues application-scheduled NVMe reads only for incoming delta rows, replacing reactive operating-system demand paging with explicit, model-aware weight movement. On real unified-memory edge hardware, NeuroPrefetcher achieves 7.9-12.0x speedup over llama.cpp across constrained memory budgets.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：边缘设备部署大规模语言模型（LLM）时，模型规模增长速度（约每代10×）远超边缘DRAM容量增速（约2×），导致模型**持续大于可用内存**，即“模型超出内存”（model-exceeds-memory）的硬约束场景。现有方法（量化、小模型、CPU/存储卸载）都假设模型可被压缩或分区后放进某个内存预算，未处理“存储成为推理关键路径上的权重主动来源”的极端情况。
- **关键观察**：在自回归解码中，MLP（多层感知机）的活跃神经元具有极强的时间局部性——相邻token之间约82–85%的活跃神经元得以保留。因此当前token所需的大多数稀疏权重已驻留在GPU中，只需从NVMe存储中获取**新增的行（delta rows）**。
- **研究意义**：论文证明，通过显式的、模型感知的权重重定位（而非反应式OS按需分页），可以在模型持续超内存的部署中实现数量级的加速，填补了现有推理系统在该场景下能力缺失的空缺。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
**预测性增量预取（Predictive Delta Prefetching）**：系统提前预测当前token各稀疏MLP层所需的活跃神经元集合，与已驻留的GPU缓冲行进行集合差运算，只从NVMe读取“新增的活跃行”（delta），避免每次token都重新加载全部稀疏权重。

### 系统架构与流程
1. **离线稀疏质心准备（Offline Sparse Centroid Preparation）**
   - 对 MLP 激活进行**阈值化**（按层分位数 α 截断低幅值，公式 \(A_{sparse}[j] = 0 \text{ if } |A[j]| < T_{l,\alpha}\)），制造稀疏二进制掩码。
   - 对掩码进行**聚类**，得到稀疏**质心（centroid）库**。运行时预测器只需输出每个层的质心ID，而非逐神经元二值向量，大幅降低预测复杂度。
   - 下投影（down projection）保持稠密，因其维度（4096）较小但稀疏化质量损失显著。

2. **共享激活预测器（Shared Activation Predictor）**
   - 在第0层之后运行一次，预测第1到31层的gate和up投影的质心ID（共62个ID）。
   - 输入特征：token嵌入、注意力前LayerNorm输出、注意力头草图、注意力后残差RMS范数、以及第0层gate激活的质心ID（结构特征）。
   - 结构：4个投影块 → 残差MLP主干 → 2组31个独立线性分类头。
   - 预测器参数206.8M（FP16约414MB），仅占基础模型参数的**2.86%**，为常驻权重。
   - 训练损失为gate和up质心ID的交叉熵之和。

3. **预测性增量预取运行时（Predictive Delta Prefetching Runtime）**
   - 每个稀疏层维护容量为 \(K_{\max}\) 的GPU活跃行缓冲。
   - 每token计算集合差：\(D_{in} = A_t \setminus A_{t-1}\)（取入行）、\(D_{out} = A_{t-1} \setminus A_t\)（取出行）。
   - 仅对 \(D_{in}\) 发起NVMe读取；FD行释放缓冲槽，供新行复用。
   - 首token冷启动时加载完整预测活跃集，后续token只读delta。

4. **I/O路径实现**
   - 离线**重排权重布局**为“神经元连续记录”（gate/up/down^T三行同址），单次读可获取一个活跃神经元所需的全部投影行；相邻神经元ID可合并为连续读范围。
   - 使用 **io_uring** 异步批量提交读请求（队列深度256），O_DIRECT 打开文件。
   - 为处理Jetson统一内存的**缓存一致性问题**，NVMe读先落入经 `cudaHostRegisterMapped` 注册的固定钉扎暂存缓冲，再用融合CUDA核 `launch_deinterleave_scatter` 将行分散到专属活跃行缓冲，避免脏数据暴露给GPU。
   - 读写与GPU稠密前缀计算**重叠执行**。

5. **内存自适应稠密/稀疏划分**
   - 模型前 \(d\) 层保持完全驻留（稠密前缀），后 \(N-d\) 层以稀疏活跃行缓冲执行（稀疏后缀）。
   - 通过自动扫描找到给定内存预算下最大的驻留稠密前缀数 \(d^*\)；当 \(d\) 过大导致稀疏层缓冲不足时，层会退化为整层NVMe读取（性能悬崖）。
   - 同时保留注意权重、嵌入层、预测器、质心表等常驻权重的独立性。

## 6. 主要结论与发现

1. **模型超出内存场景下，NeuroPrefetcher显著优于llama.cpp**：在9.0–13.2GiB可用CUDA内存范围实现**7.9–12.0×加速**（例如mem=14G时3.22 tok/s vs 0.34 tok/s）。
2. **Delta复用率稳定在82–85%**：每token约82–85%的稀疏后缀行来自上一token的活跃集，NVMe流量降至全部活跃集的15–18%；每token读取量在内存极紧时从14.8GiB下的103MiB仅增至9.0GiB下的略低于1GiB，远小于整模型13.49GiB。
3. **预取机制大幅降低OS故障**：主页面故障从每秒11,453次降至0.21次，CPU iowait从77%降至4%，GPU利用率从3%升至30%。
4. **延迟瓶颈仍是NVMe I/O**：无论内存级别，I/O占每token延迟的80–87%；计算和预测器开销很小。因此后续优化应聚焦I/O路径（更深流水线、更强制合并、量化稀疏行格式）。
5. **当前大多数推理系统无法处理模型超内存的统一内存边缘场景**：20个系统中仅4个可产出结果（NeuroPrefetcher、llama.cpp、FlexGen、Ollama），其余12个失败于分配/能力不匹配或缺乏ARM版本。
6. **质量受控**：预测器质心选择准确率约99%，质量损失主要来自聚类阶段；在d=20时Mistral-7B保留约95–96% HellaSwag准确率，Llama-3-8B约92–93%，且跨语料（WikiText-2训练，HellaSwag测试）无需任务重训。

## 7. 优点

- **问题定位精准**：识别出“模型持续超内存”这一现有系统未覆盖的硬场景，并给出系统的解决方案。
- **洞察新颖且实用**：发现token间MLP活跃神经元的82–85%持久性，并将其转化为“只取delta”的存储调度策略，而非单纯依赖稀疏计算优化。
- **架构简洁高效**：单次前向预测所有层（一次性预测），比逐层预测（如DejaVu）更早暴露I/O计划，适合存储预取的时间窗口。
- **端到端系统工程完整**：涵盖离线权重重排、io_uring异步读、缓存一致暂存、融合scatter、内存自适应划分等生产级细节。
- **实验覆盖充分**：同时进行性能、I/O、延迟分解、质量、系统能力等多维度验证，并指出与llama.cpp的交叉点（模型可驻留后优势缩小），诚实反映适用边界。
- **能力图谱研究有价值**：对20个主流系统在统一内存边缘平台的可部署性做了分类，揭示了现有卸载架构与该平台的根本冲突。

## 8. 不足与局限

- **实验模型较窄**：主要吞吐实验仅Mistral-7B；Llama-3-8B未提供端到端吞吐数据，无法验证方法在其他模型家族（如更大规模或不同激活函数）的普适性。
- **缺少强基线对比**：PowerInfer、LLM in a Flash、Neuralink等同类稀疏存储系统因平台限制未进行数值比较，使得“最快”结论局限于四套可运行系统中，缺少跨平台量化对比。
