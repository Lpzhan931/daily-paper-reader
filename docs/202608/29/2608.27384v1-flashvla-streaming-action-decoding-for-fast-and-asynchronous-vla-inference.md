## 摘要
视觉-语言-动作（VLA）模型在机器人操作领域日益展现出巨大潜力，但其实际部署仍受制于高推理延迟和不稳定的异步执行。这一挑战在基于流匹配的VLA模型中尤为突出，因为动作解码需要以VLM上下文为条件进行多次迭代步骤。尽管高效推理方法能提升控制频率，异步方法能减少执行空闲时间，但现有方法往往无法同时实现低延迟推理与准确、时间一致的异步执行。我们提出了**FlashVLA**，一种流式动作解码框架，以统一的形式解决这两个挑战。FlashVLA维护一个包含多个不同噪声级别块的流式动作缓冲区，并通过逐块因果注意力解码这些块。这种设计使FlashVLA能在每一步推理中产生一个可执行的动作块。此外，其逐块自回归形式隐式保持了动作连续性，无需额外未来状态条件即可实现平滑的异步执行。在广泛的模拟和真实世界实验中，FlashVLA在保持强任务性能的同时大幅提升了推理速度。在单GPU上可实现≥30Hz的控制频率，并在实际部署中实现平滑的异步推理。

## Abstract
Vision-Language-Action (VLA) models are increasingly promising for robotic manipulation, yet their real-world deployment remains bottlenecked by high inference latency and unstable asynchronous execution. This challenge is particularly pronounced in flow-matching-based VLA models, where action decoding requires multiple iterative steps conditioned on the VLM context. While efficient inference methods improve control frequency and asynchronous methods reduce execution idle time, existing approaches often fail to jointly achieve low-latency inference and accurate, temporally consistent asynchronous execution. We introduce \textbf{FlashVLA}, a streaming action decoding framework that addresses both challenges in a unified formulation. FlashVLA maintains a streaming action buffer with multiple chunks at different noise levels and decodes them using chunk-wise causal attention. This design allows FlashVLA to produce one executable action chunk per inference step. Moreover, its chunk-wise autoregressive formulation implicitly preserves action continuity, enabling smooth asynchronous execution without extra future-state conditioning. Across extensive simulated and real-world experiments, FlashVLA substantially improves inference speed while maintaining strong task performance. It can achieve $\geq$30\,Hz control frequency on a single GPU with smooth asynchronous inference in real-world deployment.

## 1. 核心问题与研究动机

- **背景**：视觉-语言-动作（VLA）模型将视觉观测与语言指令直接映射为机器人动作，是端到端操控领域的主流范式。以 π0.5 为代表的流匹配 VLA 模型在多种任务上表现出色，但在真实部署中面临严重瓶颈——**推理延迟过高**，难以满足实时控制需求。
- **核心问题**：作者对 π0.5 的性能剖析显示，**动作解码（action decoding）单一项就消耗了约 75% 的推理时间**，其原因在于每个动作块需要执行 10 次顺序去噪。这一瓶颈造成了 VLA 部署中两类看似对立的失败模式：
  - **同步推理**：观测与动作时间对齐，但机器人在每个块边界处停顿等待下一块解码完成；
  - **异步推理**：预测与执行重叠，但机器人执行动作时使用的是**过时观测**，预测与真实机器人状态之间存在时间错配，且前瞻越长错配越严重。
- **关键观察**：作者指出两种失败模式共享同一个根源——**流匹配 VLA 以“孤立”方式解码每个动作块**：从纯噪声出发，仅以当前观测为条件，与任何正在执行中的块没有联系。这种孤立性既将全部去噪集中在单块解码中（延迟代价），又使新块对将要加入的轨迹一无所知（错配代价）。
- **解决思路**：将动作块从“孤立解码”改为“联合解码”，用一个统一的结构性改动同时消除延迟代价和错配代价。

## 2. 方法论

### 2.1 核心思想

FlashVLA 借鉴了长视频生成中的流式逐块扩散技术，维护一个**流式动作缓冲区**，其中包含多个处于**错开噪声水平**的动作块，通过**逐块因果注意力**联合推进去噪。每个前向传播使缓冲区中所有块前进一个去噪步骤；暖机（warm-up）之后，**每个推理步骤即可产出一个可执行的动作块**。

该设计带来三个关键性质：

- **去噪分摊**：每个块在其执行前经历缓冲区中全部 N 个噪声水平，但 N 次传播分摊在 N 个不同的前向步骤中，而非集中在一个解码过程中。每个块的逐步推理延迟最多可降低 20 倍。
- **隐式异步条件**：高噪声的未来块通过因果掩码关注低噪声的临近执行块，使模型在解码未来机器人状态时已经隐式地以该状态将要加入的轨迹为条件，无需显式未来状态预测器。
- **块级记忆**：每个较高时间步的块都关注缓冲区中的所有更早块，而非仅关注其紧邻前驱。缓冲区由此编码了一段短的结构化历史，有助于长时程任务。

### 2.2 流式推理算法

- **冷启动阶段**：训练开始时缓冲区为空。以 N−1 个填充块加一个高斯噪声样本初始化缓冲区，运行 N−1 个推理步骤填充所有槽位。此间机器人执行安全默认动作（如保持静止）。该开销每个 episode 仅支付一次，可在完整 rollout 中摊销。
- **稳态流式阶段**：缓冲区填充完成后，每个推理步骤执行：(i) 所有块前进一个去噪步骤；(ii) 弹出最干净（最接近执行）的块执行；(iii) 其余块前移；(iv) 在缓冲区尾部追加一个新的纯噪声块。
- **系统级优化**：将稳态阶段的每一步编译为 CUDA Graph，合并线性层减少内核启动开销，并使用 PyTorch max-autotune 编译消除内核气泡。

### 2.3 多缓冲联合微调

- 预训练 VLA 模型从未见过部分填充的缓冲区或逐块因果注意力模式，需要在任务微调阶段适配。
- 挑战：对单个观测 o_t，冷启动过程暴露出 N 种不同的缓冲区配置，若分别作为训练样本会使数据集扩大 N 倍且低效。
- **打包方案**：将所有 N 种缓冲区配置打包进一个训练样本，共享同一观测编码，但通过注意力掩码隔离各缓冲区。观测编码只需计算一次，训练目标为跨所有配置的标准流匹配损失（公式3）。
- **架构调整**：在动作专家中应用 FiLM 增强多级时间步条件。对 SmolVLA，额外引入 time-MLP 和 FiLM 层。

## 6. 主要结论与发现

1. **统一解决低延迟与异步连续性问题**：单次结构改动（流式缓冲 + 逐块因果注意力）同时消除了同步停顿和异步错配两类成本。
2. **推理速度大幅提升**：
   - LIBERO 上端到端 per-action 加速达 **2.43×**（53.8 → 22.1 ms/step）；
   - 动作解码逐步延迟最高降低 **20×**（GPU 工作减少 9.3×，结合内核启动优化后实测加速 19.9×）；
   - 推理延迟在 RTX 5090 两视角下低至 **20.3 ms**，对应约 50 Hz 策略更新率；
   - 跨架构加速 1.95×–2.81×。
3. **任务质量保持或提升**：
   - LIBERO 同步成功率从 96.9% 提升至 97.9%，异步（d=1）提升至 97.8%；
   - RoboTwin 2.0 同步成功率从 86.0% 提升至 90.5%，异步（d=1）达 90.6%；
   - 在 d=1–4 的所有延迟水平上，FlashVLA 成功率均保持在同步基线之上。
4. **长时程任务增益显著**：RoboTwin 2.0 长时程子集成功率从 53.0% 提升至 89.6%（+36.6 点），LIBERO-Long 提升 3.8 点。增益随时程增长，验证了块级记忆的实际价值。
5. **真实世界 30 Hz 控制可行**：在单张 RTX A4000 上实现 67.3 ms 推理延迟（约两个 30 Hz 控制周期），通过两步异步延迟重叠，达到 30 Hz 平滑控制；三任务平均得分从 π0.5 同步的 80.0% 提升至 84.4%，完成时间加速 1.3×。

## 7. 优点

- **统一的视角**：把延迟瓶颈与异步错配归结为同一个根源，并用一种结构设计同时解决，而非分别打补丁。
- **即插即用**：FlashVLA 是对流匹配 VLA 的 drop-in 修改，仅需轻量架构调整和一次微调，无需从头训练。
- **无需显式未来预测**：通过因果注意力结构隐式恢复异步连续性，避免了 VLASH 等方法的辅助监督和架构手术。
- **设计优雅**：噪声阶梯与执行顺序对齐（更干净 = 更早执行），因果掩码只允许信息沿时间方向流动，具有清晰的物理语义。
- **实验充分且系统**：从多个模拟基准到真实机械臂，从同步到多级异步延迟，从同架构到跨架构，从主结果到关键组件消融，证据链完整。
- **训练高效**：多缓冲打包使 N 种缓冲区配置共享一次观测编码，避免数据集 N 倍膨胀。

## 8. 不足与局限

- **依赖微调而非端到端预训练**：FlashVLA 继承了预训练模型的独立块训练目标。作者承认，从零开始在逐块因果公式下预训练 VLA 是自然的下一步，并可能带来进一步增益。
- **冷启动开销**：每个 episode 开始时需要 N−1 步暖机，在短时间内任务上更明显，长任务中可以摊销。
- **训练数值不稳定**：微调时动作专家的归一化层可能出现梯度爆炸，需要在某些数据集上重新初始化归一化层（例如 RoboTwin 2.0 的 50 任务多任务训练）。
- **实验覆盖有限**：真实世界只测试了 3 个任务、15 次试验/任务，RoboTwin 2.0 多任务结果未报告多次运行的方差。
- **RoboTwin 2.0 加速不明显**：因仿真中渲染占主导（36.8 ms）而推理仅占 17%，端到端加速仅 1.08–1.10×，说明策略侧加速受限于整体运行时组成。这一局限正如文中所言，主要源于仿真开销而非方法本身。
- **总缓冲区跨度与原生块长的匹配依赖经验法则**：最佳性能需要将 chunk size × buffer length 大致对齐预训练模型原生动作块长度，跨不同预训练模型时需重新调整超参数。
