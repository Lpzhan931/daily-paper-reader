## 摘要
推测解码在不改变目标分布的情况下加速大语言模型推理，但在真实工作负载中，没有任何单一的草稿结构能始终表现最佳。自回归多令牌预测（MTP）是一种轻量级、稳定的提议机制，而块并行扩散则将草稿延迟分摊到更长的候选序列上；哪种选择更优在很大程度上取决于输出分布。我们提出AngelSpec，一个面向MTP和块并行推测解码的统一训练框架，从三个层面解决这种异构性。在训练层面，我们不是将单一的通用草稿模型适配到统一的数据混合上，而是对结构和数据进行协同特化：MTP草稿模型在多样化对话数据上训练，以支持高熵开放域聊天；块扩散草稿模型在代码和数学数据上训练，以支持更长的可预测续写。在架构层面，我们提出DFly，一种块扩散框架，它结合了混合目标条件骨干网络和前驱条件自回归头，在保持并行生成的同时，提高了目标特征利用率和块内依赖建模能力。在推理层面，接受长度和验证成本都随领域、请求、在线负载和硬件而变化，因此DFly将验证视为一种共享的批级资源：它跨请求将计算重新分配给高置信度前缀，并结合期望效用与基于性能剖析的成本模型，在线调整验证深度。在Hy3系列上，DFly在Hy3-A21B上的平均接受长度提高了约30%，并且在4到64的每个测试并发度下都获得了最高的平均吞吐量，相比自回归解码实现了1.98-2.40倍的加速，相比DFlash吞吐量提高了10.5-11.8%。我们发布AngelSpec，以支持这些方法的训练和扩展。

## Abstract
Speculative decoding accelerates large language model inference without changing the target distribution, but no single drafting structure performs best across real-world workloads. Autoregressive multi-token prediction (MTP) is a lightweight, stable proposal mechanism, whereas block-parallel diffusion amortizes drafting latency over much longer candidate sequences; the better choice depends strongly on the output distribution. We present AngelSpec, a unified training framework for MTP and block-parallel speculative decoding that addresses this heterogeneity at three levels. At the training level, rather than fitting one universal drafter to a uniform data mixture, we co-specialize structure and data: the MTP drafter is trained on diverse conversational data for high-entropy open-ended chat, and the block-diffusion drafter on code and mathematics data for longer predictable continuations. At the architecture level, we propose DFly, a block-diffusion framework combining a hybrid target-conditioning backbone with a predecessor-conditioned autoregressive head, improving target-feature utilization and intra-block dependency modeling while keeping generation parallel. At the inference level, both acceptance length and verification cost vary with domain, request, online load, and hardware, so DFly treats verification as a shared batch-level resource: it reallocates compute toward high-confidence prefixes across requests and combines expected utility with a profiled cost model to adapt verification depth online. Across the Hy3 series, DFly raises the average accepted length on Hy3-A21B by roughly 30% and attains the highest average throughput at every tested concurrency from 4 to 64, a 1.98-2.40x speedup over autoregressive decoding and 10.5-11.8% higher throughput than DFlash. We release AngelSpec to support training and extending these methods.

## 1. 论文核心问题与整体含义（研究动机与背景）

推测解码（Speculative Decoding）是一种不改变目标分布、可无损加速大语言模型推理的方法：轻量草稿模型先提出多个未来token，再由目标模型一次性并行验证。然而，真实在线服务中的请求高度异构，涵盖开放对话、代码生成、数学推理、工具调用与代理工作流，其条件熵和续写结构差异显著。论文的核心观点是：

- **不存在一种草稿结构能在所有负载下最优**：自回归多token预测（MTP）轻量稳定，适合高熵对话；块并行扩散（block-parallel diffusion）能摊薄草稿延迟，适合代码/数学等低熵、长可预测续写任务。
- 真实部署中，接受长度和验证成本会随领域、请求、并发负载和硬件动态变化，固定验证深度是次优的。
- 因此需要从**训练数据、模型架构、推理调度**三个层面进行系统性协同设计，而不是只优化一个通用草稿器。

作者提出 **AngelSpec** 统一训练框架，并通过工作负载特化、新架构 **DFly** 和自适应验证调度 **D-cut** 来解决上述问题。

## 2. 方法论：核心思想、关键技术与公式流程

### 2.1 整体思路
AngelSpec 不训练一个万能草稿器，而是按负载类型分工：
- **MTP 草稿器**：用丰富多样、对话导向的数据训练，面向高熵开放聊天，提供短视野草稿。
- **块扩散草稿器（DFly）**：用代码/数学数据强化，面向长可预测续写。

### 2.2 MTP 草稿器：共享参数多深度训练 + TTT
- **共享参数多深度 MTP**：保留 D 个逻辑预测深度，但所有深度复用同一物理 MTP 块，逐步自回归展开，每个深度对应不同的未来token教师标签。
- **TTT（Training-Time Test）**：训练时用前一个深度自生成的预测 token 作为下一个深度的输入，模拟推理时的误差累积过程，缓解 teacher-forcing 与多步推理的分布漂移。
- **长上下文训练**：通过序列分片和文档边界感知的掩码，将 TTT 扩展到 128k 长上下文。
- **接受对齐蒸馏**：
  - 用总变差距离 TV(p,q) 与接受率的关系：α(p,q) = 1 − TV(p,q)；
  - 冷启动阶段使用 LK Loss（KL 与 TV 自适应混合，或负 log-overlap），随后切换到端到端 TV Loss：
    \(L_{e2e} = 1 - \frac{1}{|I|D} \sum_{i\in I} \sum_{m=0}^{D-1} \prod_{k=0}^{m} \alpha_{i,k}\)
  - 损失消融实验表明，直接优化 TV 不稳定；**LK 冷启动 + e2e TV** 效果最好。

### 2.3 DFly：块并行扩散草稿架构
DFly 在 DFlash 基础上引入两个架构改进：

1. **混合目标条件骨干（Hybrid Target-Conditioning Backbone）**
   - 共享投影分支：\(c_t = W_{fc}[h_t^{(1)}; \dots; h_t^{(T)}] + b_{fc}\)，保留 DFlash 的跨层非线性变换；
   - 逐层特定视图：\(f_t^{(i)} = \sum_j \alpha_j^{(i)} h_t^{(j)}\)，借鉴 DFlare 的逐层 softmax 加权融合；
   - 二者逐位相加后经 RMSNorm：\(g_t^{(i)} = \text{RMSNorm}(c_t + f_t^{(i)})\)。
   - 好处：全局特征与逐层偏好解耦，代码任务上提升显著。

2. **前驱条件自回归头（Predecessor-Conditioned Autoregressive Head）**
   - 并行骨干仍输出 marginal 分布，无法感知块内已选 token；
   - 两种实现：
     - **Markov 头**：对并行 logits 加低秩转移偏置 \(b_{t+i} = W_1[x_{t+i-1}]W_2\)；
     - **Hidden-correction 头（最终采用）**：将前驱 token 嵌入与草稿隐藏状态拼接，经 SwiGLU 修正：\(\tilde{z}_{t+i}^D = z_{t+i}^D + \text{SwiGLU}([\bar{z}_{t+i}^D; \bar{e}_{t+i-1}])\)。
   - 这使并行骨干保持单次前向，仅增加轻量顺序模块。

3. **两阶段损失设计**
   - 冷启动：D-PACE 加权的混合 LK 损失（按前缀置信度动态加权各深度）；
   - 随后切换到端到端 TV 损失，直接优化多深度接受长度代理。

### 2.4 D-cut：自适应验证预算
- 将目标模型的验证视为**批级共享资源**，而非每个请求独立决策。
- 每个请求 i 用草稿器置信度估计前缀存活概率 \(s_{i,k} = \prod_{t=1}^k c_{i,t}\)，进而估计保留 n 个 token 的期望收益：
  \(\hat{A}_i(n_i) = \sum_{k=0}^{n_i} s_{i,k}\)
- 候选预算比例 R = {0.25, 0.50, 0.75, 1.00}，全局预算 \(K_\rho(B) = \max(B, \lceil \rho B(D+1)\rceil)\)；
- 将所有请求的 token 按置信度降序排列，取 top-K 形成各请求的连续保留前缀；
- 结合启动时 profile 的端到端延迟 \(C(B,\rho)\)，在线选择：
  \(\rho^\star = \arg\max_\rho \frac{U(B,\rho)}{C(B,\rho)}\)
- 该过程不改变目标模型输出分布，保留的 token 仍走原始验证。

### 2.5 AngelSpec 框架
基于 TorchSpec 扩展：
- 支持 MTP 的 TTT 展开、长上下文训练（Ulysses 序列并行）；
- 支持 DFly 的逐层目标条件融合、可插拔自回归头；
- 文档感知打包（document-aware packing）、注意力门控防止跨文档越界；
- 评估服务器：训练中周期性用真实引擎测接受长度和逐位接受率；
- 支持从 vLLM 抽取目标隐藏状态，流式传输给训练 worker。

## 6. 主要结论与发现

1. **工作负载特化有效**：MTP 适合高熵对话，DFly 适合代码/数学结构化续写；两类草稿器互补。
2. **TTT 显著提升 MTP 后部位置接受率**：Hy3 上平均接受率从 52.8% 提升到 66.4%（T=0），MAL 从 2.58 提升到 2.99；第3位接受率在 GSM8K 上从 0.290 提升到 0.706。
3. **DFly 架构改进有效**：在 Hy3-A21B 上平均接受长度达 4.79，比 MTP 高约 60%、比 DFlash 高约 30%；在 Qwen3-8B 上平均接受长度 5.41，优于 DSpark 的 5.32。
4. **D-cut 在高并发下显著提升吞吐**：在 Hy3-295B-A21B 生产流量上，并发 64 时吞吐比 DFly 高 15.7%，同时平均接受长度仅下降约 1.5%（2.50→2.43）；将吞吐-延迟前沿推向更高区域（相同单用户速度下高 14%）。
5. **思考模式必须匹配**：high-think 与 no-think 应分开训练草稿模型，否则接受率大幅下降。
6. **5 层草稿器 + 块大小 8 是最优效率-性能折中**，继续加深到 7 层无额外收益。
7. **端到端速度提升**：DFly 在并发 4–64 上平均吞吐为 AR 的 1.98–2.40 倍，比 DFlash 高 10.5–11.8%。

## 7. 优点

- **三层次协同设计**：训练数据、模型架构、推理调度不是孤立优化，而是围绕“真实负载异构性”这一核心统一展开，系统性较强。
- **架构创新扎实**：混合目标条件骨干和隐藏修正自回归头都建立在已有工作（DFlash、DFlare、DSpark、TreeFlash）之上，有明确的互补动机和消融验证。
- **训练目标直接面向推理指标**：使用 TV 距离、接受率、e2e 接受长度作为训练目标，而非仅依赖交叉熵，且冷启动策略避免了直接优化 TV 的不稳定性。
- **D-cut 视角新颖**：把验证算力视为批级共享资源，比传统逐请求自适应更符合真实服务场景；在几乎不损失接受率的情况下提升吞吐，实用性较高。
- **工程贡献完整**：开源训练框架，支持 MTP TTT、DFly、长上下文、文档感知打包、在线评估，可

可 复现性较强，为社区提供了完整的训练与评估闭环。

- **训练成本未披露**：论文未报告训练阶段实际 GPU 数量、GPU-hours 或 FLOPs，这对于评估方法可复现性和实际落地成本是一处明显缺口。MTP 与 DFly 均需分别训练草稿模型，且需针对 no-think / high-think 分开训练，资源开销可能不小，但文中未作讨论。
- **草稿器分工依赖人工判断**：MTP 适合高熵对话、DFly 适合代码/数学的理念直观且有实验支撑，但论文未给出一个自动的、细粒度的负载识别与路由机制；实际部署时如何判定“当前请求属于哪种类型”仍依赖静态配置或人工规则。
- **思考模式引入额外成本**：文明确认 high-think 与 no-think 必须分开训练草稿模型，这意味着每个目标模型需要维护两份甚至更多草稿器，模型版本管理、存储和切换逻辑都变得更加复杂。
- **D-cut 目前是启发式候选集搜索**：其批次级预算共享依赖于对前缀存活概率的估计和离线 profiling 得到的延迟表 C(B, ρ)，在负载模式剧烈变化（如突发流量）时是否仍能保持最优性有待验证。
- **生产验证面窄**：单一生产流量（Hunyuan）回放虽有一定代表性，但不同公司的流量组成、并发模型、硬件拓扑差异很大，结论的普适性仍需更多外部验证。
- **论文对可靠性的讨论不足**：推测解码引入了草稿模型的额外故障点、显存占用和调度开销，论文未讨论这些工程问题在真实服务中的影响。

## 9. 个人评价与讨论

AngelSpec 是一篇工程完成度和系统性都比较高的推测解码工作。它的价值不仅在于提出了某个新架构，而在于将“训练数据分工 → 草稿器架构 → 推理期调度”三个层面统一到一个框架中，并将推理指标（接受率、接受长度、端到端吞吐）直接嵌入训练目标，形成了从优化目标到在线收益的闭环。这种思路对后续推测解码研究有较强的借鉴意义。

值得注意的是，论文在评测方法上做了一个很好的示范：它同时报告了草稿质量（接受的 token 数）和端到端吞吐（并发下的 token/s），并单独剖析了草稿延迟与验证延迟的占比。这使得读者能清楚地区分“模型质量提升”和“调度优化”各自的贡献，而不是笼统地归功于某一项技术。

不过，从研究角度看，仍有几个问题值得进一步追问：

1. **MTP 与 DFly 的边界是否真的互补？** 论文的实验充分证明二者各有擅长领域，但现实中许多请求是混合型的（比如先思考后输出代码的 agent 工作流）。是否存在一种机制可以让草稿器在请求内部动态切换或在同一批内混合使用？
2. **D-cut 能否与硬件感知调度进一步结合？** 论文已注意到 GPU 资源异质性，但 D-cut 目前仍以 batch 为单位做粗粒度决策，若与更细粒度的 CUDA kernel 调度结合是否有更大空间？
3. **主观指标缺失**：论文侧重吞吐和接受率的客观指标，未报告用户可感知的时延分布（如 TTFT、TPOT 的尾延迟）。对在线服务而言，P99 时延往往比平均吞吐更关键。

整体来看，AngelSpec 是推测解码领域一篇难得的、面向真实生产环境的系统性工作，提出了若干有实用价值的技术贡献，值得后续研究者在其框架上进行扩展。
