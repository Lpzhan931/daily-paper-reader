## 摘要
大型混合专家（MoE）语言模型因其每个令牌仅激活一小部分专家而备受终端设备部署青睐，但其路由专家权重往往超过加速器内存。我们针对延迟敏感的单用户场景，其中路由专家按需从CPU内存暂存到GPU或从Flash暂存到移动NPU。在此场景下，自推测解码面临新的瓶颈：增加草稿专家集可提升准确性但会触发额外的专家加载，而廉价的小内存占用草稿则接受率低；此外，验证多令牌块会激活目标专家的并集，不再接近单个目标步骤。我们提出DraftExpert，一种面向专家卸载MoE推理的扩展感知自推测解码框架。DraftExpert通过从冻结的目标MoE中自蒸馏残差、logit/令牌和路由器一致性信号，为每层训练一个轻量级加速器驻留草稿专家。在推理时，它使用固定内存占用的共享+top-1+草稿专家草稿器，结合置信度扩展截断和目标专家预取，同时最终令牌仍由目标模型精确验证。在DeepSeek-V2-Lite和Moonlight-16B-A3B上，跨CPU-GPU和Flash-NPU卸载，DraftExpert平均提升解码吞吐量1.45倍，将草稿接受率提高至84~87%，并实现86~88%的预取命中率。

## Abstract
Large Mixture-of-Experts (MoE) language models are attractive for end-device deployment because only a small subset of experts is active per token, but their routed expert weights often exceed accelerator memory. We target latency-critical single-user settings where routed experts are staged on demand from CPU memory to a GPU or from Flash to a mobile NPU. In this setting, self-speculative decoding faces a new bottleneck: increasing the draft expert set improves accuracy but triggers extra expert loading, while cheap small-footprint drafts have low acceptance; moreover, verifying a multi-token block activates the union of target experts and is no longer close to one target step. We propose DraftExpert, an expansion-aware self-speculative decoding framework for expert-offloaded MoE inference. DraftExpert trains one lightweight accelerator-resident draft expert per layer by self-distilling residual, logit/token, and router-agreement signals from the frozen target MoE. At inference time, it uses a fixed-footprint shared+top-1+draft-expert drafter together with confidence--expansion truncation and target-expert prefetching, while final tokens are still exactly verified by the target model. On DeepSeek-V2-Lite and Moonlight-16B-A3B across CPU-GPU and Flash-NPU offload, DraftExpert improves decode throughput by 1.45x on average, raises draft acceptance to 84~87%, and achieves 86~88% prefetch hit rates.

## 一、核心问题与整体含义（研究动机与背景）

大型混合专家（Mixture-of-Experts, MoE）语言模型因每个 token 仅激活少数专家，被视为适合终端设备部署的候选方案。然而其路由专家权重往往远超消费级 GPU 或移动加速器的内存容量，实际系统只能将目标 MoE 的路由专家放在 CPU 内存（CPU→GPU 场景）或移动 Flash（Flash→NPU 场景）中按需加载，其余非路由权重（attention、共享专家、router 等）常驻加速器。此时**专家搬运（expert movement）替代算术计算成为主导解码延迟的瓶颈**。

论文的核心论点是：在该“专家卸载（expert-offloaded）”场景下，经典自推测解码的**三个成功条件全部被破坏**：

1. **草稿不廉价**：训练无关的 shared+top-r 自草稿器为提升精度增大 r，会加载更多被卸载的专家，草稿成本随之上升；
2. **验证不接近单步**：验证 K 个 token 会激活目标专家的并集，专家集随块长度快速增长，单次并行验证不再是“接近一个目标步骤”的成本；
3. **接受率不高**：若保持小 footprint（top-1），则会遗漏路由专家的残差贡献，造成隐状态漂移、路由一致性弱，接受率极低。

因此，性能的核心度量单位从“每目标前向的 token 数”转变为 **“每专家集扩展所接受的 token 数（accepted tokens per newly loaded expert）”** 。论文提出 **DraftExpert**，一个扩展感知的自推测解码框架，以恢复上述三个条件。

## 二、方法论

### 2.1 核心思想

DraftExpert 的总体思路是：**用一个小型加速器驻留的可学习模块（草稿专家）替代加载更多路由专家**，并通过自蒸馏从冻结的目标 MoE 中恢复被 top-1 草稿遗漏的信息；同时利用路由器一致性蒸馏让草稿的隐状态能够预测验证阶段的目标专家集合，从而支撑动态截断与预取。

### 2.2 固定占用空间草稿（Fixed-Footprint Drafting）

目标 MoE 第 l 层的完整输出为：

```
y*_l = S_l(h_l) + Σ_{e∈TopK_l(h_l)} g_{l,e}·E_{l,e}(h_l)
```

DraftExpert 为每层增加一个**草稿专家 E^d_l**，草稿输出为：

```
y^d_l = S_l(h_l) + g_{l,e1}·E_{l,e1}(h_l) + γ_l·E^d_l(h_l)
```

其中 e1 为目标 router 的 top-1 专家。草稿路径只使用“共享专家 + top-1 路由专家 + 草稿专家”，路由专家使用量接近 top-1，但草稿专家可以在不增加 r 的前提下学习被省略的 top-k 信息。

### 2.3 自蒸馏损失（训练目标）

DraftExpert 从冻结的目标 MoE 蒸馏四类信号（损失函数文字描述如下）：

| 损失项 | 作用 | 形式 |
|---|---|---|
| 残差损失 L_res | 让草稿专家逼近被省略的“目标输出 − 共享路径 − top-1 路径”残差 | 均方误差 |
| Logit 损失 L_logit | 蒸馏目标模型最终输出的 logit 分布（带温度缩放） | KL 散度 |
| Token 损失 L_tok | 蒸馏目标模型的 top-1 token 标签 | 交叉熵 |
| 路由器一致性损失 L_router | 让草稿隐状态的路由分布逼近目标隐状态的路由分布 | KL 散度 |

总损失为 `L = L_logit + α·L_tok + β·L_res + η·L_router`。**L_res/L_logit/L_tok 负责恢复草稿接受率；L_router 专门提升验证阶段的专家预测与预取命中率**。所有监督信号来自无标注文本和冻结的目标 MoE，无需额外标注。

### 2.4 成本感知动态截断（Confidence–Expansion Truncation）

对第 i 个候选 token，系统维护预测的验证专家集：

```
Û_i = ∪_{j≤i} ∪_l Ê_{l,j}
```

边际扩展量 Δ_i = |Û_i| − |Û_{i−1}|。**当候选人被接受的可能性低（置信度 qi < τ）且预测新增验证专家多（Δ_i > B_i）时，停止草稿**。该策略是精确的（exact）：被截断的 token 不会被发射，所有发射的候选人仍由完整目标 MoE 验证。

### 2.5 草稿-路由器专家预取（Draft-Router Expert Prefetch）

草稿阶段每保留一个 token，立即对预测的验证专家集 Û_i 中未缓存、不在途的专家发起异步预取，与剩余草稿计算重叠。验证阶段只需等待在用预取；若有未命中的专家仍按需加载。这**不改变模型语义**——命中节省延迟，未命中浪费带宽，必需而漏掉的专家走按需加载回退。

### 2.6 推理流程（伪代码）

1. 用共享+top-1+草稿专家路径生成候选 token v_i，计算置信度 q_i 与预测验证专家集 Û_i；
2. 计算边际扩展 Δ_i，若 `q_i < τ 且 Δ_i > B_i` 则停止；
3. 保留 v_i，对 Û_i 中未缓存/在途的专家发起异步预取；
4. 等待在途预取，用冻结的目标 MoE 验证全部候选 token；
5. 取目标一致前缀发射，继续解码。

## 六、主要结论与发现

1. **端到端提速显著**：DraftExpert 在两个模型、两种卸载平台上平均提升解码吞吐 **1.45 倍**（DS CG 1.36×、DS MN 1.52×、ML CG 1.29×、ML MN 1.61×）；Flash→NPU 场景因专家搬运瓶颈更突出，收益更大。
2. **草稿接受率大幅提升**：固定 footprint 下，DS/ML 接受率达 **85%/83%**，远超 top-1（~22%）和 top-3（~44-46%），且草稿成本仅比 top-1 高 5-9%，远低于 top-3 的 59-86% 额外开销。
