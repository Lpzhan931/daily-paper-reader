## 摘要
基于大型语言模型（LLM）的智能体应用通常面临较高的响应时间。投机解码是一种有前景的解决方案，可在不影响生成质量的前提下提高LLM智能体的推理效率。然而，现有最先进的投机解码算法在大批量下会显著降低速度，限制了其在真实智能体应用中的部署效果。在本工作中，我们首先对LLM智能体的投机解码进行了系统分析，并确定了加速性能下降的两个主导因素：投机令牌的高拒绝率以及动态令牌预算的利用不足。基于这些观察，我们提出了AgentSpec，一种针对LLM智能体现有方法局限性而设计的投机解码算法。AgentSpec引入了结构隔离式草拟，将投机限制在智能体工作流的语义连贯片段内，减少不相关语义路径的草拟，从而实现极低的拒绝率。此外，AgentSpec采用冗余感知的预算分配，利用智能体级信息更好地利用推理过程中动态空闲的令牌预算。我们在vLLM中针对五种不同工作负载和来自四个不同LLM家族的四种不同模型进行了实现与评估。结果表明，AgentSpec优于现有最先进方法。

## Abstract
Large language model (LLM)-based agent applications often incur high response time. Speculative decoding is a promising solution to improve the inference efficiency of LLM agents without impacting generation quality. However, state-of-the-art speculative decoding algorithms exhibit substantial speed degradation under large batch sizes, limiting their effectiveness to deploy in real-world agent applications. In this work, we first present a systematic analysis of speculative decoding for LLM agents and identify two dominant factors of speedup degradation: high rejection rate of speculative tokens, and under-utilization of dynamic token budgets.B ased on these observations, we propose AgentSpec, a speculative decoding algorithm that addresses the limitations of existing methods for LLM agents. AgentSpec incorporates structure-isolated drafting that constrains speculation to semantically coherent segments of the agent workflow, reducing the drafts of irrelevant semantic paths and achieving an extremely low rejection rate. Moreover, AgentSpec adopts redundancy-aware budget allocation that exploits agent-level information to better utilize the dynamically-free token budget during the agent inference. We implement and evaluate AgentSpec on five different workloads and four different models from four different LLM families in vLLM. Our results demonstrate the superiority of AgentSpec over state-of-the-arts.

## 1. 核心问题与研究动机

LLM Agent（智能体）应用在多步推理、工具调用、环境交互等任务中表现出色，但实际部署时存在严重的推理延迟和成本问题。

投机解码（Speculative Decoding）可以在不改变生成质量的前提下加速 LLM 推理，本论文聚焦于其在智能体场景中的应用。然而作者通过系统分析发现：

- **现有投机解码算法在单请求/小批量下效果好**（如 EAGLE-3 在 batch=1 时可达 2.5× 加速），但在现代 LLM serving 系统常用的大批量（batch > 32）场景下性能急剧下降，甚至劣于普通自回归解码。
- 论文识别出两个核心瓶颈：
  1. **高拒绝率**：智能体工作流中投机 token 被拒绝的比例非常高（EAGLE-3 超 50%，NGram 超 85%），导致大量验证开销被浪费。
  2. **动态 token 预算利用不足**：不同 batch 大小下可用于投机的 token 预算动态变化，现有方法要么统一分配、要么基于粗粒度统计分配，均不能有效利用可用预算。

## 2. 方法论：AgentSpec

AgentSpec 是一种**无需草稿模型（draft-model-free）**的投机解码算法，专门针对 LLM Agent 批量推理设计，包含两个关键组件：

### 2.1 结构隔离式草拟（Structure-Isolated Drafting）

- **核心思想**：Agent 的一个用户 query 会跨多个请求、分属不同语义块（如推理、工具调用、结果解读）。同语义块内生成模式高度一致，跨块/跨 query 则出现语义跳跃。通过限制草稿只在相同语义块内检索历史，可大幅降低不相关候选和拒绝率。
- **实现方式**：
  - 要求 agent 应用显式提供结构标识符 \(S_i = \{a_i, q_i, B_i\}\)（agent ID、query ID、语义块边界 tag 列表）；
  - 维护 token-to-string 缓存映射，避免频繁调用 tokenizer；
  - 使用轻量级字符串下推自动机（PDA）增量跟踪当前生成处于哪个语义块；
  - 每个语义块维护独立的历史缓存，只从匹配块内检索草稿候选。
- **效果**：将拒绝率从 53.3%（EAGLE-3）降至 26.4%，降低约 50%。

### 2.2 冗余感知预算分配（Redundancy-Aware Budget Allocation）

- **核心思想**：在 agent 工作负载中，若草稿与历史上重复出现的连续模式越一致，越可能被 target model 接受。因此应给“冗余度更高”的请求分配更多投机 token。
- **冗余度分数**：
  \[
  g(c,n) = \frac{c}{n} \cdot p(n), \quad p(n) = g_{\min} + (1 - g_{\min})(1 - e^{1-n})
  \]
  其中 \(n\) 为同一语义块内检索到的候选延续数，\(c\) 为与最频繁前缀一致的候选数；\(p(n)\) 用于在历史样本少时降低置信度。
- **批量预算**：\(B_t = \lfloor \alpha b_z \rfloor\)，其中 \(b_z\) 为 batch size，\(\alpha\) 控制总投机预算。
- **单请求草稿长度分配**：
  \[
  L_i = \max\left(|CT_i^*|, \frac{B_t \cdot g_i}{\sum_j g_j}\right)
  \]
  保证每个请求至少可以草拟其最置信的前缀，同时将较多预算分配给冗余度更高的请求。

该设计使 AgentSpec 的总草稿 token 数始终不超过硬件可用预算 \(M(b)\)，且随 batch 增大逐渐趋近预算上限，实现有效利用。

## 6. 主要结论与发现

- AgentSpec 在所有 agent 工作负载和模型上**一致优于 EAGLE-3、NGram、SuffixDecoding 和 MTP**。
- 现有投机解码算法在 agent 批量推理中普遍出现“负加速”（比普通自回归慢），而 AgentSpec 始终保持加速，最高达 **2.02×**（GPT-OSS-20B 上 CodeGen Agent）。
- AgentSpec 在非 agent 的 Spec-Bench 上也有效（1.14× 整体加速，子集最高 1.40×），说明其不止适用于 agent 场景。
- 与 MTP 相比，AgentSpec 在 MiMo-7B 上依然取得更高 goodput 和稳定加速。
- 结构隔离式草拟对提升效果的贡献大于冗余感知预算分配；两者结合效果最佳。
- AgentSpec 显著降低尾延迟（P90 降低 1.47×，P99 降低 1.39×），主要来源于验证开销减少 21%。
- 在没有显式语义结构输入时，AgentSpec(N) 依然优于所有 baseline，具备较好的通用性。

## 7. 优点

- **问题定位精准**：通过建模 \(\Delta T(b) \approx D(b)[(1-\rho(b))t_A - t_V(b)]\)，清晰指出“拒绝率”和“预算利用”两大瓶颈，分析有理论支撑。
- **设计契合 agent 场景**：利用 agent 工作流天然存在的语义块结构进行结构隔离草拟，思想直观且有效。
- **无草稿模型、无额外训练**：部署成本低，只需 agent 工程提供轻量结构元数据，对 serving 系统侵入性小。
- **预算分配有据可依**：用冗余度分数作为可预测的接受率代理信号，并在低历史支持场景下自动降置信，机制合理。
- **工程实现完整**：在 vLLM 生产级引擎中实现，公开 API 示例和补充复杂度分析，代码可复现性强。
- **实验全面**：多模型、多任务、多难度、多 batch、多 GPU、多消融，结论稳健。

## 8. 不足与局限

- **依赖语义结构信息**：结构隔离式草拟需要 agent 应用提供语义块边界 tag；虽然无该信息时仍可使用变体 AgentSpec(N)，但加速效果可能下降，且需要额外的接口改造。
- **对重复模式有依赖**：其草稿来源为历史重复生成片段；若工作负载中重复模式极少（如某些高度新颖的开放性任务），冗余度估计和草稿质量都会受影响。
- **实验未覆盖极端动态场景**：如真实生产环境的请求到达波动、混合工作负载、多租户并发、KV cache 压力等，均未充分验证。
- **大规模分布式扩展未验证**：论文仅在单卡 A100/H100 上测试，未说明多卡、多节点 tensor/pipeline 并行下的表现。
