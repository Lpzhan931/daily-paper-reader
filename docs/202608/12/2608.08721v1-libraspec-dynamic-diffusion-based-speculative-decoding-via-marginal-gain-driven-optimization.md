## 摘要
投机解码通过草拟多个令牌进行并行验证来加速大型语言模型推理，其效率关键取决于每轮解码所选择的投机长度。现有的动态投机方法通过估计将被接受的令牌数量来选择投机长度，这对于按顺序生成令牌的自回归式草拟器是合理的。然而，最近一波基于扩散的草拟器以显著更低的草拟成本并行生成候选块，将关键问题从生成多少令牌转变为有多少生成的令牌值得验证。因此，我们将动态投机长度选择重新表述为期望加速优化，并推导出一个边际准则：仅当接受增益超过额外验证成本时，才扩展投机序列。基于这一准则，我们开发了LibraSpec，这是一种无需训练且即插即用的算法，利用草拟器的置信度分数迭代确定投机长度。理论上，我们证明了LibraSpec单调收敛于最优投机长度。在六个目标模型、三种基于扩散的投机解码方法以及数学、编码和聊天基准上的实验表明，在贪婪和采样设置下均取得了一致的改进，相对于基线实现了额外0.5至1.5倍的提升，并相对于自回归解码实现了高达8.49倍的加速。

## Abstract
Speculative decoding accelerates large language model inference by drafting multiple tokens for parallel verification, with efficiency critically determined by the speculative length selected at each decoding round. Existing dynamic speculation methods select the speculation length by estimating how many tokens will be accepted, which is reasonable for autoregressive drafters that generates tokens sequentially. The recent wave of diffusion-based drafters, however, generates candidate blocks in parallel at substantially lower drafting cost, shifting the key question from how many tokens to generate to how many generated tokens are worth verifying. We therefore reformulate dynamic speculative-length selection as expected-speedup optimization and derive a marginal criterion that extends the speculative sequence only when its acceptance gain outweighs the additional verification cost. Building on this criterion, we develop \textit{LibraSpec}, a training-free and plug-and-play algorithm that iteratively determines the speculative length using drafter confidence scores. Theoretically, we prove that LibraSpec monotonically converges toward the optimal speculative length. Experiments across six target models, three diffusion-based speculative decoding methods, and math, coding, and chat benchmarks show consistent improvements under both greedy and sampling settings, achieving a further $0.5\sim1.5\times$ improvement over baselines and up to $8.49\times$ speedup over autoregressive decoding.

## 1. 核心问题与研究动机

- **背景**：自回归大语言模型（LLM）逐 token 生成，解码成为长上下文推理、代码生成和交互式应用的主要瓶颈。投机解码（Speculative Decoding）通过轻量草稿模型先产生候选 token 序列，再由目标模型并行验证，在保持输出分布不变的前提下实现无损加速。
- **关键问题**：每轮解码的**投机长度**（speculative length）——即提交验证的候选 token 数量——对最终加速比有决定性影响。长度过短会低估并行验证的收益；长度过长则可能因早期拒绝导致后缀验证算力浪费，甚至降低加速比。由于不同解码轮次的 token 可预测性动态变化，最优长度也随之改变，因此需要**动态投机长度选择**。
- **现有方法的局限**：已有动态长度方法主要预测“被接受的 token 数量”，这适用于**自回归式草稿者**（每个额外候选 token 都有顺序生成成本）。但新兴的**扩散式草稿者**以极低代价并行生成候选块，其优化目标已变为“多少生成的 token 值得验证”，仅估计期望接受长度不足以决定扩展投机前缀是否提升加速比——即使扩展很可能被接受，其带来的收益也可能无法抵消额外验证成本。换句话说，现有方法错失了“接受增益 vs. 验证开销”这一关键权衡。
- **研究目标**：提出一种面向扩散式投机解码的动态长度选择方法，直接优化期望加速比，而非预测接受长度，并具备无需训练、即插即用的特性。

## 2. 方法论

### 2.1 核心思想
- 将动态投机长度选择重新表述为**期望加速比优化问题**，推导出**边际增益准则**：仅当新增候选段的边际收益高于当前平均收益时，才值得扩展投机序列。
- 迭代地利用草稿模型置信度分数（confidence scores）近似目标模型接受概率，逐步逼近最优投机长度。

### 2.2 形式化定义与关键公式
- 对前缀 \(x_{\le t}\) 和长度 \(d\) 的草稿块 \(D_{1:d}\)，定义加速比：
  \[
  \eta_d = \frac{\tau_d L_{\text{target}}}{T_{\text{draft},d} + T_{\text{verify},d}}
  \]
  其中 \(\tau_d\) 为接受的连续 token 数，\(L_{\text{target}}\) 为目标模型单 token 延迟，\(T_{\text{draft},d}\) 与 \(T_{\text{verify},d}\) 分别为草稿生成与验证耗时。
- 由于扩散草稿者生成成本极低，可近似 \(T_{\text{draft},d} \approx 0\)，于是加速比主要由接受长度和验证成本决定。

- **定义（单次有益调整）**：从 \(d\) 到 \(d'\) 的调整是“有益的”，当且仅当 \(\mathbb{E}[\eta_{d'}] > \mathbb{E}[\eta_d]\)。

- **定理 3.2（边际准则）**：单次有益调整当且仅当调整段的边际收益高于当前平均收益：
  \[
  \frac{\mathbb{E}[\tau_{d:d'}]}{T_{\text{verify},d:d'}} > \frac{\mathbb{E}[\tau_d]}{T_{\text{verify},d}} \quad (d<d')
  \]
  （截断情形则要求相反不等式。）

- **定理 3.3 与 3.4（位置级边界）**：在位置级强化准则下，对所有 \(i \in [1,d]\)，
  \[
  d' \le \epsilon_i,\quad \epsilon_i=\max\Big\{d'\in\mathbb{Z} \mid d' < \frac{T_{\text{verify},i}}{\tau_i c}\sum_{j=i}^{d'}\prod_{k=i}^{j}p_k + i\Big\}
  \]
  其中 \(p_k\) 为第 k 个位置的接受概率，\(c\) 为每个投机位置的平均验证成本。定理 3.4 证明 \(d' = \min_i \epsilon_i\) 是单次有益调整的充分条件。

- **定理 3.5（单峰性）**：期望加速比关于投机长度是**单峰函数**：
  \[
  \mathbb{E}[\eta_{d+1}] > \mathbb{E}[\eta_d] \iff \prod_{i=1}^{d+1} p_i > \frac{c\, \mathbb{E}[\tau_d]}{T_{\text{verify},d}}
  \]

- **定理 3.6（收敛性）**：反复执行单次有益调整，投机长度在有限步内收敛到全局最优区间。

### 2.3 算法（LibraSpec）
- **输入**：块大小 \(n\)，最大投机长度 \(d_{\max}\)。
- **流程**：
  1. 生成一个包含 \(n\) 个 token 的草稿块。
  2. 初始化投机长度 \(d \leftarrow n\)，草稿预算 \(B \leftarrow 0\)。
  3. 循环直到 \(d \ge d_{\max}\)：
     - 用草稿置信度 \(q_k\) 近似真实接受概率 \(p_k\)，计算 \(\epsilon^* = \min_i \epsilon_i\)。
     - 若 \(\epsilon^* \le d\)，则设置 \(d \leftarrow \epsilon^*\) 并停止。
     - 否则将 \(d\) 更新为 \(\epsilon^*\)，消耗预算 \(B\)；当预算不足时按需生成额外的草稿块。
  4. 提交前 \(d\) 个 token 进行验证。
- **工程细节**：
  - 引入**草稿预算**（draft budget）\(B\)，避免频繁调用草稿模型，降低 I/O 开销。
  - 用**单一超参数** \(\alpha = \frac{T_{\text{verify},i}}{\tau_i c}\) 控制调整激进程度。
  - 每轮最多执行一次回退（rollback），防止因长度调整与概率估计相互作用产生振荡，增强稳定性。
  - 采用“置信度校准假设”（Assumption 3.7），即草稿模型置信度 \(q_i\) 与目标模型接受概率 \(p_i\) 良好校准；同时为不同草稿模型设置最大投机长度 \(d_{\max}\)。

- **动态长度选择的核心应转向加速比优化**：扩散式草稿者的低边际成本使“估计接受长度”不再充分，必须权衡接受增益与验证开销。

- **LibraSpec 显著提升加速比**：
