## 摘要
大语言模型（LLM）推理服务日益受到内存而非算力的制约。随着长上下文和长形式推理工作负载日益普及，键值（KV）缓存在LLM令牌生成（即解码）过程中主导了内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储与HBM解耦，缓解HBM容量压力。由于解码时的注意力天然稀疏，OasisKV在HBM中仅保留最相关令牌的KV条目用于注意力计算。我们观察到，利用投机解码（SD）起草的前瞻令牌可以提前准确预测未来重要的令牌。OasisKV采用高效的注意力后台流水线来识别重要的KV块，然后从更高容量的内存层级（如主机或远程内存）预取这些块，并在下一步解码使用之前暂存到HBM中。我们基于vLLM实现了OasisKV。在2,048令牌的KV预算下，前瞻预测足够准确，将精度保持在完整注意力的0.7个点以内。这使得OasisKV能够将稀疏性转化为吞吐增益：在推理工作负载上，相比密集vLLM实现1.69倍的吞吐提升，精度损失仅0.1个点；在多GPU长上下文服务中，吞吐提升可达2.1倍。在预填充-解码分离场景下，OasisKV达到约2倍的密集吞吐，同时每个请求的KV占用减少6.5至9.7倍，且解码节点主机内存占用比完整KV传输少2.2至2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

- **内存墙问题日益凸显**：LLM推理服务正从算力受限转向内存受限。随着长上下文和agentic推理工作负载（如Web-use、computer-use、coding agents）的兴起，KV缓存在LLM解码阶段同时主导了内存占用和内存流量。
- **HBM容量成为关键瓶颈**：HBM容量稀缺且昂贵，直接限制了推理批大小（batch size）与系统吞吐。以Qwen3-32B为例，平均上下文长度32.7K时，单个请求约需8.6 GB KV缓存，即使将80 GB HBM全部用于KV，最大批大小也仅有9个请求。
- **现有方案均未完整解决该问题**：
  - **稀疏注意力**（如NSA、Quest）减少KV读取，但未降低HBM中保留完整KV缓存所需的容量；
  - **KV检索**（如ShadowKV、ArkVale）将完整KV存放在主机内存中，但按需传输处于解码关键路径，传输延迟直接导致TPOT升高；
  - **KV预取**（如InfiniGen、FreeKV）试图预测并预取重要KV块，但缺乏高效的多层级内存管理系统，且现有预测信号的准确性不足。
- **PD分离进一步加剧问题**：预填充节点与解码节点之间需要传输完整KV缓存，增加了TTFT并消耗大量的解码节点主机DRAM，限制解码批大小。
- **OasisKV的整体定位**：将KV预取重叠、基于前瞻的稀疏预测、稀疏性与准确性权衡视为联合系统优化问题，提出以内存为中心的推理系统设计，有效突破本地和远程的off-GPU内存墙。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想

OasisKV的核心思想是：**在解码期间仅将完整KV缓存的一部分（稀疏工作集）保存在HBM中，利用投机解码（Speculative Decoding）产生的前瞻令牌（lookahead tokens）准确预判下一步注意力所需的KV块，并通过异步流水线从更高容量内存层级（CPU DRAM或远程内存）预取到HBM**。

### 2.2 关键技术细节

- **前瞻注意力（Look-ahead Attention）**：
  - 利用EAGLE-3等MTP（multi-token prediction）技术生成draft token，作为未来KV访问模式的训练无关信号；
  - 将draft query与normal query堆叠在一起，在同一个稀疏KV工作集上执行注意力，一次计算同时产生两个输出；
  - 经验验证：用propagated draft query预测的top-20 KV块集合与真实下一token的top-K集合逐层一致性高达98.74%。
  
- **压缩键缓存（Compressed Key Cache）**：
  - 在GPU HBM中维护每个逻辑块的坐标最小值和最大值（Quest-style的block-wise min/max summaries）；
  - draft query通过在压缩键上扫描即可对全局所有块进行排名，无需恢复完整键；
  - 开销仅为完整KV缓存大小的1/16。

- **完全异步的后台流水线**：
  - 三维流水线：Top-K预测 → KV选择 → KV传输，各层独立执行，由协调器驱动；
  - 每层使用独立的CUDA流，CUDA事件保证层内依赖；
  - 背景流水线稳态完成间隔满足 $T_{pipe} = \max\{T_{pred}, T_{select}, T_{transfer}\} \leq \Delta_{prefetch}$；
  - 层局部同步：在step t+1执行第l层注意力之前，仅等待step t为该层发起的KV传输完成，不阻塞整步。

- **Delta选择与封顶驱逐策略（Delta Selection and Capped Eviction）**：
  - KV选择阶段先求预测集与驻留集的交集，驻留块不产生PCIe流量；
  - 采用LRU风格策略选择驱逐目标，每个非驻留被预测块配对一个驱逐目标；
  - 每个KV头每步最多接纳C对（**fetch cap**），将单步传输量限制在解码时间窗口可隐藏的字节预算内。

- **头感知映射（Head-wise Mapping）**：
  - 在原有GPU/CPU页表之上增加一层头感知的逻辑到逻辑映射；
  - 不同KV头可维护不同的稀疏块集合，各GPU在张量并行下独立更新本地KV头的映射，无需跨GPU同步。

- **远程部分抓取（Remote Partial Fetching, RPF）**：
  - **部分传输**：预填充阶段额外执行一步解码，用首令牌query确定每层的top-K块集合，仅传输该集合+压缩键+draft KV状态，避免完整KV传输，降低TTFT。
  - **网络预取**：解码过程中若top-K漂移到解码节点主机内存中缺失的块，视为缓存未命中，通过后台流水线从预填充节点远程读取。

- **实现**：基于vLLM V1引擎，C++/CUDA实现核心模块，NIXL + UCX实现跨节点传输。

## 6. 论文的主要结论与发现

1. **高效预测**：利用draft token传播得到的top-K集与真实下一token的top-K集逐层一致率达98.74%，远超previous-token代理（83.9%），且无需训练专用预测器。
2. **大幅吞吐提升**：
   - 合成负载中，Qwen3-8B吞吐达2.1×密集vLLM，Qwen3-235B达1.9×；
   - 真实AIME24工作负载：Qwen3-8B 1.69×（精度损失仅0.1点），Qwen3-235B 1.20×；

3. **准确性保持**：在2,048令牌KV预算下，全程准确率距full-attention锚点在0.7点以内（pass@k平均−0.66，avg@k平均−0.35）。
4. **PCIe带宽是核心瓶颈**：消融显示吞吐由PCIe带宽而非注意力算力决定，fetch cap在0.05时达到最佳权衡（吞吐2,083 tok/s、精度−0.1点）。
5. **RPF的带宽平滑效应**：相对于完整KV传输的大突发特征，RPF将流量在时间上均匀分布，显著降低峰值带宽需求。

## 7. 优点

- **预测信号新颖且高效**：利用投机解码的draft token作为前瞻信号，与推测解码天然兼容，零额外训练开销，克服了previous-token代理的准确性不足。
- **系统设计整体性强**：将预测、选择、传输、内存管理统一为联合优化问题，异步三层流水线设计保证了预取可隐藏于解码计算之后。
- **对PCIe带宽的明确上限控制**：capped eviction策略以显式字节预算限制单步传输，可直接映射到硬件带宽约束。
- **对PD分离的深度支持**：远程部分抓取不仅减少传输量，还改变了流量时间分布，降低突发峰值，并缓解解码节点内存压力。
- **生产级集成**：基于vLLM实现而非玩具原型，支持多GPU（TP）部署，对从dense到sparse解码的转换、混合批处理有合理的调度设计。
- **评估较全面**：涵盖从8B到235B模型、单GPU到多GPU、本地到跨节点、长输入到长输出。

## 8. 不足与局限

- **依赖外部draft模型**：EAGLE-3等draft模型本身可能未对OasisKV的预测目标进行优化，draft模型的分布偏移可能影响预测稳定性；论文承认draft token被强制拒绝，未与投机解码的token接受结合。
- **前缀缓存不支持的局限**：当前原型未实现prefix caching，论文仅用数学模型分析RPF在prefix caching下的潜在TTFT收益，缺乏实测验证。
- **适用模型范围有限**：实验仅覆盖Qwen3系列和Llama-3.1-8B，未覆盖更长上下文窗口模型（如128K训练窗口下仅测至32K）或更多架构变体。
- **低批次场景下TPOT可能劣于dense**：Qwen3-235B低批时TPOT高于dense，因为KV占比小，稀疏性收益有限而每步额外开销依然存在。
- **无前缀缓存时RPF端到端收益有限**：分解显示，若无fetch cap，RPF最终传输量仍为完整传输的约1/1.33–1/1.5（虽然加入cap后可提升至1.9–2.2×），且解码期漂移会持续消耗网络带宽。
- **对比框架的非对称性**：ShadowKV、InfiniGen、FreeKV在多GPU场景下无法运行，跨框架对比无法完全控制实现质量差异。
