## 摘要
大语言模型（LLM）推理服务日益受到内存而非计算能力的制约。随着长上下文和长形式推理工作负载变得越来越普遍，键值（KV）缓存在LLM令牌生成（即解码）过程中主导了内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批处理大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储与HBM分离来缓解HBM容量压力。由于解码时的注意力天然具有稀疏性，OasisKV仅在HBM中保留最相关令牌的KV条目用于注意力计算。我们观察到，使用投机解码（SD）起草的前瞻令牌可以提前准确预测未来的重要令牌。OasisKV采用高效的注意力后台流水线来识别重要的KV块，然后从更高容量内存层级（例如主机内存或远程内存）预取这些块，并在下一步解码使用前将其暂存于HBM中。我们基于vLLM实现了OasisKV。在2,048令牌的KV预算下，前瞻预测足够准确，可将精度保持在完整注意力的0.7个百分点以内。这使得OasisKV能够将稀疏性转化为吞吐量增益：在推理工作负载上，相比密集vLLM，吞吐量提升1.69倍，精度损失仅0.1个百分点；在多GPU长上下文服务中，吞吐量提升可达2.1倍。在预填充-解码分离场景下，OasisKV的密集吞吐量约为2倍，同时每个请求的KV量减少6.5–9.7倍，解码节点主机内存占用比完整KV传输减少2.2–2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- **核心瓶颈**：大语言模型（LLM）推理服务日益**受内存而非计算能力制约**。随着长上下文（long-context）与长形式推理（long-form reasoning）工作负载涌现（如 Web-use、computer-use、coding agents 等智能体任务），KV 缓存在解码阶段同时主导**内存占用**与**内存流量**。
- **HBM 稀缺性**：高带宽内存（HBM）容量有限且昂贵，严重限制了解码批处理大小（batch size）与系统吞吐量，形成典型的“内存墙”（memory wall）瓶颈。
- **现有方案局限**：
  - 稀疏注意力（sparse attention）只减少 KV 读取量，**不解决 HBM 容量**问题；
  - KV 检索（KV retrieval）将 KV 放至 CPU 内存，但**取回延迟落在解码关键路径**上；
  - KV 预取（KV prefetch）尝试重叠传输与计算，但缺乏高效的跨层内存管理，且**受限于 CPU-GPU IO 带宽屋顶**；
  - 在 PD 分离（prefill-decode disaggregation）场景下，全量 KV 传输既增加 TTFT，又耗尽解码节点主机 DRAM。

**整体含义**：OasisKV 提出一种以内存为中心的 LLM 推理系统设计，通过**在解码期间将完整 KV 缓存存储与 HBM 解耦**，利用**前瞻稀疏预取**（lookahead sparse prefetching）突破 HBM 容量墙，实现高吞吐、低精度损失的 LLM 推理服务，并支持多 GPU 部署与 PD 分离。

## 2. 论文提出的方法论

**核心思想**：解码时的注意力天然具有稀疏性，因此只需在 HBM 中保留最相关令牌的 KV 条目；通过投机解码（Speculative Decoding, SD）产生的**草稿令牌**（draft token）作为免费且准确的前瞻信号，提前一步预测未来注意力将访问的重要 KV 块，并经过**完全异步的后台流水线**从更高容量内存层级（CPU DRAM/远程内存）预取至 HBM。

**关键技术细节：**

1. **Look-ahead Attention（前瞻注意力）**：
   - **低开销前台**：QKV 投影同时产生普通查询与草稿查询（stacked queries），共享同一份驻留 KV 工作集，一次前向调用输出两者；草稿查询扫描**压缩键摘要**（per-block min/max pooling，类 Quest 风格）以排序所有逻辑块，预测下一帧的 top-K 集合。压缩摘要仅占完整 KV 缓存大小的 1/16。
   - **预测精度**：实验证明，草稿查询预测的 top-K 集合与真实下一令牌查询的结果在每层一致性超过 98.2%，平均 98.74%，远优于用当前令牌作为代理的传统方法（平均 83.9%）。

2. **完全异步后台流水线**：
   - 每层形成“top-K 预测 → KV 选择 → KV 传输”的严格链式依赖，但**层间相互独立**，因此可跨层流水线并行（layer l+1 预测、layer l 选择、layer l−1 传输同时进行）。
   - 三个阶段分别运行在独立 CUDA 后台流上，由协调器（coordinator）驱动；前台仅在每层注意力前等待该层上一帧发起的 KV 传输完成（layer-local synchronization），而不必等待所有层。
   - 流水线稳态周期为 `max{T_pred, T_select, T_transfer}`，受最慢阶段限制。

3. **Delta Selection 与 Capped Eviction（封顶驱逐策略）**：
   - KV 选择阶段先计算预测集与驻留集的交集，已驻留块不产生 PCIe 流量。
   - 对缺失块，按最近最少选中（least-recently-selected）策略选出驱逐目标，每个新进块配对驱逐目标；**每 KV 头每步最多允许 C 个新块进入**，从而将每层传输量上界限制为 C×H 个块，保证 PCIe 流量不超过解码时窗预算 `C_token = B_link × T_decode`。

4. **KV 管理与请求调度**：
   - 在现有 GPU/CPU 页表之上增加**head-wise 逻辑到逻辑映射层**，使不同 KV 头可以维护不同的稀疏块集合，同时不破坏原有 PagedAttention 路径与统一批处理注意力内核。
   - 请求先以密集模式运行，超过稀疏化阈值（token budget）后将完整 KV 复制到 CPU 内存，GPU 仅保留选中历史块加局部窗口。
   - 支持密集与稀疏请求同批混跑。

5. **远程部分获取（Remote Partial Fetching, RPF）**：
   - 用于 PD 分离场景，避免在解码节点物化完整 KV。
   - **部分传输（Partial Transfer）**：预填充节点多执行一个解码步，用首个生成令牌的查询选出每层 top-K 块集合并取并集；只传输该稀疏并集 + 压缩键缓存 + 草稿 KV 状态。
   - **网络预取（Network Prefetch）**：解码过程中若选中块不在解码节点主机内存，视为 cache miss，按与 PCIe 预取相同的后台流水线从预填充节点发起远程读取至主机 DRAM，再聚合进入 GPU HBM。
   - 每个块至多跨网络一次，块在解码节点的驻留集单调增长。

## 6. 论文的主要结论与发现

1. **性能收益**：
   - 合成负载：Qwen3-8B 在 16K 上下文下最大达 **2.1×** vLLM 密集吞吐（1,398 vs. 676 tok/s）；Qwen3-235B TP8 下达到 **1.9×**（1,102 tok/s）。
   - AIME24 真实推理负载：Qwen3-8B **1.69×**（2,083 vs. 1,235 tok/s），精度损失仅 **−0.1 点**；Qwen3-235B **1.20×**（1,546 vs. 1,283 tok/s）。
2. **精度保持**：在 2,048 令牌 KV 预算下，精度保持在完整注意力的 **0.7 点以内**；LongBench v2 上比 Quest/FreeKV 更接近 full attention 锚点。
3. **PD 分离**：吞吐量约为密集 vLLM 的 **2.1–2.3×**；RPF 将每请求 KV 传送量减少 **6.5–9.7×**（在 32K 加 fetch cap 后总量仍降至 1/2.2），解码节点 DRAM 占用减少 **2.2–2.6×**。
4. **关键洞察——传输带宽而非注意力计算是解码瓶颈**：fetch cap 从 0.01 松至全额取回时，每步传输从 0.30 GB 增至 5.05 GB，吞吐量从 2,178 降至 824 tok/s（2.6× 下滑），而精度仅从 74.9 增至峰值 77.4——超出 PCIe 饱和点后，搬运更多字节只会拖慢解码步而不换取精度。最佳操作点为 **0.05 fetch ratio**。
5. **可扩展性**：吞吐量不受 HBM KV 容量封顶，可持续扩展至较大并发；在 16K 上下文下支持 90–95 并发请求（密集仅 22）。
6. **RPF 优势随前缀缓存命中率增大而增强**：90% 命中率下 TTFT 减半（2.0×@24K、2.2×@32K，100Gbps 链路），因为缓存命中免除了 prefill 但全量 KV 仍需传输——RPF 砍掉的是主导 TTFT 的 KV 搬移。

## 7. 优点

- **训练无关的前瞻信号**：巧妙复用投机解码草稿令牌，不做额外 predictor 训练、不做二次前向、无需修改模型架构，即获得高精度（>98%）的未来注意力预测，且与 SD 天然兼容。
- **彻底异步，解耦关键路径**：每层独立的三级流水线 + layer-local 同步，PCIe/网络传输完全隐藏于前台前向，实现真正的非阻塞预取。
- **生产级系统整合**：基于 vLLM 实现，支持多 GPU TP 扩展、密集/稀疏请求同批混合、请求中途切换稀疏模式，工程落地潜力强。
- **封顶驱逐策略**：显式建模解码时窗内的字节预算（`B_link × T_decode`），将传输入口限制转化为可调的精度/吞吐折中旋钮，而非被动竞速。
- **head-wise 映射层设计精巧**：在不破坏 PagedAttention 页表的前提下实现多头异构稀疏，多 GPU 下免去跨卡同步。
- **PD 分离中的远程部分获取**：将稀疏思想贯彻到网络传输与主机内存层，从根本上避免解码节点 DRAM 成为新瓶颈。
- **评估面向真实工作负载**：使用 agentic 长上下文、32K+ 真实编码/推理轨迹，避免短上下文单轮聊天场景的乐观偏差。

## 8. 不足与局限

- **草稿令牌未用于加速生成**：目前仅将草稿令牌作为预取信号并**强制拒绝**，未真正开启投机解码的令牌加速；这使得 EAGLE-3 草稿头的开销没有得到正面收益来抵消。作者在文中也承认这一限制，并列为未来工作。
- **额外系统开销与超参**：引入了 fetch cap、top-K 预算、sparsification threshold 等新超参数，需要针对不同模型/工作负载调整；压缩摘要、head-wise 映射、后台 worker 均占用部分 GPU 资源。
- **硬件依赖**：评估仅在 H100 + PCIe Gen5 平台上进行，未验证与其他互连（CXL、NVLink-C2C）或消费级硬件的交互；远程内存暂未实测（仅以预填充节点 DRAM 充当），SSD 分级存储只是展望。
- **基线覆盖不完整**：与 ShadowKV/InfiniGen/FreeKV 多 GPU 对比缺失（对方不支持）；前缀缓存场景仅为分析模型，缺少真实前缀命中端的实测；dense vLLM 与 OasisKV 的 CUDA graphs 使用方式不同（full vs. piecewise），可能引入对比偏差。
- **精度评估范围有限**：主要集中在数学推理（AIME/GPQA），对通用知识、代码生成、多轮对话等负载覆盖不足；各稀疏方法均基于各自框架 anchor 对比，纵向可比性受框架差异（HF Transformers vs. vLLM）影响。
- **MoE 模型收益较弱**：Qwen3-235B 上 KV 占显存比重较小，sparsity 节省相对有限，低批时 TPOT 反而高于 dense（直到批 16/32 才反超）；收益在不同模型族间存在明显差异。
- **请求寿命假设**：预填充节点需保留每请求完整 KV 直到完成，虽然换取了低解码节点内存，但转移了存储压力；未来需扩展至外部远程 KV 存储/SSD 才能规模化。
