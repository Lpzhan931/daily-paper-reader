## 摘要
大型语言模型（LLM）在自然语言理解和生成方面取得了显著成功，但其部署受到高计算需求的制约。直接在边缘部署较小的LLM可以规避这一问题，但会降低准确性。在云端部署较小的大模型虽然保持了性能，但代价是昂贵的逐词元计算。我们提出了一种分布式推理框架\our{}，它在边缘和云之间集成了投机解码（SD）。部署在边缘的紧凑草稿模型快速生成候选词元，云上的大型验证模型并行验证这些词元。被接受的词元予以保留，仅当被拒绝时才触发验证器修正，从而大幅减少云端查询次数。我们的即插即用设计将大部分计算转移到边缘，显著降低了推理时间和云成本，并在无需任何重新训练的情况下保持大模型的准确性。我们的方法展示了一条在真实环境中实现可扩展、成本高效且准确部署LLM的实用路径。在多个自然语言处理任务上使用SpecBench和CNN/Dailymail数据集的实验结果表明，与完整模型相比，\our{}将云模型调用减少了76%，且准确率零损失。

## Abstract
Large Language Models (LLMs) have achieved remarkable success in natural language understanding and generation, but their deployment is constrained by high computational demands. Deploying smaller LLMs directly on the edge can circumvent this, but with degraded accuracy. Deploying smaller cloud-based big LLMs preserves performance, but at the cost of expensive per-token computation. We present a distributed inference framework, \our{}, that integrates speculative decoding (SD) across edge and cloud. A compact draft model deployed on the edge generates candidate tokens rapidly, and a large verifier model on the cloud validates these tokens in parallel. Accepted tokens are retained, while only rejections trigger verifier correction, substantially reducing the number of cloud queries. Our plug-and-play design shifts the bulk of computation to the edge, significantly lowers inference time and cloud cost, and preserves the accuracy of the big model without any retraining requirement. Our approach demonstrates a practical path toward scalable, cost-efficient, and accurate deployment of LLMs in real-world environments. Experimental results across multiple Natural Language Processing tasks using SpecBench and CNN/Dailymail datasets demonstrate that \our{} reduces the cloud model calls by $76\%$ with zero loss in accuracy as compared to the full model.

## 1. 核心问题与整体含义（研究动机与背景）

大型语言模型（LLM）在自然语言处理任务中取得了突破性进展，但其部署面临一个根本性矛盾：

- **边缘部署困境**：直接在移动/边缘设备上部署小模型（如 1B 级别）虽然可行，但推理精度显著下降，无法捕捉复杂语言模式。即便采用模型剪枝、量化、知识蒸馏等压缩手段，也以牺牲准确性为代价。
- **云部署成本困境**：在云端托管完整大模型可以保持顶级性能，但 LLM 的自回归生成特性（每生成一个 token 都需要一次完整前向传播）导致推理时间随序列长度线性增长，云资源按使用时长计费，成本急剧上升。
- **核心研究问题**：**如何在不牺牲大模型精度的前提下，尽可能降低云端推理成本和延迟？** 更具体地说，如何在边缘与云端之间合理切分计算，让边缘设备承担更多生成计算，同时保持输出与云端大模型完全一致。

SPADE 正是为解决这一“精度—成本”权衡而提出的分布式推理框架。其整体含义在于：通过投机解码（Speculative Decoding）将边缘小模型与云端大模型有机协作，实现了“边缘承担生成主体、云端仅做并行校验”的推理模式，为 LLM 在资源受限的真实环境中规模化、低成本、高精度部署提供了一条实用路径。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

SPADE 采用**双模型协作的投机解码**架构：

- **边缘端草稿模型 Mq**（轻量 LLM）：在边缘设备上以自回归方式快速生成 D 个候选 token 块。
- **云端验证模型 Mp**（全规模 LLM）：在单次前向传播中并行验证草稿 token 块的正确性，仅在被拒绝处进行纠正。

核心洞察：**将大部分生成计算下沉到边缘，云端从“逐 token 生成”转变为“批量并行验证”，大幅压缩昂贵云调用的次数。**

### 2.2 验证准则（核心公式）

设 p(x) 为云端验证模型的目标分布，q(x) 为边缘草稿模型的草稿分布。候选 token x ~ q(x) 被接受的判定为：利用修正分布对拒绝 token 进行重采样，即从 p′(x) = norm(max(0, p(x) − q(x))) 中采样替代 token。这一机制从数学上保证了（引用文献 [12]）生成的最终序列与仅由云端大模型单独解码的结果**统计等价、零精度损失**。

### 2.3 算法流程（Algorithm 1 的文字化描述）

1. **初始化**：给定用户 prompt y₁:m，生成序列为空。
2. **边缘草稿阶段**：草稿模型 Mq 自回归生成 d 个候选 token（y_{m+1}, ..., y_{m+d}），条件于当前上下文。
3. **云端验证阶段**：将 d 个草稿 token 发送至云端；云端验证模型 Mp 在**单次前向传播**中并行计算所有候选位置的 token 分布（y*_{m+1}, ..., y*_{m+d+1}）。
4. **验收与纠正**：
   - 逐 token 按接受准则 α(x) = min(1, p(x)/q(x)) 并行判定通过率；
   - 接受最长连续前缀段直至第一个被拒绝的 token；
   - 从调整分布 p′(x) 采样，替换被拒绝位置的 token；
   - 丢弃该位置之后的剩余草稿 token。
5. **上下文更新**：将已接受 token 与纠正 token 追加至输出序列，更新上下文前缀。
6. **循环**：边缘模型从新上下文继续生成下一块草稿 token，直至生成 `<eos>`（结束符）。

### 2.4 关键设计要素

- **每次迭代至少追加一个 token**（要么是首个被验证的 token，要么是纠正后的 token），保证生成过程必然推进。
- **草稿 token 长度 d 是核心超参数**，用于权衡计算与通信开销：d 过小导致云端验证过于频繁、同步开销大；d 过大则拒绝率上升、边缘计算浪费。d 通过在小验证集（约 10 个样本）上监控接受率进行经验选择。
- **即插即用**：完全无需重训练或微调，任何一对边缘小模型 + 云端大模型均可直接套用。

## 7. 优点与亮点

1. **零精度损失的理论保证**：基于投机解码的既有理论（Leviathan et al. [12]），SPADE 的输出分布与云端大模型单独生成在统计上完全等价，具备严格的数学背书。
2. **真正的即插即用**：无需任何重训练、微调或额外蒸馏，对现有模型生态友好，部署门槛极低。
3. **通用性优于启发式方法**：区别于依赖数据集特定启发式的路由方法（如 DIMEE），SPADE 不依赖特定任务假设，可在多种 NLP 任务上直接泛化。
4. **架构简洁而高效**：将“草稿生成”这一重活下沉至免费/廉价的边缘算力，云端仅执行轻量并行验证，在算法设计与系统设计间取得了优雅平衡。
5. **每轮至少推进一个 token 的设计**：保证了生成不会死循环，且重构开销最小。
6. **实证效率优势突出**：76% 的云调用削减是令人信服的量化收益，且为跨数据集重复验证。
