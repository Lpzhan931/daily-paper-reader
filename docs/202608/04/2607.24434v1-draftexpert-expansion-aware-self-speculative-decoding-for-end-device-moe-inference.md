## 摘要
大型混合专家（MoE）语言模型因其每个token仅激活少量专家而非常适合端侧部署，但其路由专家权重常常超出加速器内存。我们专注于延迟敏感的单用户场景，其中路由专家按需从CPU内存加载到GPU，或从Flash加载到移动NPU。在此场景下，自推测解码面临新瓶颈：增加草稿专家集可提升准确性，但会导致额外的专家加载；而占用资源少、成本低的草稿模型接受率较低；此外，验证多token块会激活目标专家的并集，不再接近单步目标推理。我们提出DraftExpert，一种面向专家卸载MoE推理的扩展感知自推测解码框架。DraftExpert通过从冻结的目标MoE中自蒸馏残差、logit/token以及路由一致性信号，为每层训练一个轻量级常驻加速器的草稿专家。在推理时，它使用固定占用的共享+top-1+草稿专家草稿器，并结合置信度扩展截断和目标专家预取，同时最终token仍由目标模型精确验证。在DeepSeek-V2-Lite和Moonlight-16B-A3B上，跨CPU-GPU和Flash-NPU卸载场景，DraftExpert平均将解码吞吐量提升1.45倍，将草稿接受率提升至84%~87%，并实现86%~88%的预取命中率。

## Abstract
Large Mixture-of-Experts (MoE) language models are attractive for end-device deployment because only a small subset of experts is active per token, but their routed expert weights often exceed accelerator memory. We target latency-critical single-user settings where routed experts are staged on demand from CPU memory to a GPU or from Flash to a mobile NPU. In this setting, self-speculative decoding faces a new bottleneck: increasing the draft expert set improves accuracy but triggers extra expert loading, while cheap small-footprint drafts have low acceptance; moreover, verifying a multi-token block activates the union of target experts and is no longer close to one target step. We propose DraftExpert, an expansion-aware self-speculative decoding framework for expert-offloaded MoE inference. DraftExpert trains one lightweight accelerator-resident draft expert per layer by self-distilling residual, logit/token, and router-agreement signals from the frozen target MoE. At inference time, it uses a fixed-footprint shared+top-1+draft-expert drafter together with confidence--expansion truncation and target-expert prefetching, while final tokens are still exactly verified by the target model. On DeepSeek-V2-Lite and Moonlight-16B-A3B across CPU-GPU and Flash-NPU offload, DraftExpert improves decode throughput by 1.45x on average, raises draft acceptance to 84~87%, and achieves 86~88% prefetch hit rates.

### 1. 核心问题与研究动机

**背景与问题界定：**
- 大型混合专家（MoE）语言模型在端侧设备（如消费级 GPU、移动 NPU）部署时具有天然吸引力：每个 token 仅激活一小部分路由专家，计算量受限。
- 然而，路由专家的参数量极大（如 DeepSeek-V2-Lite 中路由专家占模型总参数 91.6%，约 14.4B 参数），往往超出加速器内存容量。
- 实际可行方案是将非路由权重常驻加速器，将路由专家卸载到慢速存储（CPU 内存或 Flash），按需加载。实验表明，专家加载时间占解码总时间的 49%–87%，成为首要性能瓶颈。

**核心矛盾——专家集扩展（Expert-Set Expansion）打破传统推测解码三大条件：**

| 经典条件 | 在专家卸载 MoE 下被破坏的原因 |
|---|---|
| ① 草稿必须廉价 | 增大 top-r 虽提升草稿精度，但需加载更多卸载专家，草稿器变慢（如 top-1→top-3 速度从 4.7× 降至 2.0×） |
| ② 并行验证接近单步代价 | K 个 token 的验证块会激活多个不同专家的并集，验证成本随块长增长（如 K=16 时成本约为一 token 解码的 5.8×） |
| ③ 接受率要高 | 小 footprint 的 top-1/top-3 草稿接受率仅 22%–42%，大量草稿被拒绝，专家移动成本浪费严重 |

**关键洞察：** 端侧 MoE 推测解码的性能单位应从"每目标前向产出的 token 数"转变为"每专家集扩展产出的被接受 token 数"（accepted tokens per expert-set expansion）。

### 2. 方法论：DraftExpert

**核心思想：** 通过固定足迹（fixed-footprint）的草稿路径 + 自蒸馏训练的轻量草稿专家 + 扩展感知的验证控制，恢复经典推测解码三条件。

**(1) 固定足迹草稿器**

- 每个 MoE 层增加一个轻量级、加速器常驻的草稿专家 Eᵈ(l)，目标 MoE 保持冻结。
- 草稿输出为：共享专家路径 + top-1 路由专家 + 草稿专家，即保持路由专家使用量接近 top-1，不做 top-r 扩展。
- 草稿公式：
  - y*ₗ = Sₗ(hₗ) + Σₑ∈TopKₗ gₗ,ₑ Eₗ,ₑ(hₗ)（目标输出）
  - yᵈₗ = Sₗ(hₗ) + gₗ,ₑ₁ Eₗ,ₑ₁(hₗ) + γₗ Eᵈₗ(hₗ)（草稿输出）

**(2) 自蒸馏训练目标**

设缺失残差 m*ₗ,ₜ = y*ₗ,ₜ − Sₗ(h*ₗ,ₜ) − gₗ,ₑ₁ Eₗ,ₑ₁(h*ₗ,ₜ)，训练损失包含四个部分：

- **残差损失** Lres：草稿专家近似缺失的 top-2~top-k 路由专家残差
- **Logit 损失** Llogit：KL 散度蒸馏目标模型输出的 logits
- **Token 损失** Ltok：交叉熵对齐目标 token
- **路由器一致性损失** Lrouter：KL 散度使草稿隐藏状态的路由分布逼近目标路由分布，用于预测验证阶段将使用的专家

总损失：L = Llogit + αLtok + βLres + ηLrouter

训练过程为离线自蒸馏，只依赖未标注文本和冻结的目标 MoE，无监督信号。

**(3) 代价感知动态截断（Confidence–Expansion Truncation）**

- 对第 i 个草稿 token，计算置信度 qᵢ 和预测新增验证专家数 Δᵢ。
- 当 qᵢ < τ 且 Δᵢ > Bᵢ（专家预算）时，停止追加草稿。被截断的 token 不会提交给验证器，因此不影响输出的精确性。

**(4) 草稿路由专家预取（Draft-Router Expert Prefetch）**

- 草稿过程中，一旦生成新的预测验证专家集合，立即发起异步预取（从 CPU/Flash 加载到加速器缓存），与剩余草稿计算重叠。
- 预取不改变模型语义：命则省时，错过则退化为按需加载。
- 路由一致性损失直接提升预取命中率。

**(5) 精确验证**

- 所有最终保留的草稿 token 均交由冻结的完整目标 MoE 验证，输出分布与原始目标模型一致。

### 6. 主要结论与发现

1. **端到端加速：** DraftExpert 平均提升解码吞吐 1.45×；其中 Flash→NPU 场景增益更大（DS 1.52×，ML 1.61×），CPU→GPU 场景增益较小（DS 1.36×，ML 1.29×）。
2. **草稿成本与接受的平衡：** DraftExpert 在保留接近 top-1 的专家足迹（88 vs top-3 的 244 个唯一专家）的同时，将接受率从 22% 提升至 84–85%，显著优于 top-r 草稿器。
3. **验证控制有效：** 置信度-扩展截断将验证成本从固定 K 的 2.35×–3.30× 降至 1.48×–1.76×，加入预取后进一步降至 1.25×–1.40×。
4. **训练目标分工明确：** 残差/logit/token 损失主要提升草稿接受率（45%→87%），路由一致性损失主要提升预取命中率（61%→88%）。
5. **精确验证保留：** 所有输出 token 均由目标 MoE 验证，无分布偏移。

### 7. 方法的优点

- **问题建模清晰：** 将专家卸载 MoE 推测解码重新定义为"专家集扩展"问题，一针见血地指出传统推测解码三条件的失效机制。
- **训练目标与系统目标对齐：** 四个蒸馏损失分别对应系统不同需求（残差→精度，logit/token→接受率，路由→预取/截断预测），设计思路优雅。
- **保持精确输出：** 不牺牲生成质量，所有发射 token 经目标模型验证。
- **轻量级、端侧友好：** 草稿专家为每层一个小的加速器常驻模块，固定足迹不随草稿长度增长。
- **硬件适配全面：** 同时验证了消费级 GPU（CPU→GPU）与移动 NPU（Flash→NPU）两种主流端侧场景，结果具有实际参考价值。
- **实验分层隔离：** 草稿侧、验证侧、训练目标分别独立实验，结论归因清晰。
