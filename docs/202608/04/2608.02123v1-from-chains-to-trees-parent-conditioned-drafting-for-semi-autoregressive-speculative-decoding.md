## 摘要
投机解码仅在草稿续文通过目标模型验证时加速大语言模型推理。诸如DSpark之类的半自回归草稿生成器通过一次骨干网络前向传播预测整个令牌块，并使用轻量级马尔可夫头进行细化。然而，DSpark将该块作为单链解码，因此早期不匹配会使剩余后缀无效，并限制大草稿块的益处。我们表明，DSpark已学习的条件结构可以在无需重新训练或额外骨干网络传播的情况下支持多个父一致的续文。我们引入了父条件草稿树（PCTree），它使用预训练的马尔可夫头为每个具体父节点分别对替代子节点进行评分，并将固定的验证预算分配给最可能的路径。这将在保持单遍并行骨干网络的同时，将DSpark的线性草稿转换为树。在Qwen3-{4B,8B,14B}和九个基准测试中，当B=7时，与匹配的DSpark相比，相对于自回归（AR）解码的测量加速增益范围为3.1%至29.5%。在Qwen3-4B GSM8K上，当B=16时，PCTree将平均接受长度从9.41提高到11.16，并将三次运行的平均AR加速从6.14倍提高到6.60倍。这些结果表明，父条件分支可以将半自回归草稿生成器中已经存在的条件能力通过仅推理的更改转化为端到端的推理增益。

## Abstract
Speculative decoding accelerates LLM inference only when drafted continuations survive target-model verification. Semi-autoregressive drafters such as DSpark predict an entire token block with one backbone forward and refine it with a lightweight Markov head. However, DSpark decodes this block as a single chain, so an early mismatch invalidates the remaining suffix and limits the benefit of large draft blocks.   We show that the conditional structure already learned by DSpark can support multiple parent-consistent continuations without retraining or additional backbone passes. We introduce Parent-Conditioned Drafting Tree (PCTree), which uses the pretrained Markov head to score alternative children separately for each concrete parent and allocates a fixed verification budget to the most probable paths. This converts DSpark's linear draft into a tree while preserving its one-pass parallel backbone.   Across Qwen3-{4B,8B,14B} and nine benchmarks, at $B{=}7$, measured speedup gains over autoregressive (AR) decoding, relative to matched DSpark, range from $3.1\%$ to $29.5\%$. On Qwen3-4B GSM8K at $B{=}16$, PCTree increases mean acceptance length from $9.41$ to $11.16$ and three-run mean AR speedup from $6.14{\times}$ to $6.60{\times}$. These show that parent-conditioned branching can turn conditional capacity already present in a semi-autoregressive drafter into end-to-end inference gains through an inference-only change.

## 1. 核心问题与研究动机

**背景问题**
- 自回归解码是 LLM 推理的主要延迟瓶颈，因为每一步生成的并行度极低。
- 投机解码（Speculative Decoding）通过轻量级草稿模型（drafter）草拟未来若干 token，再由目标模型一次前向验证，从而加速推理；但其收益取决于草稿中有多大部分能通过目标模型验证。

**现有方法的缺陷**
- **链式草稿的脆弱性**：早期 token 一旦不匹配，整个后续后缀即被废弃，导致"拒绝级联"（rejection cascade），限制了大草稿块的收益。
- **自回归草稿器的限制**：EAGLE 等自回归草稿器生成树需要多次顺序前向传播，树增长成本高。
- **并行草稿器的不足**：DFlash 等并行草稿器虽延迟低，但弱化了 token 间依赖，接受率快速衰减。
- **DSpark 的瓶颈**：DSpark 结合"一次并行骨干 + 轻量级马尔可夫头"（半自回归），但其解码器只构造**单条链**，未利用已具备的条件建模能力。

**核心洞察**
- DSpark 的马尔可夫头实际上已经学会了**父节点条件分布**，可以为不同父节点生成不同的子节点分布——该条件结构天然支持树形草稿，无需重新训练或额外骨干前向。

## 2. 方法论：PCTree

### 核心思想
将 DSpark 的线性链式草稿转换为**有预算约束的草稿树**，在保持"一次并行骨干 + B 次顺序马尔可夫阶段"的前提下，利用预训练马尔可夫头对每个具体父节点分别评分候选子节点，实现父条件化的树形展开。**纯推理时改动，不需要任何训练。**

### 关键技术细节

**（1）并行骨干阶段**
- 一次前向处理锚点 token `xt` 和 B−1 个掩码占位符，产生共享基础 logits `L = (L0, ..., LB−1)`。
- 各位置并行计算，`Ld` 不依赖块内已选 token。

**（2）马尔可夫树展开（Markov Tree Expansion）**
- 对每个前沿（frontier）父节点 `p ∈ F_{d−1}`，共享相同的 `Ld`，但附加各自独立的马尔可夫偏置：
  - `zd(p) = Ld + Markov(p)`
  - `log πd(·|p) = log softmax(zd(p))`
- 每个父节点取局部 top-k 子节点，联合路径得分：
  - `s(c) = Σ_{(u→v) ∈ path(c)} log π(v|u)`
- **逐层剪枝**：每层仅保留联合得分最高的 k 个候选作为下一层前沿，避免指数级增长。
- 候选节点总数上界约为 `k + (B−1)·k²`，优于指数增长。

**（3）预算化选择与树验证**
- 完成 B 层展开后，对所有候选节点按联合得分降序、深度升序、稳定 ID 排序，保留全局 top-N（含根节点）。由于得分沿路径单调递减，所选节点天然构成**前缀封闭的树**。
- 生成扁平的 token 张量、检索索引（root-to-leaf 路径）和**仅祖先可注意的树注意力掩码**，一次目标模型前向完成贪心树验证。
- `k=1` 时退化为 DSpark 原始链。

**（4）复杂度分析**
- DSpark 成本：`C_bb + Σ C_mk(1)`
- PCTree 成本：`C_bb + Σ C_mk(bd)`，其中 `bd ≤ k`
- 保持了 B 个顺序阶段，仅增大了马尔可夫调用的 batch 大小（上限为 k）。

### 算法流程（Algorithm 1 文字版）
1. 并行骨干一次前向获取 logits L；
2. 初始化前沿 = {xt}（得分 0），池 = {xt}；
3. 对 d = 0 到 B−1：
   - 批量调用马尔可夫头计算每个前沿父节点的 `zd(p)`；
   - 展开局部 top-k 子节点，更新联合得分并加入候选池；
   - 按联合得分保留当前层 top-k 作为下一层前沿；
4. 全局 top-N 节点选择；
5. 输出草稿 token、检索索引和树注意力掩码。

## 6. 主要结论与发现

- **接受长度全面提升**：PCTree 在全部 9 个 benchmark、3 个模型规模、两种块大小下均提升了平均接受长度 τ。
- **端到端加速增益**：B=7 时，相对匹配的 DSpark，AR 加速提升 3.1%–29.5%；代表性子任务上 B=16 的三次运行均值加速提升 7.5%–15.1%。
- **典型结果**：Qwen3-4B GSM8K，B=16 时 τ 从 9.41 增至 11.16，AR 加速从 6.14× 提升至 6.60×。
- **机制归因**：父条件重评分（PCTree）相对共享分布树（Shared-Markov）将 τ 从 10.225 提升至 11.156（+9.1%），验证节点利用率从 29.88% 提升至 32.90%，每样本轮数减少 8.4%——证明收益来自**父特定条件化**而非单纯分支。
- **分支因子**：k 从 1 到 2 获得大部分收益，k=4 基本饱和，k=8 无进一步提升。
- **预算权衡**：验证预算 N 增大可提升接受长度但边际递减，AR 加速呈非单调（B=7 峰值在 N=32，B=16 在 N=64），额外树构造和验证成本最终超过接受增益。
- **成本可抵销**：树展开增加了马尔可夫阶段延迟（如 B=16 时从 1.09ms 增至 5.24ms/轮），但每样本轮数从 26.8 降至 22.6，净效果仍为正。

## 7. 优点与亮点

- **方法优雅、零训练成本**：纯推理时策略改动即可挖掘 DSpark 已具备的条件建模能力，无需重新训练或额外骨干前向。
- **理论机制清晰**：明确指出"父无关拼接"（parent-independent stitching）的失败模式，并用受控实验验证父条件化的因果贡献。
- **树结构设计合理**：共享 logits + 批量马尔可夫调用保持顺序阶段数不变，仅扩大 batch 上限为 k；逐层 top-k 剪枝 + 全局 top-N 选择保证前缀封闭性。
- **实验设计严谨**：匹配对照组（DSpark）、机制隔离组（Shared-Markov）、外部参考组（DFlash+DDTree）分层分明；重复运行报告不确定性。
- **消融全面**：覆盖分支因子、验证预算、成本分解三个维度，揭示了收益来源和权衡边界。
- **通用性启示**：提出"并行块 + 廉价顺序精化"的草稿器架构可经推理策略改动支持树验证，具有方法论普适价值。

## 8. 不足与局限

- **草稿质量上界**：树质量受预训练草稿分布约束，训练无关的展开策略无法修复系统性地弱的马尔可夫头。
- **剪枝启发式的次优性**：逐层 top-k 剪枝是启发式方法，在节点预算 N 下可能丢弃全局最优路径。
- **大预算开销风险**：过大的 k 或 N 会使树构造和验证注意力在小型目标模型或内存受限设备上不可忽视。
- **硬件依赖性强**：加速增益依赖硬件、精度、注意力内核和预算设置，论文仅在 H20 + BF16 上验证。
- **实验覆盖不足**：
  - 多数主表配置仅单次运行，统计置信度有限；
  - 未在更大规模模型（如 32B+）或更多草稿架构上验证；
  - EAGLE-3/DFlash 对比非严格同环境；
  - B=16 草稿训练成本未披露。
- **测量细节**：未使用 prompt 级 warmup，第一个 prompt 计入测量循环，可能引入少量噪声。

## 9. 总结

PCTree 通过将 DSpark 的链式半自回归草稿转化为父条件化的有预算草稿树，在不重新训练、不增加骨干前向的前提下，实现了接受长度和端到端推理速度的显著提升。其核心价值在于揭示了"半自回归草稿器已具备的条件能力可通过推理策略改动转化为端到端收益"这一通用洞见，为投机解码的树形化提供了一条低成本、高性价比的技术路径。
