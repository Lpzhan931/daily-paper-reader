## 摘要
推测解码在不改变目标分布的情况下加速大型语言模型推理，但没有单一的草稿结构能在真实工作负载中表现最佳。自回归多词预测（MTP）是一种轻量、稳定的提案机制，而块并行扩散则将草稿延迟分摊到更长的候选序列上；选择哪种方式很大程度上取决于输出分布。我们提出AngelSpec，一个统一的MTP和块并行推测解码训练框架，在三个层面解决这种异质性。在训练层面，我们不是将单一通用草稿器拟合到统一数据混合上，而是共同特化结构和数据：MTP草稿器在多样化的对话数据上训练，用于高熵开放域聊天；块扩散草稿器在代码和数学数据上训练，用于更长的可预测延续。在架构层面，我们提出DFly，一个块扩散框架，结合混合目标条件主干和前驱条件自回归头，改善了目标特征利用和块内依赖建模，同时保持生成并行。在推理层面，接受长度和验证成本都随领域、请求、在线负载和硬件而变化，因此DFly将验证视为共享的批量级资源：它将计算重新分配给跨请求的高置信度前缀，并将预期效用与性能剖析成本模型相结合，以在线调整验证深度。在Hy3系列中，DFly在Hy3-A21B上将平均接受长度提高了约30%，并在所有测试的并发度（4至64）下获得最高平均吞吐量，相比自回归解码有1.98-2.40倍加速，比DFlash吞吐量高10.5-11.8%。我们发布AngelSpec以支持训练和扩展这些方法。

## Abstract
Speculative decoding accelerates large language model inference without changing the target distribution, but no single drafting structure performs best across real-world workloads. Autoregressive multi-token prediction (MTP) is a lightweight, stable proposal mechanism, whereas block-parallel diffusion amortizes drafting latency over much longer candidate sequences; the better choice depends strongly on the output distribution. We present AngelSpec, a unified training framework for MTP and block-parallel speculative decoding that addresses this heterogeneity at three levels. At the training level, rather than fitting one universal drafter to a uniform data mixture, we co-specialize structure and data: the MTP drafter is trained on diverse conversational data for high-entropy open-ended chat, and the block-diffusion drafter on code and mathematics data for longer predictable continuations. At the architecture level, we propose DFly, a block-diffusion framework combining a hybrid target-conditioning backbone with a predecessor-conditioned autoregressive head, improving target-feature utilization and intra-block dependency modeling while keeping generation parallel. At the inference level, both acceptance length and verification cost vary with domain, request, online load, and hardware, so DFly treats verification as a shared batch-level resource: it reallocates compute toward high-confidence prefixes across requests and combines expected utility with a profiled cost model to adapt verification depth online. Across the Hy3 series, DFly raises the average accepted length on Hy3-A21B by roughly 30% and attains the highest average throughput at every tested concurrency from 4 to 64, a 1.98-2.40x speedup over autoregressive decoding and 10.5-11.8% higher throughput than DFlash. We release AngelSpec to support training and extending these methods.

  - 投机解码（Speculative Decoding）通过轻量草稿器提出多个候选 token，再由目标模型并行验证，可在不改变目标分布的前提下加速推理。
  - 自回归多词预测（MTP）草稿器：轻量、稳定，适合高熵对话场景；块并行扩散草稿器：能在单次前向中生成很长的候选序列，适合代码/数学等低熵、高度可预测的场景，但不同方法的优劣取决于实际输出分布，不存在放之四海而皆准的草稿结构。

## 2. 论文提出的方法论：核心思想、关键技术细节与算法流程

论文的方法论可以从**训练层、架构层、推理层**三个维度概括：

### 2.1 训练层：数据与模型结构的联合专门化

- **核心思想**：不为所有工作负载训练一个通用草稿器，而是将模型结构与训练数据共同特化：
  - **MTP 草稿器**：训练于丰富多样的对话导向数据，用于高熵、开放性聊天场景。
  - **DFly 块扩散草稿器**：使用代码和数学重点数据强化，用于更长的可预测延续。
- **MTP 关键改进——Training-Time Test (TTT)**：
  - 解决训练与推理之间的**暴露偏差（exposure bias）**：原始 MTP 模块训练时每次只进行一次教师强制的预测，而推理时循环复用同一模块，错误会随深度累积。
  - TTT 将共享参数的 MTP 模块在训练过程中**自回归展开 D 步**，深度 k+1 的输入是深度 k 的预测结果（argmax），而非真实 token，从而模拟推理时的状态分布。
  - 通过共享-参数多深度机制，所有深度复用同一物理 MTP 模块，但每个深度受不同的移位目标监督。
- **损失函数设计（接受对齐蒸馏）**：
  - 传统 KL 散度只是接受率的代理指标，论文引入 **TV 距离（Total Variation）**，它直接与拒绝采样中的接受概率相关：α(p,q) = 1 − TV(p,q)。
  - 采用 **LK Loss**（KL 与 TV 的自适应混合，λ = exp(−η·sg[α])）作为冷启动目标；随后切换至**端到端 TV Loss**（基于期望接受长度 e2e TV Loss），直接在多深度上优化期望接受长度，浅层位置权重更大（因为早期拒绝会使后续草稿全部失效）。
  - 消融实验表明：纯 TV Loss 从初始点直接优化不稳定，LK 冷启动后切换到 e2e TV Loss 效果最佳。
- **训练数据策略**：多样性任务覆盖 + 长上下文/代码智能体轨迹 + 由冻结目标模型生成响应（target-model rollout）以消除教师-数据不匹配。

### 2.2 架构层：DFly 块扩散框架

- 并行草稿器（如 DFlash）的一个关键缺陷是：所有位置并行预测，位置之间**没有显式的自回归依赖**，导致后缀接受率衰减。DFly 通过两个核心改进解决该问题：
- **① 混合目标条件主干（Hybrid Target-Conditioning Backbone）**：
  - 结合 DFlash 的**共享投影分支**（从多层目标隐藏状态学习全局非线性变换 cₜ）与 DFlare 的**逐层目标视图**（每个草稿层学习各自的 softmax 加权融合 fₜ⁽ⁱ⁾）。
  - 最终条件表示为 gₜ⁽ⁱ⁾ = RMSNorm(cₜ + fₜ⁽ⁱ⁾)，即"共享语义基础 + 深度差异化细化"，兼顾表征丰富性和层特异性。
  - 仅新增 D×T 个标量权重，开销极小。
- **② 前驱条件自回归头（Predecessor-Conditioned Autoregressive Head）**：
  - 在完全并行的骨干网络之后添加一个轻量顺序头，将边缘分布转化为前缀条件分布：
    q(X_{t+1:t+B}|x≤t) = Π qᵢ(x_{t+i}|x≤t, x_{t+1:t+i−1})
  - 对比两种实现：**Markov 头**（低秩 token 转移偏置）和**隐藏修正头**（将前驱 token 嵌入与位置专用隐藏状态拼接，经 SwiGLU 修正后产生 logits），后者效果更好。
- **块扩散损失设计**：使用 D-PACE 动态位置感知加权 LK 损失冷启动，再切换至端到端 TV 损失优化多深度接受行为。

### 2.3 推理层：D-cut 自适应验证预算分配

- **核心观察**：接受长度随领域、请求、解码步骤变化；验证额外 token 的成本随在线负载、部署硬件变化。固定验证深度在轻负载下浪费可预测草稿，在高并发下浪费有限批量容量。
- **D-cut 方法**：
  1. **估计每条请求的进度**：根据草稿器的 token 级置信度 cᵢ,ₜ，用前缀乘积 sᵢ,ₖ = Πᵼ₌₁..ₖ cᵢ,ₜ 估计前缀存活概率，从而得期望进度 Âᵢ(nᵢ) = Σₖ₌₀..nᵢ sᵢ,ₖ。
  2. **全局预算选择**：从离散比率集合 R={0.25, 0.50, 0.75, 1.00} 中选择使 U(B,ρ)/C(B,ρ) 最大化的预算比率 ρ*（U 为估计批量进度，C 为启动时 profile 的端到端投机步骤延迟）。
  3. **打包验证**：按置信度降序将所有请求的草稿 token 排序，选择 top-K 构成稠密验证批次（同时保持每个请求内部的连续性），提交给目标模型验证。
- **正确性保证**：D-cut 只改变草稿被验证的深度，不改变验证方式，保留 token 仍经过原目标模型验证，因此保持输出分布完全不变（确定性草稿+目标验证协议下）。

## 6. 主要结论与发现

1. **工作负载异构性是真实投机解码的首要考虑因素**：MTP 适合高熵对话（MT-Bench 上 MTP 仍优于 DFly），DFly 适合低熵代码/数学。
2. **TTT 显著改善 MTP 深层接受率**：在 Hy3 上，TTT+Rollout 使平均接受率从 52.8% 提升至 66.4%（T=0，+13.6pp），MAL 从 2.58 提升至 2.99，且主要改善集中在第二、第三草稿位置。
3. **DFly 的混合条件主干和隐藏修正头带来一致提升**：在 Hy3-A21B 上，DFly 平均接受长度达 4.79，比 MTP（3.00）高 59.7%，比 DFlash（3.69）高 29.8%。
4. **5 层草稿器 + 块大小 8 是最优权衡**：进一步加深到 7 层几乎没有额外收益。
5. **思考模式需要专门训练**：高思考（High-think）和免思考（No-think）模式应分别训练和部署草稿器，混合使用会显著降低接受率。
6. **D-cut 扩展了可用并发范围**：在生产流量回放中，DFly 在并发度 48+ 达到饱和，而 D-cut 在 c64 仍能提升 15.7% 吞吐量，同时接受长度仅损失约 1.5%–2.8%，实现了更优的延迟-吞吐量前沿。
7. **端到端吞吐量**：DFly 在所有测试并发度（4–64）下均达到最高平均吞吐量，相对 AR 解码加速 1.98–2.40 倍（c4–c32），相对 DFlash 高 10.5–11.8%（摘要声称；表 7 中 c8/c16/c32 分别为 10.9%/11.7%/11.7%）。

## 7. 优点

1. **三层协同的系统性视角**：从训练数据、模型架构到推理时验证预算进行端到端优化，而非仅关注单一环节。
2. **问题定位精准且可复现**：清晰地指出了 MTP 的暴露偏差问题（深层接受率远低于浅层）和并行草稿器的块内依赖缺失问题。
3. **训练-推理一致性高度对齐**：TTT 自回归展开直接模拟推理状态分布；TV 距离和 LK Loss 直接优化与投机采样接受率相关的代理指标，而非传统语言建模损失。

6. **消融实验系统完整**：对每个组件（骨干、AR 头、数据扩展、深度、块大小、思考模式）都有逐一剥离验证。

## 8. 不足与局限

1. **算力信息不透明**：未披露训练草稿器所需的具体 GPU 数量、训练时间、能耗等，使读者难以评估方法的实际成本和可复现性。
2. **外部泛化验证较弱**：除了 Qwen3-8B 上的草稿质量对比外，所有主要实验结果（尤其是端到端吞吐和部署评估）均在腾讯自研的 Hy3 模型系列上进行，且论文作者均为腾讯员工；对第三方模型和部署环境的适用性证据有限。
3. **领域划分的潜在偏置**：DFly 主要为代码/数学设计（表 4 中 MT-Bench 从 3.06 降至 3.02），MTP 为对话设计。这种专门化策略假定运行时可预知工作负载类型；在混合负载场景中，若路由不正确可能导致性能回退。论文没有给出如何在实际系统中进行负载分类/路由的策略。
4. **D-cut 的实现局限性**：
   - 当前实现仅支持分段 CUDA 图，选择器和打包逻辑在关键路径上引入开销（论文承认"不假设 D-cut 是免费的"）。
   - 预算比率仅从离散集合 {25%, 50%, 75%, 100%} 中选择，可能不是最优连续值。
   - 只针对块并行草稿路径评估，短视 MTP 路径的适用性未测试。
5. **接受长度与吞吐的关系验证不完整**：第 5 节的盈亏平衡分析是设备侧预测，论文未提供每个方法"实测已提交长度 vs. 盈亏平衡阈值"的完整逐并发度对照表来验证预测与实际 TPS 的一致性。
6. **温度与思考模式的覆盖有限**：端到端吞吐实验仅报告 T=1 的 no-thinking 模式，其他温度/思考模式的组合未给出系统吞吐对比。
