## 摘要
推测解码在不改变目标分布的情况下加速大语言模型推理，但没有任何单一的草稿结构能在真实工作负载中表现最佳。自回归多标记预测（MTP）是一种轻量、稳定的提案机制，而块并行扩散则将草拟延迟分摊到更长的候选序列上；哪种选择更优很大程度上取决于输出分布。我们提出AngelSpec，一个统一的MTP与块并行推测解码训练框架，在三个层面解决这种异构性。在训练层面，我们不是将单一通用草稿器拟合到统一数据混合上，而是共同特化结构与数据：MTP草稿器在高熵开放性对话数据上训练，块扩散草稿器则在代码与数学数据上训练，以处理更长的可预测延续。在架构层面，我们提出DFly，一个块扩散框架，将混合目标条件主干与前驱条件自回归头相结合，改善了目标特征利用和块内依赖建模，同时保持并行生成。在推理层面，接受长度与验证成本均随领域、请求、在线负载和硬件而变化，因此DFly将验证视为共享的批级资源：它跨请求将算力重新分配到高置信度前缀，并将预期效用与基于性能剖析的成本模型相结合，在线调整验证深度。在Hy3系列中，DFly在Hy3-A21B上将平均接受长度提升了约30%，并在所有测试并发数（4到64）下达到最高平均吞吐量，相比自回归解码实现1.98–2.40倍加速，且吞吐量比DFlash高10.5–11.8%。我们开源AngelSpec以支持训练和扩展这些方法。

## Abstract
Speculative decoding accelerates large language model inference without changing the target distribution, but no single drafting structure performs best across real-world workloads. Autoregressive multi-token prediction (MTP) is a lightweight, stable proposal mechanism, whereas block-parallel diffusion amortizes drafting latency over much longer candidate sequences; the better choice depends strongly on the output distribution. We present AngelSpec, a unified training framework for MTP and block-parallel speculative decoding that addresses this heterogeneity at three levels. At the training level, rather than fitting one universal drafter to a uniform data mixture, we co-specialize structure and data: the MTP drafter is trained on diverse conversational data for high-entropy open-ended chat, and the block-diffusion drafter on code and mathematics data for longer predictable continuations. At the architecture level, we propose DFly, a block-diffusion framework combining a hybrid target-conditioning backbone with a predecessor-conditioned autoregressive head, improving target-feature utilization and intra-block dependency modeling while keeping generation parallel. At the inference level, both acceptance length and verification cost vary with domain, request, online load, and hardware, so DFly treats verification as a shared batch-level resource: it reallocates compute toward high-confidence prefixes across requests and combines expected utility with a profiled cost model to adapt verification depth online. Across the Hy3 series, DFly raises the average accepted length on Hy3-A21B by roughly 30% and attains the highest average throughput at every tested concurrency from 4 to 64, a 1.98-2.40x speedup over autoregressive decoding and 10.5-11.8% higher throughput than DFlash. We release AngelSpec to support training and extending these methods.

## 2. 论文提出的方法论

### 2.1 总体设计思路
无需训练单一通用草稿器，而是**结构与数据协同特化**：
- **MTP 草稿器**：面向高熵自由对话，在多样对话数据上训练，擅长短距离提案。
- **DFly 块扩散草稿器**：面向代码和数学等强结构化任务，利用更长的可预测延续，实现长块并行生成。
- **D-cut 推理调度**：在推理时将目标模型验证视为共享批级资源，动态分配验证深度。

### 2.2 MTP 草稿器的改进（共享参数多深度训练）

#### 共享参数多深度 MTP 结构
- 保留 D 个逻辑预测深度，但所有深度**共享同一物理 MTP 模块**和参数。
- 输入融合：`u(k) = Wproj(h(RMSNorm(h(k-1))), RMSNorm(E(exk)))`，其中 `exk` 在训练时为移位真值 token，推理时为上一深度采样 token。
- 经过一层 Transformer 后接目标模型 LM Head 输出预测分布。

#### Training-Time Test（TTT）
- 解决标准教师强制训练与多步推理之间的**暴露偏差**：推理时深度 k≥1 的输入来自上一深度的自生成预测，而非真值 token。
- 训练时自回归展开同一 MTP 模块 D 步，每步输入为前一步 argmax 预测，并维护不断增长的草稿 KV 缓存。
- 每个深度由不同移位目标分布监督，后期深度学会从真实上游错误中恢复。

#### 接受对齐的损失函数设计
- 核心洞察：拒绝采样的接受概率 = `α(p,q) = Σ_v min(p(v), q(v)) = 1 - TV(p,q)`。
- **基线损失**：前向 KL 散度（`L_KL`）。
- **LK Loss（冷启动）**：自适应混合 KL 与 TV（`L_LK = λD_KL + (1-λ)TV`，`λ = exp(-η·sg[α])`），或负对数重叠损失 `L_αLK = -log(α + ε)`。
- **端到端 TV 损失**：`L_e2e = 1 - (1/|I|D)Σ_i Σ_m Π_{k=0}^m α_{i,k}`，直接优化期望接受长度，早期位置权重更大（早期拒绝使后续 token 全部失效）。
- 最终配置：**LK Loss 冷启动 + e2e TV Loss**（冷启动后切换）。

#### 训练数据策略
- **多样化任务覆盖**：对话、知识问答、数学、代码、指令跟随、Agent 交互。
- **长上下文与代码 Agent 轨迹**：代码仓库上下文、迭代分析、工具交互、多步反馈。
- **目标模型 rollout**：用冻结目标模型生成响应作为训练数据，降低教师-数据分布不匹配。

### 2.3 DFly：块并行扩散草稿框架

#### 混合目标条件主干（Hybrid Target-Conditioning Backbone）
- 结合 DFlash 的**共享非线性投影**（FC 层融合多层目标隐藏状态）与 DFlare 的**逐层加权融合**（可学习的 softmax 融合权重）。
- 两种互补表示逐位置相加并做 RMSNorm：
  `g_t^(i) = RMSNorm(c_t + f_t^(i))`
- 保留全局跨层交互的同时，为每个草稿层提供深度特化的目标视图。

#### 前驱条件自回归头（Autoregressive Heads）
- 并行主干产生各位置独立边缘分布，缺少块内依赖；在主干后增加轻量顺序头。
- **马尔可夫头**：`b_{t+i} = W_1[ x_{t+i-1} ] W_2`，低秩 token 转移偏置加到并行 logits 上。
- **隐藏修正头**：`bz_{t+i} = z_{t+i} + SwiGLU([ ez_{t+i}; e_{t+i-1} ])`，将前驱 token 嵌入与位置特定隐藏状态联合修正。
- 最终采用隐藏修正头（更强的上下文依赖适应能力，仅增加少量顺序计算）。

#### 损失设计（两阶段）
- **冷启动阶段**：D-PACE 加权的混合 LK Loss（按深度置信度动态分配权重）。
- **精调阶段**：端到端 TV 损失（直接优化多深度接受行为）。

### 2.4 D-cut：自适应验证预算分配

#### 问题定义
- 批量中不同请求的接受长度差异大；验证成本随批量大小、并发数、硬件而变化。
- 固定验证深度会浪费算力或限制吞吐。

#### 核心算法
- **估计每请求进度**：用草稿器 token 级置信度的前缀乘积估计前缀存活概率，`Â_i(n_i) = Σ_{k=0}^{n_i} s_{i,k}`。
- **全局预算选择**：定义离散验证比例集合 `R={0.25, 0.50, 0.75, 1.00}`，预算 `K_ρ(B) = max(B, ⌈ρ·B(D+1)⌉)`。
- **Top-K 排序与打包**：将所有草稿 token 按置信度排序，选择全局 Top-K（同分优先浅层），保证每个请求保留连续前缀。
- **运行时选择**：启动时对每个 (B, ρ) 对剖析端到端延迟 `C(B,ρ)`，运行时选择 `ρ* = argmax U(B,ρ)/C(B,ρ)` 最大化预估吞吐。
- **正确性保证**：只改变验证深度，保留 token 仍经目标模型原始验证，不改变输出分布。

## 6. 论文的主要结论与发现

1. **工作负载异构性是推测解码设计的一等公民**：对话（高熵）适合 MTP 短提案，代码/数学（低熵）适合块并行长提案。
2. **TTT 大幅提升 MTP 草稿质量**：在 Hy3 上平均接受率从 52.8% 提升至 66.4%（T=0），MAL 从 2.58 提升至 2.99，主要改进集中在第 2、3 深度的接受率。
3. **DFly 显著超越现有块扩散草稿器**：在 Hy3-A21B 上平均接受长度 4.79 vs DFlash 的 3.69（+29.8%），比 MTP 提升 59.7%；在 Qwen3-8B 上平均 5.41 vs DSpark 的 5.32。
4. **领域特化数据有效**：加入代码和数学数据后，数学/代码接受率显著提升（如 HumanEval 从 5.26 提升至 5.53），对话任务基本保持（MT-Bench 从 3.06 略降至 3.02，属预期）。
5. **5 层草稿 + 块大小 8 是最优配置**：深度从 5 增至 7 无额外收益，块大小从 5 增至 8 是主要增益来源。
6. **Thinking 模式需要匹配训练与部署**：no-think 与 high-think 模型不能共享，应分别训练部署。
7. **D-cut 将饱和并发转化为吞吐增益**：在并发 64 时吞吐 +15.7%，而接受长度仅降低约 2.8%；在同等 per-user 延迟下聚合吞吐提升 14%。
8. **端到端吞吐**：DFly 在所有测试并发下最高，相对 AR 解码 1.98-2.40× 加速，比 DFlash 高 10.5-11.8%。

## 7. 优点

1. **系统性、多层面的异构负载解决方案**：训练数据、模型架构、推理调度三个层面形成有机整体；不同负载使用不同草稿器是合理的生产实践。
2. **TTT 的工程实现**：用因果前缀 + 对角草稿注意力模式隐式复现推理依赖结构，无需显式 TTT 掩码；长上下文训练采用 Ulysses 序列并行 + D-token halo 保持深度移位监督的 rank-local，可在 128k 上下文训练。
3. **DFly 架构设计精巧**：混合目标条件主干既保留了 DFlash 的全局非线性融合，又引入 DFlare 的层特化视图；隐藏修正头的计算开销小但带来持续增益。
4. **D-cut 的工程思考有深度**：将验证视为共享批级资源而非逐请求独立决策，结合置信度排序与硬件剖析成本模型进行运行时预算选择；接受长度下降远小于吞吐提升，说明剪枝策略精准。
5. **开源框架与可扩展性**：提供统一 MTP 和块并行训练支持（targets、objectives、optimizers 三层插件接口），内置文档感知序列打包和实时评估服务器，为社区后续研究提供基础。
6. **组件级性能分析**：通过 NVTX 剖析和 break-even committed length 计算将端到端 TPS 归因到草稿质量和迭代成本，弥补了仅报告端到端指标的不足。

## 8. 不足与局限

1. **D-cut 实现限制**：当前实现仅支持分段 CUDA 图而非完整图捕获，选择器仍在关键路径上形成同步点；实现限制可能高估 D-cut 真实收益（论文也承认这些是工程限制而非方法缺陷）。
2. **置信度估计的偏差风险**：前缀存活概率由草稿 token 置信度乘积近似，未显式校准；置信度校准偏差可能导致预算选择次优；与真实后验的偏差缺乏量化。
3. **D-cut 收益不保证**：其剪枝不一定带来吞吐增益（依赖成本模型和负载），生产断言需要伴随正确性保障与性能可回退机制。
4. **接受长度低估风险**：文中明确说明"DFly 采用全 CUDA 图和分段捕获，而 D-cut 仅分段捕获"，对比低估了 D-cut 的收益；但这也意味着生产中的实际收益可能低于理论值。

5. **领域特化的局限**：DFly 在 MT-Bench（对话）上低于 DSpark，MTP 在对话类高熵负载上仍是最优选择；这引出一个生产层面的关键问题——是否需要在同一部署中同时维护多个草稿器并按负载路由？论文并未充分讨论多草稿器并存时的显存开销、切换策略与路由成本。
6. **训练成本与可复现性信息缺失**：论文未报告各草稿器的具体 GPU 训练时数、显存占用和能耗数据；源码虽开源，但训练数据（如 Open-PerfectBlend 重新生成版本、代码 Agent 轨迹）的完整复现路径未完全说明，社区复现门槛较高。
7. **校准与泛化风险**：置信度前缀乘积作为存活概率估计未经过显式校准，在分布外负载（训练数据未覆盖的新任务）上的预算选择质量缺乏保障；论文也未量化置信度与真实接受概率之间的校准误差。
8. **D-cut 基准对比范围有限**：D-cut 仅在 DFly 草稿器路径上验证，未与 MTP 草稿器组合测试，也未与其他自适应验证策略（如动态提前退出、基于延迟反馈的启发式）对比，其普适性证据不足。
9. **长上下文场景验证薄弱**：尽管训练支持最长 128k tokens，但端到端实验和部署测试均未专门报告长上下文（如 >32k）下的推测解码收益；长上下文中草稿器与目标模型的 KV 缓存行为差异可能显著影响加速比。

## 9. 总体评价

AngelSpec 是一篇工程与系统味道浓厚的推测解码工作。其核心贡献不在于提出某一种全新的草稿算法，而在于**将"负载异构性"确立为推测解码系统设计的第一性约束**，并围绕这一约束给出了训练目标（TTT + 接受对齐损失）、模型架构（MTP 共享参数多深度、DFly 混合条件主干 + 自回归头）、推理调度（D-cut 自适应验证预算）三层递进式的完整解决方案。

论文最突出的价值在于三个层面：

- **方法论上的务实性**：没有追求单一万能草稿器，而是承认不同负载需要不同结构的草稿器，并给出了一整套训练与部署工具链支撑这一分工。
- **损失函数设计的深刻性**：从拒绝采样的接受概率数学形式出发，推导出与端到端接受长度直接相关的 TV loss，并设计了冷启动 + 切换的两阶段训练策略，这一思路对后续推测解码训练工作具有方法论参考价值。
- **生产部署视角的完整性**：D-cut 将验证预算视为批级资源进行动态分配，配合生产流量回放实验和组件级剖析，使得论文结论具备较强的工程可信度。

同时，论文也坦诚地指出了若干工程限制（分段 CUDA 图、选择器同步开销、置信度未校准等），这种披露方式增加了工作的可信度。总体而言，AngelSpec 在推测解码的"训练-架构-推理"全链路上做出了实质性的系统贡献，其开源框架有望成为该领域后续研究的重要基座。

## 10. 未来可能的研究方向

1. **草稿器自动路由**：在 MTP 与 DFly 之间基于请求级特征（如任务类型、prompt 复杂度、条件熵估计）学习自适应路由策略，替代人工选择。
2. **置信度校准与在线调整**：将草稿器的置信度输出校准到真实接受概率，并利用在线反馈（实际接受率）动态校正 D-cut 的预算估计。
3. **多草稿器集成**：在同一部署中并行维护多个轻量草稿器，按 token 级或块级动态选择最优草稿来源，进一步逼近负载分布上界。
4. **长上下文场景的系统级优化**：针对长上下文推理中草稿器与目标模型 KV 缓存不一致的问题，设计专用内存调度与预取策略。
5. **更强的端到端训练目标**：将验证阶段的批量调度决策纳入训练目标（如可微的验证深度选择），实现训练与推理调度的联合优化。
