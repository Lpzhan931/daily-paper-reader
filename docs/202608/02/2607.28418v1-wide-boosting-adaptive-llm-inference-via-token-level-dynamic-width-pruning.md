## 摘要
剪枝是一种提高LLM效率的有前景的方法。现有的静态结构化剪枝方法硬件友好且能带来实际的吞吐量提升，但其与输入无关的计算分配在激进稀疏下往往导致显著的精度下降。最近的动态稀疏方法通过使计算适应单个输入来改善质量保持，但它们仍主要局限于粗粒度的结构决策，并且在现实推理场景中的实际加速仍然具有挑战性。为解决这些挑战，我们提出WIDE，首个端到端可微分的词元级动态宽度剪枝框架，专为预填充和解码场景设计。WIDE通过允许每个词元动态选择注意力头组和FFN通道组，实现了细粒度的计算分配，将动态剪枝从层级别扩展到神经元块级别。通过两阶段训练流程，WIDE学习了有效的词元级稀疏执行模式，并实现了比现有方法更好的质量保持。为了使这种细粒度的动态剪枝变得实用，我们进一步提出了一种剪枝-内核协同设计框架，将动态稀疏加速分解为掩码重排、硬件无关的块级跳过和硬件相关的块内跳过，从而在不同粒度上实现高效执行。在50%稀疏度下，与最先进的动态深度剪枝相比，WIDE在仅校准设置下提供了55.1%的性能提升。在预填充和解码推理工作负载下，WIDE实现了接近理论的内核级加速，预填充最高1.98倍，解码最高4.95倍，以及1.68倍和1.55倍的端到端加速。我们的代码可在https://github.com/EIT-NLP/LLM-Pruning/tree/main/WIDE获取。

## Abstract
Pruning is a promising approach for improving the efficiency of LLMs. Existing static structured pruning methods are hardware-friendly and can deliver practical throughput gains, but their input-agnostic computation allocation often causes substantial accuracy degradation under aggressive sparsity. Recent dynamic sparsity methods improve quality retention by adapting computation to individual inputs, yet they remain largely limited to coarse-grained structural decisions and their practical acceleration under real-world inference scenarios remains challenging. To address these challenges, we present WIDE, the first end-to-end differentiable token-level dynamic width pruning framework designed for both prefill and decode scenarios. WIDE enables fine-grained computation allocation by allowing each token to dynamically select attention-head groups and FFN-channel groups, extending dynamic pruning beyond layer-level decisions to neuron-block-level granularity. Through a two-stage training pipeline, WIDE learns effective token-wise sparse execution patterns and achieves substantially better quality retention than existing approaches. To make such fine-grained dynamic pruning practical, we further propose a pruning--kernel co-design framework that decomposes dynamic sparsity acceleration into mask reordering, hardware-agnostic block-level skipping, and hardware-dependent intra-block skipping, enabling efficient execution across different granularities. At 50% sparsity, WIDE provides 55.1% performance boost when compared to the state-of-the-art dynamic depth pruning under calibration-only settings. Under prefill and decoding inference workloads, WIDE achieves close-to-theoretical kernel-level speedups of up to 1.98x for prefill and 4.95x for decoding, as well as 1.68x and 1.55x end-to-end acceleration. Our code is available at https://github.com/EIT-NLP/LLM-Pruning/tree/main/WIDE.

## 2. 论文提出的方法论

### 2.1 核心思想

- **动态宽度剪枝粒度**：每个token独立选择以下剪枝单元：
  - **注意力层**：按GQA头组大小（\( G = \frac{H_q}{H_k} \times d \)）选择注意力头组，保持与GQA解码优化的兼容性。
  - **FFN层**：沿中间维度（Up/Gate投影的输出特征、Down投影的输入特征）按组大小G（取16/32/64/128等tiling尺寸）选择通道组。
- **路由器（Router）**：采用bottleneck结构（\( W_1 \in \mathbb{R}^{D \times r}, W_2 \in \mathbb{R}^{r \times 2N_G} \)，r通常为16或32），输入token激活，输出每个组执行/跳过的二元决策；训练时用Gumbel-Softmax硬采样，推理时用argmax。
- **剪枝方向**：注意力Q/K/V投影按N轴（out features）剪枝，O投影按K轴（in features）剪枝；FFN Up/Gate投影按N轴剪枝，Down按K轴剪枝（见图1）。

### 2.2 两阶段训练流程

1. **阶段一（Router训练）**：冻结所有非路由参数，仅用校准数据优化路由组件。
2. **阶段二（可选LoRA恢复）**：在所有线性层加入LoRA（r=16, α=32, dropout=0.1）恢复精度。

训练目标函数（类似SkipGPT）：

\[
\mathcal{L} = \mathcal{L}_{LM} + \alpha \left[ S - \frac{1}{2N} \sum_{i=1}^N \left( 1 - \frac{\sum M_{\text{attn}}^i}{|M_{\text{attn}}^i|} \right) + \left( 1 - \frac{\sum M_{\text{ffn}}^i}{|M_{\text{ffn}}^i|} \right) \right]
\]

其中α=20（SkipGPT的设置），S为目标稀疏度，Gumbel温度从5线性退火到0.5。

### 2.3 推理加速：剪枝-内核协同设计框架

针对朴素gather-scatter实现的三大痛点（设备-主机同步、额外内存搬运、token特定权重物化），WIDE提出统一加速框架：

1. **掩码重排序（Mask Reordering）**：对每个路由组的掩码列按M维度降序排序，使活跃token聚成连续前缀，将不规则token路由转化为CTA级规则性——除每组最多一个边界块外，其余CTA行块完全活跃/非活跃。排序后输出重排掩码\(\tilde{M}\)和gather/scatter索引I。
2. **多粒度跳过谓词**：
   - \(\ell=0\)：硬件无关的**CTA级早期退出**（跳过完全非活跃的\([B_M, G]\)块）；
   - \(\ell=1\)：硬件相关的**加载跳过**（A加载时跳过非活跃行包，对应cp.async/TMA gather4等）；
   - \(\ell=2\)：硬件相关的**MMA执行跳过**（跳过非活跃tensor-core指令片段，对应wmma/wgmma/tcgen05.mma）。
3. **三种定制内核**：
   - **GEMM-MN**：适用于Q投影和FFN Up/Gate投影（N轴剪枝），单掩码列控制CTA准入，保持密集式tiled pipeline；
   - **GEMM-K**：适用于O投影和FFN Down投影（K轴剪枝），按组划分局部pipeline，非活跃组整体跳过，活跃组用原子加散射部分输出；
   - **Attention内核**：融合FlashAttention的online softmax，将三重谓词融入query端执行，因果注意力利用对齐的最大活跃query位置缩短KV流式范围；解码时（Tq=1）绕过掩码重排序，直接在块级检查路由。

## 6. 主要结论与发现

1. **质量保持显著优于现有方法**：Llama3.1-8B 50%稀疏度下，WIDE相比最强非WIDE基线提升8.80个平均准确率点（61.84 vs DDP的53.04）；Llama3.2-3B上的差距为8.97点。25%稀疏度下G=32变体保留97.92%的密集模型精度。
2. **校准-only已具竞争力**：WIDE的部分校准-only结果已超越其他方法的LoRA恢复结果，说明"从层选择迁移到宽度分配"本身就是主要收益来源。
3. **LoRA恢复后差距缩小但WIDE仍领先**：50%稀疏度下WIDE保持在约90%的保留率（64.82/58.77的准确率），优于SkipGPT（61.60/54.33）和DDP（54.64/48.88）。
4. **实际加速可观**：50%稀疏度下端到端prefill 1.68x、decode 1.55x加速；内核级接近理论加速（prefill最高1.98x，decode最高4.95x）；GEMM内核在规模较大时可达到2x以上加速。朴素gather-scatter基线对比显示WIDE内核可带来最高200x吞吐提升和1000x峰值内存降低。
5. **加速上界分析**：可加速路径（Q/Up/Gate、O/Down、Attention）在prefill和decode分别获得1.82x和1.92x加速，已接近理想上界；其余延迟来自KV投影、逐元素运算、CUDA Graph启动及WIDE自身开销（约占总延迟prefill 16.7%、decode 29.1%）。
6. **组大小存在最优权衡**：质量在大范围G下保持稳健（Gffn从16增至256，仅下降2.62点；LoRA后从16增至512仅下降1.13点）；但内核效率上G≥128才较理想（GEMM-K需足够K轴主循环开销来摊销流水线，GEMM-MN需保持可调tiling空间）。实际推荐G∈[128, 256]区间。
7. **低稀疏度开销极低**：0%稀疏度下，G≤128的设置仍保留98.60%的密集吞吐。
8. **路由行为呈语义感知**：FFN路由器保留语义承载token（如boy, running, track），跳过虚词token（a, the）；每层跳过比例与层敏感性相关（注意力平均66.2% vs FFN平均28.5%稀疏，即**注意力承担主要跳过**，FFN倾向于保守保留）；层间稀疏分布曲线与静态剪枝的层敏感性观察（如层4–12和24–28峰值）一致。

## 7. 优点

1. **方法论创新**：首次将token级动态剪枝推进到**神经元块级宽度粒度**（注意力头组 + FFN通道组），实现比层/子层路由更细粒度的计算分配；利用GQA对齐保持解码优化兼容性。
2. **系统-算法协同设计**：提出统一的"掩码重排序 + 多粒度块内跳过"加速抽象，一个谓词统一三种粒度的跳过逻辑，同时适用于GEMM-MN、GEMM-K、Attention三类内核；避免了设备-主机同步和token特定权重物化。
3. **两阶段训练有效**：仅路由校准即可达到较好质量，LoRA可选恢复进一步增强；Gumbel Softmax与sparsity损失使训练稳定收敛。
4. **实验系统性**：多层验证（精度-效率-路由行为-理论分析），尤其将朴素gather-scatter的内存流量理论分析和实测结合，有力说明定制内核的必要性。
5. **工程贡献**：同时涵盖高层面DSL（Triton/Tilelang）和底层CuTe/CUTLASS实现，对AI工程社区有参考价值。
6. **写作清晰**：问题定义、内存开销形式化、算法伪代码和附录详实，可复现性较好。

## 8. 缺点与潜在局限性

1. **训练成本未完全透明**：论文未报告完整的训练耗时、GPU-hours或能耗数据，且两阶段各10k步在4×A100上的开销并不算小；实际应用中较长的校准流程可能成为采用障碍。
2. **模型覆盖面有限**：仅在 Llama3.1-8B 和 Llama3.2-3B 两个同源Llama模型上验证，未覆盖Mistral、Qwen、DeepSeek等主流开源模型，也未测试更大规模（如70B）下的训练收敛与内核扩展性。
3. **动态路由的泛化风险**：路由器仅在校准数据上训练，未见其对分布漂移（如领域切换、恶意提示）的鲁棒性分析；对长序列中位置偏移和上下文长度外推的稳定性也未讨论。
4. **细粒度动态形状的系统压力**：虽然排序将不规则性降为“每组的边界块”，但边界块仍然存在；且排序引入的gather/scatter索引本身有内存与计算开销，在batch较小时可能抵消收益。
5. **注意力稀疏的语义风险**：跳过显著比例（平均66.2%）的注意力头组（无论维度是K/V头组还是GQA组）可能对需要细粒度注意力交互的任务（如长文档问答、代码跨文件引用）产生不可预见的质量损失；论文实验未能覆盖这类长程推理任务。
6. **对比实验的基线覆盖有偏**：所选静态宽度基线中缺少较新的结构化剪枝方法（如Sheared LLaMA、LLM-Pruner等更细粒度/二值掩码方法），使得“静态宽度剪枝普遍不敌动态宽度剪枝”这一结论的适用范围不够确定。
7. **端到端加速只在单卡单请求场景测量**：未覆盖批量推理、连续batching、KV cache复用、多卡张量并行等生产环境中的常见模式，真实部署收益可能低于报告值。

## 9. 个人评价与改进建议

### 9.1 总体评价

WIDE是一篇难得的**算法-系统协同设计**的完整论文。其价值不仅在于提出一个新的动态剪枝粒度，更在于指出了一个常被忽略的事实：**动态剪枝的“可加速性”是衡量方法有效性的第一标准**。作者通过联合设计路由器决策格式与GPU执行路径，令细粒度动态稀疏真正落到了tensor core上，这与大量只做“理论稀疏度”而回避系统实现的工作形成鲜明对比。

### 9.2 值得借鉴的方法论亮点

- 将**稀疏分配问题分解为“决策维度（选择哪些组）”与“执行维度（如何跳过）”**，并分别优化，逻辑清晰；
- 用**掩码重排序**将token维度上的不规则性转化为块内的规则性，这是一种优雅的“以少量拷贝换大量规则计算”的折衷；
- 训练目标简洁（仅Router + 可选LoRA），没有引入复杂的强化学习或可微掩码近似（除了Gumbel-Softmax），易于复现。

### 9.3 改进建议

1. **扩展模型与任务范围**：补充Mistral-7B、Qwen2.5-7B等不同架构模型的验证；增加代码生成、数学推理、长上下文检索等任务，检验路由器是否“只学会了跳过虚词”还是真正理解语义。
2. **引入更好基线和更公平的FLOPs对比**：与更现代的静态宽度剪枝方法（如LLM-Pruner的细粒度变体）对比，并报告同一稀疏度下的实际FLOPs节省，而非仅准确率对比。
3. **减少训练成本**：探索一次性联合训练（Router从零开始与主模型一起训练）以省去LoRA第二阶段；或采用蒸馏式路由器以减小其参数量。
4. **增强鲁棒性分析**：在分布外数据集上测试路由器决策质量；分析欺骗性输入（如诱导虚词标记全部保留）对稀疏度预算的影响；
5. **内核优化进一步下探**：在Hopper/Blackwell之外的架构（如A100、MI300X）上验证三粒度谓词的移植性；将掩码重排序与其他系统优化（如KV cache量化、投机解码）结合，报告组合收益。

## 10. 结论

WIDE通过将动态剪枝从层/子层粒度推进到**神经元块级宽度粒度**，并同时设计了与之匹配的**GPU执行抽象（掩码重排序 + 多粒度块内跳过）**，成功实现了在Llama3.1-8B上50%稀疏度、质量保留约90%、端到端prefill 1.68x/decode 1.55x的实际加速。其关键在于**将剪枝决策的可执行性放在与剪枝质量同等重要的位置**，为后续动态稀疏LLM推理研究提供了一个高质量的系统级范本。尽管在模型覆盖、训练成本与生产场景验证方面仍有改进空间，但该方法在精度保持、系统加速与工程完整性三个维度上的综合表现，使其成为2024-2025年动态剪枝方向上最具代表性的工作之一。
