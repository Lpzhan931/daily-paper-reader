## 摘要
大型混合专家（MoE）语言模型因每个词元仅激活少量专家而适合端侧部署，但其路由专家权重常常超出加速器内存。我们聚焦于延迟关键的单用户场景，其中路由专家按需从CPU内存分页到GPU，或从Flash分页到移动NPU。在此场景下，自推测解码面临新瓶颈：扩大草稿专家集可提高准确性，但会引发额外专家加载，而廉价的低占用草稿接受率低；此外，验证多词元块会激活目标专家并集，不再接近单步目标。我们提出DraftExpert，一种面向专家卸载MoE推理的扩展感知自推测解码框架。DraftExpert通过从冻结的目标MoE中自蒸馏残差、对数几率/词元和路由器一致性信号，为每层训练一个轻量级、驻留加速器的草稿专家。推理时，它使用固定占用（共享+top-1+草稿专家）的草稿器，结合置信度-扩展截断与目标专家预取，而最终词元仍由目标模型精确验证。在DeepSeek-V2-Lite和Moonlight-16B-A3B上，覆盖CPU-GPU和Flash-NPU卸载，DraftExpert平均提升解码吞吐量1.45倍，将草稿接受率提高到84~87%，并实现86~88%的预取命中率。

## Abstract
Large Mixture-of-Experts (MoE) language models are attractive for end-device deployment because only a small subset of experts is active per token, but their routed expert weights often exceed accelerator memory. We target latency-critical single-user settings where routed experts are staged on demand from CPU memory to a GPU or from Flash to a mobile NPU. In this setting, self-speculative decoding faces a new bottleneck: increasing the draft expert set improves accuracy but triggers extra expert loading, while cheap small-footprint drafts have low acceptance; moreover, verifying a multi-token block activates the union of target experts and is no longer close to one target step. We propose DraftExpert, an expansion-aware self-speculative decoding framework for expert-offloaded MoE inference. DraftExpert trains one lightweight accelerator-resident draft expert per layer by self-distilling residual, logit/token, and router-agreement signals from the frozen target MoE. At inference time, it uses a fixed-footprint shared+top-1+draft-expert drafter together with confidence--expansion truncation and target-expert prefetching, while final tokens are still exactly verified by the target model. On DeepSeek-V2-Lite and Moonlight-16B-A3B across CPU-GPU and Flash-NPU offload, DraftExpert improves decode throughput by 1.45x on average, raises draft acceptance to 84~87%, and achieves 86~88% prefetch hit rates.

# 1. 核心问题与整体含义（研究动机和背景）

- **端侧 MoE 部署的天然矛盾**：大规模混合专家（MoE）语言模型因每个 token 仅激活少量专家（如 DeepSeek-V2-Lite 中每层 top-6/64）而非常适合端侧部署，然而路由专家权重庞大（DeepSeek-V2-Lite 中路由专家占 91.6% 参数，约 26.8 GiB），远超消费级 GPU 或移动 NPU 的加速器内存。
- **专家卸载成为必然**：实际运行中需将非路由权重常驻加速器（因其每步前向都使用），而将路由专家存放在 CPU 内存（CPU→GPU）或 Flash（Flash→NPU）中按需加载。在这种设定下，**专家加载/搬运取代算术计算，成为解码延迟的主导因素**（在 CPU→GPU 上占解码时间的 87%，Flash→NPU 上占 49%）。
- **经典推测解码三条件在 MoE 卸载下被打破**：
  1. **草稿不再廉价**：增大草稿路由数 r 可提升接受率（top-1→top-3 从 22% 升至 42%），但草稿延迟增至 top-1 的 2.4 倍，草稿加速比从 4.7× 跌至 2.0×——**准确性是用更多专家加载换来的**；
  2. **并行验证不再接近单步代价**：K 个 token 的验证块会激活目标专家的并集，验证成本随块长度增长（K=16 时可达单步解码的 5.8×），而稠密 FFN 仅为 1.0×；
  3. **小足迹草稿接受率低**：仅共享+top-1 草稿会遗漏路由专家残差，导致隐藏状态漂移，token 一致性和路由一致性均差，即使 top-3 仍低于 50% 接受率。
- **核心范式转变**：性能优化单位从“每目标前向生成的 token 数”转变为“**每个专家集扩展所接受的 token 数**”（accepted tokens per expert-set expansion）。本文的核心含义是：在端侧 MoE 卸载场景下，推测解码的设计必须以控制专家加载足迹为核心。

# 2. 方法论：核心思想、关键技术细节

## 2.1 总体框架

DraftExpert 通过三个设计分别恢复上述三个条件，整体流程分为**离线自蒸馏**（训练草稿专家）与**在线精确推测解码**（草稿 + 截断 + 预取 + 验证）两个阶段，最终所有输出 token 均由冻结的目标 MoE 精确验证，不改变模型语义。

## 2.2 固定足迹草稿（Fixed-Footprint Drafting）

- 传统共享+top-r 草稿器的成本随 r 和草稿长度 K 增长；DraftExpert 改为**共享 + top-1 + 草稿专家**路径：
  \[
  y^d_l = S_l(h_l) + g_{l,e_1} E_{l,e_1}(h_l) + \gamma_l E^d_l(h_l)
  \]
  其中 \(S_l\) 为共享专家，\(e_1\) 为目标路由 top-1 专家，\(E^d_l\) 为每层新增的一个**轻量级、常驻加速器的草稿专家**（仅草稿专家与缩放系数 \(\gamma_l\) 可训练）。
- 效果：草稿阶段的路由专家足迹接近 top-1（K=4 时累计唯一专家仅 88 个，vs. top-1 的 84 个），而远低于 top-3 的 244 个，同时草稿延迟相对 top-1 仅增至 1.05–1.09×（对比 top-3 的 1.59–1.86×）。

## 2.3 自蒸馏训练（Self-Distillation）

- **残差蒸馏**：定义被遗漏的路由专家残差 \(m^*_{l,t} = y^*_{l,t} - S_l(h^*_{l,t}) - g_{l,e_1}E_{l,e_1}(h^*_{l,t})\)，训练草稿专家逼近之（\(L_{\text{res}}\)）；
- **最终 logits 蒸馏**（\(L_{\text{logit}}\)，温度缩放 KL 散度）与 **token 蒸馏**（\(L_{\text{tok}}\)，交叉熵）提升草稿的 token 级接受率；
- **路由器一致性蒸馏**（\(L_{\text{router}}\)）：监督草稿隐藏状态的路由分布逼近目标模型路由分布。该信号是验证侧专家预测的关键——草稿路由越准，预取命中率越高；
- 完整损失：\(L = L_{\text{logit}} + \alpha L_{\text{tok}} + \beta L_{\text{res}} + \eta L_{\text{router}}\)，所有监督来自无标注文本与冻结的目标 MoE，无需额外人工标注。

## 2.4 成本感知动态截断（Cost-Aware Dynamic Truncation）

- 对第 i 个草稿 token，用草稿 logits 计算置信度 \(q_i\)，用训练好的草稿路由器预测验证层会用到的目标专家集 \(\hat{\mathcal{U}}_i\)，计算边际专家扩展 \(\Delta_i\)；
- 当 **置信度低于阈值 τ 且边际新专家数超过预算 \(B_i\)** 时，在追加该 token 之前停止草稿、截断候选。该策略精确无损：被丢弃的候选不会输出，所有保留候选仍由目标 MoE 验证。

## 2.5 草稿路由器专家预取（Draft-Router Expert Prefetch）

- 每当一个草稿 token 被保留，立即对其预测的新增验证专家发起**非阻塞异步预取**（专家不在缓存或传输中时），与剩余草稿计算重叠；
- 验证阶段仅在需要时等待未完成的预取，缓存缺失仍走按需加载回退，不改变语义。

# 6. 主要结论与发现

1. **专家集扩展是端侧 MoE 推测解码的首要瓶颈**：草稿和验证阶段的性能均受"每次加载多少新专家"控制，而非传统意义上的 token 数或 FLOPs。
2. **固定足迹草稿器 + 自蒸馏可以同时获得低成本和接受率**：共享+top-1+草稿专家路径将草稿足迹固定在 top-1 水平的同时，通过残差/logit/token 自蒸馏将接受率推高至 83–87%，打破了"精度↔成本"的直接权衡。
3. **路由一致性蒸馏是验证侧可控性的关键**：它将草稿路由器与目标路由器的对齐度提升至 0.85–0.86，使预取命中率达到 86–88%，使验证成本从固定长块的 2.35–3.30× 降至 1.25–1.40×。
4. **端到端加速显著且平台相关**：平均提速 1.45×，其中 Flash→NPU 设置增益更大（1.52×/1.61×），因其加载瓶颈更严重、优化空间更大。
5. **无训练 baseline（shared+top-r）在精确验证下反而比 AR 慢**（表 2 中 top-r TPS 低于 AR，如 DS-CG 1.19 vs 2.19）：多付的专家移动成本在大量候选被拒的情况下无法回收。

# 7. 优点

- **问题定义深刻且具创新性**：将端侧 MoE 推测解码重新定义为"专家集扩展"优化问题，提出了"每新增专家接受的 token 数"这一新的性能单元，具有很强的解释力与通用性。
- **训练目标双管齐下（草稿准确率 + 路由可预测性）**：现有方法多只关注接受率，DraftExpert 明确将路由器一致性作为独立蒸馏目标，直接服务于验证侧预取，形成了草稿与验证两端的闭环优化。
- **精确无损的方法论保证**：所有转发 token 由冻结目标 MoE 验证，截断只影响候选提出、预取只影响数据搬运时机，均不改变生成分布，因此与基线之间的加速比比较公平。
- **工程细节务实**：动态截断的二元条件（置信度低 + 边际扩展大）简单可调，预取与草稿计算异步重叠的设计贴近真实部署；两种端侧平台的选择（消费 GPU 与移动 NPU）具有现实代表性。

# 8. 不足与局限

- **训练成本与细节缺失**：未报告草稿专家训练的数据量、GPU 时数、收敛情况等；若训练成本过高，可能削弱端侧部署的实用价值。自蒸馏依赖对完整 MoE 的离线前向，该过程本身在端侧可能难以承受。
- **实验覆盖的广度限制**：仅两个 MoE 模型，且都是约 16B 级别；未覆盖更大模型（如 DeepSeek-V3 或更大）或不同路由策略（如 top-k 更大、细粒度专家）的 MoE；未评估多用户/批处理场景（虽然论文声明聚焦单用户延迟关键场景）。
