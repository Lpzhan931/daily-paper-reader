## 摘要
在边缘设备上部署大型语言模型日益受到模型大小与可用内存之间不断扩大的差距的限制。现有方法如量化、更小模型和卸载可以提高有效内存上限，但它们仍然假设模型可以被压缩或分区以适应某个预算。我们针对更困难的模型超出内存的设置，在这种情况下，模型在整个执行过程中仍然大于常驻内存，存储成为关键路径上权重的主动来源。我们观察到自回归解码期间的MLP活动具有很强的时间局部性：大约82-85%的活跃神经元从当前token持续到下一个token。这意味着当前token所需的大部分稀疏权重已经驻留，只有新需要的行必须从存储中获取。我们提出了NeuroPrefetcher，一个存储后端LLM推理系统，利用这一特性通过预测性增量预取。在第0层之后，单个GPU驻留预测器，占用基础模型参数的2.86%，在一次前向传播中预测所有下游MLP层的稀疏活动。运行时将这些预测与驻留GPU缓冲区进行比较，并仅为传入的增量行发起应用程序调度的NVMe读取，用显式的、模型感知的权重移动取代反应式的操作系统按需分页。在真实统一内存边缘硬件上，NeuroPrefetcher在受限内存预算下比llama.cpp实现了7.9-12.0倍的加速。

## Abstract
Deploying large language models on edge devices is increasingly limited by a widening gap between model size and available memory. Existing approaches such as quantization, smaller models, and offloading can raise the effective memory limit, but they still assume that the model can be compressed or partitioned to fit within some budget. We target the harder model-exceeds-memory setting, in which the model remains larger than resident memory throughout execution and storage becomes an active source of weights on the critical path. We observe that MLP activity during autoregressive decoding has strong temporal locality: approximately 82-85% of active neurons persist from one token to the next. This means that most sparse weights needed for the current token are already resident, and only the newly needed rows must be fetched from storage. We present NeuroPrefetcher, a storage-backed LLM inference system that exploits this property through predictive delta prefetching. After layer 0, a single GPU-resident predictor, occupying 2.86% of base model parameters, predicts sparse activity for all downstream MLP layers in one forward pass. The runtime compares these predictions against resident GPU buffers and issues application-scheduled NVMe reads only for incoming delta rows, replacing reactive operating-system demand paging with explicit, model-aware weight movement. On real unified-memory edge hardware, NeuroPrefetcher achieves 7.9-12.0x speedup over llama.cpp across constrained memory budgets.

## 1. 核心问题与研究动机

大型语言模型（LLM）在边缘设备上的部署面临日益严重的**模型—内存鸿沟**：过去五年模型规模约以每代 10× 增长，而边缘 DRAM 容量仅增长约 2×。论文指出，现有方法（量化、小模型蒸馏、卸载）有一个共同假设——**模型可以被压缩或分区以适应某个内存预算**。它们无法处理更困难的 **模型超出内存（model-exceeds-memory）** 场景：即在执行全过程中，模型权重始终大于常驻内存，存储（NVMe）成为关键路径上必须主动供给权重的层级。

在此场景中，现有系统（如 llama.cpp）依赖操作系统按需分页（demand paging），导致大量页面错误、CPU 被 I/O 阻塞而 GPU 利用率极低（实测 Jetson AGX Orin 上每秒 11,453 次 major faults、CPU iowait 77%、GPU 利用率仅 3%）。核心矛盾在于：**推理性能受限于存储权重的被动移动，而非算力**。

## 2. 方法论体系

**核心观察**（论文三大关键发现之一）：自回归解码中，MLP 活跃神经元具有极强的时间局部性——约 **82–85% 的活跃神经元在相邻 token 间持续存在**。因此，当前 token 所需的大多数稀疏权重已驻留内存，只需从存储中获取“增量”（delta）行。

**总体架构**：NeuroPrefetcher 将模型的 N 个 Transformer 层划分为两部分——前 d 层为**密集前缀**（MLP 权重完全驻留 GPU），后 N−d 层为**稀疏后缀**（每层维护固定容量的活跃行 GPU 缓冲区，完整稀疏权重集存储于 NVMe）。

### 2.1 离线稀疏质心准备
- **激活阈值化**：对 MLP 激活按层计算 α 百分位阈值，将低于阈值的元素置零，强制产生稀疏性（不重训练、仅作用于 MLP、保留注意力）。采用三种稀疏级别（62%/50%/31% sparsity）。
- **稀疏模式聚类**：将二值激活掩码聚类为稀疏二值质心（centroid），使运行时预测空间从“数千个神经元级决策”压缩为“每层一个质心 ID 决策”。

### 2.2 共享激活预测器
- **一次前向传播发出全部 2×31=62 个质心 ID**（每层各一个 gate、一个 up 质心 ID），在第 0 层结束后即生成完整稀疏层 I/O 计划——这比 DejaVu 等逐层预测器更早，为存储预取提供了**前瞻时间窗口**。
- 输入特征：token embedding、pre-attention LayerNorm 输出、attention-head 草图（128 维）、post-attention RMS norm 标量、第 0 层 gate 质心 ID（紧凑激活结构编码）。
- 架构：4 个投影块（各输出 512 维）→ 拼接为 4T 语义向量，与质心 embedding（4T）拼接成 8T → 4 块残差 MLP 主干 → 31 个独立线性输出头（gate 与 up 各一组）。
- 采用交叉熵损失联合训练（gate + up），AdamW 优化器。
- 预测器包含 2.068 亿参数，仅占基础模型 2.86%，FP16 下 414 MB，始终驻留 GPU。

### 2.3 预测性增量预取
对每个稀疏层，计算活跃集的 token 间集合差：

- D_in = A_t(l) \ A_{t−1}(l)（**需要从 NVMe 获取的进入行**）
- D_out = A_{t−1}(l) \ A_t(l)（**释放缓冲区槽位的离开行**）

系统维护每层槽位映射（slot map），复用释放槽位避免缓冲压缩；SwiGLU 结构下中间神经元需 gate 与 up 同时活跃，因此同一活跃集统一索引 gate、up、downᵀ 三个投影缓冲。

### 2.4 显式 I/O 路径
- **神经元中心权重布局**：离线将 gate/up/downᵀ 三行重排为连续记录（24.5 KiB/记录），一次读取取回同一活跃神经元的全部投影行，支持相邻 ID 合并为连续读范围。
- **io_uring + O_DIRECT** 异步批量提交（队列深度 256），与密集前缀计算重叠。
- **缓存一致性暂存**：因 Jetson 统一内存上直接 I/O 可绕过 CPU 缓存导致 GPU 读到脏数据，读入数据先落到 cudaHostRegisterMapped 的暂存缓冲区，再由融合的 deinterleave-scatter CUDA 内核写入各层活跃行缓冲的指定槽位（专用 CUDA 流，与计算重叠）。
- 首个 token 冷启动时获取完整预测活跃集，之后仅走增量路径。

## 6. 主要结论与发现

1. **模型超出内存场景下**，NeuroPrefetcher 在 9.0–13.2 GiB CUDA-available 区间较 llama.cpp 实现 **7.9–12.0× 加速**（mem=14G 时 3.22 tok/s vs 0.34 tok/s）。
2. **Delta 复用率高**：82–85% 的稀疏后缀行从上一 token 复用到下一 token，NVMe 流量降至激活集的 15–18%；9.0–14.8 GiB 内存区间内 per-token I/O 仅从 ~1 GiB 降到 103 MiB，而不回退到整层 NVMe 读取。
3. **密集/稀疏分割是核心调优旋钮**：扫描 d 呈现三阶段——上升（更多密集层减少稀疏 I/O）、峰值（d*：62% 稀疏时 14、50% 时 8、31% 时 2）、急剧下降（缓冲区不足导致回退整层读取）。
4. **预测器几乎不损失质量**：约 99% 的层决策选择正确质心，质量损失主要来自离线聚类而非运行时预测；Mistral-7B 保留 95–96% 的 HellaSwag 基线准确率，Llama-3-8B 保留 92–93%。

## 7. 方法优点与亮点

- **问题定位精准**：直接瞄准多数系统回避的“模型超出内存”最困难场景，而非在已有“适配预算”假设上做增量改良。
- **时间局部性观察驱动系统设计**：将 82–85% 的神经元持久性这一量化发现直接转化为集合差机制（D_in/D_out），思想干净且工程实现周到（槽位复用、无压缩）。
- **单次预测器实现前瞻 I/O**：在第 0 层后一次前向即可获得全部下游层 I/O 计划，与逐层预测相比提供了存储预取所需的时间窗口——这是存储感知推理的关键架构创新。
- **系统级正确性处理扎实**：识别并解决了 Jetson 统一内存中直接 I/O 绕过缓存导致数据陈旧的问题，设计了 coherent staging + 融合 deinterleave-scatter 内核，且指出该机制可移植到其他平台。
- **内存自适应切分**：密集前缀长度可随内存收紧自动调整，低稀疏度

- **内存自适应切分**：密集前缀长度可随内存收紧自动调整——低稀疏度（31%）时最优 d 很小（2），高稀疏度（62%）时 d 更大（14），从而在任意内存预算下都能以最小质量损失换取 I/O 流量下降，这种“稀疏度—内存—性能”的三维折中是通过单一旋钮（d）实现的，工程实现极为简洁。
- **可移植的系统设计**：虽然实验基于 Jetson 统一内存，但论文明确描述了其设计在独立 GPU（CPU 与 GPU 分离内存）场景下的推广方式——将暂存缓冲区替换为 GPU 端 pinned memory、将 scatter 内核合并到计算流即可，表明方法并非硬件绑定。
- **全面的能力研究**：对 20 个现有系统做了详尽的可行性调查，不仅说明了“不能跑”，还分类了失败原因（初始化失败、统一内存不兼容、无 ARM 版本），为社区提供了该场景下系统生态的清晰地图，也合理化了自己作为唯一端到端方案的定位。

## 8. 局限与改进方向

- **I/O 瓶颈仍占主导**：即使实现 12× 加速，延迟分解中 NVMe I/O 仍占 80–87%。预测性预取只是将 I/O 放到了与计算重叠的更优路径上，并未本质减少所需数据量（激活集本身随模型规模增长）。进一步压缩（如更激进的稀疏化、delta 压缩）可能突破该上限。
- **依赖数据相关的局部性假设**：82–85% 的神经元持久性是在 WikiText-2 语料上观察到的，对于分布漂移较大的真实流量（如多轮对话、代码生成、结构化输出），其持久性可能变化，从而影响 delta 复用率和端到端性能。论文未对此做鲁棒性分析。
- **预测器自身的开销与内存**：2.068 亿参数的预测器即使只占 2.86%，也需常驻 GPU 内存（414 MB）。在更小模型（如 1–3B）或更严格内存预算下，该开销占比会显著上升，可能抵消收益。论文未评估预测器规模压缩（如蒸馏、量化）的影响。
- **仅适配 SwiGLU 架构**：整个稀疏化与索引机制针对 SwiGLU 的三线性投影设计（gate/up/downᵀ 统一索引）。对其他激活函数（如 ReLU、GeLU）网络，需要重新设计稀疏行映射，论文未讨论通用性。
- **离线质心构建依赖语料**：质心和预测器均基于特定语料（WikiText-2）训练，更换领域时可能需重新生成离线数据。论文未给出离线流程的自动化程度或跨领域泛化能力评估。
- **未探索量化叠加**：全程使用 FP16，而 4-bit/8-bit 量化是边缘部署的常见手段。若结合量化，模型将被压缩至更小体积，模型超出内存的边界下移，但稀疏 I/O 逻辑是否与量化权重布局兼容、性能如何提升，论文没有涉及。

## 9. 总结与个人评价

NeuroPrefetcher 是一篇系统性很强、工程完成度极高的系统论文。其核心贡献不是单个算法武器，而是“稀疏性 + 预测性预取 + 内核旁路 I/O”三者协同的完整推理引擎——尤其针对 **模型超出内存（而非模型适配内存）** 这一被主流方案回避的真实场景，给出了可量化、可复现的解决方案。

论文在方法论上有一个值得注意的智慧：它没有追求“让模型完整塞进内存”或“仅在内存与存储间做传统分页”，而是以**稀疏性为桥梁**，将“哪些权重在下一 token 需要”这一不可直接预知的问题转化为“哪些神经元活跃集变化”——利用时间局部性将存储流量缩小一个数量级。这种“以主动稀疏换取被动存储带宽”的思路，在边缘 AI 内存墙问题日益严峻的当下，具有很强的启发性。

从实验设计看，作者展现出极高诚信度：详细给出能力研究证明其他系统无法运行、明确报告 I/O 仍占大头、扫描了所有关键超参数（稀疏级别、密集前缀长度、内存预算），且没有过度宣称加速比。对硬件细节（如 O_DIRECT 缓存一致性问题）的深入刻画，使系统具备较强的可复现性。

当然，论文的实验规模仍局限于单一 SoC 平台与 7B/8B 模型，预测器训推同源（WikiText-2）也可能高估了实际泛化性能。但作为边缘稀疏推理方向的探索性工作，它已经为“存储级推理”提供了清晰的设计范式——借用论文的一句总结：**“当权重不再适配内存时，真正的瓶颈不是模型，而是 I/O 路径上缺失的预测性。”**
