## 摘要
基于大型语言模型（LLM）的智能体应用往往面临较高的响应延迟。投机解码是一种在不影响生成质量的前提下提升LLM智能体推理效率的可行方案。然而，现有的最先进投机解码算法在大批量场景下会出现明显的速度下降，限制了其在实际智能体应用中的部署。在本工作中，我们首先对LLM智能体的投机解码进行了系统性分析，并识别出导致加速效果下降的两个主要因素：投机token的高拒绝率，以及动态token预算的利用不足。基于这些观察，我们提出了AgentSpec，一种针对LLM智能体现有方法局限性的投机解码算法。AgentSpec引入了结构隔离式草拟，将投机限制在智能体工作流的语义连贯片段内，减少无关语义路径的草拟，从而实现极低的拒绝率。此外，AgentSpec采用冗余感知的预算分配，利用智能体级信息更好地利用推理过程中动态空闲的token预算。我们在vLLM中针对五种不同工作负载和来自四个不同LLM家族的四种模型对AgentSpec进行了实现与评估。实验结果表明，AgentSpec优于现有最先进方法。

## Abstract
Large language model (LLM)-based agent applications often incur high response time. Speculative decoding is a promising solution to improve the inference efficiency of LLM agents without impacting generation quality. However, state-of-the-art speculative decoding algorithms exhibit substantial speed degradation under large batch sizes, limiting their effectiveness to deploy in real-world agent applications. In this work, we first present a systematic analysis of speculative decoding for LLM agents and identify two dominant factors of speedup degradation: high rejection rate of speculative tokens, and under-utilization of dynamic token budgets.B ased on these observations, we propose AgentSpec, a speculative decoding algorithm that addresses the limitations of existing methods for LLM agents. AgentSpec incorporates structure-isolated drafting that constrains speculation to semantically coherent segments of the agent workflow, reducing the drafts of irrelevant semantic paths and achieving an extremely low rejection rate. Moreover, AgentSpec adopts redundancy-aware budget allocation that exploits agent-level information to better utilize the dynamically-free token budget during the agent inference. We implement and evaluate AgentSpec on five different workloads and four different models from four different LLM families in vLLM. Our results demonstrate the superiority of AgentSpec over state-of-the-arts.

## 2. 方法论：AgentSpec

AgentSpec是一种**无草稿模型（draft-model-free）** 的投机解码算法，包含两个核心组件。

### 2.1 结构隔离式草拟（Structure-Isolated Drafting）

**核心思想：** 智能体的生成内容具有清晰的语义块结构（如推理、工具调用、结果解读），而重复模式几乎只出现在同一查询的同一语义块内。因此，投机草稿应**仅在相同语义块内检索历史**，避免跨块/跨查询的语义漂移。

**关键技术细节：**
- 智能体应用随请求提供结构标识符：`Sᵢ = {aᵢ, qᵢ, Bᵢ}`，其中 `aᵢ` 是应用ID、`qᵢ` 是用户查询索引、`Bᵢ` 是语义块列表（由起始/结束标签对定义）。
- 采用**缓存化token-字符串映射**（类似XGrammar的缓存机制），避免解码过程中频繁调用tokenizer。
- 服务端维护一个**轻量级字符串级下推自动机（PDA）**，增量跟踪当前生成的语义块位置。
- 为每个（应用、查询、语义块）三元组维护独立的**结构隔离缓存**，草稿仅从匹配的缓存中检索。

**效果：** 拒绝率降至26.4%，比现有方法降低50%以上。

### 2.2 冗余感知预算分配（Redundancy-aware Budget Allocation）

**核心思想：** 将有限的投机token预算优先分配给接受潜力更高的请求。论文发现**历史冗余度**（redundancy，即草稿与历史重复模式的对齐程度）与草稿接受率高度正相关。

**关键技术细节：**
- 定义**冗余度评分**：
  - 公式：`g(c, n) = (c/n) · p(n)`
  - 其中 `n` 为同语义块、同查询下检索到的候选延续数；`c` 为一致同意最常见前缀的延续数；`c/n` 表示候选间共识度
  - `p(n) = g_min + (1 - g_min)(1 - e^(1-n))` 为饱和项，用于在历史支持不足时降低估计置信度；`g_min` 为最低置信度超参数
- 批量级投机预算：`B_t = ⌊α · b_z⌋`，`b_z` 为批大小，`α` 控制整体预算规模。
- 每请求草稿长度分配：
  - 公式：`Lᵢ = max(|CTᵢ|, B_t · gᵢ / Σgⱼ)`
  - 优先保证每请求至少草拟其最自信的前缀，再将剩余预算按冗余度比例分配。

**效果：** 在批大小增大的过程中，草拟token总数始终低于最大可用预算M(b)并逐渐逼近，说明预算利用率的提升。

## 6. 主要结论与发现

1. **现有投机解码方法在智能体批量推理中普遍退化**：大部分基线在批量推理时的goodput甚至低于普通自回归解码。
2. **AgentSpec在全部4个智能体基准上持续优于所有基线**：最高达到2.02×加速比（GPT-OSS-20B + Code Generation Agent），相对最佳基线最高提升104%。
3. **拒绝率大幅降低**：从53%~89%降至26.4%，这是加速提升的首要因素。
4. **预算利用率改善**：AgentSpec的草拟token数始终贴合可用预算M(b)，而现有方法严重偏离。
5. **可泛化到非智能体场景**：在Spec-Bench上实现1.14×整体加速，子集最高1.40×。
6. **即使面对MTP（预训练联合草稿模型）**，AgentSpec在MiMo-7B上仍取得更高加速比（最高1.34× vs 1.18×）。
7. **无需显式语义结构也能工作**：AgentSpec(N)（无结构输入的变体）仍优于所有基线，表明了对不同智能体应用的适应性。
8. **在不同批大小与思考模式下均保持鲁棒**：尤其在不使用thinking模式时，加速比超过2.5×。

## 8. 不足与局限

1. **依赖显式语义结构元数据**：虽然AgentSpec(N)变体无需结构输入也能工作，但完整版需要智能体应用额外提供结构标识符（agent-id、query-id、structure），在实际部署中可能需要对现有智能体框架做接口适配。
2. **加速效果依赖历史重复模式**：在生成模式多样性极高、历史重复度极低的场景下，草拟候选的可用性会下降，加速效果可能受限（论文在Spec-Bench数学推理子集上也观察到提速有限）。
3. **轻量级PDA的泛化性**：PDA的表达能力有限，对编程语言等需要上下文无关文法（CFG）甚至更复杂结构的生成场景，字符串标签对的方式可能不够泛化。
4. **实验规模有限**：未在更大参数规模（如70B以上）或真实生产级多机分布式服务环境中进行验证；vLLM之外的引擎兼容性未被评估。
5. **配置参数敏感**：α 和 g_min 等超参数虽然不随批大小变化，但未做敏感性分析——在不同工作负载下是否需要重新调参不明确。
6. **部分披露信息缺失**：GPU数量、单位实验时长、能耗等算力成本信息未提供，不利于复现和成本评估。
