## 摘要
半结构化N:M稀疏性已成为加速大型语言模型（LLM）的实用方向。然而，现有的可学习掩码方法会带来大量的参数和内存开销，限制了其在大模型和高稀疏率场景下的可扩展性。在这项工作中，我们从兼顾效率与可扩展性的角度重新审视半结构化剪枝。我们提出了重要性水库（RoI），一种通过可微子集采样学习稀疏掩码的轻量级半结构化剪枝框架。与先前对所有可行N:M模式建模完整分类分布的方法不同，RoI引入了一种紧凑logit参数化用于稀疏掩码学习，并通过无放回采样来选择掩码，从而将可训练参数从组合复杂度降低到$\mathcal{O}(M)$。因此，RoI所需的可学习参数减少了1.5-8.75倍，内存成本也显著降低，同时完全保持与硬件友好的稀疏模式对齐。在Qwen2.5 LLM系列（0.5-7B参数）多个规模上的广泛评估表明，RoI在强内存效率、稳定性和对更激进N:M稀疏模式的可扩展性方面取得了有竞争力的性能，为高效LLM部署提供了一条实用路径。

## Abstract
Semi-structured $N$:$M$ sparsity has emerged as a practical direction for accelerating large language models (LLMs). However, existing learnable-mask approaches incur substantial parameter and memory overhead, limiting their scalability to large models and aggressive sparsity regimes. In this work, we revisit semi-structured pruning from a perspective that reconciles efficiency with scalability. We propose Reservoir of Importance (RoI), a lightweight semi-structured pruning framework that learns sparsity masks through differentiable subset sampling. Unlike prior methods that model full categorical distributions over all feasible $N$:$M$ patterns, RoI introduces a compact-logit parameterization for sparsity mask learning and performs sampling without replacement to select masks, thereby reducing trainable parameters from combinatorial complexity to $\mathcal{O}({M})$. As a result, RoI requires 1.5-8.75$\times$ fewer learnable parameters and significantly lower memory cost, while remaining fully aligned with hardware-friendly sparsity patterns. Extensive evaluations across multiple scales of the Qwen2.5 LLM family (0.5-7B parameters) demonstrate that RoI achieves competitive performance with strong memory efficiency, stability, and scalability to more aggressive $N$:$M$ sparsity patterns, offering a practical path toward efficient LLM deployment.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：大型语言模型（LLM）部署面临严重的计算和内存瓶颈，剪枝是缓解这一问题的核心技术手段。剪枝分为非结构化剪枝（灵活但难以加速）、结构化剪枝（硬件友好但损害精度）和半结构化剪枝（如 N:M 稀疏性，介于两者之间，兼顾硬件加速与精度保持）。
- **核心问题**：现有的可学习掩码半结构化剪枝方法（如 MaskLLM、HyperPrune）为每个剪枝组建立对所有可行 N:M 模式的完整分类分布，即需要 $\binom{M}{N}$ 个参数。这种组合复杂度参数化方式导致训练参数量和内存开销随 M 增大急剧膨胀，严重限制了在大规模 LLM 和高稀疏率场景下的可扩展性。
- **整体含义**：论文旨在设计一种轻量级的半结构化剪枝方法，在保持硬件友好 N:M 稀疏模式的同时，大幅降低掩码学习的参数与内存开销，使可学习掩码方法能够真正扩展到大规模 LLM 与更激进的稀疏场景。

## 2. 方法论：核心思想、关键技术细节

**核心思想**：将 N:M 稀疏掩码的生成视为**从 M 个权重中无放回地采样 N 个重要权重**的过程，避免直接对所有可行掩码模式建模。通过引入了**紧凑 logit 参数化**（每个组仅需 M 个 logits），结合**Gumbel-Top-K 可微松弛**，实现可端到端梯度训练的掩码学习。

**关键背景技术**：
- **加权水库采样（WRS）**：一种无放回加权采样算法，每个元素具有权重 $w_i$，采样 K 个元素的概率 $\Pr_{\text{WRS}}(Y|w) = \frac{w_{y_1}}{W} \times \frac{w_{y_2}}{W - w_{y_1}} \times \dots$，其中 $W$ 为总权重。
- **Gumbel-Top-K 技巧**：对 logits 添加 Gumbel 噪声生成随机键 $\kappa_i = \phi_i + g_i$，通过系列 softmax 松弛生成可微的 soft one-hot 向量序列，求和得到 soft K-hot 掩码，从而实现离散采样的可微化。

**优化框架**：
- 将剪枝掩码建模为随机变量，采用**随机变分优化**框架（stochastic variational optimization），最小化变分上界：$\Phi^* = \arg\min_\Phi \mathbb{E}_{\Pr(\mathcal{M}|\Phi)}[\mathcal{L}_{CE}(\mathcal{D}; \mathcal{W} \odot \mathcal{M})]$
- 每个组的掩码分布 $\Pr(m_i|\phi_i)$ 由 WRS 分布诱导，学习 $\phi$ 即学习每个权重的重要性得分。论文证明了从 WRS 分布采样有序子集并求和构造掩码，与直接从目标掩码分布采样的期望损失等价（定理 1）。

**掩码选择松弛**：
- 对 logits 加 Gumbel 噪声得到扰动键 $\kappa_{ij} = \phi_{ij} + g_{ij}$
- 递归更新调整后的键：$\alpha_i^{(k)} = \alpha_i^{(k-1)} + \log(1 - \mu_i^{(k-1)})$，并通过 softmax 松弛得到每个采样步骤的近似 one-hot 向量
- 执行 N 次采样步骤，将 N 个 soft one-hot 向量求和，得到 N-hot 掩码的连续松弛

**温度退火策略**：
- 使用两个温度参数：$\tau$（Gumbel-Softmax 松弛锐度）和 $\lambda$（采样随机性尺度），均采用指数退火调度（从高随机性逐步过渡到确定性），平衡探索与收敛。

**参数复杂度对比**：RoI 将可训练掩码参数从 $\mathcal{O}\left(\binom{M}{N}\right)$ 降至 $\mathcal{O}(M)$，实现指数级的参数效率提升。

## 6. 主要结论与发现

- **性能竞争力**：在 2:4 稀疏模式下，RoI 在零样本准确率上达到与 MaskLLM 相当甚至略优的水平（如 7B 模型 64.54% vs. 64.44%），并一致优于所有 saliency 基线和 ProxSparse；在 WikiText-2 困惑度上，RoI 在所有模型规模上均取得最低（最优）或并列最优的结果。

- **激进稀疏下的鲁棒性**：在 2:8 压力测试中，仅掩码学习方法（RoI 和 MaskLLM）能保持合理的困惑度（<65），saliency 基线全部崩溃（PPL > 10⁴ 甚至无穷大）。

- **可解释性**：掩码重叠分析显示 RoI 与 MaskLLM 产出的掩码具有高度结构相似性（如 q_proj 上 82% 重叠），确认其能学习到与更昂贵方法一致的剪枝模式。

## 8. 不足与局限

- **硬件依赖性强**：N:M 稀疏性的实际加速效果依赖平台支持（如 2:4 在 NVIDIA Ampere/Hopper 等平台上加速显著），但 2:4 以外的模式缺乏内核和厂商优化库支持，在通用硬件（CPU 或非支持 GPU）上收益有限，制约了广泛部署。
- **评估覆盖范围有限**：① 主要集中在 Qwen2.5 一个模型家族，跨架构泛化验证仅有一个 Gemma2-9B；② 评估任务是英文通用 NLP 基准，未覆盖多语言、代码生成、复杂推理、对话等更广泛场景；③ 未涉及 Mixture-of-Experts（MoE）架构以及其他更大规模（>10B）的模型。
