## 摘要
大型语言模型（LLMs）在自然语言理解和生成方面取得了显著成功，但它们的部署受到高计算需求的限制。直接在边缘部署较小的LLM可以规避这一问题，但会降低准确性。在云端部署较小的基于云的大型模型可以保持性能，但代价是昂贵的每token计算。我们提出了一种分布式推理框架\our{}，它在边缘和云端集成了推测解码（SD）。部署在边缘的紧凑草稿模型快速生成候选token，而云上的大型验证模型并行验证这些token。接受的token被保留，只有被拒绝的token才触发验证器纠正，从而大幅减少云查询次数。我们的即插即用设计将大部分计算转移到边缘，显著降低了推理时间和云成本，并且无需任何重新训练即可保持大型模型的准确性。我们的方法展示了在真实环境中实现可扩展、成本高效且准确的LLM部署的实用路径。使用SpecBench和CNN/Dailymail数据集进行的多项自然语言处理任务的实验结果表明，与完整模型相比，\our{}在零精度损失的情况下将云模型调用减少了76%。

## Abstract
Large Language Models (LLMs) have achieved remarkable success in natural language understanding and generation, but their deployment is constrained by high computational demands. Deploying smaller LLMs directly on the edge can circumvent this, but with degraded accuracy. Deploying smaller cloud-based big LLMs preserves performance, but at the cost of expensive per-token computation. We present a distributed inference framework, \our{}, that integrates speculative decoding (SD) across edge and cloud. A compact draft model deployed on the edge generates candidate tokens rapidly, and a large verifier model on the cloud validates these tokens in parallel. Accepted tokens are retained, while only rejections trigger verifier correction, substantially reducing the number of cloud queries. Our plug-and-play design shifts the bulk of computation to the edge, significantly lowers inference time and cloud cost, and preserves the accuracy of the big model without any retraining requirement. Our approach demonstrates a practical path toward scalable, cost-efficient, and accurate deployment of LLMs in real-world environments. Experimental results across multiple Natural Language Processing tasks using SpecBench and CNN/Dailymail datasets demonstrate that \our{} reduces the cloud model calls by $76\%$ with zero loss in accuracy as compared to the full model.

- **核心研究问题**：如何在不牺牲完整模型精度的前提下，降低云端推理调用的频次与成本，使大模型部署在真实环境中既经济可行又具备高性能？
- **本文的解决思路**：提出 **SPADE**——一种边云协同的分布式推理框架，将推测解码（Speculative Decoding, SD）思想引入边缘–云端协同场景：边缘用轻量草稿模型生成候选 token，云端用完整大模型对候选段并行验证，仅在拒绝时进行纠正。该设计将大部分计算负荷下沉到边缘，显著减少昂贵的云端调用，同时严格保持云端大模型的生成分布。

## 2. 方法论：核心思想、关键技术细节与算法流程

- **核心思想**：将传统 SD 的"小模型提案 + 大模型验证"范式解耦到物理分布的两端——**草稿模型在边缘本地运行**，**验证模型在云端运行**。边缘模型不再逐 token 地请求云端，而是以"块"为单位生成候选序列，云端一次前向传播即可并行验证整块候选，从而大幅压缩云端调用次数。
- **模型配置**：
  - **边缘草稿模型 M_q**：紧凑轻量，具备低延迟特性，适合在边缘设备的受限内存与带宽下运行，负责自回归地快速生成候选 token 序列。
  - **云端验证模型 M_p**：完整大模型，负责在单次并行前向传播中对候选 token 块进行逐位置验证，保证输出与纯云端大模型分布一致。
- **验证准则**：
  - 对草稿分布 q(x) 采样出的候选 x，接受概率为：
  \[
  \alpha(x) = \min\left(1, \frac{p(x)}{q(x)}\right)
  \]
  - 若被拒绝，则从修正分布中重新采样替换 token：
  \[
  p'(x) = \text{norm}\left(\max(0, p(x) - q(x))\right)
  \]
  - 该机制确保生成序列与原验证模型独自解码在统计上完全等价（即零精度损失），引用自 Leviathan et al. [12] 的理论保证。
- **完整算法流程（Algorithm 1）**：
  1. 输入用户提示词 y₁:ₘ；
  2. 在边缘循环生成 d 个草稿 token；
  3. 将候选块 y_{m+1:m+d} 传输至云端；
  4. 云端进行单次前向传播，并行计算各位置的验证分布；
  5. 按接受准则逐位置判定：接受最长连续被认可的 token 前缀，保留其进入最终输出；首个被拒绝的 token 由修正分布 p′(x) 重新采样替换；
  6. 将接受的序列与纠正 token 一并追加到输出中，更新上下文，边缘模型从新上下文继续生成下一个草稿块；
  7. 循环直到生成结束符 `<eos>`。
- **关键设计保证**：每轮循环至少有一个 token 被追加到输出序列（接受或纠正的 token），保证生成过程必然推进，不会停滞。
- **超参数 d（草稿 token 块长度）**：
  - d 是权衡云计算与通信开销的核心旋钮：d 过小导致频繁的云端验证与同步开销，系统变为通信受限；d 过大则草稿生成成本上升、长序列被拒绝的风险增加，造成边缘算力浪费。
  - 文中将其视为超参数，通过在初始验证子集（约 10 个样本）上监测接受率来经验性选取，以最大化吞吐量为目标。

## 6. 主要结论与发现

- **云端调用显著下降，精度基本无损**：在 Spec-Bench 上，平均云端模型调用次数从完整模型的 133.25 次降至 30.16 次（约减少 **77.4%**），综合任务得分从 4.45 微降至 4.38（降幅约 1.6%）；在 CNN/DailyMail 上，云调用从 127.30 次降至 30.79 次（约减少 **76%**），各项文本质量指标与完整模型高度接近（如 BLEU-1：23.39 vs 23.76，ROUGE-L：23.92 vs 24.32），甚至 CIDEr-D 分数（3.19）高于完整模型（2.50）。
- **效率与精度取得良好平衡**：相比于纯边缘部署（草稿模型），SPADE 在质量上大幅领先（Spec-Bench 综合 4.38 vs 3.39）；相比于纯云端部署，云端运行时间降至约 **0.23×–0.24×**（即节省约 76–77% 的云端计算时长），吞吐量介于两者之间。
- **d 值的影响**：增加草稿 token 长度 d 会持续减少云端模型调用次数；当草稿模型与验证模型对齐良好时，token 接受率高，增大 d 的收益更为明显；若对齐不佳，接受率低，增大 d 将导致冗余计算。
- **整体判断**：SPADE 为边云协同 LLM 推理提供了"插拔式"的可行路径，在不重训练、不修改模型结构的前提下，以极少质量损失换取显著的成本与延迟收益。

## 7. 优点

- **创新性地结合两个成熟方向**：将推测解码从单机加速范式拓展为分布式边缘–云计算范式，针对实际问题（云端推理成本、边缘精度不足）提供了自然且优雅的解决方案。
- **即插即用，无需训练**：不涉及任何重训练、模型修改或数据集特化启发式，兼容任意草稿模型 + 验证模型的组合，具有良好泛化性。
