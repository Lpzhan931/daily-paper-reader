## 摘要
大语言模型（LLM）推理服务日益受到内存而非计算的限制。随着长上下文和长形式推理工作负载变得更为普遍，键值（KV）缓存在LLM词元生成（即解码）期间主导了内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储与HBM分离来缓解HBM容量压力。由于解码时的注意力天然是稀疏的，OasisKV仅在HBM中保留最相关词元的KV条目用于注意力计算。我们观察到，利用投机解码（SD）起草的前瞻词元可以提前准确预测未来重要的词元。OasisKV采用高效的注意力后台流水线来识别重要的KV块，然后从更高容量的内存层级（例如主机或远程内存）预取这些块，并在下一步解码使用之前暂存于HBM中。我们基于vLLM实现了OasisKV。前瞻预测足够准确，在2048词元KV预算下，其精度保持在完全注意力的0.7个百分点以内。这使得OasisKV能够将稀疏性转化为吞吐量增益：在推理工作负载上，相对于密集vLLM达到1.69倍的吞吐量，精度损失0.1个百分点；在多GPU长上下文服务中则高达2.1倍。在预填充-解码分离场景下，OasisKV的密集吞吐量约为2倍，而每个请求的KV承载量减少6.5至9.7倍，解码节点主机内存占用比完整KV传输减少2.2至2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **背景**：现代 LLM 推理服务正从"计算密集型"转向"内存密集型"。随着 Agentic 工作负载（如 Web 使用、计算机操作、编码代理）和长上下文推理的兴起，KV 缓存逐渐占据内存占用与内存流量的主导地位，HBM（高带宽内存）的容量与带宽成为限制推理批大小与系统吞吐的核心瓶颈（即"内存墙"问题）。
- **核心问题**：HBM 容量稀缺且昂贵，在解码（decode）阶段，KV 缓存无论在存储容量还是内存传输带宽上都构成严重瓶颈。现有方案存在以下不足：
  - 稀疏注意力仅减少 KV 读取，但无法解决 KV 缓存占用 HBM 容量的根本问题；
  - KV 检索（KV retrieval）将 KV 从CPU/远程内存取回 HBM 的传输放到了解码关键路径上，延迟开销显著；
  - 现有 KV 预取方案缺乏高精度的训练无关预测信号，预测准确度不足，且难以克服 CPU-GPU IO 带宽上限；
  - PD 分离架构下，完整 KV 传输导致 TTFT 增加、解码节点主机内存耗尽。
- **论文含义**：OasisKV 提出一种以内存为中心的推理系统设计，通过将完整 KV 缓存从 HBM 解耦到更高容量内存层级（CPU DRAM 或远程内存），在解码期间仅将最相关 token 的 KV 块稀疏地驻留于 HBM，并利用投机解码（Speculative Decoding）生成的前瞻 token（lookahead token）提前高精度预测未来的 KV 访问需求，配合异步流水线预取，将稀疏性真正转化为吞吐量收益。

## 2. 论文提出的方法论

### 2.1 核心思想
- **利用前瞻 token 进行 KV 块预测**：投机解码产生的 draft token 提供训练无关的准确未来访问信号（图 4、图 6 显示，相比"上一 token"预测，"前瞻 token"预测的 Top-K 块准确率更高，层间一致率达到 98.74%）。
- **异步后台预取流水线**：将 KV 预取从解码关键路径中完全移除，与前台前向计算重叠执行。
- **联合优化预测、选择与传输**：将 预测准确率、传输带宽、精度-吞吐权衡统一为一套系统优化问题。

### 2.2 关键组件与技术细节

#### (1) 前瞻注意力（Look-ahead Attention）
- 前台前向过程同时处理正常 token 和 draft token 的 query：QKV 投影一次产生两组 {q_t^l; q_{t+1}^l}。
- 后台过程：draft query 扫描压缩 key 摘要（compressed key summaries，按块 min/max pooling），预测下一解码步的全局 Top-K KV 块，无需恢复完整 key。
- 压缩 key 摘要仅占完整 KV 缓存大小的 1/16，读流量小。

#### (2) 三层异步流水线（Top-K 预测 → KV 选择 → KV 传输）
- 每个 stage 运行在独立 CUDA stream 的持久化后台 worker 上；CUDA events 强制层层依赖。
- 层间任务相互独立，可并行执行（layer l+1 预测、layer l 选择、layer l−1 传输同时进行）。
- 前台每层注意力的开始前只需等待该层自身 KV 传输完成（layer-local 同步）。
- 流水线稳态周期满足：T_pipe = max{T_pred, T_select, T_transfer} ≤ Δ_prefetch = T_step / N_layer。

#### (3) Delta 选择与上限驱逐策略（Capped Eviction）
- **Delta 选择**：KV 选择阶段先计算预测集与驻留集的交集——已驻留的块不产生 PCIe 流量；对不在预测集中的驻留块，按最近选择时间 LRU 排序，选取驱逐目标；每个非驻留块与一个驱逐目标配对形成传输计划。
- **上限驱逐策略**：每个 KV head 每个解码步最多接纳 C 个新块，将每层 PCIe 传输上限控制在 C 块/head，避免链路带宽被突发流量打满。

#### (4) 头级映射（Head-wise Mapping）
- 在原有 GPU/CPU page table 之上增加一层"head-wise 逻辑到逻辑"映射层（图 9），让每个 KV head 独立维护不同的稀疏块集合。
- 原始 PagedAttention 页表保持不变，更新 Top-K 时只需修改该 head 的映射和 GPU 内容；在张量并行下各 GPU 独立更新本地 KV head，无需跨 GPU 同步。

#### (5) 远程部分获取（Remote Partial Fetching，RPF）
- **部分传输（Partial Transfer）**：只传输首个解码步所需的 KV 块 + 压缩 key 缓存 + draft token KV 状态。prefill 节点先执行一次额外解码步骤以产生首个 query 并确定 Top-K；KV 块在 prefill 节点 host DRAM 持续保留供后续解码远端读取。
- **网络预取（Network Prefetch）**：解码期间 Top-K 选择漂移到解码节点中缺失的块时，视为 cache miss，由后台流水线从 prefill 节点远程读取到解码节点 host DRAM，再聚合并复制进 GPU HBM，整个过程与前台解码重叠，且每块最多跨网络一次。

### 2.3 与传统方案的本质差异
- 与 dense attention：不对全量 KV 计算注意力，而是限于有界工作集；
- 与 sparse attention（如 Quest）：不将全量 KV 留在 HBM；
- 与 KV retrieval（如 ShadowKV、FreeKV）：fetch 不在关键路径上，而是提前预取；
- 与 PD 分离下的 Full KV 传输：不在 decode 节点物化完整 KV，而是按需部分获取。

## 6. 主要结论与发现

- **精度保持**：在 2,048-token KV 预算下，与完整注意力差距 ≤ 0.7 点；LongBench v2 上 Qwen3-8B 丢 0.4 点，Llama-3.1-8B 丢 0.6 点；AIME24 pass@8 与完整注意力持平（83.33），AIME25 pass@8 持平（80.0）。
- **吞吐量提升**：
  - AIME24 推理负载：Qwen3-8B 上 1.69×（2,083 vs 1,235 tok/s），仅丢 0.1 精度点；Qwen3-235B TP8 上 1.20×。
  - 合成负载（多 GPU 长上下文）：最高 2.1×（Qwen3-8B，16K）；Qwen3-235B 最高 1.9×。
  - PD 分离：2.1–2.3×（约 1,204/888 tok/s vs 550/554和384/386），请求 KV 传输量降低 6.5–9.7×，decode 节点主机内存占用降低 2.2–2.6×。
- **PCIe 带宽是硬约束**：fetch cap 从 0.01 放宽到 fetch-all，吞吐从 2,178 掉到 824 tok/s（2.6×），而精度只从 74.9 波动到 77.4——证明系统瓶颈是字节移动而不是注意力计算。
- **远程部分获取（RPF）的价值**：将网络流量从请求的突发转移为均匀分布，网络空闲率从 60% 降至 1–2%；在 prefix caching 场景下 TTFT 可减少 2.0–2.2×（90% 命中率，100 Gbps 链路）。
- **预测质量**：draft query 与真实下一 token query 的 Top-K 集合逐层一致性均值为 98.74%，具备出色的预取指导能力。

## 7. 优点

- **信号来源新颖且接地气**：复用投机解码（SD）的 draft token 作为预测信号，训练无关（部署者无需训练/微调专门预测器），随着 SD 在工业界的普及，该方法的可迁移性强。
- **系统级的完整设计**：不只是提出预测算法或缓存策略，而是同时解决"预测 → 选择 → 传输 → 内存管理 → 调度"全链路问题，包含 head-wise 映射、有界工作集、layer-local 同步等生产级工程细节，并基于 vLLM 实现，集成度高。
- **异步性贯穿始终**：三层后台流水线把预取完全隐藏在前台解码后，每层独立同步，避免等待；配合 delta selection 将 PCIe 流量限制在每步上限内。
- **PD 分离场景考虑周全**：partial transfer + network prefetch 将 KV 稀疏性延伸到网络与主机内存层，在降低 TTFT 和节省 decode 节点内存方面有显著改进，并且完整 KV 保存在远端节点可继续服务后续 drift。
- **实验扎实、对比公平**：覆盖多模型、多体系结构、多部署形态；消融实验定位清晰（fetch cap、RPF），并且明确区分各自框架的全注意力参照基准，避免跨框架分数误导。

## 8. 不足与局限

- **Draft token 目前仅作预取信号而未真正结合投机解码**：论文明确说明当前强制拒绝 draft token，只把它当 lookahead 信号用；draft 模型的前向开销还没有得到吞吐收益的直接摊销（这部分计划作为未来工作）——因此实际端到端吞吐增益可能低估了更大系统潜力。
- **预测精度评估有限**：前瞻 token 与真实 token 的 Top-K 一致性只在单个模型（Qwen3-8B）和单个数据集（GSM8K）上验证，层间一致性的普适性待进一步检验。
- **未支持 prefix caching**：原型没有实现前缀缓存，图 15 的 TTFT 收益是分析模型推演而非实测，实际效果有待验证；此外多跳网络、带宽竞争等现实条件没有实测。
- **fetch ratio 等超参选择敏感**：系统需要精细地设定 fetch cap、KV budget 等参数；如 Qwen3-235B 低 batch 下 TPOT 反而高于 dense（因为 KV 占比小，稀疏化的额外开销>收益），使用时需要依据模型和负载特征调参。
- **对比方法运行条件受限**：ShadowKV、InfiniGen、FreeKV 无法支持所有配置（部分 OOM），对比图的部分区域缺少对照数据点，可视化的完整性略有欠缺。
- **未评估更长上下文（>32K）的实际极限**：虽然在分析中提到生产环境平均 32.7K 的编码 agent 上下文，但实验主要集中在 16K/32K；对 64K/128K 乃至更长上下文的真实负载验证不够。

- **精度评估中的小样本问题**：推理 benchmark 每问题仅 4–8 个样本（pass@k），在 1–2 个百分点的精度差异上统计显著性不足，结论可能存在噪声；LongBench v2 的加权平均也掩盖了不同长度区间上的性能波动。
- **未报告端到端能耗与成本**：论文以吞吐量和延迟作为主要指标，未涉及能耗、TCO（总拥有成本）或 PCIe/网络带宽占用率的量化成本核算，对于"以内存为中心"的系统设计而言，缺少一份完整的性价比评估。
- **Draft 模型自身的资源开销未被计入**：EAGLE-3 draft 模型需要额外的模型权重与计算开销，论文未将其 KV 缓存、权重内存占用及前向计算成本纳入系统总资源账本；在部分低并发场景下，draft 前向的开销可能抵消甚至超过预取收益。

## 9. 未来工作与开放问题

- **将预取信号与投机解码合流**：论文明确将"draft token 同时用于投机解码与 KV 预取"列为未来工作。若二者合并，draft 前向的计算开销可由投机解码本身加速的 token 数来摊销，预期端到端吞吐提升将显著超过当前报告的 1.2–2.1×。
- **支持前缀缓存（prefix caching）**：当前原型未实现，而生产推理服务中 prefix caching 是标配；将 OasisKV 与前缀缓存结合（如对共享前缀的 KV 块直接命中缓存、跳过预取）是自然的工程扩展，也能让论文中的 TTFT 分析模型落地为实测。
- **自适应参数调节**：fetch cap、KV 预算、块大小等超参目前依赖人工设定，且最优值与模型规模、上下文长度、并发度耦合。未来需要一套自动调参机制（如根据实时 HBM 余量、PCIe 队列深度动态调整 Top-K 与 cap），以适应生产环境的负载波动。
- **更长上下文的极限验证**：生产环境编码 agent 的平均上下文已达 32.7K，且正快速向 128K–1M 演进。OasisKV 需要验证在 64K/128K 乃至更长上下文下的预测精度、流水线稳态与内存行为，探索 KV 稀疏性与注意力丢精度之间的边界。
- **多节点、多租户扩展**：PD 分离实验仅在两个节点间进行，网络拓扑单一；在多跳网络、多租户共享带宽、QoS 约束下，网络预取的调度策略与背压机制仍是开放问题。

## 10. 总结与点评

- **总体定位**：OasisKV 是面向"内存墙"问题的一次系统性设计，其核心贡献不是单一的缓存策略或预测算法，而是将"高质量预取信号（SD draft token）+ 异步流水线 + 有界工作集 + 分层的 KV 生命周期管理"整合为一个可在 vLLM 中落地的完整系统。它强调了一个重要观点——在 HBM 容量受限时，**关键不是减少注意力计算量，而是减少 KV 缓存的驻留与迁移字节数**。
- **对比同类工作**：ShadowKV、FreeKV 等方案本质上是"按需 fetch"——直到注意力真正需要某个 KV 块时才从 CPU/远程取回，取回延迟暴露在关键路径上；OasisKV 则是"预测性 prefetch"——用未来 token 的前瞻信息提前预取，配合三层流水线隐藏传输延迟。这一差异使其在 PCIe 带宽有限时能以更高的 fetch 提前量换取吞吐收益。
- **亮点判断**：最值得借鉴的设计有两点——其一是"用投机解码的副产品（draft query）作为训练无关的预测信号"，这一思路成本极低、可迁移性强，未来若与投机解码本身合流将产生更强的协同效应；其二是"head-wise 映射 + 每层局部同步"的工程架构，将稀疏化从算法概念落地为可维护、可并行的系统原语。
- **适用边界**：OasisKV 的最优收益出现在 KV 缓存占主导的场景——长上下文、大 batch、PD 分离、带宽受限，即"内存墙"最严重的部署形态。对于短上下文、小 batch、KV 占比低的场景，稀疏化管理引入的额外开销可能超过收益（论文中 Qwen3-235B 低并发下 TPOT 高于 dense 即为例证），因此并非普适替代 dense attention。
- **一句话结论**：OasisKV 通过将投机解码的前瞻信息转化为 KV 预取信号、并以异步流水线将预取完全移出关键路径，在保持精度（≤0.7 点损失）的前提下实现了 1.2–2.3× 的吞吐提升，为"以内存为中心"的 LLM 推理系统提供了一个高完成度的参考设计；其真正的价值上限，取决于未来能否与投机解码、前缀缓存等机制深度融合，将预取开销从"必要成本"变为"附带收益"。
