## 摘要
混合注意力大语言模型将全注意力与循环线性注意力相结合，以降低长上下文推理成本，但其自回归解码仍然受内存限制。树形推测解码提供了一条有吸引力的加速路径，但现有的树推测系统是围绕全注意力模型的键值缓存设计的。在混合模型上，它们逐分支遍历循环层，并为每个提议节点物化完整状态，导致验证延迟和瞬时内存随树和批处理大小扩展不佳。我们提出了 Bole，一种内核-运行时协同设计，为混合注意力大语言模型实现高效的树推测。Bole 将线性注意力循环转化为树形封闭形式，并通过资源高效的 GPU 内核实现，并行验证所有提议节点，将线性注意力树验证加速 3.4--7.7 倍。它无损地将推测状态更新编码为 token 级因子，并且仅重建采样后选中的状态，将瞬时状态内存减少 82--99 倍，并释放 GPU 容量用于 KV 缓存。它与广泛部署的生产级大语言模型服务引擎 SGLang 的集成，将高效状态管理与针对完整混合前向传播校准的批级验证预算相结合。在四个模型、两个 GPU 平台和多样化数据集上，Bole 实现了高达自回归解码离线解码吞吐量 4.72 倍、以及最强树推测基线 2.03 倍的性能。在在线智能体工作负载下，与最强树推测基线相比，它分别将 TTFT 和 TPOT 降低了高达 67.6% 和 49.9%。

## Abstract
Hybrid-attention large language models combine full attention with recurrent linear attention to reduce long-context inference costs, yet their autoregressive decoding remains memory-bound. Tree speculative decoding offers an attractive acceleration path, but existing tree-speculation systems are designed around the key--value caches of full-attention models. On hybrid models, they traverse recurrent layers branch by branch and materialize a full state for every proposal node, causing verification latency and transient memory to scale poorly with tree and batch sizes. We present Bole, a kernel--runtime co-design that enables efficient tree speculation for hybrid-attention LLMs. Bole transforms the linear-attention recurrence into a tree-structured closed form and realizes it with a resource-efficient GPU kernel, verifying all proposal nodes in parallel and accelerating linear-attention tree verification by 3.4--7.7$\times$. It losslessly encodes speculative state updates as token-level factors and reconstructs only the state selected after sampling, reducing transient state memory by 82--99$\times$ and freeing GPU capacity for KV caches. Its integration into SGLang, a widely deployed production LLM serving engine, couples efficient state management with a batch-wide verification budget calibrated to the complete hybrid forward. Across four models, two GPU platforms, and diverse datasets, Bole delivers up to $4.72\times$ the offline decode throughput of autoregressive decoding and up to $2.03\times$ that of the strongest tree-speculative baseline. Under online agent workloads, it reduces TTFT and TPOT by up to $67.6%$ and $49.9%$, respectively, over the strongest tree-speculative baseline.

### 1. 论文的核心问题与整体含义

- **背景**：混合注意力大语言模型（Hybrid-attention LLMs）将全注意力（full attention）与循环线性注意力（recurrent linear attention）相结合，以降低长上下文推理成本。代表性模型包括 Qwen3.5 和 Kimi Linear。然而，其自回归解码仍是内存受限的，每个输出 token 都需要一次模型调用。
- **核心问题**：树形推测解码（Tree Speculative Decoding）是加速推理的有效手段，但现有系统（如 SpecInfer、DeFT、SGLang 的树推测路径）都是围绕全注意力模型的 KV 缓存设计的，无法高效处理混合模型中循环线性注意力的序列依赖特性。
- **三大瓶颈**：
  - **串行递归**：线性注意力层需要按父子关系逐个节点传播状态，树越大，线性层在目标前向传播中占比越高（8 节点时仅 4%，64 节点时达 27%）。
  - **状态爆炸**：为每个提议节点物化完整状态快照，内存消耗随树大小和批次大小线性增长。例如在 Qwen3.5-122B-A10B 上，8 个 32 节点的请求需消耗 36 GiB 瞬态内存。
  - **验证容量不确定**：目标模型可高效验证的 token 数量取决于 GPU 型号和当前批次，不同平台的最优预算不同（A100 为 128 节点，GB10 为 256 节点）。
- **解决思路**：本文提出 **Bole**，一个内核-运行时协同设计（kernel-runtime co-design），通过将线性注意力循环转化为树结构闭式解、实现并行验证，并将瞬态状态以 token 级因子编码以按需重建，从而让混合注意力模型也能享受高效的树推测解码。

### 2. 论文提出的方法论

#### 2.1 核心思想：树结构化闭式解

论文推导了线性注意力树验证的精确闭式解（Theorem 1）：

**O = DₚQS_pre + C(I + G)⁻¹D_β(V − DₚKS_pre)**

该公式等价于顺序执行，但不需要逐节点递归遍历，也不需要为每个节点维护完整的中间状态。它通过三个结构性步骤（引理）建立：

- **Lemma 1（路径因子化状态）**：每个节点的状态可分解为共享的"树前状态"贡献加上沿祖先路径的校正项之和。
- **Lemma 2（祖先掩码校正系统）**：将所有校正向量堆叠为线性系统 (I + G)U = R，其中 G 仅在严格祖先关系处非零（严格下三角）。
- **Lemma 3（深度有界幂零性）**：由于树的深度 d 有限，G^(d+1) = 0，因此 (I + G)⁻¹ 可以展开为有限多项式 Σ(−G)^m，实现了精确且固定的计算步骤。

#### 2.2 值分块并行验证内核（Value-Tiled Parallel Verification Kernel）

- 将值维度 d_v 分为多块（tiles），每个 CTA（线程块）处理一个值块，覆盖完整树的节点范围。
- 因子 G、C 由单独的 producer 构造一次，供所有值块 CTA 复用，避免重复计算。
- CTA 内使用片上有限 Neumann 展开（finite-Neumann propagation）完成 d 轮递归传播，全过程在片上完成，不写回 HBM。
- 通过二维资源分块（值维度 b_v 和键维度 b_k）平衡 CTA 并行度与片上资源占用。

#### 2.3 因子化状态生命周期（Factorized State Lifecycle）

- 每个活跃请求仅保留一个不可变的已提交状态 S_pre。
- 候选分支用 token 级因子 (P, K, U) 表示，空间复杂度从 Θ(H·d_k·d_v·T) 降为 Θ(T·H·(d_k+d_v+1))，节省 82–99 倍内存。
- 采样确定接受路径后，通过一次批量矩阵乘法 S_new = P_a·S_pre + (D_a·K_a)ᵀU_a 重建唯一需要持久化的状态。拒绝分支自动消失，无需回滚。

#### 2.4 硬件感知的批量验证预算（Hardware-Aware Verification Budget）

- 离线对每种执行配置（模型、GPU、批次区间、KV 长度区间、树模板）校准目标前向传播的延迟曲线，选定满足 T_ver(N|c) ≤ (1+ε)·T_dec(c) 的最大节点数作为验证预算。
- 运行时按 drafter 的累积路径概率全局选择最值得验证的节点，保证每个请求所选节点保持前缀连通性。

- **端到端吞吐量**：Bole 相对 SGLang-AR 的几何平均加速为 2.74 倍，相对最强推测基线为 1.26 倍。A100 峰值加速达 3.62 倍（vs SGLang-AR）、1.41 倍（vs SGLang-Tree）；GB10 峰值达 4.72 倍（vs SGLang-AR）、2.03 倍（vs 最强基线）。
- **内存节省**：Bole 将瞬态状态内存减少 82–99 倍（每个请求从数 GB 降至数十至数百 MB），在 122B TP4 部署中释放 6.26–18.58 GiB 供 KV 缓存使用，使 27B 模型在批次 8 下不再 OOM（两个基线均 OOM）。

### 7. 优点

- **理论严谨性**：闭式解推导严谨（三个引理逐步构造，最终定理保证与顺序执行代数上精确等价），且明确了并行度的来源（nilpotency 和祖先掩码结构）。
- **系统设计完整性**：从算法推导到 GPU 内核实现再到生产引擎（SGLang）集成形成完整链条，同时覆盖了内核执行效率和运行时状态管理两个层面。
- **内存效率创新**：利用"只重建被接受的状态"这一采样后信息，从本质上消除了推测分支带来的瞬态内存需求，逻辑简洁且效果显著。
- **硬件自适应**：通过离线校准捕获平台相关的计算/内存边界（roofline 效应），避免了一个固定的树预算在不同 GPU 上造成性能退化的问题。
- **服务引擎集成质量高**：支持连续批处理、CUDA Graphs、GPU-resident 状态提交等功能，保证了生产环境的实用性。

### 8. 不足与局限

- **模型覆盖局限**：实验仅使用 Qwen3.5 系列模型，尽管 Gated DeltaNet 是主流混合注意力架构之一，但未验证对其他线性注意力变体（如 Mamba2、其他 gated 循环架构）的通用性。
- **drafter 单一性**：仅使用 MTP 头作为 drafter，未测试与 EAGLE-2/3 等更复杂 drafter 的组合效果。不同 drafter 的树质量分布差异可能影响闭环收益。
- **长上下文压力测试不足**：实验未明确报告极长上下文（如 100K+ token）下的表现，而线性注意力状态管理在长上下文场景中的优势/劣势尚需进一步验证。
- **校准成本未知**：离线校准（profiling）的时间开销未被量化。如果模型/平台数量大或配置频繁变化，校准成本可能成为部署负担。
- **单框架集成**：虽然论文宣称内核可移植，但所有实验都在 SGLang 中完成，未展示在其他生产引擎（如 vLLM）中的即插即用效果。
- **TP 扩展范围有限**：仅在 122B 模型上进行了 TP4 测试，未探索更大规模（如 TP8/TP16）下因子化状态提交和跨层调度的扩展性。
