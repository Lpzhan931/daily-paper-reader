## 摘要
推测解码仅在草稿续文通过目标模型验证时加速大语言模型推理。诸如DSpark之类的半自回归草稿器通过一次骨干前向传播预测整个令牌块，并用轻量级马尔可夫头进行细化。然而，DSpark将此块解码为单链，因此早期不匹配会使剩余后缀失效，并限制大草稿块的优势。我们表明，DSpark已学习的条件结构可以在无需重新训练或额外骨干传播的情况下支持多个父一致的续文。我们引入了父条件草稿树（PCTree），它利用预训练的马尔可夫头为每个具体父节点分别对替代子节点评分，并将固定的验证预算分配给最可能的路径。这将DSpark的线性草稿转换为树，同时保留其单遍并行骨干。在Qwen3-{4B,8B,14B}和九个基准测试中，在B=7时，相对于匹配的DSpark，测得的自回归（AR）解码加速增益范围为3.1%至29.5%。在B=16的Qwen3-4B GSM8K上，PCTree将平均接受长度从9.41提高到11.16，三次运行的平均AR加速从6.14倍提高到6.60倍。这些结果表明，父条件分支可以将半自回归草稿器中已存在的条件能力通过仅推理变更转化为端到端推理增益。

## Abstract
Speculative decoding accelerates LLM inference only when drafted continuations survive target-model verification. Semi-autoregressive drafters such as DSpark predict an entire token block with one backbone forward and refine it with a lightweight Markov head. However, DSpark decodes this block as a single chain, so an early mismatch invalidates the remaining suffix and limits the benefit of large draft blocks.   We show that the conditional structure already learned by DSpark can support multiple parent-consistent continuations without retraining or additional backbone passes. We introduce Parent-Conditioned Drafting Tree (PCTree), which uses the pretrained Markov head to score alternative children separately for each concrete parent and allocates a fixed verification budget to the most probable paths. This converts DSpark's linear draft into a tree while preserving its one-pass parallel backbone.   Across Qwen3-{4B,8B,14B} and nine benchmarks, at $B{=}7$, measured speedup gains over autoregressive (AR) decoding, relative to matched DSpark, range from $3.1\%$ to $29.5\%$. On Qwen3-4B GSM8K at $B{=}16$, PCTree increases mean acceptance length from $9.41$ to $11.16$ and three-run mean AR speedup from $6.14{\times}$ to $6.60{\times}$. These show that parent-conditioned branching can turn conditional capacity already present in a semi-autoregressive drafter into end-to-end inference gains through an inference-only change.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：自回归解码是 LLM 推理的主要延迟瓶颈，推测解码（Speculative Decoding）通过轻量草稿模型生成多个未来 token，再由目标模型一次前向验证，以打破逐 token 串行瓶颈。
- **已有工作的不足**：
  - 链式草稿（如 EAGLE）脆弱：早期任一 token 被拒，后续整个后缀全部作废，形成"拒绝级联"（rejection cascade）。
  - 并行草稿器（如 DFlash 的块扩散）虽能一次前向产出整块，但缺乏块内依赖建模，接受长度快速衰减。
  - 树形草稿（如 EAGLE-2、DDTree）能对冲早期错配，但自回归草稿器建树需要多次额外前向，并行草稿器建树（DDTree）则使用与父节点无关的逐位置分布，可能拼出"局部不连贯"路径（如 B→C 虽各自高概率但条件上不合理）。
- **本文核心观察**：DSpark 这类"并行骨干 + 轻量 Markov 头"的半自回归草稿器，其预训练 Markov 头已经蕴含父条件分布信息，但原始解码器只用它构造单条链，没有利用其分支能力。
- **整体含义**：仅通过推理期策略改动（无需重训练、无需额外骨干前向），就能把 DSpark 的线性草稿转化为树形草稿，释放其已有的条件建模容量，提升接受长度并带来端到端加速。

## 2. 方法论：PCTree（Parent-Conditioned Drafting Tree）

**核心思想**：利用 DSpark 预训练的 Markov 头，为每个具体父 token 独立重打分共享的骨干 logits，在固定验证预算下保留最可能的多个路径，构成前缀封闭的草稿树。

**关键技术细节**：

- **共享骨干 logits**：一次并行骨干前向（anchor token + B−1 个 mask 占位）得到各位置基础 logits L = (L₀, …, L_{B−1})，各位置相互独立。
- **父条件重打分**：对每个前沿父节点 p，计算 z_d(p) = L_d + Markov(p)，得到该父节点专属的子代分布 log π_d(·|p)，再取该分布下的局部 top-k 子节点。
- **批量 Markov 调用**：同一深度 d 的所有前沿父节点打包成一次批处理 Markov 调用（batch size b_d ∈ {1,…,k}），保持 B 个顺序阶段的架构不变，只是批大小从 1 变为 k。
- **逐层剪枝（beam-like frontier pruning）**：每层展开后，只保留联合路径得分最高的 k 个节点作为下一层前沿，避免指数膨胀；候选节点总数上界为 k + (B−1)k²。
- **联合路径得分**：s(c) = Σ 沿路径各边 log π(v|u)，子节点得分 = 父节点得分 + 该边 log 概率。
- **全局预算选择**：B 层展开后，按联合得分降序、深度升序、稳定 ID 的规则取全局 top-N 节点；由于得分沿路径单调不增，所选节点天然构成前缀封闭树。
- **单次树验证**：将所选节点打包为扁平 token 张量 + 检索索引 + 祖先掩码（ancestor-only tree attention mask），用标准贪心树验证规则一次目标前向完成验证。
- **退化关系**：k=1 时算法退化为 DSpark 原链式解码。

**算法流程（文字版）**：
1. 一次并行骨干前向得到 L；
2. 初始化 frontier = {root}，pool = {root}；
3. 对 d = 0 到 B−1：批量 Markov 调用计算每个前沿父节点的条件分布 → 展开局部 top-k 子节点并更新联合得分入池 → 按得分保留 top-k 作为下一层前沿；
4. 从池中取全局 top-N 节点；
5. 生成草稿 token、检索索引与树掩码，一次目标前向验证。

## 6. 主要结论与发现

- **接受长度全面提升**：PCTree 在全部模型-任务配对中提升 τ；B=7 时相对 DSpark 的端到端 AR 加速提升 3.1%–29.5%。
- **代表性指标**：Qwen3-4B GSM8K 上 B=16 时 τ 从 9.41 升至 11.16，三次运行平均 AR 加速从 6.14× 升至 6.60×（+7.5%）；HumanEval +11.8%，MT-Bench +15.1%。
- **父条件重打分机制有效**：Shared-Markov 树 τ=10.225，PCTree τ=11.156（+9.1%），说明增益来自"对具体父节点条件化"而非单纯分支；PCTree 还将验证节点利用率从 29.88% 提到 32.90%，每样本轮数从 24.7 降至 22.6。
- **分支因子饱和**：k 从 1→2 获得大部分增益，k=4 已基本饱和，k=8 无进一步收益。
- **验证预算非单调**：增大 N 提升接受长度但收益递减，AR 加速在 B=7 时峰值在 N=32、B=16 时在 N=64，之后因树构建/验证开销抵消收益而回落。
- **成本收益权衡成立**：分支使每轮 Markov+树成本上升（如 B=16 时 1.09→5.24 ms/轮），但每样本轮数从 26.8 降至 22.6，更少轮次抵消额外草稿开销，净效果端到端加速。

## 7. 优点

- **训练无关（training-free）**：直接用预训练 Markov 头，零重训练成本，纯推理策略改动，实用性强。
- **保持并行骨干**：仍为一次骨干前向 + B 次顺序 Markov 调用，只增大 Markov 批大小，架构不变。
- **成本可控**：前沿批大小以 k 为上界，候选数上界 k+(B−1)k²，避免指数膨胀。
- **机制归因清晰**：精心设计的 Shared-Markov 对照将"分支"与"父条件"两个因素解耦，科学严谨。
- **分析全面**：覆盖接受长度、端到端加速、每轮成本分解、生存曲线、验证节点利用率、预算扫描、k 消融、重复性检验，多个角度互相印证。
- **诚实的不确定性披露**：明确标注单次运行配置与重复运行配置，未夸大统计置信度。
- **通用启示**：提出"并行块 + 廉价顺序细化"这类草稿器可经推理策略支持树验证的一般性观点。

## 8. 不足与局限

- **草稿质量上界**：树质量受限于预训练草稿分布，训练无关的扩展策略无法修复系统性弱的 Markov 头。
- **剪枝启发式风险**：逐层 top-k 剪枝是启发式，可能丢弃在节点预算 N 下全局最优的路径。
- **开销敏感性**：过大的 k 或 N 在小型目标或显存紧张设备上会使树构建和验证注意力开销不可忽略。
- **硬件/精度依赖**：加速增益依赖硬件、精度、注意力 kernel 与树预算，BF16/H20 上的结论未必迁移到其他环境。
- **实验覆盖不足**：主表大部分配置仅单次运行，统计置信度有限；B=16 草稿为内部训练，外部无法直接复现；外部树基线（DFlash+DDTree）因检查点不同无法严格对比。
- **未覆盖场景**：未报告服务端批处理吞吐、不同精度（如 FP8/INT8）、更长输出上限或不同目标系列（如非 Qwen）下的表现。
