## 摘要
投机解码通过将草稿生成与目标验证交错进行，缓解了自回归大型语言模型（LLM）中顺序生成的延迟。然而，现有的并行草稿后端在长序列上往往遭受快速的精度下降，导致验证期间的高拒绝率和次优的墙上时钟加速。我们观察到草稿错误并非均匀分布，而是通常源于局部高不确定性标记，这些标记破坏了后续生成轨迹的稳定性。受这种标记错误模式的启发，我们提出了CURE，一种预算感知的动态修复树，旨在修复不确定性焦点处的错误，而不会产生过高的树验证开销。具体来说，我们的方法利用预测置信度余量动态定位块并行草稿中的候选错误标记，仅在这些脆弱节点上扩展有界修复路径，并采用一种新颖的修复重新同步机制在验证后重新对齐草稿状态。在代码生成基准（HumanEval、MBPP和LiveCodeBench-lite）和数学推理基准（GSM8K）上的评估表明，与无修复的并行基线相比，CURE将平均接受长度提高了4.2-7.5%，相对于仅目标解码实现了2.66-3.49倍的端到端加速。此外，我们提供了一个与标准并行草稿框架兼容的即插即用修复模块。我们还刻画了草稿计算与验证效率之间的权衡。

## Abstract
Speculative decoding mitigates the latency of sequential generation in autoregressive Large Language Models (LLMs) by interleaving draft generation with target verification. However, existing parallel drafting backends often suffer from rapid accuracy degradation over long horizons, leading to high rejection rates during verification and suboptimal wall-clock speedups. We observe that drafting errors are not uniformly distributed but typically stem from localized high-uncertainty tokens that destabilize downstream generation trajectories. Motivated by this token error pattern, we propose CURE, a budget-aware dynamic repair tree designed to repair errors at uncertainty focal points without incurring prohibitive tree-verification overheads. Specifically, our method uses predictive confidence margins to dynamically locate candidate error tokens within a block-parallel draft, expands bounded repair paths only at these fragile nodes, and employs a novel repair resynchronization mechanism to realign draft states post-verification. Evaluations on code-generation benchmarks (HumanEval, MBPP, and LiveCodeBench-lite) and mathematical reasoning benchmark (GSM8K) demonstrate that CURE increases the average accepted length by 4.2-7.5% over parallel baselines without repair, translating to an end-to-end speedup of $2.66-3.49\times$ over target-only decoding. Furthermore, we provide a plug-and-play repair module compatible with standard parallel drafting frameworks. We also characterize the trade-off between draft compute and verification efficiency.

## 1. 核心问题与整体含义（研究动机和背景）

- 大型语言模型（LLM）自回归生成需逐 token 顺序解码，受内存带宽瓶颈限制，推理延迟较高。投机解码（Speculative Decoding）通过一个轻量草稿模型生成候选 token，再由目标模型并行验证，从而在不改变输出分布的前提下加速生成。
- 近年出现的**块并行草稿（Block-Parallel Drafting）**能够单次前向生成多个 token，避免了顺序草稿开销，但它存在结构性脆弱：草稿模型独立/粗粒度预测时，单个局部低置信度 token 错误会导致标准前缀验证拒绝整个后续草稿序列，即使后续 token 本身正确，即“错误传播级联”。
- 作者观察到，草稿错误**并非均匀分布**，而是集中在少数“**不确定性焦点（Uncertainty Focal Points, UFPs）**”上。如果能在这些局部位置进行修复，就能防止级联拒绝，同时避免对所有位置做昂贵的全树扩展。
- CURE 的核心含义是：将候选树扩展从“全树/均匀扩展”改为“**预算约束下的局部修复**”，在保持并行草稿低开销的同时，用很小的额外验证成本换回更多被错误截断的有效 token，从而提升端到端墙钟加速比。

## 2. 方法论

### 2.1 核心思想
- CURE 构建一个“**预算感知的动态修复树**”：在完成一次块并行草稿后，利用草稿模型给出的 top-1/top-2 对数概率边际，动态定位低置信度 token 位置，仅在这些脆弱位置扩展少量替代分支，生成一棵稀疏候选树；目标模型用 Tree Attention 一次验证所有路径；如果修复路径胜出，则通过“缓存重同步”把草稿模型的状态对齐到获胜路径。

### 2.2 关键技术细节
- **不确定性边际（Predictive Margin）**：对草稿块中位置 \(i\)，计算 \(m_i = \ell_{i,1} - \ell_{i,2}\)，其中 \(\ell_{i,1}\)、\(\ell_{i,2}\) 为 top-1 与 top-2 对数概率。\(m_i\) 越小，表示该位置越不确定。
- **动态分支分配**：将边际归一化为不确定性 \(u_i = \mathrm{clip}(1 - m_i/s, 0, 1)\)，再映射到分支数 \(b_i = \mathrm{clip}(\mathrm{round}(b_{\min} + u_i(b_{\max} - b_{\min})), b_{\min}, b_{\max})\)，其中默认 \(b_{\min}=1, b_{\max}=5\)；默认边际阈值 \(\tau_{\text{margin}}=1.0\)。
- **候选树构造**：对于每个选定的 UFP，保留原前缀，用 top 替代 token 替换脆弱 token，并重新采样后续后缀；共享前缀的路径自然合并为树。默认配置每块最多修复一个低边际位置，以控制验证开销。
- **单次验证**：目标模型通过 Tree Attention 同时验证默认路径 branch 0 和所有修复路径，选出最长接受前缀 \(\pi^* = \arg\max_{\pi \in T} a(\pi)\)。
- **缓存重同步（Cache Resynchronization）**：若 branch 0 获胜，则草稿缓存保持不变；若修复分支获胜，则把获胜路径的 token 重放到草稿模型的 KV 缓存中，使后续草稿状态与目标验证结果一致。这是避免状态漂移、防止后续验证失效的关键机制。
- **训练无关**：CURE 不修改草稿模型或目标模型，不需要重训或微调，属于即插即用推理层模块。

### 2.3 形式化问题
- 将修复问题建模为有约束的候选树优化：
  \[
  \pi^* = \arg\max_{\pi \in \Pi} a(\pi) \quad \text{s.t.} \quad V(\Pi) \le V_{\max}
  \]
  其中 \(a(\pi)\) 是路径接受长度，\(V(\Pi)\) 是树的总节点数（验证预算）。有效生成速率正比于 \(\frac{E[a(\pi^*)]+1}{C_d + C_v(\Pi)}\)，因此只有当接受长度增益超过树验证开销时，修复才带来正加速。
