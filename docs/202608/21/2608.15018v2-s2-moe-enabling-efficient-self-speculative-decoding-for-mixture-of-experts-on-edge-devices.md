## 摘要
由于内存和带宽的严格限制，在边缘设备上部署大型语言模型（LLMs）进行推理具有挑战性。虽然推测解码和混合专家（MoE）已被提出用于提高推理效率，但简单地将它们组合往往会导致过多的验证开销和较差的专家重用，从而限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE 通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿和目标执行。在 llama.cpp 中实现，S2-MoE 在边缘设备上的多种 MoE 模型和数据集上，相比标准自回归解码实现了高达 5.3 倍（平均约 2.0 倍）的加速。代码可在 https://github.com/angerybob/S2-MoE 获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama$.$cpp, S2-MoE achieves up to $5.3\times$ speedup (about $2.0\times$ on average) over standard autoregressive decoding across diverse MoE models and datasets on edge devices. Code is available at https://github.com/angerybob/S2-MoE.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题**：在资源受限的边缘设备上部署大语言模型（LLM）推理面临严重的内存带宽瓶颈。投机解码和混合专家（MoE）分别通过提高输出密度和降低参数密度来提升推理效率，但两者在边缘场景下无法有效结合。

**具体挑战**：
- **验证开销过大**：MoE 模型中，被验证的草稿 token 可能激活不同的专家，导致参数复用率低，验证成本高；被拒绝的草稿 token 触发的专家激活成为冗余开销。
- **专家复用不足**：相邻 token 在 MoE 中常被路由到不同专家，并行验证时加剧参数访问量。
- **草稿保真度受限**：轻量化草稿模型与目标模型之间存在上下文漂移和误差累积，降低接受率。

**整体意义**：打破直接组合投机解码与 MoE 的低效困境，为边缘端 MoE 模型推理提供了一套实用的加速方案。

## 2. 论文提出的方法论

**总体框架**：S²-MoE 是一个基于自投机解码（self-speculative decoding）的 MoE 推理加速框架，包含三个互补组件：

### 2.1 路由感知自适应投机扩展（Routing-aware Adaptive Speculative Expansion）
- **动机**：token 级置信度无法反映 MoE 中专家级验证开销，两个置信度相近的候选 token 可能触发完全不同的专家激活集合，导致验证成本差异显著。
- **核心公式**：
  - 期望收益：\( B_i = p_i \cdot T_{AR} \)，其中 \( p_i \) 为前缀置信度，\( T_{AR} \) 为单步自回归延迟。
  - 边际验证成本：\( \Delta C_{ver}(i|S) = |E_i \setminus \bigcup_{j \in S} E_j| \cdot T_{exp} \)，即新引入的专家数乘以单专家验证延迟。
  - 效用分数：\( U_i = \frac{B_i}{\Delta C_{ver}(i|S) + C_i^{draft}} \)。
- **策略**：贪心扩展效用 \( U_i \geq 1 \) 的候选，兼顾接受概率与验证成本，代替固定宽度或纯置信度剪枝。

### 2.2 重用感知专家门控（Reuse-aware Expert Gating）
- **动机**：MoE 中并行验证的 token 往往激活不同的专家，参数复用率低。
- **方法**：
  1. **跨 token 专家重要性聚合**：用 token 置信度加权聚合各 token 的专家门控 logits，得到 \( g_e = \sum_{b \in B} w_b \cdot \ell_{b,e} \)。
  2. **全局偏好专家选择**：选择 top-cap 个专家作为重用奖励集合 \( E^* \)。
  3. **软路由偏置**：向门控 logits 注入 \( \lambda_b \cdot 1[e \in E^*] \) 的偏置，偏置幅度由 top-1 与 top-(k+1) 专家的分差决定，促使低置信度 token 向已有激活专家靠拢，而不显著扰动高置信度 token 的路由决策。
- **实现**：轻量级 fused CUDA kernel，开销可忽略。

### 2.3 上下文对齐自投机解码（Context-aligned Self-speculative）
- **动机**：草稿与目标模型各自维护上下文会导致误差跨迭代累积，KL 散度随解码步数快速增大。
- **方法**：草稿与目标共享同一 KV Cache——目标先处理提示并建立缓存，草稿直接读取共享上下文；草稿的 KV 更新视为临时，验证前回滚，仅被接受的 token 提交到共享缓存，从而将误差限制在单步投机内。

## 6. 论文的主要结论与发现

1. **S²-MoE 显著加速 MoE 推理**：在 Jetson Orin 上实现 1.3×–5.3× 加速（平均约 2.0×），在 RTX 4090 上实现 1.2×–2.9× 加速，且内存越紧约束下优势越明显。
2. **朴素自投机基线在边缘 MoE 场景下常失败**：ES/LS 多半低于自回归速度，表明 MoE 下验证开销抵消了草稿生成收益。
3. **S²-MoE 优于 EAGLE3 和 Cascade**：EAGLE3 的性能随模型族波动很大，Cascade 的历史效用决策不如 S²-MoE 的当前步路由感知决策稳定。
4. **路由感知扩展有效**：AE 在保持接受长度的同时显著降低有效验证成本，改进了接受-验证的帕累托前沿。
5. **重用门控在不损失质量的前提下提升参数复用**：专家复用率最多提升 33%，任务准确率与目标模型无系统性差异（PPL 比约 1.01，Top-1 一致率 > 89%）。
6. **上下文对齐是基础性组件**：将草稿误差限制在当前投机步内，接受率最大提升 79%（GSM8K / OLMoE）。
