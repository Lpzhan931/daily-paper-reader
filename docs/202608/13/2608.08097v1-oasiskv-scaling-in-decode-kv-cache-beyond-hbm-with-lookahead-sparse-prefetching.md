## 摘要
大语言模型（LLM）推理服务日益受到内存而非算力的制约。随着长上下文和长程推理工作负载日益普及，键值（KV）缓存在LLM令牌生成（即解码）过程中主导了内存占用和内存流量。尤其是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批处理大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储从HBM中解耦，缓解HBM容量压力。由于解码时的注意力天然稀疏，OasisKV仅在HBM中保留最相关令牌的KV条目用于注意力计算。我们观察到，利用投机解码（SD）生成的前瞻令牌，可以提前准确预测未来的重要令牌。OasisKV采用高效的注意力后台流水线来识别重要的KV块，然后从高容量内存层（例如主机或远程内存）预取这些块，并在下一步解码使用之前暂存于HBM中。我们基于vLLM实现了OasisKV。在2,048令牌的KV预算下，前瞻预测足够准确，使精确度保持在完整注意力的0.7个百分点以内。这使得OasisKV能够将稀疏性转化为吞吐量增益：在推理工作负载上，相对于稠密vLLM达到1.69倍的吞吐量，精确度损失仅0.1个百分点；在多GPU长上下文服务中，吞吐量提升高达2.1倍。在预填充-解码分离场景下，OasisKV在接收每个请求时KV占用减少6.5至9.7倍，解码节点主机内存占用比完整KV传输减少2.2至2.6倍，同时吞吐量约为稠密模式的2倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

## 一、论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：大语言模型（LLM）推理服务正从"算力受限"转向"内存受限"。随着长上下文和agentic（智能体）工作负载（如Web-use、computer-use、coding agents）的普及，KV缓存（Key-Value Cache）在解码（decode）阶段同时主导了HBM（高带宽内存）的容量占用和内存流量，导致HBM容量成为制约推理批处理大小和系统吞吐量的核心瓶颈。这一现象被作者称为"内存墙"（memory wall）。
- **背景困境**：现代LLM推理中，一个32B类GQA模型在FP16/BF16下，每token的KV占用约256 KiB；在平均上下文32.7K的生产级coding-agent场景下，单个请求需要约8.6GB的KV缓存，即便80GB HBM全部留给KV也只能容纳约9个并发请求。这严重限制了decode吞吐。
- **已有方案的不足**：
  - *稀疏注意力*（Sparse Attention）：减少KV读取，但不减少HBM中保留完整KV缓存所需的容量。
  - *KV检索*（KV Retrieval）：将完整KV放在主机内存，按需取回GPU，但取回延迟落在解码关键路径上。
  - *KV预取*（KV Prefetch）：通过预测提前取回KV，但未解决预测精度、生产级引擎集成、跨层内存管理等问题。
- **论文的整体含义**：OasisKV提出一种以内存为中心的LLM推理系统设计，将KV缓存与HBM解耦，利用解码期注意力天然稀疏的特性，只将最相关token的KV块保留在HBM中，并通过推测性解码（Speculative Decoding）的lookahead tokens高精度预测未来需要的KV块，从而将稀疏性转化为系统级的吞吐增益。

## 二、论文提出的方法论

### 1. 核心思想

- **解耦存储**：将完整KV缓存存储在CPU DRAM（本地场景）或远程内存（PD分离场景），GPU HBM仅保留一个受约束的稀疏工作集。
- **Lookahead预测**：利用推测性解码（如EAGLE-3）产生的draft tokens（前瞻令牌）作为未来KV访问模式的预测信号，避免训练额外的预测器。
- **异步流水线预取**：通过独立的CUDA流和后台worker，将预测、选择和传输三个阶段的延迟隐藏在解码计算之后。

### 2. 关键技术细节

#### （1）Look-ahead Attention（前瞻注意力）

- **低开销前景计算**：前景forward pass同时处理普通token和draft token的QKV投影。draft query在普通token的稀疏KV上传播，与真实next-token query的top-K集合在每层一致率达到98.74%（最低98.2%）。
- **压缩键摘要**：采用Quest风格的per-block min/max pooling摘要（每个block存两个向量），使draft query可以扫描全部KV块并实现全局top-K排序，而无需恢复全部键向量。摘要空间仅占完整KV缓存大小的1/16。
- **共享执行**：同一层中，normal query和draft query在一个注意力内核中同时处理，减少权重读取和KV读取开销。

#### （2）完全异步的后台流水线

- 三层独立阶段：Top-K预测 → KV选择 → KV传输，每层各自维护独立的压缩键、resident映射和KV存储。
- **跨层重叠**：层l+1的Top-K预测、层l的KV选择、层l−1的KV传输可并发执行，使用CUDA事件维护层内依赖。
- **层局部同步**：在第t+1步，每层的注意力只等待本层在第t步发出的KV传输完成，而非等待所有层。
- 流水线稳态周期：$T_{pipe} = \max\{T_{pred}, T_{select}, T_{transfer}\} \le \Delta_{prefetch}$，受最慢阶段限制。

#### （3）Delta选择与上限回收策略（Capped Eviction）

- **Delta选择**：先求预测集与resident集的交集，已在GPU的块不产生PCIe流量；对resident集中不在预测集的块，按"最后被选择时间"排序，选择最久未被选中的块作为驱逐目标。
- **上限策略**：每个KV头每步最多采纳$\mathbf{C}$个新块（通过fetch ratio控制），限制每层传输最多为$\mathbf{C}$个块/KV头，无论预测top-K集合变化多大，从而保证传输量在PCIe带宽可承载的decode步预算内。

#### （4）KV管理：Head-wise Mapping

- **问题**：PagedAttention的原始页表假设每个page内的head内容属于同一逻辑块，而head-wise稀疏解码要求不同head可以维护不同的稀疏块集合。
- **解决方案**：在原有的GPU和CPU页表之上增加一层head-wise逻辑到逻辑的映射表。GPU和CPU各自维护物理KV池，通过head-wise映射记录"哪个CPU逻辑块存储在哪个GPU逻辑块中"，不同head可独立更新，无需跨GPU同步。

#### （5）远程部分获取（Remote Partial Fetching）

- **部分传输（Partial Transfer）**：PD分离场景下，prefill节点额外执行一步解码，用产生的query选出每层每head的top-K集合，形成union后，只传输该union KV块、压缩键缓存和draft KV状态。当请求完成时，prefill节点先将其完整KV暂存到prefill节点的host DRAM，然后立即释放prefill GPU页。
- **网络预取（Network Prefetch）**：解码过程中top-K选择会漂移，解码节点host内存中缺失的块通过网络从prefill节点取回，取回操作与前景注意力重叠，所有块跨网络最多传输一次。

## 六、论文的主要结论与发现

### 1. 吞吐量显著提升

- **真实推理工作负载（AIME24）**：Qwen3-8B上1.69×稠密vLLM吞吐（2083 vs 1235 tok/s），准确性损失仅0.1点；Qwen3-235B上1.20×（1546 vs 1283 tok/s）。
- **合成负载**：Qwen3-8B在16K上下文下最高2.1×（1398 vs 676 tok/s）；Qwen3-235B在TP8下最高1.9×（1102 tok/s）。
- **PD分离**：吞吐量2.1−2.3×于稠密vLLM。

### 2. KV传输与内存占用大幅下降

- PD分离下，每个请求的KV传输量减少6.5×（24K）至9.7×（32K）；结合解码期间的drift后，总传输量减少1.33×−1.50×（fetch cap为0.05时可减少1.9×−2.2×）。
- 解码节点主机内存占用减少2.2×（24K）至2.6×（32K）。

### 3. 准确性保持

- 在2,048 token的KV预算下，整体准确性在完整注意力的0.7个百分点以内。
- LongBench v2上：Qwen3-8B偏差−0.4点和Llama-3.1-8B偏差−0.6点。
- 长输出推理（平均pass@8）：相对本堆栈全注意力仅−0.66点；AIME24和AIME25的pass@8与全注意力持平。

### 4. PCIe带宽是瓶颈而非注意力计算

- Fetch-cap消融显示：fetch ratio从0.01放宽到fetch-all，吞吐量从2178跌至824 tok/s（2.6×下降），但准确性仅从74.9升至77.4。这证明decode吞吐受PCIe带宽约束，而非注意力计算。

### 5. 预测准确性

- Lookahead预测的top-K集合与真实next-token query的top-K集合在每层一致率≥98.2%（平均98.74%），可靠性远高于previous-token proxy（平均83.9%）。

## 七、优点

1. **创新性设计**：结合推测解码的draft tokens作为KV的预测信号，将SD从"加速生成"的单一用途扩展为"内存管理"的信号源，实现训练无关的高精度预测。
2. **生产级集成**：在vLLM上实现，而非原型框架；支持多GPU（TP）和PD分离，具有实际部署价值。
3. **系统层面的联合优化**：将预取重叠、lookahead预测和精度-吞吐权衡作为联合系统优化问题，而非独立组件。Delta选择、capped eviction、head-wise mapping等都是系统性设计。
4. **鲁棒性设计**：layer-local同步、完全异步的流水线，每层只需等待自己需要的KV传输完成，而非一次等待所有层。
5. **远程部分获取（RPF）**：将稀疏性原则贯穿到网络传输和主存层级，而非只作用于GPU HBM层级，避免了全量KV跨网络带来的TTFT和DRAM瓶颈。
6. **较严谨的评估方法论**：准确性对比坚持"同堆栈内相对全注意力锚点"原则，避免跨堆栈比较带来的偏差；对fetch cap这一关键超参进行了系统消融。
7. **丰富的可分析数据**：提供了PCIe带宽与decode吞吐的Roofline分析、draft预测的层间一致性分析、跨头差异分析、每个token的KV占用与带宽预算等有洞察力的分析。

## 八、不足与局限

1. **未联合投机解码收益**：OasisKV当前强制拒绝draft token，未将其接受率转化为额外的端到端加速收益，仅利用draft作为lookahead信号，浪费了SD本身的生成加速潜力。作者已在future work中提及此限制。
2. **精度在高稀疏度下下降明显**：当K从128降至64时，AIME24准确性下降3−6.9个百分点，说明top-K预算存在一个可靠性下限，不能无限缩小。
3. **前缀缓存尚未集成**：论文对RPF在前缀缓存生效时的TTFT收益仅为解析模型分析，缺少实际测量。此外，vLLM中的Automatic Prefix Caching与OasisKV的架构如何集成尚未验证。
4. **RPF的prefill侧DRAM占用未优化**：当前原型将完整KV保留在prefill节点的host DRAM直到请求完成，虽然解码节点DRAM占用降低，但prefill节点仍承担完整KV的暂存成本（文中承认可将prefill节点DRAM扩展到远程内存服务器或SSD层）。
5. **通用性有待验证**：评估局限于Qwen3和Llama-3.1系列，未覆盖更多主流模型架构（如DeepSeek、Gemma等）；对draft model的依赖意味着没有公共EAGLE-3 draft head的模型无法直接使用本方法。
6. **模拟/分析部分的比例**：图2的TPOT分析和图15的TTFT分析均为ro

roofline/解析模型（analytical model）层面的理论分析，而非端到端系统实测。这类分析能够直观展示带宽、容量与延迟的理论边界，但未计入调度开销、内核启动延迟、内存分配粒度、PCIe/NIC 队列竞争、CUDA graph 切换等真实系统因素，因此实际部署中的收益可能略低于理论预测。

此外，原论文还存在若干未展开的边界情况：例如 top-K 预测的一致性虽在平均层面达到 98.74%，但论文未报告在长尾 token、重复文本或格式敏感输出上的最坏情况一致率；fetch cap 对准确性的影响仅通过 AIME24 单项任务验证，未在 LongBench 等长输入任务上做对应消融；PD 分离实验仅报告了一个 batch size（192 请求），未充分展示请求规模变化对网络预取重叠效率的影响。

总体而言，OasisKV 在"内存墙"问题上提出了一套训练无关、以预测驱动的 KV 缓存管理系统，通过 lookahead 稀疏预测、异步流水线预取和远程部分获取，将 KV 稀疏性贯穿 GPU HBM、本地 DRAM 与远端内存/网络三级存储体系，为长上下文 LLM 推理的吞吐优化提供了一条系统级、可部署的技术路径。其核心贡献在于论证了"解码过程中 KV 缓存无需全部驻留 HBM"，并借助投机解码的 draft tokens 实现了高精度、零训练成本的未来 KV 访问预测。后续若能联合投机采样收益、补齐前缀缓存支持、扩展至更多模型架构（如 DeepSeek、Gemma 等），该方法有望进一步缩小与稠密注意力堆栈在准确性与端到端延迟上的差距，并成为 KV 缓存分层管理的通用范式。
