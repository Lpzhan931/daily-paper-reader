## 摘要
投机解码通过草拟多个令牌进行并行验证来加速大语言模型推理，其效率关键取决于每一轮解码所选择的投机长度。现有的动态投机方法通过估计将有多少令牌被接受来选择投机长度，这对于按顺序生成令牌的自回归草稿模型是合理的。然而，最近一波基于扩散的草稿模型以极低的草稿成本并行生成候选块，将关键问题从“生成多少个令牌”转变为“生成的令牌中有多少值得验证”。因此，我们将动态投机长度选择重新表述为期望加速优化问题，并推导出一个边际准则，仅当接受增益超过额外验证成本时才扩展投机序列。基于该准则，我们开发了\textit{LibraSpec}，一种无需训练且即插即用的算法，利用草稿模型置信度分数迭代确定投机长度。理论上，我们证明LibraSpec单调收敛于最优投机长度。在六个目标模型、三种基于扩散的投机解码方法以及数学、编程和聊天基准上的实验表明，在贪心采样和随机采样设置下均取得了一致的改进，相对于基线进一步提升了$0.5\sim1.5\times$，并且相对于自回归解码实现了高达$8.49\times$的加速。

## Abstract
Speculative decoding accelerates large language model inference by drafting multiple tokens for parallel verification, with efficiency critically determined by the speculative length selected at each decoding round. Existing dynamic speculation methods select the speculation length by estimating how many tokens will be accepted, which is reasonable for autoregressive drafters that generates tokens sequentially. The recent wave of diffusion-based drafters, however, generates candidate blocks in parallel at substantially lower drafting cost, shifting the key question from how many tokens to generate to how many generated tokens are worth verifying. We therefore reformulate dynamic speculative-length selection as expected-speedup optimization and derive a marginal criterion that extends the speculative sequence only when its acceptance gain outweighs the additional verification cost. Building on this criterion, we develop \textit{LibraSpec}, a training-free and plug-and-play algorithm that iteratively determines the speculative length using drafter confidence scores. Theoretically, we prove that LibraSpec monotonically converges toward the optimal speculative length. Experiments across six target models, three diffusion-based speculative decoding methods, and math, coding, and chat benchmarks show consistent improvements under both greedy and sampling settings, achieving a further $0.5\sim1.5\times$ improvement over baselines and up to $8.49\times$ speedup over autoregressive decoding.

# LibraSpec 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- 投机解码（Speculative Decoding）通过轻量级草稿模型生成多个候选 token，再由目标模型并行验证，从而减少自回归解码的串行瓶颈。
- 解码效率高度依赖每一轮选择的**投机长度（speculative length）**：太短会浪费并行验证能力，太长则会在早期拒绝时浪费目标模型计算。
- 已有动态投机长度方法主要面向**自回归草稿模型**，其核心是“预测下一轮会被接受多少个 token”，并据此决定生成长度。
- 但最新一代**扩散式草稿模型**（如 FastdLLM、DFlash、DDTree）能够以极低的草稿成本**并行生成整个候选块**，使得核心问题从“生成多少 token”转变为“生成的 token 中有多少值得验证”。
- 因此，论文指出：仅估计期望接受长度不足以决定是否延长投机前缀，因为即使新增 token 很可能被接受，其带来的收益也可能无法覆盖额外验证成本。
- 整体含义：论文将动态投机长度选择重新定义为**期望加速比优化问题**，提出无需训练、即插即用的 LibraSpec，用边际收益准则动态决定每轮提交多少个候选 token 进行验证。

## 2. 方法论

### 核心思想

- 在扩散式投机解码中，草稿代价相对验证代价很小，因此加速比近似为：  
  \[
  \eta_d \approx \frac{\tau_d L_{\text{target}}}{T_{\text{verify}}}
  \]
  其中 \(\tau_d\) 是被接受的 token 数，\(L_{\text{target}}\) 是目标模型单 token 延迟，\(T_{\text{verify}}\) 是验证延迟。
- 于是，投机长度选择的关键就变成：**每增加一个候选 token，其带来的接受增益是否超过对应的验证成本**。

### 关键技术细节

- 论文定义了“单次有益调整（Single Beneficial Adjustment）”：从长度 \(d\) 调整到 \(d'\)，当且仅当期望加速比 \(E[\eta_{d'}] > E[\eta_d]\)。
- 推导出边际准则：扩展投机序列时，新增片段的边际收益必须高于当前平均收益；截断时，被删除后缀的边际收益必须低于当前平均收益。
- 在前缀接受（prefix acceptance）假设下，位置 \(i\) 之后的边际期望增益可展开为：
  \[
  E[\tau_{i:d'}] = \sum_{j=i}^{d'} \prod_{k=i}^{j} p_k
  \]
  其中 \(p_k\) 是第 \(k\) 个 token 的接受概率。
- 论文给出位置级上界：
  \[
  d' \le \epsilon_i,\quad \epsilon_i = \max\left\{ d' \in \mathbb{Z} \mid d' < \frac{T_{\text{verify}}^i}{\tau_i c} \sum_{j=i}^{d'} \prod_{k=i}^{j} p_k + i \right\}
  \]
  并证明 \(d' = \min_i \epsilon_i\) 是单次有益调整的充分条件。
- 进一步证明期望加速比是投机长度的**单峰函数**，因此不断应用有益调整会**单调收敛到全局最优投机长度区间**。
- 实际部署时，目标模型接受概率 \(p_i\) 在验证前未知。论文在“草稿模型置信度 \(q_i\) 与目标接受概率 \(p_i\) 近似校准”的假设下，用草稿置信度代替未知概率，并引入 \(d_{\max}\) 控制校准随投机距离增长而恶化的影响。
- 同时用超参数 \(\alpha\) 吸收验证延迟、接受数等运行时因素，控制调整的激进程度。

### 算法流程（LibraSpec）

1. 生成一个大小为 \(n\) 的初始草稿块。
2. 以默认块大小作为当前投机长度 \(d\)，并维护草稿预算 \(B\)。
3. 循环执行以下步骤直到 \(d \ge d_{\max}\)：
   - 根据当前已生成草稿 token 的置信度计算 \(\epsilon^*=\min_i \epsilon_i\)；
   - 若 \(\epsilon^* \le d\)，则将长度设为 \(\epsilon^*\) 并停止；
   - 否则，扩展长度至 \(\epsilon^*\)，并消耗草稿预算；
   - 若预算不足，则额外生成新的草稿块。
4. 提交最终确定的 \(d\) 个 token 给目标模型验证。
5. 为减少振荡，最多执行一次回退操作。

## 6. 主要结论与发现

- 扩散式草稿模型改变了动态投机长度选择的优化目标：应由“预测接受长度”转为“直接优化收益-验证成本权衡”。
- LibraSpec 能有效追踪 oracle 最优投机长度：在案例研究中，与 oracle 的绝对偏差仅 2.78 个 token，而静态长度偏差为 9.48 个 token。
- 在 FastdLLM 上，相比原始静态长度，LibraSpec 在 Qwen2.5-7B/14B/32B 上平均加速提升约 1.25×~1.57×，显著优于 FailFast 和 G4-style。
- 在 DFlash 和 DDTree 上，LibraSpec 额外带来约 0.39×~0.69× 的平均加速提升。
- 启用 thinking mode 的 Qwen3 推理模型上，LibraSpec 仍能获得额外约 0.27×~0.30× 的加速，相对提升约 9%~11%。
- 总体最高加速比达到 **8.49×**，相对自回归解码。
- 方法对超参数 \(\alpha\) 和 \(d_{\max}\) 均表现稳健；较强草稿模型可采用更激进的扩展策略。

## 7. 优点

- **问题建模准确**：将动态投机长度选择从“接受长度预测”重构为“期望加速比优化”，更贴合扩散式草稿模型的特点。
- **理论完备**：给出必要/充分条件、单峰性证明和有限步收敛性保证，不只是经验调参。
- **即插即用、无需训练**：不需要额外预测器、不需要训练，可无缝集成到 FastdLLM、DFlash、DDTree 等主流扩散式投机解码方法中。
- **成本低**：仅利用草稿模型已有置信度，并用草稿预算机制减少额外草稿调用。
- **实验扎实**：覆盖多种模型规模、多种任务、两种解码设置，且与多种动态长度基线对比，结论一致。

## 8. 不足与局限

- 依赖“草稿模型置信度与目标接受概率校准良好”的假设。若置信度随投机距离快速退化，LibraSpec 的效果会受限。
- 理论分析建立在简化设定上：假设无限长草稿序列、验证代价随位置线性增加等；实际系统中有 I/O、调度、批处理等因素，需通过超参数 \(\alpha\) 和 \(d_{\max}\) 近似补偿。
- 主要面向扩散式草稿模型，对自回归草稿模型不是核心适用场景。
- 实验中最大模型为 30B-A3B 的 MoE 模型，未包括更大稠密模型；对长上下文、多请求并发等真实服务场景的验证不足。
- 未报告详细算力消耗、延迟分解之外的端到端系统开销，实际部署中的工程成本需要进一步评估。
- 超参数 \(\alpha\) 和 \(d_{\max}\) 需要按草稿模型单独选择，尽管论文表明敏感度较低，但仍非完全免调参。
