## 摘要
在边缘设备上部署大型语言模型（LLM）进行推理，由于严重的内存和带宽限制而具有挑战性。尽管已经提出了推测解码和混合专家（MoE）来提高推理效率，但简单地将它们结合往往会导致过度的验证开销和较差的专家重用，限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展来减少冗余验证，通过重用感知的专家门控来提高验证效率，并通过共享上下文来对齐草稿和目标执行。在llama.cpp中实现，S2-MoE在边缘设备上的各种MoE模型和数据集上，相对于标准自回归解码实现了高达5.3倍（平均约2.0倍）的加速。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama.cpp, S2-MoE achieves up to 5.3x speedup (about 2.0x on average) over standard autoregressive de?coding across diverse MoE models and datasets on edge devices.Code is available at https://github.com/angerybob/S2-MoE.

## 1. 核心问题与整体含义（研究动机与背景）

- **边缘部署痛点**
  - 在边缘设备上部署 LLM 推理面临严重的内存和带宽限制，推理负载通常 batch size 很小，甚至退化为单 batch 执行，参数复用有限，主要瓶颈是内存带宽。
  - 吞吐量可分解为：吞吐 =（输出密度 × 带宽）/ 参数密度（单位每次迭代生成 token 数 × 带宽 / 每迭代访问参数量）。提升效率需提高输出密度或降低参数密度。

- **两种已有技术路线**
  - **推测解码（SD）**：用轻量草稿模型生成多个 token，再由目标模型并行验证，提高"输出密度"。
  - **MoE 稀疏化**：每次只激活部分专家参数，降低"参数密度"。

- **核心矛盾**
  - 将 SD 与 MoE 简单结合在边缘场景并不有效：草稿 token 可能激活不同专家，导致验证阶段参数复用度低、验证开销剧增；被拒绝的草稿 token 仍会触发大量"冗余专家激活"，使验证代价不成比例地放大，乃至抵消加速收益。
  - 现有置信度剪枝依赖 token 级置信度，但 token 级置信度与专家级验证开销无关，难以适用 MoE 场景。

- **现有方案的不足**
  - 外部草稿模型难以做到轻量且对齐（MoE 模型本身激活参数少，压缩空间小）。
  - 自推测解码虽能提升草稿与目标对齐度，但在 MoE 上仍受困于：草稿保真度有限、拒绝 token 的冗余验证、专家参数复用差。
  - Cascade 等基于历史信息的策略在路由不稳定时可靠性下降。

- **S2-MoE 的定位**
  - 提出一个面向边缘 MoE 推理的自推测解码框架，同时解决：草稿/目标上下文对齐、验证开销感知的扩展、专家参数复用三大问题。

## 2. 方法论：核心思想、关键技术细节

S2-MoE 由三个互补组件构成：

### （1）路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）

- **目标**：在构建草稿树时，不只看置信度，而是以"验证效用"（utility）为准则进行自适应扩展，避免高开销低收益的候选分支。
- **期望收益公式**：
  - 草稿候选 token i 的接受概率估计为前缀置信度：$p_i = \prod_{j=1}^{k} p_{i,j}$。
  - 期望收益 $B_i = p_i \cdot T_{AR}$，其中 $T_{AR}$ 为目标模型单步自回归解码平均延迟。
- **路由感知代价估计**：
  - 定义边际验证代价 $\Delta C_{ver}(i|S) = \left| E_i \setminus \bigcup_{j \in S} E_j \right| \cdot T_{exp}$，其中 $E_i$ 为 token i 预测激活的专家集合，$S$ 为已选扩展 token 集合，$T_{exp}$ 为每增加一个专家带来的延迟。
  - 总扩展代价 $C_i = \Delta C_{ver}(i|S) + C_i^{draft}$。
- **效用函数**：$U_i = B_i / C_i$，只有当 $U_i \geq 1$ 时才接受扩展候选，即收益覆盖代价才继续扩展。
- **关键洞察**：利用草稿阶段的路由信号预测目标路由（论文通过实验验证了该相关性），从而在验证前即可估计验证开销。

### （2）复用感知专家门控（Reuse-aware Expert Gating）

- **问题**：MoE 中相邻 token 倾向于激活不同专家，并行验证时专家复用率低，内存参数访问量大。
- **方法**：
  1. **跨 token 专家重要性聚合**：按 token 置信度加权聚合各 token 的专家 logits：$g_e = \sum_{b \in B} w_b \cdot \ell_{b,e}$，使高置信度 token 的专家偏好获得更大权重。
  2. **全局偏好专家选择**：选择 $E^* = \text{TopCap}(\{g_e\})$，限制 bias 的专家数 cap ≥ k，保留原始 top-k 可选择性。
  3. **软路由偏置**：对每个 token 的 gating logits 施加 $\ell'_{b,e} = \ell_{b,e} + \lambda_b \cdot \mathbb{1}[e \in E^*]$，$\lambda_b$ 由 top-1 专家与第 k+1 位专家分数差距决定，以促进复用偏好专家而不破坏主导路由决策。
  4. **高效融合实现**：实现为轻量级 fused CUDA kernel，开销可忽略。

**效果**：在示例中将验证激活专家数从 6 降到 4，低置信度 token 更易被引导到复用专家，高置信度 token 保持原有选择。

### （3）上下文对齐的自推测解码（Context-aligned Self-speculative Decoding）

- **问题**：轻量草稿在独立上下文推理时，预测误差会逐步累积，导致草稿与目标分布发散（KL 散度随解码步数快速增大）。
- **方法**：
  - 草稿与目标模型共享同一份 KV cache。
  - 目标模型先处理 prompt 建立 KV cache；草稿直接读取共享上下文。
  - 草稿产生的 KV 更新视为临时状态，验证前回滚；只有被接受的 token 才提交到共享 KV cache。
- **效果**：草稿误差被限制在单个推测步骤内，不会跨迭代传播，显著提升接受率。

## 6. 主要结论与发现

- **端到端加速**：S2-MoE 在 Jetson Orin 上实现 1.3×–5.3× 加速，RTX 4090 上 1.2×–2.9× 加速，平均约 2.0×。
- **优于基线**：
  - 一致优于 AR、ES、LS、EAGLE-3、Cascade。
  - 内存越紧，S2-MoE 优势越明显——验证对冗余专家激活和参数复用越敏感。
- **三组件互补**：CA+AE+RG 三种机制各自贡献增量提升，组合效果最佳。
- **上下文对齐显著提升草稿保真度**：GSM8K 上 OLMoE 接受率提升达 79%。
- **路由感知扩展优于固定宽度和置信度剪枝**：在保持相当接受长度的情况下明显降低有效验证代价，扩展了帕累托前沿。
- **复用感知门控提升专家复用率**：DeepSeek 上复用率改善 26%–33%。
- **质量几乎无损**：
  - 各模型任务准确率差异小且无系统性偏差。
  - LongBench 结果与原始模型相当。
  - WikiText-2 上 PPL 比 1.012–1.013，Top-1 一致率 > 89%。
