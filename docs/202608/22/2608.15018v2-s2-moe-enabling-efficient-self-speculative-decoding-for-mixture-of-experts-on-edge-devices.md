## 摘要
由于严重的内存和带宽限制，在边缘设备上部署大型语言模型（LLM）进行推理具有挑战性。虽然推测解码和混合专家（MoE）已被提出用于提高推理效率，但简单地将它们结合往往会带来过大的验证开销和较差的专家重用，限制了它们在内存受限的边缘环境中的有效性。在这项工作中，我们提出了S2-MoE，一种用于边缘设备上MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿和目标执行。在llama.cpp中实现，S2-MoE在多种MoE模型和边缘设备数据集上相比标准自回归解码实现了最高$5.3\times$的加速（平均约$2.0\times$）。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama$.$cpp, S2-MoE achieves up to $5.3\times$ speedup (about $2.0\times$ on average) over standard autoregressive decoding across diverse MoE models and datasets on edge devices. Code is available at https://github.com/angerybob/S2-MoE.

# S2-MoE：在边缘设备上实现高效的混合专家自推测解码

## 1. 核心问题与研究动机

- **背景挑战**：在边缘设备（如 Jetson Orin）上部署大规模语言模型（LLM）面临严重的内存和带宽约束，推理吞吐量受制于内存带宽（memory-bound），参数访问成为瓶颈。
- **两个独立的加速方向各有局限**：
  - **推测解码（SD）** 通过轻量草稿模型一次生成多个 token，再用目标模型并行验证，虽然提高了“输出密度”，但在 MoE 场景下失效——不同草稿 token 可能激活不同专家，导致参数重用率低、验证开销大。
  - **混合专家（MoE）** 通过稀疏激活降低了“参数密度”，但专家路由的不确定性使推测解码的验证过程变得极其昂贵，最终可能抵消甚至逆转两者的收益。
- **核心矛盾**：在 MoE 模型中，朴素结合 SD 与 MoE 会导致：(i) 被拒绝 token 触发大量“冗余专家激活”；(ii) 相邻 token 之间专家复用率低；(iii) 轻量草稿模型与目标模型的上下文漂移导致误差累积，接受率下降。
- **总结**：需要一个同时保障草稿保真度、低冗余验证和强参数复用的 SD-MoE 融合方案，这正是 S²-MoE 的出发点。

## 2. 方法论：S²-MoE 框架

S²-MoE 在 llama.cpp 中实现，包含三个互补的组件，共同解决 MoE 场景下推测解码的效率瓶颈。

### 2.1 路由感知的自适应推测扩展（Routing-aware Adaptive Speculative Expansion）

- **核心思路**：基于“效用分数”动态决定是否扩展某个推测候选，效用分数同时考虑接受概率（收益）和验证代价（成本）。
- **关键公式与逻辑**：
  - 期望收益 \( B_i = p_i \cdot T_{AR} \)，其中 \( p_i \) 为前缀置信度（前缀所有 token 置信度的乘积），\( T_{AR} \) 为一次自回归解码步的平均延迟。
  - 边际验证成本 \( \Delta C_{ver}(i|S) = |E_i \setminus \cup_{j \in S} E_j| \cdot T_{exp} \)，其中 \( E_i \) 为 token \( i \) 激活的专家集合，\( T_{exp} \) 为单个额外专家的延迟开销（可由运行时测量或离线 profiling 获得）。
  - 效用分数 \( U_i = B_i / (\Delta C_{ver}(i|S) + C_i^{draft}) \)，只有当 \( U_i \geq 1 \) 时才纳入扩展。
- **优势**：相比固定宽度扩展或仅基于置信度的剪枝，该方法显式建模了 MoE 特有的验证成本差异（即使置信度相似的候选，若激活不同专家，验证成本可能差异巨大），实现了更优的接受率–验证代价权衡。

### 2.2 复用感知的专家门控（Reuse-aware Expert Gating）

- **核心思路**：在验证阶段，通过软路由偏置（soft routing bias）促进不同草稿 token 间的专家参数复用，提升验证的计算密度。
- **实现步骤**：
  1. **跨 token 专家重要性聚合**：以 token 置信度 \( w_b \) 为权重，将 MoE 层的门控 logits 按 \( g_e = \sum_b w_b \cdot \ell_{b,e} \) 聚合成专家重要性分数（高置信度 token 的偏好权重更高）。
  2. **全局优选专家选择**：通过 TopCap 选择一组优选专家集合 \( E^* \)，限制偏置范围，在保持原 top-\( k \) 路由结构的同时鼓励复用。
  3. **软路由偏置注入**：对每个 token 的门控 logits 添加偏置 \( \lambda_b \cdot \mathbb{1}[e \in E^*] \)，其中 \( \lambda_b \) 与 top-1 专家和 top-(k+1) 专家的分数差成正比，从而只影响“边界专家”，不扰乱主导路由决策。
- **关键特性**：训练无关（training-free），且因为偏置只增加跨 token 的专家重叠，实际验证成本不会超过 Sec 4.1 的估计值（成本估计是保守的）。已实现为轻量级融合 CUDA kernel。

### 2.3 上下文对齐的自推测解码（Context-aligned Self-speculative Decoding）

- **核心思路**：草稿模型与目标模型共享同一个 KV 缓存，避免独立上下文导致的误差跨迭代累积。
- **实现细节**：
  - 目标模型先处理 prompt 建立 KV 缓存，草稿模型在推测阶段直接读取共享上下文。
  - 草稿模型的 KV 更新被视为“临时状态”，验证前回滚；只有被接受的 token 才写入共享缓存。
- **效果**：草稿误差被限制在单个推测步内，不会跨迭代传播，显著提升了长文本生成中的草稿保真度与接受率。

## 6. 主要结论与发现

- **性能提升显著**：S²-MoE 在 Jetson Orin 上实现 1.3×–5.3× 加速（平均约 2.0×），在 RTX 4090 上实现 1.2×–2.9× 加速，且稳定优于所有基线。

- **朴素自我推测（ES/LS）常常不如自回归**：验证了“低专家复用 + 高冗余验证”是 MoE 场景下 SD 失效的根本原因。
- **EAGLE-3 不稳定**：在部分模型/任务上有效但波动大；S²-MoE 无需训练，却能在所有模型上取得更稳定、更高的加速比；Cascade 因依赖历史信号，在路由不稳定时收益有限。
- **质量几乎无损**：任务准确率差异小且无系统性方向；LongBench 分数接近原模型；PPL ratio 保持在 1.012–1.013，Top-1 一致率 > 89%，表明路由偏置带来的输出扰动是**有界且不显著的**。

## 7. 优点与亮点

1. **问题定位精准**：从吞吐量分解公式（Output Density / Parameter Density · BW）切入，明确指出 MoE 场景下推测解码的两个本质瓶颈——冗余验证和专家复用不足，并逐一设计解决方案，逻辑链条清晰。
2. **训练无关且即插即用**：无需训练草稿头或微调模型，仅依赖推理时的路由信号和轻量 offline profiling，部署成本低、兼容性好。
3. **组件设计具有协同性**：路由感知扩展（控制验证规模）与复用感知门控（提高验证密度）在数学上自洽——门控偏置只会增加专家重叠，使扩展阶段的成本估计保持保守，形成良性反馈。
4. **系统实现完整**：在 llama.cpp 中实现专家级参数卸载（非层级），适配 Jetson 统一内存和 RTX 4090 分离内存两种架构；代码开源，可复现性好。
5. **实验验证扎实**：模型覆盖面广（从 6.7B 到 116.8B）、硬件条件多样（三种内存预算 + 离散 GPU）、质量评估多维度（任务准确率 + 长文本 + 分布一致性），充分证明了方法的有效性和泛化能力。

## 8. 不足与局限

1. **依赖路由预测质量**：自适应扩展的效用计算依赖草稿阶段的路由信号预测目标路由（Opportunity 1），虽然实证显示相关性较高，但在路由极其不稳定的层或异常输入下，成本模型可能失真，影响决策质量。
2. **复用感知门控是有损的**：虽然质量损失被控制在很小范围，但它仍是目标路由的“受控近似”而非无损变换。在严格需要逐 token 输出与原始模型完全一致的场景中，该方法不适用。
3. **GPT-OSS 评估缺失分布一致性指标**：论文因 GPT-OSS 训练方式特殊（Harmony 格式）而省略了 PPL/KL 等指标，这虽然合理，但也意味着对该模型的质量论证不如其他模型完整。
4. **未与其他 MoE-offloading 系统深度对比**：论文指出现有 MoE offloading 工作没有公开的 llama.cpp 兼容实现，因此只评估了自己的卸载策略，缺少与 SOTA 卸载策略（如缓存调度、预取算法）的公平对比。
5. **实验平台覆盖有限**：只测试了 NVIDIA 硬件（Jetson 和 RTX 4090），未覆盖 CPU-only 边缘设备、移动端 NPU 或其他厂商硬件，结论的外推范围受限。
6. **无训练开销不等于完全免费**：成本模型的校准（\( T_{exp} \)、\( T_{AR} \)）虽然轻量，但仍需针对每种硬件平台做离线 profiling，部署新设备时有一定初始化成本。
