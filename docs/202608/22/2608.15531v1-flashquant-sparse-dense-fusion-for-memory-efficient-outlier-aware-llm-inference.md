## 摘要
低位量化降低了大型语言模型（LLM）推理的内存占用和计算成本。然而，高幅度的异常值权重可能引发显著的量化误差并降低模型精度。异常值感知量化通过以高精度保留异常值、量化其余权重来解决此问题，从而形成低位稠密GEMM路径和高精度稀疏SpMM路径。现有实现尽管共享激活和输出，却在不同GPU内核中执行这些路径，从而错失了算子内复用的机会，并导致冗余的全局内存访问。这种低效在内存受限的解码工作负载中尤为明显。我们提出了FlashQuant，一种用于异常值感知W4A16解码的内容共享执行框架。FlashQuant将稠密GEMM与稀疏异常值SpMM路径融合到单个GPU内核中，使得异构计算之间能够在芯片上复用激活和输出块。它引入了三项关键技术：稀疏-稠密分块，将异常值处理与稠密GEMM块对齐；Tile-COO异常值编码，实现高效稀疏访问并减少共享内存存储体冲突；以及流水线调度，使计算与数据移动重叠。实验表明，FlashQuant降低了异常值处理开销，相比cuBLAS BF16实现了2.74倍至4.18倍的加速，相比最强非融合异常值感知基线最高取得1.53倍加速。

## Abstract
Low-bit quantization reduces the memory footprint and computational cost of large language model (LLM) inference. However, high-magnitude outlier weights can induce substantial quantization errors and degrade model accuracy. Outlier-aware quantization addresses this issue by retaining outliers in high precision while quantizing the remaining weights, resulting in a low-bit dense GEMM path and a high-precision sparse SpMM path. Existing implementations execute these paths in separate GPU kernels, despite their shared activations and outputs, thereby missing opportunities for intra-operator reuse and incurring redundant global-memory accesses. This inefficiency is particularly pronounced in memory-bound decoding workloads. We propose FlashQuant, a content-sharing execution framework for outlier-aware W4A16 decoding. FlashQuant fuses the dense GEMM and sparse outlier SpMM paths into a single GPU kernel, enabling on-chip reuse of activation and output tiles across heterogeneous computations. It introduces three key techniques: sparse-dense tiling, which aligns outlier processing with dense GEMM tiles; Tile-COO outlier encoding, which enables efficient sparse access and reduces shared-memory bank conflicts; and pipelined scheduling, which overlaps computation with data movement. Experiments show that FlashQuant reduces outlier-processing overhead, achieving $2.74\times - 4.18\times$ speedup over cuBLAS BF16 and up to $1.53\times$ speedup over the strongest unfused outlier-aware baseline.

# FlashQuant 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大型语言模型（LLM）在推理时面临严峻的内存与计算压力。低位权重量化（如 INT4）是降低内存占用和带宽成本的主流手段，但高幅度**异常值权重（outlier weights）** 经低比特量化后会引入显著重构误差，导致模型精度下降。
- **异常值感知量化**：通过将少量（如 1%–3%）高幅度异常值以高精度（BF16）保留、其余权重低比特量化，在精度与效率间取得良好权衡。例如对 LLaMA3-8B 进行 INT4 量化时，保留 1% 异常值可将 WikiText2 困惑度从 6.896 降至 5.979。
- **现有瓶颈**：该策略将矩阵乘法分解为两条路径——低位稠密 GEMM（量化权重）+ 高精度稀疏 SpMM（异常值权重）。现有系统（如 Marlin + Sputnik/cuSPARSE）将二者作为**独立 GPU 内核**执行，导致同一激活矩阵被重复加载、部分输出被单独写回全局内存，造成**冗余全局内存访问**。
- **关键洞察**：在内存受限的自回归解码场景（小 batch、带宽瓶颈）中，即使异常值占比很小，其额外访存开销也可能造成不成比例的延迟增长。GEMM 与 SpMM 共享相同输入与输出，存在**算子内数据复用的潜在空间**。
- **整体含义**：FlashQuant 通过将两条计算路径融合为单一 GPU 内核，消除冗余访存，使异常值感知量化在保持精度的同时更接近纯量化推理的效率上限，为内存高效 LLM 推理提供了新的执行范式。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想
- **内容共享融合（Content-Sharing Fusion）** ：将低比特稠密 GEMM 与高精度稀疏 SpMM 融合进单个 GPU 内核，使两种异构计算路径在统一的平铺执行空间中协同调度，实现激活与输出的片上复用，避免分离内核带来的冗余全局内存流量。

### 2.2 三大关键技术

#### ① 稀疏-稠密分块（Sparse-Dense Tiling）
- 建立统一的跨 CTA / warp / thread 三级分块层级，使稀疏异常值路径与稠密 GEMM 路径在**共享的激活与输出块**上对齐：
  - **CTA 级别**：每块 CTA 加载一次激活块到共享内存，GEMM 与 SpMM 路径共同消费；部分结果在片上累加后才写回。采用 **Stream-K 工作分配**改善不同 SM 间的负载均衡。
  - **Warp 级别**：稠密路径专用 warp 使用 Tensor Core MMA；稀疏路径专用 warp 使用 CUDA Core 执行不规则乘累加，同时为稀疏路径分配额外 warp 以提升延迟隐藏。
  - **Thread 级别**：共享内存中激活矩阵采用带 8 元素交错（swizzle）的行主序布局，减少 bank 冲突。

#### ② Tile-COO 异常值编码
- 面向融合执行设计的稀疏格式，包含三个数组：`tile_indptr`（分块偏移）、`bucket_info`（桶偏移与大小）、`packed_outliers`（打包的异常值/索引）。
- 特点：
  - 异常条目与 GEMM 分块边界精确对齐；
  - 每 4 个异常值打包为一组进行**向量化解码**；行/列索引用 uint8 表示，值用 bfloat16；
  - 相较 CSR，显著降低元数据开销（Tile-COO：`(N_tile+1)×4 + N_B×4 + nnz×4` 字节 vs CSR：`(K+1)×4 + nnz×12` 字节）。
- **两阶段稀疏重排序**：
  - **列重排序**：按非零数降序 + 贪心堆调度，平衡各 warp 桶的负载；
  - **元素重排序**：依据共享内存 bank 分组将桶内元素交错排列，减少子 warp 间 bank 冲突（示例中冲突次数从 4 降到 1）。

#### ③ 流水线调度（Pipelined Execution）
- 四阶段流水线 + 双缓冲：全局内存加载 → 寄存器暂存 → 反量化与异常值解码 → Tensor Core/CUDA Core 计算，实现数据搬运与计算重叠，隐藏全局内存延迟。

### 2.3 计算分解公式
原始分解：`Y = X·W ≈ X·dequant(W_Q) + X·W_O`，其中 `W_Q` 为低位稠密权重矩阵，`W_O` 为高精度稀疏异常值矩阵。FlashQuant 将两项在单内核中融合执行，共享 `X` 的加载与 `Y` 的累加写回。

- **显著性能提升**：FlashQuant 相比 cuBLAS BF16 获得 **2.74×–4.18×** 加速；相比最强未融合基线（Sputnik+Marlin）在 RTX 3090/4090/5090 上分别获得 **1.03×–1.16× / 1.12×–1.37× / 1.23×–1.53×** 加速。

- **架构趋势**：在新一代 GPU（更高浮点吞吐）上，FlashQuant 优势更突出——融合带来的额外计算开销相对变小，而访存流量削减的收益持续存在。
- **访存削减**：与 Sputnik+Marlin 相比，FlashQuant 最多减少 **45.4%** 的全局内存访问。
- **存储效率**：Tile-COO 相比 CSR 显著减少异常值矩阵的存储开销（低精度索引编码贡献明显）。

- **精度-效率权衡**：异常值感知量化（SpQR）在不同保留阈值下的一致困惑度优于 GPTQ，内存开销仅适度增加。

## 7. 优点

- **问题洞察新颖**：明确指出异常值感知量化中分离内核执行的“冗余访存”是系统级瓶颈，而非仅关注计算层面的稀疏内核优化。
- **融合思路创新**：提出“内容共享融合”（content-sharing fusion）概念，将同一数学算子衍生的异构计算路径统一调度，超越传统的生产者-消费者型内核融合。
- **三项技术协同设计**：稀疏-稠密分块（统一调度空间）、Tile-COO（GPU 友好的稀疏格式 + 存储压缩）、流水线调度（延迟隐藏）三者环环相扣，从访存、编码、调度三个维度解决融合难点。
- **存储格式设计精细**：Tile-COO 利用 tile 级结构性，将 8 位行/列索引与 BF16 值打包为 uint4 元组，兼顾向量化解码效率与存储压缩；重排序策略同时处理负载均衡与 bank 冲突两个问题。
- **实验设备覆盖广**：横跨三代 GPU 架构，验证了方法的可移植性与可扩展性；端到端实验覆盖模型精度、吞吐、显存占用多维度。

## 8. 不足与局限

- **适用场景有限**：当前针对 **INT4 权重量化 + BF16 异常值**的 W4A16 解码场景设计，不直接支持 INT2 等更低精度格式（论文将之列为未来工作）；也未覆盖 prefill 阶段或更大 batch 的高算力场景。
- **小 batch 性能退化**：batch < 8 时因输入填充（padding 至 8）引入冗余计算，优势明显减弱，对 batch=1/2 的极端延迟敏感场景不够友好。
- **依赖离线预处理**：需要离线重排序与打包，虽为一次性成本，但增加了部署流水线复杂度；论文未报告预处理阶段本身的硬件资源消耗。
- **精度报告简略**：端到端精度实验仅报告 WikiText2 困惑度，未覆盖更广泛的下游任务（如常识推理、代码生成、对话评测等），精度结论的泛化性有待验证。
