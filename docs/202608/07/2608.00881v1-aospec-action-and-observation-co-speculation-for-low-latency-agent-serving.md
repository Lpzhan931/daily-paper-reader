## 摘要
大语言模型智能体越来越多地通过有状态工具行动，但模型生成和环境执行在每一步仍然是串行的。随着解码加速，工具执行成为日益增长的瓶颈。现有的仅动作或仅观察推测使大部分延迟暴露出来：价值集中在少数缓慢的调用中，有些结果只能通过执行才能出现，而更长的前瞻通常需要越来越不可能的动作预测链。我们提出AOSpec，一个无损框架，在整个智能体-环境循环中协同推测动作和观察。期望值解码（EVD）将观察推测导向具有最大预期延迟收益的结果，优化预期隐藏时间而非命中率。对于只有执行才能揭示的结果，AOSpec在包含其效果的隔离分叉中启动延迟关键的目标动作，而联合动作-状态验证（JASV）在重用前验证动作及其来源状态与已提交的执行。JASV将长视野动作依赖从全链预测重塑为目标动作-状态验证，打破了前瞻-准确性权衡，并在不牺牲串行语义的情况下实现长距离重叠。在跨越四个工作台、五个行动者模型和五个服务速度的Terminal-Bench服务设置中，AOSpec优于所有实际基线，平均端到端延迟降低11.8-32.5%，p99延迟最多降低42.8%。其增益随着解码加速而增加，其观察模型无需重新训练即可从Terminal-Bench迁移到SWE-bench Verified。

## Abstract
Large language model agents increasingly act through stateful tools, yet model generation and environment execution remain serialized at every step. As decoding accelerates, tool execution becomes a growing bottleneck. Existing action- or observation-only speculation leaves much of this latency exposed: value is concentrated in a few slow calls, some outcomes emerge only through execution, and longer lookahead typically requires an increasingly unlikely chain of action predictions. We present AOSpec, a lossless framework that co-speculates actions and observations across the full agent-environment loop. Expected Value Decoding (EVD) directs observation speculation toward outcomes with the greatest expected latency benefit, optimizing expected time hidden rather than hit rate. For outcomes only execution can reveal, AOSpec launches latency-critical target actions in isolated forks that contain their effects, while Joint Action-State Verification (JASV) verifies both the action and its origin state against committed execution before reuse. JASV recasts long-horizon action dependency from full-chain prediction into target action-state verification, breaking the lookahead--accuracy tradeoff and unlocking long-range overlap without sacrificing serial semantics. Across Terminal-Bench serving settings spanning four harnesses, five actor models, and five serving speeds, AOSpec outperforms every practical baseline, reducing mean end-to-end latency by 11.8-32.5% and p99 latency by up to 42.8%. Its gains increase as decoding accelerates, and its observation model transfers from Terminal-Bench to SWE-bench Verified without retraining.

**研究动机与背景：**

- 现代基于大语言模型（LLM）的智能体通过"推理→动作→观察"的循环与环境交互，越来越多地依赖**有状态工具**（如文件系统、运行进程、训练脚本等），而不再局限于简单信息检索。
- 在解耦的智能体循环（disaggregated agent loop）中，**模型生成与工具执行严格串行**，每一步都必须等待上一步完成。随着解码速度不断提升（从20 ms/token降至1 ms/token），工具执行时间在端到端延迟中的占比越来越大，成为新的主导瓶颈。
- 现有的推测执行方案只覆盖单一侧：
  - **动作推测**：预测并提前启动未来工具调用，但同步骤重叠窗口有限（最多只能隐藏min(Di, Ti)的时间），且多步前瞻需要整条动作链全部预测正确，准确率随链长呈乘法性崩塌。
  - **观察推测**：从临时观察继续生成，但无法预测依赖环境状态（如文件内容、进程状态、训练指标）的输出，这些结果只能通过实际执行获得。
- 论文通过剖析1,921条训练轨迹，识别出三大根本挑战：
  - **延迟集中**：17%的长耗时调用占据97%的工具总时间，命中率与延迟节省严重脱钩。
  - **环境依赖**：部分关键观察信息超出智能体上下文的信息边界，纯预测不可行。
  - **前瞻权衡**：更长的前瞻能创造更多重叠机会，但链式预测误差使实际收益趋近于零。

**整体含义：** AOSpec是首个同时推测动作与观察的**无损**框架，能够在整个智能体-环境循环中隐藏工具执行延迟，且收益随解码加速而放大。

### 2. 论文提出的方法论

**核心思想：** 将推测从"猜测未来动作链"转变为"在隔离环境中并行执行有价值的候选动作+预测高价值观察"，并在重用前严格验证，从而在保持串行语义等价的前提下最大化延迟隐藏。

**关键技术细节与算法流程：**

**（1）期望值解码（Expected Value Decoding, EVD）**

- EVD将观察候选的**概率**与其对应的**工具执行时间**结合，直接优化"预期隐藏时间"而非命中率。
- 价值函数定义为：**V(c) = pθ(c|Ht, at) × T̂(c)**，其中pθ是候选观察的概率，T̂(c)是从历史执行中通过相似度函数K估计的该候选对应的工具耗时。
- 候选来源可以是小型专用模型（可微调）或通用LLM，支持基于正则表达式模式（Pattern-EVD）或嵌入相似度（Embedding-EVD）两种相似度估计方式。
- 只有与真实观察**字节级一致**的推测分支才会被保留。

**（2）隔离分叉中的动作执行**

- 对于依赖环境状态、无法预测的观察，AOSpec在**隔离的沙箱分叉**中提前启动延迟关键的目标动作，以获得真实的执行结果。
- 基于写时复制（CoW）文件系统实现快照、分叉、提交和丢弃操作，每个分叉记录其来源环境的不可变版本号。

**（3）联合动作-状态验证（Joint Action–State Verification, JASV）**

- 是AOSpec的核心创新。当智能体发出目标动作ai时，JASV只接受同时满足两个条件的分叉：
  - 推测动作与目标动作**完全一致**（工具名和参数）
  - 分叉启动时记录的环境版本与当前已提交环境版本**一致**
- 通过版本号比较而不是递归扫描实现O(1)验证开销。
- JASV的关键突破：**将长视野动作依赖从"整链预测"重构为"目标动作-状态验证"**——即使中间步骤没有提前预测，只要目标动作和起点状态正确，就能安全重用分叉结果，从而打破前瞻-准确性权衡。

**（4）完整算法流程**

- 在已验证的观察边界启动actor生成，同时启动动作分叉。
- 当actor发出目标动作时，JASV检查是否有有效分叉；无则从已提交环境正常执行。
- 在执行未完成期间，EVD启动多个观察候选分支进行推测生成，与实际返回结果竞赛。
- 真实观察返回后，只保留与真实观察字节一致的推测分支，其余全部丢弃；已提交环境更新后，清除失效分叉并启动新分叉。

### 3. 实验设计

### 6. 论文的主要结论与发现

- AOSpec在**所有45个配置-速度组合**中均优于所有实际基线，平均端到端延迟节省从20 ms TPOT时的**11.8%**提升至1 ms时的**32.5%**；同一条件下最强基线的收益仅从4.3%提升至12.2%。
- **p99延迟降低最高达42.8%**（从7780秒降至4449秒），中位数和p90也有约10.7%和10.5%的降低，尾部收益更大，与延迟集中特征一致。
- AOSpec在41/45个设置中超过了**one-step动作Oracle上限**，说明观察推测和跨步动作前瞻的组合超越了单步天花板。
- **EVD优于纯概率或纯工具时间排序**：EVD每个试验隐藏60.5秒，而纯似然47.6秒、纯工具时间39.4秒；EVD将命中率向超过60秒的长调用转移。
- **JASV使长距离预测保持可用**：预测准确率在前瞻10步下降至7.7%，但JASV通过动作+状态验证使得这些预测中的正确部分仍然可以安全利用，无需匹配中间链条。
- **观察模型从Terminal-Bench迁移到SWE-bench无需再训练**：1 ms TPOT时在SWE-bench达到18.9%的延迟节省（最强基线仅4.2%）。
- 微调0.6B观察模型可大幅提升top-1准确率（2.4%→29.1%），但随着候选宽度增加到5，冻结模型与微调模型差距从26.7个百分点缩小到4.8个百分点，说明AOSpec可以在有足够计算资源时实现训练自由。

### 7. 优点

- **无损（Lossless）保证**：通过JASV的动作-状态双重验证和环境版本比较，推测执行与串行执行语义完全一致，不牺牲正确性。
- **打破前瞻-准确性权衡**：JASV是将长视野动作推测从"全链匹配"重构为"动作-状态匹配"的巧妙设计，是方法层面的实质性创新。
- **优化目标从命中率转向预期延迟节省**：EVD的设计直接对齐实际目标，对延迟分布高度偏斜的真实工具调用更有意义。
- **双重推测互补性**：观察推测覆盖可预测但耗时的调用，动作推测覆盖环境依赖的调用，两者互补且增益可以叠加。
- **可迁移性**：观察模型无需重新训练即可迁移到另一个工作负载（SWE-bench），说明学习到的观察模式具有一定的通用性。
- **可训练自由的选项**：在允许多个候选分支时，冻结模型也能达到接近微调模型的性能，降低了部署成本。
- **实验设计较规范**：跨模型、跨工作台、跨速度的广泛覆盖，以及系统性的消融，验证了方法的鲁棒性和可解释性。
- **推理成本可控**：默认仅8个动作分叉和5个观察分支，动作草稿模型为激活参数约30亿的MoE模型，实际部署的额外算力开销尚在可接受范围。

### 8. 不足与局限

- **实验基于轨迹回放而非真实在线系统**：由于Actor模型通过API访问且行为不可控，回放方式是社区认可的折衷方案，但无法反映真实在线服务中模型实际发出的动作与推测分叉动态交互的复杂情况（如推测结果可能改变后续生成的选择），实际收益可能与报告值有出入。
- **动作草稿模型规模较大**：使用Qwen3.6-35B-A3B-FP8作为动作草稿模型，虽然激活参数较少（约30亿），但总参数规模达到350亿，部署推理开销仍然可观；论文对drafting的额外算力消耗及其作为服务成本的综合分析不足。
- **适用范围受限**：
  - JASV要求工具效果可被沙箱隔离，对于无法隔离的外部副作用（如网络请求、真实API调用、物理设备控制等），推测无法安全进行。
  - 依赖CoW文件系统快照和版本比较机制，对某些无文件系统状态的环境可能不适用。
  - 观察验证要求**字节级完全一致**，处理过程UUID等字段会降低接受率，论文仅提及可规范化但未实现。
- **环境状态完整性假设**：JASV的版本验证仅覆盖文件系统状态，非文件系统输入和效果被明确排除在外；若工具行为受文件系统之外的状态（如网络状态、系统负载）影响，可能存在验证盲区。
- **报告指标偏重延迟**：对服务成本、额外算力开销、内存/存储开销等运维指标缺乏分析，可能影响实际部署的经济性评估。
- **动作预测准确性整体偏低**：即使在候选宽度32时，动作匹配率仅为23.7%，虽然JASV保证正确性，但大量分叉的启动-丢弃可能导致资源浪费，论文未详细分析这种浪费的成本边界。
- **观察模型的跨领域通用性只验证了一个迁移方向**：从Terminal-Bench到SWE-bench（均为命令行/Bash领域），对于其他类型工具（如GUI操作、多模态环境等）的迁移能力未经检验。
- **训练数据泄漏与偏差风险**：任务按类别拆分，但具体实现细节有限；训练集本身就来自与测试集相同的工作台环境，模型可能学到的是特定环境的模式而非一般性的观察预测能力。
