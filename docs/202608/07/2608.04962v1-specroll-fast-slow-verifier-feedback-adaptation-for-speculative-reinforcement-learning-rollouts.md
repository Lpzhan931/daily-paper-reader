## 摘要
强化学习（RL）后训练提升了大型语言模型的推理能力，但自回归滚动生成仍然是一个主要的效率瓶颈。推测性解码可以加速生成，但在RL期间应用它很困难，因为目标策略持续演变：静态提议者会变得过时，而频繁的草稿模型更新则增加了大量开销。我们引入了SpecRoll，一种推测性滚动引擎，在保持目标模型采样分布的同时，以两个时间尺度进行自适应。轻量级的未来token头生成并行提议，而我们提出的Reflex模块利用延迟的验证器反馈，在没有反向传播的情况下执行有界的、轨迹局部的隐藏状态校正。互补的慢路径仅在检测到持续退化时更新头部参数。SpecRoll将这些机制与并发感知的稀疏树验证和精确目标验证相结合，保持目标滚动分布和GRPO目标不变。在从1.5B到14B的五个模型和三个数学推理数据集上，SpecRoll相比普通GRPO实现了1.26-2.15倍的生成加速和1.21-2.04倍的端到端加速。在所有15个匹配设置中，它在生成时间和端到端时间上也优于FastGRPO，平均成对端到端增益为1.18倍。受控消融实验表明，快速和慢速自适应路径提供了互补的益处。我们的源代码可在https://anonymous.4open.science/r/SpecRoll-26062006获取。

## Abstract
Reinforcement learning (RL) post-training improves the reasoning capabilities of large language models, but autoregressive rollout generation remains a major efficiency bottleneck. Speculative decoding can accelerate generation, yet applying it during RL is difficult because the target policy continually evolves: static proposers become stale, while frequent drafter updates add substantial overhead. We introduce SpecRoll, a speculative rollout engine that preserves the target model's sampling distribution while adapting at two timescales. Lightweight future-token heads generate parallel proposals, while our proposed Reflex module uses delayed verifier feedback to perform bounded, trajectory-local hidden-state corrections without backpropagation. A complementary slow path updates the head parameters only when sustained degradation is detected. SpecRoll combines these mechanisms with concurrency-aware sparse-tree verification and exact target verification, leaving the target rollout distribution and GRPO objective unchanged. Across five models ranging from 1.5B to 14B and three mathematical reasoning datasets, SpecRoll achieves 1.26-2.15x generation speedup and 1.21-2.04x end-to-end speedup over vanilla GRPO. It also outperforms FastGRPO in both generation and end-to-end time across all 15 matched settings, with an average pairwise end-to-end gain of 1.18x. Controlled ablations show that the fast and slow adaptation paths provide complementary benefits. Our source code is available at https://anonymous.4open.science/r/SpecRoll-26062006.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：强化学习（RL）后训练（如 GRPO）是提升大语言模型数学推理能力的关键手段，但训练过程中需要生成大量长自回归响应，rollout 生成成为显著的端到端效率瓶颈。
- **核心挑战**：投机解码（Speculative Decoding）虽可加速生成，但在 RL 场景下应用面临两大难题：
  - **策略漂移**：目标策略在每轮优化后持续更新，静态提议者（proposer）很快过时，频繁更新草稿模型又引入大量额外计算开销。
  - **并发变化**：rollout 过程中活跃响应数不断减少，固定大小的验证树不能高效利用硬件。
- **论文目标**：设计一种能在 RL 训练过程中保持目标采样分布、同时以两个时间尺度自适应适配策略漂移的推测性 rollout 引擎，实现高效且可扩展的 decoder 级加速，并与现有系统级优化互补。

### 2. 论文提出的方法论

**核心思想**：SpecRoll 将投机解码的自适应拆分为"快-慢"两个互补的时间尺度——
- **快速路径（Reflex）**：无需反向传播，利用延迟的验证器反馈做轨迹局部的隐状态修正；
- **慢速路径（持久整合）**：仅在检测到持续退化时更新提议头参数。

**三大技术组件**：

1. **轻量未来 token 头（Future-Token Heads）**
   - 使用 H 个轻量 horizon 头（文中 H=3，预测位置 t+2、t+3、t+4），从目标骨干网络的同一隐状态 `h_t` 并行预测后续 token 分布：
     - `z_{t,h} = g_φ_h(h_t) + h_t`，复用目标词汇投影矩阵 W；
   - 候选形成前缀闭合的稀疏树，避免了独立自回归 drafter 及其 KV cache 的开销。

2. **Reflex：无梯度轨迹局部修正**
   - 基于验证器反馈，将提议误差分解为**分布误差**（候选集内部概率分配偏差，`d_dist`）和**覆盖误差**（遗漏目标重要 token，`d_cov`）；
   - 分别构造隐空间修正方向 `r_dist = W_S^⊤(p_S − q_S)` 和 `r_cov = Σ_{y∈O} p_S(y)(W_y − W_b⋆)`；
   - 通过指数滑动平均（EMA）在轨迹-horizon对内部累积修正记忆；使用**保守可靠性门控**（基于延迟对齐余弦的置信下界 `dRel = ā − z_δ·s_a/√n`）决定是否启用修正，以避免有害干预；
   - 修正仅作用于 proposal 隐状态，不改变目标模型参数与采样分布。

3. **漂移触发的持久整合（Slow Path）**
   - 维护每 horizon 的有界验证记录缓冲区（reservoir）；
   - 仅当连续多个监控窗口检测到持续漂移（分布距离上升且接受率下降）、并有足够间隔时，才触发对对应 head 的辅助损失更新：
     - `L_aux = λ_dist·D_KL(p_S∥q_S) + λ_tok·(−log q(y⋆)) + λ_prox·Ω(ϕ, ϕ_before)`
   - 目标骨干、词汇投影和策略参数均保持冻结，不参与该辅助梯度。

4. **并发感知稀疏树验证**
   - 每轮验证根据活跃响应数 `B_t` 动态分配节点预算 `N_t = clip(⌊C_peak/B_t⌋, N_min, N_max)`；
   - 使用精确节点级拒绝采样（Exact node-wise verification）保证目标采样分布完全不变，GRPO 目标不受影响。

### 6. 主要结论与发现

- 相对 vanilla GRPO，SpecRoll 实现 **1.26×–2.15× 生成加速**（平均 1.57×）和 **1.21×–2.04× 端到端加速**（平均 1.51×），且在全部 15 个设置中均优于 FastGRPO（平均端到端增益 1.18×）。
- **效率来源**：SpecRoll 的优势不是无限的接受长度，而是更高的 token 接受率（14/15 设置高于 FastGRPO），表明其更有效地利用了验证预算。
- **快慢路径互补**：单独启用 Reflex 或持久整合均优于无自适应基线，二者组合效果最强（如 Qwen2.5-14B 端到端从 1.16× 提升到 1.45×）。
- **精确性保障**：精确目标验证确保目标采样分布与 GRPO 目标完全不变，训练奖励轨迹与 vanilla GRPO 基本一致，证明加速不影响优化质量。

### 7. 优点

- **创新性的双时间尺度自适应设计**：将延迟验证器反馈拆分为无梯度的轨迹局部记忆（处理瞬时失配）和选择性的持久参数学习（处理跨轨迹持续漂移），避免了频繁反向传播的高开销。
- **严格保持目标分布**：所有优化均不影响目标模型采样分布和 GRPO 目标，理论上有精确验证保证（含附录中的定理与命题支撑）。
- **轻量设计**：使用未来 token 头替代独立自回归 drafter，省去额外 KV cache 和模型同步成本。
- **理论深度**：附录包含反馈方向与代理函数的梯度表示、延迟记忆跟踪的有限样本界、条件 KL 下降到首槽位接受率的传递定理等，具有较强的理论支撑。
- **工程实用性**：并发感知的稀疏树验证使方法能自适应不同并发阶段，全面计时（包含所有额外开销）保证了结论的可信度。

### 8. 不足与局限

- **模型规模覆盖有限**：实验最大模型仅 14B，未验证更大规模模型（如 70B+）上的可扩展性。
- **任务领域单一**：仅覆盖数学推理数据集，未涉及代码生成、多语言推理或其他广泛任务；论文自身指出此局限。
- **硬件环境单一**：仅在 NVIDIA B200 上评测，不同硬件平台、执行栈、并发设置和响应长度分布下收益可能不同。
- **训练时长有限**：每个数据集仅训练 1 个 epoch，未验证长训练周期下的持久收益和长期稳定性。
- **可靠性门控依赖较多超参数**：Reflex 涉及多个超参数（如支持 top-k、反馈权重、Alpha 区间等），敏感性分析显示结果非单调（如 k=32 反而较差），调参成本较高；
