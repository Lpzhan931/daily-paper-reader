## 摘要
推测解码仅在草稿续写通过目标模型验证时加速大语言模型推理。诸如DSpark之类的半自回归草稿器通过一次骨干网络前向传播预测整个令牌块，并使用轻量级马尔可夫头进行细化。然而，DSpark将该块作为单链解码，因此早期的不匹配会使剩余后缀失效，并限制大草稿块的收益。我们表明，DSpark已学习的条件结构可以在无需重新训练或额外骨干传递的情况下支持多个父一致续写。我们引入了父条件草稿树（PCTree），它利用预训练的马尔可夫头为每个具体父节点分别对替代子节点进行评分，并将固定的验证预算分配给最可能的路径。这将DSpark的线性草稿转换为树，同时保留其单遍并行骨干。在Qwen3-{4B,8B,14B}和九个基准测试中，当B=7时，相对于自回归（AR）解码的实测加速比增益，与匹配的DSpark相比，范围从3.1%到29.5%。在Qwen3-4B GSM8K上，当B=16时，PCTree将平均接受长度从9.41提高到11.16，三次运行的平均AR加速比从6.14倍提高到6.60倍。这些结果表明，父条件分支可以将半自回归草稿器中已有的条件能力通过仅推理更改转化为端到端推理增益。

## Abstract
Speculative decoding accelerates LLM inference only when drafted continuations survive target-model verification. Semi-autoregressive drafters such as DSpark predict an entire token block with one backbone forward and refine it with a lightweight Markov head. However, DSpark decodes this block as a single chain, so an early mismatch invalidates the remaining suffix and limits the benefit of large draft blocks.   We show that the conditional structure already learned by DSpark can support multiple parent-consistent continuations without retraining or additional backbone passes. We introduce Parent-Conditioned Drafting Tree (PCTree), which uses the pretrained Markov head to score alternative children separately for each concrete parent and allocates a fixed verification budget to the most probable paths. This converts DSpark's linear draft into a tree while preserving its one-pass parallel backbone.   Across Qwen3-{4B,8B,14B} and nine benchmarks, at $B{=}7$, measured speedup gains over autoregressive (AR) decoding, relative to matched DSpark, range from $3.1\%$ to $29.5\%$. On Qwen3-4B GSM8K at $B{=}16$, PCTree increases mean acceptance length from $9.41$ to $11.16$ and three-run mean AR speedup from $6.14{\times}$ to $6.60{\times}$. These show that parent-conditioned branching can turn conditional capacity already present in a semi-autoregressive drafter into end-to-end inference gains through an inference-only change.

## 2. 方法论：PCTree

### 2.1 核心思想
- 保留 DSpark 的**并行骨干**（一次前向得到各位置共享 logits）和**轻量马尔可夫头**。
- 将对每个深度唯一贪婪子节点的选择，替换为**基于具体父节点的 top-k 分支扩展**，并构建一个受验证节点预算约束的树。
- 关键区别：**父条件评分**——不同父节点使用相同基 logits \(L_d\)，但各自加上不同的 Markov bias，得到**不同的子节点分布**，避免"父无关拼接"（如把高概率但互不连贯的 token 拼成路径）。

### 2.2 关键技术细节

- **马尔可夫树扩展**：
  - 阶段 \(d\) 使用当前 frontier（父节点集合），每个父 \(p\) 计算 \(z_d(p) = L_d + \text{Markov}(p)\)。
  - 对所有父节点批量调用一次 Markov 头，计算每个父节点的 top-k 子节点。
  - 子节点联合路径分数 \(s(c) = \sum_{(u\to v)\in \text{path}(c)} \log \pi(v|u)\)。
  - 每层仅保留分数最高的 k 个节点作为下一层 frontier（layered top-k pruning），控制候选规模在 \(O(B k^2)\) 而非指数增长。
- **预算选择与树验证**：
  - 所有节点按联合分数降序、深度升序、稳定 ID 排序，取全局 top-N（含根节点）构成前缀闭合树。
  - 打包为扁平 token 张量 + 检索索引 + 祖先掩码，一次性送入目标模型验证，使用标准贪心树推测解码规则。
- **与 DSpark 关系**：当 \(k=1\) 时退化为 DSpark 单链。
- **复杂度**：PCTree 与 DSpark 保持相同的 \(B\) 个顺序 Markov 阶段，仅将每阶段 batch 从 1 增至不超过 k，额外开销来自 Markov 批处理和树选择/打包。

## 6. 主要结论与发现

- **PCTree 普遍提升接受长度**：在所有 3 个目标模型、9 个 benchmark、两种块大小下均优于 DSpark。
- **端到端加速可观**：B=7 时，相对 DSpark 的 AR 加速比增益为 3.1%–29.5%；B=16 时，代表性套件上增益 7.5%–15.1%。
- **父条件建模是关键**：Shared-Markov tree 虽也有提升，但 PCTree 进一步将接受长度从 10.225 提至 11.156（+9.1%），轮数减少 8.4%，证明父特定重评分而非单纯分支是主要收益来源。
- **成本可被抵消**：虽然 Markov+tree 阶段延迟上升，但更长的接受路径减少了平均轮数，从而整体 AR 加速比提升（B=7 从 4.24× 到 4.50×，B=16 从 6.14× 到 6.60×）。
- **超参敏感性**：k 从 1 到 2 收益最大，k=4 已饱和；N 存在非单调效应，过大预算反而拖累端到端速度。

## 7. 优点

- **纯推理时改造**：不改变 DSpark 预训练权重、不额外训练、不增加骨干前向次数，工程落地成本低。
- **巧妙的机制利用**：识别并复用已有 Markov 头的父条件能力，避免重新设计架构。
- **复杂度可控**：层级 top-k 剪枝将候选规模限制在 \(O(Bk^2)\)，树验证单次前向完成。
- **实验设计规范**：设有"Shared-Markov"对照，因果归因严谨；重复运行、标准差不缺失；消融全面（k、N、成本分解）。
- **适用范围明确**：指出对任何"并行块 + 轻量顺序精化"因子的草稿器均可适用，具有泛化潜力。

## 8. 不足与局限

- **依赖预训练草稿质量**：树的质量受限于 pretrained Markov 头；若头本身条件建模弱，训练-free 扩展无法根治。
- **剪枝启发式非最优**：层级 top-k 可能剪掉全局最优路径，存在理论次优性。
- **成本与硬件敏感性**：大 k / N 在小型目标模型或内存受限设备上可能抵消收益；加速比依赖 GPU、精度、注意力内核和工作负载。
- **实验覆盖有限**：
  - 主要硬件单一（H20），未测试其他平台。
  - 多数非关键配置仅一次运行，统计置信度不足。
  - B=16 草稿为自训，外部基线（EAGLE-3、DFlash）非严格同环境，跨系统比较需谨慎。
  - 未探讨与置信度调度、近重验证等现有 DSpark 服务的组合效果。
- **应用限制**：仅对贪心解码验证，未覆盖采样/多温度场景；树验证对 memory layout 和 KV 缓存管理要求更高，实际部署时需额外工程优化。
