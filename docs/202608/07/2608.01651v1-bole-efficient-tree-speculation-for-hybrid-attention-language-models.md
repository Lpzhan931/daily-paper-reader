## 摘要

## Abstract
Hybrid-attention large language models combine full attention with recurrent linear attention to reduce long-context inference costs, yet their autoregressive decoding remains memory-bound. Tree speculative decoding offers an attractive acceleration path, but existing tree-speculation systems are designed around the key--value caches of full-attention models. On hybrid models, they traverse recurrent layers branch by branch and materialize a full state for every proposal node, causing verification latency and transient memory to scale poorly with tree and batch sizes. We present Bole, a kernel--runtime co-design that enables efficient tree speculation for hybrid-attention LLMs. Bole transforms the linear-attention recurrence into a tree-structured closed form and realizes it with a resource-efficient GPU kernel, verifying all proposal nodes in parallel and accelerating linear-attention tree verification by 3.4--7.7$\times$. It losslessly encodes speculative state updates as token-level factors and reconstructs only the state selected after sampling, reducing transient state memory by 82--99$\times$ and freeing GPU capacity for KV caches. Its integration into SGLang, a widely deployed production LLM serving engine, couples efficient state management with a batch-wide verification budget calibrated to the complete hybrid forward. Across four models, two GPU platforms, and diverse datasets, Bole delivers up to $4.72\times$ the offline decode throughput of autoregressive decoding and up to $2.03\times$ that of the strongest tree-speculative baseline. Under online agent workloads, it reduces TTFT and TPOT by up to $67.6%$ and $49.9%$, respectively, over the strongest tree-speculative baseline.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：混合注意力大语言模型（hybrid-attention LLM）将全注意力（full attention）与循环线性注意力（recurrent linear attention）结合，例如 Qwen3.5 和 Kimi Linear 等模型。全注意力提供全局检索能力但 KV 缓存随上下文增长，线性注意力用固定大小的状态压缩前缀，降低长上下文推理成本。
- **核心问题**：混合注意力模型的自回归解码仍然受内存带宽限制；树投机解码（tree speculative decoding）虽然能通过一次前向验证多个候选 token，但现有系统（如 SpecInfer、DeFT、STree、SGLang、AdaServe）均针对全注意力模型的 KV 缓存设计，无法高效处理混合模型中的循环线性注意力层。
- **具体瓶颈**：
  1. **串行递归**：线性注意力依赖父节点到子节点的状态传播，需要逐分支、逐节点执行，树规模增大时线性层耗时占比从 4% 升至 27%。
  2. **状态爆炸**：为每个提议节点物化完整状态快照，瞬态内存随树大小和批大小线性增长，例如 122B 模型在 8 请求、32 节点时消耗 36 GiB，挤占 KV 缓存容量。
  3. **验证容量可变**：可高效验证的 token 数量随 GPU 型号、批大小、KV 长度等变化，固定预算不可靠。
- **整体意义**：Bole 是首个面向混合注意力 LLM 的"内核-运行时"协同设计，将线性注意力树验证从串行变为并行、从全状态物化变为因子化存储，并集成到生产级服务引擎 SGLang 中，显著提升解码吞吐并降低在线延迟。

## 2. 方法论

Bole 的核心思想是：**将循环线性注意力的树形递归改写成闭式并行形式，用 token 级因子替代完整状态快照，并在运行时按硬件能力分配批量验证预算**。

### 2.1 并行树验证的闭式形式

- 针对 Gated DeltaNet（GDN）的递归更新 \(S_t = \gamma_t S_{t-1} + k_t u_t^\top\)，Bole 通过三步推导出定理 1 的闭式解：
  - **Lemma 1（路径因子化状态）**：将每个节点的更新状态分解为共享前缀状态与祖先路径上的 rank-1 修正之和。
  - **Lemma 2（祖先掩码线性系统）**：将所有节点的修正向量 \(U\) 组织为 \((I + G)U = R\)，其中 \(G\) 仅包含严格祖先间的依赖，矩阵严格下三角。
  - **Lemma 3（深度有界幂零性）**：\(G^{d+1}=0\)，因此 \((I+G)^{-1} = \sum_{m=0}^{d}(-G)^m\)，即有限 Neumann 级数，精确且无需迭代收敛。
- 最终闭式形式：\(O = D_P Q S_{\text{pre}} + C(I+G)^{-1}D_\beta(V - D_P K S_{\text{pre}})\)。
- 该形式在代数上等价于顺序执行，不需要逐节点递归遍历，也不需要为每个节点保存完整状态。

### 2.2 值分块并行验证内核

- 将值维度 \(d_v\) 分为多个 tile，每个 CTA（线程块）处理一个值 tile，覆盖所有树节点。
- 树因子 \(G, C\) 由 Q/K、gates、衰减系数和树拓扑一次性构造，供所有值 tile 复用。
- CTA 内执行：
  - 计算 \(\mathbf{B}_0 = D_P(QS_{\text{pre}})\) 和 \(\mathbf{R} = D_\beta(V - D_P K S_{\text{pre}})\)；
  - 用固定的 d 轮有限 Neumann 迭代 \(\mathbf{Z}^{(m+1)} = -G\mathbf{Z}^{(m)}\) 求解 \(U\)；
  - 计算最终输出 \(O = B_0 + CU\)。
- 通过寄存器/共享内存常驻，避免中间矩阵写入 HBM；共享内存工作集上界为 \(\Theta(T^2 + T b_v + b_k(T + b_v))\)，兼顾 CTA 并发度与片上复用效率。

### 2.3 因子化投机状态生命周期

- 每个请求每个层只保留一个**不可变的已提交状态** \(S_{\text{pre}}\)。
- 候选分支只存储 token 级因子 \(P, K, U\)，空间复杂度从 \(\Theta(T H d_k d_v)\) 降为 \(\Theta(T H(d_k + d_v + 1))\)。
- 采样确定接受路径后，通过一次批量矩阵乘法 \(S_{\text{new}} = P_a S_{\text{pre}} + (D_a K_a)^\top U_a\) 重建仅被接受的状态，拒绝分支无需回滚或占用任何状态槽。

### 2.4 硬件感知的批量验证预算

- 离线对每个执行配置（模型、GPU、批大小、KV 长度桶、树形状桶）扫描总验证 token 数，选择满足 \(T_{\text{ver}}(N|c) \le (1+\epsilon)T_{\text{dec}}(c)\) 的最大容量 \(B_{\text{ver}}(c)\)。
- 在线按 drafter 给出的累积路径概率在批量内做全局 top-k 选择，确保每个请求选中的节点保持前缀连通。

### 2.5 SGLang 生产集成

- 使用 CUDA Graphs 捕获固定形状的"扁平森林"执行流；
- 设备端完成森林物化、采样、路径压缩、跨层统一状态提交；
- 避免主机-设备同步气泡，保持 GPU 流水线连续运行。

## 6. 主要结论与发现

- **并行验证显著加速线性层**：完整 Gated DeltaNet 树验证核相比串行版本加速 3.4×–7.7×；状态物化时间占比在 A100 上为 38%、在 GB10 上为 86%，导致带宽更低的 GB10 收益更大。
- **因子化状态内存大幅缩减**：瞬态状态内存比全快照减少 82–99 倍；非缓存投机开销相对 AdaServe 降低 74.0%–88.5%，释放 6.26–18.58 GiB 用于 KV 缓存。
- **端到端吞吐提升**：
  - 离线：几何平均相对 SGLang-AR 加速 2.74×；A100 上峰值达 SGLang-AR 的 3.62×、最强投机基线的 1.41×；GB10 上峰值达 4.72× 和 2.03×。
  - MAT 略高于所有基线（如 27B 模型达 6.62 vs AdaServe 6.61）。
  - 在 27B 模型上，Bole 能在 batch 8 下运行，而 SGLang-Tree 和 AdaServe 在 A100/GB10 均 OOM。
- **在线智能体负载**：相比 AdaServe，TTFT 最多降低 67.6%（GB10 上 27B 场景），TPOT 最多降低 49.9%；前缀缓存命中率从约 70% 提升到 91–93%，接近 AR 基线。
- **预算敏感性**：最优验证 token 数在 A100 为 128、GB10 为 256，验证了"硬件感知批量预算"的必要性。
- **消融**：预算、并行求解、因子化状态三者均贡献增益；在 GB10 上因子化状态对在线吞吐的贡献最大（累计加速从 1.30× 升至 2.23×）。

## 7. 优点

- **算法-内核-运行时协同**：不是单点优化，而是从数学推导（闭式解）→ GPU 内核（值分块 + 有限 Neumann）→ 运行时调度（批量预算 + CUDA Graphs）全链路设计。
- **精确无损**：闭式解与顺序递归在代数上完全等价，不引入近似；因子化状态是精确恢复。
- **通用性强**：支持连续批处理、CUDA Graphs、张量并行（TP4）、多种 Qwen3.5 模型和两个不同计算/带宽比平台。
- **生产落地**：集成到 SGLang，而非停留在仿真；代码量约 6.2k LoC，使用 Python/Triton，便于移植。
- **实验设计扎实**：同时报告吞吐、延迟、MAT、内存开销、内核指标、消融和敏感性，验证链条完整。
- **动机量化清晰**：图 1 中的"线性层占比增长、状态快照内存、硬件阈值"三个现象直接驱动设计，问题导向明确。

## 8. 不足与局限

- **模型覆盖有限**：只验证了 Qwen3.5 系列（GDN + 全注意力），未测试 Mamba-2、Kimi Linear 或其他混合架构；STree 只支持对角 SSM，Bole 的闭式解是否对所有门控 delta 递归通用需进一步说明。
- **平台数量有限**：仅 A100 和 GB10 两个平台，缺乏对 Hopper/Blackwell 数据中心 GPU 的验证。
- **在线工作负载单一**：只使用 Open-SWE-Traces 一种编码智能体数据集，无法代表所有 agentic 负载（如多模态、长文档、并行多 agent）。
- **缺少错误分析**：未讨论 MAT 退化情况、树结构异常（如极端不平衡树）对性能的影响。
- **预算校准成本**：离线配置扫描依赖"执行桶"（批量、KV 长度、树深度等）组合，桶数量多时校准开销可能较高；论文未量化该开销。
- **无统计置信区间**：结果以点估计呈现，未报告标准差、多次运行方差或显著性检验。
- **基线移植公平性**：AdaServe 的本地实现不支持混合注意力，作者自行移植优化，可能引入与官方实现不一致的行为；但已说明统一了 drafter 和预算。
- **无端到端能耗/成本对比**：仅报告延迟和吞吐，未评估内存占用对多租户 SLA 和功耗的影响。
