## 摘要
混合注意力大语言模型将全注意力与循环线性注意力相结合，以降低长上下文推理成本，但其自回归解码仍然受内存限制。树推测解码提供了一种有吸引力的加速路径，但现有的树推测系统是针对全注意力模型的键值缓存设计的。在混合模型上，它们逐分支遍历循环层，并为每个提议节点物化一个完整状态，导致验证延迟和瞬态内存随树大小和批大小扩展性差。我们提出了Bole，一种内核-运行时协同设计，为混合注意力LLM实现高效的树推测。Bole将线性注意力循环转化为树结构的闭式形式，并通过资源高效的GPU内核实现，并行验证所有提议节点，将线性注意力树验证加速3.4--7.7倍。它将推测状态更新无损编码为token级因子，并仅重建采样后选中的状态，将瞬态状态内存减少82--99倍，并释放GPU容量用于KV缓存。将其集成到广泛部署的生产级LLM服务引擎SGLang中，将高效状态管理与针对完整混合前向传播校准的批级验证预算相结合。在四个模型、两个GPU平台和多种数据集上，Bole的离线解码吞吐量最高可达自回归解码的4.72倍，最强树推测基线的2.03倍。在在线代理工作负载下，与最强树推测基线相比，它分别将TTFT和TPOT降低了最多67.6%和49.9%。

## Abstract
Hybrid-attention large language models combine full attention with recurrent linear attention to reduce long-context inference costs, yet their autoregressive decoding remains memory-bound. Tree speculative decoding offers an attractive acceleration path, but existing tree-speculation systems are designed around the key--value caches of full-attention models. On hybrid models, they traverse recurrent layers branch by branch and materialize a full state for every proposal node, causing verification latency and transient memory to scale poorly with tree and batch sizes. We present Bole, a kernel--runtime co-design that enables efficient tree speculation for hybrid-attention LLMs. Bole transforms the linear-attention recurrence into a tree-structured closed form and realizes it with a resource-efficient GPU kernel, verifying all proposal nodes in parallel and accelerating linear-attention tree verification by 3.4--7.7$\times$. It losslessly encodes speculative state updates as token-level factors and reconstructs only the state selected after sampling, reducing transient state memory by 82--99$\times$ and freeing GPU capacity for KV caches. Its integration into SGLang, a widely deployed production LLM serving engine, couples efficient state management with a batch-wide verification budget calibrated to the complete hybrid forward. Across four models, two GPU platforms, and diverse datasets, Bole delivers up to $4.72\times$ the offline decode throughput of autoregressive decoding and up to $2.03\times$ that of the strongest tree-speculative baseline. Under online agent workloads, it reduces TTFT and TPOT by up to $67.6%$ and $49.9%$, respectively, over the strongest tree-speculative baseline.

- **树推测解码的优势**：树推测解码（Tree Speculative Decoding）通过轻量草稿模型生成多分支候选token树，让目标模型一次前向并行验证所有节点，可显著提高平均接受长度（MAT）和吞吐量。
- **现有系统无法适用于混合模型**：
  - 现有树推测内核（如SpecInfer、DeFT）依赖全注意力的注意力矩阵掩码，无法处理循环线性注意力的递归依赖；
  - 现有运行时（如SGLang、AdaServe）围绕全注意力的KV缓存设计，在混合模型上逐分支遍历循环层，并为每个提议节点物化完整状态，导致验证延迟与瞬态内存随树和批大小急剧增长。

  3. **验证容量不确定**：GPU可高效验证的token数随硬件和当前批次变化，固定预算不可靠。

  1. 树耦合的循环依赖构成了拓扑关键路径，难以并行；

  3. 全注意力、循环线性注意力、稠密算子的成本耦合且随配置变化。

## 2. 方法论：核心思想、关键技术细节与算法

### 核心思想
**Bole = 内核–运行时协同设计**，将线性注意力递归转化为树结构闭式解，实现并行验证；将推测状态无损编码为token级因子，仅重构选中路径状态；通过硬件感知的批级验证预算自动控制验证成本。

### 关键技术细节

#### (1) 并行树求解器（Closed-Form Tree Verification）
- **定理1**（Bole闭式验证）：对Gated Delta规则，顺序树执行可代数等价地改写为：
  \[
  O = D_P Q S_{\text{pre}} + C(I + G)^{-1}D_\beta(V - D_P K S_{\text{pre}})
  \]
  其含义：
  - \(S_{\text{pre}}\) 为提交前的共享状态（单一不可变）；
  - \(G\) 为祖先掩码线性系统（严格下三角、深度有界幂零），\((I+G)^{-1}\) 可展开为有限级数 \(\sum_{m=0}^{d}(-G)^m\)；
  - 该闭式解**精确等价**于顺序执行，无需任何近似。
- **三条引理支撑**：
  - 引理1（路径因子化状态）：每个节点的状态可表示为共享状态与祖先节点修正项的叠加；
  - 引理2（祖先掩码修正系统）：将所有节点的修正向量堆叠为线性系统 \((I+G)U = R\)，\(G\) 中只保留严格祖先依赖；
  - 引理3（深度有界幂零）：最大祖先深度为 \(d\) 时 \(G^{d+1}=0\)，逆矩阵为有限多项式。

#### (2) 值分块并行验证内核（Value-Tiled GPU Kernel）
- 将值维度 \(d_v\) 划分为 \(N_v\) 个分块，每个CTA处理一个值分块、覆盖全部树节点；
- 树相关因子（\(G\)、\(C\)）由单独factor producer一次构建，所有CTA复用，避免重复计算；
- CTA内部：
  - 将 \(Q S_{\text{pre}}\)、\(K S_{\text{pre}}\) 按 \(d_k\) 分块、用张量核心MMAs计算；
  - 执行有限Neumann迭代 \(Z^{(m+1)} = -G Z^{(m)}\)，全部驻留在片上寄存器/共享内存，不写回HBM；
  - 最后构造输出 \(O = B_0 + C U\)。
- 通过二维资源分块（\(b_v\) 和 \(b_k\)）平衡每个CTA效率与并行度，将工作集限制为 \(\Theta(\tilde{T}^2 + \tilde{T}b_v + b_k(\tilde{T}+b_v))\)。

#### (3) 融合树验证流水线
- 一次“轮级拓扑预处理”后，每层执行三个阶段：
  1. **树并行卷积与门控准备**：沿父链读取输入，融合卷积、偏置、SiLU、门控；
  2. **因子构建**：用Q/K/门掩码一次构造 \(G\)、\(C\)；
  3. **值分块求解与读出**：生成输出 \(O\) 和紧凑的提交因子 \(U\)。

#### (4) 因子化状态生命周期（Factorized Linear State Storage and Commit）
- **存储复杂度对比**：
  - 传统快照：\(O(H d_k d_v)\) 每节点分支状态；
  - Bole因子化：\(O(H d_k d_v)\) 一个提交状态 + \(O(TH(d_k + d_v + 1))\) 树因子，单节点因子开销仅 \(O(2H d_s)\)（当 \(d_k=d_v=d_s\)），优势随状态维度扩大。
- **三类生命周期管理**：
  - **持久状态**：每请求每层的唯一规范状态 \(S_{\text{pre}}\)，验证期间不可变；
  - **轮级因子**：\(P, K, U\) 仅保留到采样后，被拒绝的分支自动消失，无需回滚；
  - **层内暂存**：\(G, C\) 和Neumann工作区仅在一个层内存在，跨层复用。
- **接受路径提交**：采样后选出一条路径，用单次批量矩阵乘按公式 \(S_{\text{new}} = P_a S_{\text{pre}} + (D_a K_a)^\top U_a\) 重建唯一需要持久化的状态，跨线性层合并为一次GPU launch。

#### (5) 硬件感知的批级验证预算（Hardware-Aware Verification Budget）
- **离线校准**：对每个执行配置（模型、GPU、并行度、批次大小、KV长度桶、树深度），扫描总验证节点数 \(N\)，记录完整混合前向延迟 \(T_{\text{ver}}(N|c)\)，选取满足 \(T_{\text{ver}}(N|c) \le (1+\epsilon) T_{\text{dec}}(c)\) 的最大 \(N\) 作为该配置的容量 \(B_{\text{ver}}(c)\)。
- **在线分配**：用草稿模型的累积路径概率 \(\rho(v)=\prod_{u \in P(v)} p_{\text{draft}}(u|\pi(u))\) 对节点全局排序，在容量内优先选择高概率节点；因单调性，每个请求选出的节点自动保持前缀连通。

#### (6) 生产引擎集成
- 集成到SGLang中，使用Python + Triton实现约6.2k LoC；
- **CUDA Graph原生打包森林执行**：将变长树拓扑打包为扁平不规则森林，固定地址和内核形状，支持容量分桶CUDA Graphs复用；
- **统一跨层状态提交**：验证输出因子直接写入预分配GPU缓冲区，采样后单次launch完成所有线性层的状态重建和全注意力层KV提交；
- **无气泡GPU执行**：选择、森林物化、目标执行、采样、路径压缩、状态提交全部在GPU上形成单一捕获执行流，消除主机同步间隙。

- **离线解码吞吐**：
  - 几何平均较SGLang-AR加速2.74×，较最强推测基线加速1.26×；
  - A100峰值：较SGLang-AR 3.62×、较SGLang-Tree 1.41×、较AdaServe 1.39×；
  - GB10峰值：较SGLang-AR 4.72×、较SGLang-Tree 2.03×、较AdaServe 2.06×。
- **MAT提升**：在所有模型和工作负载上，Bole的MAT均高于SGLang-Tree和AdaServe（如MBPP上6.38/6.88/6.62/6.40 vs 6.29/6.76/6.56/6.31）。
- **在线Agent负载**：
  - 较最强推测基线：TTFT降低61.3–73.3%，TPOT降低28.9–49.9%（对SGLang-Tree为63.5–67.6%和33.8–50.3%）；
  - 前缀缓存命中率90.8%/92.6%（A100/GB10），接近SGLang-AR（89.8%/93.3%），远高于SGLang-Tree（69.7%/58.3%）和AdaServe（69.3%/59.8%）；
  - 内存释放使更多可复用前缀留在KV缓存中，减少重复prefill，同步改善TTFT和TPOT。
- **预算敏感性与平台差异**：A100最优总预算128 token，GB10为256 token，验证了固定预算不可行、硬件感知预算的必要性。

## 7. 优点（方法与实验设计的亮点）

- **理论严谨性**：通过路径因子化、祖先掩码线性系统、深度有界幂零三条引理，严格证明闭式解与顺序执行代数等价，保证无损加速。
- **内核-运行时协同设计**：不局限于单点优化，而是从算法、GPU内核、调度、状态管理、生产引擎集成全栈联动，系统性解决瓶颈。
- **因子化状态生命周期极具创新性**：将“分支状态发散”问题转化为“token级因子 + 单一提交状态”，实现82–99×内存压缩且无损，从根本上消除回滚和快照需求。
- **硬件感知预算**：用离线校准替代固定启发式，适配不同GPU和批次的算力-带宽特征，鲁棒性高。
- **生产级集成**：在真实广泛部署的SGLang中落地，支持连续批处理、CUDA Graphs和GPU端统一提交，工程完成度高。
- **实验设计全面且分层**：从端到端吞吐到内核微基准再到组件消融，证据链完整；在线负载采用真实Agent轨迹，贴近实际部署；同时报告内存、缓存命中率、MAT等解释性指标，便于理解加速来源。
- **公平性意识**：保持相同草稿器、树预算、采样配置；将AdaServe移植到SGLang以保证框架一致性。

## 8. 不足与局限

- **模型覆盖有限**：仅评估Qwen3.5系列，未覆盖其他混合注意力架构（如Kimi Linear、自研GDN变体），结论对更广泛混合模型的推广性有待验证。
- **平台覆盖有限**：仅A100（数据中心GPU）和GB10（边缘/桌面级）两类，未包括H100、MI300X等更先进或不同架构的加速卡。
- **树配置未充分探索**：固定top-k=4、最大深度=8，未对不同树宽度、深度、形状组合做系统敏感性分析；不同模型可能偏好不同树形状。
- **AdaServe移植公平性**：AdaServe原实现不支持混合模型，移植可能损失其部分优化，导致基线略弱；虽然文中说明“port and optimize”，但无法排除移植偏差。
- **预算校准开销**：离线校准需要为每个执行配置扫描大量N值，虽然是一次性成本，但在模型/硬件频繁更新的生产环境中可能带来运维负担；论文未讨论校准开销本身。
- **TPT（Tensor Parallel）评估较浅**：仅122B模型使用TP4，未研究不同TP大小对Bole收益的影响。
- **缺乏长上下文压力测试**：论文聚焦在线Agent和常规数据集，未专门评估超长上下文（如100K+）下因子化状态与KV缓存交互的表现。
- **未讨论数值稳定性与精度细节**：闭式解涉及矩阵乘法和级数求和，论文未明确分析在低精度（FP16/BF16）下与顺序执行相比是否引入额外舍入误差（尽管声称无损等价，但实际浮点行为可能不同）。
