## 摘要
大型语言模型（LLM）推理服务日益受限于内存而非算力。随着长上下文和长形式推理工作负载日益普遍，键值（KV）缓存在LLM词元生成（即解码）期间主导内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批处理大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储从HBM中解耦来缓解HBM容量压力。由于解码时注意力天然是稀疏的，OasisKV仅将最相关词元的KV条目保留在HBM中用于注意力计算。我们观察到，利用投机解码（SD）草拟的前视词元可以提前准确预测未来重要词元。OasisKV采用高效的注意力后台流水线来识别重要KV块，然后从更高容量内存层级（例如主机或远程内存）预取这些块，并在下一步解码使用前暂存于HBM中。我们基于vLLM实现OasisKV。在2048词元KV预算下，前视预测足够准确，可将精度保持在完全注意力的0.7个百分点以内。这使得OasisKV能够将稀疏性转化为吞吐量增益：在推理工作负载上相比密集vLLM提升1.69倍，精度损失仅0.1个百分点；在多GPU长上下文服务中提升高达2.1倍。在预填充-解码分离场景下，OasisKV达到约2倍的密集吞吐量，同时每个请求的KV量减少6.5至9.7倍，解码节点主机内存占用比完整KV传输少2.2至2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

# OasisKV 论文详细总结

## 1. 论文的核心问题与整体含义

- **核心问题**：LLM 推理服务正从“算力受限”转向“内存受限”。随着长上下文、Agentic 工作负载（如 Web 浏览、计算机使用、编程代理）的普及，解码阶段（Decode）的 KV 缓存成为 HBM（高带宽内存）容量与带宽的主要瓶颈，严重限制推理的批处理大小（batch size）、单请求延迟与系统整体吞吐。
- **现有方法的局限**：
  - 稀疏注意力（Sparse Attention）：降低 KV 读取量，但不减少 KV 缓存所需的 HBM 容量。
  - KV 检索（KV Retrieval）：只在 HBM 中保留活动子集，但离片 KV 传输位于解码关键路径上，延迟直接暴露。
  - KV 预取（KV Prefetch）：通过预测提前预取，但受限于 CPU–GPU/网络互联带宽，且现有预测器要么需要模型定制训练，要么预测精度不足；在 PD 分离（Prefill–Decode Disaggregation）场景下问题更加突出。
- **整体含义**：OasisKV 给出了一种以内存为中心的 LLM 推理系统设计思路，将 KV 缓存从 HBM 解耦至更大容量但更慢的存储层，并通过“前瞻（lookahead）稀疏预取”将稀疏性转化为吞吐收益，系统性缓解 HBM 容量墙问题。

## 2. 论文提出的方法论

### 2.1 核心思想

- 利用投机解码（Speculative Decoding, SD）中 EAGLE-3 等机制草拟的“未来 token”作为预测信号（lookahead token），在下一步解码真正发生之前，准确预测当前步最可能被注意到的 KV 块，并通过后台异步流水线从 CPU DRAM 或远程内存中预取到 HBM。
- 这样 HBM 中只需保留一个 **有界的稀疏 KV 工作集**（默认 2048 token/头），而完整 KV 缓存持久存放在 CPU 或远程内存中。

### 2.2 关键技术细节

1. **Look-ahead Attention（前瞻注意力）**
   - 前景：QKV 投影同时产生正常查询 `q_t` 与草稿查询 `q_{t+1}`，二者共享一次权重读取和同一 KV 工作集。
   - 背景：草稿查询通过压缩键摘要（Quest 风格的 block-wise min/max pooling 上界）扫描全量逻辑块，预测下一步的 Top-K 块；压缩摘要仅占完整 KV 的 1/16。
   - 关键观测：用草稿 token 在稀疏 KV 上传播得到的 Top-K 集合与真实下一 token 的 Top-K 集合逐层一致性平均达 98.74%（Qwen3-8B/GSM8K 实验）。

2. **完全异步的后台流水线**
   - 每层三个独立阶段：Top-K 预测 → KV 选择 → KV 传输，分别放在独立 CUDA stream 上，通过 CUDA events 维护层内依赖。
   - 层间任务相互独立，可并发执行（第 l+1 层预测、第 l 层选择、第 l−1 层传输同时进行），只有在本层下一步注意力开始前才等待该层的 KV transfer 完成。
   - 流水线稳态周期满足 `T_pipe = max(T_pred, T_select, T_transfer) ≤ Δprefetch = T_step / N_layer`，瓶颈为最慢阶段（通常是 KV 传输）。

3. **Delta 选择与封顶淘汰（Capped Eviction）**
   - KV 选择先求预测集与常驻集的交集，常驻块不产生 PCIe 流量。
   - 对常驻但不属于预测集合的块按“最近最久未选择”排序，作为淘汰候选；每个非驻留新块与一个淘汰块配对，形成传输计划。
   - 每个 KV 头每步新进入块数不超过上限 C（由 fetch ratio 控制），从而将单步 PCIe 流量严格限制在解码时间预算内（`C_token = B_link * T_decode`）。

4. **KV 管理与调度**
   - 在既有 GPU/CPU page table 之上增加一层 **head-wise 逻辑到逻辑映射**：不同 KV 头可以维护不同稀疏块集合，且不需要改变原有 page table，兼容 PagedAttention/FlashAttention 执行路径，也支持多 GPU tensor parallelism 下各 GPU 独立更新本地头映射。
   - 请求开始时按密集方式运行，上下文超过稀疏化阈值后复制全量 KV 到 CPU 内存，GPU 只保留选定历史块和局部窗口，支持密集/稀疏请求同批混跑。

5. **远程部分获取（Remote Partial Fetching, RPF）——面向 PD 分离**
   - **部分传输**：prefill 节点额外执行一次解码步生成首个生成 token 的 query，据此选取首步 Top-K KV 块，加上压缩键缓存与 draft token 的 KV 状态，在接待（admission）时只传这三部分，而不是全量 KV；prefill GPU 资源可提前释放。
   - **网络预取**：解码过程中 Top-K 漂移导致缺失块时，由后台流水线从 prefill 节点 staging pool 远程读取到 decode 节点，再转入 GPU；缺失请求按层聚合批量传输，且每块最多跨网络一次。
   - 效果：每请求 KV 传输从“一次性全量突发”变为“随解码分布的需求驱动流”，decode 节点 DRAM 只保留需求填充的子集。

## 6. 论文的主要结论与发现

1. **预测精度足够高**：2048-token KV 预算下，OasisKV 精度损失 ≤ 0.7 点（推理任务大多在 0.1–0.7 点，长输入约 0.4–0.6 点）。
2. **吞吐显著提升**：真实 AIME24 推理负载上，Qwen3-8B 达 1.69×（2083 vs 1235 tok/s，精度仅降 0.1 点）；Qwen3-235B TP8 达 1.20×；合成多 GPU 长上下文最多 2.1×。
3. **PD 分离优势明显**：吞吐约为 dense 的 2.1–2.3×；远程部分获取使每请求 admission KV 减少 6.5–9.7 倍，decode 节点主机内存占用减少 2.2–2.6 倍，且网络流量分布更均匀。
4. **带宽而非注意力计算是解码吞吐的硬约束**：fetch cap 消融显示吞吐随每步 PCIe 流量变化 2.6 倍，精度几乎不变（74.9→77.4），证明联网带宽饱和后“搬更多字节并不能买来吞吐”，默认 fetch ratio 0.05 为最佳操作点。
5. **稀疏性能提升来源于容量与延迟双效应**：小 batch 因 2K 工作集降低 attention 计算而 TPOT 更短；大 batch 因 KV 内存有界而能支撑更高并发（16K 下 90–95 并发 vs dense 22），从而保持吞吐增长。

## 7. 优点

- **新颖且实用的预测信号**：复用投机解码的 draft token 作为前瞻信号，无需额外训练专用 predictor，也不要求模型架构配合，兼容日益普及的 SD 推理路径。
- **系统设计完整、工程落地扎实**：基于生产级 vLLM 实现，支持多 GPU（TP）、PD 分离、多级内存管理、密集/稀疏混合批处理；head-wise 映射层很好兼容现有 PagedAttention/FlashAttention 流程。
- **优雅地处理了流水线同步问题**：层间独立的异步流水线 + CUDA event 依赖控制，使后台预取延迟被完全隐藏，流水线周期受最慢阶段约束的公式简洁有力。
- **量化了带宽瓶颈并给出可调旋钮**：fetch cap/eviction 策略直接连接系统吞吐与精度，消融实验揭示“带宽饱和后继续传输无收益”的关键现象，为运维调参提供依据。
- **远程部分获取方案有价值**：从“整缓存搬家”变为“按需求远取”，既减少 TTFT 又降低 decode 节点 DRAM 压力，对 PD 分离架构有直接借鉴意义。

## 8. 不足与局限

- **精度覆盖存在盲区**：LongBench v2 的 short split 上有明显下降（Qwen3-8B：−1.11，Llama-3.1：−1.67），说明短上下文场景下稀疏化收益有限、风险更高；GPQA 上 pass@4/avg@4 也略有降低。
- **未真正启用投机解码的加速收益**：当前 draft token 仅用于预测并强制拒绝，白白付出草稿模型推理开销，作者也将其列为未来工作；若与 SD 联合使用，可能进一步摊薄开销。
- **受限于互联硬件与规模**：实验集中在 H100 + PCIe Gen5 + 400G RoCE 配置；未验证 NVLink-C2C、CXL、RDMA 等更高速或更异构的互联，也未做大规模多节点集群压力测试。

## 8. 不足与局限（续完）

- **精度覆盖存在盲区**：LongBench v2 的 short split 上有明显下降（Qwen3-8B：−1.11，Llama-3.1：−1.67），说明短上下文场景下稀疏化收益有限、风险更高；GPQA 上 pass@4/avg@4 也略有降低。
- **未真正启用投机解码的加速收益**：当前 draft token 仅用于预测并强制拒绝，白白付出草稿模型推理开销，作者也将其列为未来工作；若与 SD 联合使用，可能进一步摊薄开销。
- **受限于互联硬件与规模**：实验集中在 H100 + PCIe Gen5 + 400G RoCE 配置；未验证 NVLink-C2C、CXL、RDMA 等更高速或更异构的互联，也未做大规模多节点集群压力测试。
- **Qwen3-235B 在低并发下不如 dense**：MoE 模型 KV 占 HBM 比例较小，稀疏化省下的容量有限，而每步预取/预测开销仍存在，导致小 batch 下 TPOT 反而更高。

## 9. 总体评价与适用场景

- **总体评价**：OasisKV 是一篇典型的系统方向（Systems for ML）论文，亮点在于将“投机解码的草稿 token”这一已有信号重新诠释为 KV 预取的预测源，并围绕它构建了完整的异步流水线、淘汰策略和 PD 分离扩展。整体工作质量高、工程实现完整、实验充分，对 HBM 容量墙问题给出了一个立即可用且无需额外训练的纯系统级答案；预测一致率、流水线周期公式与 fetch cap 消融共同构成了一个自洽且有说服力的论证闭环。
- **适用场景**：长上下文、高并发的 LLM 推理服务（Agent 工作负载、编程代理、长文档处理），尤其是已经部署 EAGLE 类投机解码的推理栈，以及 PD 分离架构下的长上下文服务。在 KV 占 HBM 主导地位的 dense 模型上收益最大；在 KV 占比小的 MoE 模型或短上下文场景下需谨慎评估性价比。
- **可推广的价值点**：OasisKV 的“预测信号复用 + 有界常驻工作集 + 异步分层流水线 + 远端按需拉取”四件套，可推广到 CXL 内存池、异构存储分层、多租户调度等更广泛的以内存为中心的推理架构设计中，具有超越本文场景的方法论意义。
