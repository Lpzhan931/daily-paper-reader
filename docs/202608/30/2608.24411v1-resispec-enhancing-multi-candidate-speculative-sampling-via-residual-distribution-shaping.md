## 摘要
大型语言模型（LLM）服务的效率从根本上受限于自回归解码的序列性。推测解码（SD）通过使用轻量级草稿模型推测未来token，然后由LLM在单次并行前向传递中验证这些token，从而缓解这一问题。为了进一步提升效率，多候选方案提出多样化的候选集以增加token被接受的可能性。然而，我们表明这些方案受到“残差漂移”（Residual Drift）的瓶颈制约：即初始候选被拒绝导致残差目标分布偏离草稿模型的预测。这种偏移使后续候选失效，并迫使系统进行昂贵的重采样。为解决此问题，我们提出ResiSpec，一个在验证过程中策略性地重塑提议分布以将残差目标质量锚定在草稿模型高置信区域的框架。通过在不牺牲输出精确性的前提下数学上重新对齐验证过程，ResiSpec防止了候选过时，并在最先进的多候选方法基础上实现了高达1.92倍的加速。代码可在https://github.com/Czzzk/Resispec获取。

## Abstract
The efficiency of Large Language Model (LLM) serving is fundamentally limited by the sequential nature of autoregressive decoding. Speculative Decoding (SD) mitigates this by using a lightweight draft model to speculate future tokens, which are then validated by the LLM in a single parallel forward pass. To further boost efficiency, multi-candidate schemes propose diverse candidate sets to increase the likelihood of token acceptance. However, we show that these schemes are bottlenecked by Residual Drift: a phenomenon where the rejection of initial candidates causes the residual target distribution to diverge from the draft model's predictions. This shift renders subsequent candidates ineffective and forces the system into expensive resampling. To resolve this, we propose ResiSpec, a framework that strategically reforms the proposal distribution during verification to anchor the residual target mass within the draft model's high-confidence regions. By mathematically re-aligning the verification process without compromising output exactness, ResiSpec prevents candidate obsolescence and achieves up to 1.92$\times$ speedup over state-of-the-art multi-candidate methods. Code is available at https://github.com/Czzzk/Resispec.

## 1. 论文的核心问题与整体含义

- 大型语言模型（LLM）的自回归解码是顺序生成的，每一步都必须读取不断增长的 KV Cache，导致严重的 I/O 瓶颈，GPU 算力无法被充分利用。
- 推测解码（Speculative Decoding, SD）通过“轻量草稿模型先猜、目标 LLM 并行验证”的方式打破顺序依赖，是当前主流的无损加速方案。
- 多候选 / 树形推测解码（如 SpecInfer、Sequoia、EAGLE）通过一次前向验证多个候选 token 来进一步扩大搜索空间，但论文发现其存在一个关键的扩展瓶颈：
  - 当某个候选被拒绝后，为了保证无偏采样，目标分布必须更新到“残差分布”（residual distribution）。
  - 残差分布天然集中在草稿模型**预测置信度低或“盲区”**的区域；而后续候选又是从原始草稿分布中预先采样的，两者产生“支持集失配”。
  - 论文将此现象命名为 **Residual Drift（残差漂移）**：早期拒绝会导致后续候选迅速失效，迫使系统进入昂贵的重采样，使多候选方法的边际收益随候选数量增加而快速下降。
- 论文的核心含义是：多候选推测解码的扩展瓶颈不是并行计算能力不足，而是**验证阶段的采样逻辑**没有与草稿模型的高置信区域保持对齐。解决该问题可以在不改变输出分布的前提下显著提升推理效率。

## 2. 论文提出的方法论

### 核心思想

- 论文提出 **ResiSpec（Residual Distribution Shaping）**，核心思路是在验证阶段引入一个**辅助代理分布 k(x)**，用它替代原始草稿分布 q(x) 来构建接受概率和残差分布。
- 如果某个候选被拒绝，ResiSpec 会主动“塑造”新的残差分布，使其仍然与草稿分布 q(x) 的高密度区域保持接近，从而保证后续预采样候选仍然有效。
- 这种重塑是在验证阶段进行的，不增加额外的模型前向调用，也不改变目标模型输出的边际分布。

### 关键技术细节

- 代理分布定义为：
  - k(x) = p(x) − r(x) + s(x)
  - 其中 r(x) 是预留给残差分布的未归一化质量，s(x) 是松弛函数，用来保持归一化。
  - 约束条件：s(x) · r(x) = 0（支撑集不相交）；Σ k(x) = 1；在采样点 x0 处满足局部对齐 k(x0) = q(x0)。
- 残差分布写作：
  - p'(x) = r(x) / Z，其中 Z = Σ r(x)。
  - 目标是最大化 p'(x) 与 q(x) 的重叠，即最小化 L1 距离。
- 理论上理想的残差形状是 r(x) = Z·q(x)，但受容量约束 Z ≤ min_{x:q(x)>0} p(x)/q(x) 限制，实际中往往退化不可行（长尾 token 会使上界趋近于零）。
- 因此 ResiSpec 采用“最小预算”启发式：
  - Z = max(Z*, |q(x0) − p(x0)|)
  - 在拒绝点 x0 处，先通过局部注入 s(x0) = q(x0) − p(x0) 完成对齐；
  - 随后将残差质量按容量约束裁剪并重新分配（water-filling），最终构造出代理分布 k。
- 验证流程（Algorithm 1）：
  1. 初始化残差 R = P，草稿分布 D = Q；
  2. 逐个采样候选 x_i；
  3. 按概率 min(1, R(x_i)/D(x_i)) 接受；
  4. 若拒绝，调用 GetProxy 构造代理分布 K；
  5. 更新残差 R = norm(max(R − K, 0))；
  6. 若全部拒绝，从最终残差分布中重采样。
- 论文给出了严格的**无偏性证明**（Theorem 1）：只要代理分布在验证点与草稿分布对齐，最终输出的边际分布严格等于目标分布 p(x)，不会引入采样偏差。

## 6. 论文的主要结论与发现

- 多候选推测解码的扩展瓶颈来自 **Residual Drift**：候选被拒后，残差分布会漂移到草稿模型的盲区，导致后续候选失效。
- ResiSpec 通过引入代理分布 k(x) 重塑验证过程中的残差，使残差分布保持在草稿模型高密度区域内，从而避免候选过时。

- 实验上，ResiSpec 相比 SpecInfer、Sequoia、EAGLE 等基线在相同配置下均能提升接受长度和吞吐量，最高加速 1.92×。
- ResiSpec 是验证阶段的通用 add-on，可以与不同的候选生成方法（如 EAGLE）和树构建方法（如 Sequoia）组合使用。
