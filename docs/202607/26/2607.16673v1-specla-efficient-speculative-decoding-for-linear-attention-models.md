## 摘要
线性注意力模型用循环状态替代不断增长的KV缓存，但自回归解码仍逐个读取、更新和写入这些状态。推测性解码可通过在单次目标前向传播中验证多个草拟令牌来降低这一成本，然而现有推测系统专为Transformer的KV缓存设计。对于有状态线性注意力目标，验证必须遵循跨链和分支的循环依赖，接受必须仅更新被接受的状态轨迹，且草拟器必须避免提交浪费有状态验证工作的候选。本文提出SpecLA，一种面向有状态线性注意力模型的推测性解码运行时。SpecLA采用拓扑感知内核验证链和树，存储验证过程中产生的紧凑因子以恢复被接受的状态，并使用置信剪枝加上与目标对齐的EAGLE风格草拟器，为验证器提供有用的候选。在NVIDIA H100上以公开的GDN-1.3B为目标，SpecLA相比自回归解码实现了高达1.70倍的端到端加速。

## Abstract
Linear-attention models replace the growing KV cache with recurrent states, but autoregressive decoding still reads, updates, and writes these states one token at a time. Speculative decoding can reduce this cost by verifying several draft tokens in one target pass, yet existing speculative systems are designed for Transformer KV caches. For stateful linear-attention targets, verification must follow recurrent dependencies across chains and branches, acceptance must update only the accepted state trajectory, and the drafter must avoid submitting candidates that waste stateful verification work. This paper presents SpecLA, a speculative decoding runtime for stateful linear-attention models. SpecLA verifies chains and trees with topology-aware kernels, stores compact factors produced during verification to recover accepted states, and uses confidence pruning plus a target-aligned EAGLE-style drafter to feed useful candidates to the verifier. On an NVIDIA H100 with a public GDN-1.3B target, SpecLA achieves up to 1.70x end-to-end speedup over autoregressive decoding.

# 论文总结：SpecLA: Efficient Speculative Decoding for Linear-Attention Models

## 1. 核心问题与整体含义（研究动机和背景）
- **问题背景**：线性注意力模型（如 Gated DeltaNet）使用固定大小的循环状态替代不断增长的 KV 缓存，但自回归解码仍需要逐个 token 读取、更新和写入该循环状态，导致每次解码都涉及密集的状态读写（约 2 MiB/layer），内存带宽成为瓶颈。推测解码（Speculative Decoding）在 Transformer 上已广泛采用，但现有推测系统基于 KV 缓存设计，不适用于有状态的线性注意力模型。
- **核心困难**：
  - 验证阶段：循环状态在推理时需保持跨链和分支的依赖，现有解码核或预填核无法高效处理短链/树形候选。
  - 接受阶段：无法像 Transformer 那样通过截断 KV 缓存后缀来丢弃被拒 token；需要显式恢复被接受状态，避免污染循环状态。
  - 草拟阶段：草拟器需要与循环目标动态对齐，且需避免提交低置信度候选浪费验证工作。
- **论文目标**：首次为有状态线性注意力模型设计高效的推测解码运行时 SpecLA，实现端到端加速。

## 2. 方法论
### 核心思想
SpecLA 保持经典的 draft–verify–accept 循环，但针对状态模型做出三方面关键设计：
- **拓扑感知验证（Topology-Aware Verification）**：根据候选拓扑（链或树）选择最优执行路径。
- **接受因子状态管理（Accepted-Factor State Management）**：仅缓存验证中产生的紧凑因子（如 key、value、decay 系数），而非完整状态或 token 日志，避免快照开销或重算开销。
- **目标对齐草拟与剪枝（Target-Aligned Draft Integration）**：采用 EAGLE 风格的草拟器，基于目标循环特征训练；并通过置信度阈值剪枝低概率路径，减少无效验证。

### 关键技术细节
1. **拓扑感知验证内核**：
   - **状态驻留串行内核（State-Resident Serial Kernel）**：按层优先组织计算，将循环状态分片（V 维度平铺）保留在 SRAM 中，实现多个相邻 token 在相同层内连续验证，避免 HBM 往返。
   - **树掩码并行内核（Tree-Masked Parallel Kernel）**：构造树依赖掩码 `M_tree`，通过 Delta-rule 的 UT 分解实现在一次并行前向中完成所有树节点验证，保持精确的祖先依赖。
   - **链分解混合内核（Chain-Decomposed Hybrid Kernel）**：将树拓扑分解为依赖链（基于重轻分解），对每个链使用串行内核，链间在边界状态准备好后并行执行。平衡串行低开销和并行暴露度的优势。

2. **接受因子状态管理**：
   - **因子缓存（Factor Buffering）**：验证时记录每个候选的紧凑因子（key、value、decay 因子、Delta-rule 系数等，约 16 KiB/layer for L=8），而非完整状态（2 MiB/layer）。接受后仅使用相应因子做轻量级 Delta 构造更新状态。
   - **延迟状态更新（Delayed State Update）**：不立即在每次接受后执行状态更新，而是将接受因子缓存到“待定缓冲区”，在下一轮验证内核开始时融合更新，避免单独的状态读写往返。

3. **目标对齐草拟与剪枝**：
   - **置信指导树剪枝**：根据从根到节点的累计对数概率 `q(v)` 设置窗口阈值 `τ_tree`，仅保留 `q(v) >= q* - τ_tree` 的节点，并保证祖先封闭性。再通过预算 `T` 截断。
   - **EAGLE 风格草拟器**：训练一个轻量 Transformer 式草稿层，输入特征来自目标线性注意力模型的循环状态，使草拟分数反映目标动态。保持顺序注意而非循环，因为短小窗口下注意开销可忽略。
