## 摘要
大型语言模型（LLM）的日益部署加剧了自回归解码的计算和内存瓶颈，其中低计算强度和带宽受限的内核主导了推理成本。权重剪枝提供了一种有前景的补救措施，但现有方法仍局限于静态剪枝（SP）——永久移除冗余权重但缺乏自适应性，或动态剪枝（DP）——适应输入稀疏性但引入运行时不规则性。本文提出SPDP，一个统一的稀疏推理框架，将非结构化SP与输入自适应DP相结合，用于GPU上的高效LLM推理。SPDP协同设计了一种新的分块列式位图压缩（Tiled-CBC）格式和两个互补的GPU内核：（1）一个CUDA核spMspV内核，具有混合激活感知动态共享内存位图解码（HAD-SMBD），用于细粒度、运行时激活跳过；（2）一个针对预填充计算优化的Tensor-Core SpMM内核。这种联合格式-内核设计协调了静态和动态稀疏性，在LLM推理的两个阶段保持带宽高效的内存访问和高计算强度。在推理优化GPU上的综合评估表明，SPDP相比最先进的稀疏框架（如SpInfer）实现了1.24倍至1.37倍的平均加速（最高2.51倍），同时以高达25%的更高稀疏度匹配困惑度。SPDP推进了推理效率-质量帕累托前沿，表明统一的静态-动态剪枝可以在大规模LLM服务中带来显著的吞吐量和每瓦性能提升。

## Abstract
The increasing deployment of large language models (LLMs) has magnified the computational and memory bottlenecks of autoregressive decoding, where low compute intensity and bandwidth-bound kernels dominate inference cost. Weight pruning offers a promising remedy,   but existing methods remain confined to either static pruning (SP), which permanently removes redundant weights but lacks adaptivity, or dynamic pruning (DP), which adapts to input sparsity but introduces runtime irregularity. This paper presents SPDP, a unified   sparse-inference framework that integrates unstructured SP with input-adaptive DP for efficient LLM inference on GPUs. SPDP co-designs a new Tiled-Column-wise Bitmap Compressed (Tiled-CBC) format and two complementary GPU kernels: (1) a CUDA-core spMspV kernel   featuring Hybrid Activation-aware Dynamic Shared-Memory Bitmap Decoding (HAD-SMBD) for fine-grained, runtime activation skipping, and (2) a Tensor-Core SpMM kernel optimized for prefill computation. This joint format-kernel design harmonizes static and dynamic   sparsity, maintaining bandwidth-efficient memory access and high compute intensity under both phases of LLM inference. Comprehensive evaluations on inference-optimized GPUs demonstrate that SPDP achieves 1.24x-1.37x average speedup (up to 2.51x) over state-of-the-   art sparse frameworks such as SpInfer, while matching. perplexity with up to 25% higher sparsity. SPDP advances the inference efficiency-quality Pareto frontier, showing that unified static-dynamic pruning can deliver substantial throughput and performance-per-watt   improvements in large-scale LLM serving

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：随着大语言模型（LLM）在推理、对话、摘要和代码生成等任务中的广泛应用，其推理成本日益突出。尤其是自回归解码阶段，由于每次只生成一个 token，计算强度低、内存带宽受限，成为推理性能的关键瓶颈。
- **核心矛盾**：
  - **静态剪枝（SP）**：离线移除冗余权重，永久减少模型大小和内存占用，但缺乏对输入的自适应性，可能剪掉对特定上下文重要的参数。
  - **动态剪枝（DP）**：运行时根据输入激活值自适应跳过不重要的列（激活稀疏），具有输入感知能力，但引入运行时不规则性、控制流开销，且对内存占用没有帮助。
- **核心问题**：静态剪枝与动态剪枝在理论上天然互补（SP 沿行维度压缩权重，DP 沿列维度跳过激活），但二者在 GPU 上难以直接组合——布局不匹配、元数据开销大、Tensor Core 利用率下降，导致理论稀疏收益无法转化为实际加速。
- **论文目标**：提出 **SPDP**，一个统一的稀疏推理框架，首次在同一 GPU 执行框架下同时利用静态和动态稀疏性，实现带宽高效访问和高计算强度，推进 LLM 推理的效率–质量帕累托前沿。

## 2. 方法论：核心思想与关键技术

- **核心思想**：SP 和 DP 沿正交维度发挥作用，重叠稀疏度接近理论独立乘积水平（约等于 sp × dp），联合使用可实现乘法级的总稀疏度提升，同时保持模型质量。SPDP 通过**格式–内核联合设计**（joint format–kernel co-design）将二者统一。

- **Tiled-CBC 稀疏格式**（Tiled-Column-wise Bitmap Compressed）：
  - 将权重矩阵分层划分为 GTile（如 8×4 示意）和列瓦片（256×1），列瓦片是压缩和剪枝的最小单元。
  - 列瓦片采用列主序存储，与 DP 的列级激活稀疏模式对齐，支持运行时按列跳过。
  - 存储结构由五个数组组成：**TileOffset**（GTile 索引）、**Values**（非零值）、**Bitmap**（每列 4 个 uint64_t 位图）、**ColInfo**（打包列偏移与每列非零数）、以及对齐元数据。
  - 相比 SpInfer/Flash-LLM 等面向静态剪枝的格式，Tiled-CBC 能在 DP 下直接定位激活相关的稀疏片段，无需扫描无效片段。

- **解码阶段：SPDP-spMspV 内核（CUDA 核）**：
  - 采用 `load-as-sparse, compute-as-dense`（LSCD）策略：只从全局内存加载激活相关的列瓦片，在共享内存/寄存器中重建稠密片段，用 CUDA 核执行 GEMV。
  - **HAD-SMBD（混合激活感知动态共享内存位图解码）**：是 SpInfer SMBD 的扩展，针对 DP 场景做了三点改进：(1) 列主序解码以匹配 CUDA 核 GEMV；(2) 利用 ColInfo 获取列偏移；(3) 对 DP 不激活的列直接跳过，统一静态位图解压与动态列跳过。
  - **两阶段解码**：Phase I 用 MaskedPopcount 计算线程内前缀秩并加载非零值；Phase II 复用 Phase I 信息解码同一寄存器的配对 FP16 lane，避免重复计算，降低解码开销。

- **解码阶段：细粒度异步流水线**：
  - 采用三重缓冲/独立异步组：ColInfo 加载（DP 决策元数据）、XTile 加载（激活向量）、GTile 加载（权重瓦片）三路并发。
  - 元数据预取先行、数据加载随后，形成"元数据→数据"两级预取流水线，确保只传输激活相关的列，最大化内存–计算重叠。
  - 使用 `cp.async`（LDGSTS.128）实现全局到共享内存的直接流式传输，列值按 16 字节边界填充对齐。

- **预填充阶段：SPDP-SpMM 内核（Tensor Core）**：
  - 预填充阶段仅使用 SP（因为 DP 只作用于解码），对应 SpMM 计算，使用 Tensor Core 执行。
  - 复用 Tiled-CBC 格式，无需重新格式化。
  - 额外引入**布局对齐阶段**：将列主序的 WTile 在共享内存中转换为 Tensor Core 所需的行主序操作数布局，通过 padding 方案避免共享内存 bank 冲突。
  - 消除 DP 相关阶段（如 GTile 中的列选择），但保留 XTile 加载和 XTile-to-register 传输（输入从向量变为矩阵）。

## 6. 主要结论与发现

- **SP 与 DP 互补性得到验证**：两者的重叠稀疏度接近理论独立乘积水平（sp × dp），联合修剪可实现接近预期的总稀疏度。
- **SPDP 显著优于现有框架**：
  - 内核级：在 A10G 上平均加速 1.88×（最高 3.32×）对比 cuBLAS，1.24×（最高 1.70×）对比 SpInfer；在 L4 上平均加速 2.11×（最高 3.52×）对比 cuBLAS，1.37×（最高 2.51×）对比 SpInfer。
  - 端到端：在匹配困惑度的情况下，SPDP 可实现比 SpInfer 高最多 25% 的总稀疏度，同时保持更低或相当的 TPOT。
- **模型质量保持**：组合剪枝在同等总稀疏度下困惑度低于单独的 SP 或 DP；且与 4-bit 量化兼容良好。
- **硬件效率提升**：SPDP-spMspV 相比 SpInfer 具有更高的 SM 占用率（66.0% vs 48.0%/38.2%）、更低的 bank 冲突（74 vs 3817/4491），同时保持相当的带宽利用率。
- **应用边界明确**：SPDP 针对 LLM 中等稀疏度范围（30%–60%）优化；在极高稀疏度（>90%，如 SuiteSparse）或预填充大 batch 场景下，通用稀疏内核或稠密计算仍有优势。

## 7. 优点（方法与实验设计的亮点）

- **正交性分析扎实**：通过实验定量验证 SP 与 DP 的稀疏决策独立性（重叠稀疏度 ≈ sp × dp），为此前仅停留在理论层面的"双稀疏"提供了实证基础。
- **格式–内核联合设计**：Tiled-CBC 从设计之初就同时考虑了解码阶段的运行时可寻址性和预填充阶段的 Tensor Core 兼容性，避免了重复格式和转换开销。
- **针对实际硬件瓶颈的精细优化**：
  - 使用 `cp.async` 和三组独立异步组实现内存–计算深度重叠。
  - HAD-SMBD 通过两阶段解码复用一次性获取的列元数据，避免重复 Popcount。
  - 布局对齐阶段使用 padding 方案消除共享内存 bank 冲突。
- **Roofline 建模贯穿始终**：从理论分析到实践验证皆以计算强度（CI）为核心指标，架构逻辑清晰。
- **实验细致**：同时覆盖模型质量（5 个下游任务）和系统性能（3 种 GPU 平台、多种矩阵形状），并包含硬件级剖析（Nsight Compute）。
