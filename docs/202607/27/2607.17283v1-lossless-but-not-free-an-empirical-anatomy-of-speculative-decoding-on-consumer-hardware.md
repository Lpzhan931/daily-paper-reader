## 摘要
大语言模型的单流自回归解码受限于内存带宽：每个生成的token需要对目标模型进行一次完整的前向传播，且连续传播无法并行化。推测解码重构了这一计算过程：一个小的草稿模型自回归地提出K个token，目标模型在一次批处理传播中对所有token进行评分，而拒绝采样规则可证明地保持目标模型的输出分布。我们提供了一个从头开始、与设备无关（CUDA/MPS/CPU）的实现，并在消费级Apple Silicon笔记本上，针对五种草稿/目标后端配置进行了实证研究。在三个层次上验证了分布等价性，最终对每种方法约9200个真实模型token进行了双样本检验（χ²=162.5，自由度=200，p=0.976），并精确达到了贪心序列一致性。最佳配置在K=6时实现了实测1.61倍的实际时间加速比，接受率曲线从K=1时的69.7%下降到最优点的37.8%，而五种配置中有三种出现减速，原因要么是草稿模型未能超过小型目标模型的速度，要么是量化的Metal后端串行执行了“并行”验证——我们分离并量化了这一效应。失败与成功同样具有启发性：只有当验证真正是批量并行且草稿/目标延迟差距真实存在时，推测解码才有价值。

## Abstract
Single-stream autoregressive decoding of large language models is bound by memory bandwidth: each generated token requires one full forward pass through the target model, and successive passes cannot be parallelized. Speculative decoding restructures this computation: a small draft model proposes $K$ tokens autoregressively, the target model scores all of them in one batched pass, and a rejection-sampling rule provably preserves the target model's output distribution. We present a from-scratch, device-agnostic (CUDA/MPS/CPU) implementation and an empirical study across five draft/target backend configurations on a consumer Apple-silicon laptop. Distribution equivalence is verified at three levels, culminating in a two-sample test over roughly 9,200 real-model tokens per method ($χ^2 = 162.5$, dof $= 200$, $p = 0.976$) and exact greedy-sequence agreement. The best configuration reaches a measured $1.61\times$ wall-clock speedup at $K=6$, on an acceptance profile declining from 69.7% at $K=1$ to 37.8% at the optimum, while three of five configurations decelerate, either because the draft fails to out-speed a small target or because the quantized Metal backend executes "parallel" verification serially, an effect we isolate and quantify. The failures are as instructive as the successes: speculative decoding pays off only when verification is genuinely batch-parallel and the draft/target latency gap is real.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）的自回归解码受限于内存带宽，每个生成的 token 都需要一次完整的前向传播，且无法并行化。这导致在消费级硬件（如 Apple Silicon 笔记本）上单流推理速度慢。
- **研究动机**：推测解码（Speculative Decoding）通过引入一个小的草稿模型（draft model）快速提出 K 个 token，再由目标模型（target model）并行验证，理论上可保持输出分布不变并加速推理。然而，现有研究大多在服务器级 GPU 上进行，该算法在消费级硬件上的实际加速效果尚不明确，且可能因系统实现细节而失效。
- **整体含义**：本文旨在从零实现一个设备无关的推测解码引擎，并在真实的消费级硬件（Apple M3 笔记本）上进行全面实证分析，揭示其成功与失败的条件，为实际部署提供指导。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- 利用一个快的草稿模型自回归生成 K 个候选 token，然后目标模型在一次前向传播中批量计算所有候选位置的概率分布，通过拒绝采样（rejection sampling）决定接受哪些 token，并保证输出分布与直接使用目标模型采样完全一致。
- 算法流程（一轮）：
  1. **草稿阶段**：从草稿模型 \(q\) 自回归采样 K 个 token \(x_1,...,x_K\)，同时保留每一步的完整分布 \(q_i\)。
  2. **验证阶段**：目标模型 \(p\) 在上下文 + 全部 K 个 draft token 上执行一次前向传播，得到 K+1 个分布 \(p_1,...,p_{K+1}\)（包括一个 bonus 分布）。
  3. **接受/拒绝**：从 i=1 到 K，采样均匀随机数 \(r_i\)，接受条件为 \(r_i < \min(1, p_i(x_i)/q_i(x_i))\)。若在位置 a+1 第一次拒绝，则丢弃后续 draft，从调整后的分布 \(p'_{a+1}(x) \propto \max(0, p_{a+1}(x)-q_{a+1}(x))\) 中采样一个 token 作为替代。
  4. **奖励 token**：若所有 K 个 draft 都被接受，则额外从 \(p_{K+1}\) 采样一个 token（免费）。
- **关键技术细节**：
  - 所有采样算术（温度缩放、接受测试、调整分布构造、多项采样）在 CPU 上以 float32 执行，保证跨设备可复现。
  - 实现了设备无关的模型抽象接口（SpecModel），支持 Hugging Face Transformers (fp16)、llama.cpp GGUF (4/8-bit) 后端，可在 CUDA/MPS/CPU 上运行。
  - 严格的 KV 缓存同步与回滚逻辑，确保缓存一致性。
  - 通过三层次验证保证分布等价性：① 合成分布上的统计检验（50000 次试验，KL 散度 ≤ 3.5×10⁻⁴）；② 确定性模拟模型上的全解码器测试（χ² p=0.029）；③ 真实模型上的双样本检验（约 9200 token/方法，χ² p=0.976）以及贪心序列比特一致性。

## 3. 实验设计

- **硬件与软件**：Apple Silicon (M3 类) 笔记本，18 GB 统一内存，macOS 26.5；Python 3.12.2, PyTorch 2.12.1 (MPS 后端), Transformers 5.13.0, llama-cpp-python 0.3.33 (Metal)。
- **模型**：使用 Qwen2.5 系列（共享分词器）：
  - 草稿模型：Qwen2.5-0.5B（fp16 或 q8_0 量化）
  - 目标模型：Qwen2.5-1.5B, 3B, 7B（fp16 或 q4_k_m 量化）
- **五种配置**（draft → target，后端）：
  - primary: 0.5B fp16 (MPS) → 1.5B q4_k_m (Metal)
  - all_gguf: 0.5B q8_0 (Metal) → 1.5B q4_k_m (Metal)
  - stretch_7b: 0.5B q8_0 (Metal) → 7B q4_k_m (Metal)
  - mixed: 0.5B q8_0 (Metal) → 1.5B fp16 (MPS)
  - mixed_3b: 0.5B q8_0 (Metal) → 3B fp16 (MPS)
- **基准（baseline）**：直接使用目标模型自回归解码，与推测解码对比吞吐量（token/s）、首 token 时间（TTFT）、接受率等。
- **Prompt 集**：固定 100 条指令风格 prompt（长度 48–788 字符），涵盖解释、摘要、推理、编码、如何做、比较、创意等类别。主实验取前 30 条（2 条预热，28 条记录），生成 128 个新 token，温度 T=0.8，K=4。K-sweep 使用 10 条 prompt（2 条预热），96 token，K ∈ {1,2,4,6,8,10,12}。等价性检验使用 100 条 prompt × 100 token，T=1.0。
- **对比方法**：不同配置之间的横向对比；未与 Medusa、自推测等变体比较（聚焦两模型原始形式）。

## 4. 资源与算力

- **硬件**：仅一台 Apple M3 笔记本（18 GB 统一内存），无 GPU 集群。论文明确说明所有测量在此单一消费级设备上完成。
- **训练**：无需训练，仅推理阶段测量。

## 5. 实验数量与充分性

- **主实验**：5 种配置 × 28 条 prompt（各生成 128 token），报告平均值和标准差。
- **K-Sweep**：最佳配置 mixed_3b 在 K=1..12 共 7 个点，每个点 8 条 prompt（2 预热，6 记录），生成 96 token。
- **等价性检验**：
  - Level 1: 4 种合成分布 × 50000 次试验。
  - Level 2: 确定性模拟模型上 1000 次生成 × 25 token，以及贪心比特一致测试（K=1,2,4,8）。
  - Level 3: 真实模型上 100 prompt × 100 token，共约 9200 token/方法；贪心测试 5 prompt × 最多 200 token。
- **充分性评价**：
  - **优点**：三层次验证非常严谨，统计检验 p 值高，确认分布等价；K-sweep 覆盖了典型范围；对五种配置的对比揭示了不同后端的影响。
  - **不足**：
    - 仅使用单一 prompt 集，可能未覆盖所有领域（如对话、长文本）。
    - K-sweep 的 prompt 数量较少（6 条记录），相邻 K 的标准差重叠较大，作者自认应视为持平而非显著差异。
    - 未包含 8B 级目标模型的本地实测（仅提供 Colab 脚本）。
    - 未与 Medusa、自推测等其他加速方法对比。
    - 未进行消融实验（如不同量化级别、不同 draft 大小等）。

## 6. 主要结论与发现

1. **分布等价性成立**：三层次检验确认推测解码输出与纯目标模型采样统计上不可区分（χ² p=0.976）。
2. **最大加速比**：最佳配置 mixed_3b（0.5B draft → 3B target，MPS fp16 验证器）在 K=6 时达到 1.61 倍加速；K∈[2,6] 形成平台（1.52-1.61×）。
3. **三分之二的配置反而减速**：
   - primary 和 all_gguf 的验证器基于 llama.cpp Metal 后端，其“并行”验证在 batch size 2-7 时实际是串行的（每个位置执行矩阵-向量乘法，重复读取权重），导致验证成本线性增长。
   - stretch_7b 虽然有理想的 draft/target 延迟差距，但因 Metal 验证器串行化，仍减速。
   - mixed 和 mixed_3b 使用 MPS 后端（torch GEMM），验证批量并行性好（5 token 仅比单 token 多 20% 时间），因此加速。
4. **接受率随位置递减**：位置 1 接受率 66-75%，位置 4 仅 24-36%，导致增加 K 的边际收益递减。
5. **采样开销可忽略**：CPU float32 采样仅占 2.2% 的 wall-time。
6. **关键条件**：推测解码有效的前提是 (a) 验证真正批量并行，(b) draft 步延迟显著小于 target 步延迟。

## 7. 优点

- **从零实现，设备无关**：实现了可运行于 CUDA/MPS/CPU 的统一框架，便于复现和扩展。
- **严谨的分布等价性验证**：三层次检验（从合成分布到真实模型）确保实现正确性，并提供统计证据。
- **系统性失败分析**：不仅报告成功，还深入诊断了减速的两种根本原因（串行验证、draft 太慢），这些洞察对实践有重要指导价值。
- **透明且可复现**：所有代码、prompt、配置、结果 JSON 均开源；每个实验值可追溯到具体 artifact。
- **关注消费级硬件**：弥补了现有研究主要基于服务器 GPU 的空白。

## 8. 不足与局限

- **硬件范围有限**：仅针对单台 Apple M3 笔记本，结论不一定直接推广到其他消费级设备（如 Intel/NVIDIA 组合、不同架构）。

- **未探索自适应 K**：仅固定 K，未实验动态调整策略。

- **内存占用为非递减上限**：未精确测量各配置的 KV 缓存开销。
