## 摘要
线性注意力模型用循环状态取代了不断增长的键值缓存，但自回归解码仍然每次只读取、更新和写入一个令牌的状态。推测解码可以通过在一次目标传播中验证多个草案令牌来降低这一成本，然而现有的推测系统是为Transformer的键值缓存设计的。对于有状态的线性注意力目标，验证必须遵循跨链和分支的循环依赖关系，接受必须仅更新被接受的状态轨迹，并且草案生成器必须避免提交会浪费有状态验证工作的候选方案。本文介绍了SpecLA，一个针对有状态线性注意力模型的推测解码运行时。SpecLA使用拓扑感知内核验证链和树，存储验证过程中产生的紧凑因子以恢复接受的状态，并使用置信度剪枝加上目标对齐的EAGLE风格草案生成器，为验证器提供有用的候选方案。在配备NVIDIA H100、使用公开GDN-1.3B目标的平台上，SpecLA相比自回归解码实现了高达1.70倍的端到端加速。

## Abstract
Linear-attention models replace the growing KV cache with recurrent states, but autoregressive decoding still reads, updates, and writes these states one token at a time. Speculative decoding can reduce this cost by verifying several draft tokens in one target pass, yet existing speculative systems are designed for Transformer KV caches. For stateful linear-attention targets, verification must follow recurrent dependencies across chains and branches, acceptance must update only the accepted state trajectory, and the drafter must avoid submitting candidates that waste stateful verification work. This paper presents SpecLA, a speculative decoding runtime for stateful linear-attention models. SpecLA verifies chains and trees with topology-aware kernels, stores compact factors produced during verification to recover accepted states, and uses confidence pruning plus a target-aligned EAGLE-style drafter to feed useful candidates to the verifier. On an NVIDIA H100 with a public GDN-1.3B target, SpecLA achieves up to 1.70x end-to-end speedup over autoregressive decoding.

# SpecLA: 面向线性注意力模型的高效推测解码——论文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：线性注意力模型（如 Gated DeltaNet, GDN）用固定大小的循环状态替代 Transformer 中不断增长的 KV 缓存，理论上可降低长序列推理的内存压力。然而，自回归解码时每一 token 仍需读取、更新、写回一个稠密的循环状态（例如 GD-1.3B 每层 2 MiB），导致内存带宽瓶颈（算术强度 <1 FLOP/B）。推测解码通过一次目标调用验证多个草案 token 来分摊状态移动和启动开销，但现有推测解码系统专为 Transformer 的 token 索引 KV 缓存设计，无法直接适用于有状态的线性注意力模型。
- **核心挑战**：
  1. **SRAM 驻留验证**：候选 token 组成短链或树，现有单 token 解码核重复读写状态，长序列预填充核的启动成本在短窗口内无法摊销；树形候选要求祖先依赖而非完整因果依赖。
  2. **稠密状态接受**：拒绝的 token 不能像 KV 缓存那样截断后缀，需要紧凑的接受状态恢复机制，避免完整状态快照或 token 重放的高开销。
  3. **目标对齐草案生成**：草案生成器必须适应目标模型的循环动态，并剪枝低置信度路径以节省验证工作。

## 2. 方法论：核心思想与关键技术

SpecLA 在“草案构造→目标验证→接受提交”三阶段基础上，设计了三个层级的关键机制：

### 2.1 拓扑感知验证核（Level 1）
- **状态驻留串行核（Chain-Resident Serial）**：执行顺序从 token 主序改为层主序，同一层内连续处理相邻 token，使得循环状态块在 SRAM 上保持驻留；通过值维度分块（V-tiling）适配 SRAM 容量（H100 SM 仅 228 KiB，状态 2 MiB 需分块）。
- **树遮蔽并行核（Tree-Masked Parallel）**：将草案树拓扑编码为树遮蔽矩阵 \( M_{\text{tree}} \)，插入 Delta 规则的 UT 分解公式，一次性计算所有候选的 logits，保证祖先依赖而防止兄弟泄露。但全并行路径需要构建多个中间张量，短窗口下开销大。
- **链分解混合验证（Chain-Decomposed Hybrid）**：将草案树按重轻分解为若干条链，每条链内部用状态驻留串行核验证；链间当边界状态就绪时并行执行。既避免了全并行的安装开销，又利用了就绪链的并行性。

### 2.2 接受因子状态管理（Level 2）
- **因子缓冲**：验证过程中每个 token 的中间因子（键 \( k_t \)、值 \( v_t \)、衰减因子 \( \alpha_t \)、Delta 系数 \( \beta_t \)）远小于完整状态（每层 128.5 KiB vs 2 MiB，8 token 时缩小约128倍）。将这些因子缓存，接受后仅执行轻量 Delta 构造（外积与加和），避免重放 token 的完整前向计算（加速 2.74–4.28×）。
- **延迟更新**：将接受的因子保持为待定缓冲区，不立即执行状态更新；下一次验证时融合到验证核中，从 HBM 一次加载状态并应用待定因子，再继续验证当前草案，消除一次额外的状态往返（延迟减少 1.15–1.44×）。

### 2.3 目标对齐草案集成（Level 3）
- **置信度剪枝**：对每条候选路径计算累积对数概率 \( q(v) \)，保留满足 \( q(v) \geq q^\star - \tau_{\text{tree}} \) 的节点（\( \tau_{\text{tree}} \) 为全局窗口），再用 token 预算 \( T \) 截断。利用 \( q \) 的单调性自动修剪深度与宽度。
- **EAGLE 风格草案生成器**：在线性注意力目标的循环特征上训练草案层，使草案分数反映目标动态，而非使用 Transformer 特征。但仍保持 Transformer 自注意力结构（草案窗口 ≤8，低开销），避免给草案路径引入循环状态管理。

## 3. 实验设计

### 3.1 目标模型和草案模型
- **目标**：公开 GDN-1.3B 纯 Gated DeltaNet 模型，配置 \( h_v=8, d_k=d_v=256 \)，含因果深度卷积和 SiLU 门控，循环状态 FP32。
- **草案**：EAGLE 风格 GDN 草案层（Transformer 自注意力），草案长度链式8 token，树式最多16节点（top-\(k=4\)）。

### 3.2 数据集
- **混合套件**：480 条提示，覆盖对话、指令跟随、数学推理、代码生成、问答、摘要。
- **GSM8K**：1,319 条数学问题。
- **HumanEval**：164 条代码生成问题。
所有生成使用贪心解码，最多 128 新 token。

### 3.3 对比基线
- **Autoregressive**：标准逐 token 自回归解码。
- **FLA-SD**：使用相同草案但采用原生 FLA/GDN 路径的目标验证（即解码核重放或预填充核的简单复用）。
- **Chain**：使用 SpecLA 的串行验证核但仅链式草案。
- **SpecLA**（树式）：完整的链分解混合验证 + 因子缓冲 + 延迟更新 + 剪枝。
所有加速比基于实测端到端延迟计算，输出哈希与自回归全等检查。

### 3.4 额外微基准
- 树验证效率：对比串行、并行、混合三种验证核（10个示例树+6个形状分组）。

- 控制研究：合成接受概率 \( p \in \{0.5,1.0\} \) 和草案长度 \( L \in \{5,12\} \)，测量加速比；并基于 Qwen3.5-9B 投影到 9B 规模。

## 6. 主要结论与发现

1. **端到端加速**：SpecLA（树式）在混合集、GSM8K、HumanEval 分别达到 **1.42×、1.70×、1.06×** 加速比，树式优于链式（混合集 1.42× vs 1.26×）。
2. **树验证远优于逐叶回放**：链分解混合验证在 32 节点 top-4 树上达到 7.11× 加速，串行 + V-tiling 本身也优于回放 1.19–4.74×。
3. **因子缓冲 vs 重放**：将接受状态恢复延迟降低 2.74–4.28×（8 接受 token 时 35.96 ms → 13.10 ms）。
4. **延迟更新**：融合核将边界延迟降低 1.15–1.44×。
5. **接受概率决定收益**：\( p<0.7 \) 时加速比可能低于1×；\( p=0.8 \) 以上才稳定正收益；通过目标对齐草案和剪枝可提高实际接受率至 0.73–0.81（混合集/GSM8K）。

## 7. 优点

- **问题定位精准**：首次系统分析线性注意力模型在推测解码下的三个核心挑战（SRAM、状态回退、草案对齐），并给出针对性解决方案。
- **方案创新性强**：
  - 层主序 V-tiling 串行核巧妙利用已知草案序列，将状态读取次数从 O(L) 降为 O(1)。
  - 链分解混合验证在并行度和启动开销之间取得平衡，代码行数少但效果好。
  - 因子缓冲利用线性注意力更新公式的可分解性，是一种“中间表示复用”的优雅设计。
- **实现兼顾效率与正确性**：所有自定义核经过 FP32 全等价验证；输出哈希保证分布一致。
- **实验设计务实**：除了端到端，通过微基准和控制研究剥离了验证、状态管理、草案质量的影响，有助于理解各组件贡献。

## 8. 不足与局限

- **模型规模单一**：仅测试 1.3B 纯 GDN 模型，更大模型（如 7B/70B）或混合架构（含 Transformer 层）未评估，结论通用性受限。
