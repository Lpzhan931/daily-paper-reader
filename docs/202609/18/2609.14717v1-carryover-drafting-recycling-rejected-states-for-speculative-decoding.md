## 摘要
推测解码通过并行验证多个草拟 token 来加速 LLM 推理，使得单次目标模型前向传播即可接受多个 token。从构造上，验证过程会为被接受和被拒绝的 token 都计算表示。然而，传统草拟器仅保留被接受 token 的表示，使得验证器在拒绝 token 上花费的大量计算实际上被浪费。我们发现，目标前向过程中产生的这些被丢弃隐藏状态保留了关于未来 token 的有用信息，可改进后续草拟。然而，实现这一机会面临两个不同挑战。在推理时，回收开销会增加草拟延迟，削弱由接受长度增加带来的加速。在训练时，标准并行草拟器训练不会产生与推理对齐的拒绝状态，而通过顺序 rollout 获取它们会牺牲跨训练位置的并行性。我们提出 Carryover Drafting，它解决了这两个挑战。Carryover 将被拒绝的目标隐藏状态回收为临时 KV 上下文，使草拟器能够选择性地关注它们。它复用草拟器现有接口，仅添加一个可学习嵌入来区分被拒绝状态与已提交上下文。额外的 KV 上下文在每轮草拟时被替换，使其长度以一个提议块为界。我们提出并行 draft--verify--draft 训练，使草拟器接触到与推理对齐的拒绝状态，同时保持跨训练位置的并行性。在 DFlash 以及一个源自 DSpark 的半自回归草拟器上、跨两个目标模型的实验表明，这一简单的 Carryover 机制相比相应基线将平均接受长度提高了 6.5--14.7%，将端到端 vLLM 加速提高了 7.9--14.4%，在翻译任务上加速增益达到 28.8%。

## Abstract
Speculative decoding accelerates LLM inference by verifying multiple drafted tokens in parallel, allowing a single target forward pass to accept several tokens. By construction, verification computes representations for both accepted and rejected tokens. Yet, conventional drafters retain only the representations of accepted tokens, leaving the substantial verifier computation spent on rejected tokens effectively wasted. We find that these discarded hidden states generated during target forward retain useful information about future tokens that can improve subsequent drafts. However, realizing this opportunity poses two distinct challenges. At inference, recycling overhead can increase drafting latency, diminishing the speedup gained from increased acceptance length. During training, standard parallel drafter training does not produce inference-aligned rejected states, while obtaining them through sequential rollouts would sacrifice parallelism across training positions. We introduce Carryover Drafting, which addresses both challenges. Carryover recycles rejected target hidden states as temporary KV context, allowing the drafter to selectively attend to them. It reuses the drafter's existing interface and adds only a single learned embedding to distinguish rejected states from committed context. The additional KV context is replaced each drafting round, keeping its length bounded by one proposal block. We introduce parallel draft--verify--draft training that exposes the drafter to inference-aligned rejected states while preserving parallelism across training positions. Experiments with DFlash and a DSpark-derived semi-autoregressive drafter across two target models show that this simple Carryover mechanism improves average acceptance length by 6.5--14.7% and end-to-end vLLM speedup by 7.9--14.4% over the corresponding baselines, with speedup gains reaching 28.8% on translation.

## 1. 核心问题与研究动机

- **背景**：自回归 LLM 每次前向只生成一个 token。推测解码（speculative decoding）用轻量 drafter 并行草拟多个 token，再由 target 在一次前向中并行验证，从而一次接受多个 token。draft 质量直接决定加速比。
- **现状**：近期方法（EAGLE / EAGLE-3、DFlash、DSpark 等）让 drafter 复用 target 已算出的隐藏状态来提升草拟质量，但它们**只保留被接受 token 的隐藏状态，丢弃被拒绝 token 的隐藏状态**。
- **核心矛盾**：验证过程"按构造"已经为接受与拒绝 token 都计算了表示，而推测解码中 draft 往往只被部分接受——这意味着**验证器在拒绝 token 上的大量计算被白白浪费**。
- **作者发现**：这些被丢弃的隐藏状态仍保留关于未来 token 的有用信息，可用于改进后续草拟。由此提出核心问题：*能否把被拒绝的隐藏状态"顺延"（carry over）到下一轮草拟？*
- **两大挑战**：
  - **推理侧**：回收需要额外投影与注意力开销，可能抵消接受长度提升带来的收益；若跨轮持续保留拒绝状态，KV 上下文会无限增长。
  - **训练侧**：标准并行 drafter 训练基于记录的 target 响应，无法产生与推理时一致的拒绝状态；而用顺序 rollout 获取这些状态会牺牲跨训练位置的并行性。

## 2. 方法论

### 2.1 核心思想

将每轮验证产生的**被拒绝 target 隐藏状态**回收为下一轮草拟的**临时 KV 上下文**，让 drafter 通过其**已有的注意力层**选择性关注；不新增门控或专用投影模块，仅加一个可学习嵌入以区分"拒绝状态"与"已提交上下文"。

### 2.2 推理侧关键细节

- 记第 r 轮 target 在提议位置的隐藏状态为 $H_r=(h_{r,1},\dots,h_{r,B})$，接受前缀 $H^{acc}_r=h_{r,1:m_r}$，拒绝后缀 $H^{rej}_r=h_{r,m_r+1:B}$。
- 复用已有特征投影 $F$ 与每层 KV 投影：$\Phi_\ell(H)=\big(K_\ell(F(H)),\,V_\ell(F(H))\big)$。
- 回收构造：$U_{r+1,\ell}=\Phi_\ell(H^{rej}_r+E_{carry})$，上下文拼接为 $ctx_{r+1,\ell}=[\,C_{r+1,\ell}\,;\,U_{r+1,\ell}\,]$，其中 $C$ 为常规更新后的已提交 drafter KV 上下文。
- **轻量接口**：$E_{carry}$ 是相对基线的**唯一新增模块**（drafter 与既有投影一并微调）。接口探测显示专用投影器接受长度略高，但会额外引入一个投影模块，故选择单个嵌入。
- **缓存语义**：拒绝状态是**只读的 drafter 上下文**，既不替换已接受 token 的隐藏状态，也**不进入 target KV 缓存**；每轮验证**整体替换**上一轮 carryover 上下文，完整接受时为空，因此新增上下文**上限为 B 行/层**，存储复用验证窗口。每个拒绝状态保留其被计算时的绝对位置，RoPE 仅在该状态被投影为 key 时施加一次。
- **延迟模型**：$L_{carry}\approx (t_{draft}+t_{verify}+t_{reuse})/\tau$，$S_{carry}\approx \tau\,t_{AR}/(t_{draft}+t_{verify}+t_{reuse})$，其中 $t_{reuse}$ 为回收带来的额外草拟延迟，故设计目标是"高接受 + 低开销"。
- **正确性说明**：在给定解码历史与携带输入的条件下，drafter 定义提案分布 q；按该实际 q 执行标准的 target 接受/残差修正规则，仍保持目标分布不变。Carryover 只改变提案分布，不改变 target 概率与接受规则；拒绝文本只作为 drafter 输入，不能写入已提交 target KV。

### 2.3 训练：并行 draft–verify–draft

- 沿用并行块草拟器训练：在记录的 target 响应 y 上随机采样锚点（**每响应 512 个锚点**），Baseline 与 Carryover 使用**完全相同的训练数据与损失**（含按位置指数衰减的权重）。
- 每个采样锚点上构造一个局部转移：
  1. **Draft（无梯度）**：drafter 生成 detached 提议；
  2. **Verify（冻结 target，并行）**：用块对角因果掩码隔离各分支（每支只读自己的记录前缀与自己的提议前驱），贪婪验证返回接受长度 $m_i$ 与 detached 拒绝隐藏状态 $H^{rej}_i$；
  3. **Draft（有梯度）**：锚点平移为 $a'_i=a_i+m_i+1$（下一修正/奖励 token 位置），第二次草拟读取记录前缀、经上式接收 $H^{rej}_i$，并以**原始记录续写**为监督目标。
- **梯度只流经第二次草拟**（含共享投影与 carryover 嵌入）；第一遍草拟与 target 验证均 detached。
- **不新增 target 采样数据**：记录响应仍是唯一监督来源，中间 draft–verify 只提供"平移后的位置"与"拒绝状态"。
- 各锚点的 draft–verify–draft 转移**相互独立**，故训练在位置上保持并行；完全接受时 $H^{rej}=\varnothing$，第二遍退化为平移锚点上的基线训练，仍提供监督，这类样本被保留。

## 3. 实验设计

- **目标模型**：Qwen3-4B、Gemma 4 12B。
- **两种草拟范式（drafter）**：
  - **DFlash**：并行块预测；
  - **Markov**：在并行主干上加入 DSpark 的 rank-256 一阶修正头，代表半自回归块草拟。两者均为 5 层 drafter、15 个提议 token，关闭置信度调度以固定验证长度。
- **训练数据**：500K prompts，来自 UltraChat-200K 与 Magpie-Llama-3.1-Pro-300K-Filtered（沿用公开 speculator 数据配方），由各自 target 重新生成响应，Baseline 与 Carryover 共享同一批响应。Baseline 训练 10 epoch，Carryover 从 10-epoch 基线 checkpoint 继续训练 3 epoch。
- **Benchmark**：Red Hat speculator benchmark，共 844 条 prompt（HumanEval 164、tool calling 200、Math/MT-Bench/QA/RAG/Summarization/Translation 各 80）。温度 T=0 与 T=1。
- **指标与执行**：接受长度（含验证产生的 bonus token，微平均）；离线 vLLM 的逐数据集加速比；混合工作负载上的在线 vLLM 平均加速比；并发 1/2/4/8/16/32 的吞吐（output tokens/s）。硬件为 1 张 H200。
- **对比方法**：各自对应的 Baseline（DFlash / Markov，不携带任何状态）vs. +Carryover。
- **消融/诊断**：
  - **Carryover 接口消融**（Qwen3-4B Markov 探针，约 40K 样本、6 epoch，HumanEval/Math/MT-Bench）：
    - (a) 携带信息类型：draft 生成的 token、target 生成的 token、target top-5 加权、target 隐藏状态（本方法）；
    - (b) 区分方式：不显式区分、独立投影器（19.7M 参数）、carryover 嵌入（本方法）。
  - **匹配锚点下的 target-token Recall**：Carryover ON / 同权重但无携带状态（OFF）/ Baseline 三者在相同解码锚点比较 Recall@1 与 Recall@16。
  - **拒绝分支统计与增益关系**：拒绝状态数量、拒绝后接受、以及作者定义的"再收敛"（re-convergence，含 ±1 位置容差）与数据集级增益的相关性；跨 drafter 类型（DFlash vs Markov）比较。
  - **注意力诊断**：可视化 drafter 对携带行的注意力占比（全 softmax 的 19.78%；15 个拒绝状态子集为 23.40%）。

## 6. 主要结论与发现

- **普遍有效**：在所有评测数据集设置上均观察到接受长度提升，平均提升 **6.5–14.7%**；端到端 vLLM 加速相对基线提升 **7.9–14.4%**，说明接受增益足以覆盖回收开销。
- **翻译任务增益最大**：在每个 target–drafter–温度组合中翻译的相对增益最高，Qwen3-4B Markov 在 T=1 达 **+28.6%**，Markov 在翻译上的端到端加速增益最高达 **28.8%**。
- **对更强 drafter 依然有效**：从全并行 DFlash 迁移到半自回归 Markov，增益保持甚至扩大，说明 Carryover 与"块内依赖建模"互补。
- **并发下的表现**：随并发从 1 增至 32，Baseline 与 Carryover 相对自回归的加速都下降，但 Carryover 相对 Baseline 的增益在两个 target 与两种 drafter 上均保持。
- **回收什么最重要**：携带 **target 隐藏状态** 的增益（+9.6%~+14.8%）远大于 draft 生成的 token（不一致，甚至负增益）与 target token 提示（+1.8%~+5.8%）。
- **如何区分**：不显式区分已具竞争力；19.7M 参数的独立投影器仅略优（如 Math +15.2% vs +14.8%），故选择单嵌入方案。
- **机制解释**：在相同锚点下，ON 相比 OFF 在每个位置提升 Recall@1 达 1.28–5.60 点、Recall@16 达 0.29–1.89 点；注意力诊断显示 19.78%（15 拒绝子集 23.40%）的注意力落在携带行上，证明该接口被真实使用。
- **增益来源是"再收敛"而非"数量"**：数据集级增益与归一化再收敛数的相关性 r=0.96（去掉翻译为 0.90），明显高于"
