## 摘要
投机解码通过轻量级草稿模型提出多个候选词元，并由更大的目标模型并行验证，从而加速自回归语言模型推理。然而，在第一次拒绝之后，基于前缀的标准验证会丢弃剩余的草稿后缀，因此生成和验证这些位置所花费的计算量不会推动解码进度。我们聚焦于DFlash，表明被拒绝后缀中的被拒绝位置仍可能与目标延续对齐，这说明草稿模型尽管存在局部词元级错误，仍能保留有用的语义和结构信息。受此观察启发，并借鉴条件扩散的思想，我们提出了ReTrace，一种拒绝轨迹条件化方法，它使每个草稿块基于前一轮的拒绝后缀进行条件化，而非仅从全新的掩码占位符生成草稿。ReTrace保留被拒绝后缀的隐藏表示，将其与下一个草稿块对齐，利用来自同一验证过程的目标感知校正信号对其进行细化，并通过门控残差融合将其接纳到草稿器的输入嵌入中。由于被拒绝的词元从未被提交，且目标端验证保持不变，ReTrace保持了投机解码的无损特性，且无需额外的模型前向传递。使用Qwen3模型在数学推理、代码生成和开放域对话上的实验表明，与DFlash骨干相比，ReTrace持续提高了平均接受长度和端到端解码速度。通过在不修改轮内候选生成的情况下引入跨轮条件化，ReTrace与现有草稿改进大体正交，可与之结合以获得进一步提升。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

# ReTrace：用于投机解码的拒绝轨迹条件化——论文详细中文总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型的自回归解码每一词元都需要一次前向传播，推理延迟高、GPU 并行算力利用不充分。投机解码通过“轻量草稿模型生成候选 + 目标模型并行验证”来加速推理，成为一种主流方案。
- **核心问题**：在标准前缀验证机制下，一旦草稿序列在某个位置被目标模型拒绝，该位置之后剩余的草稿后缀会被整体丢弃。生成和验证这些后缀位置的计算量已经发生，却没有转化为任何解码进度，造成计算浪费。
- **关键观察**：作者以 DFlash 这类“并行块式扩散草稿器”为研究对象，发现一个反直觉的现象：尽管草稿在首个被拒位置出现局部词元级错误，其后继被拒位置仍可能重新与真实目标延续对齐，即被拒后缀中保留了有用的语义、结构和预测信息。
- **量化证据**：使用 Qwen3-4B 与 DFlash-b16 分析，被拒后缀中 30.4% 的目标词元仍是草稿模型 top-1，75.2% 落在 top-5；同时，被拒草稿隐藏状态与同一真实目标延续的余弦相似度显著高于随机目标窗口（macro-average 0.351 vs 0.128）。
- **整体含义**：被拒绝的草稿计算不应当被简单丢弃，而可以跨轮次复用，作为下一轮草稿生成的辅助条件，从而在**保持投机解码无损性**的前提下提升接受长度和端到端解码速度。

## 2. 论文提出的方法论

- **核心思想**：受条件扩散启发，ReTrace 将“上一轮被拒后缀的隐藏表示轨迹”作为条件信号，注入到下一轮掩码草稿块的输入中；目标模型验证过程、验证规则、词元提交方式完全不变。
- **整体流程**（以 DFlash 为骨干）：
  1. 第 t 轮草稿器生成大小为 B 的候选块，同时得到最终层隐藏表示 \(h^D_{t,1:B}\)；
  2. 目标模型并行验证，得到接受长度 \(A_t\)；若 \(A_t < B\)，首个被拒位置为 \(r_t = A_t + 1\)；
  3. ReTrace **丢弃已提交的接受前缀表示**，也丢弃首个被拒位置（该位置由目标侧 correction token 取代），只保留严格位于首个被拒位置之后的表示：
     \[
     h^D_{t,r_t+1}, \dots, h^D_{t,B}
     \]
  4. 将这些表示与下一轮草稿块位置对齐：\(m_{t+1,j} = h^D_{t,r_t+j}\)，不足部分补零；
  5. 利用验证阶段已产生的**目标模型表示**做目标感知校正：
     \[
     c_{t+1,j} = W_c[m_{t+1,j}; u_{t+1,j}], \quad r_{t+1,j} = m_{t+1,j} + \beta c_{t+1,j}
     \]
     其中 \(u_{t+1,j}\) 是在验证第 \(r_t+j\) 个候选时对应的目标层表示，\(u_{t+1,j}=h^T_{t,r_t+j-1}\)，无需额外目标前向；
  6. 通过**门控残差融合**注入草稿器输入：
     \[
     \tilde{e}_{t+1,j} = e_{t+1,j} + W_v r_{t+1,j}\odot \sigma(W_g[e_{t+1,j}; r_{t+1,j}])
     \]
     \(W_v\) 零初始化，保证训练初期退化为原始 DFlash 行为；
  7. 该条件信号只保留、使用一轮，下一轮由新的被拒后缀替换。
- **算法要点**：训练时缓存并 detach 上一轮表示，避免跨轮梯度传播；草稿骨干、校正模块与门控注入模块联合优化，目标模型冻结。推理时全部输入来自已有草稿/验证中间量，**不增加额外目标模型前向，也不增加额外草稿前向**。
- **与现有工作的区别**：不同于 Lyanna 等“从可复用隐藏轨迹重采样候选树再验证”的做法，ReTrace 不要求被拒状态自己生成可接受候选，只将其用作下一轮条件信息，从而更轻量且与轮内草稿改进方法正交。

## 3. 实验设计

- **目标模型与草稿器**：Qwen3-4B、Qwen3-8B 为验证模型；以对应 DFlash-b16（5 层草稿层、块大小 16）为直接骨干与基线。
- **基准与数据集**（7 个 benchmark，覆盖 3 类任务）：
  - 数学推理：GSM8K、MATH-500、AIME25；
  - 代码生成：HumanEval、LiveCodeBench；
  - 开放域对话与指令跟随：MT-Bench、Alpaca。
- **评估指标**：平均接受长度 \(\tau\)、相对标准自回归解码的端到端加速比（Speedup）。
- **对比基线**：
  - EAGLE-3（树大小 16 与 60）作为强特征级投机解码方法；
  - DFlash-b16 作为直接骨干基线；
  - 另有 SFT 对照（用同样训练数据/预算继续训练 DFlash 但不做拒绝轨迹条件化），用于排除“更多训练带来提升”的替代解释。
- **解码配置**：贪心温度 0 与采样温度 1，块大小 16，禁用 thinking mode，评价规模为 GSM8K/MATH/LiveCodeBench/Alpaca 各 128 条、HumanEval 164 条、AIME25 30 条、MT-Bench 80 条。

## 4. 资源与算力

- **训练算力**：32 张 NVIDIA A800 40GB GPU，分布在 4 个八卡节点；采用 FSDP 分布式策略。
- **训练设置**：训练 8 epochs，prompt batch size 32，BF16，AdamW（weight decay 0.01），学习率 \(5\times10^{-5}\) 余弦衰减，warmup 比例 0.05，prompt/response 长度 512/1,024。
- **训练数据**：40K 条 prompt-only 样本，取自 Open-PerfectBlend 混合指令池（数学、代码、对话、指令跟随等）。
- **推理测量硬件**：单张 NVIDIA A800 GPU，batch size 1，context 1,024。文中给出了微基准：ReTrace 每轮额外 conditioning 开销仅 0.13ms，约占 DFlash 单轮周期（32.49ms）的 0.40%。

## 6. 论文的主要结论与发现

- 被拒后缀虽然不能被直接提交，但其隐藏表示保留了**可复用的预测信息**；词元级上目标词元常处于草稿高概率区间，表示级上与真实目标轨迹显著对齐。
- ReTrace 通过跨轮条件化，在保持投机解码正确性与无损性的前提下，稳定提升 DFlash 骨干的接受长度和端到端速度：在 4 组模型–温度配置均值下，接受长度相对 DFlash 提高约 6.97%，速度提高约 5.34%。
- 目标感知校正是有效的：结合验证阶段已有的目标状态，比单纯拼接/覆盖被拒状态带来更一致的增益。
- 门控残差融合优于简单覆盖，因为它保留当前轮掩码输入作为主路径，条件信号只作为选择性的残差。
- ReTrace 的额外开销极低（每轮约 0.13 ms），不需要额外的目标模型前向，适合实际部署。
- ReTrace 不修改轮内草稿生成，因此与 Domino 等轮内改进正交，可以叠加获得额外收益。

## 7. 优点

- **问题切入角度有新意**：不是单纯提高草稿质量，而是把“标准投机解码丢弃被拒后缀”这一结构性浪费视为可优化对象，并给出清晰的定量动机。
- **方法轻量且无损**：只复用已有验证/草稿中间表示，不增加目标模型 forward，不改验证规则，保留投机解码的无损性；工程落地的额外成本很低。
- **设计具有可解释性**：拒绝轨迹构造、位置对齐、目标感知校正、门控残差注入每个模块都有明确功能与消融支撑。
- **实验严谨性较好**：设置 SFT 对照以排除额外训练干扰；给出耗时分解；同时考虑单请求与高并发服务场景；并验证与 Domino 的兼容性。
- **正交性与扩展性好**：由于不干预同一轮内的草稿生成，理论上可叠加 EAGLE、Domino、树形草稿等改进。

## 8. 不足与局限

- **评估面较窄**：只在 Qwen3 系列（4B/8B）目标模型与 DFlash 系列草稿器上验证，未覆盖其他常见模型家族（Llama、DeepSeek 等）和其他非 DFlash 骨架。
- **训练需要额外标注/算力**：虽然推理开销低，但 ReTrace 需要 40K 条指令数据的联合微调，并要求草稿器、校正与门控模块的额外训练成本（32 卡 A800），这在资源受限环境可能不友好。
- **依赖 DFlash 的并行块结构**：论文也承认该复用机制更适合 DFlash 这类“单一深层并行块”草稿器；对 EAGLE 这类树状/自回归特征草稿器，被拒状态的重用与对齐问题更复杂，结论不能直接推广。
- **条件信号仅保留一轮**：这个设计虽简单，也可能丢失跨越更多轮次的冗余信息；论文没有实验比较更长条件的收益与开销。
- **理论分析较弱**：对“为什么被拒后缀仍能带预测信息”以及“校正矩阵何时有效”缺少更泛化的理论解释，更多是经验观察与启发式设计。
- **潜在选择偏差**：方法专门基于 DFlash 的失败模式设计，若未来更高效的草稿器使被拒信息减少，ReTrace 的边际收益可能下降；需要更广的后续验证。
