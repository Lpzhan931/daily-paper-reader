## 摘要
在边缘设备上部署大型语言模型（LLM）通常依赖于模型压缩或分割推理。然而，压缩会降低推理能力，而分割推理则面临严重的广域网（WAN）通信瓶颈。边缘-云推测解码成为一种有前景的替代方案，利用边缘小模型生成令牌供云端验证。然而，在不稳定的广域网上，不可避免的预测拒绝会引发灾难性的流水线停顿和网络级回滚，从而抵消协作收益。为克服这一问题，我们提出AceSpec，一种非对称边缘-云协作框架。AceSpec利用未饱和的边缘计算资源主动构建概率状态缓存，有效将网络级流水线刷新转化为O(1)局部内存查找。为节省带宽，它采用非对称通信协议，上行传输最小主干索引，下行传输紧凑稀疏分布。此外，我们引入了一种网络感知的拉格朗日优化资源分配策略，动态最大化局部缓存命中率。评估表明，AceSpec实现了高达3.52倍的吞吐量加速，并表现出卓越的带宽抗性，即使在严重受限的50 Kbps广域网条件下也能维持接近峰值的推理性能。

## Abstract
Deploying Large Language Models (LLMs) on edge devices typically relies on model compression or split inference. However, compression degrades reasoning capabilities, while split inference suffers from severe Wide Area Network (WAN) communication bottlenecks. Edge-cloud speculative decoding emerges as a promising alternative, leveraging an edge small model to draft tokens for cloud verification. Yet, over volatile WANs, inevitable prediction rejections trigger catastrophic pipeline stalls and network-wide rollbacks, neutralizing collaborative gains. To overcome this, we propose AceSpec, an asymmetric edge-cloud collaborative framework. AceSpec utilizes un-saturated edge compute to proactively construct a probabilistic state cache, effectively transforming network-wide pipeline flushes into $\mathcal{O}(1)$ local memory lookups. To preserve bandwidth, it employs an asymmetric communication protocol that transmits minimal main-chain indices uplink and compact sparse distributions downlink. Furthermore, we introduce a network-aware, Lagrangian-optimized resource allocation strategy that dynamically maximizes the local cache hit rate. Evaluations demonstrate that AceSpec achieves up to a 3.52$\times$ throughput speedup and exhibits exceptional bandwidth immunity, sustaining near-peak inference performance even under severely constrained 50 Kbps WAN conditions.

### 一、核心问题与整体含义（研究动机与背景）

- **问题背景**：在边缘设备上部署大型语言模型（LLM）通常面临两大传统路径的困境：
  - **模型压缩**虽可降低资源需求，但不可避免地损害模型的推理与生成能力；
  - **分割推理**（Split Inference）将网络切分至边缘与云端，但中间隐状态需经广域网（WAN）传输，导致严重的“通信墙”瓶颈，在低带宽、高延迟网络下效率极低。
- **推测解码的优势与不足**：边缘-云推测解码（Speculative Decoding）通过让边缘端小模型（SLM）草拟候选令牌、云端大模型（LLM）并行验证，将通信负载从连续张量压缩为离散令牌序列。然而，传统推测解码假设近零通信开销，在WAN环境下其同步“停下等待”的依赖造成严重通信瓶颈；后续管线化方案（如PicoSpec、PipeSD、E2-SCI）虽部分隐藏延迟，但存在单链回滚惩罚大、无法支持随机核采样、批传输带宽浪费或需侵入式训练等局限。
- **本文目标**：提出AceSpec，利用边缘端未饱和计算资源构建概率状态缓存，将WAN上的高代价回滚转化为本地O(1)内存查找，在不增加上行通信量、无需训练的通用前提下实现高效稳定的边缘-云LLM推理。

### 二、方法论

#### 1. 核心思想

AceSpec的核心在于“**以计算换通信**”：利用边缘设备空闲的并行计算能力，在云端验证的异步等待窗口内，主动构建一个多分支概率令牌树缓存，将网络级流水线清空（Pipeline Flush）的代价转化为一次本地内存查找。

#### 2. 架构与关键流程

- **系统架构**（图1）：
  - **边缘客户端**：部署轻量草稿SLM，集成三个子系统——树形草稿器（Tree-based Drafter）、概率KV缓存管理器（Probabilistic KV Cache Manager）与本地重采样器（Local Resampler）。
  - **云端服务器**：部署高参数目标LLM，执行高度并行的验证循环，扮演评估者角色，仅校验边缘提案并返回必要的概率分布。
- **异步执行管线**（图2与算法1）：
  1. 边缘端完成草稿迭代后，通过**非对称流传输**只发送主干链的令牌索引（标量数组）到云，节约上行带宽；
  2. 在云端验证窗口内，边缘端对主干链各潜在拒绝点进行**异步多分支树扩展**，将备选状态序列存入本地概率缓存；
  3. 云端单次前向验证主干链，若在某位置拒绝，则打包该位置的**稀疏化目标分布**并返回；
  4. 边缘端本地重采样确定正确令牌，以“（拒绝位置，重采样令牌）”作为查询键查本地树缓存；命中则通过KV压缩操作实现O(1)状态恢复，完全消除串行重草稿的网络回滚惩罚。
- **高效树构建**：采用定制的**树注意力掩码**（图4），由共享前缀块、主路径分支块和后缀对角块组成，将N条分支打包为一次并行前向传播，避免草稿延迟与分支数线性增长。

#### 3. 理论优化框架

- **性能建模**：AccSpec推导了加速比下界公式：
  $S \geq \frac{S_{ideal}}{1 + (1 - P^{tree}_{hit}(T)) \cdot \rho}$
  其中 $S_{ideal}$ 为管线完全掩蔽时的理想加速上限，$\rho$ 为回滚惩罚比，$P^{tree}_{hit}$ 为树缓存命中率。
- **两级约束优化**：
  1. **网络感知预算**：以 $T_{tree\_draft}(B) \leq RTT(t) + T_{verify}$ 为约束推导计算预算，$B^*(t) = \min\{B_{max}, \lfloor T^{-1}_{tree\_draft}(RTT(t)+T_{verify})\rfloor\}$；
  2. **任务感知形态分配**：将分支预算以 $\alpha^k$（前缀生存概率）加权后的对数命中率作为目标，结合LLM词汇分布的长尾幂律特性 $R(F_k) \approx 1 - cF_k^{-\beta}$，通过**拉格朗日乘子法**求解，得闭式非均匀几何衰减分配：
  $F_k^* = B_{alloc}(t) \cdot \frac{1-\eta}{1-\eta^\gamma} \cdot \eta^k$，其中 $\eta = \alpha^{1/(\beta+1)}$。
- **设计洞见**：由于浅层拒绝概率最高，计算冗余应集中于浅层节点（k=0,1），且随深度按几何级数递减，由此在固定预算下最大化缓存命中率。

### 六、主要结论与发现

- **吞吐加速显著**：AceSpec获得最高**3.52×**吞吐加速（LLaMA-1B/70B + HumanEval），在多数配置中优于PicoSpec和DSSD等最新管线化方案。
- **带宽免疫力优秀**：带宽从100 Mbps降至50 Kbps时，吞吐量保持稳定平台，证明其非对称通信协议的有效性；仅在25 Kbps以下才出现明显性能下降。
- **非均匀分支分配有效**：消融实验证明拉格朗日优化的非均匀几何衰减策略在吞吐量、命中率和TTFT上全面优于单分支与均匀多分支，如GSM8K上吞吐提升至24.37 tokens/s。
- **敏感性的边界**：分支预算存在边际收益递减拐点（约40-80）；温度上升致使分布平坦化时命中率仍能保持81%以上，证明方法兼顾确定性与创造性任务。
- **失败案例的启示**：在Qwen-1.7B/32B + HumanEval中仅有0.98×加速，低于基线——较大草稿模型在边缘端的多分支扩展耗时超过云端验证窗口，使管线变为边缘计算受限，恰好验证了“网络感知预算”约束的必要性。
