## 摘要
长上下文推理在解码过程中会保留不断增长的键值（KV）缓存，这消耗大量GPU内存并可能降低生成吞吐量。这一瓶颈在混合语言模型中依然存在，因为其残差全局注意力层可能主导与上下文相关的缓存需求。我们研究如何在总KV驻留预算下分配这种状态。我们引入HeadWiseKV，一种无需训练的框架，在保留混合语言模型原生的局部、循环和线性路径的同时，压缩其残差全局KV缓存。它为每个物理KV头分配一个静态的多级历史窗口，使缓存需求在服务之前即可预测。我们将此分配形式化为一个受限的操作率失真问题，并提出SeqCalib作为HeadWiseKV中的核心策略生成算法。SeqCalib按执行顺序处理各层，并根据部署时使用的低层策略对每个决策进行条件化，从而考虑跨深度的交互。分组缓存运行时将所选策略物化为实际的逐头KV驻留，而非完整缓存上的掩码。我们在四个混合长上下文模型上评估下游质量，并在Qwen3.6-27B上研究物理驻留和服务行为。HeadWiseKV在评估的模型上保持了接近Full-KV RULER和LoCoMo的质量。在固定模型系统研究中，它在112K上下文长度下将采样峰值设备内存减少了8.59%，并将最大验证成功上下文从114K扩展到161K。

## Abstract
Long-context inference retains a growing key--value (KV) cache during decoding, which consumes substantial GPU memory and can reduce generation throughput. This bottleneck remains in hybrid language models because their residual global-attention layers can dominate context-dependent cache demand. We study how to allocate this state under an aggregate KV-residency budget. We introduce HeadWiseKV, a training-free framework that compresses the residual global KV caches of hybrid language models while preserving their native local, recurrent, and linear paths. It assigns each physical KV head a static, multilevel history window, making cache demand predictable before serving. We formulate this allocation as a restricted operational rate--distortion problem and propose SeqCalib as the core policy-generation algorithm in HeadWiseKV. SeqCalib processes layers in execution order and conditions each decision on the lower-layer policy used at deployment, thereby accounting for interactions across depth. A grouped-cache runtime materializes the selected policy as actual per-head KV residency rather than a mask over a full cache. We evaluate downstream quality across four hybrid long-context models and study physical residency and serving behavior on Qwen3.6-27B. HeadWiseKV retains near-Full-KV RULER and LoCoMo quality across the evaluated models. In the fixed-model systems study, it reduces sampled peak device memory by 8.59\% at a 112K context length and extends the largest verified successful context from 114K to 161K.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：长上下文自回归推理中，每个全注意力层会为所有历史 token 存储 KV 向量，使 KV 缓存随上下文长度和并发量线性增长，容易耗尽 GPU 显存并降低解码吞吐。
- **针对场景**：混合架构语言模型（如 Gemma 系列、Qwen3-Next / Qwen3.6）虽然用局部滑动窗口或循环块替换了部分全注意力层，但残留的少量全局注意力层仍保留全量历史，成为 KV 内存瓶项的“残余瓶颈”。混合化只是把瓶颈“搬了家”，而不是消除它。
- **现有方法的两难**：
  - 请求相关的动态策略（如 Ada-KV、HeadKV 等）能按当前 prompt 选择 token 或 head，但通常先构造完整缓存再做压缩或逻辑稀疏，无法降低 prefill 峰值显存；在线打分、索引和移动也会带来请求时开销。
  - 静态策略（如 StreamingLLM、DuoAttention）在服务前固定容量，显存可预测，但多采用“全历史 vs 压缩/流式”的二值划分，粒度较粗，难以适应混合模型中不同全局头对历史长度的不同需求。
- **本文含义**：提出一种静态、训练无关、细粒度且可物理实现的 KV 驻留预算方法——HeadWiseKV，在不改变模型结构和推理路径的前提下，使得 KV 内存需求在服务前确定，同时尽量保持长上下文任务质量。

## 2. 方法论：核心思想、关键技术细节与算法流程

- **核心思想**：为每个“物理 KV 头”预先分配一个静态的多级连续后缀历史窗口（如 8K / 16K / 32K / full），在服务期间保持不变。该策略直接决定物理驻留量，而非在完整缓存上叠加逻辑掩码。
- **结构化驻留模型**：
  - 只考虑模型中残留的全局注意力层，顺序记作 \(L_F\)，每层包含物理 KV 头集合 \(H_l\)；在 GQA 中多个查询头共享一个 KV 头，因此决策单位为物理 KV 头 \((l,h)\)。
  - 决策空间为 \(a_{lh} \in W = \{w_1,\dots,w_K,\text{full}\}\)，每个 \(w_k\) 表示保留最近多少 token 的 KV。
  - 总驻留成本用规范化比率表示：\(R_C(a) = N_C(a)/N_C(a_F)\)，即压缩策略相对全满策略的 KV 存储占比；实际显存还需另测全设备峰值 VRAM。
- **SeqCalib：核心离线校准算法**：
  - 将问题形式化为“受限操作率-失真问题”的理想目标，但直接求解不可行；SeqCalib 用逐层逐头的条件化相似度测试代替全局搜索。
  - 按层执行顺序处理：校准第 \(\ell\) 层时，先冻结其下方所有已选定窗口的策略 \(a_{<\ell}\)（即部署时真正生效的低层前缀），在该前缀下对第 \(\ell\) 层做一次全历史 trace，然后用同一 trace 回放每个候选窗口。
  - 对每个 KV 头，比较“只保留候选窗口 w”与“保留全历史”的注意力输出（pre-gate 输出），计算平均余弦相似度 \(\hat S_{lh}(w|a_{<\ell})\)。若相似度达到阈值 \(\tau\)，选择存储成本最低的窗口：
    \[
    \hat a_{lh,\tau}=\arg\min_{w\in W} \{ n_{lh,C}(w) : \hat S_{lh}(w|\hat a_{<\ell,\tau})\ge\tau\}.
    \]
  - 因 \(W\) 包含 `full`，总有可行解。算法在一次层序遍历后得到完整策略矩阵和对应驻留率。该选择保证“在固定低层前缀下的逐层最小成本”，但非全局联合最优。
  - 为了支撑不同显存预算，在有序阈值网格 \(T=(\tau_1,\dots,\tau_G)\) 上独立运行多个 SeqCalib 记录（策略、驻留率、最低头相似度等），再由确定性预算选择器按“先最大最低头相似度、再最小驻留率、再最小网格索引”选取最优记录。
- **运行时物化**：
  - 服务端只加载一次静态策略矩阵，不根据输入或注意力在线重算。
  - 使用“分组缓存”布置：相同窗口长度的物理 KV 头可共享组配置，但各自 KV 内容保持独立；每个头只读写自己被分配的历史切片，组内查询头读取对应 KV 头后再做原有投影。
  - 原始局部注意力层、循环层或线性层路径不变，只有被配置的全局 KV 头改变物理驻留。
  - 校准与部署共享相同的层/头索引、窗口语义与注意力缩放；部署前还会做 trace 兼容性检查。

## 6. 主要结论与发现

- **质量保持**：在匹配 68.95% KV 驻留预算时，HeadWiseKV（τ=0.995）在 Qwen3.6-27B 上的 RULER 为 99.65（Full-KV 为 100.00），LoCoMo 为 94.55（与 Full-KV 一致）；在 Airline 和 Retail 上还略高于 Full-KV，显示细粒度按头分配可能通过削减干扰历史反而带来微小收益。
- **压缩潜力**：固定模型上在 128K 参考上下文中可将可配置全局 KV 驻留降至 68.95%，质量损失极小；在更温和压缩档位（85.74%、96.00% 驻留）上完全保持 RULER/LoCoMo 分数，说明冗余具有较强层间/头间异质性。
- **显存与上下文能力**：Qwen3.6-27B 上，在 112K 上下文长度下采样峰值显存降低 8.59%；最大验证成功上下文从 Full-KV 的 114K 扩大到 161K（约 1.41 倍），首次 OOM 推到 162K。
- **吞吐特征**：解码吞吐与 Full-KV 基本持平（在共同成功上下文中为 0.954–1.017 倍）；prefill 吞吐与实现相关，幅度更波动（0.810–1.092 倍）。
- **跨模型迁移**：共享 τ 下，RULER 与 Full-KV 差距始终很小（≤0.61 分），但 LoCoMo 上有更大波动；τ 不是固定压缩率，而是基于质量相似度的阈值，需要按目标模型/任务验证最终档位。

## 7. 优点：方法与实验设计的亮点

1. **训练无关、架构友好**：无需重训模型或改动注意力机制，只调整残留全局 KV 的物理存放长度。
2. **内存可预测**：策略在服务前确定，显存需求离线可算，无在线选择开销，可直接做容量规划。
3. **细粒度多级分配**：相比 StreamingLLM/DuoAttention 的“全留/压缩”二值选择，用多种历史窗口更匹配真实层头异质性。
4. **深度条件化校准**：SeqCalib 按执行顺序冻结低层策略后校准高层，贴近部署实际输入分布，避免“全满前缀下选出的策略”在截断后被证伪。
5. **真实物理驻留而非掩码**：运行时只分配选定长度缓存，能降低 prefill 阶段峰值显存；这是许多动态稀疏方法做不到的。
6. **实验表述谨慎**：区分匹配队列与绝对测量、单独报告质量/系统运行点、对基线细节做适配声明，提升了结果的可信度。

## 8. 不足与局限

1. **静态策略的固有局限**：无法根据 prompt 恢复已驱逐的证据；若某请求非常依赖孤立远古 token，则可能失效。
2. **非全局最优**：SeqCalib 只在固定低层前缀下做层内最小化，不保证全局策略最优；论文明确承认这是 stage-wise 而非 joint-optimal。
3. **校准依赖参考分布与任务**：连续文本校准流与下游任务分布可能不一致；换模型、换 KV 格式或上下文规模时需重新校准。
4. **跨模型 LoCoMo 不够稳定**：共享 τ 在个别模型上仍出现最多约 2 分下降，说明“校准相似度高”不等于“对话长期记忆一定保持”，需要额外验证。
5. **系统结果覆盖窄**：详细的匹配系统测量只在 Qwen3.6-27B + RTX 4090 D 上给出；没有展示多卡、更大批处理、不同 KV 量化或不同后端的普遍性。
6. **基础设施细节不足**：未说明 GPU 总数量、校准计算时间、具体服务软件栈版本等，影响复现的便利性。
7. **统计效力有限**：基准只报聚合均值，未做逐样本配对检验或不确定性区间；部分容量探测是单点扩展，非端到端质量-显存联合评估。
