## 摘要
长上下文大语言模型应用，如文档摘要和多轮智能体，需要从前缀长度达数万词元的上下文生成，使得解码延迟成为主要瓶颈。推测解码（SD）在不改变模型输出的情况下降低延迟，但其加速效果取决于接受的草稿词元数和草稿步骤延迟：轻量级草稿速度快但缺乏捕捉长距离依赖的能力，而强独立草稿能恢复接受率，但在长前缀下会带来不断增长的KV访问成本。我们引入了用于长上下文SD的记忆增强草稿生成方法，为强独立草稿配备压缩的草稿侧KV记忆：一个轻量级适配器构建并增量更新该记忆，以保留远处信息和精确的近期上下文。目标验证器保留其完整KV缓存并应用标准接受/拒绝规则，从而保持SD的无损保证。在Llama 3.1-8B和70B目标模型上，当前缀长度高达32K时，实验表明我们的方法将草稿侧记忆减少了超过70%。相较于自回归解码，它分别实现了最高2.08倍和3.33倍的加速。

## Abstract
Long-context LLM applications such as document summarization and multi-turn agents require generation from prefixes spanning tens of thousands of tokens, making decoding latency a major bottleneck. Speculative decoding (SD) reduces latency without changing model outputs, but its speedup depends on both accepted draft tokens and draft-step latency: Lightweight drafts are fast but lack the capacity to capture long-range dependencies, whereas strong independent drafts recover acceptance but incur growing KV-access cost at long prefixes. We introduce memory-augmented drafting for long-context SD, equipping a strong independent draft with compressed draft-side KV memory: A lightweight adaptor constructs and incrementally updates this memory to retain distant information and exact recent context. The target verifier retains its full KV cache and applies the standard accept/reject rule, preserving SD's lossless guarantee. Experiments on Llama~3.1-8B and 70B targets at prefix lengths up to 32K show that our method reduces draft-side memory by over 70%. It achieves speedups of up to 2.08x and 3.33x , respectively, over autoregressive decoding.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长上下文大语言模型（如文档摘要、在线深度研究、多轮智能体）需要处理数万 token 的前缀，导致自回归解码延迟成为瓶颈。推测解码（Speculative Decoding, SD）通过草稿模型提出候选 token、目标模型并行验证，可以在不改变输出分布的前提下加速解码。
- **问题**：SD 的加速效果取决于两个因素：
  - **接受长度（Lacc）**：草稿越强、越能捕捉长距离依赖，接受 token 越多；
  - **草稿延迟（td）**：草稿步骤需要读取/处理多少 KV 缓存。
- **现有矛盾（长上下文 SD 困境）**：
  - 轻量级草稿（如 EAGLE 风格的单层依赖草稿）速度快，但随上下文增长，其接受长度显著下降（实验显示 EAGLE 的 Lacc 随前缀长度单调下降）；
  - 强独立草稿（如 3B/8B 模型）可保持高接受率，但每一步都要扫描完整历史 KV 缓存，KV 访问成本随前缀长度线性增长，导致草稿延迟大幅上升，最终抵消加速收益。
- **核心含义**：长上下文 SD 必须在“草稿容量”与“草稿侧 KV 访问成本”之间取得平衡。现有方法（如 StreamingLLM、TriForce、MagicDec、QuantSpec、LongSpec 等）大多通过丢弃或量化中间 KV 来降低访问成本，但缺乏可学习的压缩状态；而一般 KV 压缩方法（逐出、量化、上下文压缩）主要用于单个模型推断，不能直接适用于“不对称”的草稿-验证器结构。

## 2. 论文提出的方法论

### 2.1 核心思想：记忆增强滑窗草稿（Memory-Augmented Sliding-Window Drafting, MASW）

- 为强独立草稿模型配备**压缩的草稿侧 KV 记忆**，替代完整的历史 KV 缓存。
- 记忆由三部分组成：
  1. **Sink tokens（锚点）**：序列最前 S 个原始 token 的精确 KV（保留注意力锚点）；
  2. **Local window（局部窗口）**：最近 W 个非 sink token 的精确 KV；
  3. **Memory slots（记忆槽）**：周期性生成的压缩状态，承载从远古历史中提取的信息。
- 目标验证器始终保留**完整 KV 缓存** ，并使用标准接受/拒绝规则，因此无损保证不破坏。

### 2.2 关键技术细节

- **记忆形成**：每间隔 r 个 token（排除 sink token），草稿模型在当前压缩边界插入一个记忆槽 token gm，对该 token 执行与前向相同的 Transformer 计算（使用掩码注意，只看到当前局部窗口、sink 和先前 slots）。槽位通过结构化注意力掩码实现“压缩写入”，并通过下一个 token 预测目标训练，从而学习“功能替代”被逐出的原始 token。
- **投影与 KV 生成**：每个 Transformer 层为记忆槽使用**可训练的镜像投影矩阵**（mirrored projection matrices）W_K,g、W_V,g，从槽位隐藏状态生成 K/V；普通 token 仍使用冻结的原始投影 W_K,r、W_V,r。镜像矩阵初始化为从原始投影复制，构成记忆适配器的全部可训练参数。
- **记忆更新**：解码过程中，一旦新槽位生成，超出局部窗口的旧 token KV 被逐出，而槽位 KV 保留在草稿缓存中。槽位共享紧邻的下一个原始 token 的 RoPE 位置 ID，避免扰动原始位置。
- **草稿侧预填充**：MASW 使用结构化的记忆掩码进行草稿端 prefill，可在与目标 model prefill 并行的过程中构建初始记忆。由于草稿是独立模型，草稿 prefill 与目标 prefill 并行执行，额外计算被目标 prefill 掩盖，不增加 TTFT。
- **无损保证**：只有草稿侧使用压缩记忆；目标验证器仍然持有完整前缀 KV，并执行标准并行验证和拒绝采样，因此输出分布与目标模型一致。

### 2.3 训练方法

- 冻结草稿骨干，只训练 **记忆适配器（镜像 KV 投影）**。
- 分为两个阶段：
  - **预训练**：在 RedPajama 的 2B token 上继续预训练，关闭 EOS；
  - **SFT**：在 LongAlpaca 和 BookSum 数据上进行指令微调（序列截断至 8K token）。
- 损失函数为原始 token 的下一 token 预测损失（记忆槽位置不计算损失），条件为压缩记忆 Dt。

## 6. 主要结论与发现

- MASW 在长上下文 SD 中能大幅削减草稿侧 KV 开销，同时保持接受长度接近全量 KV 草稿。
- **效果**：
  - 在 Llama 3.1-8B 目标上，最高加速 2.08×（4× 压缩 + L3B 草稿）或 1.94×（8× 压缩 + L8B 草稿）；
  - 在 Llama 3.1-70B 目标上，最高加速 3.33×（4× 压缩 + L8B 草稿），8× 压缩也能保持在 2.7-3.03× 的范围。
  - 与 AR 相比，MASW 在长前缀下加速比随上下文增加仍保持稳定或增长；而 full-KV SD 会退化，EAGLE/SWA 甚至低于 AR。
- **草稿侧效率**：在 32K 前缀 + 70B 目标下，MASW 将草稿侧附加内存从 17-18 GB 降至 4-5 GB（减少超过 70%），草稿延迟从 41-55 ms 降至 12-15 ms；Tok./Iter 仅损失较小（例如 4.82→3.77 对于 8B 草稿）。
- **记忆的连续性与可服务性**：压缩记忆是连续、追加式的，与现有 KV 缓存服务系统兼容。
- 训练上下文 8K 的适配器在 32K 前缀上表现优于训练 32K 的适配器；说明学习的是相对压缩操作，具有良好的长度外推能力，短序列训练效率更高。
- PT+SFT 优于仅 PT 或仅 SFT；复制初始化优于随机初始化；窗口 128 最优。

## 7. 优点与亮点

1. **问题定位准确**：清晰识别了“轻量草稿丢失长程接受率”与“强草稿全量 KV 成本高”之间的矛盾，结合理论和实验分析（延迟公式、解码加速模型）。
2. **设计巧妙**：用可训练的镜像投影矩阵实现记忆槽的 KV 投影，避免为每个槽手工设计 pooling；通过结构化注意力掩码自然地引导槽位学习“压缩替换”。
3. **保持无损**：目标验证器不改变，SD 无损保证不变；草稿侧的压缩不引入采样分布偏差。
4. **工程友好**：
   - 压缩记忆是连续、固定形状、append-only；
   - 草稿 prefill 与目标 prefill 并行，不增加 TTFT；
   - 内存布局规律（sink + local + slots）便于高效服务系统实现。
5. 适配器训练成本低（只训练投影矩阵，冻结草稿骨干），且能在训练 8K 上下文下外推到 32K，说明泛化能力强。
6. 实验对比详尽，消融覆盖面广（初始化、训练策略、窗口宽度、上下文长度）。

## 8. 不足与局限

1. **训练数据与上下文规模受限**：作者自述只用 2B token、8K 上下文训练适配器；未探索更大语料、更长训练上下文（虽然 8K 已显示外推能力，但更系统结论仍待验证）。
2. **适配器容量有限**：只训练 K/V 投影，可能封顶每个槽可编码的信息量；作者提到联合微调更大参数集（MLP 或 low-rank）是未来方向。
3. **固定超参数**：局部窗口、sink 数量、槽间隔是手工设定（W=S=128，r=4/8），没有自适应分配机制。
4. **扩展到自推测解码的代价**：若用目标模型本身或其子层做草稿，长上下文草稿成本可能更高，论文未展开。
