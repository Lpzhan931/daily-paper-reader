## 摘要
边缘设备上的 LLM 推理受到计算和内存资源的限制，使得高效的自回归解码颇具挑战。推测解码通过用较小的草稿模型生成 token，并以批处理的目标模型前向传播并行验证多个 token，从而缓解这一瓶颈。然而，验证引入了一种运行时相关的中间状态，介于解码阶段受内存限制的通用矩阵-向量（GEMV）操作与预填充阶段受计算限制的通用矩阵-矩阵（GEMM）操作之间，因为其算术强度随推测长度和接受率变化。我们提出 SPECTRA，一种运行时可变构的瓦片架构，可在完整的推测解码流水线中保持高利用率。在每个瓦片内，计算引擎在用于 GEMM 的脉动式执行和用于 GEMV 的向量通道执行之间切换。在瓦片之间，SPECTRA 通过选择瓦片数量、内核划分和通信模式来动态调整计算并行度。瓦片级和系统级重构均以逐内核方式运行，从而能够在这些多样化的工况下高效执行。在由 20 个瓦片组成的 FPGA 原型上，针对 Pythia、SmolLM2 和 GPT-2 系列进行评估，SPECTRA 通过瓦片级重构实现了最高 $2.09\times$ 的加速，并相比固定设计，从系统级自适应中进一步获得 $1.25\times$ 的增益。

## Abstract
LLM inference on edge devices is constrained by computational and memory resources, making efficient autoregressive decoding challenging. Speculative decoding alleviates this bottleneck by generating tokens with a smaller draft model and verifying multiple tokens in parallel with a batched target model pass. However, verification introduces a runtime-dependent intermediate regime between memory-bound general matrix-vector (GEMV) operations in decoding and compute-bound general matrix-matrix (GEMM) operations in prefill, as its arithmetic intensity varies with speculation length and acceptance rate. We present SPECTRA, a runtime-reconfigurable tiled architecture that sustains high utilization across the full speculative decoding pipeline. Within each tile, the compute engine switches between systolic execution for GEMMs and vector-lane execution for GEMVs. Across tiles, SPECTRA dynamically adapts computation parallelism by selecting tile count, kernel partitioning, and communication pattern. Both tile-level and system-level reconfiguration operate on a per-kernel basis, enabling efficient execution across these diverse regimes. Evaluated on a 20-tile FPGA prototype across the Pythia, SmolLM2, and GPT-2 families, SPECTRA achieves up to $2.09\times$ speedup from tile-level reconfiguration and a further $1.25\times$ gain from system-level adaptability over fixed designs.

## 1. 核心问题与研究动机

- **背景**：LLM 在边缘/移动设备上的推理受限于内存带宽与片上容量，自回归解码每步只生成一个 token（$M=1$），前向传播退化为内存受限的 GEMV 操作，算术强度（AI）仅约 0.5 FLOPs/byte，算力严重闲置。
- **推测解码的引入与代价**：用轻量 draft 模型一次预测 $\gamma$ 个 token，再由 target 模型批量并行验证，可减少串行前向次数（典型接受率 0.8–0.9、$\gamma=4\text{–}8$ 时每次目标调用产出 3–6 个 token）。但它引入了一个**运行时相关的中间计算区间**：验证阶段的批大小 $M=\gamma+1$，AI 介于内存受限的 decode（GEMV）与计算受限的 prefill（GEMM）之间，且随推测长度和接受率动态漂移。
- **核心矛盾**：
  - 固定数据通路无法同时高效覆盖两端：纯向量设计在 prefill/验证时算力闲置，纯脉动设计在 draft decode 时低效。
  - 多瓦片并行会降低每瓦片工作量但不等比减少数据搬运（输入/权重复制），使工作点沿 roofline 左移；对接近拐点的验证内核，增加瓦片数反而可能把它推入内存受限区。
  - 边缘设备内存容量有限，target 模型无法常驻片上，误判 token 的搬运代价被放大。
- **整体含义**：高效支持推测解码需要**同时**在瓦片内（计算数据流）与瓦片间（并行度、划分、通信）具备逐 kernel 的协调灵活性，而非针对单一工作点做静态优化。

## 2. 方法论

### 2.1 总体架构
- 由**多个可重构加速器瓦片 + 片上网络（NoC）+ 分布式内存子系统 + 主机处理器（CVA6 RISC-V）**组成的分块架构。
- 可重构性体现在两个层级：**瓦片级（kernel 粒度数据流切换）**与**系统级（瓦片分配、划分与通信编排）**。

### 2.2 瓦片内：可重构计算引擎（核心创新）
- 基于 **8×8 PE 阵列（64 个 MAC 单元）**，配多 bank 本地存储（64 bank 权重存储 + 8 bank 输入/部分和/输出），支持双缓冲以重叠搬运与计算。
- **两种执行模式，在 kernel 粒度按外维 $M$ 选择**：
  - **Systolic 模式（$M>1$，prefill 与批量验证）**：输出驻留脉动阵列，权重按列流式送入，激活带行相关时延注入形成对角波前，部分和在 PE 内沿归约维本地累加。
  - **Vector-lane 模式（$M=1$，自回归 decode）**：同一 PE 阵列重构为 8 条独立点积通道，单个激活在列方向广播，权重存储重索引以并行访问全部 64 bank，每周期取一个完整的 8×8 权重子块，避免 $M=1$ 时的利用率塌陷。
- **关键点**：两种模式复用同一套算术单元，仅改变数据投递时序与本地存储的逻辑解释（控制与索引不同），因此重构开销小。
- 支持三类 kernel：GEMM（$M>1$）、GEMV（$M=1$）、FlashAttention（按 query 长度、KV 长度、每头维 $d_h$ 参数化）。

### 2.3 融合后处理单元
- 采用 FlashAttention 式数据流，**不物化完整 $QK^T$ 分数矩阵**，而是沿 KV 块增量计算。
- 上部分支：$K$-way 比较器求行最大值（数值稳定）、指数查找表（Exp LUT）、加法树累加归一化因子，通过 $M_{\text{prev}}/M_{\text{new}}/I_{\text{prev}}/I_{\text{new}}$ 维护行最大值与归一化系数，实现在线 softmax。
- 下部分支：值聚合，归一化注意力权重作用于 V 向量，V buffer 采用 ping-pong 预取，流式输出 $O=\text{softmax}(QK^T/\sqrt{d_h})\cdot V$。
- 输出累加结构随执行模式自适应：全序列注意力用多 bank 存储缓冲多 query 行；decode/验证时塌缩为紧凑寄存器结构，降低低 $M$ 内核的本地访问开销。

### 2.4 系统级可重构
- **三类通信原语**：
  - **DMA**：片外内存 ↔ 瓦片私有本地存储（加载权重、流水线边界搬运激活）。
  - **P2P**：瓦片间直传，支持一对一与多对多。
  - **Multicast**：一份数据并行复制到多个目标瓦片，避免冗余传输。
- **内核内并行（sharding）**：把 $[M\times K]\cdot[K\times N]=[M\times N]$ 按某一维切分到 $T$ 个瓦片：
  - **N-sharding（输出并行）**：按输出列切分，激活复制、权重切分，无需跨瓦片归约（DMA 即可）。
  - **K-sharding（归约并行）**：按归约维切分，各瓦片算部分和，经 P2P 做跨瓦片归约。
  - **M-sharding（行并行）**：按输入行切分，各行独立、无归约，但权重需复制。
- **内核间流水线**：上游生产者瓦片把中间数据经 NoC 直接转发给下游消费者瓦片，避免片外往返；不同上下游 sharding 组合对应不同通信模式（M–M 一对一 P2P、M–N 需 multicast 复制、M–K 多对多协调 P2P）。
- **映射策略**：由内部映射流程基于 **FPGA 实测的代价模型**为每个 kernel 选择瓦片数、sharding 轴、计算模式与通信模式，再由处理器瓦片下发映射配方。典型规律：单 token draft decode 行并行度有限，倾向 K-sharding；prefill 与批量验证矩阵块较大，倾向 N-sharding（无归约开销）；当提示维行并行度充足而输出较窄时用 M-sharding。

## 6. 主要结论与发现

- **瓦片级可重构有效**：可重构引擎相对 systolic-only 加速 **1.42×（Pythia）/ 2.09×（SmolLM2）/ 1.16×（GPT-2）**，相对 vector-only 加速 **3.80× / 5.97× / 8.02×**。对 systolic-only 的增益主要来自加速 draft decode，其大小取决于工作负载的相位构成而非模型规模（GPT-2 因 target 侧 prefill/验证占主导，增益最小）。
- **提升推测解码本身的收益**：相对匹配 target-only 基线，可重构架构取得最大 **1.36× / 2.04× / 3.82×** 加速，优于两种固定数据通路。
- **长度可扩展**：输出长度扫描中加速比区间为 2.67–5.14×（R/V）、1.25–2.20×（R/S）、1.15–2.12×（TR/SDR）；提示长度扫描中为 3.20–7.01×、1.31–2.20×、1.18–2.12×。随提示长度增加，GEMM 主导的 prefill 占比上升，相对 vector-only 的优势扩大。
- **系统级混合 sharding 有效**：混合策略相对最佳固定 sharding 族提升 **1.14× / 1.25× / 1.05×**（Pythia / SmolLM2 / GPT-2）。K-sharding 是最强的单一固定基线；Pythia 与 SmolLM2 的 prefill/验证内核会切换到 N 族 sharding，SmolLM2 还在较窄的 K/V 投影上用 M 族 sharding——说明没有单一 sharding 族普遍最优。
- **消融**：$\gamma\in\{4,8,16\}$ 中 **$\gamma=8$ 最优**（在暴露足够验证并行度与避免额外 draft/验证开销之间取得平衡）；固定 $\gamma=8$ 时，输出长度从 32 增至 256，加速比由 1.22× 升至 1.90×，因为生成越来越被反复的 draft/verify 循环主导。
- **平台级**：仅 100 MHz 下达到 **0.69 TPS**，约为两台 Jetson（0.19 TPS）的 **3.6×**；能效 **0.035 TPS/W**，相对 Jetson TX2（0.012）与 Orin NX（0.008）分别提升约 **2.9× 与 4.4×**。说明对延迟敏感的端侧推测解码，架构专用化可胜过标称主频优势。
- **总体论断**：推测解码的高效支持必须同时具备瓦片内（匹配 kernel 形状的计算数据流）与瓦片间（匹配 sharding 策略的通信基底）的协同灵活性。

- **评估维度全面且基线匹配合理**：三模型

- **评估维度全面且基线匹配合理**：三模型家族（GPT-NeoX、LLaMA、GPT-2）、MHA 与 GQA、提示/输出长度扫描、$\gamma$ 消融及平台级对比覆盖较全；与 target-only 采用“同提示、同完成长度”的匹配比较，避免了生成长度差异带来的偏差；数据通路三配置共享同一硬件平台并报告资源开销，横向对照较透明。
- **系统级可重构的实用性**：通过混合 sharding 与 DMA/P2P/Multicast 通信原语解决不同 kernel 形状的映射问题，实测混合策略优于最佳固定族，说明系统级灵活性可转化为真实收益。
- **低频率下的能效优势**：100 MHz FPGA 原型在 TPS/W 上超过更高标称频率的 Jetson 平台，体现架构专用化与推测解码协同设计的价值，为边缘 LLM 推理提供了有说服力的案例。
- **消融设计有针对性**：$\gamma$ 与输出长度两个维度直接对应推测解码的核心运行时参数，结论（$\gamma=8$ 最优、长输出下收益增大）对实践有指导意义。

## 8. 缺点与局限

- **原型频率与绝对性能有限**：FPGA 原型仅 100 MHz，绝对吞吐 0.69 TPS，难以直接代表 ASIC 或更高频实现；与 Jetson 的对比使用文献延迟数据而非同一实验条件实测，跨来源公平性存在不确定性。
- **模型规模偏小**：draft 为 70M–135M、target 为 160M–774M，未覆盖 7B 级及以上模型；更大模型在边缘设备上的带宽/容量瓶颈可能不同，结论外推需谨慎。
- **默认提示长度偏短**：主评估默认 $p=32$，虽然补充了 $p=64/128/256$ 扫描，但默认设置可能低估 prefill 阶段的影响，而 prefill 恰是 GEMM 主导、对数据通路选择敏感的部分。
- **统计与基线覆盖不足**：每对模型仅 20 条提示，未报告置信区间或方差；缺少与 EAGLE、Medusa、自推测解码等系统级推测优化方法的端到端对比，难以判断双层可重构相对纯算法优化的增量。
- **映射代价模型的可移植性**：映射策略依赖 FPGA 实测代价模型，移植到 ASIC 或其他工艺时需重新标定；未讨论多用户、批处理或连续批处理场景下的调度与公平性。
- **可重构性开销未充分分解**：相对 systolic-only，LUT +82%、FF +79%，控制/路由逻辑开销显著；在资源紧张的边缘芯片上可能不可忽略，但论文未给出面积与能耗的细粒度分解。
- **未涉及正交优化**：未讨论量化、稀疏化、KV cache 压缩等与推测解码正交的技术，也未分析 draft 模型质量、接受率波动对映射决策鲁棒性的影响。

## 9. 总体评价与启示

- **核心贡献**：SPECTRA 将“推测解码运行时动态性”上升为架构设计的一等约束，提出瓦片内计算数据流可重构与瓦片间并行/通信可重构的双层方案，并用 FPGA 原型验证了相对固定数据通路和固定 sharding 的收益。
- **方法学价值**：用 roofline 与 $AI(M)=M/2$ 清晰刻画验证阶段的中间工作点，指出多瓦片并行会使工作点左移，从而说明“没有单一静态映射普遍最优”，这一分析框架对边缘 LLM 加速器设计具有可迁移性。
- **工程启示**：高效支持推测解码不仅需要匹配 kernel 形状的计算单元，还需要匹配 sharding 策略的通信基底与代价模型驱动的逐 kernel 映射；算子融合与在线 softmax 进一步降低了低 $M$ 内核的本地访问开销。
- **适用边界**：当前结论主要适用于小规模模型、单序列、延迟敏感的边缘场景；在更大模型、更高频 ASIC、多序列批处理或与更先进推测算法结合时，双层可重构的收益与开销仍需重新评估。
- **总体判断**：论文问题定义清晰、设计闭环完整、实验趋势一致，是边缘推测解码加速领域具有参考价值的工作；其局限主要来自原型规模与对比范围，而非方法本身的方向性缺陷。
