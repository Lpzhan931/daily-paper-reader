## 摘要
投机解码通过让轻量级草稿模型预测未来 token 并由目标模型验证，从而无损地加速大语言模型推理。近期的块扩散草稿模型通过并行预测多个 token，进一步降低了起草延迟。然而，现有的块草稿模型将每个输入位置处的目标隐藏状态投影到一个单独的草稿模型侧 KV 缓存中，这会带来随并发量增长的每请求内存和 KV 写入开销；直接原地复用目标 KV 虽可消除该缓存，但无法在整个块内维持草稿质量。我们提出一种混合目标上下文注入方法，仅使用最后一个输入位置处的目标隐藏状态来补充直接目标 KV 复用，且无需单独的草稿模型侧 KV 缓存。基于此设计，我们提出 H-Spec，一种混合 Mamba-注意力并行草稿器，通过互补模块利用这两种目标上下文来源。Mamba 模块由投影后的末 token 目标隐藏状态初始化，而注意力模块则原地复用目标 KV。尽管 Mamba 采用循环式公式，其并行扫描使 H-Spec 能够保持块并行草稿。在三个目标模型和多种任务上，H-Spec 相比最佳基线，在平均接受长度上提升 5.0--13.3%，在批大小为 1 的 token 间延迟加速比上提升 5.3--12.6%。在并发服务下，H-Spec 在评估的各并发水平上始终实现更高吞吐量，同时保持比基线更低的 KV 缓存利用率。

## Abstract
Speculative decoding losslessly accelerates large language model inference by having a lightweight draft model predict future tokens for verification by the target model. Recent block diffusion drafters further reduce drafting latency by predicting multiple tokens in parallel. However, existing block drafters project target hidden states at every input position into a separate drafter-side KV cache, incurring per-request memory and KV-write overhead that grow with concurrency; directly reusing target KVs in place removes this cache but fails to sustain draft quality throughout the block. We propose a hybrid target-context injection method that complements direct target KV reuse with target hidden states only at the last input position, requiring no separate drafter-side KV cache. Building on this design, we propose H-Spec, a hybrid Mamba-attention parallel drafter that consumes the two target-context sources through complementary modules. Mamba modules are initialized with projected last-token target hidden states, while attention modules reuse target KVs in place. Despite its recurrent formulation, Mamba's parallel scan allows H-Spec to preserve block-parallel drafting. Across three target models and diverse tasks, H-Spec improves over the best baseline by 5.0--13.3% in mean accepted length and 5.3--12.6% in batch-size-1 inter-token latency speedup. Under concurrent serving, H-Spec consistently achieves higher throughput while maintaining lower KV cache utilization than baselines across evaluated concurrency levels.

# H-Spec 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：投机解码（Speculative Decoding）通过轻量草稿模型预测未来 token、目标模型一次性验证，实现无损加速。近期块扩散草稿器（Block Diffusion Drafter）通过并行预测多个 token 进一步降低起草延迟。
- **核心痛点**：现有块草稿器采用 **KV 注入**机制——把目标模型每个输入位置的隐藏状态投影为 Key/Value，写入一个**独立的草稿器侧 KV 缓存**。这带来两个问题：
  - **显存开销**：以官方 DFlash checkpoint 为例，草稿器使每 token KV 内存膨胀至目标模型的 **1.139×–1.800×**（Table 1）；
  - **写入开销随并发增长**：Qwen3-8B 上，每步 KV 注入时间从 4 并发到 128 并发增长 **4.7×**（Figure 3）。
- **朴素方案的失败**：直接原地复用目标模型 KV 缓存可消除该缓存，但实验（Figure 4）显示：块内早期位置（索引 0、1）草稿接受率几乎无损（−2.07~+1.91 pp），但**后期位置显著退化**，索引 2/4/6 处最多下降 6.3/12.5/16.5 pp。
- **核心研究问题**：*能否设计一种并行草稿器，在无需草稿器侧 KV 缓存的前提下，仍保持对目标模型的强条件依赖？*

## 2. 方法论

### 2.1 核心思想：混合目标上下文注入
- 观察到隐藏状态与 KV 提供的信息本质不同：
  - **隐藏状态**：整合了前序 token 信息，是面向未来预测的**上下文摘要**；
  - **目标 KV**：提供位置级的细粒度检索信息，但缺乏对整个输入的显式摘要。
- 因此提出**双源互补注入**：
  - **原地复用目标 KV**：零额外内存，提供位置级上下文；
  - **仅在最后一个输入位置注入目标隐藏状态**：因果注意力下末位隐状态条件于完整前缀，是 O(1) 存储的全局摘要。
- 两者结合既避免了 O(N) 的草稿器侧 KV 缓存，又维持了整块草稿质量。

### 2.2 H-Spec 架构（混合 Mamba-注意力）
- **Mamba 模块承载全局摘要**：用末 token 目标隐藏状态初始化 Mamba-2 的循环状态。
  - 跨层融合公式：先对选定目标层集合 M 的末位隐藏状态做拼接与投影，得到中间表示 `F_n(M) = Proj_r(Concat({h_n^(m)}_{m∈M}))`，再投影为初始状态 `S_init = Proj_dS(F_n(M))`。
  - `Proj_r` 与 `Proj_dS` 在所有草稿层共享，每轮前向只计算一次初始状态。
  - 状态更新遵循选择性 SSM：`S_i = Ā_i S_{i-1} + B̄_i x_i`，采用 Mamba-2 的 SSD 结构以提升运行时效率。
- **注意力模块承载位置级上下文**：原地复用目标 KV。
  - KV 维度与目标模型对齐，保证可直接复用；
  - **逐层 KV 映射**：每个草稿层消费某一个目标层的 KV（避免跨层融合而重新引入额外内存）；
  - 因果注意力 + 滑动窗口注意力（SWA，窗口 2048）；
  - **位置对齐**：目标 KV 已存为 post-RoPE 形式，草稿块 Q/K 必须沿用目标模型的 RoPE θ 并从目标前缀位置索引续接。
- **并行兼容性**：尽管 Mamba 是循环式公式，其线性状态递推可用**并行扫描**一次性计算所有草稿位置，从而保持块并行起草。
- **输入依赖选择性**：块输入不加位置嵌入，但首个 Mamba 模块的循环扫描天然产生位置相关隐状态，注意力模块再通过 RoPE 补充位置信息，保证块内选择性。
- **因果校正**：在混合骨干后接 DSpark 的 Markov head（一阶马尔可夫依赖），作者明确说明这**不是本文贡献**。
- **参数匹配配置**：为与 5 层 DFlash/DSpark 参数量对齐，H-Spec 采用 **4 层**（3 层完整 Mamba-注意力-MLP + 1 层部分 Mamba-MLP）；Mamba 头维度 64、状态维度/组数/卷积核 4、扩展因子 1，头数随目标模型变化（Qwen3-4B 44、Qwen3-8B 48、Llama3.1 56），总可训练参数与 DSpark 差距 ≤2.9%。

## 6. 主要结论与发现

- **单请求性能**：H-Spec 相比最佳基线，平均 τ 提升 **13.3%/5.0%/8.7%**，ITL 加速比提升 **12.6%/5.3%/8.7%**（Llama3.1-8B-IT / Qwen3-4B / Qwen3-8B），且**无需任何草稿器侧 KV 缓存**。
- **服务性能**：在全部并发档位下实现**最高吞吐**与**最低 KV 缓存利用率**；峰值吞吐比最强基线提升 13.0–17.3%（Llama）、5.1–7.4%（Qwen3-4B）、7.6–9.7%（Qwen3-8B），KV 占用降低 4.3–24.6%。吞吐优势随并发增大而扩大。
- **上下文源互补性**：去掉任一来源均显著掉点——仅末 token 隐状态掉 τ 24.1–30.5%，仅 KV 复用掉 τ 7.1–11.7%。
- **架构有效性**：混合骨干比仅 Mamba 高 τ 28.9–45.1%，比仅注意力高 13.3–15.3%。
- **运行时缩放**：低并发（C<32）时混合骨干较慢，但随并发升高与输入增长（>512 token）反超，Mamba 的 O(1) 复杂度优于注意力的 O(N)。
- **鲁棒性**：在 greedy/untruncated 采样、k∈{3,5,7}、1K–32K 上下文、微调目标迁移等设置下，H-Spec 均保持领先，且优势随草稿长度增加而扩大。

## 7. 优点

- **问题识别精准**：清晰指出现有块草稿器草稿侧 KV 缓存是可避免的系统瓶颈，并用实测数据（内存膨胀比例、注入延迟随并发增长）量化其代价。
- **方法设计有理论依据**：利用“末位隐状态是全局摘要、目标 KV 是位置级信息”的互补性，将两类上下文分别交给 Mamba 与注意力模块，动机与架构高度对齐。
- **兼顾算法与系统**：不仅提升草稿质量，还消除了随并发增长的 KV 写入与内存开销，在高并发服务场景下 Pareto 占优。
- **实验严谨**：统一训练配方复现全部基线、参数量匹配、目标层选择一致、广泛报告 bootstrap CI 与配对显著性检验，公平性强。
- **评估维度全面**：覆盖单请求延迟、并发吞吐、KV 占用、长上下文、采样参数、草稿长度、跨模型迁移等多个维度。

## 8. 不足与局限

- **架构约束**

- **架构约束**：H-Spec 的注意力模块必须与目标模型在 KV 维度、层结构、RoPE 配置上严格对齐，才能安全地原地复用目标 KV。这使草稿器高度绑定于特定目标模型，更换目标模型需重新设计逐层 KV 映射并重新训练，通用性受限，难以作为跨模型即插即用的通用草稿器。
- **训练与调参成本**：虽然推理侧消除了草稿 KV 缓存，但训练侧仍需完整的 100K 样本、5 epoch 与 10 万级优化器步数；混合骨干引入 Mamba 头维度、状态维度、组数、扩展因子等超参，论文未系统给出这些超参的敏感性分析，调参经验的可迁移性未知。
- **对末位隐状态的依赖**：全局摘要被完全压缩到最后一个输入位置的隐状态中，属于 O(1) 的信息瓶颈。当目标分布高度依赖远端细节（如长文档中的具体事实）时，该摘要可能不足以支撑高质量起草；论文在 32K 上下文上优势的收窄在一定程度上印证了这一风险。
- **低并发场景不占优**：混合骨干在 C<32 时前向耗时高于块扩散骨干，说明其在延迟敏感的低并发/单请求场景下并非普适最优，收益主要集中在高并发服务端。
- **评测覆盖面**：KV 缓存利用率与吞吐仅在单张 A100 80G、vLLM 环境下测量，未验证张量并行/流水并行或多节点部署下的行为；与 DFlash-2 仅为初步对比，未纳入主表。
- **复现透明度**：训练 GPU 的具体型号、总 GPU 小时、数据混合的完整配比与随机种子等细节披露不足，第三方独立复现存在不确定性。
- **未触及的维度**：论文未讨论草稿器对量化目标模型、MoE 目标模型或超长（>32K）上下文的表现，也未给出能耗与成本分析。

## 9. 总体评价

- **贡献定位**：H-Spec 是一篇从系统瓶颈出发、算法与架构协同设计的工作。其核心洞见——“末位隐状态=全局摘要、目标 KV=位置级检索”——简洁且可解释，直接消解了块草稿器的草稿侧 KV 缓存这一可避免的开销。
- **理论与实践匹配**：方法动机、架构选择（Mamba 承载全局摘要、注意力承载位置级上下文）与消融结果高度自洽，两类上下文来源的互补性得到了定量验证，而非仅凭直觉堆叠模块。
- **实用价值**：在单请求与高并发两类场景同时取得领先，且在高并发下呈现 Pareto 占优（更高吞吐 + 更低 KV 占用），对实际推理服务部署具有直接意义。
- **主要限制**：草稿器与目标模型的强耦合、低并发下的性能劣势，以及对超长上下文与多卡部署验证的缺失，限制了其作为“通用即插即用草稿器”的适用范围。
- **总体结论**：在“消除草稿器侧 KV 缓存同时保持块并行起草质量”这一明确目标上，H-Spec 给出了目前较有说服力的解法；其实验严谨度（统一训练配方、参数量匹配、目标层选择一致、bootstrap 置信区间与配对显著性检验）在同领域中处于较高水准，结论可信度较强。
