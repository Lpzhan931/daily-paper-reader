## 摘要
树投机解码在一次目标前向传播中验证多个候选延续。对于仅含注意力的 transformer，验证器主要需要祖先掩码。循环混合语言模型打破了这一假设：候选行还必须携带原生顺序解码沿其根到节点路径本应产生的循环状态。否则，验证器可能使用正确的注意力掩码，却仍以不可能的循环历史为条件。我们提出 GDN Tree-Scan，一个集成到 vLLM 中的、用于 Gated-DeltaNet 混合语言模型的服务化验证器。该系统结合了 FlashAttention-2 树偏置注意力、分支局部 GDN 扫描/重放、设备侧多草稿提交，以及仅对已接受链进行状态发布。在公开的 Qwen3.6-27B-FP8 检查点上，在温度 0.6 的干净 batch-one (B=1) SWE/Codex 解码门控中，一个六节点根分支树在接近原生的验证前向时间下将每次事件的已提交 token 数提高了 17.2%，并达到 23.88 token 加权的解码 tokens/s，而原生五步 MTP (E5) 为 18.80，即 27.0% 的 token 加权解码吞吐增益。按请求等价的延迟视角为 +4.0%，端到端任务墙钟时间仍以 prefill 为主。经验等价性证据的范围限于循环 oracle 概率重打分（p-rescore）在观测到的原生翻转下限内闭合，而非完整的分布距离证明。

## Abstract
Tree speculative decoding verifies multiple candidate continuations in one target forward pass. For attention-only transformers, the verifier mainly needs an ancestry mask. Recurrent-hybrid language models break this assumption: a candidate row must also carry the recurrent state that native sequential decode would have produced along its root-to-node path. Otherwise, a verifier can use a correct attention mask while still conditioning on an impossible recurrent history.   We present GDN Tree-Scan, a served verifier for Gated-DeltaNet hybrid language models integrated into vLLM. The system combines FlashAttention-2 tree-bias attention, branch-local GDN scan/replay, device-side multidraft commitment, and accepted-chain-only state publication. On the public Qwen3.6-27B-FP8 checkpoint, in a clean batch-one (B=1) SWE/Codex decode gate at temperature 0.6, a six-node root-branch tree increases committed tokens/event by 17.2% at near-native verify-forward time and reaches 23.88 token-weighted decode tokens/s versus 18.80 for native five-step MTP (E5), a 27.0% token-weighted decode-throughput gain. The per-request-equal latency view is +4.0%, and end-to-end task wall time remains prefill-heavy. Empirical equivalence evidence is scoped to recurrent-oracle probability-rescore (p-rescore) closure within the observed native flip floor, not a full distribution-distance proof.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：投机解码（speculative decoding）通过草稿模型提出候选 token，再由目标模型并行验证，从而加速自回归生成。树式投机解码把单条草稿链扩展为候选 token 树，在一次目标前向传播中验证多条候选延续，并在验证器接受规则下保持目标分布。
- **关键矛盾**：对纯注意力 Transformer，验证器的核心问题基本只是"祖先关系问题"——第 i 行只能关注提示词与其祖先，不能关注兄弟分支，一个祖先掩码即可。
- **循环混合模型打破该假设**：Qwen3.6 风格的混合栈除 softmax 注意力层外还包含大量 Gated-DeltaNet（GDN）循环层（线性注意力 + 携带式服务状态）。因此一个合法的树行需要**两个路径局部事实**：注意力祖先关系 **和** 循环状态谱系。
- **污染案例**（论文 Fig. 1）：若兄弟节点 b1 在内存中被排在脊柱节点 n1 之后，采用"打包式顺序扫描"会得到 `F(S_n1, x_b1)`，而正确结果应是 `F(S_n0, x_b1)`。此时**即使注意力掩码完全正确**，验证器仍会以"不可能的循环历史"为条件，导致验证语义错误。
- **论文定位**：贡献不是"树投机解码"本身，而是**服务化实现等价性（served-realization equivalence）**——在 vLLM / 分叉 FlashAttention-2 / GDN 写回 / 拒绝采样的真实服务路径上闭合"目标—验证器"边界。作者明确表示不主张首次混合投机解码或首次有状态树解码，也不主张与 SGLang 等相邻生产系统做同层直接对比（SGLang 的机制主要在 cache/scheduler 层）。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想：把循环状态纳入树契约

- 验证器契约（Algorithm 1）：
  - **输入**：前缀状态 `S0`、父节点数组、候选 token id、采样状态。
  - **输出**（更强）：验证与提交之后，下一个服务化解码事件必须从"原生顺序解码在已接受 token 上本应到达的同一可观测 token 前缀与循环状态"出发（在观测到的原生数值下限内）。
- **工程不变量**：树只含候选 id 与父链接；注意力行只看到前缀 + 祖先；每个 GDN 行由其**父行**的循环状态计算；提交器使用与目标验证器相同的残差规则；持久状态只对**已接受链**重放/发布。
- 关键表述："注意力祖先关系是必要条件，但不是充分条件。"

### 2.2 FA2 树分叉（注意力侧）

- vLLM 通用树注意力路径（Triton `unified_attention` 的加性祖先偏置）与原生 FA2 解码**不是同一实现**，故需要真正的 FA2 分叉。
- 实现方式：保留原有 `varlen_fwd` 不变，新增 `varlen_fwd_tree_bias` 入口，仅用于解码：
  - 对投机查询行 i 与投机键行 j：`ℓ_ij = scale·q_i k_j^T + b_ij`，其中 `b_ij = 0`（j 属于 i 的祖先），否则 `−∞`；前缀上下文列对所有行仍可见。
  - 稠密 fp32 `tree_bias` 矩阵以 `[q,q]` 或 `[B,q,q]` 元数据传入，在 QK 分数 tile 之后、FA2 掩码与 softmax 之前加入。
  - 补丁内部用 `context_len = seqlen_k − seqlen_q` 加显式 query/key 偏移把 tile 坐标映射回投机后缀坐标，避免偏置误加到前缀列；注入 FA2 累加器的值经过缩放以匹配"缩放 logits 上的加性偏置"语义。
- **解码专用**：prefill 保持原生 FA2；仅当 `FR13_FA2_TREE_BIAS=1`、解码元数据携带非空偏置矩阵、且 `max_query_len>1` 时走分叉路径，否则回退原生路径。树偏置路径中 ALiBi **fail-loud**（避免两套位置偏置机制混淆等价性主张）。

### 2.3 分支局部 GDN 扫描与重放（循环侧）

- 每个节点 i 的 GDN 后状态 `S_i` 必须等于"原生扫描（root→i 的 token 序列）"的结果；线性化打包扫描在分支跟随兄弟节点时必然错误。
- 核函数维护每个 padded 节点的后状态表 `h_cache`，形状 `[N_PAD, B_V, DIM_K]`（fp32）：
  - 节点步：`S' = exp(g_t) S_{t−1}`；`Δ_t = β_t (v_t − S' k_t)`；`S_t = S' + Δ_t k_t^T`；`o_t = S_t q_t`（rank-1 更新，与原生路径同一更新体）。
  - 扫描阶段：按拓扑序遍历节点，从 `S0` 或 `h_cache[parent(i)]` 加载父状态，计算并写入 `h_cache[i]` 供子节点使用（Algorithm 2）。
  - 提交后：设备提交器选出接受节点序列 A，**按原生顺序重放** A，只发布重放得到的 `S` 及对应卷积状态；被拒分支仅作为临时验证状态留在 `h_cache`，不得进入未来模型记忆。
- **几何与溢出边界**（Table V）：
  - 部署扫描锁定 `B_V=16`、`num_warps=8`；原生打包解码参考几何为 `B_V=32`、1 warp、3 stages。
  - `N_PAD` 为 2 的幂；cat6root 占 pad8，cat9 与更深部署族占 pad16；`n_pad > 16` 时运行期 fail-loud。
  - 资源模型：缓存后状态占用 `M_h = N_PAD · B_V · DIM_K · 4` 字节；寄存器压力估计 `R_h ≈ N_PAD·B_V·DIM_K / (32W)`。文中称部署的 cat9 几何实测 254 regs/thread、**0 spill**（128 KB），而"全树原生形状"（BV32/w1/N16，256 KB）会灾难性溢出、不可部署。
  - 明确说明：`B_V=16/w8` 不是为证明原生 SASS 一致，而是因为在 `N_PAD=1` 与 16 时对已存档扫描参考**输出位精确**、零溢出且保留足够 tile 宽度。
  - **recompute-from-spine** 变体：不缓存每个节点后状态，而从脊柱重算祖先，可回到原生 `BV32/w1/s3`、突破 pad16 状态缓存墙，代价是额外 rank-1 重放计算；这是更宽树的正确路线。
- **数值缝（numeric seams）**：门控约定、beta 的 bf16 往返、q/k 归一化用除法而非 rsqrt、输出缩放、rank-1 状态更新、输出计算后的 bf16 携带状态边界——这些不是装饰性问题，因为在投机解码中微小数值差异可能改变清晰边距的 argmax 或残差采样决策。
- **发布路径**：设备提交器选路后，运行时用已接受节点行重映射 GDN 状态与卷积状态，采用 **gather-before-scatter** 顺序避免源/目标列重叠竞态；下一个事件的卷积先验取自接受叶节点（重映射之前）。

### 2.4 草稿头与提交器

- **草稿器**：不引入辅助模型，使用 Qwen 原生 MTP 头；每次草稿步只读一次 LM-head logits：
  - argmax 作为 child-rank-0 脊柱 token，且是唯一反馈进下一步 MTP 隐状态的 token；off-spine 树节点是同一 logits 张量的**只读** runner-up 叶子（cat9 在内部脊柱步读 depth-local top-2 叶子；cat6root 只读根 runner-up，其余保持原生脊柱）。
  - 单 logits 路径是承重的：脊柱 argmax 与 runner-up 叶子来自同一全词表张量，而非通过第二个采样 helper 重算 LM head。
- **接受行采样重映射**：部分树接受会改变下一步草稿输入行。原生线性 MTP 从 `offset=accepted_len` 处采样；树路径将下一采样行映射为 `base + accepted_path[len−1]`（无草稿 token 被接受时映射到根行），防止替代分支获胜后下一步仍条件于被拒兄弟的隐状态。
- **提交器**：温度 0.6 下由部署的**设备端 multidraft** 提交器选择输出（非贪心 LCP 捷径）：对每个父节点消费目标分布、计算 SpecInfer 风格残差混合源权重、采样草稿源、以 `min(1, p/q_mix)` 接受，否则回退目标残差；设备路径消除了 host 侧 `[N_nodes × |V|]` softmax 传输与 Python 逐节点循环，同时保持 host 参考分布。旧的纯整数贪心 GPU 提交器仅用于温度 0 调优路线。

### 2.5 树形状（Fig. 3）

- **cat9**：9 节点毛毛虫树 = 5 步原生脊柱 + 4 个内部深度 top-2 runner-up 叶子。
- **cat6root**：6 节点 = 5 步原生脊柱 + **1 个根兄弟**（depth-0 备选）。当原生 MTP 因第一个脊柱 token 被拒而丢掉整个事件时，验证器仍可提交该兄弟分支，且几乎不增加验证前向时间。

- **运行时**：vLLM 镜像固定 digest `sha256:3dbe092e…8e776`，对应 `vLLM 0.19.2rc1.dev134+gfe9c3d6c5`，外加分叉 FA2 `.so` 替换与启动期 tree-GDN patcher。
- **工作负载 / 场景**：4 个 SWE/Codex 任务，**干净 B=1**、温度 0.6、真实顺序窗口、`num_running` 接近 0；部署封装固定 `GPU_UTIL=0.82`、`MAX_NUM_SEQS=1`、`MAX_MODEL_LEN=131072`、`FR13_DEVICE_MULTIDRAFT=1`。
- **对比方法（臂）**：
  - **Native E5**：原生五步 MTP 脊柱（基线）。
  - **cat9**：9 节点毛毛虫树。
  - **cat6root**：6 节点根分支树。
- **指标体系**（三种视角刻意分离）：
  - 主指标：token 加权解码 TPS（总生成解码 token / 请求解码秒数）。
  - 次指标：按请求等价 TPS（per-request-equal）。
  - 机制层：`s/fwd gpu`（纯解码前向 GPU 秒 / 纯解码草稿数）、`accept/event`、`committed/event = accept/event + 1`（验证器保证的下一 token）。
- **测量纪律**：速度模式关闭重度捕获/oracle 探针，仅保留低开销计数器；等价模式开启循环 oracle 捕获与 p-rescore，且明确不用于速度。此前的读数曾因 raw prompt 探针、B=4 共驻、插桩开销或分母错误而混淆，故最终将 token 加权吞吐、按请求延迟、p-rescore 等价与端到端墙钟 caveat 作为**不同测量**报告。等价的 p-rescore 使用各臂**自身的无投机循环解码路径**作为 oracle（此前的 chunked re-prefill 帧错误被纠正）。
