## 摘要
循环语言模型通过重复应用权重共享块来增加有效深度而不增加参数量，但每生成一个 token 由此产生的 T 次串行循环块调用会显著增加解码延迟。为解决该问题，我们提出 WaveFront 解码（WFD），一种面向循环语言模型、无需训练的自推测解码框架。WFD 利用这类架构的两个特性：中间递归输出可提供有效的草稿预测；权重共享允许不同位置和递归深度的 token 状态在一次批处理的循环块调用中处理。WFD 将这些混合深度状态组织成对角波前，在浅层深度持续起草新位置，同时将较早位置推进至全深度验证。与分阶段的先起草后验证调度不同，WFD 因此在同一批循环调用中联合批处理起草与验证，同时被拒绝的草稿通过全深度预测进行纠正。在六个 Spec-Bench 任务类别上，相较于自回归解码，WFD 在 Ouro-2.6B 上实现 2.42 倍加速，在 Huginn-3.5B 上实现 3.54 倍加速，并持续优于先起草后验证方法。跨递归 KV 共享进一步减少了波前 KV 流量，并将 WFD 在 Huginn-3.5B 上的加速提升至 4.81 倍。

## Abstract
Looped language models repeatedly apply a weight-shared block to increase effective depth without increasing parameter count, but the resulting T sequential recurrent-block calls per generated token substantially increase decoding latency. To address the issue, we introduce Wavefront Decoding (WFD), a training-free self-speculative decoding framework designed for looped language models. WFD exploits two properties of these architectures: intermediate recurrence outputs provide effective draft predictions, and weight sharing allows token states at different positions and recurrence depths to be processed in one batched recurrent-block call. WFD organizes these mixed-depth states into a diagonal wavefront, continuously drafting new positions at shallow depth while advancing earlier positions toward full-depth verification. Unlike the phase-separated draft-then-verify schedule, WFD therefore co-batches drafting and verification within the same recurrent calls, while rejected drafts are corrected using full-depth predictions. Across six Spec-Bench task categories, WFD achieves 2.42x speedup on Ouro-2.6B and 3.54x on Huginn-3.5B over autoregressive decoding, consistently outperforming draft-then-verify. Cross-recurrence KV sharing further reduces wavefront KV traffic and increases WFD's speedup to 4.81x on Huginn-3.5B.

# WaveFront Decoding（WFD）论文深度总结

## 一、核心问题与研究动机

- **背景**：循环语言模型（Looped LMs，又称 recurrent-depth / universal transformers）通过反复应用同一组权重共享的层块，在不增加参数量的前提下提升有效深度。代表架构分两族：
  - **Full-stack 型**（如 Ouro）：重复整个 Transformer 堆栈；
  - **Prelude–Recurrent–Coda（P/R/C）型**（如 Huginn）：只重复内部的循环块 R。
- **核心矛盾**：参数效率并不等于低解码延迟。每生成一个 token 需对共享循环块做 **T 次串行调用**。在小批量解码下，自回归解码受内存带宽限制，每一步都要重复从显存读取同一批权重，却几乎没有额外并行度可挖，导致循环部分的延迟近似随 T 线性增长，抵消了小参数量的优势。
- **机会**：循环结构天然提供了"草稿—验证"分解：中间递归输出往往与最终 next-token 预测一致，因此**浅层递归可充当草稿模型，全深度递归充当验证器**，且草稿阶段算出的隐状态可在验证阶段复用，无需外部草稿模型或额外训练。
- **已有基线（DtV）的局限**：作者将上述思路实例化为两阶段基线 **Draft-then-Verify（DtV）**——先以浅层深度 Td 自回归生成 γ 个草稿，再把 γ 个位置堆成 batch 从 Td 续跑到 T 做验证。但它仍是"先起草、后验证"的**分阶段交替**执行，验证时不产生新草稿、起草时也不推进验证，浪费了本可共享同一批权重调用的批处理机会。
- **本文目标**：消除起草与验证之间的相位边界，把两者融合进同一次前向调用，从而在**不训练、不改模型、不加辅助模型**的前提下显著降低解码延迟。

## 二、方法论：WaveFront Decoding

### 1. 核心思想
- 让多个 token 位置**同时处于不同递归深度**"在途"（in-flight），用**一次批处理的循环块调用**同时推进所有位置的状态。
- 这些混合深度的状态在"位置 × 时间步"网格上形成一条**对角波前（diagonal wavefront）**：新位置在浅层被持续起草，较早位置同时被加深并走向全深度验证。
- 结果：起草、中间递归、验证三件事**并发进行**，而非交替进行。被拒绝的草稿由全深度预测纠正，因此**按构造保持自回归输出**（贪心验证下逐 token 等价）。

### 2. 架构抽象与算法流程
- 统一抽象为三元组 **(P, R, C)**：P（prelude）把输入 token 映射为初始隐状态；R（recurrent block）把状态更新 T 次；C（coda）把状态映射为 next-token logits。
  - 状态演化：`s⁰ᵢ = P(xᵢ)`，`sᵗᵢ = R(sᵗ⁻¹ᵢ, eᵢ)`（t=1…T），`ℓᵗᵢ = C(sᵗᵢ)`。
  - Full-stack 模型是 R 包含整个堆栈、不再注入 eᵢ、P/C 退化为 embedding 与 LM head 的特例。
- **Algorithm 1（调度器）**要点：
  1. 预填充 prompt，贪心取首个 token 并送入待处理集合 A_P；
  2. 循环中：若 A_P 非空，则执行一次 P 把新位置加入 A_R；
  3. 对 A_R 执行**一步** R，把到达草稿点（step = Td）或提交点（step = T）的 token 送入 A_C；
  4. 对 A_C 执行一次 C：
     - 到达 T 的 token 触发**验证**：与波前中同位置的草稿 token 比对；一致则提交，不一致则提交纠正 token、**冲刷**该位置之后所有在途位置，并从纠正 token 处重新生长波前；
     - 到达 Td 的 token 触发**起草**：贪心取新 token 加入 A_P，进入波前。
- **稳态波前宽度**：`W = ⌈T / Td⌉`。调度器对 T、Td 的取值方式不敏感，可无缝适配自适应深度变体；验证用贪心，但调度器兼容任意采样方法。

### 3. 成本模型与加速分析
- **关键前提**：解码阶段 R 是**内存带宽受限**的；在小批量下，对多位置的一次批处理调用只流式读取一次共享权重，延迟与单位置调用几乎相同（附录 B.1 用算术强度分析佐证）。因此延迟主要由**每提交一个 token 所需的串行循环块调用次数**决定，而非 FLOPs。
- 设 L_P、L_R、L_C 为一次（可批处理）调用的延迟，全接受（α=1）时稳态每 token 延迟为：
  - **AR**：`L_AR = L_P + T·L_R + L_C`
  - **DtV**：`L_DtV = L_P + L_R·(γTd + (T−Td))/γ + L_C`，当 γ→∞ 时趋近 `L_P + Td·L_R + L_C`
  - **WFD**：`L_WFD = L_P + Td·L_R + L_C`
- **核心结论**：WFD 用**有限的在途宽度 W = ⌈T/Td⌉** 就达到了 DtV 在 γ→∞ 时的渐近每 token 延迟。稳态下每 Td 次批处理 R 调用提交一个 token（推进新位置至草稿点的调用同时推进旧位置至验证点）。L_P + L_C 项三种方法都要付一次，因此 WFD 加速上限为 T/Td。
- **拒绝代价对比**：
  - DtV 一旦拒绝，丢弃整个草稿块的后缀，浪费随 γ 增长，须在"验证摊销"与"拒绝浪费"间权衡最优 γ；
  - WFD 一次拒绝最多冲刷 **W−1 个在途位置**（且这些位置只被部分推进），上限由架构常数 W ≤ T 界定，与起草激进度无关，随后从纠正前缀渐进补满波前——这解释了 WFD 在低接受率下的鲁棒性。

### 4. 跨递归 KV 共享（近似扩展）
- **瓶颈识别**：DtV 验证时所有位置处于同一递归步、访问同一份 recurrence-specific KV cache；而 WFD 中位置处于不同递归步，访问**不同的递归专属 KV 槽**，导致 KV 流量随波前宽度 W 增长。长上下文下这会抵消批处理权重读取的收益（Huginn 的 W=8 比 Ouro 的 W=4 更严重）。
- **对策**：跨递归 KV 共享让混合深度位置访问**公共 cache**，直接消除该流量。它与权重共享互补（权重共享摊销权重读取，KV 共享削减递归级 KV 流量）。
- **注意**：由于共享 KV 状态会随 token 加深而被更新，波前位置可能观察到与串行 AR 不同的更新阶段，因此**WFD + KV 共享被视为近似扩展**，需单独评估精度。

## 六、主要结论与发现

- 早期递归输出本身即是强草稿：任务级接受率 0.78–0.97，整体 α 为 **Ouro 0.92 / Huginn 0.94**，无需任何训练。
- **WFD 在每一个任务上均优于 DtV**：整体相对 AR 加速 **2.42×（Ouro）/ 3.54×（Huginn）**，相对 DtV 再提升约 **1.27×**。
- **接受率越低，WFD 相对 DtV 的优势越明显**：如 Ouro 翻译任务 α=0.78/0.80 时，DtV 仅 1.06×，WFD 仍保持 1.92×，与"DtV 拒绝浪费随 γ 增长、WFD 拒绝冲刷有界"的分析一致。
- 受控实验显示 WFD 在 α ∈ [0.6, 0.95] 全区间优于所有 DtV 配置，且**不需要单独调草稿块长度 γ**（其投机占用被 W 自然界定）。

- **批量扩展性**：随着用户 batch size 增大，自回归解码本身获得更多可并行位置，内存带宽受限假设被削弱，AR 的相对劣势收窄，WFD 的加速比随之下降；但在扫描范围内（1–64，含 OOM 边界），WFD 始终优于 DtV，且在加上 KV 共享后能在更大 batch 下保持正收益。这说明 WFD 的收益定位是**小批量、延迟敏感的在线服务场景**，而非高吞吐离线批处理。
- **草稿深度敏感性**：Td 扫描（图 7）显示吞吐对 Td 存在单峰，且最优值恰好落在"早退接受率 × 同时活跃位置数"的平衡点（Ouro T=4 取 Td=1、Huginn T=32 取 Td=4），与 `W = ⌈T/Td⌉` 的理论预测一致；调度器对 T、Td 的具体取值不敏感，可无缝接入自适应深度变体。
- **机制归因的干净性**：CUDA graph 抽查（表 7）表明 WFD 的收益不是 kernel launch 开销被消除带来的假象；fp32 精确性验证（表 8）显示 AR 与 WFD 在 GSM8K 前 100 条 prompt 上 **token 级完全一致**，证明 bf16 下 WFD 略高的精度仅来自批形状与归约顺序的数值差异，而非算法层面的精度改变——WFD 在贪心解码下是**逐 token 精确等价**于自回归输出的。
- **roofline 归因**：附录 B 的算术强度分析预测了解码阶段的吞吐上界，实测中 Huginn 较接近该上界，而 **Ouro 仅达到 roofline 的约 18%**，作者将其归因于 full-stack 架构下 P/C 调用在每 token 延迟中占比更高、以及实现层面的调度与内存开销，而非 WFD 调度本身的失效。

## 七、局限与未来工作

- **解码方式受限**：所有实验均为贪心解码，调度器虽在设计上兼容任意采样方法，但采样、树状草稿（tree drafting）与投机解码的联合实测缺失，实际部署中的温度采样场景收益未知。
- **模型覆盖有限**：仅验证了两个公开 checkpoint（Ouro-2.6B、Huginn-3.5B），分别代表 full-stack 与 P/R/C 两族，但未覆盖更大规模或不同递归深度配置的模型，Td 的最优取值规律能否跨规模迁移尚无证据。
- **KV 共享是近似扩展**：共享 KV 会改变位置观察到的更新阶段，因此 WFD + KV 共享在严格意义上偏离了精确自回归语义，需要按模型单独验证精度；且 **Ouro 无法承受朴素的事后 KV 共享**，说明该优化并非普适，取决于模型训练时 KV 的组织方式。
- **接受率场景偏乐观**：自然场景下任务级接受率高达 0.78–0.97，低接受率区间的结论主要依赖人工强制伯努利采样，真实分布外（OOD）或高熵生成场景下的鲁棒性有待检验。
- **实现复杂度与显存开销**：波前需要同时驻留 W 个不同递归深度的隐状态与（在无共享时）多份递归专属 KV 槽，显存占用高于 DtV；调度器需维护 A_P / A_R / A_C 三集合与冲刷—重生长逻辑，工程实现门槛不低。

## 八、总体评价

- **贡献定位**：WFD 把循环语言模型中"浅层即草稿、深层即验证"的直觉，从**分阶段交替（DtV）**重构为**同一前向调用内的相位融合**，用一条对角波前让起草、加深、验证三件事并发。这是一个**概念简洁、约束极少（training-free、无辅助模型、不改权重）、理论刻画完整**的系统级优化。
- **理论亮点**：以"每提交一个 token 所需的串行循环块调用次数"为延迟货币，给出三种方法的闭式延迟模型，并指出 WFD 用**有限宽度 W = ⌈T/Td⌉** 即达成 DtV 在 γ→∞ 时的渐近延迟；同时用"拒绝冲刷上界 ≤ W−1"解释了 WFD 在低接受率下相对 DtV 的结构性优势，理论与实验（α 扫描、γ 调优对比）高度自洽。
- **实证强度**：两族架构 × 六类任务 × 四维受控扫描，加上 CUDA graph 与 fp32 等价性验证，证据链较为完整；DtV 基线经过 γ 调优，比较口径公平；对 bf16 精度差异的诚实归因、对 Ouro roofline 达标率偏低的主动说明，都提升了可信度。
- **保留意见**：核心增益建立在"小批量解码受内存带宽限制"这一前提上，因此适用边界清晰但偏窄；KV 共享作为近似手段的模型依赖性（Ouro 不适用）削弱了方法在长上下文场景下的普适性；采样/树状草稿的缺失使结论目前仅对贪心解码成立。总体而言，这是一篇**问题选得准、分析做得透、工程约束讲得清**的推理加速工作，其价值更多在于揭示循环架构"参数效率 ≠ 解码效率"这一被忽视的错配，并给出一个近乎零成本的调度层解法。
