## 摘要
长上下文 LLM 推理的瓶颈在于注意力机制：其反复的 KV 缓存读取使解码受限于内存。自推测解码通过用稀疏注意力草拟 token、再用全注意力对其进行验证来缓解这一问题，但现有的批量方法仍是同步的：同一批次中的所有请求共享单一的草拟—验证调度，尽管最优草拟长度在不同请求之间差异很大，且在单个请求内部也会动态变化。我们提出 ASPIRE，一个非同步的批量自推测解码框架，它由三个组件构成。首先，统一的混合前向传播允许草拟请求与验证请求共存于同一次批量前向传播中，从而无需全局的草拟—验证阶段。其次，轻量级的在线推测调度器利用按请求估计的接受率与批次感知的成本模型，使每个请求能够独立选择何时进行验证。第三，草拟内刷新层在草拟过程中于单个指定层执行全注意力，在每个草拟步更新稀疏上下文，以降低草拟过程中的陈旧性。在三个模型和五个推理与长上下文基准上，ASPIRE 的解码吞吐量相较自回归基线实现了 $1.70$–$4.58\times$ 的加速，并且相较最强的已有自推测基线将平均加速比提升了约 $27\%$。

## Abstract
Long-context LLM inference is bottlenecked by attention, whose repeated KV-cache reads make decoding memory-bound. Self-speculative decoding alleviates this by drafting tokens with sparse attention and verifying them with full attention, but existing batched methods remain synchronized: all requests in a batch share a single draft-verify schedule, even though the optimal draft length varies widely across requests and changes dynamically within each request. We propose ASPIRE, a non-synchronized batched self-speculative decoding framework built on three components. First, a unified mixed forward allows drafting and verifying requests to coexist in the same batched forward pass, removing the need for global draft-verify phases. Second, a lightweight online speculation scheduler uses per-request acceptance-rate estimates and a batch-aware cost model to let each request independently choose when to verify. Third, an intra-draft refresh layer performs full attention at a single designated layer during drafting, updating the sparse context at every draft step to reduce staleness during drafting. Across three models and five reasoning and long-context benchmarks, ASPIRE achieves $1.70$-$4.58\times$ speedup in decoding throughput over autoregressive baselines and improves average speedup by approximately $27\%$ over the strongest prior self-speculative baselines.

## 1. 核心问题与整体含义

- **背景瓶颈**：长上下文 LLM 推理中，MLP 受模型权重访问主导、可随批大小摊薄而呈计算受限；而自注意力为每个请求维护独立 KV 缓存，无法跨批次摊薄，每个新 token 都要重读该请求的完整历史 KV，因而随序列长度与批大小增长呈**内存受限**（低算术强度）。
- **现有解法**：自推测解码（self-speculative decoding）以"稀疏注意力草拟 + 全注意力精确验证"的方式，把昂贵的全 KV 读取只发生一次，并在多个被接受 token 上摊薄，MagicDec、Vegas 等系统已证明其在长上下文中的价值。
- **核心痛点**：现有批量自推测方法仍是**全局同步**的——整批请求共享同一套草拟—验证节奏，而论文的实证研究表明：
  - **跨请求高度异质**：256 个 LongBench 样本（前缀 16k–20k）中，每请求平均接受草稿长度从 **2.56 到 20.00**（均值 11.51）；
  - **请求内高度动态**：单个请求在不同验证轮次间接受长度波动显著；
  - 同步批处理因此迫使部分请求"草拟不足"、部分"草拟过度"，损失并行效率。
- **整体含义**：论文主张把同步边界从"批次级"下移到"请求级"，让同一批次内的请求各自沿不同推测轨迹推进，同时保留批量执行的 MLP 摊薄收益；这为长上下文推理吞吐优化提供了一个新的调度维度。

## 2. 方法论

### 2.1 核心思想
用**统一混合前向**消除全局草拟/验证阶段，用**在线逐请求调度器**决定每个请求何时验证，用**草拟内刷新层**抑制稀疏上下文陈旧，三者协同提升"推测利用率"。

### 2.2 统一混合前向（Unified Mixed Forward）
- 在第 $t$ 步，活跃请求分为验证集 $V_t$ 与继续草拟集 $D_t$；每个请求 $i$ 维护当前草稿长度 $d_i$ 与稀疏上下文 $\mathcal{S}_i$。
- 因草拟与验证共用同一目标模型权重与 MLP 计算，二者仅差在注意力上下文与解码长度：
  - $D_t$ 中请求：用稀疏注意力对 $\mathcal{S}_i$ 解码 **1 个 token**；
  - $V_t$ 中请求：用全注意力解码 **$d_i+1$ 个 token**（覆盖草拟前缀 + 1 个额外 token）。
- 通过为每个请求指定各自的注意力上下文与解码长度，异质请求可在**同一次批量前向**中执行，保留 MLP 的 GEMM 化收益，同时让注意力保持请求私有。
- 前向结束后：$V_t$ 请求比对草稿前缀与全上下文输出，把接受的前缀 + 已验证的下一 token 追加进上下文并重置 $d_i$；$D_t$ 请求追加 1 个草稿 token 并使 $d_i$ 加一。

### 2.3 在线推测调度器（Speculation Scheduler）
- **目标草稿长度 $\gamma_i$**：设 $c_i = T^{\text{draft}}_i / T^{\text{verify}}_i$，在接受率估计 $\alpha_i$ 下，期望提交 token 数为 $(1-\alpha_i^{\gamma+1})/(1-\alpha_i)$，期望周期时间为 $T^{\text{verify}}_i(1+c_i\gamma)$，于是
  $$\gamma_i=\arg\max_{\gamma\in\{0,\dots,d_{\max}\}}\frac{(1-\alpha_i^{\gamma+1})/(1-\alpha_i)}{1+c_i\gamma}.$$
- **接受率估计 $\alpha_i$**：若草拟 $d_i$ 个、接受 $a_i$ 个，则 $\hat\alpha_i=a_i/\min(a_i+1,d_i)$（部分接受视为 $a_i$ 次成功 + 1 次失败，全接受视为 $d_i$ 次成功），再做指数平滑 $\alpha_i\leftarrow \omega\alpha_i+(1-\omega)\hat\alpha_i$；初始用先验 $\alpha_0$，且首次验证前至少草拟 $\gamma_{\text{init}}$ 个 token。
- **批次感知代价比 $c_i$**：用拟合运行时迹的三项步时模型
  $$\tau_t=\beta_{\text{model}}+\beta_{\text{mlp}}\cdot n_t+\beta_{\text{attn}}\cdot\Big(\sum_{j\in D_t}|\mathcal{S}_j|+\sum_{j\in V_t}\ell_j\Big),\quad n_t=|D_t|+\sum_{j\in V_t}(d_j+1),$$
  即 MLP 项随前向 token 总量线性（计算受限）、注意力项随读取的 KV 长度线性（内存受限）。在"整批 $B$ 个槽位均为请求 $i$ 副本"的均质近似下得到 $T^{\text{draft}}_i=\beta_{\text{model}}+\beta_{\text{mlp}}B+\beta_{\text{attn}}B|\mathcal{S}_i|$、$T^{\text{verify}}_i=\beta_{\text{model}}+\beta_{\text{mlp}}B(d_i+1)+\beta_{\text{attn}}B\ell_i$，并随 $d_i,\ell_i,|\mathcal{S}_i|$ 在线重算。
- **决策规则**：当 $d_i\ge\gamma_i$ 或 $d_i\ge d_{\max}$ 时验证，否则继续草拟（Algorithm 1）。

### 2.4 草拟内上下文刷新（Intra-Draft Refresh）
- 指定**单层刷新层 $\ell_r$**（默认倒数第二层 $N-2$）：草拟时其余层走稀疏注意力，该层执行**全注意力**并捕获注意力 logits，用于为下一步刷新稀疏集；验证时直接复用已有的全注意力结果（取首、末验证 token 的 logits 平均）。
- **稀疏集选择**：对 logits 做 online softmax 得权重 $A^{\text{src}}_{i,t,h}(u)$，token 重要性 $r_{i,t}(u)=\max_h A^{\text{src}}_{i,t,h}(u)$；在分页 KV 上以页为单位打分 $s_{i,t}(P)=\sum_{u\in P}r_{i,t}(u)$；预算 $k_i=\max(k_{\min},\lceil\rho P_i\rceil)$，其中 $P_i=\lceil\ell_i/\text{page\_size}\rceil$，并在预算内**始终保留最近 $L$ 页**保证局部连续性，其余按分数取 top。
