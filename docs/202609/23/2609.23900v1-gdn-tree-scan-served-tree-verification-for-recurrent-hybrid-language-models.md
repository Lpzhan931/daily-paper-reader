## 摘要
树形推测解码在一次目标前向传播中验证多条候选续写。对于纯注意力 Transformer，验证器主要只需要一个祖先关系掩码。循环-混合语言模型打破了这一假设：候选行还必须携带原生顺序解码沿其根到节点路径本应产生的循环状态。否则，验证器可能使用了正确的注意力掩码，却仍以一个不可能出现的循环历史作为条件。我们提出 GDN Tree-Scan，这是一个集成于 vLLM 的、面向 Gated-DeltaNet 混合语言模型的服务化验证器。该系统结合了 FlashAttention-2 树偏置注意力、分支局部 GDN 扫描/重放、设备端多草稿提交，以及仅对被接受链进行状态发布。在公开的 Qwen3.6-27B-FP8 检查点上，在温度 0.6 下的干净 batch-one（B=1）SWE/Codex 解码门控中，六节点根分支树在接近原生的验证前向耗时下将每次事件提交 token 数提升 17.2%，并达到 23.88 个按 token 加权的解码 token/s，而原生五步 MTP（E5）为 18.80，即按 token 加权的解码吞吐量提升 27.0%。在按请求等量的延迟视角下为 +4.0%，端到端任务墙钟时间仍以 prefill 为主。经验等价性证据仅限于在观测到的原生翻转下限内的循环预言机概率重打分（p-rescore）闭合，而非完整的分布距离证明。

## Abstract
Tree speculative decoding verifies multiple candidate continuations in one target forward pass. For attention-only transformers, the verifier mainly needs an ancestry mask. Recurrent-hybrid language models break this assumption: a candidate row must also carry the recurrent state that native sequential decode would have produced along its root-to-node path. Otherwise, a verifier can use a correct attention mask while still conditioning on an impossible recurrent history.   We present GDN Tree-Scan, a served verifier for Gated-DeltaNet hybrid language models integrated into vLLM. The system combines FlashAttention-2 tree-bias attention, branch-local GDN scan/replay, device-side multidraft commitment, and accepted-chain-only state publication. On the public Qwen3.6-27B-FP8 checkpoint, in a clean batch-one (B=1) SWE/Codex decode gate at temperature 0.6, a six-node root-branch tree increases committed tokens/event by 17.2% at near-native verify-forward time and reaches 23.88 token-weighted decode tokens/s versus 18.80 for native five-step MTP (E5), a 27.0% token-weighted decode-throughput gain. The per-request-equal latency view is +4.0%, and end-to-end task wall time remains prefill-heavy. Empirical equivalence evidence is scoped to recurrent-oracle probability-rescore (p-rescore) closure within the observed native flip floor, not a full distribution-distance proof.

## 1. 核心问题与整体含义

### 研究背景
- **树形投机解码（Tree Speculative Decoding）** 的核心思想是：在一次目标模型前向传播中同时验证多条候选续写路径，从而提升单位前向的产出效率。
- 对于**纯注意力 Transformer**，验证器的核心问题相对简单：只需构建正确的**祖先关系掩码（ancestry mask）**，保证第 *i* 行只能看到提示词和其祖先节点，不能看到兄弟分支即可。
- **循环-混合语言模型（Recurrent-Hybrid LM）** 打破了这一简化假设。以 Qwen3.6 为例，其 64 层中包含 48 层 Gated-DeltaNet（GDN）循环层和 16 层 softmax 注意力层。

### 核心问题
- 在循环混合模型中，一个候选节点行**不仅要携带正确的注意力祖先关系，还必须携带原生顺序解码沿其根到节点路径本应产生的循环状态（recurrent state）**。
- 否则会出现图 1 所示的"最小污染案例"：验证器使用了正确的注意力掩码，却让兄弟分支节点继承了错误的前驱打包行（packed row）的循环状态，导致其**条件于一个不可能出现的循环历史**。
- 论文指出：**注意力祖先关系是必要条件，但远非充分条件**。

### 整体含义
- 论文的贡献定位不是"树形投机解码"本身，而是**服务化实现等价性（served-realization equivalence）**这一实现目标：在 vLLM / forked-FA2 / GDN 的实际服务栈上，闭合目标验证器边界。
- 作者明确声明：不主张首次提出混合模型投机解码，也不主张首次提出有状态树解码。

## 2. 方法论

### 核心思想
将循环状态纳入树契约，构建一个**验证器契约（Verifier Contract）**：验证任意候选树后，下一次服务化解码事件必须从与原生顺序解码相同的可观测 token 前缀和循环状态出发（在观测到的原生数值翻转下限内）。

### 输入/输出契约
- **输入**：前缀状态 S₀、父节点数组（parent array）、候选 token ids、采样状态。
- **输出**：验证并提交后，下一解码事件的 token 前缀与循环状态边界，与原生顺序解码在已接受前缀上一致。

### 工程不变量
> 若树中只含候选 ids 与父链接；注意力行只看到前缀与祖先；每个 GDN 行由其父行的循环状态计算；提交器应用与目标验证器相同的残差规则；且持久状态仅对接受链重放或发布——则下一解码事件与原生顺序解码边界一致。

### 关键技术组件

#### （1）FA2 Tree-Fork（注意力侧）
- vLLM 通用树注意力路径（Triton unified_attention）与原生的 FA2 解码**不是同一种实现**，因此需要真正的 FA2 fork。
- 保留原生 `varlen_fwd` 不变，新增 `varlen_fwd_tree_bias` 入口，仅用于解码（decode-only）。
- 对投机查询行 *i* 与投机键行 *j*，实现：
  - ℓᵢⱼ = scale·qᵢkⱼᵀ + bᵢⱼ
  - bᵢⱼ = 0 若 j ∈ ancestors(i)，否则 −∞
- 前缀上下文列对所有行可见；密集 fp32 `tree_bias` 矩阵在 QK 分数 tile 之后、FA2 掩码与 softmax 之前加入。
- 通过 `FR13_FA2_TREE_BIAS=1`、非空 bias 矩阵、`max_query_len>1` 三个条件触发；prefill 保持原生 FA2。ALiBi 在 tree-bias 路径上**fail-loud**（避免两种位置偏置机制混合）。

#### （2）分支局部 GDN 扫描/重放（循环侧）
- GDN 递推是带状态的线性注意力更新，服务核实现与原生路径相同的 rank-1 更新体：
  - S′ₜ = exp(gₜ)Sₜ₋₁
  - Δₜ = βₜ(vₜ − S′ₜkₜ)
  - Sₜ = S′ₜ + Δₜkₜᵀ
  - oₜ = Sₜqₜ
- 对树节点 *i*，不变量为：**Sᵢ = native scan(tokens(root → i))**。
- 线性化的树扫描在分支跟随兄弟节点于内存中时必然错误：若 b1 是 root n0 的子节点，正确状态应为 S_b1 = F(S_n0, x_b1)，而非 F(S_n1, x_b1)。
- 核为每个 padded 节点保存后状态于 `h_cache`，形状为 `[NPAD, BV, DIM_K]`（fp32）。
- 资源模型：
  - 缓存后状态内存：**M_h = NPAD · BV · DIM_K · 4 bytes**
  - 寄存器压力估算：**R_h ≈ NPAD · BV · DIM_K / (32W)**
- 部署几何：**BV=16，num_warps=8**；cat6root 用 pad8，cat9 用 pad16；n_pad > 16 时 fail-loud。
- 关键：**扫描与重放调用同一 node-step 体**，防止"验证用一种递推、发布用另一种递推"。

#### （3）设备端多草稿提交（Committer）
- 使用 Qwen 原生 MTP 头作为 drafter：根与 spine token 来自同一 logits 张量，runner-up 叶子作为 top-k 候选。
- 在温度 0.6 下，由设备端 multidraft 提交器选择输出：对每个父节点，消费目标分布、计算 SpecInfer 风格残差混合源权重、采样 draft 源、以 min(1, p/q_mix) 接受、否则回退到目标残差。
- 设备端路径消除了主机端 [Nnodes × |V|] softmax 传输和 Python 逐节点循环。
- 部分树接受时需**采样行重映射**：映射到 base + accepted_path[len−1]，或未接受草稿时的根行，防止下一步 MTP 条件于被拒兄弟的隐藏状态。

#### （4）仅接受链状态发布（Publication）
- 提交后，按原生顺序重放接受链，再写回持久状态。
- 使用 gather-before-scatter 排序，避免源/目标列重叠竞争。
- 卷积先验取自接受叶子；被拒行仅保留在 `h_cache` 中作为临时验证状态。

#### 算法流程（Algorithm 1 & 2）
1. 将候选 ids、父索引、祖先掩码打包进 vLLM 解码元数据。
2. softmax 注意力层用 FA2 tree bias，行 *i* 仅见前缀与祖先。
3. 对每个 GDN 层，按拓扑序处理每个节点：从 S₀ 或 `h_cache[parent]` 加载父状态，计算 Sᵢ 与 oᵢ，存入 `h_cache[i]`。
4. 设备端应用残差投机接受规则。
5. 按原生顺序重放接受路径，仅发布接受的 GDN/conv 状态。

## 6. 主要结论与发现

1. **循环状态是树验证的必需部分**：仅靠注意力祖先掩码不足，GDN 行必须从父行状态计算，而非前一个打包行。
2. **cat6root 在干净 B=1 解码吞吐上优于原生 E5**：
   - committed tokens/event 从 4.11 提升到 4.82（**+17.2%**）；
   - token 加权解码 TPS 23.88 vs 18.80（**+27.0%**）；
   - 验证前向耗时几乎原生（0.138 vs 0.137 s/fwd）。
3. **根兄弟节点的价值**：它是深度-0 的替代分支，能挽回原生 MTP 在第一个 spine token 被拒时损失的事件，而非把额外计算花在需全部祖先存活的深层叶子上。
4. **按请求等
