## 摘要
长上下文大语言模型应用（如文档摘要和多轮智能体）需要从数万token的前缀生成内容，使解码延迟成为主要瓶颈。投机解码在不改变模型输出的情况下降低延迟，但其加速取决于接受的草稿token数和草稿步骤延迟：轻量草稿速度快但缺乏捕获长距离依赖的能力，而强独立草稿虽能恢复接受率，但在长前缀下会带来不断增长的KV访问成本。我们引入了用于长上下文投机解码的记忆增强草稿方法，为强独立草稿配备压缩的草稿侧KV记忆：一个轻量适配器构建并增量更新该记忆，以保留遥远信息和精确的近期上下文。目标验证器保留其完整KV缓存，并应用标准接受/拒绝规则，从而保持投机解码的无损保证。在前缀长度高达32K的Llama~3.1-8B和70B目标上的实验表明，我们的方法将草稿侧记忆减少了超过70%。与自回归解码相比，它分别实现了高达2.08倍和3.33倍的加速。

## Abstract
Long-context LLM applications such as document summarization and multi-turn agents require generation from prefixes spanning tens of thousands of tokens, making decoding latency a major bottleneck. Speculative decoding (SD) reduces latency without changing model outputs, but its speedup depends on both accepted draft tokens and draft-step latency: Lightweight drafts are fast but lack the capacity to capture long-range dependencies, whereas strong independent drafts recover acceptance but incur growing KV-access cost at long prefixes. We introduce memory-augmented drafting for long-context SD, equipping a strong independent draft with compressed draft-side KV memory: A lightweight adaptor constructs and incrementally updates this memory to retain distant information and exact recent context. The target verifier retains its full KV cache and applies the standard accept/reject rule, preserving SD's lossless guarantee. Experiments on Llama~3.1-8B and 70B targets at prefix lengths up to 32K show that our method reduces draft-side memory by over 70%. It achieves speedups of up to 2.08x and 3.33x , respectively, over autoregressive decoding.

## 1. 核心问题与研究动机

**背景：**
- 长上下文 LLM 应用（如文档摘要、深度检索、多轮智能体等）需要在数万 token 的前缀条件下生成，自回归（Autoregressive）解码天然串行，导致解码延迟成为瓶颈。
- 投机解码（Speculative Decoding，SD）通过让轻量草稿模型（draft model）先提议若干 token，再由目标模型并行验证，可在不改变输出分布的前提下降低延迟。
- SD 的加速效果取决于两个互相竞争的因素：草稿平均接受长度 `L_acc`（需要草稿足够逼近目标模型）和草稿单步相对延迟 `td/tt`（需要草稿比目标模型便宜得多）。

**核心矛盾（长上下文 SD 困境）：**
- 轻量草稿（如 EAGLE 式单层采样头）在大前缀下容量不足，无法捕获长距离依赖，接受长度随上下文增长而下降。
- 强独立草稿（如 3B 独立模型）恢复接受率，但每一步草稿解码都需读取全部历史 KV 缓存，KV 访问成本随前缀长度线性增长，侵蚀端到端加速。
- 因此，理想的长上下文草稿应当**具备足够容量以保持高接受率**，同时**避免扫描完整前缀以保持低延迟**。

## 2. 方法论：Memory-Augmented Sliding-Window (MASW) Drafting

### 核心思想
本文提出**记忆增强滑动窗口草稿（MASW）**：为**强大的独立草稿模型**配备一个**压缩的草稿侧 KV 记忆**。该记忆由三部分构成，由轻量可训练适配器构建并增量更新，既保留远距离历史压缩信息，又精确保留近期原始上下文。目标验证器始终保留完整 KV 缓存，故无损性保持。

### 草稿侧记忆结构（三部分）
在解码步 `t`，草稿侧工作记忆 `Mt` 定义为：
- **Sink 记忆 `Msink`**：序列最前 `S` 个原始 token 的 KV 条目，始终保留，稳定注意力；
- **局部窗口 `Mlocal,t`**：最近 `W` 个非 sink 原始 token 的精确 KV 条目（滑动窗口，随解码推进被逐出）；
- **记忆槽 `Mslot,t`**：每隔 `r` 个原始 token 插入一个记忆槽 token `gm`，作为对已逐出历史信息的压缩表征，不断累积形成压缩记忆链。

这样的设计使草稿每次访问量由 `S + W + ⌊t/r⌋` 决定，与完整前缀长度 `t` 解耦。

### 记忆物化（Memory Materialization）机制
- 每个压缩边界 `τm = m·r` 处，插入一个记忆槽 token `gm`，通过正常 Transformer 前向计算，其条件为当前局部窗口、sink token 及此前所有记忆槽：
  `gm ← fθ(Mlocal,τm, Msink, Mslot,<m)`；
- 该过程通过**结构化注意力掩码**实现（而非人工池化规则），实现“压缩—逐出—累积”的增量记忆链；
- **镜像投影矩阵**：记忆槽在每个 transformer 层的 K/V 由专门的**可训练镜像投影矩阵** `W_K,g^{(l)}`、`W_V,g^{(l)}` 产生，初始化时复制自冻结骨干的原始 K/V 投影；原始 token 仍使用冻结的骨干投影；
- RoPE 位置：记忆槽与紧随其后的原始 token 共享同一位置 ID，避免为后续 token 移动原始位置。

### 预填充（Prefill）
- 目标与草稿分别预填充同一前缀；草稿使用结构化记忆掩码，在单次前向中同步物化前缀记忆槽，且草稿预填充与目标预填充**并行运行**（草稿预填充延迟 `Pd < Pt`，总体为 `max(Pd, Pt) = Pt`），不增加首 token 延迟。

### 验证与无损性
- 目标验证器使用不变的标准全前缀 KV 缓存；
- 拒绝时草稿丢弃已物化的回滚窗口外局部 KV 与拒绝点后的记忆槽；
- 标准 accept/reject 规则照常应用，**无损保证（lossless guarantee）完整保留**。

## 6. 主要结论与发现

1. **长上下文 SD 困境确认**：EAGLE 的 `L_acc` 随前缀长度单调下降（8B 上），而独立 3B 草稿的接受长度保持稳定——长上下文 SD 需要**更强的草稿容量**；
2. **KV 访问主导延迟**：解码延迟随前缀长度近似线性增长，且斜率受**KV 访问主导**而非模型大小——降低了上下文访问成本比增加草稿容量更重要；
3. **MASW 大幅降低草稿侧 KV 成本**：草稿侧额外峰值内存从 17.21~18.02 GB 降至 3.98~5.05 GB（减少 70%+），草稿延迟从 41.34~54.92 ms 降至 12.39~15.37 ms；
4. **加速一致性**：在 Llama 3.1-8B 目标上最高 2.08×、70B 目标上最高 3.33×，且在长前缀下持续优于自回归、全 KV SD、EAGLE、EAGLE-3、SWA、SnapKV 等基线（尤其 70B 上速度提升显著，有些场景吞吐超越 ASR 基线 3.3 倍）；
5. **无损保证保留**：由于验证器使用完整 KV cache 和标准 accept/reject 规则，输出分布与目标模型一致；
6. **压缩比例与接受率平衡**：4× 压缩保留更高接受长度；8× 更大程度降低草稿延迟，最终效果取决于目标模型规模与上下文长度；
7. **无需过长训练上下文**：8K 训练上下文训练的适配器在 32K 评估长度下表现优于用 32K 上下文训练的适配器（固定训练数据预算），证明了压缩机制可外推。

## 7. 方法/实验设计的亮点与优势

- **对 SD 加速模型的两项干扰因素进行解耦分析**：通过公式 `Speedup=(L_acc+1)/(L_draft·td/tt + 1)` 和 `T_decode ≈ αd² + βLd` 分别建模草稿质量与延迟、KV访问成本的影响，动机有清晰的模型驱动；
- **记忆三件套设计（sink + local + slot）结合结构化注意力，而非简单池化或检索**：槽 token 通过端到端 next-token 目标学习“功能替代”历史 token，无需额外检索或专用压缩 kernel；
- **硬件友好**：压缩记忆是连续、append-only、无需修改既有 KV 缓存条目的，兼容现有 KV-cache 服务系统；
- **适配器设计轻量且冻结骨干**：仅训练镜像投影矩阵，保持草稿模型原始的独立解码行为；预填充阶段与目标同并行，不增加 TTFT；
- **目标侧完全不改动**：无损性天然成立，不改变标准 SD 框架；
- **消融细致**：覆盖了窗口尺寸、投影初始化、训练流程、训练上下文长度等核心变量。
