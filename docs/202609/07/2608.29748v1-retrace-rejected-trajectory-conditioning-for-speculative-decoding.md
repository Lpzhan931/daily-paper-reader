## 摘要
投机解码通过让轻量级草稿模型提出多个候选词元，并由较大的目标模型并行验证，从而加速自回归语言模型推理。然而，在第一次拒绝之后，基于前缀的标准验证会丢弃剩余的草稿后缀，因此生成并验证这些位置的计算不会促进解码进展。聚焦于DFlash，我们表明被拒绝后缀中的拒绝位置可能仍与目标续写对齐，这表明草稿模型尽管存在局部词元级错误，仍能保留有用的语义和结构信息。受此观察启发，并借鉴条件扩散的思路，我们提出了ReTrace，一种拒绝轨迹条件化方法，它将每个草稿块基于上一轮被拒绝的后缀进行条件化，而非仅从头生成的掩码占位符生成。ReTrace保留被拒绝后缀的隐藏表示，将其与下一个草稿块对齐，通过同一验证过程中的目标感知校正信号进行细化，并通过门控残差融合将其纳入草稿器的输入嵌入。由于被拒绝的词元永远不会被提交，且目标端验证保持不变，ReTrace保持了投机解码的无损性质，且无需额外的模型前向传播。使用Qwen3模型在数学推理、代码生成和开放域对话方面的实验表明，与DFlash主干相比，ReTrace持续提高平均接受长度和端到端解码速度。通过在不修改轮内提案生成的情况下引入跨轮条件化，ReTrace与现有草稿改进基本正交，并可能与其结合以进一步获益。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：投机解码（Speculative Decoding）通过轻量级草稿模型（draft model）生成多个候选 token，再由大型目标模型（target model）并行验证，从而减少目标模型串行前向传播次数、加速LLM推理。解码速度的提升高度依赖于草稿与目标之间的对齐程度。
- **核心问题**：在标准的**前缀式验证**中，一旦草稿序列在第一个不匹配位置被拒绝，该位置之后的整个草稿后缀都会被丢弃。然而，产生和验证这些后缀位置的计算成本已经花费，却没有转化为实际的解码进度——这是一种系统性、固有的计算浪费。
- **核心观察**：以 DFlash（基于块扩散的并行草稿生成器）为研究对象，本文通过一个直观示例（图1）表明：尽管草稿在局部出现重复、遗漏或错误，但**首个拒绝点之后的草稿位置仍然可能与真实目标续写重新对齐**。这一现象提示：被拒绝的后缀并非毫无价值，而是可能保留了关于目标续写的语义、结构与方向性信息。
- **整体意义**：该问题挑战了“草稿仅用于当前验证轮次、拒绝即丢弃”的惯性思维，提出被拒绝计算可以跨轮转移复用的新视角。

### 2. 方法论：ReTrace 拒绝轨迹条件化

#### 核心思想
ReTrace 借鉴**条件扩散模型**的思路，将被拒后缀视为一条"拒绝轨迹"（rejected trajectory），用其隐藏表示作为**下一轮草稿块的辅助条件**，而非仅从全新的 mask 占位符生成。整个方案的关键在于：
- **不改变目标模型验证逻辑**，不提交任何被拒 token；
- **不引入额外前向传播**，所有已用信息均来自标准草稿与验证过程；
- 保持投机解码的**无损性**。

#### 总体流程（在 DFlash 基础上的增量式改造）
在标准 DFlash 的逐轮"草稿→验证→接受"循环中，仅增加信号构造与注入，其余验证规则与上下文提交逻辑保持不变。

#### 技术细节

**（1）拒绝轨迹的构建与对齐**
- 第 t 轮草稿块包含 B 个候选位置及对应最终层隐藏表示 `hDt,1...hDt,B`。
- 设验证后接受长度为 `At`，首个拒绝位置为 `rt = At+1`。ReTrace **排除**已接受前缀表示（已进入上下文）和首个拒绝位置本身（该位置已被目标模型的修正 token 解析），仅保留**严格位于首个拒绝位置之后的后缀隐藏表示**：`hDt,rt+1 ... hDt,B`。
- 将该信号对齐到下一块前缀位置：第 j 个草稿位置上对齐到 `hDt,rt+j`；若对齐位置用完则以零填充（公式 5）。
- 若整块全部接受或后缀为空，则信号重置为零，退化为原始草稿行为。

**（2）目标感知校正（Target-Aware Correction）**
- 由于被拒后缀仅反映草稿自身的错误预测路径，ReTrace 利用验证过程中**目标模型已产生的隐藏表示**对其进行修正，区分草稿视角与目标评估视角。
- 将对齐的草稿状态 `mt+1,j` 与对应的目标状态 `ut+1,j`（即第 `rt+j-1` 个位置的末层目标表示，因为因果模型中该位置预测第 `rt+j` 位 token）拼接，经浅层可学习线性投影 `Wc∈R(d×2d)` 得到校正增量（公式 7）：

  `ct+1,j = Wc([mt+1,j; ut+1,j])`

- 再以残差形式叠加到原始草稿状态上（公式 8）：

  `rt+1,j = mt+1,j + β·ct+1,j`
  
  其中 β 为校正强度，训练初期从 0 线性 warmup 至 1，以保证优化稳定性。

**（3）门控残差融合（Gated Residual Conditioning）**
- 校正后的信号**不完全取代**当前草稿块的 mask 输入，而是以带门控的残差方式注入（公式 9）：

  `ẽt+1,j = et+1,j + Wv·rt+1,j ⊙ σ(Wg([et+1,j; rt+1,j]))`

- 门控是**向量级**（逐隐藏维）的，决定信号各维度进入的程度；Wv 零初始化保证初值下残差消失、模型从原始 DFlash 行为出发逐步学习，优化稳定。
- 锚点位置与没有对齐信号的位置保持原输入，最大化保留原始草稿通路。

**（4）训练与推理**
- 训练阶段：缓存草稿/目标表示跨轮使用时会 **detach**（阻止跨轮梯度传播），freeze 目标模型，只对草稿骨干、校正模块、门控注入模块用 DFlash 原始块扩散目标联合优化；
- 推理阶段：信号只用一轮，之后被最新拒绝后缀信号替换，除微小的矩阵运算外无额外模型前向或验证成本。

### 6. 主要结论与发现

1. **被拒后缀保留有可利用的预测信息：**
   - token 级：30.4% 被拒后缀位置的目标 token 是草稿模型的 top-1 预测，75.2% 位于 top-5 内；
   - 表示级：被拒草稿状态与真实目标续写的隐藏表示余弦相似度（0.351 宏平均）显著高于随机窗口基线（0.128），差距在四个 benchmark 上全部为正。
2. **ReTrace 在全部 28 组主实验配置中一致提升 DFlash 骨干的性能：**
   - 平均接受长度相对提升 **6.97%**，端到端加速比相对提升 **5.34%**；

3. **性能提升来源于拒绝后缀条件化而非额外训练：** 同预算 DFlash SFT 基线的接受长度几乎饱和，而 ReTrace 持续提升。

### 7. 优点（亮点）

- **问题视角新颖且有实证支撑：** 提出双重探针（token 级排名 + 表示级相似度）系统验证"被拒后缀可用"，而非仅凭直觉；
- **方法轻量优雅：** 严格复用已计算的信息，无额外模型前向传播；信号只存活一轮，机制简洁且避免错误累积；
- **保持无损性质：** 目标模型的验证逻辑、token 提交规则完全不变，理论上不引入仅靠 ReTrace 产生的生成质量退化；
- **工程友好的训练策略：** 零初始化残差 + β warmup + 跨轮 detach，使训练从已有 DFlash 检查点出发时非常稳定；
- **通用性与可组合性：** 不修改轮内生成逻辑，明确与已有草稿改进（如 Domino 的轮内因果细化）正交，容易作为插件式增强与其他工作叠加；
- **实验规范意识强：** 排除额外训练收益的 SFT 对照、并发批处理压力测试、延迟微观分解均为方法型论文中相当充分的验证体系。

### 8. 不足与局限

- **方法对草稿器结构存在依赖前提：** 理论分析明确聚焦 DFlash 这类**并行块扩散**草稿器，并论证 EAGLE 式自回归草稿器中早期错误会在分支内传播、且树结构分支难以做位置对齐恢复。方法本身对每一类草稿器的适用方式并未全部验证，跨草稿器泛化性尚不完全明确（只测试了 Domino 一种组合）。
- **实验覆盖面的偏向：** 主实验只使用了 Qwen3 一个模型家族；未报告不同目标模型尺度（如 30B/70B）下行为；生成长度大多偏短，对需要超长续写（如长文档、长 agentic 规划）场景的收益和信号衰变规律缺乏研究。
- **训练成本与数据要求未充分透明：** 附录未提供总的 GPU-hours 估计，也未显示不同训练数据量下的性能曲线（40K 样本是否有非平凡的最低阈值尚不清楚）；
- **优化信号的局部性：** 训练仅用当前轮预测损失，无显式的跨轮目标、门控损失或反事实约束，模型学到的注入行为可能是一种局部最优——是否能推广到更深的草稿骨干有待验证；
- **离线分析存在测度限制：** 表示相似性测量使用最后的草稿层 vs 目标最终层，不同层间分布的天然差异可能影响相似性解读；随机窗口基线虽能排除一般近邻效应，但未做逐基准归一化；
- **并发实验只针对 GSM8K 单一数据集：** 服务场景下多任务混合负载的表现仍有待进一步测试。
