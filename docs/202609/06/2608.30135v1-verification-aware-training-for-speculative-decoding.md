## 摘要
投机解码通过使用草稿模型生成候选令牌，并由目标模型在单次前向传递中验证，从而加速大型语言模型推理。验证过程是顺序进行的，并从第一次拒绝位置起丢弃所有后续位置，然而现有的草稿训练依赖于对目标的令牌级模仿，并采用固定的逐位置权重，这既不反映上述性质。我们提出了验证感知训练（VAT），这是一种即插即用框架，在每一步训练时模拟验证过程，并将由此产生的接受与拒绝模式转化为监督信号。VAT包含两个部分：(i) 验证头，一个轻量级联合训练的二分类器，用于监督草稿模型在每个位置是否能通过顺序验证；(ii) 验证自适应加权，它不再使用固定加权方案，而是在每个样本的首次拒绝点之前保持完整权重，并将衰减重新锚定至该点开始。VAT仅修改训练目标，因此可应用于现有方法之上，而无需更改草稿架构、目标模型或推理过程。在Qwen3-4B、Qwen3-8B和LLaMA-3.1-8B上对EAGLE-3和DFlash应用VAT后，平均接受长度最多提升11.4%，端到端加速最高提升8.7%，在数学、代码和聊天基准上均取得一致增益。代码将发布于 https://github.com/naver-ai/vat

## Abstract
Speculative decoding accelerates large language model inference by using a draft model to generate candidate tokens, which are verified by the target model in a single forward pass. Verification proceeds sequentially and discards every position from the first rejection onward, yet existing draft training relies on token-level imitation of the target with a fixed per-position weighting that reflects neither property. We introduce Verification-Aware Training (VAT), a plug-in framework that simulates verification at every training step and turns the resulting accept and reject patterns into supervision. VAT consists of two components: (i) a verification head, a lightweight jointly trained binary classifier that supervises the draft model on whether each position survives sequential verification; (ii) verification-adaptive weighting, which replaces the fixed weighting schedule by keeping full weight up to each sample's first rejection point and re-anchoring the decay to start there. VAT modifies only the training objective, so it can be layered on top of existing methods without changing the draft architecture, the target model, or the inference procedure. Applied to EAGLE-3 and DFlash on Qwen3-4B, Qwen3-8B, and LLaMA-3.1-8B, VAT improves average acceptance length by up to 11.4% and wall-clock speedup by up to 8.7%, with consistent gains across math, code, and chat benchmarks. Code will be available at https://github.com/naver-ai/vat

## 1. 核心问题与整体含义（研究动机）

投机解码（Speculative Decoding）通过先让轻量级草稿模型生成候选 token，再由目标模型一次前向验证来加速 LLM 推理。其验证过程有两个关键特性：

- **顺序验证**：从第一个草稿位置开始逐 token 验证；
- **首个拒绝即失效**：一旦某个 token 被拒绝，其后的所有草稿 token 都会被丢弃，无论它们本身质量如何。

然而，现有草稿模型的训练与这两个特性是**错位的**：
- 训练目标只是逐位置的 token 级模仿（imitation），即让草稿输出尽量接近目标分布，没有告诉模型“这个 token 是否能在验证中被接受”；
- 逐位置损失权重采用预先固定的衰减 schedule，在所有样本上共享，无法针对不同样本的“首次拒绝位置”进行调整。

因此，本文的核心动机是：**草稿模型的训练目标应与推理时的验证机制对齐**，否则模型接收的监督信号与真正决定加速效果的“接受长度（acceptance length）”不一致。

## 2. 方法论：Verification-Aware Training（VAT）

VAT 是一个**即插即用（plug-in）的训练框架**，只在训练目标上做修改，不改变草稿架构、目标模型或推理流程。其核心思想是**在每一步训练中模拟目标模型的验证**，把产生“接受/拒绝”信号转化为监督。

### 2.1 训练时验证模拟

- 在每个草稿位置 k，已知草稿分布 p̂_k 和目标分布 p_k；
- 按投机采样规则定义位置级接受指示量：m_k = 1[草稿 token 被接受]；
- 定义首个拒绝点：k* = min{ k : m_k = 0 }（若全部接受则 k* = K+1）；
- 定义位置 k 的累积接受标签：v_k = 1[k < k*] = ∏_{j≤k} m_j。

v_k 反映的是推理时“顺序验证”的真实结果：只有前面全部位置都通过时，当前位置才贡献给接受长度。

### 2.2 组件一：验证头（Verification Head）

- 一个轻量级二分类器，加在草稿模型最后一层隐藏状态之上；
- 用二元交叉熵对 v_k 进行监督：

  L_VH = −(1/K) ∑_k [ v_k log v̂_k + (1−v_k) log(1−v̂_k) ]

- 它本质上是**显式让草稿模型预测“当前位置是否能通过顺序验证”**，而不仅仅是预测下一个 token；
- 该头只用于训练或在推理中做早停辅助，不改变草稿解码过程。

### 2.3 组件二：验证自适应加权（Verification-Adaptive Weighting）

- 现有方法有固定 schedule，例如 EAGLE-3 用 w_k = 0.8^{k−1}，DFlash 用 w_k = exp(−(k−1)/γ)；
- VAT 将其替换为以 k* 为锚点的样本自适应权重：

  ŵ_k = 1  （k < k*）
  ŵ_k = w_{k−k*+1}（k ≥ k*）

即：首个拒绝位置之前权重全为 1；首个拒绝位置之后，复用既有衰减曲线并从 k* 处重新开始衰减。

- 理由：由于验证会丢弃首个拒绝之后的所有位置，一个 token 对接受长度的贡献取决于其前面所有位置是否被接受。因此“衰减的起点”应锚定在每个样本自身的 k* 上，而不是固定在 k = 1 上。

### 2.4 最终训练目标

L = ∑_{k=1}^K ŵ_k ( ℓ_k^soft + ℓ_k^hard ) + β L_VH

- 同时使用目标分布 soft label 和目标采样 token 的 hard label（结合知识蒸馏与直接监督）；
- β 在所有实验中设为 1.0；
- VAT 只修改训练侧目标，推理时不需要额外计算。

## 6. 主要结论与发现

1. **VAT 一致提升性能**：在 Qwen3-4B、Qwen3-8B、LLaMA-3.1-8B 上，对 EAGLE-3 与 DFlash 均有提升：
   - 平均接受长度最多提升 **11.4%**；
   - 墙钟加速最多提升 **8.7%**；
   - 数学、代码、对话三类 benchmark 上均有正收益。
2. **代表性结果**：如 Qwen3-4B 上 EAGLE-3 的加速从 4.07× 提到 4.39×（+7.9%），DFlash 从 4.54× 提到 4.81×（+5.9%）；τ 分别为 6.28→6.78 与 5.73→6.08。
3. **验证头带来积极训练动态**：带验证头时，首个拒绝位置随训练向更靠后偏移，说明更多连续草稿 token 可以通过验证。
4. **权重适应比衰减函数形式更重要**：无论底层衰减曲线是 0.8^{k−1} 还是 exp(−(k−1)/γ)，验证自适应加权后二者表现几乎相同，增益主要来自“按样本 k* 自适应”，而非 schedule 的函数形式。
5. **软+硬标签互补**：单独加 soft label 也能提升 τ，与 hard label 并用效果最好。
6. **验证头可额外支持推理时早退**：当验证头预测到首次拒绝时提前终止 draft，可在不显著牺牲 τ 的情况下进一步提高墙钟加速，并接近“oracle”上界。

## 7. 优点与亮点

- **与推理机制深度对齐**：显式模拟顺序验证，训练信号直接反映“是否能通过验证”而非仅模仿目标 token。
- **即插即用、侵入性低**：只改变训练目标，不改草稿架构、目标模型或推理流程，很容易叠加到已有方法上。
- **样本级自适应**：权重锚定在每个样本自己的首个拒绝点 k*，较固定 schedule 更合理。
- **训练-推理一致性高**：验证头虽然是训练辅助目标，但可以顺带用于推理阶段做早停，产生额外收益。
- **跨范式通用**：在自回归草稿（EAGLE-3）与扩散块式草稿（DFlash）上都有效，说明 VAT 与底层草稿机制无关。
- **实验细致**：除主实验外，做了较多加权策略、验证规则、语料温度、阈值选择等消融，对设计选择的论证比较充分。

## 8. 不足与局限

- **模型规模覆盖有限**：实验全在 8B 及以下模型上进行，能否在大模型（如 70B+）上保持收益尚不明确；论文也承认这一点。
- **训练总成本披露不足**：只给出 per-step 时间和峰值显存，没有给出完整的 GPU 数量、总训练时长，难以评估整体训练开销。
- **DFlash 上额外开销更明显**：VAT 需要额外一次目标 LM head 前向，导致训练显存从 23.8 GB 增至 31.5 GB、每步耗时增加 6.1%，在更大模型上可能需要优化或缓存。
- **存在个别指标倒退**：例如 LLaMA-3.1-8B、T=1 下 DFlash + VAT 在 GSM8K 上的 speedup/τ 有小幅下降，说明收益并非所有细粒度任务上绝对一致；虽然平均收益为正，但需要观察方差和任务敏感性。
- **需要模拟验证与目标采样**：训练时需要同时访问目标模型的 token 分布或接受规则，对已冻结目标模型依赖较强；对无法提供逐位置分布的目标模型可能不适用。
- **验证头阈值需要选择**：推理早停时需挑选阈值（EAGLE-3 最佳为 0.5，DFlash 为 0.6），不同模型或任务可能需要重新调校。
