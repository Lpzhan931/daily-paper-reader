## 摘要
长上下文大语言模型应用（如文档摘要和多轮智能体）需要处理数万token前缀的生成，使得解码延迟成为主要瓶颈。投机解码（SD）在不改变模型输出的情况下降低延迟，但其加速效果取决于接受的草稿token数量和草稿步长延迟：轻量级草稿速度快但缺乏捕获长距离依赖的能力，而强大的独立草稿虽能恢复接受率，但在长前缀下会带来不断增长的KV访问成本。我们引入了用于长上下文SD的记忆增强草稿，为强大的独立草稿配备压缩的草稿侧KV记忆：一个轻量级适配器构建并增量更新该记忆，以保留远距离信息和精确的近期上下文。目标验证器保留其完整KV缓存，并应用标准接受/拒绝规则，保持SD的无损保证。在Llama 3.1-8B和70B目标上，前缀长度高达32K的实验表明，我们的方法将草稿侧内存减少了70%以上。与自回归解码相比，它分别实现了高达2.08倍和3.33倍的加速。

## Abstract
Long-context LLM applications such as document summarization and multi-turn agents require generation from prefixes spanning tens of thousands of tokens, making decoding latency a major bottleneck. Speculative decoding (SD) reduces latency without changing model outputs, but its speedup depends on both accepted draft tokens and draft-step latency: Lightweight drafts are fast but lack the capacity to capture long-range dependencies, whereas strong independent drafts recover acceptance but incur growing KV-access cost at long prefixes. We introduce memory-augmented drafting for long-context SD, equipping a strong independent draft with compressed draft-side KV memory: A lightweight adaptor constructs and incrementally updates this memory to retain distant information and exact recent context. The target verifier retains its full KV cache and applies the standard accept/reject rule, preserving SD's lossless guarantee. Experiments on Llama~3.1-8B and 70B targets at prefix lengths up to 32K show that our method reduces draft-side memory by over 70%. It achieves speedups of up to 2.08x and 3.33x , respectively, over autoregressive decoding.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想

- 提出 **Memory-Augmented Sliding-Window (MASW) Drafting**（记忆增强滑窗草稿解码），其核心理念是：**强草稿模型不需要访问完整历史 KV，只需访问一个紧凑的、由三部分构成的“工作记忆”**。
- 草稿侧仍使用**独立的强模型**以保证接受率，但通过压缩记忆降低每步访问的数据量。
- 目标验证器完整保留全前缀 KV 缓存并采用标准接受/拒绝规则——SD 的无损性保证不受影响。

### 2.2 三部分记忆结构

草稿模型在时刻 t 的可用记忆为：

\[
M_t = M_{sink} \cup M_{local,t} \cup M_{slot,t}
\]

- **Sink 记忆（M_sink）** ：保留前 S 个 token 的原始 KV 条目（"注意力锚点"），始终可访问；
- **局部窗口（M_local,t）** ：保留最近 W 个非 sink token 的精确原始 KV，保证近期上下文不失真；
- **记忆槽（M_slot,t）** ：以固定间隔（每 r 个 token）物化的紧凑 KV 条目，编码被驱逐的远端历史信息。

### 2.3 记忆物化（Memory Materialization）机制

- 每经过 r 个 token（sink 除外），在压缩边界 \(\tau_m = mr\) 处插入一个记忆槽 token \(g_m\)；
- \(g_m\) 通过完整的 Transformer 前向计算得到，其注意力范围为：当前局部窗口 + sink tokens + 之前已物化的所有记忆槽；
- 每个记忆槽可读取先前槽位，因此**连续槽位形成增量式压缩链**而非独立的段落摘要；
- **注意力掩码设计**：普通原始 token 只能看到紧凑记忆视图（sink + 可用槽位 + 局部窗口），而非完整历史；记忆槽 token 则能看到此前所有槽位及其局部单元，由此实现“写入策略”，并以下一个 token 预测作为训练目标来优化压缩有效性。

### 2.4 镜像投影与 KV 物化

- 每个 Transformer 层为记忆槽 token 设置**专门的、可训练的镜像 KV 投影矩阵** \(W^{(l)}_{K,g}\) 和 \(W^{(l)}_{V,g}\)；
- 原始 token 仍使用冻结的骨干模型投影 \(W^{(l)}_{K,r}\)、\(W^{(l)}_{V,r}\)；
- 镜像矩阵从骨干模型的对应权重**拷贝初始化**，构成记忆适配器（memory adaptor）的可训练参数；
- 记忆槽的 KV 对物化后被追加到 M_slot，同时滑出局部窗口的原始 token KV 被驱逐。

### 2.5 训练流程

- 分两阶段训练：
  - **预训练（PT）** ：在 RedPajama 上采样 2B tokens 进行继续预训练；
  - **监督微调（SFT）** ：使用 LongAlpaca 和 BookSum 长上下文数据，序列截断至 8K tokens；
- 损失函数为基于压缩记忆的原始 token 下一词预测损失：
  \[
  L = \sum_t -\log p(x_t | D_t, x_{<t})
  \]
- 记忆槽位置不计入损失（它们是压缩载体而非预测目标）。

### 2.6 与投机解码的集成

- **预填充阶段**：目标模型完整预填充构建 KV 缓存；草稿模型使用结构化注意力掩码并行预填充，物化前缀记忆槽；
- **解码阶段**：草稿只读取紧凑记忆进行自回归生成；目标验证器使用完整 KV 并行验证并执行标准接受/拒绝；
- **回滚机制**：被拒绝时，草稿丢弃推测产生的局部 KV 和边界之后新物化的槽位，通过原始 KV 回滚窗口恢复活跃局部上下文。

## 6. 论文的主要结论与发现

- **长上下文 SD 中容量与 KV 成本存在根本冲突**：轻量草稿上下文增长会导致接受率下降，全量 KV 强草稿则在长前缀下因 KV 流式访问成本过高而失去优势；
- **MASW 可有效平衡接受率与草稿延迟**：通过在草稿侧引入三部分紧凑记忆（sink + 局部窗口 + 压缩槽位），在保持较强接受长度的同时显著降低草稿每步的 KV 访问量；
- **草稿侧内存显著缩减**：与全量 KV 草稿相比，额外峰值内存从 17–18 GB 降至 4–5 GB（减少超过 70%）；
- **端到端加速显著**：
  - Llama 3.1-8B 目标：最高 **2.08×** 加速（32K 前缀）；
  - Llama 3.1-70B 目标：最高 **3.33×** 加速（16K 前缀，4× 压缩）；
  - 优于 EAGLE、EAGLE-3、SWA、SnapKV 和全 KV SD 基线。
- **4× 压缩通常保留更多接受 token，8× 进一步降低延迟，最佳权衡依赖目标规模和前缀长度**；
- **记忆适配器可在目标预填充期间并行完成草稿预填充**，不增加首 token 延迟；
- **镜像投影采用权重拷贝初始化显著优于随机初始化**，保持骨干 KV 几何形状有利于训练稳定性；
- **预训练 + SFT 两阶段训练优于任一单阶段**；
- **8K 训练语境已足以让压缩机制外推到 32K**——MASW 学习的是可重复的相对压缩操作，而非依赖绝对上下文长度。

- **结构超参数固定**：局部窗口大小、sink 数量、槽间隔均为人工设定固定值，未实现自适应分配；
- **任务覆盖单一**：仅在摘要类 LongBench 任务上评估（GovReport/QMSum/MultiNews），未测试代码、多轮对话、长文档问答、推理等任务，结果的一般化能力尚不明确；
- **批量场景缺评估**：主延迟实验仅使用 batch size 1，虽然方法支持异质批次，但未报告实际实现后的批量推理吞吐表现；
- **预填充额外开销**：草稿侧记忆增强预填充的时间显著增加（如 8B draft 在 32K 下从 1835ms 增至 7992ms），虽然可与目标预填充并行隐藏，但在草稿预填充慢于目标预填充的场景下可能会成为瓶颈；
- **未对比更近期的长上下文 SD 系统**：如 TriForce、MagicDec、LongSpec 等未作为端到端基线出现在主实验中（仅做相关工作讨论）；
- **安全风险与放大器效应**：加速可能使现有模型在更大规模上被用于生成误导性、滥用性内容等有害用途。
