## 摘要
专家混合（MoE）模型将语言模型的能力扩展到智能手机上，但专家卸载仍受限于有限的 DRAM 容量和昂贵的数据移动。顺序的 token 路由将专家执行与碎片化的闪存读取和多阶段 NPU 准备耦合在一起，使稀疏计算因权重传输而停滞。每次传输仅服务少量 token，随后执行便继续推进。我们利用投机解码的多 token 验证窗口，将专家移动与单 token 执行解耦，从而实现权重复用、连续闪存读取以及加载-计算重叠。我们提出 BigMoMo，一种跨内存层次利用该窗口的移动 MoE 运行时。它利用接受率、路由影响和移动成本来剪枝投机分支与专家激活；根据运行时共同加载模式重新组织闪存上的专家；并将就绪专家批处理，以将 NPU 计算与待处理传输重叠。在两个移动平台上的四个 MoE 模型和五个基准测试中，BigMoMo 相较于按需自回归卸载实现了平均 4.83 倍的解码加速，相较于最佳投机 MoE 基线实现了 1.82 倍的加速，并支持参数量高达 30B 的 MoE 模型。

## Abstract
Mixture-of-Experts (MoE) models expand language model capacity on smartphones, but expert offloading remains constrained by limited DRAM capacity and costly data movement. Sequential token routing couples expert execution to fragmented flash reads and multistage NPU preparation, leaving sparse computation stalled on weight transfers. Each transfer serves few tokens before execution moves on. We exploit the multi-token verification window of speculative decoding to decouple expert movement from single-token execution, enabling weight reuse, contiguous flash reads, and load-compute overlap. We present \textsc{BigMoMo}, a mobile MoE runtime that exploits this window across the memory hierarchy. It prunes speculative branches and expert activations using acceptance rates, routing impact, and movement cost; reorganizes on-flash experts according to runtime co-loading patterns; and batches ready experts to overlap NPU computation with pending transfers. Across four MoE models and five benchmarks on two mobile platforms, \textsc{BigMoMo} achieves mean decoding speedups of $4.83\times$ over on-demand autoregressive offloading and $1.82\times$ over the best speculative MoE baseline, supporting MoE models up to 30B parameter.

# BigMoMo 论文总结

## 1. 核心问题与研究动机

- **背景**：MoE（专家混合）模型通过稀疏激活（每 token 只激活 top-k 专家）在有限计算量下扩展模型容量，被认为是移动端部署大模型的重要路径。但 MoE 的总参数量远超手机 DRAM 容量（典型 < 24GB，实际可用更小），因此必须将专家权重卸载到闪存（UFS）中按需加载。
- **移动端的特殊性**（区别于 CPU–GPU 服务器平台）：
  - **专家搬运带宽受限**：UFS 带宽仅约 4 GB/s（小/随机访问下进一步退化），远低于服务器主机–设备互联带宽，专家移动延迟无法被有效隐藏。
  - **不规则闪存访问开销高**：token 相关的动态路由导致专家请求稀疏、碎片化，即使共激活专家也未必连续存放，无法充分利用闪存带宽。
  - **多阶段执行路径**：移动 NPU（Qualcomm Hexagon）要求权重先映射进 NPU buffer，再搬入 VTCM 做反量化/布局转换，最后交给 HMX 计算（$T_e = T_{Flash} + T_{Map} + T_{VTCM} + T_{HMX}$），多级状态管理造成流水线气泡。
- **根本矛盾**：现有卸载方案只做了**模型层的参数解耦**（专家可独立放置/移动），但**专家移动仍与单 token 路由顺序耦合**——一次搬运往往只服务一个 token，搬运成本无法被计算摊薄。
- **核心洞见**：应把解耦从"参数层"推进到"**系统层的数据移动解耦**"，而投机解码（speculative decoding）的多 token 验证窗口天然提供了放大的执行粒度，带来三个机会：
  1. **权重复用**：同一验证轮内多个候选 token 命中同一专家，可共享一次加载。
  2. **闪存友好访问**：一轮内暴露更多专家请求，可将碎片读聚合成连续读。
  3. **跨阶段重叠**：单个专家服务多个 token 后计算量增大（$T_{HMX}^{(m)}$），可隐藏更多后续搬运延迟。
- **整体含义**：论文主张移动端高效智能不必只靠"缩小模型"，通过解耦数据移动与顺序专家执行，可以让约 30B 参数的 MoE 模型在手机上高效推理。

## 2. 方法论

### 2.1 核心思想
BigMoMo 是一个面向移动端的内存层次感知 MoE 运行时，把投机验证窗口作为调度单元，在**移动前、移动中、执行时**三个阶段分别解耦数据移动与计算。

### 2.2 关键技术一：面向复用的专家移动准入（§4.2）
- **问题**：大量投机草稿节点最终被拒绝（论文测得被拒绝 token 占总验证计算时间 82.1%、专家移动时间 81.8%），却仍触发专家搬运。
- **接受率感知的节点剪枝**：为树中节点 $d$ 定义价值
  $$V_d = \hat{p}_{h(d)} \prod_{u \in path(d)} q_u$$
  其中 $\hat{p}_h$ 为按树深度离线标定的历史接受概率，$q_u$ 为草稿模型 token 概率。按 $V_d$ 降序保留累计价值达到总价值 $\rho$ 比例的最小节点集合。
- **层次感知的专家剪枝**：定义专家路由影响
  $$I_e = \sum_{d \in D_e} V_d \min_{j \in T_d \setminus \{e\}} |s_{d,e} - s_{d,j}|$$
  （低价值节点选中、或存在路由分数相近替代专家的专家，影响更小）。再结合离线测得的跨层次移动成本 $C_e$，定义剪枝优先级 $P_e = \Delta I_e / C_e$，在累计路由影响预算 $\tau$ 下迭代剪枝，被剪专家的路由权重重分配给分数最接近的保留专家；每轮至少保留一个专家，直至超出预算。

### 2.3 关键技术二：运行时自适应的闪存专家组织（§4.3）
- **动机**：共加载关系在相邻验证轮间持续存在（Fig.8a），且近期带来较大读时间下降的重排往往持续受益（Fig.8b）。
- **超图建模**：专家为顶点，一轮验证中被共同加载的专家集合构成超边 $M_l^k$，用最近 $K$ 轮的叠加超边捕捉重复共加载模式。
- **锚区域选择**：为每个超边挑选与之重合度最高、可容纳 $|M_l^k|$ 个专家的连续闪存区域作为 Anchor Region，最小化需搬入区内的区外专家数。读时间估计：
  $$T_l^k = T_{Flash}(S(A_l^k)) + \sum_{e \in M_l^k \setminus A_l^k} T_{Flash}(S(e))$$
- **增量重定位**：对候选交换 $(e_i, e_j)$，在最近 $K$ 轮窗口上重算所有超边的读时间，收益为
  $$B_l(e_i, e_j) = \sum_{r=k-K+1}^{k} (T_l^r - \tilde{T}_l^r(e_i, e_j))$$
  只执行收益为正且最大的可行交换；交换在两个专家都已载入共享 DRAM 后于后台进行，且当有延迟敏感的 Flash→DRAM 读请求到来时暂停重定位写入，保证读优先。

### 2.4 关键技术三：跨层次移动–计算调度（§4.4）
- **问题**：同层专家处于不同移动阶段、就绪时间不一致，同步等待最慢路径会造成 HMX 空闲。
- **VTCM 双缓冲**：VTCM 划分为两个交替权重缓冲 + 128 KiB 激活/输出区；按缓冲容量组织计算组，超尺寸专家沿输出维 $N$ 以 32 的倍数切块，权重打包为连续 128 B 向量并按 bank 并行分发。
- **调度策略**：以残余 HMX 计算时间作为重叠窗口 $W_t$，估计下一专家就绪间隔 $\tau_{next}(t)$，未覆盖移动时间为
  $$R_t = \max(0, \tau_{next}(t) - W_t)$$
  初始阶段为已在 NPU buffer 中的最高频 8 个专家预构造计算组；选择规则为
  $$b_t^\star = \begin{cases}\arg\min_{b: T_{VTCM}^{(b)} \le W_t,\, T_{HMX}^{(b)} \ge R_t} T_{HMX}^{(b)}, & \text{存在满足条件的 } b\\ \arg\max_{b: T_{VTCM}^{(b)} \le W_t} T_{HMX}^{(b)}, & \text{否则}\end{cases}$$
  即优先选能恰好覆盖 $R_t$ 的最短计算组，避免下一专家就绪后仍需等待；若无法覆盖则选最长者尽量填补。新映射完成的专家持续加入后续分组，形成滚动调度。
