## 摘要
推测解码通过并行验证多个草拟 token 来加速 LLM 推理，使单次目标模型前向传播能够接受多个 token。按照其构造方式，验证过程会同时为被接受的 token 和被拒绝的 token 计算表示。然而，传统草拟器仅保留被接受 token 的表示，使得花费在被拒绝 token 上的大量验证器计算实际上被浪费。我们发现，目标前向传播过程中产生的这些被丢弃的隐藏状态保留了关于未来 token 的有用信息，可用于改进后续草拟。然而，实现这一机会面临两个不同的挑战。在推理时，回收开销可能增加草拟延迟，削弱因接受长度增加而带来的加速。在训练时，标准的并行草拟器训练不会产生与推理对齐的被拒绝状态，而通过顺序 rollout 获得这些状态又会牺牲训练位置间的并行性。我们提出 Carryover Drafting，同时解决这两个挑战。Carryover 将被拒绝的目标隐藏状态回收为临时 KV 上下文，使草拟器能够选择性地关注它们。它复用草拟器已有的接口，仅增加一个学习得到的嵌入，以区分被拒绝状态与已提交上下文。额外的 KV 上下文在每个草拟轮次被替换，使其长度以一个提议块为界。我们提出并行 draft–verify–draft 训练，使草拟器接触到与推理对齐的被拒绝状态，同时保持训练位置间的并行性。在 DFlash 以及一个源自 DSpark 的半自回归草拟器上、跨两个目标模型的实验表明，这一简单的 Carryover 机制相比相应基线将平均接受长度提升 6.5–14.7%，端到端 vLLM 加速提升 7.9–14.4%，在翻译任务上加速增益可达 28.8%。

## Abstract
Speculative decoding accelerates LLM inference by verifying multiple drafted tokens in parallel, allowing a single target forward pass to accept several tokens. By construction, verification computes representations for both accepted and rejected tokens. Yet, conventional drafters retain only the representations of accepted tokens, leaving the substantial verifier computation spent on rejected tokens effectively wasted. We find that these discarded hidden states generated during target forward retain useful information about future tokens that can improve subsequent drafts. However, realizing this opportunity poses two distinct challenges. At inference, recycling overhead can increase drafting latency, diminishing the speedup gained from increased acceptance length. During training, standard parallel drafter training does not produce inference-aligned rejected states, while obtaining them through sequential rollouts would sacrifice parallelism across training positions. We introduce Carryover Drafting, which addresses both challenges. Carryover recycles rejected target hidden states as temporary KV context, allowing the drafter to selectively attend to them. It reuses the drafter's existing interface and adds only a single learned embedding to distinguish rejected states from committed context. The additional KV context is replaced each drafting round, keeping its length bounded by one proposal block. We introduce parallel draft--verify--draft training that exposes the drafter to inference-aligned rejected states while preserving parallelism across training positions. Experiments with DFlash and a DSpark-derived semi-autoregressive drafter across two target models show that this simple Carryover mechanism improves average acceptance length by 6.5--14.7% and end-to-end vLLM speedup by 7.9--14.4% over the corresponding baselines, with speedup gains reaching 28.8% on translation.

# Carryover Drafting 论文总结

## 1. 核心问题与研究动机

- **背景**：自回归 LLM 每步前向只生成 1 个 token；推测解码（speculative decoding）用轻量 drafter 一次提出多个 token，目标模型（target）用单次前向并行验证，从而一次接受多个 token，加速比取决于**接受长度 τ** 与**草拟开销**的权衡。
- **关键观察**：验证过程"按构造"必须为**被接受的 token 和被拒绝的 token 都计算表示**，但 EAGLE/EAGLE-3、DFlash、DSpark 等 target-conditioned drafter 只保留接受 token 的隐状态，被拒绝部分的验证计算被白白浪费。
- **核心假设**：这些被丢弃的 target 隐藏状态含有关于未来 token 的有用信息，可提升后续草拟质量。
- **两大挑战**：
  - *推理侧*：回收会带来额外草拟延迟（投影 + 注意力开销），可能抵消接受长度带来的收益；若跨轮累积保留，KV 上下文会无限增长。
  - *训练侧*：标准并行 drafter 训练基于记录的 target 响应，不产生推理时会出现的拒绝状态；用顺序 rollout 获取又会破坏训练位置间的并行性。
- **整体含义**：论文提出以极小改动"回收"验证阶段已经付过费的计算，属于对现有 block-diffusion 类 drafter 的通用增强，而非替换其结构。

## 2. 方法论

### 2.1 核心思想（推理）
- 将被拒绝的 target 隐藏状态作为**临时、只读的 KV 上下文**注入 drafter，通过**已有的**投影接口进入，让 drafter 用既有注意力层选择性关注。
- 仅新增**一个学习嵌入 E_carry** 用于在投影前区分"被拒绝状态"与"已提交上下文"；不新增门控或专用投影模块。
- 每轮验证后**替换**carryover 上下文，长度以 1 个提议块（B）为界；全接受时为空。
- 拒绝状态**不替换**接受 token 的隐状态，也**不进入 target 的 committed KV cache**。

### 2.2 关键技术细节与公式（文字化）
- 设第 r 轮提议位置的目标隐状态为 `H_r = (h_{r,1},…,h_{r,B})`（拼接选定的多个 target 层，顺序与 baseline 一致）。
- 若接受前 `m_r` 个提议：`H_acc = h_{r,1:m_r}`，`H_rej = h_{r,m_r+1:B}`。
- 已有投影：`Φ_ℓ(H) = (K_ℓ(F(H)), V_ℓ(F(H)))`，其中 F 为特征投影，K_ℓ/V_ℓ 为第 ℓ 层 KV 投影。
- Carryover 更新：`U_{r+1,ℓ} = Φ_ℓ(H_rej + E_carry)`，`ctx_{r+1,ℓ} = [C_{r+1,ℓ} ; U_{r+1,ℓ}]`，其中 C 为基线已提交的 drafter KV 上下文，U 为被拒绝状态构成的临时上下文（每轮替换旧的 U）。
- 位置编码（RoPE）只在 drafter 投影为 key 时施加一次，拒绝状态保留其被计算时的绝对位置。
- **正确性**：条件于解码历史与 carry 输入，drafter 定义提案分布 q；沿用标准接受规则与残差修正（以真实 q 为准）即可保持目标分布不变——Carryover 只改变提案分布，不改变 target 概率与接受准则。

### 2.3 训练方法：Parallel Draft–Verify–Draft
- 在每条记录的 target 响应 y 上采样随机 anchor（512 个/响应），流程：
  1. **Draft（无梯度）**：drafter 生成 detached 提议；
  2. **Verify（冻结 target）**：用**块对角因果掩码**并行验证各分支（每条分支只读自己的记录前缀与自身提议），贪心得到接受长度 m_i 与 detached 拒绝状态 H_rej,i；
  3. **Draft（有梯度）**：anchor 平移到 `a'_i = a_i + m_i + 1`（下一个纠正位或 bonus 位），第二遍 drafter 读取记录前缀与 H_rej，对记录的后续 token 计算基线损失。
- **梯度只流经第二遍**（含共享投影 Φ 与 E_carry）；第一遍与 target 验证均 detach。
- **并行性**：每个 anchor 的 draft–verify–draft 转移独立构造，各阶段内 anchor 并行，无需完整多轮 rollout，也不新增 target 采样数据。
- **全接受情形**：H_rej = ∅，第二遍退化为"平移 anchor 上的基线训练"，因此仍贡献监督（每 anchor 恰好 1 个监督转移）。

### 2.4 成本模型
- `L_carry ≈ (t_draft + t_verify + t_reuse) / τ`，`S_carry ≈ τ·t_AR / (t_draft + t_verify + t_reuse)`。
- 其中 `t_reuse = T_Carryover draft − T_baseline draft` 为回收引入的额外草拟延迟，设计目标是让 t_reuse 尽量小。
