## 摘要
大语言模型（LLM）推理常常同时受到计算和内存的限制，尤其是在基于卸载的部署中，模型权重在自回归解码过程中需要跨内存层级传输。在此情形下，减少执行的层数可以降低每token延迟，同时避免代价高昂的权重移动。受此观察启发，我们提出FlexEE，一种面向资源受限且基于卸载的LLM推理的提前退出框架。FlexEE通过逐层退出监督以实现可靠的中间层预测、在Top-K本地词表上进行自推测解码以实现低成本的退出决策，以及动态隐藏状态管理以实现KV缓存正确且内存感知的执行，使提前退出在LLM解码中变得实用。在生成任务和下游任务上，FlexEE能够以最小的精度损失实现高效提前退出，在0\%/50\%权重卸载下，分别在Llama2-7B和Llama3-8B上带来最高1.27$\times$/3.16$\times$和1.25$\times$/2.83$\times$的端到端加速。

## Abstract
Large language model (LLM) inference is often constrained by both computation and memory, especially in offloading-based deployments where model weights are transferred across memory hierarchies during autoregressive decoding. In this setting, reducing the number of executed layers can lower per-token latency while also avoiding costly weight movement. Motivated by this observation, we present FlexEE, an early exiting framework for resource-constrained and offloading-based LLM inference. FlexEE makes early exiting practical for LLM decoding through layer-wise exit supervision for reliable intermediate-layer prediction, self-speculative decoding over a Top-K local vocabulary for low-cost exit decisions, and dynamic hidden state management for KV-cache-correct and memory-aware execution. Across generative and downstream tasks, FlexEE enables efficient early exit with minimal accuracy degradation, delivering up to 1.27$\times$/3.16$\times$ and 1.25$\times$/2.83$\times$ end-to-end speedups on Llama2-7B and Llama3-8B under 0\%/50\% weight offloading, respectively.

## 1. 核心问题与研究动机

- **背景**：LLM 规模持续增长（scaling laws），参数量常超出片上内存容量，资源受限场景下普遍采用**权重卸载（offloading）**——将部分层参数放在片外内存（如 CPU 内存），推理时按需加载。
- **瓶颈转移**：卸载部署下，推理瓶颈从"计算"转向"片外访存"，加速的关键变成**减少参数加载的数据量与频次**。
- **核心洞察**：减少执行的层数（early exiting）可同时降低每 token 延迟 *和* 避免昂贵的权重搬运，是卸载场景下天然的互补范式。
- **现有早退方法的三重挑战**（论文图 1a）：
  1. **中间层建模能力弱**：LLM 只针对最后一层训练解码，中间层隐状态难以可靠解码，直接早退会导致严重质量退化。
  2. **退出决策开销高**：需将隐状态投影到全词表（如 Llama2 的 32K）做 LM head 投影，计算与搜索代价抵消了跳层的收益。
  3. **KV 缓存不兼容**：中间层退出后，后续层无法为未来 token 生成 K/V；已有补救方案（状态复制 / KV 复制 / KV 驱逐）要么需加载所有剩余层权重（卸载场景下抵消收益），要么损害语义一致性。
- **整体含义**：论文提出 FlexEE，一个**算法—系统协同设计**的卸载感知早退框架，使早退在卸载式 LLM 解码中真正可用。

## 2. 方法论

### 2.1 核心思想

- 只在**被卸载的层**上做早退判定（这些层语义更可靠，且跳层可直接避免权重加载）；
- 两阶段预测器：**自推测层（Self-Spec Layer）** 先在局部候选词表上做一次全词表投影并选出 Top-K 候选；**早退层（Early-Exit Layer）** 只在该紧凑候选空间内预测并判定是否退出；
- **动态隐藏状态管理**：退出时保留隐状态，下一个 token 前向到退出层之后的第一层时复用，更新完该层 KV 后清除。

### 2.2 关键技术细节

**（1）逐层早退监督（提升中间层可解码性）**

- 训练时在多个关键 Transformer 层后接共享 LM head，施加统一语言建模目标，逐层监督权重从深层向浅层渐进迁移：
  - $J(X,Y,t)=\sum_{l=0}^{L-1}\tilde e(t,l)\,J_{CE}\big(g(x_{l+1}),Y\big)$
- 效果（图 3）：中间层熵与 WikiText PPL 显著下降，最终层性能几乎不变，无额外推理开销。
- 本文直接基于 **LayerSkip** 的预训练 checkpoint 构建，属于 training-free 的推理侧设计。

**（2）退出特征选择**

- 候选特征：Top Prob、Gap（top-1 与 top-2 概率差）、Top Logit、Prob Shift（相邻层同 token 概率变化）。
- 用 300K WikiText token 离线推导各层最小阈值：
  - $\lambda_l^*=\min\{\lambda \mid \frac{\sum_i \mathbf 1[p_l^{(i)}\ge\lambda \wedge \hat y_l^{(i)}=y_i^{final}]}{\sum_i \mathbf 1[p_l^{(i)}\ge\lambda]}\ge\tau\}$
- 结论：**Top Prob 与 Gap** 阈值随层平滑、覆盖率（coverage ratio）高、跨模型一致；Top Logit 不稳定，Prob Shift 覆盖率过低。故最终只用 Top Prob + Gap。

**（3）自推测轻量预测器**

- 用 $H_l(N)=P(y^*\in \text{Top-}N(\hat p_l))$ 衡量局部候选集对最终预测的覆盖能力；
- 用 $E_l(N)=\mathbb E_t[p_{1,\text{Top-}N}^{(l)}-p_{1,\text{full}}^{(l)}]$ 衡量截断词表带来的近似误差；
- 实验发现 N=30 是甜点（覆盖迅速上升、误差迅速下降，之后收益递减）；Llama2 取 **K=30**，Llama3（128K 词表）取 **K=80**。
- 退出判据：局部 Top-1 概率与局部 Gap **同时**超过离线标定的逐层阈值即退出；阈值在局部候选空间下搜索，使标定集上早退准确率 > 0.99（τ=0.99）。

**（4）动态隐藏状态管理（解决 KV 冲突）**

- 退出时缓存该层隐状态；生成下一 token 时，前向到达退出层之后的第一层，将缓存隐状态与当前 token 表示联合参与计算；该层 KV 更新完成后清除缓存以回收内存。
- 相比 state copying（需加载所有剩余层权重）、KV copying（破坏语义一致性）、KV eviction（掩码注意力），本方案**不为当前 token 加载后续层权重**，天然契合卸载推理；图 6 显示其在长序列下 PPL 更低、相对延迟更小。

**（5）算法流程（Algorithm 1 摘要）**

- 逐层循环：加载隐状态 → 加载 K/V cache → 计算当前层并评估早退判据（同时**异步预取**下一层权重 $W_{l+1}$）→ 存储更新后的隐状态 → 更新 K/V cache → 若满足判据则缓存退出隐状态并终止当前 token 解码。

## 6. 主要结论与发现

- FlexEE 在几乎不损失精度的情况下实现高效早退：Llama2-7B 从第 8/16 层早退时平均退出层为 22.8/24.9（名义深度减少 28.8%/22.2%），13B 为 28.3/30.8，Llama3-8B 为 24.3/26.2。
- **越深的 self-spec 层 → 退出越晚但性能越好**，说明在语义更可靠的卸载层上做预测更合理。
- **端到端加速**：Llama2-7B 在 0%/50% 卸载下 1.27×/3.16×（75% 时达 3.29×）；Llama3-8B 为 1.25×/2.83×（75% 时 3.10×）；Llama2-13B 为 1.25×/2.67×（75% 时 2.68×）。
- **精度优于既有早退方法**：表 2 中 FlexEE 在 PPL 上显著优于 ShortGPT、AdaInfer、SpecEE、LayerSkip，MMLU/CommonsenseQA/SST 上 ∆Acc 最小（部分任务甚至为正）。
- **局部 Top-K 优于全词表**：全词表阈值过于保守，导致退出更晚、吞吐更低；Top-30 已达全词表质量的 98.67%。
- **开放式生成质量可比**：AlpacaEval-LC 胜率接近 50%，MT-Bench 分数几乎持平（如 Llama3-8B 6.39 vs Dense 6.41）。
- **自适应退出**：退出层分布跨越 8–15、16–23、24–30 及最终层，难 token 保留全深度计算。
- **batch 增大时收益减弱**：需等 batch 内所有样本退出才能跳层；但 FlexEE 目标场景（单用户交互、batch=1）恰好收益最大。
- 开销分析表明隐藏状态读写约 0.02 ms/层，远小于权重加载（7.11–10.96 ms/层），且计算可与异步权重预取重叠。

## 7. 优点

- **问题定位精准**：抓住卸载场景下"访存而非计算才是瓶颈"的本质，把早退与"避免权重加载"直接绑定，形成清晰的设计动机链。
- **算法—系统协同设计**：三项技术（逐层监督、Top-K 自推测预测、动态隐藏状态管理）分别对应三个挑战，逻辑闭环。
- **training-free 的推理侧预测器**：不需要重新训练即可复用 LayerSkip checkpoint，实用性强；且预测额外 FLOPs 仅为 AdaInfer 的约 1/30.74。
- **KV 缓存方案优雅**：以"保留+单层复用+及时清除"替代全层复制/重建，兼顾语义连续性与内存/访存效率，并有 PPL 与延迟双重验证。
- **开销分析细致**：显式给出预测器 FLOPs 公式、隐藏状态内存上界公式、逐阶段耗时表，并说明隐藏状态可复用未更新的 K/V 缓存空间。
- **实验覆盖广**：4 个模型、14+ 数据集、4 档卸载比例、多档 batch，含开放式生成与人类偏好式评测，结论稳健。
- **阈值泛化性验证**：跨数据集阈值向量 cosine 相似度 0.997–0.999，证明标定成本低、可迁移。

## 8. 不足与局限

- **依赖上游模型质量**：FlexEE 建立在带逐层早退监督的预训练模型（LayerSkip）之上，底层模型质量直接决定上限；对未做此类监督的通用 checkpoint 可能失效。
- **场景受限**：收益集中于**小 batch、内存受限的卸载式服务**；batch 增大（如 B=8）时收益明显衰减（Llama2-7B 50% 卸载下从 21.8 降至 6.4 tokens/s）。
- **卸载比例边际收益递减**：50%→75% 时增益下降，因为早退多发生在深层，无法充分利用额外卸载的层。
- **训练侧算力未报告**：论文未给出任何训练/标定的 GPU 数量与时长，复现成本不透明。
- **评测平台为模拟**：加速实验是"在实验平台上模拟部署场景"，非真实边缘设备或端侧硬件实测，实际部署收益可能打折扣。
- **对比基线存在不对等风险**：SpecEE 采用复现报告值、ShortGPT 借用 AdaInfer 统计量，且各方法 FLOPs 口径不完全统一，横向比较的公平性有限。

- **对 K/V 语义一致性的理论保证不足**：动态隐藏状态管理通过"保留退出隐状态 + 下一 token 单层复用"缓解 KV 缺失，但论文主要给出经验性 PPL/延迟证据，缺少对语义漂移程度的形式化分析。

## 9. 总体评价与适用建议

- **定位**：FlexEE 是一篇典型的**算法—系统协同**工作，其贡献不在于提出全新的早退机制，而在于**把已有早退思想适配到"权重卸载"这一具体部署约束下**，并针对性解决由此暴露的三个工程障碍。
- **核心贡献排序**：
  1. **动态隐藏状态管理**——最具系统价值，直接化解早退与 KV 缓存的结构性冲突，且天然避免加载后续层权重；
  2. **Top-K 自推测预测器**——以极低额外算力（0.264 GFLOPs）换取可用的退出判据，训练-free、即插即用；
  3. **卸载感知的退出层选择**——只在被卸载层判定，把"省计算"与"省访存"统一起来。
- **适用场景**：单用户/小 batch 交互式推理、内存受限且需权重卸载的服务端或端侧部署；对延迟敏感但可容忍轻微质量波动的场景收益最大。
- **不适用场景**：高吞吐大 batch 服务（收益随 batch 增大而衰减）、无逐层早退监督的通用 checkpoint、对安全与事实一致性要求极高且无额外校验的场景。
- **与相关工作关系**：与 LayerSkip 属"依赖"关系（复用其 checkpoint 与逐层监督思想），与 AdaInfer/SpecEE 属"改进/替代"关系（预测开销更低、精度更好、且面向卸载），与 ShortGPT 属"不同技术路线"（剪枝 vs 动态跳层）。
- **可复现性**：方法描述与公式较完整，阈值标定流程明确，开源与否是复现的关键前提；训练侧算力缺失虽因"training-free"可部分解释，但仍影响端到端复现成本评估。
- **潜在后续方向**：将阈值标定扩展到领域自适应语料；给出 K 的自适应选择规则；在真实端侧硬件上验证加速比；补充安全/偏差专项评测；探索与量化、投机解码等其他卸载友好的加速技术组合。
