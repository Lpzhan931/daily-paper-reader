## 摘要
将大型语言模型（LLM）直接部署在边缘移动平台上，因隐私性增强、个性化以及降低延迟等诸多优势而日益受到关注。然而，LLM 具有繁重的计算需求，资源受限的移动和边缘平台难以满足。除了计算资源有限之外，移动和边缘系统通常外形紧凑，缺乏物理散热机制（例如风扇）来散发高处理器利用率产生的热量，以防止节流和处理能力下降，而 LLM 很容易导致这些问题。为缓解这些影响，先前工作提出了各种功耗管理策略，例如动态电压频率缩放（DVFS），以降低移动平台上重计算任务的功耗和发热。最近，也提出了针对移动 LLM 的 DVFS 方法。然而，这些方法大多侧重于优化硬件参数和处理器频率，在某些受热约束的场景下表现不足。受机器学习近期进展的启发，我们发现并利用了这样一个关键洞见：并非所有 token 都需要全深度推理才能保持高质量生成。基于此，我们提出 PELM，一种在传统 DVFS 处理器频率调优基础上，增加两个面向工作负载的额外调控旋钮的解决方案：1）投机解码，2）可变验证深度，以将优化空间扩展到多个维度，从而实现更节能的端侧 LLM 推理。在跨硬件平台和数据集的广泛评估中，PELM 与最先进的功耗管理方法相比表现出更优性能，最高实现 23.1% 加速和 52.4% 能耗降低，同时保持相当的任务性能。源代码可在 https://github.com/imec-nu/PELM 获取。

## Abstract
Deploying Large Language Models (LLMs) directly on mobile platforms at the edge is gaining traction due to a myriad of benefits, such as increased privacy, personalization, and reduced latency. However, LLMs have heavy computational requirements, which are difficult for resource-constrained mobile and edge platforms to fulfill. In addition to limited compute resources, mobile and edge systems often have a compact form factor and lack physical mechanisms to dissipate heat generated from high processor usage rates (e.g., fans) to prevent throttling and reduced processing power, which LLMs can easily cause. To mitigate these effects, prior works have proposed various power governing strategies, such as dynamic voltage and frequency scaling (DVFS), for reducing power and heat generation for heavy computational tasks on mobile platforms. Recently, DVFS methods tailored for mobile LLMs have also been proposed. However, these methods mostly focus on optimizing hardware parameters and processor frequencies, and they fall short under some thermally constrained scenarios. Drawing from recent advances in machine learning, we identify and take advantage of the key insight that not all tokens require full-depth inference to maintain high-quality generation. Motivated by this, we present PELM, a solution that augments traditional DVFS processor frequency tuning with two additional workload-specific knobs: 1) speculative decoding and 2) variable verification depth to expand the optimization space to multiple dimensions for more power efficient on-device LLM inference. In extensive evaluations across hardware platforms and datasets, PELM demonstrates superior performance compared to state-of-the-art power governing methods, with up to 23.1% speedup and 52.4% reduction in energy consumption, while maintaining comparable task performance. The source code is available at https://github.com/imec-nu/PELM.

# PELM 论文总结

## 1. 核心问题与整体含义

- **背景**：LLM 端侧（移动/边缘）部署因隐私、个性化、低延迟等优势日益受关注，但面临两大瓶颈——(a) 计算资源受限导致解码吞吐低；(b) 设备紧凑、缺乏主动散热（如风扇），长时间推理极易触发热节流。
- **现有方案的不足**：传统 DVFS（schedutil、ondemand 等）及针对 LLM 的 DVFS（如 FUSE）只调节**处理器频率**这一单一旋钮，假设性能随频率平滑变化；但 LLM 生成具有高度不规则、token 相关的计算模式，仅调频陷入"降频省电但伤 QoE、升频保速但加剧过热"的根本两难。
- **核心洞见**：并非所有 token 都需要全深度（full-depth）推理即可保持高质量生成。作者实测（图 1、图 2）发现存在**多对一映射**——例如 32 层 @1.3 GHz 与 24 层 @0.7 GHz 速度相近，但后者能耗低 41.7%；且中间层（如第 24 层）输出在 HumanEval/GSM8K 上仍具可比的任务性能。
- **整体含义**：将优化空间从"仅频率"扩展到硬件 + 算法 + 工作负载三维，为端侧 LLM 提供兼顾能效与生成质量的跨层功耗管理方案。

## 2. 方法论

- **核心思想**：在传统 DVFS 频率控制之外，引入两个工作负载相关旋钮：
  1. **自投机解码（Self-Speculative Decoding, SSD）**：用模型自身前若干层作为草稿模型，免去独立草稿模型的显存开销；
  2. **可变验证深度（Variable Depth）**：验证阶段不必跑满全部 L 层，只用前 `vd` 层（`ns < vd ≤ L`），进一步压缩计算量。
- **问题形式化**：将标准 DVFS 问题 `min E[J(q)]`（受温度上限与目标速度约束）改写为多目标加权形式（式 2）：
  - 最小化 `λ_p·p(f,q) + λ_φ·(1-φ(vd|q)) + λ_R·(-R(ex,ns|vd,q))`
  - 其中引入新目标 **输出保真度 φ**（以验证深度 vd 为代理），并对速度采用奖励而非硬约束。
- **转化为 Q-learning**：将目标转为 `max_π E[Q_π(s,a)]`，用 Bellman 方程迭代更新；因动作空间庞大（AGX Orin 上 CPU 单簇最多 29 档频率、GPU 11 档），采用 **Branch-DQN** 将高维动作空间分解为多个子域，降低参数量与计算开销。
- **状态 / 动作 / 奖励设计**（表 1）：
  - **状态 s**：CPU/GPU 功耗与利用率、温度及温度变化率、可变深度 vd、投机加速比 R、当前 CPU/GPU 频率；
  - **动作 a**：CPU/GPU 频率、退出层 ex、投机次数 ns、可变深度 vd；
  - **奖励 r**：由速度奖励 `r_S`（鼓励接近目标速度、惩罚超速/欠速、偏好低 GPU 频率与高投机加速比）、可变深度奖励 `r_vd`（热余量充足时奖励深验证、紧张时奖励浅层）、热惩罚 `r_thermal`（sigmoid + 温度变化率）、频率-负载失配惩罚 `r_u`、功耗惩罚 `r_p` 共同构成。
- **行为策略（探索阶段）**：不采用随机采样，而是设计知识引导策略——基于热余量、速度比、投机加速比，采用类 **AIMD（加法增乘法减）** 逻辑调频；对投机参数采用反馈回路（比较当前与上一步加速比来调整 ex 与 ns）。
- **HQCache（Hidden Queue Cache）**：解决可变深度导致的 KV-cache 缺失问题。缓存各中间层隐藏状态，当当前 token 目标深度超过前序 token 时，从最深层缓存恢复而非从第一层重算；该机制同时应用于草稿与验证阶段。
- **控制流程**（算法 1）：每 100 ms 更新一次控制决策，DQN 选动作 → 更新频率与解码参数 → 执行 Δt → 观测新状态、计算奖励 → 存入回放缓冲区并小批量更新网络，周期性同步目标网络。

## 3. 实验设计

- **模型**：LLaMA-3.2-1B、LLaMA-3.1-8B、LLaMA-2-13B，均使用 LayerSkip 预训练（提供早退能力），HuggingFace Transformers + PyTorch 后端，batch size = 1。
- **平台**：Jetson AGX Orin（12 核 A78AE、2048 CUDA、64 GB、15–60 W）与 Jetson Orin Nano（6 核、1042 CUDA、8 GB、7–15 W）；均运行 Jetpack 6.2.1 / Ubuntu 22.04.5。
- **热条件**：通过固定风扇 PWM 定义 4 档散热（AGX Orin：64/51/38/26；Nano：90/77/64/51），所有实验从 45 ℃ 开始，热失效阈值 78 ℃（Orin）/ 73 ℃（Nano）。
- **Benchmark / 对比方法**：
  - **BLTN**：系统默认 governor（schedutil + nvhost_podgov）；
  - **STSD**：标准自投机解码（前 1/4 层为草稿，草稿长度固定 3）；

- **评估指标**：

## 6. 主要结论与发现

- **能效**：PELM 在 13B@Orin 上相比其他四种方法节能 29.0%–52.4%；8B 上节能 13.4%–32.5%；1B@Orin 上能耗略高（0.4%–7.3%）但唯一稳定满足 25 tokens/s 目标。
- **速度**：整体最高 **23.1% 加速**，在多数散热条件下保持最高或相当的平均生成速度。
- **热鲁棒性**：CR 完成率在几乎所有场景达 100%，仅在 13B + 最低散热这一极端场景下降至 45%（zTT 为 34%，PELM 多完成 32.4% 的查询）。
- **自适应行为**：重负载（13B/8B）下 PELM 运行在最低 GPU 频率（如 13B-High 为 0.57，比 BLTN/STSD 低 37.4%）；轻负载（1B）下反而主动提高频率（0.52 vs BLTN 0.28）以满足 QoE 目标——呈现双向自适应。
- **任务质量**：8B/1B 上 TSA 与全模型 vanilla 解码统计可比，最大退化 <17.2%；13B 上仍保留有意义质量；PPJ 在中重负载下最高提升 45.4%。
- **消融结论**：移除投机解码（A2）性能损失最大；移除可变深度（A1）普遍降低 PPJ；移除频率控制（A3）在轻负载下可获高 PPJ，但在中重负载下能耗失控。
- **局部性**：24 个高局部性案例中 18 个 SR 提升，能耗多数下降；但 1B@Nano 上因模型能力有限，8/12 案例未获加速，TSA 波动更大。
- **系统开销**：DQN 开销可忽略；HQCache 加载延迟 0.090–0.320 ms，比单层前向（4.195–20.416 ms）快 46–60 倍；缓存内存 <1% 模型权重。

## 7. 优点

- **跨层协同设计**：首次将 ML 领域的投机解码与系统领域的 DVFS 结合，构建"硬件频率 + 算法吞吐 + 计算负载"三维联合优化空间，突破单一调频的根本困境。
- **问题建模严谨**：从标准 DVFS 形式化出发，逐步引入可变深度并显式建模输出保真度 φ，将多目标标量化后自然映射到 DQN 奖励，数学链条清晰。
- **工程细节扎实**：Branch-DQN 分解大动作空间；知识引导的 AIMD 式行为策略优于随机探索；HQCache 针对可变深度的 KV-cache 缺失问题给出高效解法并量化其收益。
- **评估全面**：双平台、三模型、五数据集、四热档、完整留一消融、查询局部性分析、系统开销实测，指标覆盖能效、速度、完成率与任务质量。
- **实用性强**：DQN 极小（22 KB）可 CPU 运行，控制周期 100 ms，具备真实部署可行性；开源代码可复现。

## 8. 不足与局限

- **模型依赖**：PELM 依赖能暴露中间层输出的早退模型（如 LayerSkip），当前此类模型主要集中于 LLaMA 家族；迁移到 Phi、Qwen 等需在预训练/微调阶段加入早退监督。若模型无早退能力，PELM 退化为"DVFS + 全深度验证的自投机解码"。
- **未评估量化模型**：论文明确使用未量化 checkpoint，量化会改变延迟-功耗特性，且需保证可变深度执行下中间层输出与 HQCache 状态恢复的一致性，留作未来工作。
- **平台局限**：仅在 NVIDIA Jetson 两代平台上验证，移植到其他 SoC（如异构 CPU/GPU/NPU）需重映射控制旋钮并重新调参。
- **未考虑并发负载**：未评估后台任务共存或平台级 DVFS 策略交互场景下的鲁棒性。
- **实验样本偏小**：每数据集仅 40 条样本，部分任务得分（如 13B 的 Code 为 0）可能不具统计代表性；基线未包含最新 LLM 专用 DVFS（throttLL'eM、GreenLLM、AGFT 等）。
- **基线适配风险**：FUSE、zTT 原非为 LLM 设计，直接套用可能低估其潜力或高估 PELM 优势。
- **算力信息缺失**：未报告训练/评测总算力开销，不利于复现与横向比较。
- **1B@Nano 局部性表现不稳定**：小模型下投机正确性更难保证，SR 提升不一定转化为 TSA 提升，说明方法在小模型上的收益存在非单调性。
