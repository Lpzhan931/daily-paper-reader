## 摘要
推测解码可加速 rollout 生成，而 rollout 生成在强化学习（RL）后训练的开销中占主导地位。在线协同训练能够进一步提升草稿模型的准确率，从而带来更大的加速。然而，将该方法扩展到长上下文大模型上的协同训练面临两个障碍：（1）标准因果上下文并行（CP）实现不支持分支注意力；（2）目标特征跨越流水线并行（PP）阶段。我们通过一个面向大规模在线草稿协同训练的端到端系统解决了这两个问题。对于 CP，我们扩展了打包式、负载均衡的 zigzag ring attention，将 rank 局部的分支注意力与因果主序列注意力合并。对于 PP，TapChannel 通过单独路径跨阶段传输中间目标特征，且不影响流水线调度。实验表明，协同训练的草稿模型能够紧密跟踪策略基线，同时在模型规模高达 122B 时带来显著的 rollout 和端到端加速。我们的 CP 设计在 256K token 下实现了良好的扩展性，并较先前工作显著节省内存，而 PP 传输仅带来适度开销。代码见 https://github.com/NVIDIA-NeMo/RL/issues/3698。

## Abstract
Speculative decoding accelerates rollout generation, which dominates the cost of reinforcement learning (RL) post-training. Online co-training can further increase the draft's accuracy, yielding greater speedups. However, scaling this approach to co-training on large models with long contexts poses two obstacles: (1) branch attention is unsupported by standard causal context-parallel (CP) implementations, and (2) target features span across pipeline-parallel (PP) stages. We address both with an end-to-end system for large-scale online draft co-training. For CP, we extend packed, load-balanced zigzag ring attention by merging rank-local branch attention with causal main-sequence attention. For PP, TapChannel transports intermediate target features across stages via a separate path, leaving the pipeline schedule unaffected. Experiments demonstrate that co-trained drafts closely track the policy baseline while delivering substantial rollout and end-to-end speedups across model scales up to 122B. Our CP design achieves strong scaling at 256K tokens with significant memory savings over prior work, and our PP transport incurs modest overhead. Code can be found at https://github.com/NVIDIA-NeMo/RL/issues/3698.

# 论文总结：面向大规模长上下文 RL 后训练的在线草稿协同训练

## 1. 核心问题与整体含义

- **研究背景**：强化学习（RL）后训练已成为构建推理与智能体大模型的标准范式，而其墙钟时间主要由 **rollout 生成**主导。推测解码（Speculative Decoding, SD）通过“小模型草稿 + 大模型并行验证”加速自回归生成，且不改变输出分布。
- **核心动机**：将草稿模型在 RL 过程中**在线协同训练**，可随策略演化持续提升接受长度，带来更大加速。但把该方案扩展到**大模型 + 长上下文**场景存在两个系统性障碍：
  1. **标准因果上下文并行（CP）不支持分支注意力**：EAGLE-3、DFlash、DSpark 等先进草稿结构引入了分支式注意力，并消费目标模型的中间隐状态，标准 CP 无法处理。
  2. **目标特征跨流水线并行（PP）阶段**：草稿只驻留在最后一个 PP 阶段，而所需的目标隐状态分散在多个远端阶段，标准 PP 仅连接相邻阶段，无法传递。
- **整体含义**：论文主张**不改变目标模型的并行拓扑**，而是围绕既有 CP/PP 配置改造系统，使大规模长上下文 RL 后训练中的在线草稿协同训练变得可行。

## 2. 方法论

### 2.1 核心思想：在线草稿协同训练

- 设策略参数为 θ、草稿参数为 ϕ，草稿在**同一批策略 rollout token** 上训练，并对目标特征 $H_\theta(x)$ 施加 **stop-gradient**，联合目标为：

$$L(\theta, \phi) = L_{RL}(\theta) + \lambda L_{draft}\big(\phi; x, \text{sg}(H_\theta(x))\big)$$

- 草稿模型被实例化为**策略最后一个 PP 阶段上的子模块**，与策略模型联合更新。

### 2.2 CP 下的分支注意力

- **分解思路**：每个分支 query 面对两个 key 集合——① 跨 CP rank 分片的**主序列因果前缀**；② 保留在分支锚点所属 rank 上的**分支局部 key**。两者独立计算后合并。
- **主序列部分**：沿用打包式、负载均衡的 **zigzag ring attention**；每个 ring step 中 K/V 在 rank 间循环，query 保持本地。
- **合并方式**：采用 ring attention 步骤间的标准 online-softmax 归约：

$$\ell = \log(e^{\ell_m} + e^{\ell_b}), \quad O = e^{\ell_m - \ell} O_m + e^{\ell_b - \ell} O_b$$

- **统一支持三种草稿族**：
  - **EAGLE-3**：训练时测试（TTT），每步产生独立分支，关注逐步增长的草稿内上下文；
  - **DFlash**：块扩散，一次前向生成整块 token；
  - **DSpark**：在 DFlash 上加入轻量 Markov 头，以低秩、前 token 条件偏置恢复块内因果依赖。
- **通信成本**：前向每 rank 出站量为 $V^{CP}_{fwd} = 2(C-1)\frac{N}{C} d_{kv} b$，**与分支数量/深度无关**；反向复用同一 K/V ring，无额外分支相关流量。通信与注意力按 ring step 粒度重叠，暴露开销为 $E(r)_{CP} = \max(t^{(r)}_{comm}, t^{(r)}_{attn})$。

### 2.3 PP 下的 TapChannel

- **问题**：产生 tap（目标隐状态）的层跨多个 PP 阶段，而草稿仅在最后阶段；标准 PP 只连相邻阶段。
- **方案**：在**流水线调度之外**开一条旁路（side path），每个源阶段在草稿阶段有预分配的 mailbox 槽位；源阶段完成某 micro-batch 的策略前向即写入，草稿阶段在自身前向之前读取。
- **同步机制**：每个槽位带**序列戳（sequence stamp）**，源与草稿各自读写时递增；同址源用 **CUDA IPC**，跨节点源用**专用 NCCL 通信器 + GPUDirect RDMA**。
- **成本**：每 micro-batch 特征载荷 $V_{Tap} = b\,n \sum_{s \in S} d_s$，每个特征**仅直传一次**（与 PP 跳数无关）；残差会合延迟 $E(m)_{Tap} = \max_{s} \max(\tau_{s,m}, \Delta_{s,m})$，只有超出 slack 的部分才产生可见开销。

## 6. 主要结论与发现

- **学习轨迹保持**：协同训练的草稿在奖励、验证准确率、训练-推理 KL 散度上均**紧密跟踪 baseline**，KL 近零，验证了训练与推理后端数值一致，保持了 GRPO 的 on-policy 假设。
- **端到端加速**：接受长度 2.28–4.78，rollout 加速 1.19–2.23×，端到端训练加速 **1.16–1.88×**；DFlash 与 DSpark 一致优于 EAGLE-3。
- **CP 性能**：打包 zigzag 注意力相比最优 USP 变体在 CP=2/4/8 下分别快 **2.9×/2.3×/1.5×**，每 GPU 峰值显存降低 **2.7×**；TTT 注意力从 CP=1 的 17.7 s 降至 CP=8 的 2.35 s（7.5×，94% 并行效率），显存从 53.2 GB 近线性降至 7.5 GB，实现 256K token 扩展。
- **PP 开销**：TapChannel 单边写达 27–39 GB/s，比 host staging 快 4.5–8.5×；对源阶段几乎无干扰，接收端草稿阶段仅 1.6% HBM 争用，而 host staging 使所有 rank 降速 >80%。全流程中块草稿开销 <15%，EAGLE-3 因 TTT 为 34%；Tap 等待仅占优化时间 1.5–2.2%。
- **多轮场景限制**：Workplace Assistant 上端到端加速仅 1.25–1.43×，明显低于 rollout 阶段加速，原因是 rollout 仅占步时 55.8%，工具执行与环境延迟无法被更快解码消除。
- **MoE 与线性注意力**：大 MoE 目标虽接受长度高，但每次验证前向触发稀疏路由专家计算，端到端加速偏低；线性注意力模型因验证本身较便宜，推测收益也相对更小。

## 7. 优点

- **系统设计“非侵入”**：不修改目标模型既有 CP/PP 拓扑，而是让草稿适配既有并行布局，工程落地性好。
- **统一的分支注意力抽象**：将分支注意力拆为“主序列因果部分 + rank 本地分支部分”并在线 softmax 合并，一套机制同时覆盖 EAGLE-3、DFlash、DSpark 三种结构。
- **通信成本与分支无关**：分支 K/V 留在本地，通信量仅与 CP 度、序列长度、KV 宽度相关，不随分支数量/深度增长，理论上限清晰。
- **TapChannel 的调度透明性**：旁路传输不进入流水线调度，避免打乱 pipeline bubble 结构；序列戳 + 预分配槽位设计兼顾同址与跨节点两种场景。
- **实验覆盖较广**：跨 3 个草稿族、5 个目标模型（8B–122B）、单轮与多轮、CP 与 PP 两个瓶颈维度，并给出 operator 级和系统级双层验证。
- **公平对比**：CP 对比在相同 GPU 数、相同 workload 下与 USP 直接对照，并暴露其 padding 开销；PP 对比设置 host-staging 基线。
