## 摘要
推测解码通过让轻量级草稿模型预测未来 token，并由目标模型进行验证，从而无损地加速大语言模型推理。近期的块扩散草稿器通过并行预测多个 token，进一步降低了草稿生成延迟。然而，现有块草稿器将每个输入位置的目标隐藏状态投影到独立的草稿端 KV 缓存中，带来随并发量增长的每请求内存和 KV 写入开销；直接原地复用目标 KV 可以消除该缓存，但无法在整个块内维持草稿质量。我们提出一种混合目标上下文注入方法，仅通过最后一个输入位置的目标隐藏状态来补充直接的目标 KV 复用，且无需独立的草稿端 KV 缓存。在此设计基础上，我们提出 H-Spec，一种混合 Mamba-注意力并行草稿器，通过互补模块利用这两种目标上下文来源。Mamba 模块由投影后的最后一个 token 目标隐藏状态初始化，而注意力模块则原地复用目标 KV。尽管其具有循环形式，Mamba 的并行扫描仍使 H-Spec 能够保持块并行草稿生成。在三个目标模型和多种任务上，H-Spec 将平均接受长度较最佳基线提升 5.0–13.3%，并将批大小为 1 的 token 间延迟加速比提升 5.3–12.6%。在并发服务下，H-Spec 在所评估的各并发级别上始终实现更高的吞吐量，同时保持比基线更低的 KV 缓存利用率。

## Abstract
Speculative decoding losslessly accelerates large language model inference by having a lightweight draft model predict future tokens for verification by the target model. Recent block diffusion drafters further reduce drafting latency by predicting multiple tokens in parallel. However, existing block drafters project target hidden states at every input position into a separate drafter-side KV cache, incurring per-request memory and KV-write overhead that grow with concurrency; directly reusing target KVs in place removes this cache but fails to sustain draft quality throughout the block. We propose a hybrid target-context injection method that complements direct target KV reuse with target hidden states only at the last input position, requiring no separate drafter-side KV cache. Building on this design, we propose H-Spec, a hybrid Mamba-attention parallel drafter that consumes the two target-context sources through complementary modules. Mamba modules are initialized with projected last-token target hidden states, while attention modules reuse target KVs in place. Despite its recurrent formulation, Mamba's parallel scan allows H-Spec to preserve block-parallel drafting. Across three target models and diverse tasks, H-Spec improves over the best baseline by 5.0--13.3% in mean accepted length and 5.3--12.6% in batch-size-1 inter-token latency speedup. Under concurrent serving, H-Spec consistently achieves higher throughput while maintaining lower KV cache utilization than baselines across evaluated concurrency levels.

- **研究问题**：能否设计一种并行草稿器，在**不使用草稿端 KV 缓存**的前提下，仍保持强目标模型条件化与草稿质量？

## 2. 方法论

### 2.1 核心思想：混合目标上下文注入（Hybrid Target-Context Injection）

- 观察到隐藏状态与 KV 提供的信息性质不同：
  - **目标 KV**：提供位置级细粒度信息，供未来 query 检索，但缺乏对整段输入的显式上下文摘要。
  - **末位隐藏状态**：在因果注意力下，最后一个输入位置的隐藏状态已被全部前缀条件化，构成完整输入的紧凑摘要，且存储开销为 $O(1)$（与输入长度无关）。
- 因此将二者互补结合：**原地复用目标 KV（细粒度）+ 仅末位位置的目标隐藏状态（全局摘要）**，从而消除 $O(N)$ 的草稿端 KV 缓存。

### 2.2 架构：Mamba–注意力混合并行草稿器

- **Mamba 模块（承载末位隐藏状态）**：
  - 跨层融合选定目标层在末位 $n$ 的隐藏状态：$F_n(\mathcal{M}) = \mathrm{Proj}_r(\mathrm{Concat}(\{h_n^{(m)}\}_{m\in\mathcal{M}}))$，再投影为 Mamba-2 初始循环状态 $S_{\text{init}} = \mathrm{Proj}_{d_S}(F_n(\mathcal{M}))$。
  - 共享 $\mathrm{Proj}_r$、$\mathrm{Proj}_{d_S}$ 权重，每个草稿前向仅计算一次初始状态。
  - 状态更新沿用 Mamba-2 选择性递推 $S_i = \bar{A}_i S_{i-1} + \bar{B}_i x_i$，利用 **并行扫描（parallel scan）** 一次性计算块内所有位置，保持块并行草稿。
  - 不加位置嵌入，但递推扫描天然产生位置相关隐藏状态，保留输入依赖选择性。
- **注意力模块（承载目标 KV）**：
  - KV 维度、注意力头数与 KV 头数对齐目标模型，实现目标 KV 原地复用。
  - 层间 KV 映射：每个 H-Spec 层的注意力模块消费某一个目标层的 KV（不做跨层 KV 融合，否则需物化融合 KV、重新引入缓存）。
  - 因果注意力 + 目标 KV 作为前缀；采用 **2,048 token 滑窗注意力（SWA）** 提升长上下文稳定性。
  - 位置对齐：目标 KV 已存 post-RoPE，草稿块 Q/K 使用目标模型 RoPE θ 并从目标前缀续接位置索引。
- **因果校正（Causal Correction）**：复用 DSpark 的 Markov head，一阶马尔可夫依赖修正各草稿位置 logits；作者明确声明这不是本文贡献，混合骨干可搭配任意校正机制。
- **配置匹配**：为公平对比，注意力/MLP/Markov head 维度与 DFlash/DSpark 对齐，参数总量差 ≤2.9%；因每层多一个 Mamba 模块，采用 4 层（3 层完整 Mamba-Attention-MLP + 1 层部分 Mamba-MLP）。

## 6. 主要结论与发现

- **单请求性能**：在 3 个目标模型、8 任务平均上，H-Spec 较最佳基线提升 $\tau$ 5.0–13.3%、ITL 加速比 5.3–12.6%（Llama 13.3%/12.6%，Qwen3-4B 5.0%/5.3%，Qwen3-8B 8.7%/8.7%）；配对 bootstrap 95% CI 全部位于零以上。
- **扩展评测**：DeepSpec 9 任务上 $\tau$ 提升 3.8–12.5%、Spd. 提升 4.3–13.1%，且在每任务、每模型上均领先且统计显著。
- **并发服务**：在 $C=8$–128 全并发级别上实现最高吞吐、最低 KV 缓存利用率；峰值吞吐较最强基线提升 13.0–17.3%（Llama）、5.1–7.4%（Q4B）、7.6–9.7%（Q8B）；KV 利用率较最省内存基线降低 4.3–24.6%；吞吐优势随并发增大（Qwen3-8B 上 $C=8\to128$ 时优势扩大 1.13–1.58×），与基线 KV 注入开销随并发增长的现象一致。
- **消融**：仅用末位隐藏状态或仅用目标 KV，平均 $\tau$ 分别下降 24.1–30.5% 与 7.1–11.7%，证实两种上下文**互补而非可互换**；混合骨干较 Mamba-only 提升 28.9–45.1%、较 Attention-only 提升 13.3–15.3%（参数大致匹配）。
- **运行时扩展**：低并发（$C<32$）时混合骨干因计算图更深略慢；高并发与长输入（>约 512 token）时反超（Mamba 每步 $O(1)$、注意力 $O(N)$）。
- **鲁棒性**：贪心/无截断采样、不同草稿长度、1K–32K 长上下文、零样本迁移到微调目标下，H-Spec 均保持最优（11/12 迁移设置统计显著）。

## 7. 优点

- **问题定位精准**：将"草稿端 KV 缓存"识别为随并发放大的可避免开销，并给出定量证据（KV 内存 1.1–1.8×、注入时间 4.7× 增长）。
- **方法设计有原则**：不是简单删缓存，而是基于"隐藏状态=全局摘要、KV=位置级细节"的信息性质差异做互补注入，$O(1)$ 存储的末位隐藏状态与 Mamba 循环状态角色天然契合。
- **架构–机制匹配**：Mamba 承担摘要初始化、注意力承担 KV 复用，且并行扫描保证块并行性不被破坏。
- **实验严谨性高**：
  - 统一训练配方 + 匹配参数量 + 相同目标层选择 + 统一验证策略（固定长度验证）与统一注意力实现，控制变量到位。
  - 系统使用配对 bootstrap CI 做显著性检验，报告置信区间而非仅报点估计。
  - 同时报告单请求质量与并发服务效率，且以 Pareto 形式（吞吐 vs KV 利用率）呈现，更贴近真实部署。
- **工程友好**：仅需 K/V 维度对齐即可原地复用目标 KV，直接接入 vLLM 生态（Speculators 框架），且天然兼容任意因果校正机制。

## 8. 不足与局限

- **架构约束**：必须使草稿器 K/V 维度与目标模型一致才能原地复用，比隐藏状态式 KV 注入多一层架构限制；同时匹配注意力/KV 头数，未探索部分头复用。
- **低并发/短输入劣势**：$C<32$ 或输入较短时混合骨干前向更慢（计算图更深），优势区间在高并发与长上下文；小规模部署收益可能被抵消。
- **贡献边界**：因果校正（Markov head）直接沿用 DSpark，非本文贡献；与 DFlash-2 的卷积/路径选择器等组件是否叠加增益未验证。
- **实验覆盖**：
  - 目标模型仅 4B–8B，未验证数十亿以上更大模型上的可扩展性与收益保持性。
  - Serving 仅单卡 A100，未覆盖多卡张量并行、不同显存容量、不同推理引擎（仅 vLLM）。
  - DFlash-2 为自实现基线，缺少官方训练流程，比较结论具"初步"性质。
  - 长上下文仅 2 任务、2 个长度维度，覆盖有限。
- **统计与偏差风险**：
  - 3/45 个设置中领先不显著；整体结论依赖任务平均，存在任务选择敏感性风险。
  - 训练数据（Magpie + Ultrachat 100K）与评测分布可能不完全代表生产流量。
  - 部分指标（如 KV 利用率）依赖具体 serving 引擎实现，跨平台可比性存疑。
- **可复现性**：训练 GPU 型号、时长、总算力开销、显存占用等未披露；未报告端到端部署成本。
