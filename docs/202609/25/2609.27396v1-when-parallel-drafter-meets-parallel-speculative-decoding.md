## 摘要
DSpark 风格的并行起草器使推测解码变得非常高效，但其起草阶段在每一轮的关键路径上仍保持串行。并行推测解码（PSD）将起草与验证重叠，但现有方法必须提前猜测被接受的前缀和 bonus token：一旦猜错，整个批次就会退回到串行起草。我们提出 DPara，一个 PSD 框架，它复用了有效的并行起草器，同时保证每一轮中主干网络与验证的重叠，从而彻底消除了这种概率性回退。当目标模型进行验证时，DPara 的扩散主干会为每个接受边界预计算起草表示，并将 bonus token 留作未指定；随后，一个轻量级自回归头将揭示出的验证结果与匹配的预计算表示相结合，几乎即时地生成下一轮的起草 token——将占主导的主干前向与验证完全并行化，只留下可忽略的头部开销保持串行。在 Qwen3-8B 和 Qwen3-14B 上、跨七个数学、代码和聊天基准的实验表明，DPara 相比自回归解码实现了平均 3.21× 和 3.52× 的加速，同时超越了最强的串行和并行推测解码基线。

## Abstract
DSpark-style parallel drafters have made speculative decoding highly effective, yet their draft phase remains serialized on the critical path of every round. Parallel speculative decoding (PSD) overlaps drafting with verification, yet existing methods must guess the accepted prefix and bonus token in advance: a wrong guess reverts the whole batch to serial drafting. We present DPara, a PSD framework that reuses effective parallel drafters yet guarantees backbone--verification overlap in every round, thereby eliminating this probabilistic fallback altogether. While the target verifies, DPara's diffusion backbone precomputes draft representations for every acceptance boundary with the bonus left unspecified; a lightweight autoregressive head then combines the revealed verification outcome with the matching precomputed representation to emit the next round's draft tokens almost instantly---fully parallelizing the dominant backbone forward with verification and leaving only the negligible head cost serial. Experiments on Qwen3-8B and Qwen3-14B across seven math, coding, and chat benchmarks show that DPara achieves average speedups of $3.21\times$ and $3.52\times$ over autoregressive decoding, surpassing the strongest serial and parallel speculative decoding baselines alike.

## 1. 核心问题与整体含义

- **研究背景**：推测解码（SD）通过轻量起草器生成候选 token、目标模型并行验证来加速 LLM 推理。其端到端效率主要受两个因素支配：平均接受长度与起草延迟。
- **并行起草器进展**：DART、DFlash 等扩散式并行起草器可在一次前向中预测多个未来位置；DSpark、Domino 进一步用轻量自回归头恢复序列一致性，提高接受长度。
- **关键瓶颈**：即使使用 DSpark 风格并行起草器，传统“起草—验证”仍是串行调度，起草阶段占端到端延迟约 **24%–32%**，位于关键路径。
- **PSD 的困境**：并行推测解码（PSD）尝试将起草与验证重叠，但 SSD、PEARL 等方法必须提前猜测接受前缀和 bonus token。猜错会导致整批请求回退到串行起草；batch 越大，至少一个请求猜错的概率越高，batch=16 时 SSD 回退率可达 **57%–96%**。
- **核心问题**：能否彻底消除 PSD 中由预测错误导致的概率性串行回退？论文给出肯定回答，并提出 DPara。

## 2. 方法论

- **核心思想**：将“必须等待验证结果的计算”和“可独立于验证结果的计算”分离。DPara 在目标模型验证当前块时，用扩散骨干为**所有可能的接受边界**预计算草稿表示；bonus token 暂不指定，等验证返回后再由轻量 AR 头结合真实结果生成下一轮草稿。
- **关键要求与 M-DFlash**：
  - DFlash 传统上只从单个、无 target feature 的 anchor token 预测未来 logits。
  - DPara 要求骨干从**多个、无 target feature 的 anchor token**出发，并一次性覆盖所有接受边界。
  - 作者将 DFlash 微调为 **M-DFlash**，不引入新可训练参数；从官方 DSpark checkpoint 初始化，只训练扩散骨干，冻结 AR head、目标模型、token embedding、LM projection 和 confidence head。
- **注意力结构**：
  - 使用共享因果 spine + 隔离双向分支的树状注意力掩码。
  - 前一轮 bonus 与草稿 token 构成共享无特征 spine；每个接受边界对应一组 mask token，分支内双向可见，分支间不可见，且只能看到对应 anchor 前缀。
  - 一次骨干前向即可为所有接受边界产出 logits。
- **训练目标**：
  - AR 头按 \(z_i = \ell_i + W E(y_{i-1})\)、\(y_0=b\) 生成 token。
  - 损失为位置加权混合：约 **0.1 的交叉熵 + 0.9 的全词表概率距离**，权重 \(w_i=e^{-(i-1)/\gamma}\)，\(\gamma=4\)，并带 validity mask；confidence loss 被禁用。
- **算法流程**：
  1. 同时启动：M-DFlash 在 spine 上预计算所有接受边界的 base logits；目标模型验证同一 token block。
  2. 验证返回接受长度 \(r\) 和 bonus \(b\)。
  3. 选择预计算分支 \(r\)，无需回退。
  4. AR 头以 \(b\) 为起点，快速生成下一轮草稿 \(y_{1:d}\)。
  5. 更新特征缓存，丢弃被拒后缀，下一轮以 \(b\) 作为新的无特征 anchor。
- **理论延迟模型**：\(T_{\text{step}} \approx \max(T_{\text{verify}}, T_{\text{precompute}}) + T_{\text{Head}}\)。只要骨干预计算落在验证窗口内，占主导的骨干前向即可被隐藏，关键路径只剩轻量 AR 头。
