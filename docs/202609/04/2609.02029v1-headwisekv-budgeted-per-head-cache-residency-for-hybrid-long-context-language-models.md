## 摘要
长上下文推理在解码过程中会保留不断增长的键值（KV）缓存，这消耗大量GPU内存并可能降低生成吞吐量。在混合语言模型中，这一瓶颈依然存在，因为其残差全局注意力层可能主导上下文相关的缓存需求。我们研究如何在聚合KV驻留预算下分配这种状态。我们提出HeadWiseKV，一种无需训练的框架，可压缩混合语言模型的残差全局KV缓存，同时保留其原生的局部、循环和线性路径。它为每个物理KV头分配一个静态的多级历史窗口，使得服务前的缓存需求可预测。我们将此分配问题形式化为受限的操作速率-失真问题，并提出SeqCalib作为HeadWiseKV中的核心策略生成算法。SeqCalib按执行顺序处理层，并基于部署时使用的下层策略来条件化每个决策，从而考虑跨深度的交互。分组缓存运行时将所选策略物化为实际的每头KV驻留，而非完整缓存上的掩码。我们在四个混合长上下文模型上评估下游质量，并在Qwen3.6-27B上研究物理驻留和服务行为。HeadWiseKV在所评估模型中保持接近全KV的RULER和LoCoMo质量。在固定模型系统研究中，它在112K上下文长度下将采样峰值设备内存降低8.59%，并将最大已验证成功上下文从114K扩展到161K。

## Abstract
Long-context inference retains a growing key--value (KV) cache during decoding, which consumes substantial GPU memory and can reduce generation throughput. This bottleneck remains in hybrid language models because their residual global-attention layers can dominate context-dependent cache demand. We study how to allocate this state under an aggregate KV-residency budget. We introduce HeadWiseKV, a training-free framework that compresses the residual global KV caches of hybrid language models while preserving their native local, recurrent, and linear paths. It assigns each physical KV head a static, multilevel history window, making cache demand predictable before serving. We formulate this allocation as a restricted operational rate--distortion problem and propose SeqCalib as the core policy-generation algorithm in HeadWiseKV. SeqCalib processes layers in execution order and conditions each decision on the lower-layer policy used at deployment, thereby accounting for interactions across depth. A grouped-cache runtime materializes the selected policy as actual per-head KV residency rather than a mask over a full cache. We evaluate downstream quality across four hybrid long-context models and study physical residency and serving behavior on Qwen3.6-27B. HeadWiseKV retains near-Full-KV RULER and LoCoMo quality across the evaluated models. In the fixed-model systems study, it reduces sampled peak device memory by 8.59\% at a 112K context length and extends the largest verified successful context from 114K to 161K.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究问题**：长上下文推理在解码阶段会保留规模不断增长的 KV（键值）缓存，这会消耗大量 GPU 显存并降低生成吞吐量。混合语言模型（Hybrid Language Models）虽然引入了局部注意力、循环或线性路径，但其中残留的全局注意力层的 KV 缓存开销仍然很大，成为系统性能的关键瓶颈。
- **关键发现**：在混合模型中，通常是少数残留的全局层决定了长请求能否适配进显存。由于各个注意力头对历史上下文长度的敏感程度不同，采用同一窗口长度或仅仅做“完整 / 压缩”的二元分配往往不够精细，无法有效平衡质量与资源占用。
- **论文的核心主张**：将 KV 压缩做进“预算体系”中——为每个物理 KV 头在请求前（offline）分配一个静态的多级历史窗口，使运行时能够以确定性的、可预测的方式分配物理存储；压缩聚焦于全局注意力头，不触碰局部或循环路径。
- **整体含义**：HeadWiseKV 的核心目标是**在不重训练、不改架构的前提下，用静态的按头（per-head）多级窗口**替换全量 KV，显著降低推理显存峰值并延长可处理的上下文长度，同时尽量保持全 KV 下的模型质量。

### 2. 方法论：核心思想、关键技术细节与流程

#### 2.1 核心思想
- 将 KV 驻留策略拆分为三层 **离线到在线（offline-to-online）** 的流水线：
  1. **结构驻留模型（Structured Residency Model）**：定义每个物理 KV 头可选的有限历史窗口集合与存储成本。
  2. **SeqCalib 策略生成算法（核心）**：在给定码本和相似度阈值下，逐层、按执行顺序为每个物理头挑选最短且满足质量阈值的后缀窗口。
  3. **分组缓存运行时（Grouped Cache Runtime）**：把选定策略一次性加载并实现为实际的物理缓存形态（不同的物理长度），而不是在全量缓存上套一个逻辑稀疏掩码。

#### 2.2 关键定义
- **决策单元**：物理 KV 头 `(ℓ, h)`（而非 query 头）；在 GQA 中同一 KV 头可被多个 query 头共享。
- **窗口码本**：`a_ℓh ∈ W = {w1...wK, full}`，其中 `wk` 为有限连续后缀长度。例如 `W = {8K, 16K, 32K, full}`。
- **存储成本函数**：`n_ℓh,C(w) = r_C(w) × (维度 × 精度)`；总成本为逐头求和的 `N_C(a)`。
- **归一化驻留率（R_C）**：选定策略的缓存成本 / 全满策略缓存成本。如 `R = 0.5` 表示相关 KV 存储仅为 full 方案的一半。
- **受限率-失真问题（rate–distortion formulation）**：在所有满足预算（rate ≤ β）的策略矩阵中，最小化与全 KV 参考模型的端到端期望偏离。

#### 2.3 SeqCalib 算法
- **执行顺序与条件化**：
  - SeqCalib 按前向执行顺序逐层处理（layer-by-layer）。
  - 当校准层 `ℓ` 时，**低层策略 `a<ℓ` 保持部署时的真实状态并被冻结**。
  - 对当前层做一次 full-history trace，再在同样的下层前置条件下回放所有候选窗口。
- **相似性度量**：
  - 比较候选窗口与 full-history 条件下的 attention 输出均值余弦相似度（mean-cosine）。
  - 对每个候选 `w`，计算公式为：
    - `o(w) = Σ π(w) · v`（局部重归一化后的注意力输出）
    - 比较 `o(w)` 与 `o(full)`（完整历史条件下的输出）的余弦相似度，并在校准数据集、多个 query 位置上取平均。
- **决策规则**：针对每个物理头，选**最短、成本最低且平均相似度 ≥ τ 的窗口**；由于 `full` 总是可行，任何层都有解。
- **全局性质**：算法能保证在给定已选下层前缀下的**逐层局部最小成本**（fixed-prefix minimality），但**不保证联合全局最优**。论文明确区分“stage-wise exact”而非“globally optimal”。
- **预算选择**：在不同阈值 τ 上独立跑若干次，形成“τ 网格银行”及其驻留率记录，再由确定性 lexicographic 规则（在预算内最大化最低头分数 → 最小化速率 → 最小化网格序）选择实际部署策略。

#### 2.4 运行时设计
- 分组缓存运行时按策略矩阵为不同窗口分配不同的物理缓存组。
- 每个物理 KV 头只读写分配的 K/V 切片，query 头读取对应的 KV 组后拼接输出并走模型的原始门控与输出投影。
- 本地、循环层完全不动。
- 策略是一次性加载、请求无关的，不随 prompt 变化；物理缓存不完整构建，因此能够降低 prefill 峰值。

### 6. 主要结论与发现

1. **质量保持**：在 68.95% KV 驻留下，HeadWiseKV 在 Qwen3.6-27B 的 RULER 得分仅从 100.00 降到 99.65，LoCoMo 保持 94.55 不变；在 agent 任务（Airline、Retail）上甚至高于 Full-KV。
2. **系统收益**：112K 上下文时峰值显存降低约 8.59%（−2.01 GiB）；prefill 吞吐量为 Full-KV 的 0.810–1.092×（随上下文长度变动），decode 吞吐量为 0.954–1.017×，保持基本一致。
3. **最大上下文扩展**：Full-KV 能成功运行到 114K、在 115K OOM；HeadWiseKV 能成功运行到 161K、在 162K OOM——**最大已验证上下文长度扩大 1.41×**。
4. **压缩冗余广泛存在**：在 96% 和 85.74% 驻留率下质量完全无下降；只有到 68.95% 的最强压缩档才出现轻微 RULER 下降（0.35 分）。
5. **跨模型迁移可行但需注意**：共享阈值 τ 在四个模型上都能保持 RULER 接近全 KV（差距 ≤ 0.61），但 LoCoMo 在部分模型上有 2 分左右差距、诱导的驻留率差异很大——说明 τ 是“保真阈值”而不是压缩率控制器，部署时需要按模型独立验证。
6. **静态分配也能奏效**：尽管无法针对特定 prompt 保留“孤立的远处信息”，HeadWiseKV 通过细分窗口粒度与下层条件化的校准，在多数 benchmark 上优于具有 prompt 自适应能力的动态方法（如 AdaKV/HeadKV-R2）。

### 7. 优点

#### 7.1 方法层面
- **训练自由、部署友好**：无需重训练或架构改动，静态策略可预加载、可预测。
- **细粒度、多级分配**：比 StreamingLLM / DuoAttention 的二元“保留/压缩”更细；对同一层不同物理 KV 头可给不同历史长度。

- **物理驻留的实现**：不是“在一个完整 cache 上加逻辑 mask”，而是真实压缩存储分布，因此可以降低 prefill 阶段的峰值显存。
- **理论框架清晰**：把问题放进率-失真框架，并给出有限的逐层最优性（fixed-prefix minimality）的形式化命题，虽然不声称全局最优，但把方法的边界讲清楚了。

#### 7.2 实验层面
- **工作量大，分层清楚**：构建了“质量 vs 系统”分离的报告方式，避免了将策略效果与 runtime 实现混在一起，一定程度上比许多 KV 压缩论文更严谨。
- **多维度评估**：不只测内存，还测吞吐、最大上下文、质量、跨模型泛化。
- **仔细记录了限制**：对控制方法实现适配与单独 campaign 报告各自的限制，不以“全场景优于”的口吻误导。

### 8. 不足与局限

#### 8.1 方法本身
- **静态分配的固有劣势**：无法保留特定 prompt 中孤立的远端信息。HeadWiseKV 对此的回应是“多级窗口+校准已足够好”，但并不是应对“prompt 特异长尾依赖”的通用解。
- **SeqCalib 非全局最优**：虽然 layerwise 条件化更贴近部署，但“逐层贪心 + 局部阈值”并不能保证联合最优的分配矩阵。
- **校准数据代表性**：依赖来自 WikiText-103 的有限校准段；目标分布一变，需要重新验证甚至重新校准。
- **需要知道完整层与 GQA 映射信息**：运行时需要 backend 暴露物理 KV 头与 query head 的映射关系、支持不同窗口分组，工程实现门槛较纯 mask 方法高。
- **τ 和 W 等超参需要人工选定**，且没有自动化选择机制。

#### 8.2 实验与分析
- **模型样本量有限**：只测了 4 个混合模型，含 1 个 Gemma 和 3 个 Qwen-family 模型，模型族多样性不够；对 Qwen 系权重基本是夸家族验证。
- **系统测量仅限单卡（RTX 4090 D）**，batch size/调度固定；不代表多卡、高并发生产环境的结论。
- **聚合分数掩盖离散错误模式**：论文自己也承认 aggregate scores 不能支持 per-example 配对的不确定性分析。
- **基线对照不完全公平**：尽管双方都有说明，但不同方法由于 cache lifecycle 与实现差异，在相等“预算”下做绝对吞吐/显存比较仍可能偏向某一种实现；如 StreamingLLM 与 DuoAttention 属于 adapted 控制，不一定等价于各自原论文的系统行为。
- **未覆盖 KV cache 量化与其他正交压缩技术的组合效果**，实际部署中往往同时做量化。

#### 8.3 可能的应用风险
- 模型、cache format 或目标上下文长度一旦变化，离线策略需要重新校准——在实际频繁更新模型的服务场景中会产生额外运维负担。
- 对任务质量影响较难预估：某些任务上（如 LoCoMo 的部分模型）会出现 2 分左右的掉点，论文建议在部署前做目标 workload 的验证。
