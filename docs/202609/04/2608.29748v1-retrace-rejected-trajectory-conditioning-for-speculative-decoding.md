## 摘要
投机解码通过让轻量级草稿模型提出多个候选词元，再由更大的目标模型并行验证，从而加速自回归语言模型推理。然而，在第一次拒绝后，标准的基于前缀的验证会丢弃剩余的草稿后缀，导致在这些位置上生成和验证所花费的计算无助于解码进度。我们聚焦于DFlash，表明被拒绝后缀中的被拒绝位置仍可能对齐目标延续，这说明草稿模型尽管存在局部词元级错误，仍能保留有用的语义与结构信息。受此观察启发，并结合条件扩散思想，我们提出了ReTrace——一种拒绝轨迹条件化方法，它使每个草稿块基于上一轮被拒绝的后缀进行条件化，而非仅从新的掩码占位符生成。ReTrace保留被拒绝后缀的隐藏表示，将它们与下一草稿块对齐，利用同一验证过程中目标感知的校正信号进行细化，并通过门控残差融合将其纳入草稿模型的输入嵌入。由于被拒绝词元从不被提交，目标端验证也保持不变，ReTrace在无需额外模型前向传递的情况下保留了投机解码的无损性质。使用Qwen3模型在数学推理、代码生成和开放式对话上的实验表明，与DFlash骨干相比，ReTrace持续提高了平均接受长度和端到端解码速度。通过在不修改轮内提案生成的前提下引入跨轮条件化，ReTrace与现有草稿改进方法大体正交，并可与它们结合以获得进一步收益。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

## 一、核心问题与研究动机

投机解码（Speculative Decoding）通过"轻量草稿模型提出候选 + 目标大模型并行验证"的范式，显著减少了串行解码中昂贵的目标模型前向传播次数。然而，在该范式中存在一个**根本性的计算浪费问题**：

- 标准前缀验证在**第一个不匹配位置**即终止，剩余草稿后缀（rejected suffix）及其隐藏表示被直接丢弃；
- 这些位置已消耗的草稿生成与目标验证计算**未能转化为解码进展**；
- 例如在图 1 的 MT-Bench 示例中，尽管存在局部词元错误，被拒绝的后续草稿位置实际上可能重新与目标延续对齐（realign）。

本文核心发问：**被拒绝的计算是否仍保留关于目标延续的信息？能否将其复用于下一轮草稿的条件生成？**

作者以 DFlash 为代表研究该问题，原因在于：
- DFlash 的并行块扩散机制中，后续位置并非由前序采样词元自回归生成，**局部拒绝不会彻底污染后续状态**；
- DFlash 生成单一较深块，拒绝后留下的隐藏序列在位置上与后续草稿位置天然对齐，便于跨轮复用。

通过定性与定量分析，作者发现被拒绝后缀确实保留有效预测信号（token 级与表示级），由此提出 **ReTrace 方法**。

## 二、方法论

### 2.1 核心思想

ReTrace 的核心是引入**跨轮条件化（cross-round conditioning）**：不再丢弃上一轮被拒绝后缀的隐藏表示，而是将其**对齐**到下一草稿块位置，经**目标感知校正（target-aware correction）** 精炼后，通过**门控残差融合（gated residual fusion）** 注入草稿模型的输入嵌入中。

关键性质：被拒绝词元从不提交、目标端验证不变、不增加额外前向传递，因此**保持投机解码的无损性**。

### 2.2 关键技术细节

#### (1) 拒绝轨迹的构造与对齐

第 t 轮草稿块产出表示集合 $\{h^D_{t,1},...,h^D_{t,B}\}$。若接受长度 $A_t < B$，首个拒绝位置为 $r_t = A_t+1$。ReTrace 仅保留首个拒绝位置**之后**的部分：

$$\{h^D_{t,r_t+1}, h^D_{t,r_t+2}, ..., h^D_{t,B}\}$$

对齐到下一轮提案位置的方式为（式 5）：

$$m_{t+1,j} = \begin{cases} h^D_{t,r_t+j}, & 1 \le j \le B - r_t \\ 0, & B - r_t < j \le B \end{cases}$$

即保持原顺序移到下一块开头；无剩余信号时退化为原始 DFlash 流程。

#### (2) 目标感知校正

利用验证阶段已产生的目标表示提供互补信息（式 6-8）：

$$u_{t+1,j} = h^T_{t,r_t+j-1}$$

通过轻量投影与残差更新：

$$c_{t+1,j} = W_c [m_{t+1,j}; u_{t+1,j}]$$
$$r_{t+1,j} = m_{t+1,j} + \beta \cdot c_{t+1,j}$$

其中 $\beta$ 在早期训练阶段线性 warmup（50 步内增至 1.0），保证优化稳定性。

#### (3) 门控残差融合

将校正信号作为残差、经**向量级门控**注入（式 9）：

$$\tilde{e}_{t+1,j} = e_{t+1,j} + W_v r_{t+1,j} \odot \sigma(W_g [e_{t+1,j}; r_{t+1,j}])$$

- $W_v$ 零初始化保证起始行为与原始草稿一致；
- 门控按隐藏维度选择性放行信号；
- 锚点位置及无对应信号位置保持原始输入。

#### (4) 训练与推理

- 训练：缓存表示在轮间 **detach**，仅用当前轮预测损失联合优化草稿骨干、校正模块与门控注入模块；目标模型冻结；
- 推理：所有信号均来自标准草稿与验证过程的既有表示，**零额外目标前向**，信号仅存活一轮即被替换。

## 七、方法亮点与优势

1. **问题视角新颖**：将"被拒绝的计算"从浪费转化为条件信号，提出了投机解码中的**计算复用**新方向，与关注轮内草稿改进的现有工作形成互补；
2. **无损且零额外前向**：所有条件信号均来自既有的草稿与验证表示，目标端验证过程完全未被修改，保守了投机解码的理论保证；
3. **设计细致**：
   - 排除已解决的接受前缀与修正词元位置，避免冗余/冲突信号；
   - 目标感知校正同时使用草稿端与目标端信息，而无需额外的目标前向；
   - 向量门控 + 零初始化保证训练稳定起步，不干扰原始合理行为；
   - 保留一个轮次的短生命周期条件信号，避免误差跨轮累积；
4. **训练启发式合理**：β warmup 与零初始化 $W_v$ 协同，降低联合训练难度；
5. **部署考虑充分**：附录包含并发服务测试与低秩部署变体（rank-64 潜变量、rank-32 校正），增强了实用性与生产可用性论证。

## 八、不足与局限性

1. **理论分析欠缺**：仅凭经验观察说明被拒绝后缀"保留有用信息"，缺乏对其成立条件、为何在 DFlash 上有效而可能在其他架构上失效的机理性分析或形式化刻画；
2. **架构普适性不足**：仅在 Qwen3 × DFlash 组合上验证，"条件化 + 目标感知校正"中的拼接连结（concatenation）对隐藏维度翻倍引入的显存/计算开销在更大模型上如何扩展未做讨论；
3. **公平性局限**：与 EAGLE-3 对比时，EAGLE-3 需要较大的候选树才能更好发挥（表 2 中增大树大小从 16→60 增益明显），而 ReTrace 只验证了块大小 16，更高块大小下的表现（以及校正模块的扩展性）未知；
4. **实验的单轮性**：训练与评测主要在单类数据混合上进行，未见跨领域迁移或不同数据规模/质量下的敏感性分析；
5. **缺少与其他复用方法的直接对比**：相关工作部分提及 Lyanna（Make Every Draft Count）与 Token Recycling，但实验部分并未与这些计算复用方法进行直接基准对比，削弱了对该子领域内"最优复用策略"判断的支撑；
6. **附录披露的具体局限**：正文未展开讨论"全接受或拒绝发生在末位时条件信号重置"对长的连续接受序列（多个完整块全部被接受）情况下潜在收益上限的影响。

## 总结

ReTrace 提出了一个概念清晰、工程上轻量且与现有草稿改进正交的投机解码增强机制——将上一轮被拒绝后缀的隐藏表示经目标感知校正后作为下一轮草稿的条件输入。通过在 Qwen3-4B/8B 上 7 个基准、两种解码温度下的系统实验，验证了该机制在平均接受长度与端到端加速上的一致性提升。其独特价值在于：重塑了对投机解码中"失败计算"的理解——被拒绝的轨迹不必是噪声，而可以成为引导下一轮提案的信息资源。
