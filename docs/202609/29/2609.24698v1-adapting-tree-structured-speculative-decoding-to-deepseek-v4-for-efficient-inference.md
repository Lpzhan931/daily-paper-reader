## 摘要
在自回归解码过程中反复执行目标模型是大语言模型推理延迟的主要来源之一。与沿单一候选链进行的线性推测不同，树结构推测会保留来自共享前缀的多条分支；在相同预算下，这种更广的覆盖范围可以提升接受率与效率。将其适配到 DeepSeek-V4 并非易事：其 CSA/HCA 在线压缩注意力将难点集中在目标验证侧，从共享前缀分出的分支会被压缩成不同状态，从而破坏跨分支状态一致性。我们通过分支感知因果验证、临时状态隔离以及接受路径状态刷新，将树结构推测解码集成到 DeepSeek-V4-Flash 流水线中，使各分支间的验证与压缩状态更新保持一致。在预算 D=5 到 D=8、批大小 1 到 64 以及三个数据集（GSM8K、MBPP、ShareGPT）上，树结构推测在所有设置下均比匹配的线性配置取得更高的接受长度（例如在 D=8 时约为 2.83--3.41，对比 2.39--2.84），并在几乎所有配置下提升吞吐量——仅在最小预算下提升有限——最高约 18.5%。更重要的是，这些增益遵循稳定且可迁移的规律：相对增益随预算增长而增大，并且在中小批大小下对可预测性较低的工作负载最为显著；而超过某一预算后，吞吐量趋于平台期，并与仍在上升的接受长度脱钩。这些结果表明，在相同预算下保留多条候选路径可以有效提升 DeepSeek-V4 的解码效率，并为将推测解码适配到未来具有压缩、稀疏或结构化上下文表示的模型提供了经验。

## Abstract
Repeated execution of the target model during autoregressive decoding is a major source of LLM inference latency. Unlike linear speculation, which follows a single candidate chain, tree-structured speculation retains multiple branches from shared prefixes; under the same budget, this broader coverage can improve acceptance and efficiency. Adapting it to DeepSeek-V4 is nontrivial: its CSA/HCA online compressed attention concentrates the difficulty on the target-verify side, where branches diverging from a shared prefix compress into different states, breaking cross-branch state consistency. We integrate tree-structured speculative decoding into the DeepSeek-V4-Flash pipeline via branch-aware causal verification, temporary state isolation, and accepted-path state refresh, keeping verification and compressed-state updates consistent across branches. Across budgets D=5 to D=8, batch sizes 1 to 64, and three datasets (GSM8K, MBPP, ShareGPT), tree speculation achieves a higher accepted length than the matched linear configurations in all settings (e.g., at D=8 about 2.83--3.41 versus 2.39--2.84) and improves throughput in nearly all configurations---marginal only at the smallest budget---by up to about 18.5%. More importantly, the gains follow stable, transferable regularities: the relative gain grows with the budget and is most pronounced for less predictable workloads at small-to-medium batch sizes, while beyond a certain budget throughput plateaus and decouples from the still-rising accepted length. These results show that retaining multiple candidate paths under the same budget can effectively improve DeepSeek-V4 decoding efficiency, and offer experience for adapting speculative decoding to future models with compressed, sparse, or structured context representations.

# 论文总结：将树结构推测解码适配到 DeepSeek-V4

## 1. 核心问题与整体含义

- **研究动机**：自回归解码需要目标模型为每个新 token 反复执行前向计算，是 LLM 推理延迟的主要来源；长上下文模型因注意力与上下文管理成本更高，该问题更突出。
- **背景**：DeepSeek-V4 通过 CSA（Compressed Sparse Attention）与 HCA（Heavily Compressed Attention）在线压缩上下文，降低存储与注意力计算量，但 token 生成仍是自回归的，目标模型重复执行仍是延迟瓶颈。
- **树结构推测的价值**：线性推测只保留单条候选链，一旦早期 draft 预测错误，后续后缀可能全部失效；树结构推测保留共享前缀下的多条候选分支，在相同验证预算下扩大候选覆盖，有望提升接受长度与效率。
- **核心难题**：DeepSeek-V4 的 CSA/HCA 不是在每个 token 上维护独立 KV，而是沿序列维度在线构建压缩表示。树推测中不同分支从共享前缀分叉后会压缩成不同状态，导致跨分支状态不一致。难点不在构建候选树，而在目标验证侧保持树推测语义与压缩状态一致性。
- **整体含义**：该工作不仅是一次工程适配，也为未来具有压缩、稀疏、分层或结构化上下文表示的模型如何适配推测解码提供了可迁移经验。

## 2. 方法论

- **核心思想**：在 EAGLE-3/MTP 风格的自回归推测解码框架下，将线性候选链替换为树结构候选，并针对 DeepSeek-V4 的 CSA/HCA 在线压缩注意力，在目标验证侧保证分支因果可见性、临时状态隔离和接受路径状态刷新。
- **三阶段推测前向流程**：
  - **Draft extend**：从已接受前缀扩展出候选分支，组织为候选树；树形状由 draft 输出、分支参数和验证 token 预算决定。
  - **Draft decode**：在树拓扑下计算 draft 侧表示，每个候选 token 只沿其祖先路径进行因果注意；DeepSeek-V4 的 FlashMLA/注意力路径已提供树注意力支持，适配主要提供候选布局和注意力元数据。
  - **Target verify**：验证候选分支并选择接受路径。验证前通过 verify preprocess 将候选树转换为验证计划，描述候选链提取方式、注意力与压缩边界；共享前缀可复用前缀状态，分叉后的分支必须独立压缩，避免混合互斥序列历史。
- **分支感知因果验证**：不同分支的物理批内顺序不再反映逻辑依赖，目标模型必须保留树拓扑，使每个候选只关注已接受上下文和自身祖先，而不关注无关分支。
- **临时状态隔离**：
  - 验证完成前所有分支都是临时的，中间结果不能影响其他分支或已接受状态。
  - 使用 scratch pad 存储临时分支状态，避免 speculative 分支直接写入持久 KV cache。
  - 对 DeepSeek-V4 的页式 KV cache pool，直接写入多分支会复杂化页分配、状态归属和分支回收，因此临时存储是必要的。
- **接受路径状态刷新**：
  - 验证后系统选择一条具体接受路径，只保留该路径相关状态，丢弃拒绝分支。
  - 刷新内容包括 token 历史、KV 状态、CSA/HCA 压缩状态及相关压缩中间缓冲区，使 token 历史、注意力 cache 与压缩状态都对应同一逻辑前缀。
- **性能优化**：
  - scratch-pad 执行减少持久 cache 流量；若只有单候选链或接受链已是最新缓存链，可跳过刷新。
  - C4 与 C128 使用不同刷新调度：C4 压缩频繁需及时更新；C128 压缩较少，可延迟并合并部分 cache 写入。
  - 设备侧元数据处理：候选索引、链边界、验证计划元数据尽量在 device 上准备，减少 host 控制开销，实现 host 调度、GPU 元数据处理和目标模型执行的重叠。
  - CUDA Graph 覆盖范围受候选树配置限制，需覆盖常见树形状且避免未用图容量造成显存浪费。
  - draft 侧候选布局和元数据尽量复用于目标验证。
- **SGLang 集成**：完整流程作为一个 speculative forward，包含 draft extend、draft decode、verify preprocess、target verify、accepted-path selection、状态刷新，再返回 SGLang 推理流水线开始下一轮解码。
- **说明**：论文未给出显式数学公式或算法伪代码，主要以系统流程和工程机制描述方法。

## 6. 主要结论与发现

- **接受长度全面优于线性**：所有预算、批大小和数据集上，树配置接受长度均高于匹配线性配置。D=8 时约 2.83–3.41，线性约 2.39–2.84。
- **吞吐提升**：多数配置吞吐为正收益，仅 D=5 最小预算附近接近持平或略负；最高约 **18.5%** 提升，出现在 ShareGPT、`s3_k2_d6`、bs=4。
- **相对增益随预算增长**：树相对线性的接受长度提升从 D=5 约 +11.0% 升至 D=6 +14.4%、D=7 +17.1%、D=8 +18.6%。线性基线随预算几乎不变，增益主要来自树侧。
- **接受长度对批大小几乎不变**：固定配置和数据集下，bs=1 到 64 波动小于 0.04；吞吐的批大小依赖是执行层效应，不是接受效应。
- **加深链收益有限，加宽树更有效**：固定预算下“浅而宽”与“深而窄”接受长度差约 2%，说明当前 draft 模型长链可靠性不足，树通过同预算内保留更多分支提高接受上限。
- **任务可预测性影响绝对值，但相对增益差异不大**：绝对接受长度 GSM8K > MBPP > ShareGPT；相对增益三类任务接近，MBPP 最低，GSM8K 与 ShareGPT 相当。
- **吞吐与接受长度在高预算后脱钩**：吞吐增益随 D 增长后在 D≈6–7 后趋于平台，约 +9–10%；接受长度仍上升，但额外接受收益被树执行固定开销抵消。
- **批大小呈倒 U 形**：吞吐增益在中小 batch 达到峰值，约 bs=4，向 bs=64 衰减。小 batch 下解码 memory-bound，接受更多 token 直接减少目标前向；大 batch 下目标前向 compute-bound，额外候选争用算力。
- **最不可预测工作负载收益最大**：ShareGPT 吞吐增益最高，符合“单链最容易早期失败处，树宽度回收浪费最多”的解释。
- **与 draft 侧方案正交**：树推测改进验证侧，DSpark 等改进 draft 侧，两者不冲突，可组合。
- **适用条件**：draft 接受能力成为瓶颈，且目标侧能廉价验证树；压缩注意力下跨分支状态发散使目标验证成本更高，但该范式在 DeepSeek-V4.1-Flash 中延续，因此目标验证侧适配仍有价值。
