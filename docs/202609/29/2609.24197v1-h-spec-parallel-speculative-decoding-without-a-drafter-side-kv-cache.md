## 摘要
推测解码通过让轻量级草稿模型预测未来 token 并由目标模型验证，从而无损加速大语言模型推理。近期的块扩散草稿模型通过并行预测多个 token 进一步降低了草稿延迟。然而，现有块草稿模型会将每个输入位置的目标隐藏状态投影到单独的草稿模型侧 KV 缓存中，带来随并发量增长的每请求内存与 KV 写入开销；直接原地复用目标 KV 虽可消除该缓存，却无法在整个块内维持草稿质量。我们提出一种混合目标上下文注入方法，在直接复用目标 KV 的基础上，仅在最后一个输入位置补充目标隐藏状态，从而无需单独的草稿模型侧 KV 缓存。基于该设计，我们提出 H-Spec，一种混合 Mamba-注意力并行草稿器，通过互补模块消费这两类目标上下文来源。Mamba 模块以投影后的末 token 目标隐藏状态初始化，而注意力模块则原地复用目标 KV。尽管 Mamba 采用循环形式，其并行扫描使 H-Spec 仍能保持块并行草稿。在三个目标模型和多样任务上，H-Spec 相比最佳基线将平均接受长度提升 5.0--13.3%，将 batch size 为 1 时的 token 间延迟加速比提升 5.3--12.6%。在并发服务下，H-Spec 在所评估的各并发水平上始终实现更高吞吐量，同时保持比基线更低的 KV 缓存利用率。

## Abstract
Speculative decoding losslessly accelerates large language model inference by having a lightweight draft model predict future tokens for verification by the target model. Recent block diffusion drafters further reduce drafting latency by predicting multiple tokens in parallel. However, existing block drafters project target hidden states at every input position into a separate drafter-side KV cache, incurring per-request memory and KV-write overhead that grow with concurrency; directly reusing target KVs in place removes this cache but fails to sustain draft quality throughout the block. We propose a hybrid target-context injection method that complements direct target KV reuse with target hidden states only at the last input position, requiring no separate drafter-side KV cache. Building on this design, we propose H-Spec, a hybrid Mamba-attention parallel drafter that consumes the two target-context sources through complementary modules. Mamba modules are initialized with projected last-token target hidden states, while attention modules reuse target KVs in place. Despite its recurrent formulation, Mamba's parallel scan allows H-Spec to preserve block-parallel drafting. Across three target models and diverse tasks, H-Spec improves over the best baseline by 5.0--13.3% in mean accepted length and 5.3--12.6% in batch-size-1 inter-token latency speedup. Under concurrent serving, H-Spec consistently achieves higher throughput while maintaining lower KV cache utilization than baselines across evaluated concurrency levels.

- **背景**：推测解码通过轻量草稿模型预测未来 token、目标模型并行验证来无损加速 LLM 推理；块扩散草稿器可并行预测多个 token，进一步降低草稿延迟。
- **核心问题**：现有块扩散草稿器依赖 KV 注入，将每个输入位置的目标隐藏状态投影为独立的草稿端 KV 缓存。该缓存带来随并发请求增长的显存与 KV 写入开销；若直接原地复用目标 KV，又会在块内后续草稿位置显著降低接受率。
- **整体含义**：论文提出一种无需草稿端 KV 缓存的并行草稿方案，试图在保持目标模型条件注入质量的同时，改善高并发服务下的吞吐与显存效率。

## 2. 方法论
- **核心思想**：混合目标上下文注入——直接原地复用目标 KV，并仅在最后一个输入位置补充目标隐藏状态。前者提供细粒度位置信息，后者在因果注意力下汇总整个前缀，且存储开销为 O(1)。
- **H-Spec 架构**：混合 Mamba-注意力并行草稿器，分别消费两类上下文。
  - **Mamba 模块**：以投影后的末 token 目标隐藏状态初始化循环状态。跨选定目标层融合末 token 隐藏状态，经 `Proj_r` 与 `Proj_dS` 得到 Mamba-2 初始状态；权重跨草稿层共享，每 forward 只计算一次。
  - **注意力模块**：原地复用目标 KV，匹配目标模型的 KV 维度与头数；每层注意力消费某一目标层的 KV；采用因果注意力、2048 token 滑动窗口注意力，并用与目标前缀连续的位置索引和 RoPE 对齐。
  - **并行性**：Mamba 虽为循环形式，但其线性状态递推可用并行扫描并行计算所有草稿位置，从而保持块级并行草稿。
  - **因果校正**：在混合骨干后接 DSpark 的 Markov head，增强相邻位置依赖；论文声明该部分不是其贡献。
- **配置**：为匹配 5 层 DFlash/DSpark 参数量，H-Spec 使用 4 层：3 个完整 Mamba-attention-MLP 层 + 1 个部分 Mamba-MLP 层；Mamba head dim 64，state dim/groups/conv kernel 为 4，expansion 为 1，head 数按目标模型调整。

## 7. 优点
- **系统视角明确**：识别草稿端 KV 缓存为并发服务中的可避免瓶颈，并以 O(1) 末 token 隐藏状态 + 原地 KV 复用消除该缓存。
- **架构设计合理**：Mamba 初始状态与末 token 全前缀摘要天然匹配，注意力模块与目标 KV 位置级信息互补，且 Mamba 并行扫描保持块并行。
- **实验较全面**：覆盖 3 个目标模型、8/9 个任务、服务负载、消融、敏感性和零样本迁移，并使用 bootstrap 置信区间。

- **服务评估有价值**：不仅报告单请求速度，还强调并发吞吐与 KV 利用率，符合实际部署关注点。
