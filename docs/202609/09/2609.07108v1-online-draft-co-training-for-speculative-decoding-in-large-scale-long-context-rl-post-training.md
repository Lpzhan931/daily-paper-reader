## 摘要
投机解码加速了推理解码，而推理解码在强化学习后训练中占主导成本。在线协同训练可以进一步提高草稿模型的准确性，带来更大的加速。然而，将这种方法扩展到大型模型的长上下文协同训练面临两个障碍：（1）标准因果上下文并行实现不支持分支注意力，（2）目标特征跨流水线并行阶段。我们通过一个端到端系统来解决这两个问题，实现大规模在线草稿协同训练。对于上下文并行，我们通过合并排名局部分支注意力与因果主序列注意力，扩展了打包、负载均衡的锯齿形环注意力。对于流水线并行，TapChannel通过独立路径跨阶段传输中间目标特征，不影响流水线调度。实验表明，协同训练的草稿模型与策略基线保持一致，同时在不同规模（最高122B参数）的模型上实现了显著的推理解码和端到端加速。我们的上下文并行设计在256K token下实现了强扩展性，并相比先前工作大幅节省了内存，而我们的流水线并行传输开销适中。代码可在 https://github.com/NVIDIA-NeMo/RL/issues/3698 获取。

## Abstract
Speculative decoding accelerates rollout generation, which dominates the cost of reinforcement learning (RL) post-training. Online co-training can further increase the draft's accuracy, yielding greater speedups. However, scaling this approach to co-training on large models with long contexts poses two obstacles: (1) branch attention is unsupported by standard causal context-parallel (CP) implementations, and (2) target features span across pipeline-parallel (PP) stages. We address both with an end-to-end system for large-scale online draft co-training. For CP, we extend packed, load-balanced zigzag ring attention by merging rank-local branch attention with causal main-sequence attention. For PP, TapChannel transports intermediate target features across stages via a separate path, leaving the pipeline schedule unaffected. Experiments demonstrate that co-trained drafts closely track the policy baseline while delivering substantial rollout and end-to-end speedups across model scales up to 122B. Our CP design achieves strong scaling at 256K tokens with significant memory savings over prior work, and our PP transport incurs modest overhead. Code can be found at https://github.com/NVIDIA-NeMo/RL/issues/3698.

## 一、核心问题与研究动机

### 问题背景

- **RL后训练成本瓶颈**：强化学习（RL）后训练已成为构建推理与智能体大语言模型（LLM）的标准范式，而rollout生成占据了RL后训练的绝大部分墙钟时间。
- **投机解码的加速作用**：投机解码（Speculative Decoding, SD）通过一个小型草稿模型（draft model）生成多个候选token，再由目标策略模型并行验证，可在不改变输出分布的前提下加速自回归生成。
- **在线协同训练的挑战**：随着RL策略不断演化，固定草稿模型会逐渐失去对齐性。在线协同训练（online co-training）可以让草稿模型随策略同步更新，保持高接受率。但当扩展到**大型模型 + 长上下文**场景时，存在两大关键障碍：
  - **分支注意力不受CP支持**：EAGLE-3、DFlash、DSpark等先进草稿架构引入了分支结构注意力（branch-structured attention），标准因果上下文并行（Context Parallelism, CP）实现无法直接支持。
  - **目标特征跨PP阶段**：这些草稿模型依赖目标模型的中间隐藏状态（taps），但在流水线并行（Pipeline Parallelism, PP）下，产生这些特征的层可能位于与草稿模型所在阶段不相邻的其他PP阶段。

### 核心目标

在不改变目标策略模型已有并行拓扑（CP/PP）的前提下，设计一套端到端系统，使得**大规模、长上下文RL后训练中的在线草稿协同训练**成为可能，从而在保持RL学习轨迹的同时，获得rollout与端到端训练加速。

## 二、方法论

### 2.1 在线协同训练目标

$$L(\theta, \phi) = L_{RL}(\theta) + \lambda L_{draft}(\phi; x, \text{sg}(H_\theta(x)))$$

- $\theta$ 为策略参数，$\phi$ 为草稿参数；
- 草稿与策略在同一批rollout token上训练，目标特征 $H_\theta$ 施加**停止梯度**（stop-gradient）；
- 草稿模型作为策略最后一个PP阶段上的子模块实例化，随策略模型联合更新。

### 2.2 机制一：CP下的分支注意力

**核心思想：将分支注意力分解为两个独立部分，分别计算后合并。**

每个分支查询（query）需要关注两组键：

1. **主序列的因果前缀**（causal prefix of the main sequence）——按zigzag方式跨CP rank分片；
2. **分支本地键**（branch-local keys）——保存在拥有该分支锚点（anchor）的rank上，无需跨rank通信。

**关键步骤：**
- 主序列组件沿用打包（packed）、负载均衡的**zigzag环注意力**（standard CP）处理方式；
- 在每一步环通信中，主序列K/V在各rank间轮转，查询保持本地驻留；
- 分支本地组件在所属rank上直接计算，无需通信；
- 两个部分的注意力结果通过**在线softmax归并（online-softmax merge）**完成合成：

$$\ell = \log(e^{\ell_m} + e^{\ell_b}), \quad O = e^{\ell_m - \ell} O_m + e^{\ell_b - \ell} O_b$$

其中 $(O_m, \ell_m)$ 与 $(O_b, \ell_b)$ 分别对应主序列与分支组件的输出和 log-sum-exp。

**支持范围**：该方法统一支持 EAGLE-3（TTT多步分支）、DFlash（块级分支）和 DSpark（马尔可夫头扩展）三类草稿架构，因为它们都共享同一核心需求——分支位置需要同时关注主序列因果前缀和分支本地KV上下文。

**通信成本**：前向环中每个rank输出量为 $V_{fwd}^{CP} = 2(C-1)(N/C)d_{kv}b$，分支本地K/V留在所属rank上，故通信成本**与分支数量或深度无关**。通信与注意力在环步粒度上重叠。

### 2.3 机制二：PP下的TapChannel 跨阶段特征传输

**问题**：产生taps（中间目标特征）的层横跨多个PP阶段，而草稿仅存在于最后一个PP阶段。标准流水线通信仅连接相邻阶段，无法送达非相邻特征。

**TapChannel设计：**
- 在草稿所在阶段为每个源阶段（source stage）设置**预分配的邮箱槽位**（mailbox slot）；
- 源阶段完成某个microbatch的策略前向后，将taps写入自己的槽位；草稿阶段在同一microbatch前向之前读取该槽位；
- **同步机制**：每个槽位携带一个序列戳（sequence stamp），源阶段写入与草稿阶段读取时均递增该戳以协调生产-消费关系；
- 同节点源使用CUDA IPC；跨节点源使用专用NCCL通信器（GPUDirect RDMA）；
- TapChannel走**独立于正常流水线调度的旁路**（side path），不给pipeline增加额外通信步骤。

**开销建模**：每microbatch传输负载为 $V_{Tap} = bn\sum_{s \in S} d_s$，每个特征只直接传输一次，与PP跳数无关。流水线调度天然提供了源阶段产出tap到草稿阶段前向之间的**闲置窗口（slack window）**，若传输在此窗口内完成，则无额外延迟。残留会合延迟为 $E_{Tap}^{(m)} = \max_{s \in S}\max(\tau_{s,m}, \Delta_{s,m})$（取传输时间与闲置窗口的实际暴露部分）。

## 六、主要结论

1. **策略学习轨迹保持**：无论使用EAGLE-3、DFlash还是DSpark，协同训练运行在奖励、AIME准确率和训练-推理KL散度上均紧贴基线轨迹，确认投机解码和协同训练不改变RL学习动态。
2. **加速效果显著**：协同训练的草稿达到2.28–4.78的接受长度，产生1.19–2.23×的rollout加速和1.16–1.88×的端到端训练加速。
3. **草稿架构差异**：DFlash与DSpark在数学任务上始终优于EAGLE-3的接受长度，但在多轮智能体任务中差异缩小。
4. **大规模MoE目标中端到端收益受限**：Qwen3.5-122B-A10B与GPT-OSS-120B接受长度虽高，但端到端加速较低（1.19–1.35×），一次验证前向需要路由更多的专家计算。线性注意力模型的验证前向本身更廉价，投机带来的相对加速也天然更小。
5. **CP性能大幅领先**：packed zigzag环注意力在相同工作负载下比USP延迟降低1.5–2.9×，每GPU峰值内存降低2.7×，且在256K长序列下实现近线性扩展（CP=8时94%并行效率，7.5×加速）。
6. **TapChannel开销适中**：块级草稿（DFlash/DSpark）在线协同训练增加的时间开销低于15%，EAGLE-3约34%（TTT多次前向导致），但草稿阶段等待taps的时间仅占策略更新时间的1.5–2.2%，传输与流水线调度充分重叠。T aptChannel单边写相较host staging快4.5–8.5×，源阶段计算干扰在噪声范围内，接收端仅1.6%的HBM竞争。

## 七、方法亮点与贡献

1. **新颖的CP分支注意力分解思路**：将分支注意力分解为主序列因果部分（跨rank环通信）+分支本地部分（rank本地存储），通过在线softmax归并恢复完整注意力输出。这种设计使通信成本与分支数量、深度**无关**，且充分利用长上下文下注意力计算量随序列长度二次增长而通信量线性增长的天然重叠优势。
2. **旁路特征传输（TapChannel）的工程优雅性**：完全不动pipeline调度，不增加管道通信步数，利用现有调度中天然存在的闲置窗口隐藏传输时间。每个特征只传输一次，与PP跳数无关。
3. **面向大规模RL的系统级整合**：实验全部在NeMo-RL中完成，覆盖同步异步RL（GRPO），保持现有TP/PP/CP/EP并行拓扑不变——与"为草稿训练修改并行布局"的先前工作形成关键差异，工程实用性更强。
4. **支持多草稿家族的端到端统一系统**：EAGLE-3、DFlash、DSpark三类不同的草稿架构共用同一套CP/PP扩展机制，显示了系统设计的普适性。

7. **分支注意力通信分析中理论与实际场景存在部分脱节**：论文公式（4）中关于通信暴露时间为 $\max(t_{comm}^{(r)}, t_{attn}^{(r)})$ 的分析忽略了在不同注意力实现（如Flash Attention变体）下计算与通信重叠粒度的实际差异。

## 总结

该论文解决了大规模、长上下文RL后训练中投机解码在线协同训练的两个关键系统障碍（CP分支注意力和PP跨阶段特征传输），提出了打包zigzag环注意力的分解与合并机制及TapChannel旁路传输通道，提供了一个端到端的支持系统。实验结果覆盖多种草稿架构、目标模型规模（8B~122B）以及单轮/多轮任务场景，验证了协同训练保持RL学习轨迹的同时能带来实际有效的端到端加速。虽在超参数讨论、MoE/线性注意力适配、算力透明度方面存在改进空间，但其方法论的通用性与系统实现的完备性构成了对大规模RL训练基础设施的重要贡献。
