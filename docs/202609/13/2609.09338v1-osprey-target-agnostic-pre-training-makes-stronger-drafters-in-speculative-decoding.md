## 摘要
投机解码对于加速 LLM 推理至关重要。然而，这种加速并不稳健：草稿模型通常针对单个目标模型的狭窄分布进行训练，其接受率在工作负载发生变化时会急剧下降。这与现代 LLM 开发形成了鲜明反差：目标模型之所以受到重视，恰恰在于它们通过大规模预训练获得了广泛的泛化能力。我们认为，自然的补救措施——预训练——一直难以应用于草稿模型，因为现有方案都是目标特定的：草稿模型会消耗目标的隐藏状态，并基于目标的 logits 进行蒸馏，因此必须为每个目标重复进行预训练。我们提出 Osprey，它转而从现成的预训练小语言模型出发来引导草稿模型的构建，将广泛的预训练视为一种可复用、目标无关的资产，并将针对每个目标的工作缩减为一个轻量级适配步骤。实现这一点需要克服两个挑战：小语言模型的深度远超受延迟约束的草稿模型所能承受的范围，并且它们的预训练计算必须在草稿模型学会接收目标隐藏状态并以目标词表输出 token 的同时保持完整。Osprey 通过以下方式同时解决这两个问题：剪枝得到浅层骨干网络，用目标无关的下一 token 预训练恢复其语言建模能力，并通过词表对齐、零初始化的 QKV 扩展以及从目标模型输出分布中蒸馏，使其适配每个目标。实验表明，单个预训练的 Osprey 骨干网络可以跨目标迁移，并将 Qwen3-8B 的平均接受长度提升 16.1%，将 Llama-3.3-70B-Instruct 提升 21.2%，将 229B 的 MiniMax-M2.5 提升 22.7%（每秒 token 数提高 17.5%），且在域外和多语言数据上增益最大。我们的代码可在 https://github.com/LeanModels/Osprey 获取。

## Abstract
Speculative decoding is critical for accelerating LLM inference. However, the speedup is fragile: drafters are typically trained against a narrow distribution for a single target model, and their acceptance rate collapses under workload shifts. This is a striking inversion of modern LLM development, where target models are valued precisely for the broad generalization they acquire through large-scale pretraining. We argue that the natural remedy, pretraining, has been hard to apply to drafters because existing recipes are target-specific: the drafter consumes the target's hidden states and is distilled on the target's logits, so pretraining must be repeated for each target. We introduce Osprey, which instead bootstraps drafters from off-the-shelf pretrained small language models, treating broad pretraining as a reusable, target-agnostic asset and reducing per-target work to a lightweight adaptation step. Realizing this requires overcoming two challenges: small LMs are far deeper than a latency-bound drafter can afford, and their pretrained computation must remain intact while the drafter learns to ingest target hidden states and emit tokens in the target's vocabulary. Osprey addresses both by pruning to a shallow backbone, restoring its language-modeling capability with target-agnostic next-token pretraining, and adapting it to each target through vocabulary alignment, zero-initialized QKV expansion, and distillation from the target model's output distribution. Empirically, a single pretrained Osprey backbone transfers across targets and improves mean acceptance length by 16.1% for Qwen3-8B, 21.2% for Llama-3.3-70B-Instruct, and 22.7% for the 229B MiniMax-M2.5 (with 17.5% higher tokens per second), with the largest gains on out-of-domain and multilingual data. Our code is available at https://github.com/LeanModels/Osprey.

# Osprey 论文中文结构化总结

## 1. 核心问题与研究动机

- **背景**：投机解码（Speculative Decoding）是加速 LLM 推理的关键技术——轻量草稿模型提出多个候选 token，大目标模型并行验证，被接受的 token 精确符合目标分布，因而兼具加速与无损性，常用场景可获 2–5× 解码加速。
- **核心问题**：这种加速非常脆弱。草稿模型通常在特定数据分布、模型家族或部署域上训练，一旦服务负载发生迁移（如 chat→code、通用 QA→领域推理、短回答→长文本生成），接受率会急剧下降。论文用 EAGLE-3 举例：在 math 数据上训练时平均接受长度 5.06，但在 code 数据上仅 1.86。
- **深层矛盾**：目标模型通过大规模预训练获得广泛泛化能力，而加速它们的小草稿模型却继承了延迟优势、丢失了泛化能力，形成"倒置"。
- **为何难以直接预训练草稿模型**：现有 EAGLE 式方案本质是**目标特定**的——草稿模型消费目标的隐藏状态、在目标的表示空间和 logits 上蒸馏，换一个目标就要重跑一次昂贵的训练流水线，且无法直接继承现成预训练 LLM 的广泛先验。
- **论文主张**：把广泛预训练视为**可复用的、目标无关的资产**，用现成小语言模型（SLM）作为通用草稿起点，把逐目标工作缩减为轻量适配。

## 2. 方法论：Osprey 四阶段流水线

核心思想是将草稿模型构建解耦为**目标无关阶段（做一次）**与**逐目标适配阶段（每个目标重复）**。

### 阶段 1：剪枝（Pruning）
- 从现成预训练 SLM 出发，只保留其 embedding、LM head、最终归一化层以及前 N 个 transformer 块（N ∈ {1,2,3,4}）。
- 例：Qwen3-4B 保留 2 层 → 约 591M 参数；LayerSkip-Llama3.2-1B 保留 4 层 → 约 506M 参数。
- 保留 N 小是因为草稿模型自回归执行，深度直接影响加速收益。LayerSkip 这类带早退目标的模型可提供更强的初始先验。

### 阶段 2：目标无关预训练（Pretraining, off-policy）
- 用标准下一 token 预测（NTP）目标在通用语料上继续预训练，恢复剪枝后受损的语言建模能力。
- 实验用 FineWeb 的 100B token 采样、训练 5 个 epoch（约 500B token），刻意超过该规模的计算最优配比，目标是获得广泛训练的语言骨干而非最小化预训练成本。
- 产出**浅层 NTP 骨干（Shallow NTP Backbone）**，可跨目标复用。

### 阶段 3：草稿模型转换（Adaptation, 每目标）
包含三个组件：
- **多层目标隐藏状态**：沿用 EAGLE-3，取目标低/中/高三层隐藏状态拼接后投影：
  `c_t = W_c · [h_t^(ℓlow); h_t^(ℓmid); h_t^(ℓhigh)]`，作为草稿每一注意力层的输入。
- **零初始化 QKV 扩展**：草稿在位置 t 可用的是上一位置投影 `c_{t-1}`，将其与 token 侧表示 `z_t` 拼接，并用零初始化列扩展预训练 QKV 投影 `W̃_qkv = [0 | W_qkv]`。初始化时新列不起作用，即 `W̃_qkv [c_{t-1}; z_t] = W_qkv z_t`，从而**在适配起点完整保留预训练行为**，训练中再逐步学会利用目标隐藏状态。
- **词表对齐**：把 embedding 与 LM head 尺寸改为目标词表 |V_T|。对目标词表中与源词表共享的 token 直接复制预训练行；对目标独有 token，将其字符串用源分词器切分后取对应源 token 行的均值初始化。MLP、归一化等其余预训练组件无架构改动地迁移。

### 阶段 4：目标蒸馏（Distillation, on-policy）
- 冻结目标模型，采用 EAGLE-3 的 Training-Time Test（TTT）框架对齐训练与推理：输入 token 为 teacher-forced，而草稿的隐藏状态轨迹按自回归方式生成。
- 目标模型先产生 logits（蒸馏目标）与隐藏状态（草稿输入），草稿展开 K_train 步，用**折扣蒸馏损失**训练，强调靠前的草稿步：
  `L_adapt = Σ_{k=0}^{K_train-1} λ^k · CE(p_θ^(k), q_φ^(k))`，λ = 0.8。
- 所有草稿参数（预训练与新加）均参与训练。

## 3. 实验设计

### 目标模型与场景
- **Qwen3-8B**：5×5 跨域矩阵。用 chat、code、commonsense、finance、math 五个域各约 65k 问题提示，目标模型生成响应后适配草稿；在每域 512 条留出提示上评测，区分 ID（适配=评测域）与 OOD（不同域）。
- **Llama-3.3-70B-Instruct**（dense）：用目标再生成的 Open-PerfectBlend 数据适配。
- **MiniMax-M2.5**（229B MoE，FP8 服务）：用 70k 代码提示适配。

### Benchmark
- MATH-500、HUMANEVAL、LIVECODEBENCH、MT-BENCH、COMMONSENSE-EVAL。
- 多语言：MGSM（11 语言）、GLOBAL-MMLU（42 语言及 native 设置）。

### 对比方法
- **EAGLE-3**：自研复现版 + 官方 checkpoint。
- **参数量匹配的 2 层 EAGLE-3**（from-scratch），用于分离"层数/容量"与"预训练"的贡献。

- 指标：平均接受长度（AL，每验证步接受 token 数）、端到端吞吐（TPS）。

## 4. 资源与算力

- **阶段 2 预训练**：4 节点 × 8 张 NVIDIA H100 = 32 GPU（FSDP、bf16、FlashAttention-2/3、AdamW）。55k 步（≈462B token）约 95 小时，折合约 **3,040 H100-hours**；10k 步约 18 小时，**576 H100-hours**。有效全局 batch ≈ 8.39M token/步。

- **MiniMax-M2.5 适配**：4×B200，约 36 小时（**144 GPU-hours**），35k 步。
- 评测：Qwen3-8B 在单张 H100（tp=1）；MiniMax-M2.5 在 4×B200。
- 论文给出清晰的算力核算表，并强调阶段 2 仅训练约 500M 参数浅层模型、**零目标前向**，而 from-scratch 蒸馏需运行目标模型（FLOPs/token ≈ 2(N_pθ + N_qφ)），成本高出数个量级。

## 6. 主要结论与发现

- **跨域鲁棒性显著提升**：Qwen3-8B 上 Osprey 平均 AL 3.686，比 EAGLE-3 的 3.176 高 **16.1%**，在全部 25 个域对上均更优；OOD 增益（17.3%）大于 ID（12.4%），OOD/ID 保留比 0.782 > 0.750。
- **跨目标、跨家族迁移成功**：同一个由 Qwen3-4B 剪枝得到的 2 层骨干，可迁移到 Llama 家族与 MoE 架构：
  - Llama-3.3-70B：平均 AL 2.97，比复现 EAGLE-3 高 **21.2%**，比官方 checkpoint 高 27.5%；吞吐高 17.9%/22.2%。
  - MiniMax-M2.5：平均 AL 3.232，高 **22.7%**，吞吐 219.8 TPS，高 **17.5%**；在 LiveCodeBench（+50.7%）、HumanEval（+38.7%）、MATH-500（+24.6%）增益最大。
- **多语言 OOD 泛化强**：仅用代码数据适配，MGSM 上 AL 高 12.4%，Global-MMLU 高 23.8%，native 语言回答高 15.4%。
- **增益来自预训练先验而非容量**：参数量匹配的 2 层 from-scratch EAGLE-3 仅比 1 层高 0.094 AL，而 Osprey 高出 0.405 AL。
- **超参更鲁棒**：学习率降 10 倍，warm-start 仅损失 0.11 AL，from-scratch 损失 1.07 AL。
- **预训练收益快速饱和**：10k 步与 55k 步 checkpoint 下游差异仅 0.026 AL，OOD/ID 比几乎一致（0.799 vs 0.800），交叉熵从约 19 快速降到 5 nats，PPL 在约 10k 步后稳定在 37 左右。
- **成本可摊还**：MiniMax-M2.5 上每节省约 880 H100-hours/十亿生成 token，55k 步预训练成本约 3.5B token 后回本，10k 步约 0.65B token 后回本。
- **服务敏感性**：batch 增大时 AL 稳定且吞吐增益保持（batch 1 时 +24%，batch 16 时 +13%）；草稿链从 2 增到 8 时，AL 增益从 7% 扩大到 53%（EAGLE-3 在 6 token 附近饱和）；采样温度 0→1.0 下增益仍保持 41%→35%。

## 7. 优点

- **问题视角新颖**：把"草稿模型的分布脆弱性"与"预训练带来的泛化"联系起来，提出目标无关预训练作为可复用资产，是对投机解码范式的重新思考。
- **方法解耦干净**：目标无关阶段与逐目标阶段分离，单个骨干跨模型家族、跨 dense/MoE、跨分词器、跨隐藏维度复用，工程价值高。
- **零初始化 QKV 扩展设计优雅**：在适配起点保持预训练行为不变，使"预

训练先验不被破坏，属于"零成本起点"的优雅设计。

- **接口兼容性强**：草稿侧沿用 EAGLE-3 的多层隐藏状态注入与 TTT 训练框架，服务侧可复用现有 EAGLE 推理实现，落地阻力小。
- **消融体系完整**：预训练有无、预训练预算、参数量匹配、学习率、服务配置、扩散草稿扩展等层层递进，关键结论（增益来自先验而非容量）有直接证据支撑。
- **成本核算清晰**：给出 H100-hours 级别的明细与"回本 token 数"估算，让读者能自行判断收益是否值得，而非只报相对提升。
- **实用导向**：把目标无关骨干当作一次投入、多目标复用的资产，契合多模型服务商的实际部署形态。

## 8. 不足与局限

- **统计显著性不足**：作者自承大部分实验为单次运行、未做多种子，16.1%、21.2% 这类幅度虽大，但小差距（如 0.026 AL 的预算饱和结论）缺乏置信区间，说服力有限。
- **预训练成本仍不低**：55k 步需约 3,040 H100-hours，虽然相对 from-scratch 蒸馏便宜，但对中小团队仍是门槛；论文给出的"回本"依赖较高流量假设，低流量场景下摊销困难。
- **目标无关阶段仍需通用语料**：FineWeb 100B token 采样、5 epoch 的配置带有一定经验性，未系统研究语料域、规模与最终下游 AL 的关系，最优预训练配方不明。
- **剪枝策略偏简单**：仅保留前 N 层 + embedding/LM head，未探索中间层选择、层间重要性、结构重排等更细粒度的骨干构造方式。
- **词表对齐较为启发式**：目标独有 token 用源分词器切分取均值初始化，对分词差异极大的语言（如中文、阿拉伯语）是否足够未单独验证。
- **评测域与指标有限**：跨域矩阵用 5 个域、每域 512 条留出提示，规模偏小；指标集中在 AL 与吞吐，未报告任务级准确率退化情况（虽然投机解码理论上无损，但实际接受/拒绝模式对延迟分布的影响未展开）。
- **MoE 与 FP8 场景验证较浅**：MiniMax-M2.5 仅一个目标、一种服务配置，结论外推需谨慎。
- **未覆盖长上下文与结构化输出**：如长文档摘要、JSON/代码补全等对草稿链长度敏感的场景缺乏针对性实验。

## 9. 启发与思考

- **范式迁移**："通用预训练 + 轻量适配"在投机解码上复现了 LLM 本身的成功路径——把昂贵的一次性泛化投资与廉价的任务特化分离。这一思路可能推广到更广的推理加速组件，如早退头、路由预测器、KV 压缩器。
- **接受率的本质**：AL 的脆弱性并非单纯容量问题，而是分布覆盖问题。这提示未来草稿设计可把"分布鲁棒性"作为一等目标，而非只追求 ID 峰值。
- **零初始化扩展的通用性**：通过零初始化新增通道以保持起点行为不变，是一种可用于任意"预训练模型 + 新输入模态/接口"场景的通用技巧，值得在其他适配任务中借鉴。
- **成本视角**：论文把讨论从"加速比"推进到"总拥有成本（TCO）"，包括摊销周期与回本 token 数，为工程选型提供了更实用的决策框架。
- **可复用骨干的想象空间**：同一个浅层骨干跨家族、跨 dense/MoE、跨分词器复用，暗示未来可能出现"草稿模型即基础设施"的形态——社区训练一次，各方按需适配。

## 10. 一句话总结

Osprey 把草稿模型从"每个目标重训的专用件"重构为"可复用的通用预训练骨干 + 每目标轻量适配"，用目标无关的浅层 NTP 预训练注入泛化先验，再以零初始化 QKV 扩展和多层隐藏状态蒸馏完成对齐，在 Qwen3-8B、Llama-3.3-70B、MiniMax-M2.5 上取得 16%–23% 的平均接受长度提升，且增益被消融证明来自预训练先验而非参数量，为投机解码的跨域鲁棒性提供了新的解法与成本核算框架。
