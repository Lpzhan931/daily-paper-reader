## 摘要
Whisper 是一种广泛使用的语音识别编码器-解码器模型。其编码器通过一次并行前向传播读取整段语音，但解码器逐 token 写出转写文本，这主导了推理时间。推测解码可在不改变输出的前提下缩短此类循环：小型草稿模型猜测接下来若干 token，原模型在一次前向传播中验证全部猜测。我们提出 Whisper-Flash，一种基于语音识别特性的两层草稿模型：尚未写出的词早已被说出。它读取 Whisper 的编码音频与已接受的解码器状态，并在单次前向传播中提出八个 token。在完整的 LibriSpeech 测试集上，Whisper-Flash 每秒处理的音频量是贪婪解码的 3.16×/2.85×，且输出完全一致；在批大小高达 96 以及温度采样下仍保持更快。消融实验表明，对音频的直接访问最为重要。

## Abstract
Whisper is a widely used encoder-decoder model for speech recognition. Its encoder reads an utterance in one parallel pass, but its decoder writes the transcript one token at a time, which dominates inference time. Speculative decoding shortens such loops without changing their output: a small drafter guesses several upcoming tokens, and the original model verifies them all in one forward pass. We present Whisper-Flash, a two-layer drafter built on a property of speech recognition: the words still to be written have already been spoken. It reads Whisper's encoded audio and accepted decoder states and proposes eight tokens in a single forward pass. On the complete LibriSpeech test sets, Whisper-Flash processes $3.16\times/2.85\times$ as much audio per second as greedy decoding with identical outputs, and it remains faster at batch sizes up to 96 and under temperature sampling. Ablations show that direct access to the audio matters most.

- **核心洞察**：语音识别与文本生成不同——识别器尚未写出的词，实际上已经在音频中被说出并编码。因此，并行草稿模型可以直接从编码音频中“读取”未来信息，而不必完全凭空猜测。
- **整体含义**：论文提出 Whisper-Flash，利用“目标模型历史状态 + 直接音频访问”进行并行草拟，再由冻结 Whisper 验证，从而在保持输出一致的情况下显著提升吞吐。

## 2. 方法论

### 2.1 核心思想

- 使用一个两层草稿模型，在单次前向传播中并行提出 8 个候选 token。
- 草稿模型同时读取两类记忆：
  - **声学记忆**：Whisper 编码器输出 \(A=E(x)\)，通过 cross-attention 直接访问。
  - **历史记忆**：目标解码器在已接受位置上的隐藏状态，取 5 个 block 的残差流拼接并投影到草稿器宽度。
- 冻结的 Whisper 目标模型对候选块进行一次因果前向验证，接受最长匹配前缀，并在首个不匹配处输出目标模型自己的 token。

### 2.2 提议、验证与推进流程

- 设当前已生成转写为 \(y_{\le t}\)，最新已生成但尚未被目标处理的 token \(y_t\) 作为 anchor。
- 草稿器一次提出 \(K=8\) 个候选 \(\hat{y}_{t+1:t+K}\)。
- 目标模型对 anchor 和候选进行一次因果前向传播，得到每个位置的预测。
- 验证器保留与目标一致的候选前缀；若全部 K 个都一致，则额外产生一个 bonus token。
- 第一个不一致位置由目标模型自己的 token 纠正，并成为下一轮 anchor。
- 缓存回滚只保留旧 anchor 和已接受候选；拒绝位置不进入目标缓存和草稿器历史，因此 greedy 输出保持不变。
- 若剩余输出预算为 \(R\)，最多提出 \(R-1\) 个候选，保留一个位置给目标模型自己的 token。
- EOS 被接受时结束转写，不再生成 bonus。

### 2.3 草稿器结构

- 输入为 anchor embedding 后接 \(K=8\) 个可学习 mask 向量：
  \[
  X_t=[\text{Emb}(y_t), m,\dots,m]
  \]
- 每个 mask 位置独立预测自己的 token。
- 每层草稿器：
  - 块内 query 在同一 softmax 中 attend 到历史记忆和当前 block，block 内部双向可见。
  - 使用 RoPE 标记文本位置。
  - cross-attention 读取声学记忆。
  - 后接 feed-forward 更新。
- 草稿器从 Whisper 前两个解码器 block 初始化，增加 60.7M 可训练参数；编码器、目标解码器、embedding 和输出头保持冻结并共享。
- 历史特征取目标解码器第 1、8、15、22、29 个 block 的残差流，拼接为 6400 维后投影到 1280 维。
- 草稿器拥有自己的声学 key/value 投影，但共享编码器状态、token embedding 和输出头。

### 2.4 采样验证

- 温度采样时，草稿器从自身分布 \(q_i\) 采样候选。
- 验证器以概率 \(\min(1, p_i(\hat{y}_i)/q_i(\hat{y}_i))\) 接受，其中 \(p_i\) 是相同温度与 token 规则下的目标分布。
- 首次拒绝时，从归一化残差 \((p_i-q_i)_+\) 重采样。
- 全部接受后采样一个 bonus token，从而在精确算术下保持目标分布。

### 2.5 训练与推理

- 草稿器训练目标是预测 Whisper 自己的 greedy 续写，而非参考转写。
- 每条语音最多贡献 16 个 packed anchor block；每个 block 只看自己 anchor 之前的历史。
- 损失对 8 个位置使用衰减权重 \(e^{-(j-1)/4}\)，偏向早期位置，因为后续猜测只有在前面都被接受时才有意义：
  \[
  L=-\frac{\sum_{b,j}v_{bj}e^{-(j-1)/4}\log q_\theta(y_{t_b+j})}{\sum_{b,j}v_{bj}e^{-(j-1)/4}}
  \]
- checkpoint 按验证集平均接受前缀长度选择。
- 推理时使用 CUDA graphs 捕获 prefill、drafting 和验证过程；greedy 基线也使用同一图捕获目标，因此加速来自每轮发出更多 token，而非减少 kernel 启动开销。
