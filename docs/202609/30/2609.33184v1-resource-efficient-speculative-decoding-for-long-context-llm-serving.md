## 摘要
投机解码通过并行验证来自草稿模型的多个 token，减少了目标模型的顺序调用次数。然而，KV Cache 的增长限制了 GPU 内存受限情况下的长上下文服务。将 KV 卸载到 CPU 内存可以缓解这一压力。但是，现有卸载方案会在注意力计算前恢复完整的 KV 历史，未能充分利用一个验证轮次内跨查询 KV 共享带来的收益。现有并行投机解码方法还忽略了在受内存带宽限制的目标验证等待历史 KV 时闲置的 GPU 计算能力。我们提出 SpecStream，一种投机解码系统，它无需等待完整 KV 历史恢复便开始验证，并利用 KV 传输期间的计算气泡，在同一批 GPU 上进行并发草稿生成。它仅卸载目标模型已提交的历史，使候选回滚保持在 GPU 本地。每个流式传输的 KV 分块服务于该轮次中的所有查询，并通过在线 softmax 保持完整注意力。目标优先调度在资源限制下控制草稿并发执行，以约束其对目标验证的干扰。实验表明，SpecStream 在任务质量上接近 SGLang 投机解码，同时在有限 GPU 内存下支持更多并发请求。在不同数据集上，对于 Qwen3 和 InternLM2.5，它分别比卸载基线取得平均 1.41 倍和 1.32 倍的吞吐量加速。与在分离的目标和草稿 GPU 上进行的并行投机解码相比，SpecStream 将每 GPU 输出吞吐量平均提升 55.4%。

## Abstract
Speculative decoding reduces sequential Target model calls by verifying multiple tokens from the Draft model in parallel. Yet KV Cache growth limits long-context serving under constrained GPU memory. Offloading KV to CPU memory relieves this pressure. However, existing offloading schemes restore the full KV history before attention and fail to fully exploit the benefits of KV sharing across queries within a verification round. Existing parallel speculative decoding methods also overlook idle GPU compute capacity while memory-bandwidth-bound Target verification waits for historical KV. We present SpecStream, a speculative decoding system that begins verification without waiting for the full KV history to be restored and exploits compute bubbles during KV transfers for concurrent drafting on the same GPUs. It offloads only Target-committed history, keeping candidate rollback local to the GPUs. Each streamed KV chunk serves all queries in the round, with online softmax preserving full attention. Target-priority scheduling controls Draft concurrent execution under resource limits to constrain interference with Target verification. Experiments show that SpecStream maintains task quality close to SGLang speculative decoding while supporting more concurrent requests under limited GPU memory. Across different datasets, it achieves average throughput speedups of 1.41$\times$ and 1.32$\times$ over the offloading baseline for Qwen3 and InternLM2.5, respectively. Compared with parallel speculative decoding on separate Target and Draft GPUs, SpecStream improves output throughput per GPU by an average of 55.4%.

## 1. 核心问题与研究动机

- **背景**：长上下文 LLM 服务中，KV Cache 随序列增长而膨胀，模型权重固定但 KV 持续占用显存，导致 GPU 内存成为核心瓶颈（受显存容量与数据搬运带宽双重约束）。
- **投机解码（Speculative Decoding）**：用轻量 Draft 模型生成多个候选 token，Target 模型一次前向并行验证，从而减少 Target 的顺序调用次数；但**每一轮验证仍依赖历史 KV**，权重、KV、候选状态与执行缓冲区共同争抢显存，可能更快触及显存上限。
- **卸载（Offloading）的困境**：把 KV 历史放到 CPU 内存可缓解显存压力，但现有方案（如 TriForce、SD+Offload）**必须先恢复完整 KV 历史才开始注意力计算**，传输时间随上下文线性增长并落在 Target 验证的关键路径上。
- **两个被忽视的机会**：
  - 一轮验证中的 q 个查询虽然因果可见性不同，但**共享同一份已提交历史 KV**，一次取回可服务整组查询，摊薄传输成本（见式 (3)：D_token(q) ≈ D_H / E[U(q)]）。
  - 历史 KV 卸载后，Target 验证受 H2D 带宽限制而等待，形成**计算气泡**（G ≈ max(0, T_H2D − T_attn)），此时 GPU 算力闲置；而现有并行投机方案（MineDraft、SPECTRE、SwiftSpec）依赖额外 GPU 或流水线，未利用这些气泡在同一 GPU 上推进 Draft。
- **整体含义**：论文主张把"KV 访问组织方式"与"投机解码完整步骤的执行调度"协同设计，在有限显存下同时提升并发能力与吞吐效率，而非单纯加快传输或增加设备。

## 2. 方法论：SpecStream

### 2.1 核心思想
围绕投机解码中 KV 的**状态与生命周期特征**，联合设计三部分：提交感知的 KV 分层管理、多查询流式验证、目标优先的片内并发调度。

### 2.2 提交感知、无回滚 KV 分层（Commit-Aware Rollback-Free KV Tiering）
- 以 **Target 提交边界 C_r** 约束迁移资格，KV 被划分为三段（式 (4)，0 ≤ H ≤ C_r ≤ L_r）：
  - **Sealed History [0, H)**：已确认提交、迁移完成的历史，驻留 CPU；
  - **Active Tail [H, C_r)**：近期已提交 KV，驻留 GPU；
  - **Speculative Frontier [C_r, L_r)**：未验证候选 KV，驻留 GPU。
- 候选的接受/拒绝与 KV 回收**全部在 GPU 本地完成**，回滚区间 [C′_r, L_r) 与 CPU 历史 [0, H) 不相交，无需 CPU 副本清理或跨设备回滚。
- **批量迁移**：GPU 保留目标长度 T 的 Active Tail，新提交 KV 先积累，再按粒度 g 批量迁移；迁移终点 E = max(H, g·⌊max(0, C_r − T)/g⌋)，仅当 E > H 时迁移 [H, E)；异步拷贝完成并确认可用后才推进边界 H 并回收显存。

### 2.3 多查询流式验证（KV Streaming for Multi-Query Verification）
- **分块 + 跨查询共享**：将当前层 Sealed History 沿 token 位置切成 J 个连续分块；分块 j 到达 GPU 后即用整组查询计算 S_j = Q K_jᵀ / √d_h，**每块只传一次即服务本轮全部 q 个查询**，无需等待整层历史恢复。
- **在线 softmax 保持精确注意力**：每查询每头维护累积量 (m, ℓ, a)，初值 (−∞, 0, 0)；对每个分块先算局部状态 m_j、ℓ_j、a_j（式 (7)），再以 m′ = max(m, m_j)、α = exp(m − m′)、β = exp(m_j − m′) 做重标定并合并 ℓ′ = αℓ + βℓ_j、a′ = αa + βa_j（式 (8)）；处理完 CPU 历史后继续处理 GPU 上的 Active Tail 与 Speculative Frontier（后者需按绝对位置施加因果掩码），最终输出 O = a/ℓ。
- 作者论证该分块归约在实数算术下**等价于一次性全历史 softmax**（式 (9)），只改变 KV 到达与归约顺序，不改变全注意力定义。
- **流水线**：双 staging buffer + 独立传输/计算流实现传输与注意力重叠；相邻分块合并为传输批次；当前层释放缓冲后预取下一层历史（跨层预取）。
- **Cohort 批处理**：在调度批次内把层、验证宽度、数据类型、KV 头数、头维度、分块大小兼容的请求聚合，用批注意力核统一执行，同时保持各请求独立的 KV 索引、绝对位置与在线 softmax 状态。
- **I/O 感知的动态验证宽度**：按"每个有效输出 token 的估计时间"选宽度，q* = arg min_{q∈Q} ( T̂_round(q) / Û(q) )，Q = {2, 4, 6, 8}；利用近期传输、验证、草稿生成、拒绝纠正成本与已提交 token 数估计，记录不足时做有限初始采样；仅当收益超过切换阈值才改变 q。

### 2.4 目标优先的片内并发执行（Target-Priority Intra-GPU Co-Execution）
- 用 **NVIDIA MPS** 让 Target 与 Draft 在不同进程同卡并发；用 **TPC mask** 限制 Draft 的算力（TPC 为含 SM 的硬件簇），Target 保留全部 TPC；但 L2 与内存带宽仍共享，需运行时控制争用。
- **离线标定**：测量不同 TPC 数 n 下 Draft 单步时间 t_D(x, n)，以及相对独占执行的 Target 验证延迟增幅 ΔT(x, n) = [T^co_T(x, n) − T^alone_T(x)] / T^alone_T(x)；结合端到端吞吐选定默认分配 n₀（实验为 34 TPC/GPU）。
- **运行时准入**：用上一轮观测更新估计，需同时满足 Δ̂T(x, n₀) ≤ ε_T（延迟增幅在预算内）与 t̂_D(x, n₀) + δ ≤ Ŝ（含安全裕度的一步草稿能塞进剩余窗口），否则推迟。
- **单 token 粒度准入 + ACK 反馈**：每次只提交一个 token 的完整前向，指令携带请求/轮次标识、序号、TPC 分配与最晚启动时间 t_latest = t₀ + Ŝ − t̂_D − δ；Draft 完成后回 ACK，Target 再决定是否继续，保证每请求至多一个未完成草稿步；若宽度、批量或上下文变化导致延迟超预算，则停止新并发步，待已启动计算结束后恢复 Target 独占执行。

- **实现平台**：在 **SGLang 0.5.17** 上实现 SpecStream。
- **模型对**：Qwen3-32B / 0.6B；InternLM2.5-20B-Chat / 1.8B-Chat。

- **对比基线**：
  - 自回归解码 **AR**；
  - **SGLang SD**（投机解码，全 KV 驻 GPU）；
