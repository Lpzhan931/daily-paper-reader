## 摘要
投机解码通过并行验证多个草拟 token 来加速 LLM 推理，使得单次目标模型前向传播能够接受多个 token。从构造上，验证过程会计算被接受和被拒绝 token 的表示。然而，传统草稿模型仅保留被接受 token 的表示，使验证器在拒绝 token 上花费的大量计算实际上被浪费。我们发现，目标模型前向传播期间生成的这些被丢弃隐藏状态保留了关于未来 token 的有用信息，可改进后续草稿。然而，实现这一机会面临两个不同挑战。在推理时，回收开销可能增加草拟延迟，削弱因接受长度增加而获得的加速。在训练时，标准并行草稿模型训练不会产生与推理对齐的被拒绝状态，而通过顺序 rollout 获取这些状态会牺牲跨训练位置的并行性。我们提出 Carryover Drafting，可同时解决这两个挑战。Carryover 将被拒绝的目标隐藏状态回收为临时 KV 上下文，使草稿模型能够选择性地关注它们。它复用草稿模型现有的接口，仅添加一个可学习嵌入来区分被拒绝状态与已提交上下文。额外的 KV 上下文在每轮草拟中被替换，使其长度限制在一个提议块以内。我们提出并行 draft--verify--draft 训练，使草稿模型接触与推理对齐的被拒绝状态，同时保持跨训练位置的并行性。在 DFlash 以及由 DSpark 衍生的半自回归草稿模型上、跨两个目标模型进行的实验表明，这一简单的 Carryover 机制相比相应基线将平均接受长度提升了 6.5--14.7%，将端到端 vLLM 加速比提升了 7.9--14.4%，在翻译任务上的加速增益达到 28.8%。

## Abstract
Speculative decoding accelerates LLM inference by verifying multiple drafted tokens in parallel, allowing a single target forward pass to accept several tokens. By construction, verification computes representations for both accepted and rejected tokens. Yet, conventional drafters retain only the representations of accepted tokens, leaving the substantial verifier computation spent on rejected tokens effectively wasted. We find that these discarded hidden states generated during target forward retain useful information about future tokens that can improve subsequent drafts. However, realizing this opportunity poses two distinct challenges. At inference, recycling overhead can increase drafting latency, diminishing the speedup gained from increased acceptance length. During training, standard parallel drafter training does not produce inference-aligned rejected states, while obtaining them through sequential rollouts would sacrifice parallelism across training positions. We introduce Carryover Drafting, which addresses both challenges. Carryover recycles rejected target hidden states as temporary KV context, allowing the drafter to selectively attend to them. It reuses the drafter's existing interface and adds only a single learned embedding to distinguish rejected states from committed context. The additional KV context is replaced each drafting round, keeping its length bounded by one proposal block. We introduce parallel draft--verify--draft training that exposes the drafter to inference-aligned rejected states while preserving parallelism across training positions. Experiments with DFlash and a DSpark-derived semi-autoregressive drafter across two target models show that this simple Carryover mechanism improves average acceptance length by 6.5--14.7% and end-to-end vLLM speedup by 7.9--14.4% over the corresponding baselines, with speedup gains reaching 28.8% on translation.

# Carryover Drafting 论文总结

## 1. 核心问题与整体含义

**研究背景**
- 自回归 LLM 每次前向仅生成一个 token，投机解码（speculative decoding）通过轻量草稿器并行提出多个 token、目标模型一次前向并行验证来加速推理。
- 草稿质量是加速比的核心因素，近期方法（EAGLE、EAGLE-3、DFlash、DSpark）通过复用目标模型已算出的隐藏状态来提升草稿质量。

**核心问题**
- 验证过程**天然会为被接受和被拒绝的 token 都计算表示**，但传统草稿器只保留被接受 token 的隐藏状态，把验证器在拒绝 token 上花费的大量计算直接丢弃。
- 作者发现：这些被丢弃的隐藏状态中蕴含关于未来 token 的有用信息，可用于改进后续草稿。

**两个实现挑战**
1. **推理侧**：回收会引入投影与注意力开销，可能抵消接受长度增加带来的收益；若跨轮保留拒绝状态，KV 上下文会无限增长。
2. **训练侧**：标准并行草稿训练基于离线记录的目标响应，不产生推理时那种"草稿被验证后拒绝"的对齐状态；用顺序 rollout 获取又会牺牲跨训练位置的并行性。

**整体含义**
- 将投机解码验证阶段的"废弃计算"转化为后续草稿的质量收益，是一种几乎不增开销、接口改动极小的通用增强方案。

## 2. 方法论

### 核心思想
- 将上一轮被拒绝的目标隐藏状态**回收为临时的 drafter KV 上下文**，让草稿器通过其已有的注意力层选择性关注它们。
- 仅新增**一个可学习嵌入** $E_{carry}$ 用于区分"被拒绝状态"与"已提交上下文"，复用草稿器现有的特征投影 $F$ 和逐层 KV 投影 $K_\ell, V_\ell$。
- 每轮草拟**替换**（而非累加）携带状态，使额外 KV 长度恒定为**一个提议块** $B$。

### 关键技术细节
- 记第 $r$ 轮草稿位置的目标隐藏状态为 $H_r=(h_{r,1},\dots,h_{r,B})$，接受前缀为 $H^{acc}_r$，拒绝后缀为 $H^{rej}_r$。
- 复用投影：$\Phi_\ell(H) = (K_\ell(F(H)),\, V_\ell(F(H)))$。
- 构造携带上下文：
  $$U_{r+1,\ell} = \Phi_\ell(H^{rej}_r + E_{carry}),\quad ctx_{r+1,\ell} = [C_{r+1,\ell};\, U_{r+1,\ell}]$$
  其中 $C_{r+1,\ell}$ 为基线正常更新的已提交 drafter KV 上下文。
- **只读语义**：被拒绝状态仅作为草稿器的只读上下文，既不替换已接受 token 的隐藏状态，也不进入目标模型的 KV cache；全部接受时携带上下文为空。

### 并行 draft–verify–draft 训练
- 在每条记录的目标响应 $y$ 上随机采样 512 个 anchor $a_i$。
- **第一段草稿**：生成 proposal（**无梯度**，detached）。
- **验证**：冻结目标模型用块对角因果掩码并行验证各分支，贪心返回接受长度 $m_i$ 与 detached 的拒绝隐藏状态 $H^{rej}_i$；anchor 平移到 $a'_i = a_i + m_i + 1$。
- **第二段草稿**：读取记录前缀与 $H^{rej}_i$（经公式 2 注入），对记录的后续 continuation 计算损失；**梯度只流经第二段**（含共享投影与 $E_{carry}$）。
- 全接受的分支 $H^{rej}_i=\varnothing$，退化为基线在平移 anchor 上的训练，仍提供监督。
- 由于每个 anchor 的转移独立构造，训练保持跨位置并行。

### 延迟模型
- $L_{carry}\approx (t_{draft}+t_{verify}+t_{reuse})/\tau$，加速比 $S_{carry}\approx \tau\, t_{AR}/(t_{draft}+t_{verify}+t_{reuse})$，因此需要"高接受 + 低开销"的轻量设计。

## 6. 主要结论与发现

- **接受长度**：相对基线平均提升 **6.5–14.7%**，在所有评测数据集设置上均取得增益；从纯并行 DFlash 到半自回归 Markov 增益持续存在，说明与块内依赖建模互补。
- **端到端加速**：相对自回归解码，vLLM 平均加速比提升 **7.9–14.4%**，说明接受增益可覆盖回收开销；翻译任务最高达 **28.8%**（Qwen3-4B Markov，$T=1$）。
- **并发鲁棒性**：并发 1→32 时基线增益下降，但 Carryover 相对基线的优势保持。
- **消融结论**：携带**目标隐藏状态**明显优于携带 token 提示；无显式区分与嵌入接近，独立投影器略优但多引入一个投影模块，故选嵌入。
- **机制发现**：
  - 在匹配解码 anchor 下，ON 比 OFF 在每个草稿位置提升 Recall@1（1.28–5.60 点）与 Recall@16（0.29–1.89 点），说明模型确实学会了利用拒绝状态。
  - 增益与 **re-convergence**（拒绝轨迹预测与最终提交 token 的一致性）相关性最强（$r=0.96$，去掉翻译为 0.90），强于拒绝状态数量（0.74/0.84）与拒绝后接受率（0.52/0.71）。
  - Markov 的 re-convergence（2.76）高于 DFlash（2.51），在 8 个数据集中的 7 个上获得更大 Carryover 增益——暗示**草稿器越强，被拒绝状态越有用**。
  - 注意力诊断显示携带行获得 **19.78%** 的全 softmax 注意力（15 个拒绝状态子集为 23.40%）。

## 7. 优点

- **问题洞察新颖**：首次系统性地指出验证阶段被拒绝 token 的隐藏状态是"可回收的计算浪费"，并给出可行性证据。
- **接口极简、工程友好**：完全复用草稿器现有投影路径，只加一个嵌入；额外 KV 每轮替换、长度有界，可直接集成进块扩散草稿器。
- **训练方案巧妙**：并行 draft–verify–draft 在不做完整多轮 rollout、不新增目标采样数据的前提下，构造出与推理对齐的被拒绝状态，保住了训练并行性。
- **理论安全性**：明确论证 Carryover 只改变草稿分布 $q$ 而不改变目标概率与接受规则，因此标准接受/残差修正仍保持目标分布不变；拒绝文本不进入目标 KV。
- **实验设计较完整**：双目标模型 × 双草稿范式 × 8 任务 × 双温度，并配有消融、匹配 anchor 召回、注意力可视化与统计相关性分析，结论链条较自洽。
- **机制分析有深度**：用 re-convergence 这一诊断量解释了增益的跨任务、跨草稿器差异，而非仅报告结果。
