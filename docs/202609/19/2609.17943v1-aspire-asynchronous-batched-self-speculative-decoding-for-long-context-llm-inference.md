## 摘要
长上下文 LLM 推理的瓶颈在于注意力机制：重复的 KV 缓存读取使解码受限于内存带宽。自推测解码通过使用稀疏注意力草拟 token 并用全注意力验证 token 来缓解该问题，但现有批处理方法仍是同步的：一个批次中的所有请求共享同一个草拟-验证调度，尽管最优草拟长度在不同请求间差异很大，且在每个请求内部也会动态变化。我们提出 ASPIRE，一个基于三个组件的非同步批量自推测解码框架。第一，统一的混合前向传播允许草拟请求和验证请求共存于同一次批量前向传播中，从而无需全局草拟-验证阶段。第二，轻量级在线推测调度器利用每个请求的接受率估计和批次感知成本模型，让每个请求独立选择何时验证。第三，草拟内刷新层在草拟期间于单个指定层执行全注意力，在每个草拟步更新稀疏上下文，以减少草拟期间的陈旧性。在三个模型和五个推理与长上下文基准上，ASPIRE 相较于自回归基线在解码吞吐量上实现了 $1.70$-$4.58\times$ 的加速，并将平均加速比相较最强先前自推测基线提升约 $27\%$。

## Abstract
Long-context LLM inference is bottlenecked by attention, whose repeated KV-cache reads make decoding memory-bound. Self-speculative decoding alleviates this by drafting tokens with sparse attention and verifying them with full attention, but existing batched methods remain synchronized: all requests in a batch share a single draft-verify schedule, even though the optimal draft length varies widely across requests and changes dynamically within each request. We propose ASPIRE, a non-synchronized batched self-speculative decoding framework built on three components. First, a unified mixed forward allows drafting and verifying requests to coexist in the same batched forward pass, removing the need for global draft-verify phases. Second, a lightweight online speculation scheduler uses per-request acceptance-rate estimates and a batch-aware cost model to let each request independently choose when to verify. Third, an intra-draft refresh layer performs full attention at a single designated layer during drafting, updating the sparse context at every draft step to reduce staleness during drafting. Across three models and five reasoning and long-context benchmarks, ASPIRE achieves $1.70$-$4.58\times$ speedup in decoding throughput over autoregressive baselines and improves average speedup by approximately $27\%$ over the strongest prior self-speculative baselines.

## 1. 核心问题与研究动机

- **背景**：长上下文 LLM 推理中，MLP 受模型权重访问主导、属计算受限，批处理可将其从 GEMV 型转为 GEMM 型，从而提升吞吐；但**注意力**依赖每请求独立的 KV 缓存，无法在批次内摊销，随序列长度与批大小增长而内存流量激增、算术强度仍低，成为解码瓶颈。
- **已有方案**：自推测解码（self-speculative decoding）用稀疏注意力快速草拟多个 token、再用全注意力一次性并行验证，使昂贵的全 KV 访问被多个被接受 token 摊销，在长上下文场景尤其有吸引力（MagicDec、Vegas、TriForce 等）。
- **关键缺陷（本文动机）**：
  - 现有批量自推测系统仍是**同步**的——同批次所有请求共享一个全局草拟/验证调度与统一草稿长度。
  - 但实测表明最优草稿长度**高度异质且动态**：256 条 LongBench（前缀 16k–20k）样本上，每请求平均被接受草稿长度分布在 2.56–20.00（均值 11.51）；同一请求内部各验证轮之间也剧烈波动。
  - 同步批处理因此迫使异质请求"齐步走"，导致部分请求欠草拟、部分过草拟，白白损失加速空间。
- **另一问题**：Vegas 等方法仅在验证边界刷新稀疏上下文，草拟过程中上下文逐渐**陈旧（stale）**，限制草稿长度与质量。
- **整体含义**：ASPIRE 主张把调度粒度从"批次级"下沉到"请求级 + 步级"，在保持批量执行效率的同时实现非同步自推测解码。

## 2. 方法论

**核心思想**：让同批次请求在同一次模型前向中处于不同推测状态（部分草拟、部分验证），配合逐请求在线调度器与草拟内上下文刷新，最大化单位时间产出 token 数。

### 2.1 统一混合前向（Unified Mixed Forward）

- 第 $t$ 步，活跃请求被分为验证集 $V_t$ 与草拟集 $D_t$；每请求维护草稿长度 $d_i$ 与稀疏上下文 $S_i$。
- 草拟请求：用稀疏注意力对 $S_i$ 解码 **1 个 token**；验证请求：用全注意力对完整缓存上下文解码 **$d_i+1$ 个 token**。
- 二者共享同一目标模型权重与 MLP 计算，仅注意力上下文与解码长度不同；通过为每请求指定各自的注意力上下文与解码长度，在同一批前向中执行异构请求，既保留 MLP 批处理收益，又让注意力保持请求特定。
- 前向结束后：$V_t$ 中请求比对草拟前缀与全上下文输出，把被接受 token + 验证得到的下一 token 追加到上下文并重置 $d_i$；$D_t$ 中请求追加 1 个草拟 token 并令 $d_i \leftarrow d_i+1$。**全局草拟/验证阶段被彻底消除**。

### 2.2 在线推测调度器

- 目标：逐请求决定"继续草拟"还是"验证"，以最大化吞吐（token/时间）。
- **目标草稿长度** $\gamma_i$：沿用 Leviathan 等人的期望推测效率目标，令 $c_i = T^{\text{draft}}_i / T^{\text{verify}}_i$，则
  $$\gamma_i = \arg\max_{\gamma \in \{0,\dots,d_{\max}\}} \frac{(1-\alpha_i^{\gamma+1})/(1-\alpha_i)}{1 + c_i \gamma}$$
  即在期望接受率 $\alpha_i$ 下最大化预测 token 产出率。
- **接受率估计 $\alpha_i$**：一次验证草拟 $d_i$ 个、接受 $a_i$ 个时，取 $\hat\alpha_i = a_i / \min(a_i+1, d_i)$（部分接受视为 $a_i$ 次成功 + 1 次失败；全接受视为 $d_i$ 次成功），再做指数平滑 $\alpha_i \leftarrow \omega\alpha_i + (1-\omega)\hat\alpha_i$；初始先验 $\alpha_0$，且首轮须草拟至少 $\gamma_{\text{init}}$ 个 token 才允许验证。
- **批次感知成本模型**：设 $n_t = |D_t| + \sum_{j\in V_t}(d_j+1)$ 为总前向 token 数，建模单步运行时
  $$\tau_t = \beta_{\text{model}} + \beta_{\text{mlp}}\cdot n_t + \beta_{\text{attn}}\cdot\Big(\sum_{j\in D_t}|S_j| + \sum_{j\in V_t}\ell_j\Big)$$
  其中 MLP 项随总 token 数线性（计算受限），注意力项随总读取 KV 长度线性（内存受限）；系数由采样生成的运行时 trace 拟合。
- 在"批次内 $B$ 个槽位都是请求 $i$ 的副本"的同构近似下得到 $T^{\text{draft}}_i = \beta_{\text{model}} + \beta_{\text{mlp}}B + \beta_{\text{attn}}B|S_i|$，$T^{\text{verify}}_i = \beta_{\text{model}} + \beta_{\text{mlp}}B(d_i+1) + \beta_{\text{attn}}B\ell_i$，并随 $d_i$、$\ell_i$、$|S_i|$ 在线重算 $c_i$。
- **决策规则（Algorithm 1）**：若 $d_i \ge d_{\max}$ → 验证；若尚无验证结果且 $d_i < \gamma_{\text{init}}$ → 草拟；否则计算 $\gamma_i$，当 $d_i \ge \gamma_i$ 时验证，否则继续草拟。
