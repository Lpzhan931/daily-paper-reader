## 摘要
混合大语言模型将全注意力层与线性注意力层交错排列，以降低长上下文推理的成本。这种结构使得前缀缓存变得复杂：全注意力键值缓存可逐令牌寻址，而线性注意力层维护的循环状态无法回滚到任意前缀边界。现有的混合前缀缓存方法通过存储循环状态检查点来应对这一不匹配问题。因此，令牌级匹配仅在与存储检查点对齐的位置上可直接使用，将前缀复用限制在离散的边界集合内。我们提出Tail-Replay，一种能在混合大语言模型中实现无约束令牌级前缀重用的前缀缓存机制。关键见解在于，诸如Gated DeltaNet的线性注意力机制可视为对输入前缀的一种结构化有损压缩：门控循环更新会逐步衰减早期输入的贡献。因此，匹配前缀的循环状态可以通过仅重放该前缀的一小段近期后缀来良好近似。Tail-Replay利用这一特性，缓存精确的全注意力键值缓存，同时省略循环状态检查点。在缓存命中时，它通过重放匹配前缀的一小段近期后缀来重建线性注意力状态。因此，重用边界由共享令牌决定，而非循环状态检查点决定。我们使用LongBench和RULER基准，在三个基于Gated DeltaNet的混合模型上评估Tail-Replay。在仅使用5%–10%重放预算的情况下，它在LongBench和RULER上保留了92.8%–99.9%的完整预填充质量。对于服务效率，我们评估了多种匹配前缀长度——8K、16K和32K下的首令牌时间加速比。该加速比随前缀长度增长，在32K时达到相对完整预填充的9.1–14.3倍。

## Abstract
Hybrid large language models interleave full-attention layers with linear-attention layers to reduce the cost of long-context inference. This structure complicates prefix caching: full-attention key-value caches are token-addressable, whereas linear-attention layers maintain recurrent states that cannot be rolled back to arbitrary prefix boundaries. Existing hybrid prefix caching methods address this mismatch by storing recurrent-state checkpoints. As a result, token-level matches are directly usable only at positions aligned with stored checkpoints, constraining prefix reuse to a discrete set of boundaries. We present Tail-Replay, a prefix caching mechanism that enables unconstrained token-level prefix reuse in hybrid large language models. The key insight is that linear-attention mechanisms such as Gated DeltaNet can be viewed as a structured, lossy compression of the input prefix: gated recurrent updates progressively attenuate the contributions of earlier inputs. Consequently, the recurrent state of a matched prefix can be well approximated by replaying only a short, recent suffix of that prefix. Tail-Replay exploits this property by caching the exact full-attention key-value cache while omitting recurrent-state checkpoints. On a cache hit, it reconstructs the linear-attention states by replaying a short, recent suffix of the matched prefix. As a result, the reuse boundary is determined by the shared tokens rather than by recurrent-state checkpoints. We evaluate Tail-Replay on three Gated DeltaNet-based hybrid models using the LongBench and RULER benchmarks. With only a 5--10\% replay budget, it retains 92.8--99.9\% of full-prefill quality on LongBench and RULER. For serving efficiency, we evaluate time-to-first-token speedups across multiple matched-prefix lengths---8K, 16K, and 32K. The speedup grows with prefix length, reaching $9.1$--$14.3\times$ over full prefill at 32K.

## 一、核心问题与研究动机

- **背景**：LLM应用场景（多轮对话、RAG、多智能体等）带来长上下文、高并发需求，模型层面和系统层面各自提出优化方案。
  - 模型层面：混合架构（Hybrid Architecture），将全注意力（Full Attention, FA）层与线性注意力（Linear Attention）层交错排列，以降低长上下文推理开销。
  - 系统层面：前缀缓存（Prefix Caching），通过复用请求间共享前缀来避免冗余的预填充计算。
- **核心矛盾**：上述两种技术天然存在兼容性冲突，即所谓“线性注意力的魔咒”：
  - FA层的KV缓存是**按token可寻址**的，可在任意前缀边界直接复用；
  - 线性注意力层在预填充中通过递归更新将前缀压缩成**不可回退的循环状态**，无法表示为任意较早前缀的状态。
- **现有工作的不足**：Marconi 和 Sparse Prefix Caching 等方案通过存储“循环状态检查点”来缓解问题，但本质上仍将前缀复用的边界约束在检查点所在位置，**无法实现真正的任意token级前缀复用**。
- **核心问题**：能否让混合LLM的前缀缓存像纯FA模型那样，在任意共享token边界实现直接复用，而不受循环状态检查点的限制？

## 二、方法论：Tail-Replay

- **核心思想**：将 Gated DeltaNet（GDN）等线性注意力机制视为对输入前缀的**结构化有损压缩**——其门控递归更新会对早期输入的信息逐步衰减，因此长前缀的循环状态主要由近期输入主导。基于此，**匹配前缀的循环状态可通过仅重放该前缀末尾的一小段近期后缀来高精度近似**。
- **具体机制**：
  1. **缓存内容设计**：仅缓存FA层的逐token KV缓存，以及每个FA层的输出隐藏状态 $h_i$；**不存储任何线性注意力层的循环状态检查点**。
  2. **缓存命中时的状态重建**：将混合模型按“一个FA层 + 其后连续的若干线性注意力层”划分成独立的重放组。在缓存命中时，从零初始化状态 $\hat{S}_{m-k}=0$ 出发，仅将匹配前缀末尾 $k=\lceil rm\rceil$ 个token（$r$ 为重放比例，5%–10%）的FA输出隐藏输入至线性注意力层，按GDN递推公式：
     - $S_i = T_i S_{i-1} + \beta_i v_i k_i^\top$
     - $T_i = \alpha_i (I - \beta_i k_i k_i^\top)$
     得到近似的匹配前缀边界状态 $\hat{S}_m$。
  3. **分组独立重放**：各组独立执行重放，缓存FA输出隐藏可保证每组第一个线性注意力层的输入与原始预填充时完全一致，从而将误差限制在各组内部，避免跨组误差累积。
  4. **随后服务**：重建所有线性注意力层状态后，结合检索到的FA KV继续处理未匹配的新token。
- **两项效率优化**：
  - **尾部FFN跳过（Tail-FFN Skip）**：重放组末端层中，其FFN输出对状态重建不是必需的（下一个组从已缓存的下一层FA输出隐藏开始），因而在重放中可跳过该FFN计算，仅计算线性注意力部分。
  - **传输/重放重叠（Transfer/Replay Overlap）**：由于重放不依赖FA KV，FA KV从主机内存到设备端的传输可放在独立副本流上与重放并行，仅在查询前向前同步，隐藏大部分数据搬运开销。

## 三、实验设计

- **模型**：三种基于Gated DeltaNet的混合架构LLM：
  - OLMo-Hybrid-7B
  - Qwen3.5-4B
  - Qwen3.6-27B
- **质量评测基准**：
  - **LongBench**：narrativeqa（16K/32K/64K）、hotpotqa、qasper、musique、qmsum等多任务长上下文理解。
  - **RULER**：cwe（多键值检索）、qa1（问答）、niah（针堆检索）、vt（可变跟踪）四种任务，分别在8K和16K上下文长度上评测。
- **对比基线**：
  - **Full prefill**：完整预填充（理想质量参考线）；
  - **ZEROONLY**：复用匹配的FA KV但将线性注意力循环状态直接置零而不重放——用于分离重放在状态重建中的贡献；
  - **H2D-SER**（串行传输路径）与 **H2D-OVL+skip**（传输/重放重叠 + FFN跳过）：用于效率评测。
- **实验场景/设置**：
  - 质量实验：重放预算 $r \in\{5\%, 10\%\}$，与Full和Zero-only对照；
  - 效率实验：narrativeqa共享前缀，名义上下文长度8K、16K、32K，测TTFT（time-to-first-token），重复20次取平均。

## 六、主要结论与发现

- **质量保持**：Tail-Replay以5%重放预算在LongBench上保留92.8%–98.9%的全预填充质量，RULER上保留93.1%–99.9%；以10%预算质量进一步恢复（LongBench可达98.1%，RULER可达99.9%）；
- **效率提升**：TTFT加速随匹配前缀长度增长而增加，32K前缀下相对全预填充加速9.1–14.3倍（5%重放 + OVL+skip路径下）；OVL+skip较串行H2D传输在32K时进一步压缩TTFT约18%–42%；
- **重放必要性的证实**：ZEROONLY在RULER多个重检索/追踪类任务上崩溃极为严重（如vt任务几乎归零，OLMo-Hybrid-7B从0.885/0.795降至0.006/0.000），说明仅复用FA KV而不重建线性状态是远不够的，Tail-Replay的重放机制是质量保障的关键；
- **缩放规律**：全预填充成本随上下文大幅增长，而Tail-Replay因只处理固定比例的尾部，开销相对平稳，因此前缀越长、加速收益越大。

## 七、主要优点

- **问题切入精准**：直击混合架构与现有前缀缓存的“体系性失配”，问题定义清晰、动机强；
- **方法优雅而务实**：利用Gated DeltaNet门控衰减这一结构性质，用一个很简单的“短后缀重放”自然绕开了检查点带来的离散边界限制，实现任意token级前缀复用，工程语义简洁；
- **合理的分组隔离设计**：缓存各FA层输出隐藏、按组独立重放，从方法上控制了误差的传递范围，理论合理性较强；
- **工程优化到位**：FFN跳过和传输/重放重叠两个优化显示作者不仅关心算法正确性，也关注端到端系统效率中的瓶颈转移问题；
- **实验具有强对照性**：ZEROONLY基线设计巧妙，有效隔离与证明了线性状态重建的独立重要性；
- **推理效率验证扎实**：做了多次计时重复取均值，并汇报了相对全预填充的加速倍数，效率结论有说服力。

- **对比实验缺失**：未与Marconi、Sparse Prefix Caching或LinearKV等其他混合模型前缀缓存方法同台对比，读者难以直接判断“无检查点”方式相对“有检查点”方式在质量与延迟上的净增益有多大。
- **多轮前缀推广不明确**：论文只描述了整段前缀命中场景，对于部分命中、多段分离共享、位置无关的拼接型前缀复用是否依然适用，未做充分讨论或实验；
- **方法适用范围的边界未厘清**：核心假设依赖Gated DeltaNet（门控衰减）的记忆特性；对Samba、Mamba-2、其他无门控或有长程强记忆的线性注意力变体，Tail-Replay的有效性缺乏理论界定或实验验证；
- **算力能耗与显存开销**：缓存FA层输出隐藏会引入额外存储开销，论文并未量化这部分显存/内存成本或其对服务吞吐的潜在影响；效率实验未计及缓存构建成本；
