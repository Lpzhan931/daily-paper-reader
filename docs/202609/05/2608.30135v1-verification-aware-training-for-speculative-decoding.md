## 摘要
推测解码通过使用草稿模型生成候选令牌，并由目标模型在单次前向传递中验证，从而加速大型语言模型推理。验证按顺序进行，并丢弃从首次拒绝位置开始的所有位置，然而现有的草稿训练依赖于对目标的令牌级模仿，并使用固定的逐位置加权，既未反映顺序验证性质，也未反映丢弃模式。我们提出验证感知训练（VAT），一种即插即用的框架，在每个训练步骤中模拟验证，并将由此产生的接受和拒绝模式转化为监督信号。VAT包含两个组件：(i) 验证头，一个轻量级的联合训练二元分类器，用于监督草稿模型每个位置是否能通过顺序验证；(ii) 验证自适应加权，它取代固定的加权方案，在每个样本的首次拒绝点之前保持完整权重，并重新锚定衰减的起始点。VAT仅修改训练目标，因此可以叠加在现有方法之上，而无需改变草稿架构、目标模型或推理过程。将VAT应用于EAGLE-3和DFlash，在Qwen3-4B、Qwen3-8B和LLaMA-3.1-8B上，平均接受长度最多提升11.4%，墙钟加速最多提升8.7%，在数学、代码和聊天基准测试中均取得一致改进。代码将发布于 https://github.com/naver-ai/vat

## Abstract
Speculative decoding accelerates large language model inference by using a draft model to generate candidate tokens, which are verified by the target model in a single forward pass. Verification proceeds sequentially and discards every position from the first rejection onward, yet existing draft training relies on token-level imitation of the target with a fixed per-position weighting that reflects neither property. We introduce Verification-Aware Training (VAT), a plug-in framework that simulates verification at every training step and turns the resulting accept and reject patterns into supervision. VAT consists of two components: (i) a verification head, a lightweight jointly trained binary classifier that supervises the draft model on whether each position survives sequential verification; (ii) verification-adaptive weighting, which replaces the fixed weighting schedule by keeping full weight up to each sample's first rejection point and re-anchoring the decay to start there. VAT modifies only the training objective, so it can be layered on top of existing methods without changing the draft architecture, the target model, or the inference procedure. Applied to EAGLE-3 and DFlash on Qwen3-4B, Qwen3-8B, and LLaMA-3.1-8B, VAT improves average acceptance length by up to 11.4% and wall-clock speedup by up to 8.7%, with consistent gains across math, code, and chat benchmarks. Code will be available at https://github.com/naver-ai/vat

# 论文总结：《面向推测解码的验证感知训练》

## 1. 核心问题与整体含义（研究动机与背景）

- **推测解码的背景**：大型语言模型（LLM）自回归解码效率低，推测解码通过草稿模型快速生成候选 token，再由目标模型在单次前向传播中批量验证，实现无损加速。
- **被忽视的验证机制**：验证是**顺序进行**的，一旦某位置 token 被拒绝，**该位置之后的所有候选 token 都会废弃**，而现有草稿模型训练只做**逐位置 token 级模仿**，给定固定的位置权重（如 EAGLE-3 的 `0.8^(k-1)`、DFlash 的 `exp(-(k-1)/γ)`），完全未反映上述“顺序验证”与“首个拒绝后整段丢弃”的真实推理特性。
- **核心矛盾**：决定推理加速的关键是**平均接受长度**（acceptance length），而训练目标既不告诉模型“该 token 能否通过验证”，也不按样本具体在哪个位置被拒绝来调整梯度信号。
- **论文含义**：作者提出了一种**即插即用、只修改训练目标**的框架，在训练时模拟验证过程，把接受/拒绝模式作为额外的监督信号，使草稿训练与实际解码机制对齐。应用在 EAGLE-3 与 DFlash 两个最先进的草稿模型上，取得显著的接受长度与墙钟速度提升。

## 2. 方法论：VAT 的核心思想与技术细节

VAT（**Verification-Aware Training**）的核心思想是“**让训练过程看见推理时实际发生的验证**”。它包含两个协调的组件：

- **(i) 训练时模拟验证**：训练中，用目标模型和草稿模型在每个位置的分布，模拟推测采样规则——token `x` 被接受概率为 `min(1, pk(x)/p̂k(x))`，从而得到逐位置接受指示 `mk`，以及首个拒绝点 `k* = min{k : mk=0}`。再定义**接受标签** `vk = ∏_{j≤k} mj`，表示“该位置之前的全部 token 均被接受”。该标签直接反映顺序验证中该位置是否真正贡献接受长度。
- **(ii) 验证头（Verification Head）**：在草稿模型最后一层隐藏状态上接一个轻量的二分类头，预测每个位置是否能在顺序验证后存活（即预测 `vk`），用二元交叉熵损失 `LVH` 训练。该头仅作训练辅助，不改推理结构。梯度通过该头回传到草稿模型，促使隐藏状态保留与“是否与目标一致”有关的特征，弥补纯 next-token 监督缺乏验证信号的缺陷。该头也可以可选地在推理期使用，用于提前终止草稿生成（early-exit）。
- **(iii) 验证自适应加权（Verification-Adaptive Weighting）**：原有权重 `wk` 是固定、全局共用、从 `k=1` 开始衰减的；VAT 将它们替换为样本自适应权重：
  - 在首个拒绝点**之前**：保持完整权重 `1`（这些位置切实贡献接受长度）；
  - 在首个拒绝点**及其之后**：保留前述衰减曲线但**重新锚定**到从 `k*` 开始衰减。
  - `k*` 本身也分配全权重（因为这是最直接的失败点，修改此位置的预测能延长接受前缀），而之后的位置仍给予**衰减而非归零**的学习信号，因为它们在极端样本中仍有学习价值。
- **完整训练目标**：最终损失 `L = Σ_k ŵ_k (ℓ_k^soft + ℓ_k^hard) + β·LVH`，即软标签（目标分布上的交叉熵）与硬标签（目标采样 token 的交叉熵）结合，再配合验证头损失；所有实验取 `β = 1`。

综上，技术细节在于：**只改训练目标** → 可叠加在任意现有草稿模型上；**不改变草稿架构、目标模型或推理过程**。

## 6. 主要结论与发现

- **核心收益**：在 3 个目标模型上，VAT 同时提升平均接受长度和墙钟加速比。举例：
  - Qwen3-4B：EAGLE-3 加速比从 4.07× 提高到 4.39×（+7.9%），τ 从 6.28 升至 6.78（+8.0%）；DFlash 加速比从 4.54× 到 4.81×（+5.9%），τ 从 5.73 到 6.08（+6.1%）；
  - 最优处：平均接受长度最高**+11.4%**，墙钟加速最高**+8.7%**；
  - `T=1` 解码条件下也有整体一致的提升。
- **组件各有贡献且可叠加**：单独添加验证头、验证自适应加权或软+硬标签均能提高 τ；三者联合效果最佳（组合目标的 3 项全部使用在 Qwen3-4B/DFlash 上给出 τ=6.08、加速 4.81×）；其中验证头+自适应加权的组合已在仅用硬标签时恢复大部分收益。
- **“从 k* 重新锚定衰减”是加成来源**：统一基线上，固定权重表现差异很小（均匀 5.72 vs 0.8^(k−1) 的 5.73 vs exp 5.99）；而换用验证自适应加权后，两种基曲线均达到 τ≈6.08–6.09，表明收益主要来自“按样本锚定”的自适应机制而非衰减曲线的函数形态。
- **验证头重塑了训练动态**：带验证头的草稿，首个拒绝点逐步后移；同时首个拒绝点之后的 token 匹配率不因训练推进而退化——表征更有利于验证后置位点的预测。
- **推理期可选增益**：验证头可作为目标验证的廉价代理执行早退，恢复 oracle 早退的大部分性能提升（例如 DFlash Code：4.83×→4.97×，oracle 为 5.20×）；τ 有小幅下降（误拒造成），但整体加速因为节省了计算而净收益。
- **VAT 具备即插即用的通用性与部署价值**：只修改训练阶段目标，兼容自回归与扩散两种草稿机制，不改变推理路径。

## 7. 优点（方法与实验亮点）

- **问题切入点精准有力**：抓住“训练目标与推理验证过程不一致”这一真实但常被忽略的痛点，归纳出两个直接可操作的训练原则，逻辑链条清晰。
- **方法极简且物理直观**：

- **工程友好、改动成本低**：不改草稿架构、不改目标模型、不改推理流程，只改目标

## 8. 局限性与潜在不足

- **训练阶段开销随草稿范式不同而差异显著**。EAGLE-3 类模型因训练过程已复用目标 LM Head，VAT 的额外时间与显存代价可忽略（+1.2%、+0.1GB）；但 DFlash 等原本不需要目标分布的模型，必须额外引入一次 LM Head 前向，导致显存峰值增加 7.7GB、耗时增加 6.1%。在显存受限的微调环境中这可能成为部署障碍。
- **验证标签的可靠性依赖目标模型行为与验证规则的一致性**。训练语料由目标模型贪心生成，验证模拟亦默认贪心采样规则；虽然论文在附录验证了随机采样规则下的正交稳健性，但并未系统测试目标模型因解码温度、采样算法或自身版本变化而导致的标签漂移问题，实际适配时可能需要重新生成标签。
- **推理期验证头早退需人工设定阈值**，且存在“误拒”导致的接受长度回退。论文只给出了固定阈值扫描结果，缺乏阈值自适应机制或与动态草稿长度策略的联合优化；在真实服务中，不合理的阈值选择可能反而降低吞吐。
- **验证头为二分类目标，只能粗糙刻画逐位置是否存活**，无法捕捉 token 层面接受概率的连续差异；在分布接近的边界情形下，二值化可能丢失部分可学习的细粒度信息。
- **实验规模存在边界**。所有实验集中在 4B–8B 目标模型与两组草稿架构上，未覆盖更大的模型（如 30B/70B+），也未评估长上下文（>2K tokens）或服务端并发场景；对超大模型和长序列的泛化仍有待实证。
- **消融中的“软+硬标签”组合机制未深挖**。论文将其视为标准训练配方，但未解释为何软硬标签结合能够放大了验证自适应加权的收益，缺少更深层的表征分析。

---

## 9. 总结与展望

VAT 在整个推测解码技术栈中切中了一个关键却常被忽略的盲区——**训练目标与实际顺序验证过程的不一致**。通过引入可插拔的验证头与按样本锚定重加权的损失函数，它以极低的工程侵入代价同时提升了平均接受长度与端到端解码加速比，并在自回归、扩散两类迥异的草稿模型上获得了一致收益，显示出良好的通用性。

从方法论上讲，该工作的核心价值不仅在于性能提升（最优约 +11% 接受长度、+9% 墙钟加速），更在于它指出了一种设计原则：**草稿模型训练的终极优化目标应当是“通过验证的长度”，而非逐 token 的模仿精度**。这一原则对未来的草稿模型设计具有直接的指导意义，且可以进一步延伸到草稿长度规划、前瞻性拒绝/恢复策略、或与 token 级置信度估计的协同优化中。

论文实验架构完整、消融层层递进、表格与附录互为印证，在实验设计上体现出较高的规范性与严谨性。尽管其在训练开销和部分场景覆盖方面仍有局限，但作为一项以训练期改动为核心的加速方法，VAT 提出了一种轻量、清晰且可扩展的范式，在小模型上验证充分，便于后续向更大规模与更复杂解码策略推广。
