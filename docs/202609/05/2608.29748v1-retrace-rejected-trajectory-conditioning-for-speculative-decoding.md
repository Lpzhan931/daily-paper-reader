## 摘要
推测解码通过让轻量级草稿模型提出多个候选token，并由较大的目标模型并行验证，从而加速自回归语言模型推理。然而，在第一次拒绝之后，基于前缀的标准验证会丢弃剩余的草稿后缀，因此生成和验证这些位置的计算不会促进解码进度。聚焦于DFlash，我们表明被拒绝后缀中的被拒绝位置仍可能与目标延续对齐，这表明草稿模型尽管存在局部token级错误，仍能保留有用的语义和结构信息。受此观察启发，并借鉴条件扩散的思想，我们引入了**ReTrace**，一种拒绝轨迹条件化方法，它使每个草稿块以来自前一轮的拒绝后缀为条件，而非仅从新的掩码占位符生成。ReTrace保留被拒绝后缀的隐藏表示，将其与下一个草稿块对齐，利用同一验证过程中的目标感知校正信号对其进行细化，并通过门控残差融合将其纳入草稿器的输入嵌入。由于被拒绝的token从未被提交，且目标端验证保持不变，ReTrace保留了推测解码的无损特性，且无需额外的模型前向传播。使用Qwen3模型在数学推理、代码生成和开放式对话上的实验表明，ReTrace在其DFlash骨干上持续提高了平均接受长度和端到端解码速度。通过在不修改轮内提案生成的情况下引入跨轮条件化，ReTrace在很大程度上有别于现有草稿改进方法，并可与它们结合以进一步获益。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：大语言模型的自回归解码效率受限于序列依赖性——每生成一个token都需要一次完整的前向传播，导致推理延迟随输出长度增长。推测解码（Speculative Decoding）通过“草稿-验证”范式解决这一瓶颈：轻量级草稿模型先提出多个候选token，再由大目标模型并行验证，从而在一次前向传播中提交多个token，加速推理。
- **核心问题**：标准前缀验证在首次拒绝后即丢弃草稿后缀。然而，生成和验证这些被丢弃位置的计算已经发生，却没有转化为任何解码进度，造成计算浪费。论文提出一个关键问题：**被拒绝的后缀是否仍保留对目标延续有用的预测信息？能否将其复用于下一轮草稿生成？**
- **核心观察**：论文聚焦于DFlash这一基于扩散的并行草稿模型，发现尽管草稿在早期位置出现token级错误并被拒绝，后续位置仍可能重新与目标延续对齐（图1示例）。定量分析进一步表明：30.4%的被拒绝后缀位置中，目标token仍是草稿模型的top-1预测；75.2%落在top-5内；被拒绝的草稿隐藏状态与真实目标延续的隐藏状态之间的余弦相似度（0.351）显著高于随机窗口基线（0.128）。这说明被拒绝轨迹保留了一定程度的延续特定信息——不足以直接接受，但可作为辅助条件信号。
- **整体含义**：推测解码中被丢弃的计算不必是浪费——它可以条件化后续的草稿生成，提升整体解码效率。该工作挑战了“首次拒绝后后续草稿计算完全无用”的隐含假设。

### 2. 论文提出的方法论：核心思想、关键技术细节

**方法名称**：ReTrace（Rejected-Trajectory Conditioning）

**核心思想**：受条件扩散启发，ReTrace将上一轮被拒绝后缀的隐藏状态序列视为“拒绝轨迹”，将其作为下一草稿块的辅助条件信号。它不修改轮内提案生成方式，仅在轮与轮之间建立跨轮信息流，因此与现有草稿改进方法正交。

**关键技术细节**：

1. **拒绝轨迹的构建与对齐**
   - 解码轮次t中，草稿模型产出B个候选token及其最终层表示：{hDt,1, hDt,2, …, hDt,B}
   - 设At为被接受的token数。当At < B时，首个拒绝位置为rt = At + 1
   - ReTrace排除已解决的接受前缀 hDt,1:At 和首个拒绝位置 hDt,rt（后者由目标侧修正token替代，已通过标准上下文传递）
   - 仅保留首个拒绝位置之后的表示：{hDt,rt+1, …, hDt,B}
   - 将对齐信号定义为：mt+1,j = hDt,rt+j（当 1 ≤ j ≤ B−rt），否则为0——即按原顺序将保留状态移至下一提案块的开头位置
   - 若整块被接受或无剩余表示，ReTrace退化为原始草稿过程

2. **目标感知校正**
   - 将每个对齐的草稿状态与验证期间产生的对应目标模型表示配对：ut+1,j = hTt,rt+j−1（因果模型中位置rt+j−1的状态预测位置rt+j的token）
   - 通过可学习的轻量投影将两者映射为草稿表示空间中的更新量：ct+1,j = Wc[mt+1,j; ut+1,j]
   - 校正后的信号为残差形式：rt+1,j = mt+1,j + β·ct+1,j，其中β在校准启动阶段线性增加、推理时完全激活

3. **门控残差融合**
   - 校正信号通过向量级门控残差连接注入草稿器输入：ẽt+1,j = et+1,j + Wv·rt+1,j ⊙ σ(Wg[et+1,j; rt+1,j])
   - 门为向量值，逐维度控制信号强度；锚点和无对齐信号的位置保持原始输入
   - Wv初始化为零，确保初始化时残差消失、草稿器从原始行为出发逐步学习

4. **优化与推理**
   - 训练时缓存表示在跨轮复用前被detach（切断梯度），防止跨轮梯度传播
   - 草稿骨干、校正模块与门控注入模块通过当前轮预测损失联合优化，目标模型冻结
   - 推理时无需额外目标模型前向传播，各信号仅保留一轮后即被最新拒绝后缀的信号替换

### 6. 论文的主要结论与发现

- **被拒绝后缀保留预测信息**：token级分析显示目标token在草稿分布中常保持高排名；表示级分析显示被拒绝状态与其真实目标延续的相似度显著高于随机基线——被拒绝轨迹具有有限的、可复用的预测价值。
- **ReTrace一致优于DFlash骨干**：跨四种模型-温度配置，宏平均接受长度提升6.97%，宏平均加速比提升5.34%。在贪心和随机解码下、每个benchmark上均获得接受长度提升。
- **组件均有效**：简单覆盖注入已有小幅提升（6.45→6.51），门控融合带来更大增益（→6.79），目标感知校正进一步提升（→6.90），证明各设计选择均有实际贡献。
- **增益非来自额外训练**：以相同数据和预算继续训练原始DFlash仅获边际提升且很快饱和，而ReTrace在整个训练过程中持续上升——增益可归因于拒绝后缀条件化本身。
- **运行时开销可忽略**：条件化开销仅0.13ms/周期，占DFlash周期延迟的0.40%，却将加速比从3.37×提升至3.73×。
- **与现有方法正交**：ReTrace可叠加在Domino之上，宏平均吞吐量从287.17升至301.39 tok/s，接受长度从7.43升至7.79 tokens。
- **在并发场景下依然有效**：在所有并发级别（1–32）上ReTrace均为最快方法，并发32时仍保持1.62×加速比，而EAGLE-3的两种配置均低于目标模型单独解码。

### 7. 优点

- **问题新颖且切中要害**：识别出推测解码中一个基础性的效率缺陷——拒绝后缀的浪费性丢弃，并提供了多重证据链验证可复用性，而非仅凭直觉断言。
- **方法设计精致**：选择DFlash（并行块预测）作为合适的研究载体，并清晰论证了为何EAGLE类自回归草案不具备同等的可复用条件；目标感知校正巧妙地利用验证中已有的目标表示作为“免费”的校正信号；门控残差与零初始化设计保证了训练初始阶段与原始行为完全一致，优化稳定性好。
- **保留无损性**：被拒绝token从未提交，目标验证规则和输出提交程序完全不变，理论上的无损属性不受影响。
- **开销极低**：无需额外目标前向传播或自回归草稿步骤，条件化仅增加0.40%的周期延迟。
- **实验严谨**：特别值得称道的是SFT对照组设计——排除“额外训练本身带来提升”的混淆因素；消融实验系统地隔离了各组件贡献；编码时配合逻辑清晰的算法框图和流水线插图，使读者容易理解。

### 8. 不足与局限

- **模型覆盖范围有限**：仅在Qwen3-4B/8B上验证。不同模型家族的隐藏状态几何特性差异可能影响拒绝轨迹的可复用性，结论的外部推广性有待验证。
- **仅使用DFlash作为骨干**：声称方法与现有草稿改进正交并做了Domino兼容实验，但未与更多草稿器（如EAGLE系列）结合验证。
- **校正信号依赖目标模型表示**：在嵌入维度差异较大的模型对中，校正信号的表达力可能需要更复杂的映射（而非线性投影），论文未深入讨论此边界。
- **条件信号粒度**：token级rank分析与表示级相似度分析虽确认了“有预测价值但非完美对齐”，但未分析更细粒度模式（如哪种类型的数据/输入状态从中获益最大）。
- **训练数据规模有限**：仅40K提示训练，且训练时长细节披露不足——后续工作或复现时对数据要求的具体性会是一个实际障碍。
