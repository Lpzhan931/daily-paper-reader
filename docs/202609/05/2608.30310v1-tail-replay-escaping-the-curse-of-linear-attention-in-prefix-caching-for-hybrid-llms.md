## 摘要
混合大语言模型将全注意力层与线性注意力层交错排列，以降低长上下文推理的成本。这种结构使前缀缓存复杂化：全注意力键值缓存是可按令牌寻址的，而线性注意力层维护的循环状态无法回滚到任意前缀边界。现有的混合前缀缓存方法通过存储循环状态检查点来解决这一不匹配问题。因此，令牌级别的匹配仅在与存储检查点对齐的位置可直接使用，将前缀重用限制在离散的边界集合上。我们提出了Tail-Replay，一种在混合大语言模型中实现无约束令牌级前缀重用的前缀缓存机制。关键洞察在于，诸如Gated DeltaNet之类的线性注意力机制可被视为对输入前缀的结构化有损压缩：门控循环更新会逐步衰减早期输入的贡献。因此，匹配前缀的循环状态可以通过仅重放该前缀的一个短暂近期后缀来很好地近似。Tail-Replay利用了这一特性，缓存精确的全注意力键值缓存，同时省略循环状态检查点。在缓存命中时，它通过重放匹配前缀的一个短暂近期后缀来重建线性注意力状态。因此，重用边界由共享令牌决定，而非循环状态检查点。我们使用LongBench和RULER基准评估了基于Gated DeltaNet的三种混合模型上的Tail-Replay。仅用5-10%的重放预算，它在LongBench和RULER上保留了完整预填充质量的92.8-99.9%。在服务效率方面，我们评估了在多个匹配前缀长度（8K、16K和32K）下的首令牌时间加速比。加速比随前缀长度增长，在32K时达到完整预填充的9.1-14.3倍。

## Abstract
Hybrid large language models interleave full-attention layers with linear-attention layers to reduce the cost of long-context inference. This structure complicates prefix caching: full-attention key-value caches are token-addressable, whereas linear-attention layers maintain recurrent states that cannot be rolled back to arbitrary prefix boundaries. Existing hybrid prefix caching methods address this mismatch by storing recurrent-state checkpoints. As a result, token-level matches are directly usable only at positions aligned with stored checkpoints, constraining prefix reuse to a discrete set of boundaries. We present Tail-Replay, a prefix caching mechanism that enables unconstrained token-level prefix reuse in hybrid large language models. The key insight is that linear-attention mechanisms such as Gated DeltaNet can be viewed as a structured, lossy compression of the input prefix: gated recurrent updates progressively attenuate the contributions of earlier inputs. Consequently, the recurrent state of a matched prefix can be well approximated by replaying only a short, recent suffix of that prefix. Tail-Replay exploits this property by caching the exact full-attention key-value cache while omitting recurrent-state checkpoints. On a cache hit, it reconstructs the linear-attention states by replaying a short, recent suffix of the matched prefix. As a result, the reuse boundary is determined by the shared tokens rather than by recurrent-state checkpoints. We evaluate Tail-Replay on three Gated DeltaNet-based hybrid models using the LongBench and RULER benchmarks. With only a 5--10\% replay budget, it retains 92.8--99.9\% of full-prefill quality on LongBench and RULER. For serving efficiency, we evaluate time-to-first-token speedups across multiple matched-prefix lengths---8K, 16K, and 32K. The speedup grows with prefix length, reaching $9.1$--$14.3\times$ over full prefill at 32K.

## 论文总结：Tail-Replay：在混合大语言模型的前缀缓存中逃离线性注意力的诅咒

### 一、核心问题与研究动机

混合大语言模型（Hybrid LLM）通过在架构中层叠少量全注意力（Full-Attention, FA）层和线性注意力（Linear-Attention）层，以降低长上下文推理开销。然而，这种架构给前缀缓存（Prefix Caching）带来了根本性困难：

- 全注意力层的 KV 缓存是**令牌可寻址的**（token-addressable），可针对任意前缀边界直接复用。
- 线性注意力层则通过就地更新将前缀压缩为**循环状态**（recurrent state），**无法回滚**到任意早期前缀。

现有混合前缀缓存方案（如 Marconi、Sparse Prefix Caching）通过存储循环状态检查点（checkpoint）来应对，但缓存命中率受限于离散的检查点边界，**令牌级前缀匹配无法被充分利用**。论文将这一矛盾称为“线性注意力的诅咒”。核心要解决的核心问题是：**如何在混合 LLM 中实现不受检查点约束的、任意令牌边界的无缝前缀复用。**

### 二、方法论：Tail-Replay

- **核心洞察**：Gated DeltaNet（GDN）等线性注意力可被视为对输入前缀的**有损压缩**：门控循环更新逐步衰减早期 token 的贡献，因此前缀的最终状态主要由近期 token 决定。由此，重放短近期后缀足以近似重建匹配前缀的循环状态。

- **缓存策略**：仅缓存精确的全注意力层 KV 状态和 FA 输出隐藏向量（FA output hidden），**不缓存任何循环状态检查点**。

- **分组独立重放**：为每个 FA 层及紧随其后的线性注意力层构建一个组。各组的输入隐藏向量因 FA 输出被缓存而保证了与原始 prefill 完全一致，从而**将重建误差限制在组内**。

- **重放过程**：当发生缓存命中时：
  1. 直接复用匹配前缀的 FA KV cache；
  2. 对于每个线性注意力组，从零状态 **S₀** 开始，只取最近 k 个（k = ⌈r·m⌉）缓存 FA 输出隐藏向量进行重放；
  3. 利用 GDN 更新公式重建出匹配前缀末尾的循环状态。

- **核心公式**（GDN 循环状态更新）：
  ```
  S_i = T_i S_{i-1} + β_i v_i k_i^T,  T_i = α_i (I - β_i k_i k_i^T)
  ```
  其中 α_i 为学习门控，控制对早期信息的衰减强度，Tail-Replay 正是利用这一门控衰减特性来实现近似。

- **两项性能优化**：
  1. **尾部 FFN 跳过**：重放时跳过线性注意力组末尾的 FFN 运算，因为下一个线性组将从已精确缓存的 FA 输出处开始，无需计算 FFN 输出；
  2. **传输与重放重叠**：FA KV 从主机内存到设备的传输与重放计算在独立流上并行执行，仅在查询前向传播前同步，有效隐藏数据传输延迟。

### 三、实验设计

- **模型**：三种基于 Gated DeltaNet 的混合 LLM——OLMo-Hybrid-7B、Qwen3.5-4B 和 Qwen3.6-27B。
- **基准数据集**：
  - **LongBench**（多任务长上下文理解）：包括 narrativeqa、hotpotqa、qasper、musique、qmsum，上下文长度从 16K 到 64K；
  - **RULER**（长上下文检索/计数能力）：包括 cwe、qa1、niah、vt，各覆盖 8K 和 16K 两种长度。
- **对比方法**：
  - **Full Prefill**：全量预填充（无缓存复用）；
  - **Zero-only**：仅复用 FA KV 缓存但将线性注意力状态置零，作为消融以区分状态重建的贡献；
  - **Tail-Replay（r = 5% 和 r = 10%）**：本文提出的两种重放预算；
  - 论文在引言中对比了 Marconi 和 Sparse Prefix Caching 等现有混合缓存方案，但实验部分未与其进行定量对比。
- **评测指标**：
  - **质量**：LongBench 各任务 F1/ROUGE-L 分数；RULER 各任务召回率；
  - **效率**：TTFT（Time-to-First-Token，从缓存传输/重放开始到生成首个 token 的时间），前缀长度分别约 8K、16K、32K；
  - 数据传输方式对比了串行 H2D 传输（H2D-SER）和重叠传输+FFN 跳过（H2D-OVL+skip）。

### 六、主要结论与发现

Tail-Replay 通过“缓存精确 FA 状态 + 重放短近期后缀”的方式代替“存储检查点”策略，实现了混合 LLM 中无约束的 token 级前缀复用：

- **质量保持**：在 LongBench 上，5% 重放预算保留 92.8–98.9% 的完整 prefill 质量，10% 预算时为 93.9–98.1%；在 RULER 上分别保留 93.1–99.9% 和 96.7–99.9%；
- **效率提升**：TTFT 加速比随匹配前缀长度增长而显著扩大——8K 时约 2.5–5.7×，16K 约 5.1–11.1×，32K 时最高可达到 9.1–14.3×；
- **数据传输优化有效**：相对于串行 H2D 传输模式，OVL+skip 在 32K 时进一步将 TTFT 降低 18–42%，说明重放与显存传输重叠能有效隐藏数据移动成本。

### 七、主要优点

- **问题定位有新意**：明确识别了混合架构中“token 级匹配≠状态可复用”的深层矛盾，并以“门控衰减”特性利用数据自身的近似可重建性替代存储检查点，另辟蹊径；
- **缓存开销更小**：省去所有线性注意力层状态检查点的存储和管理，从而显著简化缓存管理，并使缓存命中的边界不受离散检查点限制；
- **分组独立设计方案精细**：缓存每个 FA 层的输出隐藏向量以保障各线性注意力组的输入“完全一致”，从原理上把重建误差隔离在组内——设计上具备严谨性；
- **完善的两项工程优化**：FFN skip 可以避开不必要的重复计算；传输/重放重叠则把与缓存效率的矛盾降到最低，工程衔接较完整；
- **评测结果较扎实**：质量和效率均有多个模型、两个基准、多任务和多长度的验证，结论一致性很高，在质量和效率上的取舍关系被描述得较为清楚。

### 八、不足与局限

- **依赖特定线性注意力的遗忘特性**：方法建立在 Gated DeltaNet 等门控循环更新逐步衰减早期输入这一特性上。若线性注意力变体不具有该遗忘性（如固定权重、无门控的单纯线性注意力），近期重放近似误差可能会更大，方法的普适性尚缺乏评估；
- **实验范围偏窄**：评测集中在 8K–64K 范围，没有覆盖 128K 或以上更长的上下文；推理侧也主要是“理想化单前缀”的 TTFT 测度，缺少端到端服务器吞吐、多用户并发、缓存利用率等系统级结果，也缺少与已有缓存系统（Marconi、Sparse Prefix Caching）的定量直接对比；
- **和零状态基线对比**：虽然 Zero-only 效果很差，但论文提供该对比的目的主要在于隔离状态重建的价值；从工程质量角度看，仍需要与更接近工业的部署方案（也包含 FA KV cache 输出、仅截取长序列中的尾部，或者已有其他工作提到的“解码尾部不需要重放”等）进行对比；
- **重放预算增高后边际收益有限且代价上升**：在 TTFN 到最长 32K 时 10% 的重放预算会明显提高 TTFT，说明重放开销已成为限制因素，在更长上下文中如何扩展、是否可通过自适应重放比率优化需要继续研究；
- **没有披露有关超参选择的细节**，如重放比率的搜索与不同任务/不同前缀长度的关联性；在小模型（例如 4B 与 7B）性能差异的原因未深入分析；
- 论文的总篇幅有限（双栏共 7 页），部分实现细节和全系统延迟拆分的展示较为有限。

整体而言，Tail-Replay 给出的“检查点→重放”转换方向具有较强的启发价值：将线性注意力看作对前缀的上下文有损压缩，利用近期信息主导性的特点恢复状态，巧妙地绕开了混合模型前缀缓存的状态可回滚性问题。该方案在以类 Gated DeltaNet 为线性层的混合模型上效果显著，但其通用性、系统级规模验证和更长上下文的表现仍有较大的后续测试空间。
