## 摘要
混合专家（MoE）模型扩展了智能手机上语言模型的能力，但专家卸载仍受限于有限的 DRAM 容量和高昂的数据移动开销。顺序的 token 路由将专家执行与碎片化的闪存读取和多阶段 NPU 准备耦合在一起，使稀疏计算因权重传输而停滞。每次传输仅服务少量 token，执行便继续推进。我们利用推测解码的多 token 验证窗口，将专家移动与单 token 执行解耦，从而实现权重复用、连续闪存读取以及加载-计算重叠。我们提出 BigMoMo，一种移动端 MoE 运行时，可在整个内存层次中利用该窗口。它利用接受率、路由影响和移动成本来剪枝推测分支和专家激活；根据运行时共同加载模式重新组织闪存上的专家；并批处理就绪的专家，以将 NPU 计算与待处理的传输重叠。在两个移动平台的四个 MoE 模型和五个基准上，BigMoMo 相比按需自回归卸载平均实现 4.83 倍解码加速，相比最佳推测 MoE 基线实现 1.82 倍加速，支持高达 30B 参数的 MoE 模型。

## Abstract
Mixture-of-Experts (MoE) models expand language model capacity on smartphones, but expert offloading remains constrained by limited DRAM capacity and costly data movement. Sequential token routing couples expert execution to fragmented flash reads and multistage NPU preparation, leaving sparse computation stalled on weight transfers. Each transfer serves few tokens before execution moves on. We exploit the multi-token verification window of speculative decoding to decouple expert movement from single-token execution, enabling weight reuse, contiguous flash reads, and load-compute overlap. We present \textsc{BigMoMo}, a mobile MoE runtime that exploits this window across the memory hierarchy. It prunes speculative branches and expert activations using acceptance rates, routing impact, and movement cost; reorganizes on-flash experts according to runtime co-loading patterns; and batches ready experts to overlap NPU computation with pending transfers. Across four MoE models and five benchmarks on two mobile platforms, \textsc{BigMoMo} achieves mean decoding speedups of $4.83\times$ over on-demand autoregressive offloading and $1.82\times$ over the best speculative MoE baseline, supporting MoE models up to 30B parameter.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：移动端部署大语言模型需求增长，MoE（混合专家）模型通过稀疏激活（每 token 仅激活 top-k 专家）在有限计算下扩展模型容量。但 MoE 总参数量远超手机 DRAM 容量，现有方案采用参数卸载：将非专家权重和频繁访问专家放在 DRAM，其余专家放在闪存（UFS），按需加载。
- **核心矛盾**：移动端每一条从专家路由到专家执行的链路都受到资源约束，导致专家卸载效率低下：
  - **专家移动带宽受限**：手机 DRAM 容量小（通常 < 24GB，实际可用更少）、带宽低（LPDDR5X 最高约 78GB/s），更多专家必须留在闪存。
  - **闪存访问不规则且开销高**：闪存带宽仅约 4GB/s，且对访问粒度和连续性敏感；动态稀疏路由产生大量碎片化读取，严重浪费带宽。
  - **多阶段执行路径**：移动 NPU 推理需要 buffer 映射、权重搬运到 VTCM、反量化等多级准备，专家执行状态管理复杂，易产生流水线气泡。
- **现有方法不足**：已有 MoE 卸载工作（如 SpecMoEOff、SP-MoE、MoE-SpAc）多面向 CPU–GPU 平台，主机–设备带宽高、两层数据通路简单，可有效重叠专家移动。而移动端顺序 token 路由将专家执行与碎片化闪存读取、多阶段 NPU 准备耦合，每次专家移动仅服务单个 token，稀疏计算频繁停滞在权重传输上。
- **核心洞察**：推测解码的多 token 验证窗口天然提供了扩大的执行粒度，可将专家移动从单 token 执行中解耦，带来三个机会——权重复用（同一专家服务多个草稿 token）、闪存友好访问（合并碎片化读取为连续读取）、跨阶段移动重叠（更多计算可隐藏移动延迟）。
- **整体含义**：BigMoMo 证明移动端高效智能不必只依赖缩小模型容量；通过系统级数据移动解耦，可将 MoE 模型规模扩展至约 30B 参数并高效运行。

## 2. 论文提出的方法论

### 2.1 核心思想

从“模型级参数解耦”转向“系统级数据移动解耦”，利用推测解码的多 token 验证窗口扩大专家移动粒度，使专家移动与单 token 执行解耦，实现权重复用、连续闪存读取和加载–计算重叠。

### 2.2 三大关键技术

#### （1）面向复用的专家移动准入（§4.2）

- **接受感知节点剪枝**：对每个树深度 h 估计历史接受概率 p̂_h，结合草稿模型路径概率 q_u，定义节点价值：
  - **V(d) = p̂_h(d) · ∏_{u∈path(d)} q_u**
  - 按 V(d) 降序保留累计价值占比 ≥ ρ 的最小节点集合，剪除低价值推测分支。
- **层次感知专家剪枝**：定义专家 e 的路由影响：
  - **I(e) = Σ_{d∈D_e} V(d) · min_{j∈T_d\{e}} |s_{d,e} − s_{d,j}|**
  - 结合离线 profile 的专家移动成本 C_e，定义剪枝优先级：
    - **P(e) = ΔI_e / C_e**
  - 在累计路由影响预算 τ 下迭代剪枝，被剪专家的路由权重重分配给路由分数最接近的保留专家，每个节点至少保留一个专家。
- 目的：减少推测引入的无效专家移动与验证计算，同时保留专家共享机会。

#### （2）运行时自适应闪存专家组织（§4.3）

- **超图建模**：每个专家为顶点，一轮验证中共同加载的专家构成超边 M^k_l；最近 K 轮的重叠超边捕捉运行时共加载模式。
- **锚区域选择**：对每条超边 M^k_l，在所有可容纳 |M^k_l| 个专家的连续闪存区域中，选择驻留专家集与 M^k_l 重叠最大的区域作为锚区域 A^k_l。
- **重定位收益评估**：
  - 估计超边读取时间：**T^k_l = T_Flash(S(A^k_l)) + Σ_{e∈M^k_l\A^k_l} T_Flash(S(e))**
  - 候选交换 (e_i, e_j) 的收益：**B_l(e_i, e_j) = Σ_{r=k−K+1}^{k} (T^r_l − T̃^r_l(e_i, e_j))**
  - 选择收益最大且为正的可行交换增量执行。
- **实现约束**：交换仅在两个专家已加载到共享 DRAM 后执行，避免额外闪存读取；延迟敏感的加载请求优先于后台重组织。

#### （3）跨层次移动调度（§4.4）

- **VTCM 双缓冲**：将 VTCM 分为两个交替权重缓冲区和 128KiB 激活/输出区域，重叠权重搬运与 HMX 计算；过大专家沿输出维度 N 按 32 的倍数切分。
- **计算组调度**：
  - 估计各待处理专家的就绪时间 τ_map(e,t)（DRAM 驻留者仅含 NPU buffer 映射延迟；闪存驻留者额外含 Flash–DRAM 加载延迟）。
  - 下一专家就绪间隔：**τ_next(t) = min_{e∈E_pending(t)} τ_map(e,t)**
  - 未覆盖移动时间：**R_t = max(0, τ_next(t) − W_t)**，其中 W_t 为剩余 HMX 计算窗口。
  - 组选择策略：
    - 若存在候选组满足 T_VTCM(b) ≤ W_t 且 T_HMX(b) ≥ R_t，选择其中执行延迟最短者；
    - 否则在满足 T_VTCM(b) ≤ W_t 的候选中选择执行延迟最长者，以尽量覆盖估计间隔。
- 新就绪专家持续加入后续批次形成，计算无需等待全部专家就绪。
