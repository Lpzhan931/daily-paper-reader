## 摘要
将大型语言模型（LLM）直接部署在边缘的移动平台上，因隐私性增强、个性化以及降低延迟等诸多优势而日益受到关注。然而，LLM 具有沉重的计算需求，资源受限的移动与边缘平台难以满足。除了计算资源有限之外，移动和边缘系统通常外形紧凑，并且缺乏物理机制（例如风扇）来散发高处理器使用率产生的热量，以防止 LLM 很容易引发的降频和处理能力下降。为缓解这些影响，先前工作提出了多种功耗管理策略，例如动态电压频率调节（DVFS），以降低移动平台上重计算任务的功耗和发热。最近，也提出了面向移动 LLM 的 DVFS 方法。然而，这些方法大多聚焦于优化硬件参数和处理器频率，在一些热受限场景下表现不佳。受机器学习近期进展的启发，我们发现并利用了一个关键洞见：并非所有 token 都需要全深度推理才能保持高质量生成。受此驱动，我们提出 PELM，一种在传统 DVFS 处理器频率调优的基础上，增加两个额外的工作负载特定调节旋钮的解决方案：1）推测解码，2）可变验证深度，从而将优化空间扩展到多个维度，以实现更节能的端侧 LLM 推理。在跨硬件平台和数据集的广泛评估中，PELM 相比最先进的功耗管理方法表现出更优性能，最高实现 23.1% 的加速和 52.4% 的能耗降低，同时保持相当的任务性能。源代码见 https://github.com/imec-nu/PELM。

## Abstract
Deploying Large Language Models (LLMs) directly on mobile platforms at the edge is gaining traction due to a myriad of benefits, such as increased privacy, personalization, and reduced latency. However, LLMs have heavy computational requirements, which are difficult for resource-constrained mobile and edge platforms to fulfill. In addition to limited compute resources, mobile and edge systems often have a compact form factor and lack physical mechanisms to dissipate heat generated from high processor usage rates (e.g., fans) to prevent throttling and reduced processing power, which LLMs can easily cause. To mitigate these effects, prior works have proposed various power governing strategies, such as dynamic voltage and frequency scaling (DVFS), for reducing power and heat generation for heavy computational tasks on mobile platforms. Recently, DVFS methods tailored for mobile LLMs have also been proposed. However, these methods mostly focus on optimizing hardware parameters and processor frequencies, and they fall short under some thermally constrained scenarios. Drawing from recent advances in machine learning, we identify and take advantage of the key insight that not all tokens require full-depth inference to maintain high-quality generation. Motivated by this, we present PELM, a solution that augments traditional DVFS processor frequency tuning with two additional workload-specific knobs: 1) speculative decoding and 2) variable verification depth to expand the optimization space to multiple dimensions for more power efficient on-device LLM inference. In extensive evaluations across hardware platforms and datasets, PELM demonstrates superior performance compared to state-of-the-art power governing methods, with up to 23.1% speedup and 52.4% reduction in energy consumption, while maintaining comparable task performance. The source code is available at https://github.com/imec-nu/PELM.

# PELM 论文总结

## 1. 核心问题与整体含义

- **研究背景**：端侧（移动/边缘）部署 LLM 具有隐私、个性化、低延迟等优势，但 LLM 计算需求重，而移动设备算力有限、外形紧凑、缺乏风扇等散热机制，长时间推理极易触发热降频（thermal throttling），导致性能下降。
- **现有方法不足**：动态电压频率调节（DVFS）是主流功耗管理手段，利用 \(P \propto V^2 f\) 且 \(V \propto f\) 推出 \(P \propto f^3\)，小幅降频即可显著省电。但现有面向 LLM 的 DVFS 方案大多只调硬件频率，控制空间单一，陷入"降频省电则吞吐下降、升频保速则加剧发热"的两难，在热受限场景下表现不佳。
- **关键洞见**：并非所有 token 都需要全深度推理才能保持高质量生成。中间层输出已包含可用信息（作者在 LLaMA-3.1-8B 上验证，中间层任务得分与最终层相当），且存在"多对一映射"——多种（层数, 频率）组合可达相同 QoE，但能耗差异巨大（如 20 层@0.6GHz 与 32 层@1.3GHz 速度相同，前者省能 50.9%）。
- **整体含义**：论文提出 PELM，将传统 DVFS 的单一"频率"旋钮扩展为三维联合控制：**DVFS 频率（硬件）＋ 自推测解码（算法吞吐）＋ 可变验证深度（计算负载）**，在更大优化空间中实现端侧 LLM 的能效最优。

## 2. 方法论

- **核心思想**：把功耗治理建模为硬件参数与解码参数的联合优化问题，用深度强化学习（DQN）在线求解。
- **关键技术细节**：
  - **自推测解码（SSD）**：用模型自身前 \(ex\) 层作草稿模型，生成 \(ns\) 个草稿 token，再由验证模型一次并行验证。加速比 \(R = (n_{ac} \times L)/(n_s \times e_x + L)\)，其中 \(n_{ac}\) 为接受 token 数。
  - **可变验证深度**：验证模型不必跑满 \(L\) 层，只用 \(vd\) 层（\(n_s < vd \le L\)），加速比变为 \(R = (n_{ac} \times vd)/(n_s \times e_x + vd)\)，进一步省算力。
  - **HQCache（Hidden Queue Cache）**：解决可变深度导致的 KV-cache 缺失——当当前 token 目标深度超过前序 token 时，从已缓存的最深层隐藏状态恢复并续算，而非从第 1 层重算，并推广到草稿与验证两阶段。
- **公式/流程（文字说明）**：
  - 原始 DVFS 目标：\(\min E_q[J(q)]\)，约束 \(T_{temp}(t) < T_{limit}\)、\(S(q) \ge S_{target}\)。
  - PELM 将目标改写为加权标量化多目标：\(\min E_q[\lambda_p p(f,q) + \lambda_\phi(1-\phi(vd|q)) + \lambda_R(-R(e_x,n_s|vd,q))]\)，新增**输出保真度 \(\phi\)**（以 \(vd\) 为代理）作为新 QoE 维度。
  - 转化为 Q-learning：\(\max_\pi E_\pi[Q_\pi(s,a)]\)，用 Bellman 方程迭代，因状态/动作空间大，用 DQN 近似 Q 函数。
  - **状态**：CPU/GPU 功耗与利用率、温度及其变化率、解码速度、可变深度、推测加速比、CPU/GPU 频率。
  - **动作**：CPU/GPU 频率、退出层 \(e_x\)、推测次数 \(n_s\)、可变深度 \(vd\)。
  - **奖励**：\(r = r_S + r_{vd} + r_{thermal} + r_u + r_p\)（速度奖励、可变深度奖励、热惩罚、利用率-频率匹配惩罚、功耗惩罚）。
  - **探索策略**：非随机采样，而是知识引导行为策略（借鉴 AIMD 拥塞控制思想），依据热余量、速度比 \(S/S_{target}\)、推测加速比做加减频与深度调整；推测部分用前后步加速比对比形成反馈闭环。
  - **算法流程**：每 100ms 一个控制窗口，DQN 选动作 → 更新 CPU/GPU 频率与解码参数 → 执行 → 观测新状态 → 计算奖励 → 存入回放池 → 小批量更新参数、周期性同步目标网络。
  - **网络实现**：采用 Branch-DQN 分解高维动作空间（AGX Orin 上 CPU 各簇 29 档、GPU 11 档），策略网络仅 5,687 参数（约 22KB FP32），纯 CPU 运行。

## 3. 实验设计

- **数据集/场景**：从 5 个代表性数据集各均匀采样 40 条构成移动规模数据集——GSM8K（数学推理）、NQ-open（问答）、HumanEval（代码生成）、WMT14-DE-EN（机器翻译）、CNN/Daily Mail（文本摘要）。
- **模型**：LLaMA-3.2-1B、LLaMA-3.1-8B、LLaMA-2-13B（均基于 LayerSkip 预训练，暴露早期退出头），HuggingFace Transformers + PyTorch，batch size=1。
- **硬件平台**：NVIDIA Jetson AGX Orin（高端）与 Jetson Orin Nano（低端），JetPack 6.2.1 / Ubuntu 22.04.5。
- **热场景**：固定风扇 PWM 定义 4 种冷却条件（AGX Orin：64/51/38/26；Nano：90/77/64/51），统一从 45℃ 起始，热失效阈值 78℃（AGX）/73℃（Nano）。
- **Benchmark 与对比方法**：
  - BLTN（系统默认 governor：schedutil + nvhost_podgov）
  - STSD（静态自推测解码，前 1/4 层为草稿，草稿长度固定 3）
  - FUSE（基于搜索的移动 LLM DVFS）
  - zTT（RL 驱动的 DNN DVFS 框架）
- **评价指标**：
  - DVFS 层：解码速度（Tokens/s）、能耗（Joules）、完成率 CR、每接受 token 层数 LPAT、平均可变深度 VDm、推测比 SR。
  - 任务层：各数据集标准指标（Accuracy、EM、pass@1、BLEU、ROUGE-L），归一化后求 TSA；再定义 PPJ = TSA/Energy。

## 4. 资源与算力

## 6. 主要结论与发现

- **能效**：相比 SOTA 功耗治理方法，PELM 最高实现 **23.1% 加速、52.4% 能耗降低**，同时保持相当任务性能（最大退化 <17.2%）；PPJ 最高提升 45.4%。
- **重负载**：13B/8B 在 AGX Orin 上 PELM 能耗最低（较其他方法省 29.0%–52.4%），且多数冷却条件下速度最高；GPU 平均频率显著低于基线（如 13B-High 为 0.57 vs. BLTN/STSD 的 0.91）。
- **轻负载**：1B 模型上 PELM 反而**主动提高频率**（0.52 vs. BLTN 0.28），因为热余量充足，需满足 25 tokens/s 的 QoE 目标——体现双向自适应能力。
- **鲁棒性**：PELM 与 zTT 在几乎所有场景 CR 达 100%；最恶劣场景（13B + 最低冷却）PELM 完成 45% 查询，优于 zTT 的 34%，处理量多 32.4%。
- **消融结论**：去掉可变深度（A1）普遍降低 PPJ、增加 LPAT；去掉推测解码（A2）损失最大（更慢更耗能）；去掉频率控制（A3）仅在轻负载 1B 上有效，在中重负载下能耗严重劣化。
- **查询局部性**：聚类查询可提升推测加速比 SR（24 例中 18 例改善），降低 LPAT 与能耗；但小模型（1B@Nano）上效果不稳定，任务质量方差更大。
- **开销**：DQN 与 HQCache 开销可忽略，PELM 不增加 CPU 功耗（约 1.8–2.2W），却大幅降低 GPU 功耗（8B@AGX 中等冷却：12.39W vs. 20–21W）。

## 7. 优点

- **跨层协同设计**：首次将机器学习领域的推测解码与系统领域的 DVFS 功耗管理结合，突破了"仅调硬件频率"或"仅调解码算法"的单维局限。
- **多目标形式化**：显式引入"输出保真度 \(\phi\)"作为新 QoE 维度，并以验证深度 \(vd\) 为代理，使问题可解且贴合实际。
- **知识引导探索**：摒弃随机探索，采用受 AIMD 启发的行为策略，显著提升学习效率与稳定性。
- **HQCache 机制**：将隐藏状态缓存推广到任意层并同时用于草稿与验证，实测恢复延迟比单层重算快 46–60 倍，内存占用 <1% 模型权重。
- **实验严谨**：多平台、多模型、多热条件、多任务域，配合完整 leave-one-out 消融与系统开销实测，结论可信度高；代码开源。
- **自适应能力强**：能根据负载与热状态双向调节（重负载省电、轻负载提频），并利用查询局部性提升推测效率。

## 8. 不足与局限

- **模型依赖**：PELM 需要能暴露中间层输出的模型（早期退出监督），目前公开可用的此类模型主要集中在 LLaMA 家族（LayerSkip）；迁移到 Phi、Qwen 等其他家族需在预训练/微调阶段加入中间层监督。
- **未评估量化**：工作聚焦未量化权重，以隔离跨层控制行为；量化模型下的中间层一致性与 HQCache 状态恢复验证留作未来工作。
- **平台局限**：仅在 NVIDIA Jetson 平台验证，移植到其他 SoC（异构 CPU/GPU/NPU governor）需重新映射控制旋钮并调参。
- **未考虑并发负载**：未评估后台并发任务与平台级 DVFS 策略的交互，多租户边缘环境下的鲁棒性待验证。
- **小样本与波动**：每数据集仅 40 条，任务得分方差较大；1B 小模型上推测正确率受限，局部性收益不稳定，PPJ 并非总最优。
- **非全局最优场景**：轻负载（1B）下 PELM 有时能耗略高于最低能耗基线（0.4%–7.3%），是以满足 QoE 目标为代价的权衡，而非单纯能效最优。
- **训练算力未披露**：论文未说明大模型预训练/早期退出头训练的资源消耗，复现与成本评估受限。
