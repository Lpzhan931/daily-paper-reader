## 摘要
投机解码通过并行验证多个草拟 token 来加速 LLM 推理，使一次目标模型前向传播能够接受多个 token。按构造，验证过程会为被接受和被拒绝的 token 都计算表示。然而，传统草拟器仅保留被接受 token 的表示，导致花费在被拒绝 token 上的大量验证器计算实际上被浪费。我们发现，目标前向过程中产生的这些被丢弃隐藏状态保留有关未来 token 的有用信息，可改进后续草拟。然而，实现这一机会面临两个不同挑战。在推理时，回收开销可能增加草拟延迟，从而削弱因接受长度增加而获得的加速。在训练时，标准并行草拟器训练不会产生与推理对齐的被拒绝状态，而通过顺序 rollout 获取它们会牺牲跨训练位置的并行性。我们提出 Carryover Drafting，可同时解决这两个挑战。Carryover 将被拒绝的目标隐藏状态回收为临时 KV 上下文，使草拟器能够选择性地关注它们。它复用草拟器现有接口，仅添加一个学习到的嵌入来区分被拒绝状态与已提交上下文。额外的 KV 上下文在每个草拟轮次都会被替换，使其长度以一个提议块为界。我们提出并行 draft--verify--draft 训练，使草拟器接触到与推理对齐的被拒绝状态，同时保持跨训练位置的并行性。在 DFlash 和基于 DSpark 的半自回归草拟器上、跨两个目标模型的实验表明，这一简单的 Carryover 机制相较于相应基线将平均接受长度提高 6.5--14.7%，端到端 vLLM 加速提高 7.9--14.4%，在翻译任务上加速增益达到 28.8%。

## Abstract
Speculative decoding accelerates LLM inference by verifying multiple drafted tokens in parallel, allowing a single target forward pass to accept several tokens. By construction, verification computes representations for both accepted and rejected tokens. Yet, conventional drafters retain only the representations of accepted tokens, leaving the substantial verifier computation spent on rejected tokens effectively wasted. We find that these discarded hidden states generated during target forward retain useful information about future tokens that can improve subsequent drafts. However, realizing this opportunity poses two distinct challenges. At inference, recycling overhead can increase drafting latency, diminishing the speedup gained from increased acceptance length. During training, standard parallel drafter training does not produce inference-aligned rejected states, while obtaining them through sequential rollouts would sacrifice parallelism across training positions. We introduce Carryover Drafting, which addresses both challenges. Carryover recycles rejected target hidden states as temporary KV context, allowing the drafter to selectively attend to them. It reuses the drafter's existing interface and adds only a single learned embedding to distinguish rejected states from committed context. The additional KV context is replaced each drafting round, keeping its length bounded by one proposal block. We introduce parallel draft--verify--draft training that exposes the drafter to inference-aligned rejected states while preserving parallelism across training positions. Experiments with DFlash and a DSpark-derived semi-autoregressive drafter across two target models show that this simple Carryover mechanism improves average acceptance length by 6.5--14.7% and end-to-end vLLM speedup by 7.9--14.4% over the corresponding baselines, with speedup gains reaching 28.8% on translation.

# Carryover Drafting 论文总结

## 1. 核心问题与研究动机

- **背景**：投机解码（Speculative Decoding）通过一个轻量级草拟器（drafter）并行提议多个 token，再由目标模型（target）在一次前向传播中并行验证，从而一次接受多个 token 来加速 LLM 推理。
- **关键观察**：验证过程在构造上会同时为**被接受**和**被拒绝**的 token 计算隐藏状态表示。然而，传统草拟器（如 EAGLE、DFlash、DSpark）**只保留被接受 token 的表示，丢弃被拒绝 token 的表示**，导致大量验证器计算被浪费。
- **核心假设**：目标前向过程中产生的这些被丢弃的隐藏状态，其实保留了关于未来 token 的有用信息，可以改进后续草拟。
- **两大挑战**：
  - **推理阶段**：回收开销可能增加草拟延迟，削弱因接受长度增加带来的加速；若跨轮次保留拒绝状态，KV 上下文会无限增长。
  - **训练阶段**：标准并行草拟器训练（基于记录的 target 响应）不会产生推理时对齐的拒绝状态；而顺序 rollout 获取这些状态会牺牲训练位置间的并行性。
- **整体含义**：论文提出 Carryover Drafting，将"被浪费的验证计算"转化为可复用的草拟上下文，在不显著增加开销的前提下提升草拟质量与端到端速度。

## 2. 方法论

### 2.1 核心思想
- 将上一轮验证中**被拒绝的目标隐藏状态**回收为**临时 KV 上下文**，让草拟器通过其**现有注意力层**选择性关注它们。
- 复用草拟器已有的投影接口，仅新增**一个学习嵌入** `E_carry` 来区分"被拒绝状态"与"已提交上下文"。
- 额外 KV 上下文每轮**被替换**，长度以一个提议块（B 行/层）为界，避免无限增长。

### 2.2 关键技术细节与公式

**记号**：第 r 轮草拟 B 个 token，目标接受前 m 个，`H_r` 为目标隐藏状态；`H_acc = h_{1:m}`，`H_rej = h_{m+1:B}`。

- **投影与 KV 生成**（复用现有接口）：
  `Φ_ℓ(H) = (K_ℓ(F(H)), V_ℓ(F(H)))`
  其中 F 为现有投影，K_ℓ、V_ℓ 为草拟器第 ℓ 层投影。
- **Carryover 更新**：
  `U_{r+1,ℓ} = Φ_ℓ(H_rej + E_carry)`
  `ctx_{r+1,ℓ} = [C_{r+1,ℓ} ; U_{r+1,ℓ}]`
  其中 C 为已提交草拟器 KV 上下文，U 为临时回收上下文。
- **延迟与加速模型**：
  `L_carry ≈ (t_draft + t_verify + t_reuse) / τ`
  `S_carry ≈ τ·t_AR / (t_draft + t_verify + t_reuse)`
  其中 t_reuse 为回收带来的额外草拟延迟；要求"接受长度提升 > 回收开销"。
- **缓存语义**：拒绝状态仅作为**只读**草拟器上下文，不进入目标 KV cache，不替换已接受 token 的隐藏状态；完全接受时 U 为空。

### 2.3 并行 draft–verify–draft 训练

- 在记录的目标响应 y 上随机采样 512 个 anchor a_i。
- **第 1 步（无梯度）**：草拟器在 anchor 处生成 detached 提议 d_i。
- **第 2 步（冻结目标）**：目标用块对角因果掩码并行验证各分支，得到接受长度 m_i 与 detached 拒绝状态 H_rej_i。
- **第 3 步（有梯度）**：anchor 移位到 a'_i = a_i + m_i + 1（下一个修正/bonus 位置），第二次草拟读取记录前缀与 H_rej_i，学习记录的后继；梯度只流过第二次草拟（含共享投影与 E_carry）。
- **保持并行性**：每个 anchor 独立构造局部 transition，无需完整多轮 rollout；不新增目标采样数据，记录响应仍是监督来源。

### 2.4 算法流程（文字版）

**推理更新（Algorithm 1）**：
1. 保留所有状态 H_{1:B}，仅对 H_{m+1:B} 加 E_carry；
2. 经现有 F、K_ℓ、V_ℓ 投影得到 J_ℓ；
3. 已接受部分追加到 C_ℓ，拒绝部分作为 U_ℓ 替换旧 U；
4. ctx_ℓ = [C_ℓ; U_ℓ]，供下一轮草拟读取。

**训练更新（Algorithm 2）**：随机采样 anchor → 无梯度 draft–verify → 计算移位 anchor 与拒绝状态 → 第二次草拟（有梯度）→ 用基线损失更新 θ 与 E_carry。

## 6. 主要结论与发现

- **接受长度**：平均提升 **6.5–14.7%**，覆盖全部 8 个数据集、2 个目标模型、2 种草拟器、2 个温度。
- **端到端加速**：vLLM 加速比相对基线提升 **7.9–14.4%**；翻译任务最高达 **28.8%**（Qwen3-4B Markov，T=1）。
- **跨草拟器有效**：从纯并行 DFlash 到半自回归 Markov，Carryover 均有效，说明与"块内依赖建模"互补。
- **任务差异来源**：增益与 **re-convergence（拒绝轨迹与最终提交 token 的重合度）** 相关性最高（r=0.96，去掉翻译为 0.90），而非拒绝状态数量（r=0.74）或拒绝后接受次数（r=0.52）。
- **机理证据**：matched-anchor 下 Carryover ON 相比 OFF 在 Recall@1 提升 1.28–5.60 点、Recall@16 提升 0.29–1.89 点；注意力诊断显示 **19.78%** 的 softmax 注意力落在回收行上（15 个拒绝状态子集为 23.40%）。
- **更强草拟器收益更大**：Markov 的 re-convergence 高于 DFlash（2.76 vs. 2.51），在 8 个数据集中 7 个取得更大增益，暗示随草拟器变强 Carryover 收益可能增长。
- **理论正确性**：Carryover 改变提议分布 q 但不改变目标概率与接受规则，因此不破坏投机采样的分布保真性。

## 7. 优点

- **轻量且易集成**：仅新增一个学习嵌入，复用现有投影与注意力接口；额外 KV 上下文每轮替换，长度上界为 1 个提议块。
- **训练–推理对齐**：并行 draft–verify–draft 在不做顺序 rollout 的前提下生成推理对齐的拒绝状态，保留跨位置并行训练。
- **不引入额外数据**：复用同一记录响应与相同监督，verification 只提供移位位置与拒绝状态。
- **严格不破坏正确性**：拒绝状态仅作只读草拟上下文，不写入目标 KV cache，分布保真性论证清晰。
- **实验扎实且可解释**：不仅有主结果与消融，还提供 recall、注意力、re-convergence 等多层次机理分析，并诚实指出消融未完全隔离变量。
- **任务洞察有价值**：指出"拒绝状态的预测性（re-convergence）"而非"数量"决定收益，为后续研究提供方向。

## 8. 不足与局限

- **未与置信度调度结合**：DSpark 的 confidence scheduling 会改变可用的拒绝状态与阈值校准，论文明确**未评估** Carryover 在该策略下的表现。
- **树解码未探索**：与 Medusa、DDTree 等树验证结合是自然延伸，但涉及"保留哪个分支状态"的新设计问题，留作未来工作。
- **仅单轮回收**：并行训练只覆盖一轮 carryover；多轮保留需要 rollout 训练，当前未实现。
- **算力报告不完整**：未披露训练 GPU 数量、总时长或能耗，影响可复现性与成本评估。
- **评估覆盖有限**：benchmark 以英文/代码为主，未涉及多语言、长上下文、超长生成；并发扫描最高仅 32。
- **消融隔离性不足**：token hint vs. hidden state 的对比同时改变信息内容与注入路径，无法完全归因。
- **额外开销仍存在**：t_reuse 会随回收状态数增加；在高并发下基线收益本身衰减，Carryover 的相对增益也随之下降（如 Qwen3-4B DFlash 在 concurrency=32 时为 +7.6%）。
- **超参数敏感**：E_carry 与单独 projector 的对比显示嵌入设计接近但略低于专用投影，存在进一步优化空间。
