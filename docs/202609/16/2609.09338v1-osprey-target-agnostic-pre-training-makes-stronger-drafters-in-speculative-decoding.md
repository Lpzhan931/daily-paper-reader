## 摘要
投机解码对于加速 LLM 推理至关重要。然而，这种加速很脆弱：草稿模型通常针对单一目标模型的窄分布进行训练，一旦工作负载发生变化，其接受率就会急剧下降。这与现代 LLM 开发形成了鲜明反差：目标模型的价值恰恰在于其通过大规模预训练获得的广泛泛化能力。我们认为，自然的补救措施——预训练——一直难以应用于草稿模型，因为现有方案都是目标特定的：草稿模型会接收目标模型的隐藏状态，并基于目标模型的 logits 进行蒸馏，因此必须为每个目标重复预训练。我们提出 Osprey，它转而从现成的预训练小型语言模型出发来构建草稿模型，将广泛的预训练视为可复用、目标无关的资产，并将针对每个目标的工作缩减为一个轻量级适配步骤。实现这一点需要克服两个挑战：小型语言模型的深度远超受延迟约束的草稿模型所能承受的程度，并且草稿模型在学习接收目标隐藏状态并以目标词表输出 token 时，必须保持其预训练计算完好无损。Osprey 通过以下方式解决这两个问题：剪枝得到浅层骨干网络，以目标无关的下一 token 预训练恢复其语言建模能力，并通过词表对齐、零初始化 QKV 扩展以及从目标模型输出分布中蒸馏，将其适配到每个目标。实验上，单个预训练的 Osprey 骨干网络可以跨目标迁移，并将 Qwen3-8B 的平均接受长度提高 16.1%，Llama-3.3-70B-Instruct 提高 21.2%，229B 的 MiniMax-M2.5 提高 22.7%（每秒 token 数提高 17.5%），且在域外和多语言数据上提升最大。我们的代码见 https://github.com/LeanModels/Osprey。

## Abstract
Speculative decoding is critical for accelerating LLM inference. However, the speedup is fragile: drafters are typically trained against a narrow distribution for a single target model, and their acceptance rate collapses under workload shifts. This is a striking inversion of modern LLM development, where target models are valued precisely for the broad generalization they acquire through large-scale pretraining. We argue that the natural remedy, pretraining, has been hard to apply to drafters because existing recipes are target-specific: the drafter consumes the target's hidden states and is distilled on the target's logits, so pretraining must be repeated for each target. We introduce Osprey, which instead bootstraps drafters from off-the-shelf pretrained small language models, treating broad pretraining as a reusable, target-agnostic asset and reducing per-target work to a lightweight adaptation step. Realizing this requires overcoming two challenges: small LMs are far deeper than a latency-bound drafter can afford, and their pretrained computation must remain intact while the drafter learns to ingest target hidden states and emit tokens in the target's vocabulary. Osprey addresses both by pruning to a shallow backbone, restoring its language-modeling capability with target-agnostic next-token pretraining, and adapting it to each target through vocabulary alignment, zero-initialized QKV expansion, and distillation from the target model's output distribution. Empirically, a single pretrained Osprey backbone transfers across targets and improves mean acceptance length by 16.1% for Qwen3-8B, 21.2% for Llama-3.3-70B-Instruct, and 22.7% for the 229B MiniMax-M2.5 (with 17.5% higher tokens per second), with the largest gains on out-of-domain and multilingual data. Our code is available at https://github.com/LeanModels/Osprey.

# Osprey 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：投机解码（Speculative Decoding）是加速 LLM 推理的关键技术，通过轻量草稿模型（drafter）提出多个候选 token、由大目标模型并行验证，实现无损加速（常见 2–5× 加速）。
- **核心痛点**：加速效果**脆弱**。草稿模型通常针对**单一目标模型的窄数据分布**训练，一旦服务负载发生域偏移（chat→code、通用 QA→领域推理、短回答→长文本生成），接受率急剧下降，加速收益随之崩塌。
- **实证证据**：EAGLE3 在数学数据上训练时，数学域平均接受长度 5.06，但在代码域仅 1.86；跨域矩阵显示明显的域内/域外落差（OOD/ID 保留率仅 0.75）。
- **关键反差**：现代 LLM 开发中，目标模型的价值恰恰来自大规模预训练带来的广泛泛化；而加速它们的草稿模型却继承了小模型的低延迟、却没有继承大模型的泛化能力。
- **为何预训练难以直接用于草稿模型**：现有草稿方案本质是**目标特定**的——草稿模型消费目标的隐藏状态、在目标的 logits 上蒸馏，因此预训练必须对每个目标重复，无法复用。
- **论文主张**：把现成预训练小语言模型（SLM）的广泛预训练当作**可复用、目标无关（target-agnostic）的资产**，将每个目标的工作缩减为轻量适配。

## 2. 方法论：Osprey 四阶段流水线

### 核心思想
将草稿模型构建拆分为**两个阶段**：一次性的「目标无关阶段」（剪枝 + 预训练）与针对每个目标的「目标特定阶段」（转换 + 蒸馏），从而把通用语言先验与目标条件化解耦。

### 阶段 1：剪枝（Prune，目标无关）
- 从现成 SLM 中只保留**输入嵌入、最终归一化层、LM head 及前 N 个 Transformer 块**，N ∈ {1, 2, 3, 4}。
- 示例：Qwen3-4B 保留 2/36 层 → 约 591M 参数；LayerSkip-Llama3.2-1B 保留 4/16 层 → 约 506M 参数。
- 偏好 LayerSkip 这类**带早退训练目标**的模型作为初始化，因中间层已被显式训练为下一 token 预测器，剪枝后初始损失更低（约 4.5 vs 13.5 nats）。

### 阶段 2：目标无关预训练（Pretrain，off-policy）
- 用标准下一 token 预测（NTP）目标在通用语料上继续预训练，恢复剪枝后受损的语言建模能力。
- 数据：FineWeb 100B token 采样，训练 5 个 epoch（约 462–503B token）；**有意超出该规模模型的 compute-optimal 分配**，目标是获得泛化先验而非最小化预训练成本。
- 产物：**Shallow NTP Backbone**（浅层 NTP 骨干），可跨目标复用。

### 阶段 3：草稿模型转换（Adapt，per target）
三个组件：
- **多层目标隐藏状态**：沿用 EAGLE-3，从目标模型的低/中/高三层抽取隐藏状态，拼接后经新初始化的线性投影映射到草稿隐藏空间：`c_t = W_c · [h_t^(ℓ_low); h_t^(ℓ_mid); h_t^(ℓ_high)]`，作为每个注意力层的输入。
- **零初始化 QKV 扩展**：将投影表示 `c_{t−1}` 与 token 侧表示 `z_t` 拼接，对预训练 QKV 投影右接零初始化列：`W̃_qkv = [0 | W_qkv]`。因新列为零，初始时刻 `W̃_qkv [c_{t−1}; z_t] = W_qkv z_t`，即**目标隐藏状态初始不影响草稿计算**，预训练的 target-agnostic 行为被完整保留，训练中再逐步学习使用目标特征。
- **词表对齐**：将草稿嵌入与 LM head 调整为目标的 |V_T| 大小，但**从草稿自身预训练权重初始化**（而非从目标模型复制）。共享 token 直接复制对应行；目标独有 token 将其字符串用源 tokenizer 分词后取源 token 行的均值：`W̃[v] = mean_{i=1..m_v} W_S[s_i]`。

### 阶段 4：目标适配（Distill，on-policy）
- 冻结目标模型，采用 EAGLE-3 的 **Training-Time Test（TTT）** 框架对齐训练与推理：输入 token 教师强制，草稿隐藏状态轨迹自回归生成。
- 损失为**折扣蒸馏损失**（λ=0.8，强调靠前的草稿步）：
  `L_adapt = Σ_{k=0}^{K_train−1} λ^k · CE(p_θ^(k), q_ϕ^(k))`
- 训练中所有草稿参数（含预训练与新增部分）均更新。

### 关键设计取舍
- 不修改验证流程、不改动目标模型，仅改进辅助草稿模型，与「无草稿并行解码」「多 token 预测」类方法正交。
- 贡献不是新的蒸馏目标，而是**更强的学生初始化 + 可复用适配路径**。

## 6. 主要结论与发现

- **单个目标无关骨干可跨目标复用**：由 Qwen3-4B 剪枝为 2 层得到的骨干，可适配到 Qwen、Llama、MiniMax 三个不同家族（含 dense 与 MoE、不同 tokenizer 与隐藏维度）。
- **平均接受长度提升**：Qwen3-8B **+16.1%**（3.686 vs 3.176）、Llama-3.3-70B-Instruct **+21.2%**（相对复现基线；相对官方 checkpoint +27.5%）、MiniMax-M2.5 **+22.7%**（3.232 vs 2.634）。
- **吞吐提升**：Llama-3.3-70B +17.9%（相对复现基线）、MiniMax-M2.5 +17.5%（219.8 vs 187.1 TPS）。
- **OOD 增益更大**：OOD AL 提升 17.3%（3.493 vs 2.977），高于 ID 的 12.4%；OOD/ID 保留率更高（0.782 vs 0.750）。多语言上 MGSM +12.4%、Global-MMLU +23.8%、native 回答 +15.4%——尽管适配仅用代码数据。
- **收益来自预训练先验而非容量**：参数匹配的 2 层 EAGLE-3 仅比 1 层高 0.094 AL（3.385 vs 3.291），而 Osprey 高出 2 层 EAGLE-3 达 0.405 AL。
- **Stage 2 确有贡献**：加入目标无关预训练使整体 AL 从 3.605 → 3.790（+0.185），ID 与 OOD 均提升。
- **预训练收益快速饱和**：10k 步与 55k 步 checkpoint 下游差距仅 0.026 AL，OOD/ID 保留率几乎相同（0.799 vs 0.800）；交叉熵从约 19 快速降至 5 nats，困惑度约 10k 步后平台化于 37。
- **学习率鲁棒性显著更强**：lr 从 10⁻⁴ 降至 10⁻⁵，warm-start 仅损失 0.11 AL，从零训练基线损失 1.07 AL。
- **DFlash 扩散草稿的旁证**：warm-start 在原始 DFlash 接口下增益很小（≤0.07），但在保留预训练注意力路径的 EAGLE 式接口下 OOD 均值从 1.68 提升到 2.00，说明**目标特征注入接口的设计决定了 warm-start 收益能否存活**。

## 7. 优点

- **问题定位清晰且有意义**：把「草稿模型的域偏移脆弱性」与「目标模型的预训练泛化」形成鲜明对照，动机叙述有力。
- **解耦设计优雅**：将昂贵的通用预训练（一次性）与轻量目标适配分离，单一 checkpoint 跨多个目标复用，工程经济学合理。
- **零初始化 QKV 扩展是关键巧思**：使适配起点在功能上**完全等价于预训练 checkpoint**，从而干净地隔离「预训练先验」与「目标条件化」的贡献，也避免破坏预训练计算。
- **词表对齐无需辅助语料**：直接用源 tokenizer 对目标 token 字符串分词取均值初始化，简洁且实用（继承 FVT/WECHSEL 思路）。
- **实验设计有说服力**：跨 3 个模型家族、dense/MoE、8B–229B；5×5 跨域矩阵；参数匹配基线；学习率与预训练预算消融；服务配置敏感性扫描。
- **算力核算透明**：明确给出 GPU 型号、数量、墙钟时间、GPU-hours、盈亏平衡 token 量，并说明为何从零大规模蒸馏不可行。
- **鲁棒性与泛化证据强**：OOD 与多语言提升最大，学习率不敏感，且在多 batch/多 chain/采样温度下增益持续。
- **附录延伸验证**：把 warm-start 思想推广到扩散草稿（DFlash），并揭示接口设计对收益的影响，具有额外启发性。

## 8. 不足与局限

- **结果多为单次运行**：缺少多种子重复，小幅度差异（如 10k vs 55k 的 0.026）不应过度解读。
- **预训练成本前置，回收有前提**：Stage 2 需 576–3,040 H100-hours 的一次性投入，仅在**持续高流量服务或多目标复用**场景下才回本；低流量、一次性部署不划算。论文明确承认这一点。
- **评测覆盖有限**：仅 3 个目标模型；跨域仅 5 个域；MiniMax-M2.5 适配仅用代码数据；未穷尽语言、任务与真实部署分布。
- **服务配置固定**：仅在特定 SGLang 配置（batch=1、steps=5、topk=1 等）下报告主结果，硬件/批量/负载变化下的表现不确定。
- **对比公平性的个别缺口**：MiniMax-M2.5 的公开 EAGLE-3 基线训练成本未报告，作者主动声明不做成本对等主张；官方 EAGLE-3 checkpoint 的训练数据/预算与 Osprey 未必一致（尽管作者同时提供了受控复现基线）。
- **未涉及安全/偏见维度**：论文指出提升推理效率会同时降低有益与有害用途的成本，且方法本身不缓解偏见、事实性与安全性问题。
- **方法依赖若干既有组件**：TTT 损失、三层隐藏状态抽取、词表迁移等均沿用已有工作，贡献偏「组合与初始化路径」而非全新机制；其收益在多大程度上依赖 EAGLE-3 特定接口仍有待更广泛验证（DFlash 消融已部分暗示接口敏感性）。
- **预训练数据单一**：Stage 2 仅用 FineWeb（英文为主），多语言泛化增益虽显著，但未探索多语预训练能否进一步放大该优势。
