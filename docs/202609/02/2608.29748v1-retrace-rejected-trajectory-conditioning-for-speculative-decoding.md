## 摘要
推测解码通过让轻量级的草稿模型提出多个候选标记，并由更大的目标模型并行验证，从而加速自回归语言模型的推理。然而，在第一次拒绝之后，基于前缀的标准验证会丢弃剩余的草稿后缀，因此生成和验证这些位置所花费的计算不会促进解码进度。我们以 DFlash 为对象，表明被拒绝的后缀中被拒绝的位置仍可能与目标延续对齐，这表示草稿模型尽管存在局部词元级错误，仍能保留有用的语义和结构信息。受此观察的启发，并借鉴条件扩散的思想，我们提出了 ReTrace，一种拒绝轨迹条件化方法，它使每个草稿块基于上一轮的拒绝后缀进行条件化，而不是仅从新掩码占位符生成。ReTrace 保留被拒绝后缀的隐藏表示，将它们与下一个草稿块对齐，使用来自同一验证过程的目标感知校正信号对其进行细化，并通过门控残差融合将其纳入草稿模型的输入嵌入。由于被拒绝的标记永远不会被提交，且目标端验证保持不变，ReTrace 不需要额外的模型前向传播即可保持推测解码的无损特性。在使用 Qwen3 模型进行的数学推理、代码生成和开放式对话实验中，ReTrace 在其 DFlash 骨干上始终如一地提高了平均接受长度和端到端解码速度。通过引入跨轮条件化而不修改轮内提案生成，ReTrace 在很大程度上与现有的草稿改进正交，并可与之结合以获得进一步收益。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

### 研究背景

- **推测解码（Speculative Decoding）** 是加速自回归大模型推理的重要方法：用一个轻量级草稿模型（drafter）提出多个候选 token，再由更大规模的目标模型（target model）进行并行验证，一次前向可提交多个 token，从而降低目标模型的串行前向次数。
- 然而，**标准前缀验证存在显著浪费**：一旦首个候选 token 被目标模型拒绝，剩余草稿后缀（draft suffix）即被直接丢弃——即便生成和验证这些位置的计算已经发生，也无法转化为解码进展。在长文本任务（数学推理、代码生成、多轮对话、Agent 工作流等）中这一问题尤为突出。

### 核心观察

- 论文以 **DFlash**（一种基于扩散的并行草稿模型）为对象，发现一个关键现象：**首次拒绝之后被丢弃的草稿后缀，仍可能包含与目标延续（target continuation）对齐的有用信息**。
- 具体表现为：
  - 在真实生成示例中，草稿后缀虽存在局部重复、遗漏或错词，但后续位置仍能重新与目标输出对齐；
  - 在量化分析中，被拒后缀的 token 在草稿模型的预测分布中仍排名靠前；
  - 被拒后缀的隐藏状态与其对应的目标隐藏轨迹具有显著的高余弦相似度（高于随机基线）。
- 这说明早期 token 级错误并不会使全部后续草稿计算变得无用——**拒绝轨迹中保留了可复用的语义与结构信息**。

### 论文整体贡献

- 提出 **ReTrace（Rejected-Trajectory Conditioning）**，将上一轮被拒绝的草稿后缀作为下一轮草稿块的**额外条件信号**，实现跨轮信息流动。
- ReTrace 在不增加目标模型前向、不改变验证规则的条件下，保持了推测解码的**无损性**，并一致提升平均接受长度与端到端解码速度。
- 由于不修改轮内草稿生成，ReTrace 与现有草稿改进方法（如 Domino）**正交**，可叠加使用获取进一步增益。

## 2. 论文提出的方法论

### 2.1 核心思想

> ReTrace 借鉴**条件扩散（conditional diffusion）**的思想，将被拒绝的包含隐藏状态序列看作一条“rejected trajectory”，作为下一轮草稿块的辅助条件——使草稿模型从“仅由干净的掩码占位符生成”变为“基于已验证上下文 + 上轮被拒轨迹共同生成”。

### 2.2 关键技术流程

ReTrace 在每一轮推测解码中执行以下三个关键步骤（以第 t 轮拒绝后、第 t+1 轮使用为例）：

**Step 1：被拒轨迹的构建与对齐（Rejected-Trajectory Construction & Alignment）**

- 第 t 轮草稿块大小为 B，候选表示为 hDt,1…hDt,B；假设验证后接受长度为 At。
- 若 At < B，则首个被拒位置为 rt = At + 1。
- ReTrace **排除已接受的表示为 hDt,1:At（已提交到上下文，无需复用）**，也**排除首个被拒位置 hDt,rt（该位置已由目标模型给出的修正 token 解决）**。
- 只携带**严格位于首个被拒位置之后的残差表示**：
  hDt,rt+1, hDt,rt+2, …, hDt,B
- 将这些表示**对齐到下一轮草稿块的起始位置**：
  mt+1,j = hDt,rt+j（当 1 ≤ j ≤ B − rt），否则为 0。
- 若一轮的块被全部接受，或首个拒绝发生在最后位置，则没有可保留的信号，ReTrace 退化为原始草稿过程。

**Step 2：目标感知修正（Target-Aware Correction）**

- 被拒轨迹仅反映草稿模型的预测，可能有偏差；而验证过程中目标模型产生的表示给出了目标对同一轨迹的评估视角。
- ReTrace 利用验证时已获得的目标表示（无需额外前向），对对齐后的轨迹进行修正：

  - ut+1,j = hTt, rt+j−1（因果模型中，预测位置 rt+j 的 token 所需的状态是该位置的前一个状态）
  - ct+1,j = Wc [mt+1,j ; ut+1,j]  （拼接后经轻量投影层）
  - rt+1,j = mt+1,j + β·ct+1,j  （残差修正，β 为控制强度的系数，训练时逐步增大）

**Step 3：门控残差融合（Gated Residual Conditioning）**

- 修正后的信号不能替代当前的掩码输入，只作为**辅助的残差条件**进入草稿模型输入：

  - eet+1,j = et+1,j + Wv·rt+1,j ⊙ σ(Wg [et+1,j ; rt+1,j])
  - 其中 Wv 为零初始化（开始时残差为 0，保留草稿模型原始行为），σ 为逐元素 sigmoid 门控。

- 没有对齐信号的位置（j > B − rt）保持原始输入不变。原掩码输入始终是主通道，条件信号仅作为受门控的辅助输入。

### 2.3 训练与推理特性

- **训练**：草稿表示与目标表示在跨轮复用时均被截断（detach），只使用当前轮的预测损失联合优化草稿骨干 + 修正模块 + 门控融合模块；目标模型保持冻结。
- **推理**：无需额外模型前向，仅需在上一轮已有的草稿/目标状态上进行轻量修正与门控融合，额外延迟约 0.13 ms/轮（约 0.4% 总延迟）。
- **不受损**：被拒 tokens 不会被提交，目标验证不变，保持推测解码的无损特性。

## 6. 论文的主要结论与发现

1. **被拒轨迹存在可复用的预测信息**：
   - 30.4% 的被拒后缀位置，目标 token 仍是草稿模型 top-1 预测；75.2% 落入 top-5；
   - 被拒草稿隐藏状态与真实目标轨迹的余弦相似度显著高于随机窗口基线（平均 0.351 vs 0.128，gap 0.223）。
2. **ReTrace 一致提升解码效率**：
   - 在 4 个 模型-温度 配置的宏平均上，ReTrace 比 DFlash 提高平均接受长度 6.97%、端到端加速 5.34%；
   - 每个 benchmark 上的接受长度均有提升，贪心与随机采样均可受益；
   - 在并发服务（batch 至 32 路并发）下，ReTrace 仍保持最好的端到端加速比。
3. **组件消融验证了每一步设计都有正向贡献**：
   - 简单 overwrite 已有小幅提升（6.45 → 6.51）；
   - 加入门控残差融合进一步提至 6.79；
   - 再加上目标感知修正，达到最优的 6.90 接受长度和 3.86× 加速比。
4. **效果增益非仅来自额外训练**：SFT 基线（同数据同预算但无条件）的提升小且迅速饱和；ReTrace 在整个训练过程中持续提升，确认条件化信号是增益的关键来源（见图 4）。
5. **开销极低**：ReTrace 的引入的修正+融合开销为 0.13 ms/cycle，仅约占 DFlash 单轮总延迟的 0.40%。
6. **与 Domino 兼容**：将 ReTrace 叠加到 Domino 之上，在数学与代码 bench 上宏平均吞吐从 287.17 提升至 301.39 tok/s，平均接受长度从 7.43 提升到 7.79，证明跨轮条件化与轮内因果修正正交。

## 7. 优点

- **问题视角新颖、有洞见**：从“事后反思”视角提出：被拒而非被接受的草稿计算中有价值的信息也同样值得保留——这打破了很多推测解码工作默认“拒绝即废掉”的隐含假设。
- **无需额外模型前向**：ReTrace 仅重新利用上一轮验证中已经产生的草稿/目标状态，不增加目标模型或草稿模型的额外前向，计算开销极低。
- **保持无损性**：被拒 tokens 从不提交、验证逻辑不变、输出仍由目标模型控制，理论上的无损性不出现回退。
- **正交性强、便于叠加**：ReTrace 只修改跨轮信息流，不改动轮内草稿生成；这使得它可以和 Domino、EAGLE 等轮内草稿优化方法组合使用。
- **实证研究扎实**：先以两类离线探针（token rank + 余弦相似度）给出被拒轨迹信息有效性的定量证据，再以 8 组规模不一的实验构建了完整论证链（分析 → 主实验 → 消融 → 训练曲线 → 运算效率 → 并发形态）。
- **训练稳定性设计可取**：β 系数在初期线性 warm-up、Wv 零初始化，保证了训练开始时与 DFlash 行为完全一致，避免破坏原有初始化状态。

---

## 8. 不足与局限

- **草稿模型类型覆盖偏窄**：正文实验集中在 DFlash 这一种草稿器（以及 DFlash 上叠加 Domino 的组合）。EAGLE-3 仅作为“非 ReTrace 基线”出现在对比中，并未实际将 ReTrace 的结构扩展到 EAGLE-3 这类自回归型草稿器，虽然作者理由是 EAGLE-3 的后缀状态语义与“位置对齐延续”天然不同，但更严谨的做法是做一个“泛化到其他草稿器”的案例验证（哪怕只做 EAGLE-2/3 的消减版），以更牢靠地支撑“ReTrace 可在更大类草稿模型上使用”的结论。
- **ReTrace 的可推广性论证稍欠直接证据**：论文明确说明行文以 DFlash 作为干净场景，核心方法的有效性与“DFlash 的哪些特殊性相关”（如扩散平行生成）仍是某个层面的疑问；作者虽在文中对“为何选 DFlash”做了很好的定性解释，但没有实验证明如果 DFlash 换成 DSpark 或 JetFlow 等更新草稿器会如何。
- **目标感知修正只使用目标验证状态的一个位置**：使用的目标表示 ut+1,j 是预测该候选 token 的目标状态，而非来自后续新的目标前向，这种“修正”本质上仍是“单轮、单位置的侧向对齐”，并没有将目标对候选的完整看法（例如下一步可能接受哪个 token）纳入修正；这可能也是为何绝对相似度（0.351）仍然不高的部分原因。
- **并发实验覆盖范围较窄**：并发测试仅限 GSM8K、Qwen3-4B、贪心解码，未完成大模型（8B）或对话/代码场景的并发评估；并发下吞吐是用户实际部署中非常关心的指标

……指标，补充 8B 目标模型、数学/代码之外的异构任务以及随机采样模式下的并发评估会更有说服力。此外，并发测试报告的是单轮吞吐/端到端吞吐的相对增益，缺少对**延迟分布（如 TTFT、TPOT 的尾延迟）**的报告，而尾延迟对在线推理服务质量同样关键。

- **离线可复用性分析存在“事后回放”的乐观偏差**：量化被拒后缀与真实目标延续的对齐程度时，论文使用的是由目标模型自回归解码预先采集的“真实延续”，而真实推理中该信息不可提前获得。离线探针表明被拒轨迹与真实目标轨迹存在显著的相似度盈余，这更多说明**信息可被提取的理论上限**，而端到端实际收益（接受长度 +6.97%）远小于该上限，中间仍有不小的转化损耗。
- **训练数据规模与领域覆盖有限**：用于训练 ReTrace 门控/修正模块的指令池仅 40K 条 prompt 规模的混合数据（响应长度 1,024 token），论文未报告按任务类型（数学、代码、对话）对训练数据的配比，也没有给出训练loss的收敛曲线；在分布外领域（如多轮 Agent 轨迹、结构化输出）的效果未必能维持。
- **关键超参数敏感性缺少系统扫描**：论文只报告了最终使用的 β 调度和特征拼接维度，未展示 β 增长率、拼接特征维度、门控初始化方式等对最终加速比的影响。对于目标感知修正模块，使用的是粗粒度拼接 + 线性投影，作者未尝试更复杂的融合（如 cross-attention、MLP 门控）来验证当前简单设计是“瓶颈”还是“恰到好处”。
- **评测规模与统计鲁棒性报告不足**：多数 benchmark 使用 128 条提示评估或仅报告单次采样结果，没有列出多次独立运行的方差或置信区间。在温度 1 的随机采样场景下，接受长度与加速比具有随机性，若缺乏标准误则难以严格判断少量百分点的提升是否显著超过噪声；建议补充重复实验的标准差或配对显著性检验。
- **代码与检查点尚未开源，可复现验证难以落地**：依正文所述，方法涉及对草稿表示和目标表示的位置对齐、零初始化的门控融合及 β 调度，这类细节层面的实现需要源码配合才能精确复现；论文没有给出伪代码（Algorithm 块）和开源仓库链接，对后续研究者的友好度有所保留。

## 9. 总结与总体评价

ReTrace 回答了一个颇有启发性的问题：**推测解码中被拒绝的草稿轨迹，是否天生就该被丢弃？** 论文给出的答案是“不”。通过将上轮被拒后缀的草稿隐藏状态对齐到下一轮草稿块，并用验证阶段已得到的目标表示在轻量门控残差中修正该信号，ReTrace 打通了推测解码中原本完全断开的跨轮信息流，在**不改目标模型、不加额外前向、保持无损性**的约束下，一致地提升了平均接受长度与端到端加速比。

论文最大的方法论贡献在于把“拒绝”从单纯的负反馈事件转化为条件生成中的正信息通道。这种视角具有很强的溢出价值——任何具备“草稿并行提出 → 目标串行验证”结构的解码框架（包括自回归型草稿器的多轮批量验证、以及未来的投机采样变体）都可能借鉴“携带被拒尾迹作为下一轮条件”的思路，而无需对底层的草稿生成算法做大改。

从实验严谨性看，论文遵循“先离线证明信息存在，再在线证明收益可达”的完整证据链：token rank 和隐藏状态余弦相似度的两级探针给出了信息存在性的强证据；主实验、消融、训练曲线、运行时分解、并发 + Domino 兼容性多层实验说明了收益确实来自条件化信号而非额外训练预算。尤其值得肯定的是对训练正交性的处理——同数据同预算的 SFT 对照将“多了训练”与“多了条件信号”这两个混淆因素清晰剥离开来。

当然，ReTrace 当前的证据版图也清楚地标出了未开拓的领域：草稿器类型仍以 DFlash 为主、跨模型泛化只做了间接论证、并发评估的覆盖面偏窄、可复现性有待开源代码补全。这些与其说是缺陷，不如说是对未来工作的直接邀请。总体上，该论文提出了一项概念简洁、机制轻量、实验较扎实的增量贡献，为推测解码的效率优化开辟了一条有价值的“跨轮信息复用”方向，值得关注该领域的读者精读。
