## 摘要
基于扩散的语言模型（dLLMs）通过迭代去噪实现并行token生成，但现有解码策略在低置信度下退化为单token生成，严重限制了吞吐量。与自回归模型中投机解码按固定的从左到右顺序作用于token序列不同，dLLMs需要对去噪轨迹进行投机——即具有显式位置和解掩码顺序的多token更新序列。我们开发了一个轨迹级投机框架，通过置信度分层树探索构建草稿去噪轨迹，并通过具有双向注意力掩码的分块并行评估对其进行验证。我们的方法进一步引入了块间投机，利用扩散模型的双向结构执行跨块前瞻。我们正式刻画了该方法精确成立的条件，并将轨迹漂移确定为增加并行性的基本代价。基于Fast-dLLM的双缓存基础设施，我们的框架将去噪迭代次数减少了30%-40%，并将每步token数从2.6提高到4.3，在推理和代码基准上实现了相比vanilla dLLMs 7-14倍、相比Fast-dLLM 1.3倍的加速，同时准确率变化小于1%。

## Abstract
Diffusion-based language models (dLLMs) enable parallel token generation through iterative denoising, but existing decoding strategies collapse to single-token generation under low confidence, severely limiting throughput. Unlike autoregressive models where speculative decoding operates on token sequences in a fixed left-to-right order, dLLMs require speculating over denoising trajectories-sequences of multi-token updates with explicit positions and unmasking orders. We develop a trajectory-level speculative framework that constructs draft denoising trajectories via confidence-stratified tree exploration and verifies them through blockwise parallel evaluation with bidirectional attention masking. Our method further introduces inter-block speculation, exploiting diffusion models' bidirectional structure to perform cross-block lookahead. We formally characterize when this approach is exact and identify trajectory drift as the fundamental cost of increased parallelism. Building on Fast-dLLM's dual-cache infrastructure, our framework reduces denoising iterations by 30-40% and increases tokens-per-step from 2.6 to 4.3, achieving 7-14x speedup over vanilla dLLMs and 1.3x over Fast-dLLM with less than 1% accuracy change across reasoning and code benchmarks.

## 1. 核心问题与研究动机

- **背景**：扩散语言模型（dLLMs），如 LLaDA、Dream、Seed，通过迭代去噪并行生成文本，具备天然并行能力（一次可解码 32 token/块），理论上吞吐优于自回归模型。
- **核心问题**：现有并行解码策略（阈值法、top-k 法）在高置信度下表现良好，但在低置信度时发生“**低置信度退化**”，坍缩为单 token 生成，严重限制吞吐。实证发现：
  - 推理与代码任务中，**超过 80% 的去噪步骤**出现低置信度退化。
  - 每当模型不自信时，往往每步只生成 1-3 个 token，完全无法发挥 dLLM 原有的并行解码能力。
- **关键观察**：低置信度并不等于不正确——即使某位置置信度低，**正确 token 经常落在 top-k 候选（k≈3）中**。这启发了作者放弃固定解码策略，转向**多候选并行投机验证**。
- **为什么 AR 投机解码不适用**：自回归投机解码依赖三个 dLLMs 不具备的特性：(1) 固定从左到右生成顺序；(2) 因果注意力单遍验证；(3) 数学上无损的精确验收。dLLMs 使用双向注意力、任意顺序解掩码、支持多条等价去噪轨迹，因此需要在**轨迹空间（trajectory space）**而非 token 空间进行投机。

## 2. 方法论

### 2.1 总体框架（三阶段）
1. **候选收集**：从上一步去噪的 logits 中，在低置信度位置收集 top-k token 候选。
2. **树状草稿轨迹生成**：增量构建候选去噪轨迹树——节点 = 一个 token 块，路径 = 一条完整去噪轨迹（含 token 身份、位置、解掩码顺序）。
3. **并行验证与验收**：用块级注意力掩码在所有草稿块上做并行前向评估，按贪心或最长路径策略选取最长的有效路径。

> 关键工程复用：验证第 t 步草稿的前向传播同时为第 t+1 步的草稿构建提供 logits，开销极小。

### 2.2 树构建（置信度分层轨迹树构造）
- **置信度定义**：c(x) = max(softmax(logits_t(x)))；高置信度位置（c > τ）进根块，低置信度位置（c ≤ τ）触发分支探索。
- **混合扩展策略**：
  - 第 1 层（根）：用 top-k 扩展，最大化多样性；
  - 更深层：只做 top-1 贪心扩展，保持树紧凑。
- 复杂度：宽度 W、深度 D 下仅 O(W·D) 个节点，而非指数级 W^D（如 W3D3: 9 vs 27 条草稿序列，减少 3 倍）；树构建仅需 O(W·D·L) 次张量拷贝加一次拼接前向。
- 核心动机：dLLM 的不确定性高度集中在少数高熵位置，后续步骤置信度通常较高，因此只在关键位置分配分支容量是高效且充分的。
- 典型配置：默认采用 **W2D2(3)**（HumanEval 上最优延迟-效率折中）；更大树 W3D3(6) 虽 token/步更高，但在部分硬件上延迟不降反升。

### 2.3 块级并行验证（Blockwise Parallel Verification）
- **注意力掩码设计**（关键创新）：
  - 每个草稿块 Bi 中的 token 可以**双向关注**已解码前缀 P 和剩余掩码后缀 S（保留扩散模型的双向上下文）；
  - 不同草稿块 Bi、Bj 之间**互不可见**（隔离竞争分支，防止交叉干扰）。
- 验证方式：拼接所有草稿块做一次前向，逐路径检查块内 token 是否与模型 top 预测匹配，选择首个有效延续（贪心）或全局最长有效路径（最长路径，默认贪心）。

### 2.4 块间投机（Inter-Block Speculation）
- **动机**：解码块 Bt 的同时，利用双向注意力监视下一块 Bt+1。
- **触发条件**：c(1)_{t+1} > c(1)_t 或 c(1)_{t+1} > τ（下一块已有高置信 token）时，同时为 Bt 和 Bt+1 构建紧凑树并联合验证。
- **注意力扩展**：Bt+1 的草稿 token 可关注 Bt 的根块，反向亦然（保持根间双向可见），利用 Fast-dLLM 观察到的“相邻去噪步骤间前缀/后缀 KV 状态稳定”这一性质。
- 仅针对相邻两块，不外推更远（收益递减、验证开销过大）。可再减少约 12% 步骤。

### 2.5 理论分析
- **定理 1（理想条件下的精确性）**：在缓存前缀后缀 KV、不启用块间投机、确定性 top-1 解码条件下，该方法生成的去噪轨迹与 Fast-dLLM (Dual Cache) **逐位置逐 token 完全一致**。证明使用强归纳法：相同历史、相同缓存、相同模型 ⇒ 相同条件分布 ⇒ 相同 top-1 选择。附录 F 给出 HumanEval 与 GSM8K 上 100% token 匹配、0.00 logit 误差的实验验证。
- **命题 2（接受率下界）**：E[accepted] ≥ Σ_{ℓ=1}^{D} (∏_{j=1}^{ℓ} α_j)·b_ℓ（b_ℓ 为第 ℓ 层块大小）。该下界说明接受率随树深**乘法累积**，从而为“根层 top-k、深层 top-1”的混合策略提供了理论依据。
- **核心启示**：轨迹漂移（trajectory drift）是并行性提升的根本代价；若保持与基线相同的并行调度，方法可做到精确无损；所有偏差都源于提升的并行度，而非投机机制近似。

## 6. 主要结论与发现

- 在 Fast-dLLM（Dual Cache）强基线上，去噪步骤再降低 **30-43%**，端到端延迟降低 **约 30%**。
- 每步 token 数从 **2.6 提升至 3.8-4.3**（约 +65%）；配备块间投机后 ABL 显示可到 4.28-4.52。
- 对比 Vanilla dLLM 实现 **7-14×** 加速（LLaDA: 6.8× HumanEval ~ 13.6× GSM8K；Dream: 4.6× HumanEval ~ 6.9× GSM8K）；对比 Fast-dLLM 进一步 **1.2-1.4×**（IFEval 场景达 1.9×）。
- **准确率变化 <1%**，且失败高度集中在需要精确多步推理的 MATH L4 子集（30.4→25.1）。
- IFEval 上 Fast-dLLM 严重退化（平均仅 1.3 token/步），本方法将步骤降低 44%、TPS 提升近 2×（36.8→69.1），验证了“低置信度越普遍，加速收益越大”的核心预测。
- 理论上：轨迹投机在理想条件下可做到精确（定理 1），轨迹漂移是提升并行度的根本代价；接受率乘法累积规律为混合树设计提供了理论保证。

## 7. 方法优点

1. **问题定义有新意**：首次将 dLLM 并行加速正式表述为“轨迹空间投机”问题，明确区分低置信度≠不正确，识别低置信度退化为瓶颈。
2. **方法论系统性强**：树状轨迹草稿 + 块级注意力掩码验证 + 块间投机三段式，每步都是针对扩散模型双向结构量身定制的设计。
3. **理论与实验结合良好**：既有精确性定理与接受率界，又有逐位精确性实验验证；清晰指出“轨迹漂移”为并行度的代价，解释了精度-加速取舍的本质。
4. **与基础设施正交**：明确建立在 Fast-dLLM 双缓存之上，系统级优化与算法级优化解耦清晰，便于后续工程集成。
5. **算开销披露坦诚**：树构建开销、注意力 kernel 延迟、roofline 分析均有量化数据，为不同硬件选树结构提供了直接依据。
6. **评估诚实**：对非开源方法的对比使用“参考比较”措辞，不夸大结论；对长序列衰减与实现层面的局限有专门讨论。

## 8. 不足与局限

1. **无法保证无损**：与自回归投机解码的数学无损不同，方法在提升并行度时必然引入轨迹漂移。定理 1 只在“不增加并行度”的理想条件下成立；实践中必须接受 <1% 精度损失来换取加速，对精度敏感的应用存在风险。
2. **实验覆盖有限**：
   - 仅验证 7B 规模指令模型，未覆盖更大规模（70B+）或未微调基座模型；
   - 主要生成长度 512，长序列（2048）实验显示相对加速增益明显衰减（作者归因于提前 [EOS] 导致两步方法都退回单步）；
   - 对 Spiffy/DPad 的对比非端到端受控复现。
3. **应用限制**：
   - 块间投机需要相邻块 KV 状态稳定假设，强行扩展到更远块收益递减；
   - 最优树大小依赖具体硬件（A800 上大树延迟反升，H800 上才有增益），部署需要逐硬件调参；
   - 当前 Python 层实现未融合 kernel，端到端加速尚未完全反映算法潜力。
4. **失败分析深度有限**：MATH L4 上精度从 30.4 降到 25.1（约 5 个点），文中仅归因于“早期轨迹漂移经过多步推理传播”，缺少细粒度的 token 级错误归因或缓解机制的具体设计。
