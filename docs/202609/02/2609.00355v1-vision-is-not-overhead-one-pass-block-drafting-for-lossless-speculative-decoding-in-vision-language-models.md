## 摘要
投机解码在不改变输出的情况下加速生成，然而在视觉-语言模型（VLM）上，它陷入了一个自我拆台的循环。草拟器保持自回归，因此必须保持较小。小型草拟器无法在每一步都处理图像，因此视觉信息被压缩、剪枝或隐藏。与图像隔离的草拟器恰恰在图像使文本可预测的地方最不可靠。我们提出了GLANCE，这是第一个在未修改的VLM目标上无损的单遍块草拟器，它从两端打破了这一循环。块扩散头读取目标已融合的视觉-语言状态，因此视觉对草拟器不产生额外成本，并且在前向传播中一次填充整个块，因此深度不消耗顺序步骤。一个宽候选树在单次目标传递中被验证，每个被审计的提示都精确复现贪心解码。接地工作负载对此收益最大，进入逐字复制模式，其长序列运行对自回归草拟器来说每个词元需要一次传递，而块草拟器总共只需一次。在同一个引擎和同一轮预算下，GLANCE的解码速度比自回归快达2.93倍，每轮仅需一次草拟传递，而生产级EAGLE3-VL头需要八次，并且接受的块长度比在同一语料上训练的EAGLE-3头长2.7倍。一条定律组织了这些结果。接受长度由目标的下一个词元熵决定，拟合斜率在所有五个任务中随接地性而变陡。该定律可跨目标和模态迁移，并界定了自身的边界，因为自由运行的文本仍然偏好链式结构。我们的代码可在 https://github.com/js-lee-AI/GLANCE 获取。

## Abstract
Speculative decoding accelerates generation without changing its output, yet on vision-language models (VLMs) it has been caught in a self-defeating cycle. The drafter stays autoregressive, so it must stay small. A small drafter cannot afford the image at every step, so vision is compressed, pruned, or hidden. A drafter cut off from the image is then least reliable exactly where the image makes text predictable. We present GLANCE, the first one-pass block drafter that is lossless on an unmodified VLM target, and it breaks the cycle at both ends. A block-diffusion head reads the target's already-fused vision-language state, so vision costs the drafter nothing, and fills a whole block in one forward pass, so depth costs no sequential steps. A wide candidate tree is verified in one target pass, and every audited prompt reproduces greedy decoding exactly. Grounded workloads reward this most, entering a verbatim-copy regime whose long runs cost an autoregressive drafter a pass for every token and a block drafter one in total. Under one engine and one round budget, GLANCE decodes up to 2.93x faster than autoregression, from one draft pass a round where the production EAGLE3-VL head takes eight, and accepts 2.7x longer blocks than an EAGLE-3 head trained on the same corpus. One law organizes these results. Accepted length is set by the target's next-token entropy, with a fitted slope that steepens with grounding across all five tasks. The law transfers across targets and modalities and names its own boundary, since free-running text still favors a chain. Our code is available at https://github.com/js-lee-AI/GLANCE.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：在视觉-语言模型（VLM）上，投机解码（Speculative Decoding）长期陷入一种“自我拆台”的循环：草稿器（drafter）沿用自回归解码方式，因此为了控制成本必须做得很小；小型草稿器无法在每一步都处理图像信息，于是视觉输入常被压缩、剪枝或直接隐藏；可恰恰在“图像使文本变得高度可预测”的接地任务（如文档问答、图表问答）中，这种“看不见图像”的草稿器最不可靠，导致投机解码没能兑现其应有的加速潜力。
- **动机**：作者重新审视了一个反向问题：在接地任务上，视觉信息对于草稿器而言到底是“额外的开销”还是“草稿之所以有效的原因”？例如，当VLM回答文档问题时，许多输出文本本身就存在于图像中，下一个词元往往接近确定（近似逐字复制）。此时如果草稿器能以极低代价感知视觉上下文，就可能把这种高度可预测性直接转化为解码速度。
- **整体含义**：论文提出GLANCE，一种“单遍块草稿器”（one-pass block drafter），让草稿器直接读取目标模型已经融合了视觉信息的隐藏状态，用一次前向传播草拟整个token块，再以宽树单次验证，实现对未修改VLM目标的无损（lossless）投机解码。它打破了过去“草稿器必须小、因此必须丢弃视觉”的两难循环。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：
  1. **继承视觉而非隐藏视觉**：草稿头不读取原始视觉token，而是交叉注意力读取冻结目标VLM在若干层（{1,9,17,25,33}）已经融合了文本与图像的隐藏状态，因此视觉信息相当于“免费继承”，不增加草稿器的单步推理成本。
  2. **单遍块填充深度**：采用块扩散头（block-diffusion head，DFlash家族），一次前向就填满整个block，给出block内每个位置的边际分布，不再像自回归草稿器那样每个token都需要一次顺序pass。
  3. **宽树与单次验证**：根据一次性得到的各位置边际分布，用plug-in score（\(\hat\pi(y_{1:l})=\prod_{j\le l}q_j(y_j|x,b)\)）选出得分最高的多个前缀，构造prefix-closed的候选树；将整棵树打包进一次带祖先掩码的目标前向验证pass中，提交最长的与目标贪心解码一致的路径。
  4. **可证明无损**：给出Theorem 1（非形式化）：在目标arg max唯一且top-2 logit gap足够大时，对任意候选树，GLANCE提交的序列与冻结目标的贪心自回归解码逐位一致（fp32下bitwise）；实际运行中再用“tie-aware gate”处理接近平局的token来保持该性质。
  5. **熵定律**：论文用统一规律概括实验结果——接受的块长度由目标在round根处的下一token熵\(H\)决定。通过建模，得到公式\(\text{logit } p_m(H)=b_0-b_1H\)和\(E[a|H]\approx p_m/(1-p_m)\)，其中斜率\(b_1\)接地任务上更大；熵越低，接受长度越长。另有一个“grounded tail”现象（Theorem 2）：在极低熵区间，逐字复制（verbatim-copy）机制可使接受长度突破简单几何模型给出的上限\(e^{b_0}\)。
- **算法流程（GLANCE一个解码round）**：
  1. 输入已提交前缀+根token \(b\)；
  2. 冻结目标VLM的前向已经产生融合的视觉-语言隐藏状态；
  3. 块扩散头做一次draft pass，基于多层融合状态一次性输出整个block（长度L=15）的offwise边际分布；
  4. 由最高得分前缀构建预算为N的prefix-closed候选树；
  5. 使用一次ancestor-masked目标pass打包验证整棵树；
  6. 按目标自己的贪心路径提交最长一致前缀，并从最后一个已验证行的分布中读取一个“bonus token”作为新的根token，进入下一round。

## 6. 论文的主要结论与发现

- **GLANCE在接地任务上显著加速**：统一引擎与round预算下，相对自回归解码最高2.93倍加速；相对生产EAGLE3-VL头在DocVQA/InfoVQA/ChartQA上分别提速+5.4%/+7.6%/+6.0%，自由文本任务（captioning/TextVQA）则比EAGLE3-VL慢（–16.2%/–19.1%）。
- **草稿pass数差异是关键**：GLANCE每轮只做1次draft pass，EAGLE3-VL做8次；在快速工程中，宽度验证几乎不增加时间，而每个顺序draft pass都会线性增加墙钟成本。
- **接受长度排序随接地性单调上升**：五任务τ排序：captioning < TextVQA < InfographicVQA < DocVQA < ChartQA（在各自operating point上）；EAGLE3-VL的排序不一致（TextVQA高过DocVQA）。
- **匹配训练下GLANCE优于EAGLE-3头**：相同语料/框架/schedule下，GLANCE几何平均接受块长是EAGLE3-head的2.7倍（ChartQA上4.0倍），在另一次训练语料下优势2.04 vs 1.29。
- **熵定律统一机制**：接受长度受目标下一token熵控制；\(\logit p_m = b_0-b_1H\)拟合良好，接地性越强斜率越大；错配图探针证明图像通过“降低熵”而不是额外通道起作用。
- **接地尾效应（verbatim-copy regime）**：在极低熵round，逐字复制使接受长度超过单几何模型上限；这类长串复制只有单遍块草稿能整段收割，自回归草稿器每个token都要一次pass。
- **方法边界明确**：该方法适合有解码循环的生成任务；ScienceQA这种答案极短的分类任务会失去优势；自由生成的文本仍更适合传统链式草稿器（cap/main表显示其接受长度领先GLANCE两任务的根因是深度内聚性）。

## 7. 优点：方法或实验设计上的亮点

1. **问题诊断新颖**：把“自回归小草稿器”与“只能删减视觉”明确绑定，指出真正丢失的是接地任务中长串逐字可预测文本，给出了新的切入角度。
2. **技术创新**：首次在未修改VLM目标上实现单遍块扩散头草稿+宽树验证+无损贪心解码；视觉信息通过目标的融合隐藏状态免费继承，不对草稿器增加每步视觉编码开销。
3. **可证明性**：从验证器（而非草稿器）角度证得无损性；任何差的草稿头只会缩短接受长度，绝不改变输出；实际运行又用fp32审计和tie-aware gate兜底；并在bf16下检验了算术漂移的影响。
4. **机制定量化**：用目标熵的定律归纳实验结果，解释为什么接地任务更可草拟；用错配图像、feature-access归零、文本-状态替换和OCR重训多角度验证因果路径。
5. **实验控制严谨**：同引擎同预算对比生产系统；匹配训练隔离架构差异；在树宽与head大小之间用“同一head的width-1链”作为零混杂对照，说理清楚。
6. **结果保守、可信度高**：多处采用保守取数；给出bootstrap区间；跨引擎绝不直接比绝对速度；既报告对自己有利的结果，也坦诚报告失败的场景。
7. **通用性较强**：熵定律跨不同drafter、不同目标、甚至语音/代码/闲聊等非视觉模态仍成立，从而把具体experimental发现推向更一般的规律。

## 8. 不足与局限

- **应用范围窄**：几乎所有主实验都是batch=1、decode-only的设定；作者明确不主张更大batch下的加速仍然成立。
- **数据规模和样本量有限**：测试提示每任务往往只有20–101条（最多约200–520条prompt）；训练数据也仅16K–26K行，属于小规模；作者自述“sample sizes are small”。
- **bf16下的无损需要额外门控**：严格bitwise一致的claim仅在fp32；生产bf16下模型自身无法稳定复现自身解码（ar没有drafter时也仅25/60逐字一致），需要tie-aware gate，实际部署环境下复杂度高于论文指标。
- **跨目标/跨模态证据级别不统一**：部分transfer研究使用了“two-model proxy”或规范自回归草稿器而非同构块头，因此“定律的普适性”严谨度弱于主实验。
- **输出相等性审计在特定harness内完成**：ViSpec/Medusa在被置于官方pipeline时输出与目标贪心不一致，但作者也指出它们采用relaxed acceptance（对采样分布不做逐token保真），因此对“lossless”的指责实际上是预设差异而不是新发现。
- **架构依赖明显**：主方法面向Qwen/VLM（视觉以token prefix输入）；在Llama-3.2-11B-Vision这类cross-attention融合视觉的模型上，虽然方法仍工作且无损，但“接地任务更可草拟”的排序发生反转，作者承认该排序是“architecture-scoped”。
- **没有处理真正开源社区关心的更大battlefield**：未涉及多batch serving、多轮对话、agent类长程生成的评估；多个结论依赖single-card、batch-1的工程设定，通用化需要更多外围证据。
- **训练基线的可比性问题**：EAGLE3-VL是production公开头，并非自己用同一框架训练；作者靠matched training模拟的部分只能算“原理验证”，不一定反映正式生产头在真实引擎里的全部工程优化（如SGLang native支持），可能影响表2/表3的数据解读与后续努力方向。
