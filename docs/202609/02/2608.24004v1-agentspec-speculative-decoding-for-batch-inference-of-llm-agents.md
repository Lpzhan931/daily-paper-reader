## 摘要
基于大型语言模型（LLM）的智能体应用通常面临高响应时延。投机解码是一种有前景的解决方案，可在不影响生成质量的前提下提升LLM智能体的推理效率。然而，现有最先进的投机解码算法在较大批处理规模下会出现显著的加速退化，限制了其在实际智能体应用中的部署效果。在本工作中，我们首先对LLM智能体的投机解码进行了系统性分析，识别出加速退化的两个主导因素：投机令牌的高拒绝率以及动态令牌预算的利用不足。基于这些观察，我们提出AgentSpec，一种针对LLM智能体现有方法局限性的投机解码算法。AgentSpec引入了结构隔离式草拟，将推测约束在智能体工作流的语义连贯片段内，减少无关语义路径的草拟，从而实现极低的拒绝率。此外，AgentSpec采用冗余感知的预算分配机制，利用智能体级信息更好地利用推断过程中动态空闲的令牌预算。我们在vLLM中基于五个不同工作负载和四个不同LLM家族的四个模型对AgentSpec进行了实现与评估。结果表明，AgentSpec优于现有最先进方法。

## Abstract
Large language model (LLM)-based agent applications often incur high response time. Speculative decoding is a promising solution to improve the inference efficiency of LLM agents without impacting generation quality. However, state-of-the-art speculative decoding algorithms exhibit substantial speed degradation under large batch sizes, limiting their effectiveness to deploy in real-world agent applications. In this work, we first present a systematic analysis of speculative decoding for LLM agents and identify two dominant factors of speedup degradation: high rejection rate of speculative tokens, and under-utilization of dynamic token budgets.B ased on these observations, we propose AgentSpec, a speculative decoding algorithm that addresses the limitations of existing methods for LLM agents. AgentSpec incorporates structure-isolated drafting that constrains speculation to semantically coherent segments of the agent workflow, reducing the drafts of irrelevant semantic paths and achieving an extremely low rejection rate. Moreover, AgentSpec adopts redundancy-aware budget allocation that exploits agent-level information to better utilize the dynamically-free token budget during the agent inference. We implement and evaluate AgentSpec on five different workloads and four different models from four different LLM families in vLLM. Our results demonstrate the superiority of AgentSpec over state-of-the-arts.

## 二、方法论

### 2.1 整体框架

- AgentSpec 是一种**免草稿模型**（draft-model-free）的投机解码算法，面向 LLM Agent 负载设计。
- Agent 应用需在向服务端发送请求时附带「智能体结构标识符」，服务端据此按语义结构组织和管理历史生成内容。
- 整体包含两个核心组件：**结构隔离草稿**（Structure-Isolated Drafting）与**冗余感知预算分配**（Redundancy-aware Budget Allocation）。

### 2.2 结构隔离草稿（Structure-Isolated Drafting）

- **核心观察**：Agent 工作流中，同一用户请求的不同执行阶段（如推理、代码块、工具调用、结果解读）之间有明显的**语义鸿沟**。重复生成的 token 模式绝大多数集中在同一查询、同一语义块内；跨块、跨查询的重复极少。
- **设计思路**：将投机检索范围限制在与当前生成步骤**语义同构**的历史片段中，避免在语义边界之间检索草稿，从而消除不相关的生成路径，降低拒绝率。
- **技术实现细节**：
  - 请求格式扩展：请求 $r_i$ 附带结构标识符 $S_i = \{a_i, q_i, B_i\}$，其中 $a_i$ 为应用标识，$q_i$ 为用户查询索引，$B_i$ 为语义块的起始/结束标签列表。
  - 使用**缓存 token-字符串映射** $M$，避免在线调分词器，实现低开销的逐 token 转字符串。
  - 维护轻量级**字符串下推自动机（PDA）**，增量跟踪当前激活的语义块，从而将新生成的 token 分配到正确的块缓存中。
  - 为每个语义块维护独立的历史缓存，草稿只从当前块的缓存中检索，实现结构隔离。
- **效果数据**：AgentSpec 将拒绝率降低至约 **26.4%**，相比 EAGLE-3（53.3%）降低约 50%、比 NGram（88.7%）降低约 70%。

### 2.3 冗余感知预算分配（Redundancy-Aware Budget Allocation）

- **核心观察**：Agent 负载中，与历史重复模式越一致的草稿，其被目标模型接受的概率越高（经验数据验证了长度越长、冗余度越高时，接受率与冗余度相关性越强）。
- **冗余分数公式**：

  $g(c, n) = \frac{c}{n} \cdot p(n)$，其中 $p(n) = g_{\min} + (1 - g_{\min})(1 - e^{1-n})$

  - $n$：同一语义块和同一用户查询下检索到的候选延续个数；
  - $c$：对最高频延续前缀达成一致的候选个数；
  - $c/n$：候选中「共识」强度；
  - $p(n)$：饱和度项，用于在历史样本不足时下调置信度（降低小样本下的估值噪声）；
  - $g_{\min}$：最小置信度超参数。
- **批量预算分配**：
  - 单步总投机预算：$B_t = \lfloor \alpha b_z \rfloor$，其中 $b_z$ 为 batch 大小、$\alpha$ 为预算控制超参。
  - 每个请求 $r_i$ 获得草稿长度：$L_i = \max\left(|CT_i^*|,\ B_t \cdot \frac{g_i}{\sum_j g_j}\right)$，即优先保证每个请求至少草拟其最有信心的公共前缀，其余预算按冗余分数成比例分配，兼顾高接受潜力请求与基本覆盖。
- **实验效果**：AgentSpec 能使实际草稿 token 数量始终低于硬件最大预算 $M(b)$，并随 batch 增大而逼近 $M(b)$，预算利用效率显著优于现有方法及其 AdaSpec 式分配策略。

## 六、主要结论与发现

1. **现有方法在大 batch 下系统性失效**：在 Agent 负载下，EAGLE-3、NGram 与 SuffixDecoding 的加速比随 batch 增大快速下降，batch ≥ 32~64 后通常**慢于普通自回归解码**；AgentSpec 则在所有设置下保持对普通解码的稳定加速，最高达 **2.02×**（GPT-OSS-20B + Code Generation Agent）。
2. **拒绝率是可优化的核心杠杆**：AgentSpec 通过结构隔离将拒绝率从 50%～88% 压低到 26% 左右，验证开销也因此降低约 21%～（对比 SuffixDecoding），证明「在正确的语义片段里检索草稿」远比「检索更多的历史」有效。
3. **动态预算应基于语义冗余度而非全局接受率分配**：固定预算或 AdaSpec 式的接受率分配均无法解决预算利用问题；基于块内冗余分数的分配能使总草稿数逼近且不超出可用预算 $M(b)$。
4. **对非 Agent 负载也有正收益**：在 Spec-Bench 上达到 1.14× 的整体加速（子集最高 1.40×），说明方法不会因 Agent 专门化而损害通用场景。
5. **与 MTP 的对比**：在 MiMo-7B 上 AgentSpec 全面超过 MTP（相对增益最高 +87%），相比 Normal 最高 1.29×。
6. **无结构元数据时的表现依然稳健**：AgentSpec(N)（无显式语义结构输入）在各负载上仍能稳定优于所有基线和 Normal 解码（其弱化但保留了历史冗余检索 + 预算分配逻辑）。
7. **跨平台可泛化**：在 H100 上相比 A100 加速比更高（如 CodeGen 从 2.02× 提升到 2.28×），结论不依赖单一硬件。

## 七、方法优点

- **问题分析扎实、归因清晰**：利用理论公式 $\Delta T(b) \approx D(b)\big[(1-\rho(b))t_A - t_V(b)\big]$ 精确定位拒绝率与预算利用率两个瓶颈，并通过 vLLM 日志和计时实验（分析 FFN/Attention 的 batch 扩展特性）予以量化验证，为方法设计提供了坚实动机。
- **与 Agent 工作负载特征高度契合**：抓住「Agent 单次用户请求横跨多个语义块、块内重复率高但块间重复率极低」的结构特性，有针对性地做块内草稿，是方法能压低拒绝率的根本原因。
- **可解释且近无损**：通过可验证的草稿机制保证生成质量与自回归解码一致；额外元数据仅为结构标签，不含私密信息。
- **工程实现上务实、低侵入**：通过 token-字符串映射缓存规避在线 tokenizer 开销、PDA 增量更新 + O(1) 摊还复杂度；其渐近时间/空间复杂度（$O(K\cdot L + K)$ 时间、$O(H)$ 空间）与 NGram 等基线同阶，工程可行性较强；理论复杂度分析虽简短，但交代了关键成本。
- **方法框架可移植**：接口简单（三项附加参数），对于支持结构化输出的 Agent 框架（如 XGrammar 模式）易于扩展。

## 八、不足与局限

1. **对显式语义结构的依赖**：结构隔离草稿要求 Agent 应用主动提供语义块边界（如代码块、工具调用标签等）；尽管 AgentSpec(N) 无结构也能工作，但论文自己也承认其加速效果更依赖历史中的重复模式量，在生成过程完全无重复结构的开放任务中增益可能有限。
2. **「Agent 结构接口」的泛化成本**：不同 Agent 框架/应用的语义结构差异大，需要为每种语义类型定义块标签，这在实际多条流水线共存的生产环境中会带来一定适配与维护成本。
3. **Agent 类型覆盖有限**：验证的工作流主要是单 Agent 顺序执行类型（ReAct/Reflexion/OpenHands）；对多 Agent 协作、流式工具调用、嵌套子 Agent 等更复杂拓扑未做展示。
4. **与其它系统优化手段的协同未知**：Prefix Caching、PD 分离（Prefill-Decode disaggregation）、Chunked Prefill、投机并行等已在生产服务中常用的手段与 AgentSpec 的联合效果没有被评测，实际部署时的正交性尚需进一步验证。
5. **「可用 token 预算」的定义偏理论化**：$M(b) = AI - b$ 的推导基于固定硬件算力强度假设，未建模动态请求长度分布、显存带宽等其它资源约束在 batch 变化时的影响，边界情形下可能过乐观或过保守。
6. **未报告完整资源开销**：仅报告时间维度上的低开销，未量化额外显存/内存占用、API 层延迟成本等，完整性仍略欠。
7. **实验环境粒度不足**：未明确说明单次实验 GPU 数量、是否使用分布式/多卡推理等，难以完整复现系统级扩展性结论。
