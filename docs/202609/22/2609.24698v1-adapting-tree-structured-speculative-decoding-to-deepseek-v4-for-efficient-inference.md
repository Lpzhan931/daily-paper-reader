## 摘要
自回归解码过程中目标模型的重复执行是大语言模型推理延迟的主要来源。与沿单条候选链进行的线性投机不同，树结构投机保留来自共享前缀的多个分支；在相同预算下，这种更广的覆盖范围可以提高接受率与效率。将其适配到 DeepSeek-V4 并非易事：其 CSA/HCA 在线压缩注意力将难点集中在目标验证侧，从共享前缀分出的分支会压缩成不同状态，从而破坏跨分支状态一致性。我们通过分支感知的因果验证、临时状态隔离和接受路径状态刷新，将树结构投机解码集成到 DeepSeek-V4-Flash 流水线中，从而在各分支间保持验证与压缩状态更新一致。在预算 D=5 至 D=8、批大小 1 至 64 以及三个数据集（GSM8K、MBPP、ShareGPT）上，树投机在所有设置下都比匹配的线性配置取得更高的接受长度（例如，在 D=8 时约为 2.83--3.41 对 2.39--2.84），并在几乎所有配置中提升吞吐量——仅在最小组预算下提升甚微——最高约 18.5%。更重要的是，这些增益遵循稳定且可迁移的规律：相对增益随预算增加而增长，并且在小到中等批大小下对较难预测的工作负载最为显著；而超过一定预算后，吞吐量趋于平台期，并与仍在上升的接受长度解耦。这些结果表明，在相同预算下保留多条候选路径可以有效提升 DeepSeek-V4 的解码效率，并为将投机解码适配到具有压缩、稀疏或结构化上下文表示的未来模型提供了经验。

## Abstract
Repeated execution of the target model during autoregressive decoding is a major source of LLM inference latency. Unlike linear speculation, which follows a single candidate chain, tree-structured speculation retains multiple branches from shared prefixes; under the same budget, this broader coverage can improve acceptance and efficiency. Adapting it to DeepSeek-V4 is nontrivial: its CSA/HCA online compressed attention concentrates the difficulty on the target-verify side, where branches diverging from a shared prefix compress into different states, breaking cross-branch state consistency. We integrate tree-structured speculative decoding into the DeepSeek-V4-Flash pipeline via branch-aware causal verification, temporary state isolation, and accepted-path state refresh, keeping verification and compressed-state updates consistent across branches. Across budgets D=5 to D=8, batch sizes 1 to 64, and three datasets (GSM8K, MBPP, ShareGPT), tree speculation achieves a higher accepted length than the matched linear configurations in all settings (e.g., at D=8 about 2.83--3.41 versus 2.39--2.84) and improves throughput in nearly all configurations---marginal only at the smallest budget---by up to about 18.5%. More importantly, the gains follow stable, transferable regularities: the relative gain grows with the budget and is most pronounced for less predictable workloads at small-to-medium batch sizes, while beyond a certain budget throughput plateaus and decouples from the still-rising accepted length. These results show that retaining multiple candidate paths under the same budget can effectively improve DeepSeek-V4 decoding efficiency, and offer experience for adapting speculative decoding to future models with compressed, sparse, or structured context representations.

## 1. 核心问题与整体含义

- **研究动机**：自回归解码中，目标模型必须为每个新 token 反复执行前向，是 LLM 推理延迟的主要来源；长上下文模型更严重。
- **背景**：DeepSeek-V4 通过 CSA（Compressed Sparse Attention）与 HCA（Heavily Compressed Attention）在线压缩上下文，降低长上下文存储与注意力计算成本，但生成仍是自回归，目标模型重复执行仍是瓶颈。
- **问题定位**：线性投机解码只沿单条候选链验证，早期预测错误会使后缀失效；树结构投机在相同验证预算下保留共享前缀的多个分支，可提高接受长度。
- **核心难点**：将树投机适配到 DeepSeek-V4 并不只是加树形注意力掩码。CSA/HCA 会在线压缩历史，分支从共享前缀分开后会压缩成不同状态，破坏跨分支状态一致性，难点集中在目标验证侧。
- **整体含义**：论文通过分支感知因果验证、临时状态隔离、接受路径状态刷新，将树投机集成到 DeepSeek-V4-Flash，并总结可迁移规律，为压缩、稀疏、结构化上下文模型的投机解码适配提供经验。

## 2. 方法论

- **核心思想**：在 EAGLE-3/MTP 风格投机解码框架下，把候选 token 组织为树；相同预算下验证多条候选路径，而不是单条链；验证后只提交被接受路径的状态。
- **三阶段投机前向**：
  - **Draft extend**：将已接受前缀扩展为候选分支，按 draft 输出、分支参数和验证 token 预算组织候选树。
  - **Draft decode**：在树拓扑下计算 draft 侧表示，每个候选只沿其祖先因果路径。
  - **Target verify**：目标模型验证候选分支并选择接受路径。
- **分支感知因果验证与隔离**：
  - 每个候选应关注已接受上下文和自身分支祖先，不关注无关分支。
  - 不同分支的物理顺序不等于逻辑依赖，验证时需保留树拓扑。
  - 验证完成前所有分支都是临时的，不能污染已接受状态或其他分支。
- **验证预处理与压缩边界**：
  - 将候选树转换为验证计划，定义候选链组织和压缩边界。
  - 共享前缀可复用前缀状态；分支后必须独立压缩，避免混合互斥序列历史。
- **临时状态隔离**：
  - 使用 scratch pad 存储临时分支状态，包括压缩 token、压缩注意力状态和中间压缩结果。
  - 不直接写入持久 cache，因为 DeepSeek-V4 使用页式 KV cache pool，直接写多分支会复杂化页分配、状态归属和分支回收。
- **接受路径状态刷新**：
  - 验证后选择接受路径，刷新其 token 历史、KV 状态、CSA/HCA 压缩状态及相关中间缓冲。
  - 被拒绝分支状态不进入下一轮解码。
- **性能优化**：
  - scratch-pad 执行减少持久 cache 流量；单链或已缓存最新链时可跳过刷新。
  - C4 压缩更频繁，需及时更新；C128 压缩较稀疏，可延迟合并写。
  - 设备侧处理候选索引、链边界、验证计划元数据，减少主机控制开销。
  - CUDA Graph 覆盖受候选树配置限制，需覆盖常见树形且避免过多内存占用。
  - 尽量复用 draft 侧候选布局和元数据。
- **系统集成**：整体集成到 SGLang，形成“draft extend → draft decode → verify preprocess → target verify → 接受路径选择 → 状态刷新 → 下一轮解码”的循环。
