## 摘要
推测解码通过让轻量级草稿模型预测未来 token 供目标模型验证，从而无损加速大语言模型推理。最近的块扩散草稿器通过并行预测多个 token 进一步降低起草延迟。然而，现有的块草稿器将每个输入位置的目标隐藏状态投影到单独的草稿器侧 KV 缓存中，这会带来随并发数增长的每请求内存和 KV 写入开销；直接原地复用目标 KV 虽可消除该缓存，却无法在整个块内维持草稿质量。我们提出一种混合目标上下文注入方法，仅通过最后一个输入位置的目标隐藏状态来补充直接的目标 KV 复用，且无需单独的草稿器侧 KV 缓存。基于该设计，我们提出 H-Spec，一种混合 Mamba-注意力并行草稿器，通过互补模块消费这两种目标上下文来源。Mamba 模块用投影后的末 token 目标隐藏状态初始化，而注意力模块原地复用目标 KV。尽管采用循环式表述，Mamba 的并行扫描使 H-Spec 能够保持块并行起草。在三个目标模型和多种任务上，H-Spec 相比最佳基线，将平均接受长度提高 5.0--13.3%，并将批大小为 1 的 token 间延迟加速比提高 5.3--12.6%。在并发服务下，H-Spec 在评估的并发水平上始终实现更高吞吐量，同时保持比基线更低的 KV 缓存利用率。

## Abstract
Speculative decoding losslessly accelerates large language model inference by having a lightweight draft model predict future tokens for verification by the target model. Recent block diffusion drafters further reduce drafting latency by predicting multiple tokens in parallel. However, existing block drafters project target hidden states at every input position into a separate drafter-side KV cache, incurring per-request memory and KV-write overhead that grow with concurrency; directly reusing target KVs in place removes this cache but fails to sustain draft quality throughout the block. We propose a hybrid target-context injection method that complements direct target KV reuse with target hidden states only at the last input position, requiring no separate drafter-side KV cache. Building on this design, we propose H-Spec, a hybrid Mamba-attention parallel drafter that consumes the two target-context sources through complementary modules. Mamba modules are initialized with projected last-token target hidden states, while attention modules reuse target KVs in place. Despite its recurrent formulation, Mamba's parallel scan allows H-Spec to preserve block-parallel drafting. Across three target models and diverse tasks, H-Spec improves over the best baseline by 5.0--13.3% in mean accepted length and 5.3--12.6% in batch-size-1 inter-token latency speedup. Under concurrent serving, H-Spec consistently achieves higher throughput while maintaining lower KV cache utilization than baselines across evaluated concurrency levels.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）以自回归方式逐 token 生成，推理速度受序列依赖瓶颈制约。推测解码（Speculative Decoding）通过轻量级草稿模型预测未来 k 个 token，再由目标模型一次性验证，实现无损加速。
- **近期进展**：块扩散草稿器（如 DFlash、DSpark、Domino）通过并行预测多个 token 进一步降低起草延迟，成为主流方向。
- **核心痛点**：现有块草稿器采用 **KV 注入**机制——把目标模型每个输入位置的隐藏状态投影为独立的草稿器侧 KV 缓存。该缓存随每个请求长期驻留显存，导致：
  - 每 token KV 内存增加 **1.1–1.8×**（依目标模型而定，如 Qwen3.5-397B 增加 1.8×）；
  - 并发服务时 KV 写入/注入开销随并发数增长（Qwen3-8B 上从 4 到 128 并发，注入时间增长 **4.7×**）。
- **朴素方案的失败**：直接原地复用目标 KV 虽可消除该缓存，但在块内**后期草稿位置**上草稿质量明显下降（第 2/4/6 位分别下降最高 6.3/12.5/16.5 个百分点）。
- **研究问题**：能否设计一种并行草稿器，在无需额外草稿侧 KV 缓存的前提下，仍保持强目标模型条件化能力？
- **整体意义**：论文指出「并发服务下的系统效率」应成为草稿器设计的重要考量维度，而非仅关注单请求接受长度。

## 二、方法论

### 2.1 核心思想：混合目标上下文注入

- 观察到 **隐藏状态**与 **KV 表示**提供的信息类型互补：
  - 目标 KV：提供细粒度的**逐位置**检索信息，但缺乏对整段输入的显式上下文摘要；
  - 末位置隐藏状态：在因果注意力下条件于全部前缀，是**全输入摘要**，且仅需 **O(1)** 存储。
- 因此提出**混合注入**：直接原地复用目标 KV + 仅在最后一个输入位置注入目标隐藏状态，避免 O(N) 草稿侧 KV 缓存。

### 2.2 H-Spec 架构（混合 Mamba-注意力并行草稿器）

- **总体结构**：每个 H-Spec 层包含 Mamba 模块 + 注意力模块 + MLP，末端接一个轻量级因果修正头（采用 DSpark 的 Markov head）。
- **Mamba 初始状态注入**：
  - 从选定的目标层集合 M 中提取末位置隐藏状态 `h_n^(m)`，经跨层融合与投影得到 Mamba-2 的初始循环状态：
    - `F_n(M) = Proj_r(Concat({h_n^(m)}_{m∈M}))`
    - `S_init = Proj_dS(F_n(M))`
  - 所有草稿层**共享** `Proj_r` 与 `Proj_dS` 权重，初始状态每次前向只算一次。
- **注意力模块原地复用目标 KV**：
  - 注意力维度与目标模型的 Q/K/V 维度及头数完全对齐，使目标 KV 可直接复用；
  - 每层注意力消费**某一个**目标层的 KV（不做跨层 KV 融合，避免重新引入草稿缓存）；
  - 使用滑动窗口注意力（SWA，窗口 2,048）以保证长上下文稳定性；
  - 掩码块输入的 Q/K 使用目标模型 RoPE 与延续目标前缀的位置索引，保证位置编码一致。
- **并行起草兼容性**：尽管 Mamba 是循环结构，其线性状态递推允许**并行扫描**，从注入的初始状态一次算出所有草稿位置的状态演化，保持块并行。
- **输入相关选择性**：掩码块输入不添加位置嵌入，但 Mamba 循环扫描产生位置相关隐状态，注意力模块通过 RoPE 补充位置信息，从而保留块内输入相关选择性。
- **因果修正**：采用 DSpark 的 Markov head 引入一阶马尔可夫依赖，调整每个草稿位置的 logits。论文明确指出因果修正**不是本文贡献**，混合骨干可与任意修正机制配对。

### 2.3 架构配置与参数对齐

- 为公平比较，H-Spec 的可训练参数总量与推荐的 5 层 DFlash/DSpark 对齐（差异 ≤ 2.9%）；
- 因每层多出 Mamba 模块，改用 **4 层**：3 个完整 Mamba-注意力-MLP 层 + 1 个部分 Mamba-MLP 层；
- Mamba 头维度 64，状态维度/组数/卷积核大小均为 4，扩展因子 1；Qwen3-4B/8B 分别用 44/48 个头，Llama3.1-8B-IT 用 56 个头；
- 目标层映射沿用基线的 5 个均匀间隔层（如 Llama3.1 的 1/8/15/22/30），Mamba 用全部 5 层末隐藏状态，3 个注意力模块复用其中最后 3 层的 KV。

## 六、主要结论与发现

- **单请求性能**：H-Spec 在 8 任务上平均 τ 比最佳基线提升 **13.3%（Llama）/ 5.0%（Qwen3-4B）/ 8.7%（Qwen3-8B）**，Spd. 提升 **12.6% / 5.3% / 8.7%**；所有配对 95% CI 均高于零。
- **DeepSpec 扩展套件**：τ 提升 3.8–12.5%，Spd. 提升 4.3–13.1%，且在**每个任务的每个模型上均领先**。
- **服务效率**：在所有并发水平上吞吐最高、KV 缓存利用率最低；峰值吞吐比最强基线提升 13.0–17.3%（Llama）、5.1–7.4%（Qwen3-4B）、7.6–9.7%（Qwen3-8B）；平均 KV 利用率降低 4.3–24.6%；吞吐优势随并发增长而扩大（Qwen3-8B 上从 C=8 到 128 优势扩大 1.13–1.58×）。
- **消融结论**：
  - 两种上下文来源**互补而非可替换**：仅用末隐藏状态 τ 下降 24.1–30.5%，仅用 KV 下降 7.1–11.7%；
  - 混合骨干优于仅 Mamba（τ 提升 28.9–45.1%）和仅注意力（13.3–15.3%）。
- **鲁棒性**：在 greedy/untruncated 采样、k ∈ {3,5,7}、1K–32K 上下文（优势稳定在 6.8–9.2%）、目标模型微调后的零样本迁移（11/12 设置显著领先）下均保持优势。
- **运行时缩放**：低并发（C < 32）或短输入时混合骨干较慢（计算图更深），但随并发升高和输入变长（约 > 512 token）反超，因为避免了 KV 注入开销且 Mamba 为 O(1)/步。

## 七、优点

- **问题识别精准**：清晰量化了草稿侧 KV 缓存的内存与写入开销随并发增长的代价，并指出现有块草稿器普遍存在该问题。
- **方法论优雅且动机充分**：利用隐藏状态与 KV 的信息互补性，用「末位置摘要 + 逐位置 KV」两类信号对应 Mamba 循环状态与注意力两个模块，架构设计与信息角色自然对齐。
- **O(1) 注入开销**：仅处理末位置隐藏状态，从根本上消除 O(N) 草稿缓存，同时保留块并行起草。
- **实验严谨**：
  - 统一训练配方复现所有基线，参数对齐，控制变量到位；
  - 广泛的统计显著性检验（10,000 次 bootstrap 重采样）；
  - 覆盖多模型、多任务、单请求与服务双场景、多维度敏感性分析。
- **实用性强**：在真实 vLLM 服务环境下验证吞吐与显存收益，Pareto 占优（更高吞吐 + 更低 KV 占用）。
- **诚实的贡献边界**：明确声明因果修正（Markov head）非本文贡献，并指出与 DFlash-2 的卷积/路径选择器是正交贡献、可组合。

## 八、不足与局限

- **架构约束**：H-Spec 的 K/V 维度与头数必须与目标模型匹配才能原地复用 KV，比基于隐藏状态的 KV 注入多了额外的架构约束。
- **低并发/短输入劣势**：混合骨干在 C < 32 或输入较短时草稿更慢（计算图更深），在这些场景下收益可能被抵消。
- **算力信息不完整**：未说明训练 GPU 型号、训练时长与总 GPU 小时数，可复现性在资源层面受限。
- **基线覆盖有限**：DFlash-2 仅为作者自实现的初步对比，缺乏官方管线；未与其他类别的加速方案（如 Medusa、MTP、Orthrus 等目标模型增强方向）做直接对比。
- **实验范围**：
  - 仅评测 8B 及以下规模的目标模型（Llama3.1-8B、Qwen3-4B/8B），未验证更大模型（如 70B+ 或 MoE）上的表现；
  - 论文表格中虽列出 Qwen3.5-27B/397B 的 KV 开销数据，但未在这些模型上做端到端实验；
  - 服务评测仅用 1 块 A100 80G、闭环请求，未涉及多卡/分布式推理场景。
- **部分结果不显著**：少数设置（如 Llama3.1 数学与对话的 Spd.、Qwen3-4B 翻译的 τ）领先的置信区间包含零。
- **应用限制**：长上下文依赖 SWA（2,048 窗口）保证稳定性，超长上下文的实际效果可能受窗口选择影响；草稿词表裁剪至 32,000 token 的具体影响未单独消融。
