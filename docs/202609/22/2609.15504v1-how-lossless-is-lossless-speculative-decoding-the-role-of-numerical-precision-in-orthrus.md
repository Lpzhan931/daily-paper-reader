## 摘要
Orthrus 是一种混合自回归-扩散架构，它通过并行生成多个 token 来加速自回归语言模型推理，同时使用一个冻结的自回归主干。其核心主张是，一种模型内共识机制能够实现无损投机解码，产生与自回归模型相同的输出序列。我们独立复现了 Orthrus，并在不同数值精度下检验这一主张。在 BF16 推理下，对于来自 12 个领域的 1,190 个 prompt，作者提供的 checkpoint 仅 45% 的情况下出现精确轨迹匹配，而我们独立训练的模型为 43%。精确匹配的概率还与参考模型的响应条件困惑度强相关。尽管存在这种轨迹差异，Orthrus 在下游 lm-eval-harness 基准上并未表现出系统性性能退化。相比之下，使用 FP32 重复轨迹评估时，所有评估的 prompt 均能实现精确轨迹匹配。这些结果表明，Orthrus 的实际无损性取决于数值精度，并且精确轨迹等价性应与下游任务性能分开评估。

## Abstract
Orthrus is a hybrid autoregressive-diffusion architecture that accelerates autoregressive language-model inference by generating multiple tokens in parallel while using a frozen autoregressive backbone. Its central claim is that an intra-model consensus mechanism enables lossless speculative decoding, producing the same output sequence as the autoregressive model.   We independently reproduce Orthrus and examine this claim under different numerical precisions. Under BF16 inference, exact trajectory matching occurs in only 45% of cases for the authors' checkpoint and 43% for our independently trained model across 1,190 prompts from 12 domains. The probability of exact matching is also strongly associated with the response-conditional perplexity of the reference model. Despite this trajectory divergence, Orthrus does not show systematic degradation on downstream lm-eval-harness benchmarks. In contrast, repeating the trajectory evaluation with FP32 yields exact trajectory matching on all evaluated prompts.   These results show that the practical losslessness of Orthrus depends on numerical precision and that exact trajectory equivalence should be evaluated separately from downstream task performance.

- **背景**：自回归（AR）语言模型的解码过程本质上是串行的——生成 N 个 token 需要 N 次前向计算，且需反复访问不断增长的 KV 缓存，导致硬件利用率低、推理成本随模型与上下文长度增长而急剧上升。
- **现有方案**：扩散语言模型与并行解码方法通过同时预测多个未来 token 来缓解瓶颈，但放松严格的自回归依赖可能引入与原始模型分布不一致的偏差。
- **Orthrus 的主张**：Orthrus 是一种混合自回归-扩散架构，在冻结的 AR 主干上附加一个轻量级扩散视图。推理时，AR 组件构建上下文表示，扩散组件并行预测多个未来 token，再由模型内共识机制用 AR 视图验证候选 token。作者声称该流程**严格无损**——即加速系统保留原始自回归模型的精确预测行为。

## 6. 主要结论与发现

- **BF16 下轨迹不匹配**：作者检查点仅 **45%** 的轨迹与 Qwen3 完全匹配，自训练模型为 **43%**；发散轨迹比例分别为 55% 和 57%。
- **领域差异显著**：匹配率从 creative-en 的 12%/11% 到 gec-en 的 88%/88% 不等，poetry-en、poetry-ru、qa 等创造性/开放性任务匹配率较低。
- **困惑度强相关**：发散轨迹的响应条件 PPL 更高（匹配组约 1.10–1.11，发散组约 1.28）。逻辑回归显示 log PPL 系数显著为负：作者检查点 β₁ = −8.10（95% CI [−10.50, −5.71]，p = 3×10⁻¹¹），自训练模型 β₁ = −10.92（95% CI [−13.60, −8.24]，p = 1.3×10⁻¹⁵）。控制长度与领域后依然显著。
- **下游性能未系统性退化**：在 GSM8K、HumanEval、IFEval 上，Orthrus 模型点估计甚至略高于 Qwen3 基线（如自训练模型 GSM8K 0.4147 vs 0.4003，IFEval strict 0.1830 vs 0.1682），但差异在置信区间内不显著。说明基准分数相同/相近**不能证明**推理等价。
- **FP32 下完全匹配**：在全部 1,190 条 prompt 上，两个 Orthrus 变体的轨迹匹配率均为 **100%**，发散率为 0%。
- **核心结论**：Orthrus 的实际无损性依赖数值精度；BF16 下的轨迹发散源于有限精度数值效应；"无损"加速的评估应同时明确**操作等价判据**与**数值精度**，且轨迹等价性应与下游任务性能分开评估。

## 7. 优点
