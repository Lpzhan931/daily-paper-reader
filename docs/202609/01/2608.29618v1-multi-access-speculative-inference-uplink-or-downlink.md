## 摘要
多接入推测式推理（Multi-SPIN）将SPIN扩展到多设备边缘网络，以加速协作式令牌生成。它允许设备端的小语言模型（SLM）自回归地为各个生成任务草拟多个令牌，而边缘服务器上的大语言模型（LLM）则并行地对其进行验证。主要的通信开销出现在草拟令牌被服务器拒绝时，此时对修正令牌进行采样需要同时访问SLM输出的草稿分布和LLM输出的目标分布在完整词表上的概率。现有设计通常通过上传草稿分布来在服务器端执行修正，但传输整个词表的分布会造成严重的上行（UL）瓶颈。另一种方案是，通过下载目标分布，利用下行（DL）链路可用的高传输速率，在设备端执行修正。基于这一见解，我们将通信模式选择引入为Multi-SPIN的一个新设计维度。具体而言，每个设备可以在UL和DL模式之间自适应切换，以在UL瓶颈与共享DL资源约束之间取得平衡，从而减轻整体通信负担。我们构建了一个联合考虑模式选择、草稿长度控制和功率分配的令牌总有效吞吐量最大化问题。对于模式选择，我们揭示了一种简单的优化结构，能够高效地搜索UL设备的数量，并相应地优化其发射功率。对于草稿长度控制，我们开发了一种贪心搜索算法，可根据异构的计算和通信能力自适应地调整设备特定的草稿长度。在Qwen2.5和DeepSeek-R1模型对上的实验结果表明，所提出的框架显著提高了令牌有效吞吐量。

## Abstract
Multi-access speculative inference (Multi-SPIN) extends SPIN to multi-device edge networks to accelerate cooperative token generation. It allows on-device small language models (SLMs) to autoregressively draft multiple tokens for individual generation tasks, while an edge-server large language model (LLM) verifies them in parallel. The major communication overhead arises when a drafted token is rejected by the server, in which case sampling the correction token requires access to both the SLM-output draft distribution and the LLM-output target distribution over the full token vocabulary. Existing designs typically perform correction at the server by uploading the draft distribution, but transmitting a vocabulary-wide distribution creates a critical uplink (UL) bottleneck. Alternatively, the correction can be performed at the device by downloading the target distribution, leveraging the high transmission rates available on the downlink (DL). Motivated by this insight, we introduce communication-mode selection as a new design dimension for Multi-SPIN. Specifically, each device can adaptively switch between the UL and DL modes to balance the UL bottleneck against the shared DL resource constraint, thereby relieving the overall communication burden. We formulate a sum-token-goodput maximization problem that jointly accounts for mode selection, draft-length control, and power allocation. For mode selection, we reveal a simple optimal structure that enables efficient search over the number of UL devices, with the corresponding transmit powers optimized accordingly. For draft-length control, we develop a greedy-search algorithm that adapts device-specific draft lengths to heterogeneous computation and communication capabilities. Experimental results on Qwen2.5 and DeepSeek-R1 model pairs demonstrate that the proposed framework significantly improves token goodput.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：边缘网络部署大语言模型（LLM）时，设备端计算、内存和能耗受限，而单纯依赖边缘服务器又会产生集中式推理瓶颈。推测式推理（SPIN）通过“设备端小模型（SLM）草稿 + 服务器端大模型（LLM）并行验证”的方式，将多个顺序解码步骤合并为一次并行验证，显著降低服务器计算负担。
- **核心问题**：将 SPIN 扩展到多设备边缘网络（Multi-SPIN）时，当草稿令牌被服务器拒绝，必须从“残差分布”中采样修正令牌，而这需要同时访问 SLM 的草稿分布和 LLM 的目标分布（完整词表级别）。现有方案通常要求设备把草稿分布上传到服务器（UL 模式），但词表规模巨大（如 Qwen2.5 的 152,064 项），导致严重上行（UL）瓶颈。
- **关键洞察**：修正步骤不一定必须在服务器端完成。既然草稿分布已在设备端，也可以通过下行（DL）链路把目标分布下载到设备端，在设备上采样修正令牌（DL 模式）。下行速率通常更高，但多设备场景中共享 DL 资源又会产生竞争。因此，需要在 UL 瓶颈与共享 DL 约束之间自适应平衡。
- **整体含义**：论文将“通信模式选择”（UL 或 DL）引入为 Multi-SPIN 的新设计维度，使设备可根据系统状态动态切换传输方向，从而缓解通信负担、提升整体令牌生成效率。

## 2. 方法论

### 核心思想
- 提出 **Multi-SPIN 协议**：设备端 SLM 自回归草稿 → 上传草稿令牌及概率 → 服务器并行批处理验证 → 根据验证结果决定后续操作。
- 对于被拒绝的设备，引入两种可选的修正通信模式：
  - **UL 模式**：设备上传草稿分布，服务器采样修正令牌并下发。
  - **DL 模式**：服务器下发目标分布，设备本地采样修正令牌并上传。
- 将问题建模为 **两阶段随机优化**：
  - 阶段一（主动）：每轮开始前确定每个设备的最佳草稿长度 γ_k。
  - 阶段二（反应）：验证结果揭晓后，为被拒绝的设备选择通信模式并分配功率。

### 目标函数与建模
- 最大化**期望总和令牌有效吞吐量（token goodput）**：
  \[
  G(\gamma, \chi) = \frac{\bar{L}(\gamma)}{T_{\text{comp}}(\gamma) + \mathbb{E}_{o|\gamma}[T_{\text{comm}}^{\min}(o)]}
  \]
  其中 \(\bar{L}(\gamma)\) 为期望输出令牌数，\(T_{\text{comp}}\) 为计算时延（草稿+验证），\(T_{\text{comm}}^{\min}(o)\) 为在某验证结果下的最小通信时延。
- 通信代价由被拒设备需传输的分布大小决定（词表有效支持大小、索引位宽和量化位数）。

### 关键技术细节与算法
1. **反应式最优模式选择与功率分配**：
   - 对固定模式划分，UL 设备以最大功率发射；DL 设备在共享总功率约束下，通过“延迟均衡”求得最优功率分配（Lemma 1），DL 延迟由二分法求解方程得出。
   - 证明最优模式选择具有**前缀结构**（Lemma 2）：将设备按最小 UL 延迟升序排列后，存在一个最优划分，使得前 n 个设备用 UL、剩余用 DL。
   - 利用 UL 延迟随 n 单调不减、DL 延迟随 n 单调不增的性质，将组合搜索降为 **一维二分搜索**（Proposition 1），只需比较穿越点附近两个候选 n 即可得到最优划分。

2. **主动草稿长度控制**：
   - 采用 **贪心搜索算法**（Algorithm 1）：
     - 第一阶段：所有设备草稿长度同时加 1（同步全一更新），直到无法提升 goodput。
     - 第二阶段：逐设备（坐标贪心）增加草稿长度，每次选择提升最大的设备，直到收敛。
   - 目标评估使用**样本平均近似（SAA）**：抽取 \(N_{\text{SAA}}=1000\) 个随机验证结果样本，近似计算期望通信时延，避免遍历 \(2^K\) 种结果。

### 协议流程总结
- 设备草稿 → 上传令牌-概率对 → 服务器批处理验证 → 若全部接受，采样 bonus token 并下发；若拒绝，服务器告知拒绝位置，并基于所选模式进行分布传输和修正采样。

## 6. 主要结论与发现

- 提出的 **自适应 UL/DL 模式选择** 能显著提升令牌 goodput，尤其在下行功率相对有限或设备数较多时，避免“全 UL”受限于单设备功率和“全 DL”导致共享功率竞争。
- 最优模式选择具有**前缀结构**，使得求解放到一维搜索即可，极大降低复杂度。
- 草稿长度控制应与通信条件联合优化：仅考虑计算时延会低估通信代价，导致次优草稿长度；统一长度无法适应设备异构性。
- 随着下行功率预算增加，系统倾向于将更多被拒设备切到 DL 模式，但仍保留一部分 UL 设备，以避免过度的 DL 竞争。
- 草稿长度随下行功率增加而变长，因为 rejection 的通信惩罚被降低，系统可以更大胆地利用长草稿的并行验证收益。
