## 摘要
投机解码通过让轻量级草稿模型提出多个候选token，然后由较大的目标模型并行验证，从而加速自回归语言模型推理。然而，在第一次拒绝之后，标准的前缀验证会丢弃剩余的草稿后缀，因此生成和验证这些位置的计算不会促进解码进展。聚焦于DFlash，我们表明被拒绝后缀中的被拒绝位置仍可能与目标续写对齐，这表明草稿模型尽管存在局部token级错误，仍能保留有用的语义和结构信息。受此观察启发，并受条件扩散启发，我们引入了	extbf{ReTrace}，一种拒绝轨迹条件化方法，它将每个草稿块以上一轮的拒绝后缀为条件，而不是仅从全新的掩码占位符生成。ReTrace保留被拒绝后缀的隐藏表示，将其与下一个草稿块对齐，利用同一验证过程中的目标感知校正信号对其进行细化，并通过门控残差融合将其纳入草稿者的输入嵌入。由于被拒绝的token永远不会被提交，且目标侧验证保持不变，ReTrace保留了投机解码的无损特性，无需额外的模型前向传递。使用Qwen3模型的数学推理、代码生成和开放域对话实验表明，ReTrace在平均接受长度和端到端解码速度上持续优于其DFlash主干。通过引入跨轮条件化而不修改轮内提议生成，ReTrace与现有草稿改进大体正交，并可与之结合以获得进一步收益。

## Abstract
Speculative decoding accelerates autoregressive language model inference by having a lightweight draft model propose multiple candidate tokens, which are then verified in parallel by a larger target model. However, after the first rejection, standard prefix-based verification discards the remaining draft suffix, so the computation spent generating and verifying those positions does not contribute to decoding progress. Focusing on DFlash, we show that rejected positions in a rejected suffix may still align with the target continuation, indicating that the draft model can retain useful semantic and structural information despite local token-level errors. Motivated by this observation and inspired by conditional diffusion, we introduce~\textbf{ReTrace}, a rejected-trajectory conditioning method that conditions each draft block on the rejected suffix from the previous round rather than generating it from fresh mask placeholders alone. ReTrace retains the hidden representations of the rejected suffixes, aligns them with the next draft block, refines them using target-aware correction signals from the same verification pass, and admits them into the drafter's input embeddings through gated residual fusion. Because rejected tokens are never committed and target-side verification remains unchanged, ReTrace preserves the lossless property of speculative decoding without requiring an additional model forward pass. Experiments with Qwen3 models across mathematical reasoning, code generation, and open-ended dialogue demonstrate that ReTrace consistently improves average acceptance length and end-to-end decoding speed over its DFlash backbone. By introducing cross-round conditioning without modifying within-round proposal generation, ReTrace is largely orthogonal to existing drafting improvements and might be combined with them for further gains.

## 2. 方法论：核心思想、技术细节与算法流程

### 2.1 核心思想

- ReTrace 受条件扩散（conditional diffusion）启发，将上一轮被拒绝的后缀隐藏状态序列视为“被拒绝的轨迹”，对齐到下一轮草稿块位置，经目标感知修正后，通过门控残差融合注入草稿模型的输入嵌入。
- 关键出发点：被拒绝后缀的 token 不能直接接受，但可以用作辅助条件来改进下一轮草稿质量。

### 2.2 关键技术细节

**（1）拒绝后缀的构建与对齐（Rejected-Trajectory Construction and Alignment）**

- 第 t 轮草稿块包含 B 个候选 token 及其最终层表示：
  \( h^D_{t,1}, h^D_{t,2}, \ldots, h^D_{t,B} \)
- 设 \( A_t \) 为被接受的 token 数。若 \( A_t < B \)，首个被拒绝位置为 \( r_t = A_t + 1 \)。
- ReTrace 排除已接受的 token 表示 \( h^D_{t,1:A_t} \) 和首个被拒绝位置 \( h^D_{t,r_t} \)（该位置由目标模型修正 token 解决），只保留严格位于首个被拒绝位置之后的表示：
  \[
  h^D_{t,r_t+1}, h^D_{t,r_t+2}, \ldots, h^D_{t,B}
  \]
- 在下一轮中，将保留的表示对齐到新草稿块的前部位置，形成对齐信号 \( m_{t+1,j} \)（未对齐位置置零）。

**（2）目标感知修正（Target-Aware Correction）**

- 将每个对齐的草稿状态 \( m_{t+1,j} \) 与验证阶段产生的目标模型表示 \( u_{t+1,j} \) 配对，通过一个轻量可学习投影 \( W_c \) 生成修正更新：
  \[
  c_{t+1,j} = W_c[m_{t+1,j}; u_{t+1,j}]
  \]
  \[
  r_{t+1,j} = m_{t+1,j} + \beta \cdot c_{t+1,j}
  \]
- \( \beta \) 为修正强度系数，训练初期线性预热（50 步内从 0 增至 1），推理时取全值 1。
- 残差形式保留原始后缀信息，同时允许目标侧信息做有界调整。

**（3）门控残差融合（Gated Residual Conditioning）**

- 修正后的信号通过向量级门控残差注入草稿输入：
  \[
  \tilde{e}_{t+1,j} = e_{t+1,j} + W_v r_{t+1,j} \odot \sigma(W_g[e_{t+1,j}; r_{t+1,j}])
  \]
- 门控输出为逐维度向量，控制每个隐藏维度的注入量；原草稿输入保持为主路径。
- \( W_v \) 零初始化，保证初始时刻 ReTrace 与原始 DFlash 行为完全一致，训练稳定。

### 2.3 算法流程（文字说明）

1. 初始化条件信号 \( m \) 和 \( u \) 为零。
2. 草稿模型接收锚点 + B 个掩码占位输入。
3. 若存在上一轮拒绝信号，则依次执行目标感知修正、门控残差融合，得到条件化输入。
4. 草稿模型前向，生成 B 个候选 token 及其隐藏表示。
5. 目标模型并行验证，接受前 \( A_t \) 个 token，输出修正 token 及逐位置目标表示。
6. 若 \( A_t < B-1 \)，保留首个被拒绝位置之后的草稿隐藏表示，对齐到下一轮并缓存；否则信号重置为零。
7. 循环直至生成结束。

## 6. 主要结论与发现

1. **拒绝后缀保留预测信息**：通过 token 级排名分析和表示级相似度分析，发现 30.4% 的目标 token 在拒绝后缀中仍为草稿模型的 top-1 预测，75.2% 在 top-5 以内；拒绝草稿状态与真实目标隐藏轨迹的相似度（0.351）显著高于随机基准（0.128），证明被拒绝轨迹包含续写特定信息。
2. **ReTrace 带来一致的性能提升**：在两个模型规模、两种温度设置下，ReTrace 相对于 DFlash 主干平均提升接受长度 6.97%、端到端加速比 5.34%，且增益在所有 7 个基准上一致出现。
3. **目标感知修正和门控融合均有效**：消融实验显示，原始条件直接覆盖输入仅小幅提升（6.45→6.51），门控残差融合有更明显增益（→6.79），目标感知修正进一步改善（→6.90）。
4. **增益来自条件化而非额外训练**：SFT 对照显示，同预算下的 DFlash 继续训练很快饱和，而 ReTrace 训练曲线持续上升。
5. **开销可忽略**：ReTrace 每周期条件化延迟仅 0.13 ms，占 DFlash 周期时延的 0.40%，无额外目标模型前向或有自回归草稿步骤。
6. **与其他方法正交**：将 ReTrace 叠加到 Domino 上，在选中基准上进一步提高吞吐量（287.17→301.39 tok/s）和平均接受长度（7.43→7.79），验证了跨轮条件化与轮内改进的互补性。
7. **并发场景也有效**：在并发度 1 至 32 范围内，ReTrace 均是最快方法，在并发度为 32 时仍保持 1.62× 加速，而 EAGLE-3 在较高并发度下落至目标解码以下。

## 8. 不足与局限

- **方法依赖 DFlash 特性的可用性**：ReTrace 利用了 DFlash 单块并行生成、拒绝后缀位置自然对齐目标续写的特性。对于 EAGLE 这类自回归草稿器，早期错误会在分支内传播导致后续状态语义偏移，直接套用可能效果有限，适用范围受限。
- **需要额外训练**：ReTrace 需要训练修正投影参数和门控参数（以及联合微调草稿骨干），并非零训练成本的即插即用方案。对于无法承担训练资源的小规模应用场景，部署门槛较高。
- **条件化信号仅单轮有效**：ReTrace 将拒绝后缀只保留一轮，未考虑更长距离的跨轮信息复用；如果连续多轮出现拒绝，更早轮次的信息会被完全丢弃。
- **计算资源需求较高**：32 张 A800 GPU 的训练配置对一般研究团队或企业来说成本较大。虽然论文声称延迟开销仅 0.40%，但训练成本未纳入讨论。
- **token 级信息利用有限**：尽管拒绝后缀保留了大量 token 级预测信息（30.4% 的 top-1 命中率），ReTrace 并未直接尝试将这些 token 用于构造更优候选树，只是将其作为粗粒度条件信号。
- **模型与基准覆盖有限**：仅评估了 Qwen3 模型，未在 Llama、Mistral 等常见模型上验证；基准限于中短长度任务（至多 8192 token），未测试长文档生成、多智能体工作流等场景。
- **β 系数和门控机制的敏感性**：论文仅报告了 β 预热至 1 的结果，未系统分析 β 的不同终值、门控维度等超参数灵敏度。
- **与 EAGLE-3 的比较公平性**：EAGLE-3 在速度上显著慢于 DFlash（因为 EAGLE-3 使用树形候选需逐层验证），表格中 EAGLE-3 与 ReTrace 的对比更像是不同草稿器范式间的对比，而非方法间“同类”比较。
