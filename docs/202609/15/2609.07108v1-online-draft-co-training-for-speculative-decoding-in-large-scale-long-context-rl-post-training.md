## 摘要
推测解码可加速 rollout 生成，而 rollout 生成在强化学习（RL）后训练成本中占主导。在线协同训练可进一步提高草稿模型的准确率，从而带来更大的加速。然而，将这一方法扩展到长上下文大模型上的协同训练面临两个障碍：（1）标准因果上下文并行（CP）实现不支持分支注意力；（2）目标特征跨越流水线并行（PP）阶段。我们用一个面向大规模在线草稿协同训练的端到端系统同时解决这两个问题。对于 CP，我们扩展了打包且负载均衡的 zigzag 环形注意力，将 rank 局部的分支注意力与因果主序列注意力合并。对于 PP，TapChannel 通过单独路径跨阶段传输中间目标特征，且不影响流水线调度。实验表明，协同训练的草稿模型能紧密跟随策略基线，同时在模型规模高达 122B 时带来显著的 rollout 和端到端加速。我们的 CP 设计在 256K token 下实现了强扩展性，并相比先前工作显著节省内存；我们的 PP 传输仅带来适度开销。代码见 https://github.com/NVIDIA-NeMo/RL/issues/3698。

## Abstract
Speculative decoding accelerates rollout generation, which dominates the cost of reinforcement learning (RL) post-training. Online co-training can further increase the draft's accuracy, yielding greater speedups. However, scaling this approach to co-training on large models with long contexts poses two obstacles: (1) branch attention is unsupported by standard causal context-parallel (CP) implementations, and (2) target features span across pipeline-parallel (PP) stages. We address both with an end-to-end system for large-scale online draft co-training. For CP, we extend packed, load-balanced zigzag ring attention by merging rank-local branch attention with causal main-sequence attention. For PP, TapChannel transports intermediate target features across stages via a separate path, leaving the pipeline schedule unaffected. Experiments demonstrate that co-trained drafts closely track the policy baseline while delivering substantial rollout and end-to-end speedups across model scales up to 122B. Our CP design achieves strong scaling at 256K tokens with significant memory savings over prior work, and our PP transport incurs modest overhead. Code can be found at https://github.com/NVIDIA-NeMo/RL/issues/3698.

# 论文总结

## 1. 核心问题与整体含义

- **背景**：强化学习后训练已成为构建推理与智能体 LLM 的标准范式，而其 wall-clock 时间主要由 **rollout 生成**主导。
- **已有方案**：推测解码通过小 draft 模型并行提出多个 token，再由大 target 策略并行验证，可在不改变输出分布的前提下加速自回归生成；在线草稿协同训练还能随 RL 策略演化持续提升 draft 接受长度，进一步放大加速。
- **核心障碍**：将在线草稿协同训练扩展到**大模型、长上下文 RL 后训练**时，现有并行体系不兼容：
  - **CP 障碍**：标准因果上下文并行不支持 EAGLE-3、DFlash、DSpark 等高级 draft 的**分支结构化注意力**。
  - **PP 障碍**：draft 所需的目标模型中间隐藏特征可能分布在多个流水线阶段，而 draft 通常只位于最后一个 PP 阶段，标准相邻阶段 P2P 通信无法直接传递。
- **整体含义**：论文提出一套端到端系统，在不改变 target 模型既有 CP/PP 拓扑的前提下，使大规模长上下文 RL 在线草稿协同训练变得可行，并在最高 122B 模型上验证了显著加速。

## 2. 方法论

### 2.1 在线草稿协同训练目标

- 设策略参数为 \(\theta\)，draft 参数为 \(\phi\)。draft 在策略 rollout token 上训练，并对 target 中间特征 \(H_\theta(x)\) 施加 stop-gradient。
- 联合目标为：
  \[
  L(\theta,\phi)=L_{RL}(\theta)+\lambda L_{draft}(\phi;x,\mathrm{sg}(H_\theta(x)))
  \]
- draft 被实例化为策略最后一个 PP 阶段上的子模块，与策略模型联合更新。

### 2.2 CP 下的分支注意力

- 核心思想：每个分支 query 同时关注两类 key：
  - **主序列因果前缀**：跨 CP rank 分片。
  - **分支局部 key**：保留在拥有该分支 anchor 的 rank 上，不参与跨 rank 通信。
- 主序列部分沿用**打包、负载均衡的 zigzag ring attention**：K/V 在 ring 中循环，query 保持本地。
- 分支局部注意力在本地计算，然后与主序列注意力结果按 online-softmax 方式合并：
  \[
  \ell=\log(e^{\ell_m}+e^{\ell_b}),\quad
  O=e^{\ell_m-\ell}O_m+e^{\ell_b-\ell}O_b
  \]
  其中 \(O_m,\ell_m\) 来自主序列，\(O_b,\ell_b\) 来自分支局部。
- 该统一机制支持：
  - **EAGLE-3**：TTT 训练时模拟多步自回归，产生逐步增长的分支。
  - **DFlash**：块扩散式并行生成候选块。
  - **DSpark**：在 DFlash 基础上加入 Markov head 恢复块内因果依赖。
- 通信上，分支局部 K/V 不跨 rank 传输，因此通信量与分支数量/深度无关；前向通信量约为：
  \[
  V^{fwd}_{CP}=\frac{2(C-1)N}{C}d_{kv}b
  \]
  反向复用同一 K/V ring，不产生额外分支相关流量。通信在 ring-step 粒度与注意力重叠。

### 2.3 PP 下的 TapChannel

- 问题：产生 tap 的层跨多个 PP 阶段，而 draft 只在最后阶段；标准流水线通信仅连接相邻阶段。
- TapChannel 为 draft 阶段上的每个源阶段维护一个**预分配 mailbox slot**：
  - 源阶段完成某 microbatch 的 policy forward 后，将 tap 写入自己的 slot。
  - draft 阶段在同一 microbatch 自身 forward 前读取该 slot。
- 同步机制：
  - 每个 slot 带 sequence stamp，生产者和消费者在读写时递增。
  - 同节点源使用 CUDA IPC；跨节点源使用独立 NCCL communicator + GPUDirect RDMA。
  - buffer 复用由 bounded in-flight sends 和接收端 CUDA events 管理。
- 该路径独立于流水线调度，不进入也不改变 pipeline schedule。
- 每 microbatch 传输量为：
  \[
  V_{Tap}=bn\sum_{s\in S}d_s
  \]
  每个特征只直接传输一次，不随 PP hop 数增加。
- 若传输能在源阶段产出 tap 到 draft 阶段 forward 之间的 slack window 内完成，则不增加额外延迟；只有超出 slack 的部分形成可见开销。
