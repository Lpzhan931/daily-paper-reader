## 摘要
推测解码通过并行验证多个草拟 token 来加速 LLM 推理，使得单次目标模型前向传播能够接受多个 token。按照其构造，验证过程会为被接受和被拒绝的 token 都计算表示。然而，传统草拟器仅保留被接受 token 的表示，使得花费在被拒绝 token 上的大量验证器计算实际上被浪费。我们发现，目标前向传播期间生成的这些被丢弃隐藏状态保留了关于未来 token 的有用信息，可以改进后续草拟。然而，实现这一机会面临两个不同挑战。在推理时，回收开销可能增加草拟延迟，削弱因接受长度增加而获得的加速。在训练时，标准并行草拟器训练不会产生与推理对齐的被拒绝状态，而通过顺序 rollout 获取它们则会牺牲跨训练位置的并行性。我们提出 Carryover Drafting，解决这两个挑战。Carryover 将被拒绝的目标隐藏状态回收为临时 KV 上下文，使草拟器能够选择性地关注它们。它复用了草拟器现有接口，仅添加一个学习到的嵌入来区分被拒绝状态与已提交上下文。额外的 KV 上下文在每轮草拟时被替换，使其长度限制在一个提议块内。我们提出并行 draft--verify--draft 训练，使草拟器接触与推理对齐的被拒绝状态，同时保持跨训练位置的并行性。在 DFlash 和一个源自 DSpark 的半自回归草拟器上、跨两个目标模型的实验表明，这一简单的 Carryover 机制相比相应基线将平均接受长度提高了 6.5--14.7%，端到端 vLLM 加速提高了 7.9--14.4%，在翻译任务上加速增益达到 28.8%。

## Abstract
Speculative decoding accelerates LLM inference by verifying multiple drafted tokens in parallel, allowing a single target forward pass to accept several tokens. By construction, verification computes representations for both accepted and rejected tokens. Yet, conventional drafters retain only the representations of accepted tokens, leaving the substantial verifier computation spent on rejected tokens effectively wasted. We find that these discarded hidden states generated during target forward retain useful information about future tokens that can improve subsequent drafts. However, realizing this opportunity poses two distinct challenges. At inference, recycling overhead can increase drafting latency, diminishing the speedup gained from increased acceptance length. During training, standard parallel drafter training does not produce inference-aligned rejected states, while obtaining them through sequential rollouts would sacrifice parallelism across training positions. We introduce Carryover Drafting, which addresses both challenges. Carryover recycles rejected target hidden states as temporary KV context, allowing the drafter to selectively attend to them. It reuses the drafter's existing interface and adds only a single learned embedding to distinguish rejected states from committed context. The additional KV context is replaced each drafting round, keeping its length bounded by one proposal block. We introduce parallel draft--verify--draft training that exposes the drafter to inference-aligned rejected states while preserving parallelism across training positions. Experiments with DFlash and a DSpark-derived semi-autoregressive drafter across two target models show that this simple Carryover mechanism improves average acceptance length by 6.5--14.7% and end-to-end vLLM speedup by 7.9--14.4% over the corresponding baselines, with speedup gains reaching 28.8% on translation.

# Carryover Drafting 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：推测解码（speculative decoding）通过一个轻量级 drafter 一次性提出多个 token，再由 target 模型单次前向并行验证，从而一次接受多个 token，加速自回归 LLM 推理。drafter 质量（即接受长度）是加速的核心因素。
- **已有做法**：EAGLE、EAGLE-3、DFlash、DSpark 等目标条件化 drafter 会复用 target 已计算的隐藏状态来提升草稿质量。
- **被忽视的浪费**：按构造，验证阶段会为**被接受和被拒绝**的 token 都计算表示，但传统 drafter 只保留接受 token 的隐藏状态，把花在被拒绝 token 上的大量验证计算直接丢弃。
- **核心洞察**：这些被丢弃的拒绝隐藏状态仍保留关于未来 token 的有用信息，可用于改进后续草稿。但利用它面临两个挑战：
  - **推理时**：投影与关注额外状态的回收开销可能抵消接受长度增加带来的加速；若跨轮保留还会导致 KV 上下文无限增长。
  - **训练时**：标准并行 drafter 训练基于录制的 target 响应，不会产生与推理对齐的拒绝状态；用顺序 rollout 获取又会牺牲训练位置的并行性。
- **整体含义**：论文提出 Carryover Drafting，把“验证阶段的废料”回收为有效信号，以极小改动换取推测解码的显著加速，并指出“更强 drafter 会留下更有用的拒绝状态”，暗示该方法收益可随 drafter 改进而增大。

## 2. 方法论

### 2.1 核心思想
- 将被拒绝的 target 隐藏状态作为**临时只读 KV 上下文**回收，供下一轮草稿通过 drafter 已有的注意力层选择性关注。
- 复用 drafter 现有接口（同一投影 F 与 K/V 投影），仅新增**一个学习嵌入** `E_carry` 来区分拒绝状态与已提交上下文。
- 每轮草稿**替换**上一轮的 carryover 上下文，使其长度被限制在一个提案块（B 行）内；全部接受时该上下文为空。
- 拒绝状态**不替换**已接受 token 的隐藏状态，也**不进入 target KV cache**，保证验证分布不变。

### 2.2 关键公式与推理更新
- 记第 r 轮 target 隐藏状态 `H_r = (h_{r,1},…,h_{r,B})`，接受前 m_r 个，则：
  - 接受部分 `H_acc = h_{1:m}`，拒绝部分 `H_rej = h_{m+1:B}`
  - `Φ_ℓ(H) = (K_ℓ(F(H)), V_ℓ(F(H)))`（F 为已有融合投影，K_ℓ、V_ℓ 为各层已有投影）
- Carryover 构造：
  - `U_{r+1,ℓ} = Φ_ℓ(H_rej_r + E_carry)`
  - `ctx_{r+1,ℓ} = [C_{r+1,ℓ} ; U_{r+1,ℓ}]`（C 为正常更新的已提交上下文）
- 推理时每个 drafter 层执行：收集全部状态 → 仅对拒绝部分加 `E_carry` → 过已有投影 → 接受行扩展 C，拒绝行作为临时 U 并在下轮替换。
- **缓存语义**：拒绝行在验证工作区被复用前收集；保留其计算时的绝对位置，RoPE 仅在 drafter 投影为 key 时应用一次。
- **验证有效性**：drafter 的提案分布 q 随历史变化，但 target 概率与接受/残差修正规则不变，因此仍保持目标分布。

### 2.3 并行 draft–verify–draft 训练
- 在录制的 target 响应上采样随机锚点（每响应 512 个），Baseline 与 Carryover 共享相同数据与损失。
- 每个锚点构造一次局部转移：
  1. **Draft（无梯度）**：drafter 生成贪心提案 d_i。
  2. **Verify（冻结 target，并行）**：用块对角因果掩码让各分支读自己的记录前缀与提案前驱，返回接受长度 m_i 与拒绝隐藏状态 H_rej_i（detach）。
  3. 锚点平移至 `a'_i = a_i + m_i + 1`（下一个纠正或 bonus 位置）。
  4. **Second Draft（有梯度）**：读记录前缀至 a'_i，经上述公式接收 H_rej_i，对记录的后续做监督；梯度只流经第二阶段，包括共享投影与 carryover 嵌入。
- 全部接受时 H_rej = ∅，第二阶段退化为平移锚点上的基线训练，仍提供监督。
- 关键点：不新增 target 数据、不生成新 target 续写，记录响应仍是监督来源；各锚点独立构造，训练保持跨位置并行。

## 6. 主要结论与发现

- **接受长度**：平均提升 **6.5–14.7%**，且在所评估的每个数据集设置上都有增益。
- **端到端加速**：相对自回归解码的平均加速提升 **7.9–14.4%**，说明接受增益可覆盖回收开销。
- **任务差异显著**：翻译任务增益最大，T=1 下 Qwen3-4B Markov 达 **28.6%**，加速增益最高 **28.8%**。
- **跨 drafter 通用**：从完全并行的 DFlash 到半自回归的 Markov 均有效，说明 Carryover 与块内依赖建模互补。
- **回收内容**：回收 target 隐藏状态远优于 token hint（草稿/target token 提示）；显式区分拒绝状态仅需一个嵌入即可接近独立投影器的效果。
- **机制解释**：
  - 在匹配解码锚点下，ON 相对 OFF 在每个位置提升 Recall@1 1.28–5.60 点、Recall@16 0.29–1.89 点。
  - 增益与**重收敛**（拒绝轨迹预测与最终提交 token 的一致性）相关性最高（r=0.96，去掉翻译后 0.90），高于拒绝后接受（r=0.52/0.71）与拒绝状态数量。
  - Markov 比 DFlash 每轮重收敛位置更多（2.76 vs. 2.51），在 8 个数据集中的 7 个获得更大 Carryover 增益。
- **注意力证据**：约 19.78% 的 full-softmax 注意力落在 carried rows 上，15-rejected 子集达 23.40%，证明该接口确实被读取。

## 7. 优点

- **方法极简且集成成本低**：只新增一个学习嵌入，复用 drafter 已有投影与注意力接口，无需专用 gate 或额外投影模块。
- **上下文有界**：每轮替换 carried-over 状态，额外 KV 长度恒为一个提案块 B，避免 KV 无限增长。
- **训练保持并行**：parallel draft–verify–draft 在不牺牲训练位置并行性的前提下，构造出与推理对齐的拒绝状态，且不新增 target 数据。
- **保留推测解码正确性**：拒绝状态仅作为 drafter 输入，不改 target 概率与接受规则，不污染 target KV cache。
- **实验设计较严谨**：baseline 与 carryover 共享数据、响应、损失与评测设置；提供匹配锚点的 replay 诊断，区分“拒绝后接受”与“重收敛”两个概念，并诚实说明消融的混杂因素。
- **可解释性与可扩展性**：给出重收敛与增益的量化关联，并指出该方法收益可能随 drafter 变强而增大，为后续工作提供方向。

## 8. 不足与局限

- **未与置信度调度联合评估**：DSpark 的 confidence scheduling 会改变可用拒绝状态分布，且 Carryover 改变 drafter 预测可能需要重校准阈值；作者明确未做此评估。
- **未覆盖树解码**：与 Medusa、DDTree 等树验证方法的结合仅停留在讨论层面，涉及“保留哪个分支的拒绝状态”等未解决问题。
- **仅单轮保留**：训练只覆盖一轮 carryover，未支持多轮保留；更长的保留需依赖 on-policy rollout 训练（如 Draft-OPD），属未来工作。
- **评测规模有限**：仅 2 个 target（4B、12B）与 1 个 benchmark（844 prompt），未验证更大模型、其他 serving 框架或更广泛领域。
- **算力信息不完整**：论文未披露训练 GPU 型号、数量与总训练时长，复现成本难以评估。
- **消融隔离不足**：回收信息类型对比同时改变了信息内容与进入路径，无法完全归因于“隐藏状态”本身。
- **加速上限受任务影响**：不同数据集增益差异大（如 Qwen3-4B DFlash 在 RAG 上 T=1 仅 +1.1%），方法收益并非在所有场景都稳定显著。
- **训练数据来源单一**：监督信号来自固定的公开 prompt 混合与 target 重新生成的响应，对领域偏移的鲁棒性未讨论。
