## 摘要
自回归大语言模型（LLM）解码在每一步都会重新读取不断增长的键值（KV）缓存，因此长上下文注意力受限于图形处理器（GPU）内存带宽。块稀疏注意力会跳过低贡献的 KV 块，但在当前查询-键（QK）乘积之后才做决定的选择器（例如最大相对块阈值化，BLASST）仍会读取每个 K 块；而根据当前查询进行判断的存内处理（PIM）过滤器则会在关键路径上引入一个串行 PIM 阶段。我们提出 AMEND，一种消除这两种依赖的 GPU-PIM 注意力设计。AMEND 根据在更早步骤中审计得到的裕度来预测每个块的 BLASST 判定，因此 GPU 只获取预测为幸存者的块，而高带宽内存（HBM）中的近存储体 PIM 单元同时为被省略的补集评分。一个栈级控制器合并这两种观测，更新预测器，并提前生成下一步的掩码，因此每个被预测丢弃的块都会被重新观测，而不会阻塞当前 token。工作点通过受约束的贝叶斯优化在误丢弃预算下离线选择。在 LongBench 和 RULER 运行中，AMEND 保持了接近基线的任务质量；在批大小为 8 的模拟中，在 8K-64K 上下文范围内，它相比稠密注意力实现了 1.40–3.63 倍的端到端解码加速，并将动态解码能耗降低 28–66%。

## Abstract
Autoregressive large language model (LLM) decoding re-reads a growing key-value (KV) cache at every step, so long-context attention is bound by graphics processing unit (GPU) memory bandwidth. Block-sparse attention skips low-contribution KV blocks, but a selector that decides after the current query-key (QK) product, such as max-relative block thresholding (BLASST), still reads every K block, and a processing-in-memory (PIM) filter that decides from the current query places a serial PIM stage on the critical path. We present AMEND, a GPU-PIM attention design that removes both dependencies. AMEND predicts each block's BLASST verdict from margins audited at earlier steps, so the GPU fetches only predicted survivors while near-bank PIM units in high-bandwidth memory (HBM) concurrently score the omitted complement. A stack-level controller merges both observations, updates the predictor, and eagerly generates the next step's mask, so every predicted drop is re-observed without blocking the current token. Operating points are selected offline by constrained Bayesian optimization under a false-drop budget. Across LongBench and RULER runs, AMEND preserves near-baseline task quality; in simulation at batch size 8, it achieves $1.40$-$3.63\times$ end-to-end decode speedup and 28-66% lower dynamic decode energy than dense attention across 8K-64K contexts.

# AMEND 论文结构化总结

## 1. 核心问题与研究动机

- **背景瓶颈**：自回归 LLM 解码每步生成一个 token，需要将当前查询与全部缓存键做 QK 计算。KV 缓存随序列长度增长而查询固定，导致长上下文解码成为**GPU 显存带宽受限**任务，且随上下文变长而愈发主导总时延。
- **块稀疏注意力的两类局限**：
  - **后 QK 选择器（如 BLASST）**：虽然能跳过被丢弃块的 softmax、V 读取与 PV，但必须先读完所有 K 块才能得到判决。论文量化指出，在 90% 块稀疏度下，K 仍占剩余 K+V 逻辑流量的约 **91%**，K 流量与 Dense 相同。
  - **当前查询 PIM 过滤器**：把全缓存评分搬到 PIM，但掩码仍依赖当前查询，因此在"查询→分数→掩码→注意力"的串行链上插入了一个 PIM 阶段，无法与 GPU 并行。
- **整体含义**：GPU 与 PIM 本是两个可并行的引擎，但现有方案未能打破串行依赖。AMEND 的核心洞见是——若掩码可由**更早步骤的历史证据**预测，则 GPU 可零延迟启动幸存块注意力，PIM 并行审计被丢弃块，从而同时消除"读全 K"和"串行 PIM 阶段"两大依赖。

## 2. 方法论

### 2.1 核心思想
- **用历史 margin 预测当前 BLASST 判决**：BLASST 判决本质是每个块的 margin（块最大值 − 排他前缀最大值 − 阈值偏移 η）的符号。margin 的**大小**（而非仅符号）携带连续信号，可区分"远低于阈值"与"勉强低于阈值"。
- **补集审计（Complement Audit）**：预测丢弃会打开"观测漏洞"（selective-labels 问题）——被丢弃块永不再被评分，错误丢弃无法自我纠正。AMEND 让每个被预测丢弃的完整块都被 GPU 或 PIM 重新观测，审计结果不回修当前输出，而是**重新调节下一步预测器状态**。
- **急切下一步掩码生成（Eager Next-Mask）**：审计在当前步内完成，折叠进状态后生成下一步掩码，当前 token 的输出永不等当前审计（"no wait, no repair"）。

### 2.2 关键技术细节与流程

**预测器状态**：每个单元 (层, KV 头, 块) 维护四元组：
- μ：margin 的 EMA
- M₂：二阶矩（用于导出波动率 σ = √(M₂ − μ²)）
- a：连续丢弃年龄
- c：2-bit Schmitt 计数器（抑制孤立翻转）

**决策规则**（式 1–2）：
- 基础条件：`u_t = 1[a ≥ r] · 1[μ + zσ < −δ] · 1[base eligible]`
- 等价实现避免开方：当 q = μ + δ < 0 且 q² > z²v 时成立（v = max(M₂−μ², 0)）
- Schmitt 计数器饱和才发出丢弃：`c⁺ = clip(c⁻ + 2u_t − 1, 0, 3)`，`D̃_t = 1[u_t=1 ∧ c⁺=3]`

**五步逐步循环**（Algorithm 1）：
1. **Predict**（控制器，上一步末）：评估预测器 + 硬保持（block 0、最后 R 块、部分尾块）→ 生成 P_keep、物理并集 U_t、补集 A_t
2. **GPU attention**：读取并集 K 块，计算幸存者 QK 与块最大值，用 survivor BLASST 收紧 V/PV 保持集，完成 softmax 与 PV
3. **Complement QK**（PIM，与 2 并行）：对全局被省略块计算 QK，仅返回块最大值
4. **Reconstruct**（控制器）：按块序合并 GPU 与 PIM 最大值，运行排他前缀与 GQA 归约，得到 A_t 的完整缓存 margin γ* 与判决
5. **Fold**（控制器）：将两个观测通道折入 S⁻_{t+1}，用于生成下一步掩码

**执行契约五条不变量**：掩码仅通过 t−1 反馈；预测丢弃在步内不回滚；每个预测丢弃完整单元被 GPU-PIM 观测划分覆盖；O_t 不依赖审计 t；审计 t 生成步 t+1 掩码。

**系统映射**：GPU 负责幸存 QK、survivor BLASST 收紧、softmax、PV；AttAcc 派生的近存储体 GEMV 负责补集 QK；栈级控制器负责合并、重建、状态更新与下一步掩码。保留恒等式：QK_surv + QK_omit = QK_full。

**离线工作点选择**：五维混合型参数 θ = (r, δ, α, R, z) 通过 SCBO 在误丢弃预算 τ 下最大化丢弃召回，不放松约束。

- **SCBO 有效**：200 次评估达 0.651 最优可行召回，优于随机搜索同预算的 0.597。

## 7. 优点

- **问题定位精准**：清晰量化了后 QK 稀疏选择器的 K 流量缺口（90% 块稀疏下 K 仍占 91% 剩余流量），并指出当前查询 PIM 过滤的串行瓶颈，动机充分。
- **范式创新**：提出"因果预 QK 判决预测 + 补集审计 + 急切下一步掩码"三件套，首次将预测的观测漏洞问题（selective-labels）在稀疏注意力场景中显式解决，且审计不阻塞当前 token。
- **理论自洽**：给出 γ_P ≥ γ_U ≥ γ* 的单调性证明，保证 survivor BLASST 不引入额外误丢弃；执行契约五条不变量使依赖关系精确可验证。
- **工程可落地**：采用现有 AttAcc HBM-PIM 衬底，控制器仅需比较/选择/前缀归约/饱和状态更新，无指数与除法，面积预算有据可依。
- **校准方法规范**：将五维混合型参数选择形式化为约束黑盒问题，用 SCBO 在误丢弃预算下离线求解，并在全量评估中报告实现值，方法学严谨。
- **实验诚实**：明确标注仿真外推区间（N>16）、审计停顿暴露点（N=64）及质量下降边界（FDR>5×10⁻²），不回避局限。

## 8. 不足与局限

- **缺乏真实硬件验证**：所有性能与能耗结果来自基于 AttAcc 的仿真器，PIM 阶段时延、带宽与能耗均为参数化建模，未在真实 HBM-PIM 硬件上实测。
- **依赖特定选择器**：AMEND 预测的是 BLASST 的 max-relative 判决，因其逐块可独立追踪；对 Top-K 等依赖全局排名的选择器不直接适用，泛化性受限。
- **批大小扩展性受限**：N≥64 时审计停顿暴露（N=64 为 22.5 μs/token，N=128 为 49.2 μs/token），与 Quest-PIM 在 N=128 时接近持平，高吞吐场景优势减弱。
- **质量评估范围有限**：仅两个模型家族、两个 benchmark；未涉及 MoE、多模态或超长（>64K）上下文；Qwen 仅测 32K。
- **训练/校准开销未量化**：SCBO 搜索需要每条校准实例回放一次解码轨迹，但未报告总搜索墙钟时间或能耗成本；工作点按设置独立选择，部署时需为每个新设置重新校准。
- **误丢弃敏感性**：方法依赖离线设定的误丢弃预算，超过 5×10⁻² 后质量急剧下降，实际部署中若分布漂移（如领域外输入）可能导致预算失效。
- **PIM 功耗约束的隐式假设**：补集审计被假设完全隐藏在 GPU 工作之后，但该假设依赖批不变权重读取与批比例注意力的分解，在极端配置下可能不成立。
- **未报告训练算力细节**：质量运行仅说明使用 A100，未给出卡数、时长与总能耗，复现成本不透明。
