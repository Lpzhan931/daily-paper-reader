## 摘要
投机解码通过让轻量级草稿模型预测未来 token 以供目标模型验证，从而无损加速大语言模型推理。近期的块扩散草稿器通过并行预测多个 token 进一步降低草稿延迟。然而，现有块扩散草稿器会将每个输入位置处的目标隐藏状态投影到一个单独的草稿器侧 KV 缓存中，带来随并发度增长的每请求内存和 KV 写入开销；直接原地复用目标 KV 虽可消除该缓存，却无法在整个块中维持草稿质量。我们提出一种混合目标上下文注入方法，仅用最后一个输入位置处的目标隐藏状态来补充直接目标 KV 复用，且无需单独的草稿器侧 KV 缓存。在此设计基础上，我们提出 H-Spec，一种混合 Mamba-注意力并行草稿器，它通过互补模块利用这两种目标上下文来源。Mamba 模块用投影后的最后一个 token 的目标隐藏状态初始化，而注意力模块原地复用目标 KV。尽管 Mamba 采用循环式形式，其并行扫描使 H-Spec 仍能保持块并行草稿。在三个目标模型和多种任务上，H-Spec 相比最佳基线在平均接受长度上提升 5.0--13.3%，在批大小为 1 的 token 间延迟加速比上提升 5.3--12.6%。在并发服务下，H-Spec 在所评估的并发级别上始终实现更高的吞吐量，同时保持比基线更低的 KV 缓存利用率。

## Abstract
Speculative decoding losslessly accelerates large language model inference by having a lightweight draft model predict future tokens for verification by the target model. Recent block diffusion drafters further reduce drafting latency by predicting multiple tokens in parallel. However, existing block drafters project target hidden states at every input position into a separate drafter-side KV cache, incurring per-request memory and KV-write overhead that grow with concurrency; directly reusing target KVs in place removes this cache but fails to sustain draft quality throughout the block. We propose a hybrid target-context injection method that complements direct target KV reuse with target hidden states only at the last input position, requiring no separate drafter-side KV cache. Building on this design, we propose H-Spec, a hybrid Mamba-attention parallel drafter that consumes the two target-context sources through complementary modules. Mamba modules are initialized with projected last-token target hidden states, while attention modules reuse target KVs in place. Despite its recurrent formulation, Mamba's parallel scan allows H-Spec to preserve block-parallel drafting. Across three target models and diverse tasks, H-Spec improves over the best baseline by 5.0--13.3% in mean accepted length and 5.3--12.6% in batch-size-1 inter-token latency speedup. Under concurrent serving, H-Spec consistently achieves higher throughput while maintaining lower KV cache utilization than baselines across evaluated concurrency levels.

## 1. 核心问题与整体含义
- **背景**：大语言模型自回归生成存在串行瓶颈。投机解码通过轻量草稿模型预测多个未来 token，再由目标模型一次性验证，从而无损加速推理。
- **现有进展**：块扩散草稿器可并行预测多个 token，进一步降低草稿延迟，但通常采用 **KV 注入**：将目标模型每个输入位置的隐藏状态投影为草稿器侧 KV 缓存。
- **核心问题**：草稿器侧 KV 缓存带来额外 GPU 内存和 KV 写入开销，且随并发请求数增长；直接原地复用目标模型 KV 虽可消除该缓存，但会导致块内后期草稿位置的接受率下降。
- **整体含义**：论文试图回答“能否设计一种并行草稿器，在无需草稿器侧 KV 缓存的同时保持强目标模型条件化”。其意义在于同时改善单请求草稿质量与高并发服务效率，将系统效率纳入草稿器设计目标。

## 2. 方法论
### 2.1 核心思想
- 提出 **混合目标上下文注入**：
  - **原地复用目标 KV**：提供细粒度、位置级上下文，无额外内存。
  - **仅使用最后一个输入位置的目标隐藏状态**：在因果注意力下，最后位置隐藏状态已编码完整前缀，提供紧凑的全输入摘要，存储开销为 O(1)。
- 二者互补，避免 O(N) 的草稿器侧 KV 缓存。

### 2.2 H-Spec 架构
- **混合 Mamba-注意力并行草稿器**：
  - **Mamba-2 模块**：用投影后的最后 token 目标隐藏状态初始化循环状态。
  - **注意力模块**：原地复用目标模型 KV 缓存。
  - **轻量因果校正**：采用 DSpark 的 Markov head，引入一阶 Markov 依赖，但论文声明这不是本文主要贡献。
- **跨层隐藏状态融合**：
  - 从选定目标层集合 \(M\) 取最后输入位置的隐藏状态 \(h_n^{(m)}\)。
  - 拼接后经 \(Proj_r\) 融合到中间秩 \(r\)，再经 \(Proj_{d_S}\) 投影为 Mamba-2 初始状态 \(S_{\text{init}}\)。
  - 投影权重跨草稿器层共享，每轮前向只计算一次。
- **并行草稿兼容性**：
  - Mamba 虽为循环形式，但线性状态递推可通过并行扫描一次计算所有草稿位置。
  - 因此 H-Spec 保持块并行草稿，而非逐 token 串行。
- **注意力细节**：
  - 匹配目标模型的 Q/K/V 维度和注意力/KV 头数，以便直接复用目标 KV。
  - 每个 H-Spec 层注意力模块消费某一目标层的 KV。
  - 使用因果注意力、滑动窗口注意力 SWA，窗口 2,048。
  - 掩码块输入的 Q/K 使用目标模型 RoPE 与延续位置索引，保证位置编码一致。
- **架构配置**：
  - 为与 5 层 DFlash/DSpark 参数匹配，H-Spec 使用 4 层：3 个完整 Mamba-attention-MLP 层 + 1 个部分 Mamba-MLP 层。
  - Mamba 头维 64，状态维 4，组数 4，卷积核 4，扩展因子 1；不同目标模型使用 44/48/56 个 Mamba 头。
  - Markov rank 256；目标层选择与 DFlash/DSpark 一致。

### 2.3 算法流程概述
1. 目标模型前向已产生 KV 缓存与隐藏状态。
2. 取最后输入位置、选定目标层的隐藏状态，融合投影为 Mamba 初始状态。
3. 将掩码草稿块输入 H-Spec。
4. Mamba 模块从注入初始状态出发，并行扫描生成各草稿位置隐藏状态。
5. 注意力模块以目标 KV 为前缀、掩码块内因果注意力生成位置级上下文。
6. 输出草稿 logits，经 Markov head 因果校正。
7. 目标模型一次性验证草稿 token，完成投机解码。
