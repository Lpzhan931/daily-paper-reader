## 摘要
DSpark 风格的并行草稿器使推测解码变得非常高效，但其起草阶段在每一轮的关键路径上仍然是串行的。并行推测解码（PSD）将起草与验证重叠起来，然而现有方法必须预先猜测被接受的前缀和奖励 token：一旦猜错，整个批次就会回退到串行起草。我们提出 DPara，一种 PSD 框架，它复用了有效的并行草稿器，同时保证每一轮中骨干网络与验证的重叠，从而彻底消除这种概率性回退。当目标模型进行验证时，DPara 的扩散骨干会为每个接受边界预计算草稿表示，而将奖励 token 留作未指定；随后，一个轻量级自回归头将揭示出的验证结果与匹配的预计算表示相结合，几乎即时地生成下一轮的草稿 token——从而将占主导的骨干前向与验证完全并行化，仅留下可忽略的头开销是串行的。在 Qwen3-8B 和 Qwen3-14B 上，跨七个数学、编程和聊天基准的实验表明，DPara 相较自回归解码实现了平均 3.21× 和 3.52× 的加速，并且同时超越了最强的串行和并行推测解码基线。

## Abstract
DSpark-style parallel drafters have made speculative decoding highly effective, yet their draft phase remains serialized on the critical path of every round. Parallel speculative decoding (PSD) overlaps drafting with verification, yet existing methods must guess the accepted prefix and bonus token in advance: a wrong guess reverts the whole batch to serial drafting. We present DPara, a PSD framework that reuses effective parallel drafters yet guarantees backbone--verification overlap in every round, thereby eliminating this probabilistic fallback altogether. While the target verifies, DPara's diffusion backbone precomputes draft representations for every acceptance boundary with the bonus left unspecified; a lightweight autoregressive head then combines the revealed verification outcome with the matching precomputed representation to emit the next round's draft tokens almost instantly---fully parallelizing the dominant backbone forward with verification and leaving only the negligible head cost serial. Experiments on Qwen3-8B and Qwen3-14B across seven math, coding, and chat benchmarks show that DPara achieves average speedups of $3.21\times$ and $3.52\times$ over autoregressive decoding, surpassing the strongest serial and parallel speculative decoding baselines alike.

## 1. 核心问题与研究动机

- **背景**：推测解码（SD）通过让轻量草稿器（drafter）一次提出多个 token、再由目标模型一次性验证，来缓解解码阶段的显存带宽瓶颈。其端到端效率由两个量决定：**平均接受长度 τ** 与**关键路径上的起草延迟**。
- **并行草稿器**：DART、DFlash 等受扩散语言模型启发，单次前向即可预测多个未来位置的 logits；DSpark、Domino 进一步耦合轻量自回归头恢复序列一致性，提升了 τ。但即便如此，**传统"先起草、后验证"的串行调度仍把起草留在关键路径上**，占端到端延迟的 **24%–32%**（附录 A）。
- **并行推测解码（PSD）的困境**：PSD 试图让起草与验证重叠。但 SSD、PEARL、SpecBranch、AMUSD 等方法必须**预先猜测**被接受的前缀和 bonus token 才能提前生成下一轮草稿。一旦猜错，**整个批次回退到串行起草**（图 2）。
- **批大小放大问题**：单个请求的 bonus 失配概率 p 会被放大为批级的回退概率 1−(1−p)^B。实测在 batch 16 时，SSD 的回退率高达 **57%–96%**（附录 B），聊天类负载最严重（91%–96%）。即"依赖验证结果的并行"在大 batch 下收益被吞噬。
- **核心研究问题**：*Can we completely eliminate probable serial fallback from parallel speculative decoding?* —— 能否彻底消除并行推测解码中的概率性串行回退？
- **论文含义**：作者给出肯定回答，并提出 **DPara**——首个由 DSpark 风格并行草稿器驱动的 PSD 框架，使骨干前向与验证的**重叠不再依赖验证结果**，从而在结构上消除回退。

## 2. 方法论

### 2.1 核心思想
- 将计算划分为两类：**必须等待验证结果的计算** 与 **可独立于验证结果的计算**。
- DSpark 式架构天然支持这种切分：
  - **扩散骨干（backbone）**：昂贵，可在验证进行中为**所有可能的接受边界**预计算草稿表示；
  - **轻量自回归头（AR head）**：廉价，在验证结果揭晓后再注入真实 bonus token。
- 由此把 bonus 条件化**推迟到 AR 头**，实现**每一轮**骨干–验证重叠，且无需预测接受前缀或 bonus。

### 2.2 骨干要求与 M-DFlash
- **DFlash 的局限**：串行调度下，验证已完成，bonus 之前每个位置都有新鲜目标特征，DFlash 只需**单锚点**（bonus）+ 全特征前缀预测未来 d 个位置。
- **DPara 的要求**：骨干在验证尚未结束时启动，此时已知的只有上一轮携带的 token（接受前缀 A, t1…tr 构成 k = r+1 ≥ 1 个**尚未经过目标模型、因此无特征**的锚点）。因此骨干必须：
  1. 从**多个、无特征的锚点**预测未来 d 个位置；
  2. **一次前向覆盖所有可能的 r**。
- **关键洞察**：这只是 DFlash 单锚点语义的**严格扩展**，而非全新函数，因此可通过微调获得。得到 **M-DFlash**（Multiple-anchor-token DFlash）。
- **训练参数策略**：从官方 DSpark checkpoint 初始化，**不引入任何新可训练参数**；仅微调骨干（注意力、MLP 及其归一化）、融合多层目标特征的投影、输入/输出归一化；**冻结**目标模型、草稿器 token embedding、全词表 LM 投影、AR 头与置信度头。

### 2.3 注意力掩码：共享因果脊柱 + 隔离双向分支
- 以 d=3 为例：上一轮 bonus A 与草稿 B、C、D 构成**共享的无特征因果脊柱**。
- 每个锚点只能注意：缓存的目标特征、自身、更早的锚点，**绝不注意更晚的锚点或 mask token**。
- 四组三个 mask 分别对应接受前缀 A、AB、ABC、ABCD；组内 mask **双向互看**，只访问对应的锚点前缀，不同分支彼此不可见（如跟随 C 的分支读 A、B、C 但不读 D，故在"接受 B、C、拒绝 D"时仍然有效）。
- 该树状掩码区别于普通三角因果掩码：**共享锚点只算一次，却为每个接受边界产出 d 个未来 logits**。

### 2.4 损失函数
- 对选定边界，基础 logits 为 ℓi，冻结 AR 头加入上一 token 的修正：
  - `zi = ℓi + W·E(y_{i−1})`，`y0 = b`，`i = 1…d`（E 为头的低秩 token embedding，W 投影到词表）。
- `qi = softmax(zi)` 为学生分布，`pi` 为同位置目标分布，最小化位置加权的交叉熵与全词表概率距离混合损失：
  - `L = Σi mi·wi·[0.1·(−log qi(yi)) + 0.9·Σv |qi(v) − pi(v)|] / Σi mi·wi`
  - 其中 `wi = e^{−(i−1)/γ}`，γ = 4，`mi` 为有效性掩码（仅保留落在 assistant span 内的监督）。
- 分布匹配项让草稿提议与目标的接受行为在全词表上对齐；**置信度损失被禁用**，固定预算 d 不会被动态截断。

### 2.5 算法流程（Algorithm 1，单轮稳态）
1. **并发启动**：M-DFlash 在脊柱 t0:d 上以缓存 C 前向 → 得到所有 r ∈ {0:d} 的基础 logits ℓ(r)1:d；同时目标模型 Mt 验证同一 token 块。
2. **屏障**：目标返回接受长度 r、bonus b、t0:r 的特征。
3. **选择已算好的分支 r**（穷举枚举 ⇒ 无回退）。
4. `y0 ← b`；对 i = 1…d：`zi ← ℓ(r)i + W·E(yi−1)`，`yi ~ softmax(zi)`。
5. 更新缓存 `C ← [C, Cnew_{0:r}]`（丢弃被拒的 tr+1:d）；`t0:d ← (b, y1:d)`，其中新 bonus b 成为下一轮的无特征锚点。
- **近似轮延迟**：`Tstep ≈ max(Tverify, Tprecompute) + THead`。只要骨干落在验证窗口内，**骨干延迟被完全隐藏，关键路径只剩轻量 AR 头**。
