## 摘要
DSpark 风格的并行草稿器使投机解码极为有效，但其草稿阶段仍在每一轮的关键路径上串行执行。并行投机解码（PSD）将草稿与验证重叠，然而现有方法必须预先猜测被接受的前缀和 bonus token：一旦猜错，整个批次就会退回到串行草稿。我们提出 DPara，一个 PSD 框架，它复用有效的并行草稿器，同时保证每一轮中主干与验证的重叠，从而完全消除这种概率性回退。在目标模型进行验证时，DPara 的扩散主干会为每个接受边界预计算草稿表示，并将 bonus token 留为未指定；随后，一个轻量级自回归头将揭示出的验证结果与匹配的预计算表示结合，几乎即时地输出下一轮的草稿 token——将占主导的主干前向与验证完全并行化，仅留下可忽略的头开销串行执行。在 Qwen3-8B 和 Qwen3-14B 上跨七个数学、代码和聊天基准的实验表明，DPara 相较自回归解码分别取得 3.21 倍和 3.52 倍的平均加速，并超越了最强的串行与并行投机解码基线。

## Abstract
DSpark-style parallel drafters have made speculative decoding highly effective, yet their draft phase remains serialized on the critical path of every round. Parallel speculative decoding (PSD) overlaps drafting with verification, yet existing methods must guess the accepted prefix and bonus token in advance: a wrong guess reverts the whole batch to serial drafting. We present DPara, a PSD framework that reuses effective parallel drafters yet guarantees backbone--verification overlap in every round, thereby eliminating this probabilistic fallback altogether. While the target verifies, DPara's diffusion backbone precomputes draft representations for every acceptance boundary with the bonus left unspecified; a lightweight autoregressive head then combines the revealed verification outcome with the matching precomputed representation to emit the next round's draft tokens almost instantly---fully parallelizing the dominant backbone forward with verification and leaving only the negligible head cost serial. Experiments on Qwen3-8B and Qwen3-14B across seven math, coding, and chat benchmarks show that DPara achieves average speedups of $3.21\times$ and $3.52\times$ over autoregressive decoding, surpassing the strongest serial and parallel speculative decoding baselines alike.

- **背景**：投机解码（SD）在保持目标分布的前提下加速 LLM 推理，其端到端效率由两个量决定——平均接受长度 τ 和关键路径上的草稿延迟。
- **并行草稿器的进展**：DART、DFlash 等扩散式草稿器在单次前向中预测多个未来位置的 logits，降低草稿成本；但独立预测缺乏 token 间依赖，会损害接受长度。DSpark、Domino 通过"并行扩散骨干 + 轻量自回归头"恢复序列一致性，显著提升 τ。
- **遗留瓶颈**：即使采用先进草稿器，传统"先草稿、后验证"的串行调度仍把草稿阶段留在关键路径上，占端到端延迟的 **24%–32%**（附录 A）。
- **PSD 的困境**：并行投机解码（PEARL、AMUSD、SpecBranch、SSD）尝试让草稿与验证重叠，但必须**预先猜测接受前缀和 bonus token**。一旦猜错，整个批次回退到串行草稿。
- **批处理放大问题**：单请求 bonus 失配概率 p 会被放大为批级回退概率 1−(1−p)^B。实测 SSD 在 batch 16 时回退率高达 **57%–96%**（聊天负载最严重），导致并行收益随服务负载加剧而流失。
- **核心研究问题**：能否**彻底消除**并行投机解码中的概率性串行回退？论文给出肯定回答——DPara。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想：结果无关的预计算
- 将"必须等待验证结果的计算"与"可独立于验证结果进行的计算"分离。
- 验证进行时，扩散骨干**为所有可能的接受边界（r ∈ {0,…,d}）一次性预计算草稿表示**，且**不指定 bonus token**；验证返回 (r, b) 后，仅由轻量 AR 头结合真实 bonus 即时产出下一轮草稿。
- 时间模型：**T_step ≈ max(T_verify, T_precompute) + T_Head**，骨干延迟被完全隐藏，仅 AR 头留在关键路径。

### 2.2 骨干要求与 M-DFlash
- **新需求**：骨干需从**多个无目标特征的锚点**（k = r+1 ≥ 1 个尚未过目标模型的 token）预测未来 d 个位置，且需对**所有 r 同时成立**——这是 DFlash 单锚点语义的严格扩展，而非新函数。
- **M-DFlash**：从官方 DSpark checkpoint 初始化，**不引入任何新的可训练参数**，只微调扩散骨干。
  - **可训练**：骨干块（attention、MLP 及其 normalization）、多层目标特征融合投影、输入/输出 normalization。
  - **冻结**：目标模型 M_t、草稿器 token embedding、全词表 LM projection、AR 头、置信头。
- **树状注意力掩码**：前一轮 bonus A 与草稿 B、C、D 构成共享的无特征因果 spine；每个锚点只可见缓存目标特征、自身及更早锚点；d+1 组掩码对应接受前缀 A / AB / ABC / ABCD，**组内双向可见、组间完全隔离**。这样共享锚点只算一次，却能为每个接受边界输出 d 个未来 logits。

### 2.3 损失函数
- 位置加权混合损失（交叉熵 + 全词表概率距离）：
  - 学生分布 q_i = softmax(z_i)，z_i = ℓ_i + W·E(y_{i−1})，y_0 = b
  - L 为 0.1·(−log q_i(y_i)) + 0.9·Σ_v |q_i(v) − p_i(v)| 的加权和
  - 权重 w_i = e^{−(i−1)/γ}，γ = 4；m_i 为有效位置掩码
  - 分布匹配项对齐草稿与目标的接受行为；**置信损失被关闭**，固定预算 d 不做动态截断。

### 2.4 算法流程（单轮稳态）
1. **并行启动**：M-DFlash 在共享 spine t_{0:d} 上预计算所有 d+1 个边界的基础 logits；目标模型同时验证同一 token 块。
2. **屏障**：验证返回接受长度 r、bonus b 及 t_{0:r} 的特征。
3. **选择分支 r**（枚举覆盖，无回退）。
4. **AR 头串行循环**：y_i ∼ softmax(ℓ^{(r)}_i + W·E(y_{i−1}))，y_0 = b。
5. **更新缓存**：追加 t_{0:r} 特征，丢弃被拒后缀；新的 bonus b 作为下一轮的无特征锚点 t_0。
