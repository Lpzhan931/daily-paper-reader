## 摘要
投机解码通过并行验证多个草稿 token 来加速 LLM 推理，使单次目标模型前向传播能够接受多个 token。从机制上，验证过程会为被接受和被拒绝的 token 都计算表示。然而，传统草稿器仅保留被接受 token 的表示，使得花费在被拒绝 token 上的大量验证器计算实际上被浪费。我们发现，这些在目标模型前向传播期间生成却被丢弃的隐藏状态，保留了关于未来 token 的有用信息，可改进后续草稿。然而，实现这一机会面临两个不同挑战。在推理时，回收开销可能增加草稿延迟，削弱因接受长度增加而获得的加速。在训练时，标准并行草稿器训练不会产生与推理对齐的被拒绝状态，而通过顺序 rollout 获取它们则会牺牲跨训练位置的并行性。我们提出 Carryover Drafting，它同时解决这两个挑战。Carryover 将被拒绝的目标隐藏状态回收为临时 KV 上下文，使草稿器能够选择性地关注它们。它复用草稿器现有接口，仅添加一个可学习嵌入，以区分被拒绝状态与已提交上下文。额外的 KV 上下文在每轮草稿时被替换，使其长度限制在一个提议块之内。我们引入并行的 draft--verify--draft 训练，使草稿器接触与推理对齐的被拒绝状态，同时保持跨训练位置的并行性。在 DFlash 以及一个源自 DSpark 的半自回归草稿器上、跨两个目标模型的实验表明，这一简单的 Carryover 机制相比相应基线将平均接受长度提升 6.5--14.7%，端到端 vLLM 加速提升 7.9--14.4%，在翻译任务上加速增益达到 28.8%。

## Abstract
Speculative decoding accelerates LLM inference by verifying multiple drafted tokens in parallel, allowing a single target forward pass to accept several tokens. By construction, verification computes representations for both accepted and rejected tokens. Yet, conventional drafters retain only the representations of accepted tokens, leaving the substantial verifier computation spent on rejected tokens effectively wasted. We find that these discarded hidden states generated during target forward retain useful information about future tokens that can improve subsequent drafts. However, realizing this opportunity poses two distinct challenges. At inference, recycling overhead can increase drafting latency, diminishing the speedup gained from increased acceptance length. During training, standard parallel drafter training does not produce inference-aligned rejected states, while obtaining them through sequential rollouts would sacrifice parallelism across training positions. We introduce Carryover Drafting, which addresses both challenges. Carryover recycles rejected target hidden states as temporary KV context, allowing the drafter to selectively attend to them. It reuses the drafter's existing interface and adds only a single learned embedding to distinguish rejected states from committed context. The additional KV context is replaced each drafting round, keeping its length bounded by one proposal block. We introduce parallel draft--verify--draft training that exposes the drafter to inference-aligned rejected states while preserving parallelism across training positions. Experiments with DFlash and a DSpark-derived semi-autoregressive drafter across two target models show that this simple Carryover mechanism improves average acceptance length by 6.5--14.7% and end-to-end vLLM speedup by 7.9--14.4% over the corresponding baselines, with speedup gains reaching 28.8% on translation.

## 1. 核心问题与研究动机

- **背景**：自回归 LLM 每次前向只生成一个 token，投机解码（speculative decoding）通过轻量草稿器并行提议多个 token、由目标模型单次前向并行验证来加速推理，因此**草稿质量（接受长度）是加速的核心因素**。
- **现有做法**：EAGLE / EAGLE-3、DFlash、DSpark 等目标条件化草稿器会复用目标模型已算出的隐藏状态（多层融合后投影为草稿器 KV 上下文）来提升草稿质量。
- **被忽视的浪费**：投机解码中草稿通常只被**部分接受**。验证过程按构造会同时为"被接受 token"和"被拒绝 token"计算表示，但现有草稿器**只保留被接受 token 的隐藏状态，丢弃被拒绝 token 的隐藏状态**，导致大量验证算力被白白浪费。
- **核心问题**：被拒绝的隐藏状态能否"接力"（carry over）用于改进后续草稿？
- **两大挑战**：
  - **推理侧**：加速取决于接受长度与草稿开销的联合权衡；投影并关注额外隐藏状态的开销可能超过收益，且跨轮保留会导致 KV 上下文无限增长。
  - **训练侧**：标准并行草稿训练基于录制的目标响应，**不会产生与推理对齐的被拒绝状态**；用顺序 rollout 获取又会破坏跨训练位置的并行性。
- **整体含义**：论文主张"把验证阶段的废料变成资源"，通过一个极轻量的回收接口把被拒绝状态变成下一轮草稿的临时 KV 上下文，从而在不改变验证正确性的前提下同时提升接受长度与端到端吞吐。

## 2. 方法论

### 2.1 核心思想
- 将被拒绝的目标隐藏状态**通过草稿器已有的投影接口**（而非新增专用模块）回收为**只读的临时 KV 上下文**，让草稿器用自己现有的注意力层选择性地关注它们。
- 仅新增**一个可学习嵌入 $E_{carry}$**，用于在投影前区分"被拒绝状态"与"已提交上下文"。
- 每轮草稿**替换**（而非累积）携带状态，使额外 KV 长度**上界为一个提议块 $B$**。

### 2.2 关键公式与推理流程
- 记第 $r$ 轮提议位置上的目标隐藏状态为 $H_r=(h_{r,1},\dots,h_{r,B})$，接受前 $m_r$ 个，则
  - $H^{acc}_r = h_{r,1:m_r}$，$H^{rej}_r = h_{r,m_r+1:B}$
  - 复用已有投影：$\Phi_\ell(H) = \big(K_\ell(F(H)),\; V_\ell(F(H))\big)$
- 携带上下文构造：
  - $U_{r+1,\ell} = \Phi_\ell(H^{rej}_r + E_{carry})$
  - $ctx_{r+1,\ell} = [\,C_{r+1,\ell}\,;\,U_{r+1,\ell}\,]$
  - 其中 $C_{r+1,\ell}$ 是基线更新后的已提交草稿 KV 上下文。
- **缓存语义**：被拒绝行只作为只读草稿上下文 $U_\ell$ 存活一轮，**不进入目标模型 KV 缓存**，也不替换已接受 token 的隐藏状态；完全接受时 $U_\ell=\varnothing$；每轮替换旧 $U_\ell$；RoPE 在投影为 key 时按绝对位置应用一次。
- **验证正确性**：草稿分布 $q$ 改变，但目标概率与接受/残差修正规则不变，因此仍保持目标分布。

### 2.3 延迟模型
- $L_{carry} \approx (t_{draft}+t_{verify}+t_{reuse})/\tau$，$S_{carry}\approx \dfrac{\tau\, t_{AR}}{t_{draft}+t_{verify}+t_{reuse}}$
- 因此设计目标是**高接受 + 低开销**，这解释了为何坚持复用现有投影、每轮替换。

### 2.4 并行 draft–verify–draft 训练
- 在每条录制的目标响应 $y$ 上随机采样 512 个锚点 $a_i$。
- 步骤：
  1. **Draft（无梯度）**：草稿器在 $a_i$ 处生成 detached 提议 $d_i$；
  2. **Verify（冻结目标）**：用块对角因果掩码并行验证各分支（每条分支只读自己的录制前缀与自身提议前驱），贪婪验证返回接受长度 $m_i$ 和 detached 被拒绝状态 $H^{rej}_i$；
  3. **Draft（有梯度）**：锚点平移到 $a'_i = a_i + m_i + 1$（下一个修正/bonus 位置），第二轮草稿读取录制前缀并接收 $H^{rej}_i$，对录制的后续 $y_{>a'_i}$ 计算损失。
- **梯度只流经第二轮草稿**（含共享投影与 $E_{carry}$），第一轮与验证均 detached。
- 每个锚点独立构造转移，因此**训练在锚点间保持并行**，无需完整多轮投机 rollout；完全接受时退化为"平移锚点处的基线训练"，仍提供监督；监督来源仍是录制的目标响应，不新增目标续写。

## 6. 主要结论与发现

- **接受长度**：所有 8 个数据集、所有目标–草稿器–温度组合上均有提升，平均接受长度提升 **6.5–14.7%**。
- **端到端加速**：相对自回归解码的 vLLM 平均加速提升 **7.9–14.4%**，说明收益能覆盖回收开销；并发 1→32 时绝对加速下降，但相对基线的增益保持。
- **任务差异显著**：**翻译任务增益最大**，Qwen3-4B Markov 在 $T=1$ 达 **+28.6% 接受长度、+28.8% 加速**；RAG 在 $T=1$ 的 Qwen3-4B DFlash 上仅 +1.1%。
- **携带什么最有效**：目标隐藏状态 > 目标 token 提示 > draft 自身 token 提示（后者甚至为负）。
- **如何区分**：不显式区分已具竞争力；19.7M 参数的独立投影器略优，但单个嵌入以近乎相同的接受率换来更轻的接口，故被选为默认。
- **机制解释**：在匹配锚点上，ON 相比 OFF 在全部位置提升 Recall@1（+1.28–5.60 点）与 Recall@16（+0.29–1.89 点）；注意力诊断显示约 **19.78%** 的全 softmax 注意力落在携带行上（15 个被拒绝状态子集为 23.40%）。
- **收益来源是"再收敛"而非"状态数量"**：数据集级增益与再收敛位置数高度相关（r=0.96，去掉翻译为 0.90），明显高于"拒绝后被接受次数"（r=0.52 / 0.71）。
- **更强的草稿器获益更多**：Markov 在 8 个数据集上再收敛位置数均高于 DFlash（平均 2.76 vs 2.51），并在 8 个中的 7 个获得更大 Carryover 增益，暗示草稿器越强、被拒绝状态越有用。

## 7. 优点

- **洞察新颖且实用**：把"验证必然产生的被拒绝表示"识别为被浪费的资源，视角简单但此前少有人系统利用。
- **接口极轻量**：完全复用既有投影与注意力，只加一个嵌入；每轮替换、长度上界为一个块，避免 KV 无限增长，工程集成成本低。
- **训练方案设计巧妙**：draft–verify–draft 在**不牺牲锚点并行性**、**不新增目标续写**、**不改变监督来源**的前提下构造出与推理对齐的被拒绝状态；梯度只走第二轮，实现干净。
- **理论安全性说明到位**：明确指出携带状态只作为草稿输入、不写入目标 KV，因此不破坏投机采样的分布正确性。
- **实验证据链完整**：从端到端指标（接受长度、加速、吞吐）到机制诊断（匹配锚点 Recall、注意力分布、再收敛相关性）形成闭环，并用相关性解释了任务间差异。
- **泛化性验证**：跨 2 个目标模型、并行与半自回归两类草稿器、2 个温度、6 档并发，增益一致为正。
- **诚实的负面/边界报告**：如 RAG 在 $T=1$ 仅 +1.1%，以及消融中承认未完全解耦变量。

## 8. 不足与局限

- **未与自适应调度结合**：作者明确未在 confidence scheduling（DSpark）下评估 Carryover。调度策略会改变可用的被拒绝状态，需在同一策略下重训并可能重校准阈值，这限制了在高并发真实服务场景下的直接可用性结论。
- **仅支持单轮保留**：并行训练只覆盖"携带一轮"，未探索多轮保留/累积策略；更长保留是否带来收益与开销的权衡未知。
- **未覆盖树状验证**：与 Medusa / DDTree 等树验证的结合被留作未来工作，且提出"该保留哪条分支状态"是新的开放问题。
- **训练算力未披露**：未报告训练 GPU 型号、数量与时长，影响可复现性与成本评估。
- **消融的解耦不足**：信息类型消融同时改变了信息与注入路径，无法分离贡献；独立投影器与嵌入的差距（约 1–1.4 个点）虽被以开销为由取舍，但说明该设计选择并非最优。
- **超参/结构选择未充分搜索**：草稿层数 5、提议 15 token、512 锚点、10+3 epoch 等沿用既有配方，未做敏感性分析；嵌入维度、$E_{carry}$ 初始化等细节也未系统探究。
- **增益分布不均，存在任务偏差风险**：翻译任务增益异常突出（最高 28.8%），而 RAG 在部分设置几乎无增益。若在真实负载中翻译类任务占比小，端到端收益可能被高估；论文虽用再收敛相关性解释，但未给出可预测"何时有效"的可操作准则。
- **目标模型规模有限**：仅验证 4B 与 12B，未涉及更大规模（如 70B+）或 MoE 结构，可扩展性证据不足。
- **训练数据为合成/公开指令集**：UltraChat-200K 与 Magpie 的分布可能偏向对话与指令场景，对长上下文、代码仓库级、多轮 agent 等场景的泛化未经检验。
- **吞吐测量环境单一**：全部在单张 H200 上完成，未涉及多卡张量并行、批调度异构或显存压力下的表现。
