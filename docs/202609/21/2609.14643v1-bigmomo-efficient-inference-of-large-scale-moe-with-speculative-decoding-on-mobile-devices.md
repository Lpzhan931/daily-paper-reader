## 摘要
混合专家（MoE）模型可在智能手机上扩展语言模型容量，但专家卸载仍受限于有限的 DRAM 容量和高昂的数据移动开销。顺序词元路由将专家执行与碎片化的闪存读取及多阶段 NPU 准备耦合在一起，使稀疏计算因权重传输而停滞。每次传输仅服务少量词元，随后执行便继续推进。我们利用投机解码的多词元验证窗口，将专家移动与单词元执行解耦，从而实现权重复用、连续闪存读取以及加载—计算重叠。我们提出 BigMoMo，一种跨内存层次结构利用该窗口的移动端 MoE 运行时。它利用接受率、路由影响和移动成本来剪枝投机分支与专家激活；根据运行时共同加载模式重新组织闪存上的专家；并对就绪专家进行批处理，以将 NPU 计算与待处理传输重叠。在两个移动平台上的四个 MoE 模型和五个基准测试中，BigMoMo 相比按需自回归卸载实现了平均 4.83× 的解码加速，相比最佳投机 MoE 基线实现了 1.82× 的加速，并支持参数量高达 30B 的 MoE 模型。

## Abstract
Mixture-of-Experts (MoE) models expand language model capacity on smartphones, but expert offloading remains constrained by limited DRAM capacity and costly data movement. Sequential token routing couples expert execution to fragmented flash reads and multistage NPU preparation, leaving sparse computation stalled on weight transfers. Each transfer serves few tokens before execution moves on. We exploit the multi-token verification window of speculative decoding to decouple expert movement from single-token execution, enabling weight reuse, contiguous flash reads, and load-compute overlap. We present \textsc{BigMoMo}, a mobile MoE runtime that exploits this window across the memory hierarchy. It prunes speculative branches and expert activations using acceptance rates, routing impact, and movement cost; reorganizes on-flash experts according to runtime co-loading patterns; and batches ready experts to overlap NPU computation with pending transfers. Across four MoE models and five benchmarks on two mobile platforms, \textsc{BigMoMo} achieves mean decoding speedups of $4.83\times$ over on-demand autoregressive offloading and $1.82\times$ over the best speculative MoE baseline, supporting MoE models up to 30B parameter.

# BigMoMo 论文详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：移动端个人智能需求增长，推动 LLM 直接部署到手机。MoE 模型通过稀疏激活（每 token 只激活 top-k 专家）在有限算力下扩展模型容量，但**总参数量仍远超手机 DRAM 容量**，必须依赖专家卸载（expert offloading）：非专家权重与高频专家驻留主存，其余专家放在 Flash 二级存储中按需加载。
- **核心问题**：现有 MoE 卸载方案多面向 CPU–GPU 平台（高主机–设备带宽、两层数据通路、易重叠），而**移动端存在三重结构性失配**：
  1. **专家移动带宽受限**：DRAM 容量小（通常 <24 GB，实际可用更少），更多专家留在 UFS Flash，动态路由导致每个专家计算的移动开销频繁且漫长。
  2. **不规则 Flash 访问开销高**：专家从 Flash 而非 host DRAM 读取，对访问粒度与连续性极度敏感；稀疏动态请求变成碎片化随机读，实测有效带宽远低于 UFS 理想带宽。
  3. **多阶段执行路径**：移动 NPU 需要先映射到受限的 NPU buffer，再搬到 8 MiB 片上 VTCM 做反量化/布局转换，才能交给 HMX 计算，形成流水线气泡。
- **根本症结**：MoE 的"参数解耦"只解耦了参数量与计算量，**没有解耦"专家移动"与"逐 token 路由"的时序耦合**——一次权重搬运只服务极少量 token 就被下一次路由打断。
- **整体含义**：作者主张从"模型级参数解耦"转向"**系统级数据移动解耦**"，即把执行粒度从单 token 扩展到**投机解码的多 token 验证窗口**，从而在一个窗口内聚合多个专家的移动请求，实现权重复用、连续 Flash 读取与加载–计算重叠。其更大意义在于证明：移动端高效智能不必只靠"缩小模型"，30B 级 MoE 也能在手机上高效运行。

## 2. 方法论

### 2.1 核心思想

利用投机解码（tree-based speculative decoding）的**多 token 验证窗口**，将专家移动从单 token 执行中解耦，带来三个机会：
- **复用友好的专家移动**：同一验证轮内多个 draft token 命中同一专家，可共享一次加载。
- **Flash 友好的专家访问**：一轮内暴露更多移动请求，提供调度空间把碎片读聚合成顺序读。
- **跨阶段移动重叠**：单次移动服务 m 个 token 时，可隐藏的移动时间为 min(R_j, T_HMX^(m))，计算量增大 → 可隐藏的传输更多。

但直接套用会带来三个实现问题（即三个技术模块的动机）：
1. 低价值投机 token 引入**无用专家移动**；
2. 专家移动依赖路由 + 动态内存状态，**静态放置调度失效**；
3. 不同层次专家的就绪时间不同，**同步等待或立即执行都会造成 NPU 空转气泡**。

### 2.2 关键技术细节

**(1) Reuse-Oriented Expert Movement Admission（§4.2，移动前剪枝）**

- **接受率感知节点剪枝**：节点价值
  \(V_d = \hat{p}_{h(d)} \prod_{u \in \text{path}(d)} q_u\)
  其中 \(\hat{p}_{h(d)}\) 为离线标定的深度接受概率，\(q_u\) 为 draft 模型沿路径的 token 概率。按 \(V_d\) 降序保留累计价值占比达 \(\rho\)（默认 0.9）的最小节点集。
- **层次感知专家剪枝**：定义路由影响
  \(I_e = \sum_{d \in D_e} V_d \min_{j \in T_d \setminus \{e\}} |s_{d,e} - s_{d,j}|\)
  即被低价值节点选中、或存在路由分数相近替代者的专家影响更低。再结合离线 profile 的跨层次移动代价 \(C_e\)，定义剪枝优先级 \(P_e = \Delta I_e / C_e\)，在累积路由影响预算 \(\tau\)（默认 0.4）下迭代剪枝；被剪专家的路由权重**重分配给路由分数最接近的保留专家**，并保证每个节点至少保留一个专家。

**(2) Runtime-Adaptive On-Flash Expert Organization（§4.3，移动中重排）**

- 用**超图**建模最近 K 轮（默认 K=3）的共加载关系：专家为顶点，一轮共加载的专家集合为超边 \(M^l_k\)。
- 为每个超边选择**锚区域** \(A^l_k\)：在所有能容纳 |M^l_k| 个专家的连续 Flash 区域中，选与请求集合重叠最大的那个。
- 超边的 Flash 读时间估计：
  \(T^l_k = T_{Flash}(S(A^l_k)) + \sum_{e \in M^l_k \setminus A^l_k} T_{Flash}(S(e))\)
  第一项为锚区连续读，第二项为区外专家的散读。
- 候选交换 \((e_i, e_j)\)（区外请求专家 ↔ 区内非成员专家）的**重定位收益**为最近 K 轮 Flash 读时间的累计下降：
  \(B_l(e_i,e_j) = \sum_{r=k-K+1}^{k} (T^l_r - \tilde{T}^l_r(e_i,e_j))\)
  每轮只执行收益最大的可行交换，保持总占用不变；**交换仅在两者都已载入 DRAM 后执行**，且在有延迟敏感的 Flash→DRAM 读请求时暂停后台重定位写入。

**(3) Cross-Hierarchy Movement Scheduling（§4.4，移动后执行调度）**

- 专家移动总延迟 \(T_e = T_{Flash}^{(e)} + T_{Map}^{(e)} + T_{VTCM}^{(e)} + T_{HMX}^{(e)}\)，各阶段因驻留状态不同而就绪时间不同。
- VTCM 划分为双缓冲权重区 + 128 KiB 激活/输出区；就绪专家按 buffer 容量组成计算组，超大专家沿输出维 N 以 32 为粒度切分；权重打包为连续 128 B 向量按 bank 并行分发。
- 调度时估计下一个专家就绪间隔 \(\tau_{next}(t) = \min_{e \in E_{pending}(t)} \tau_{map}^{(e,t)}\)，未覆盖移动时间
  \(R_t = \max(0, \tau_{next}(t) - W_t)\)
  其中 \(W_t\) 为残余 HMX 计算时间。
- 组选择策略：若存在 \(T_{VTCM}^{(b)} \le W_t\) 且 \(T_{HMX}^{(b)} \ge R_t\) 的候选，取其中 \(T_{HMX}\) **最短**者（避免过度延迟）；否则在 \(T_{VTCM}^{(b)} \le W_t\) 的候选中取 \(T_{HMX}\) **最长**者（尽量覆盖等待窗口）。新就绪专家持续加入后续成组。

### 2.3 系统流程（§4.1）

构造 draft tree → 节点剪枝（按接受率/置信度）→ 目标验证中每层路由暴露专家分配 → 专家剪枝（含驻留相关的移动代价）→ 驻留查找确定需从 Flash 取回的专家 → 运行时自适应 Flash 重排 → 跨层次调度，就绪专家分批与 HMX 计算重叠，无需等整层专家全部搬完。

  - **局限**：draft 长度/分支宽度默认仅 D=2, B=2，虽做了敏感性（Table 8）但范围偏窄（最大 D=4, B=4）；未报告与原始（非复现）基线实现在其他平台上的对比；缺少对更长上下文/更大 batch 场景的覆盖。

## 6. 主要结论与发现

- **性能**：在 4 个 MoE 模型 × 5 个基准 × 2 个平台上，BigMoMo 平均较 On-Demand 加速 **4.83×**、较 SD-OnDemand 加速 **3.00×**、较最佳基线加速 **1.76×**（结论节与元数据写作 1.82×，摘要中为 1.82×，正文 §5.2 为 1.76×，存在表述不一致）。分模型对最佳基线加速为 Qwen3 1.73×、LFM2 1.47×、Gemma-4 1.80×、ERNIE-4.5 2.03×。
- **尾延迟与端到端**：Qwen3 上 P50/P90/P99 分别较最佳基线提升 1.46×/1.77×/1.98×；四模型端到端加速分别为 1.69×/1.43×/1
