## 摘要
推测解码通过使用轻量级草稿模型提出候选 token，由目标模型并行验证，从而加速大语言模型（LLM）推理。然而，草拟与验证表现出不同的服务特性，并偏好不同的批配置，这使得固定的草稿-目标耦合在并发工作负载下效率低下。现有的分布式设计可以在物理上分离这两个阶段，但往往保留请求或批亲和性，从而阻碍其容量被全局共享。我们提出 NebulaSD，一种多对多（即 M 对 N）推测解码系统，它将草稿 worker 和目标 worker 组织为可独立调度的资源池，并从共享请求池中动态重建阶段特定的批。这种动态重新分配消除了固定的 worker 局部性，要求请求状态在新选择的 worker 上可用，同时不引入迁移停顿。NebulaSD 通过由 worker 触发的批重建以及与模型执行重叠的异步 KV 状态准备来应对这一挑战。我们从系统和扩展性两个角度评估 NebulaSD，结果表明，在四 GPU 部署上，动态池化相比物理分离基线将请求轮处理速率提高了 50.4%，相比同置执行提高了 72.6%，同时显著提高了有效 GPU 利用率。基于性能剖析的仿真进一步表明，在理想化状态移动下，计算侧容量可实现近似成比例的扩展。

## Abstract
Speculative decoding accelerates Large Language Model (LLM) inference by using a lightweight draft model to propose candidate tokens for parallel verification by a target model. Drafting and verification, however, exhibit different service characteristics and favor different batch configurations, making fixed draft-target coupling inefficient under concurrent workloads. Existing distributed designs can physically separate the two stages, but often retain request or batch affinities that prevent their capacities from being shared globally. We present NebulaSD, a many-for-many, or M-for-N, speculative decoding system that organizes draft and target workers into independently schedulable resource pools and dynamically reconstructs stage-specific batches from shared request pools. Such dynamic reassignment removes fixed worker locality, requiring request states to be made available at newly selected workers without introducing migration stalls. NebulaSD addresses this challenge through worker-triggered batch reconstruction and asynchronous KV-state preparation overlapped with model execution. We evaluate NebulaSD from both system and scaling perspectives, showing that dynamic pooling improves request-round processing rate by 50.4% over a physically disaggregated baseline and 72.6% over co-located execution on a four-GPU deployment while substantially increasing effective GPU utilization. Profile-driven simulations further show approximately proportional compute-side capacity scaling under idealized state movement.

## 1. 核心问题与研究动机

- **背景**：LLM 自回归解码延迟高、服务成本大。推测解码（Speculative Decoding）通过轻量草稿模型提议多个候选 token，再由目标模型并行验证，从而在单次目标前向中提交多个 token，显著加速生成。
- **核心矛盾**：草拟（drafting）与验证（verification）两个阶段的服务特性截然不同，且偏好不同的批配置：
  - 草稿模型小（如 Qwen3-1.7B），延迟随 batch 增大几乎不变（batch=512 时仍约 16–18 ms），有大量批处理余量；
  - 目标模型大（如 Qwen3-8B），batch 达到 512 时延迟急剧上升，批处理余量小。
- **现有方案的局限**：
  - 许多系统仍以固定的请求/批关联组织两阶段（固定草稿-目标配对），导致某一阶段的闲置容量无法共享给另一阶段，系统速率被局部较慢阶段限制。
  - 已有的分布式推测解码（如 Disaggregated SD、SLED、WISP、DSD、SPECTRE）虽能物理分离两阶段，但主要面向异构部署、边缘协同、远程草拟等目标，仍保留请求或批亲和性，**未将草稿与目标 worker 同时暴露为可全局调度的资源池**。
- **由此引出的关键挑战**：一旦请求可在 worker 间动态重分配，KV 缓存状态必须在执行前于新 worker 上可用；若迁移置于执行关键路径会引入停顿，若准备过晚则导致 worker 空闲，若过度提前迁移又会干扰前台计算。
- **整体含义**：论文提出 NebulaSD，将推测解码的两阶段视为**可独立供给、独立调度的服务阶段**，通过 M-for-N 资源池化实现全局容量共享，验证了阶段解耦 + 动态批重建 + 异步状态迁移在并发推理场景下的显著收益。

## 2. 方法论

### 2.1 核心思想

- **M-for-N 架构**：将 M 个草稿 worker 与 N 个目标 worker 组织为两个**独立供给、全局可调度**的资源池 \(D=\{d_1,\dots,d_M\}\)、\(T=\{t_1,\dots,t_N\}\)，由集中式调度器统一协调。
- **移除两类亲和性**：
  - 请求不再永久绑定到某个 worker（同一请求在不同推测轮可由不同 worker 服务）；
  - 移除跨阶段批亲和性——一个阶段同批处理的请求在下一阶段不必保持同批。
- 每个请求维护两个逻辑执行状态 \(S^r_D\)、\(S^r_T\)，通过主机侧 KV 存储（HostKV）在任意 worker 上准备所需状态。

### 2.2 关键技术细节

- **阶段推进与池容量建模**：
  - 执行依赖关系：\(draft^q_r \prec target^q_r \prec draft^{q+1}_r\)。
  - 批执行时间 \(bT_s(B)=\phi_s(z_B)\)，阶段服务率 \(\mu_s(B)=|B|/bT_s(B)\)。
  - 稳态系统速率受较慢阶段限制：\(\mu_{sys} \le \min\{\mu_D, \mu_T\}\)。

- **重叠式批规划与状态准备**：
  - 草稿与目标 worker 采用对称的调度抽象；worker 可在前驱阶段完成前就触发下一批规划并启动状态准备。
  - 稳态执行在 TARGET_q、DRAFT_{q+1}、TARGET_{q+1} 间交替，状态准备与前驱计算重叠；预测完成时间仅用于提前规划，实际就绪事件决定何时可执行。

- **Worker 触发的批重建（算法 1）**：
  - 调度器在 worker 触发机会到来时，从对应阶段的共享请求池中重建该 worker 的下一批。
  - **就绪时间预测**：
    - 前驱完成时间 \(e^r\)（已观测）或 \(\hat{e}^r = t_{start}+\phi_{\bar{s}}(z)\)（预测）；
    - 目标 worker 预测可用时间 \(\hat{a}_w\)；
    - KV 状态就绪时间 \(\hat{k}_r(w)\)；
    - 批最早预测开始时间 \(\hat{S}(B,w)=\max\{\hat{a}_w, \max_{r\in B}\hat{e}^r, \hat{k}(B,w)\}\)。
  - **服务约束批重建**：为避免在线穷举子集搜索，采用有界贪心策略：
    - 服务准入上界 \(\hat{d}_r(w)=\max\{\hat{e}^r+g_s, \hat{S}(\{r\},w)\}+\Delta_s\)，其中 \(g_s\) 为阶段目标服务间隔，\(\Delta_s\) 为允许的批形成松弛量；
    - 可采纳条件：\(|B|\le B_{max}\)、Fit(B,w)=1、\(\hat{S}(B,w)\le \min_{r\in B}\hat{d}_r(w)\)；
    - 按服务紧迫度与时间兼容性排序，贪心构造批；等待时间提供老化效应，单请求预测起始时间作为可行性基线。

- **实现机制**：
  - **Persistent HostKV**：主机侧持久化 pinned-memory 存储草稿与目标模型的 KV 状态，使用稳定偏移寻址，避免反复分配与重打包。
  - **增量 KV 回写**：仅异步回写未持久化的 KV 后缀，前缀保持不变；迁移成本按 \(\hat{T}_{s,wb}=\Delta Q_s(B)\cdot b_{KV,s}/\beta_{s,D2H}\)、\(\hat{T}_{s,in}=Q_s(B)\cdot b_{KV,s}/\beta_{s,H2D}\) 估算。
  - **双缓冲 GPU KV Bank**：每个 worker 维护两个 KV bank，状态机为 FREE→FILLING→READY→COMPUTING→EXPORTING→FREE，允许 COMPUTE_{k+1} ∥ D2H_k、COMPUTE_k ∥ H2D_{k+1}。
  - **进程隔离运行时**：control / execution / DMA 三进程分离，避免控制面与拷贝完成处理干扰 GPU 提交延迟。
  - **有界 H2D 提交**：默认 32 MiB 分块提交，避免大量 H2D 堆积阻塞另一 bank 的 D2H 回写（head-of-line blocking）。
  - **PREPARE→RUN 两阶段协议**：准备阶段固定批成员、目标 worker、bank 身份与状态版本；运行时仅在 INPUT_READY ∧ KV_READY ∧ WORKER_READY 满足时转为 RUN。

## 3. 实验设计

### 3.1 数据集 / 场景

- 无传统 NLP 数据集，采用**合成并发请求负载**：
  - 512 个同时到达的请求，最大生成长度 128 tokens（敏感性实验中扩展到 256/512）；
  - 请求处于 post-prefill 状态，带初始 anchor token；
  - 推测深度默认 d=4（敏感性实验取 3/4/5）。

### 3.2 Benchmark 与基线

- **Co-located**：每 GPU 上各放一个草稿实例和一个目标实例，传统耦合执行（固定草稿-目标配对）。
- **Native Distributed**：物理分离为 2D+2T，草稿 batch 上限 128，但保留跨阶段批亲和性。
- **NebulaSD**：同样 2D+2T 资源配置与 batch 上限，额外启用共享请求池、worker 触发批重建、跨 worker 状态迁移、提前状态准备。
- **NebulaSD Simulation（Ideal Sim.）**：理想化离散事件仿真，隔离调度潜力与运行时开销。
- **主要指标**：请求轮处理速率（request-round processing rate，即每秒完成的“草稿+验证”推测轮数）、时间加权 SM 活跃度、平均每请求计算服务占比。

### 3.3 大规模仿真场景

- 扩展配置：19 GPU（3D+16T）、48 GPU（8D+40T）、76 GPU（12D+64T）、96 GPU（16D+80T）、152 GPU（24D+128T）、192 GPU（32D+160T）。
- 对比 NebulaSD 与 Co-located 在不同请求并发下的 SM 利用率与请求服务占比。

## 6. 主要结论与发现

- **四 GPU 真实系统**：
  - 请求轮处理速率从 Co-located 的 1109.37、Native Distributed 的 1273.35 提升到 NebulaSD 的 **1914.83 rounds/s**，即相比物理分离基线提升 **50.4%**，相比同址执行提升 **72.6%**。
  - 时间加权 SM 活跃度从 30.1%（Co-located）、29.4%（Native Distributed）提升到 **47.3%**。
  - 草稿平均 batch（89.24）小于 Native Distributed（128），目标 batch（31.32）相近，说明收益来自**填补执行气泡**而非单纯增大 batch：
    - 草稿平均间隙从 114.96 ms 降至 4.38 ms，目标从 24.03 ms 降至 4.45 ms。
  - 代价：同预算下每请求计算服务占比从 97.9%（Co-located）降至 44.0%，即系统服务了更多并发请求。
- **理想

仿真与扩展性：理想仿真接近上界；NebulaSD 在大规模配置下持续优于 Co-located，且随 GPU 规模增大，收益主要体现为更高的 SM 利用率和更均衡的两阶段负载分配。
- **KV 状态增长敏感性**：随着 max gen 从 128 增至 512，迁移开销增大，收益有所衰减；在 512 token 下 Native Distributed 因显存不足被迫降配，NebulaSD 仍保持可用与领先。
- **推测深度敏感性**：d=3/4/5 下结论一致，d=4 为默认较优平衡点；更深推测提升单轮接受 token 数但加重目标阶段负担，收益取决于两阶段容量比。
- **调度器参数敏感性**：\(g_s\) 与 \(\Delta_s\) 在一定范围内变化时性能稳定，说明批重建策略对参数不敏感、鲁棒性较好。
- **草稿模型规模敏感性**：将草稿换成 Qwen3-1.7B 后，草稿阶段延迟上升、批处理余量缩小，收益幅度下降，印证"草稿阶段有大量批余量"是收益来源的关键前提。
- **微基准**：KV 迁移与前台计算的干扰在进程隔离与有界 H2D 提交下得到有效抑制；PCIe 带宽成为长序列迁移的主要成本项。
- **总体结论**：将推测解码的两阶段解耦为可独立调度的资源池、并以异步 KV 迁移 + worker 触发批重建支撑 M-for-N 配对，能在不改变模型与推测算法的前提下，把系统速率提升到接近由较慢阶段容量决定的上界。

---

## 7. 局限性与未来工作

- **硬件平台受限**：真实系统仅验证于 4×RTX 4090 单节点、PCIe 互联；作者明确指出 host-device 带宽是长序列迁移的主要瓶颈，跨节点/高带宽互联（如 NVLink、RDMA）下的表现未验证。
- **负载类型单一**：实验使用合成并发负载（512 同时到达、固定长度），缺少真实生产 trace、请求到达分布、变长输出与共享前缀等场景。
- **规模扩展依赖仿真**：大规模结论（19–192 GPU）来自基于 profiling 的离散事件仿真，属理想化评估，未在真实集群复现。
- **基线公平性说明**：基线保留各自原始批/亲和性配置，未统一 resident concurrency，作者声明这是架构差异；512-token 长序列下 Native Distributed 因显存不足改用 64 请求/对，不参与等配置比较。
- **未来方向（可推断）**：将 M-for-N 资源池扩展到多节点/异构互联、结合前缀缓存与真实 trace 调度、以及进一步降低 KV 迁移成本（压缩、量化、按需迁移）等。

## 8. 个人评价与启发

- **贡献定位**：论文把"推测解码加速"从"算法层接受率优化"扩展到"服务系统层的阶段解耦与全局调度"，核心洞见是**两阶段偏好不同批配置**，从而可通过 M-for-N 池化共享闲置容量，思路清晰且工程落地完整。
- **方法亮点**：worker 触发批重建 + 预测式就绪时间 + 有界贪心构造，避免了在线穷举子集搜索；Persistent HostKV、双缓冲 KV bank、进程隔离与有界 H2D 提交等实现细节，直击"迁移不能进关键路径"这一核心矛盾。
- **实证强度**：真实系统 + 仿真互补，覆盖性能、扩展性、迁移开销与多组敏感性，指标设计（请求轮速率、SM 活跃度、间隙、计算服务占比）能有效揭示收益来源。
- **可复现性与局限**：实现细节描述较充分，但真实实验规模小、负载合成化，结论外推需谨慎；迁移成本对互联带宽高度敏感，是该类系统普适化的关键变量。
- **总体判断**：NebulaSD 为分布式推测解码提供了一个"资源池化"的通用框架，其价值不仅在于具体加速数字，更在于揭示阶段解耦 + 动态批重建 + 异步状态迁移这一组合在并发 LLM 服务中的可行性与边界条件。
