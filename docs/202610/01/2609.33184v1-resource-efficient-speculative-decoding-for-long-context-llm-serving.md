## 摘要
投机解码通过并行验证来自草稿模型的多个 token，减少目标模型的顺序调用次数。然而，在 GPU 内存受限时，KV 缓存的增长限制了长上下文服务。将 KV 卸载到 CPU 内存可以缓解这一压力。但是，现有卸载方案会在注意力计算前恢复完整的 KV 历史，未能充分利用一个验证轮次内跨查询共享 KV 的收益。现有并行投机解码方法还忽视了在受内存带宽限制的目标验证等待历史 KV 时闲置的 GPU 计算能力。我们提出 SpecStream，一种投机解码系统，它无需等待完整 KV 历史恢复便开始验证，并利用 KV 传输期间的计算气泡在同一批 GPU 上并发进行草稿生成。它仅卸载目标模型已提交的历史，将候选回滚保留在 GPU 本地。每个流式传输的 KV 块服务于该轮次中的所有查询，并通过在线 softmax 保持完整注意力。目标优先调度在资源限制下控制草稿并发执行，以限制对目标验证的干扰。实验表明，SpecStream 在任务质量上接近 SGLang 投机解码，同时在有限 GPU 内存下支持更多并发请求。在不同数据集上，对于 Qwen3 和 InternLM2.5，它相较卸载基线分别实现了平均 1.41 倍和 1.32 倍的吞吐加速。与在独立目标 GPU 和草稿 GPU 上进行并行投机解码相比，SpecStream 将每 GPU 输出吞吐平均提高 55.4%。

## Abstract
Speculative decoding reduces sequential Target model calls by verifying multiple tokens from the Draft model in parallel. Yet KV Cache growth limits long-context serving under constrained GPU memory. Offloading KV to CPU memory relieves this pressure. However, existing offloading schemes restore the full KV history before attention and fail to fully exploit the benefits of KV sharing across queries within a verification round. Existing parallel speculative decoding methods also overlook idle GPU compute capacity while memory-bandwidth-bound Target verification waits for historical KV. We present SpecStream, a speculative decoding system that begins verification without waiting for the full KV history to be restored and exploits compute bubbles during KV transfers for concurrent drafting on the same GPUs. It offloads only Target-committed history, keeping candidate rollback local to the GPUs. Each streamed KV chunk serves all queries in the round, with online softmax preserving full attention. Target-priority scheduling controls Draft concurrent execution under resource limits to constrain interference with Target verification. Experiments show that SpecStream maintains task quality close to SGLang speculative decoding while supporting more concurrent requests under limited GPU memory. Across different datasets, it achieves average throughput speedups of 1.41$\times$ and 1.32$\times$ over the offloading baseline for Qwen3 and InternLM2.5, respectively. Compared with parallel speculative decoding on separate Target and Draft GPUs, SpecStream improves output throughput per GPU by an average of 55.4%.

## 1. 核心问题与研究动机

- **背景**：长上下文 LLM 服务中，KV Cache 随序列推进持续增长，成为 GPU 显存的主要消耗者；投机解码（Speculative Decoding）虽通过 Draft 模型一次生成多个候选、Target 一次并行验证来减少顺序调用，但并未消除每轮验证对历史 KV 的依赖，反而可能更早触及显存上限。
- **现有方案痛点**：
  - **CPU offload 方案**（如 TriForce、SD+Offload）必须先恢复完整 KV 历史才能开始注意力计算，传输时间随上下文线性增长，延长 Target 验证的关键路径。
  - 现有方案未利用**一个验证轮次内多个查询共享同一段已提交 KV 历史**的特性——单次历史读取本可服务整个查询组。
  - 现有并行投机方案（MineDraft、SPECTRE、SwiftSpec）未利用 Target 等待历史 KV 时**闲置的 GPU 算力**（compute bubbles）。
- **核心洞察**：
  - 投机验证中 q 个查询因果可见性不同，但共享同一段已提交历史，一次拷贝即可服务全部查询，从而分摊传输成本（式 3：$D_{token}(q) \approx D_H / E[U(q)]$）。
  - Target 验证受内存带宽限制而等待数据时，Draft 仍可继续生成候选；计算气泡 $G \approx \max(0, T_{H2D} - T_{attn})$ 可被回收利用。
  - 但 Draft 资源分配需权衡：分配过少则单步变长，分配过多则干扰 Target（图 1 显示吞吐先升后降，无限制时甚至低于 offload 基线）。

## 2. 方法论：SpecStream

SpecStream 在 SGLang 上实现，围绕投机解码的 KV 状态与访问特性，联合设计**历史管理、流式计算、同 GPU 调度**三部分。

### 2.1 提交感知的无回滚 KV 分层（Commit-Aware Rollback-Free Tiering）

- **状态划分**（式 4）：
  - Sealed History $[0, H)$：已迁移至 CPU 的不可撤销已提交历史；
  - Active Tail $[H, C_r)$：GPU 上保留的近期已提交 KV；
  - Speculative Frontier $[C_r, L_r)$：GPU 上未验证的候选 KV。
- **核心思想**：以 Target 提交边界 $C_r$ 约束迁移范围，只 offload 已提交历史，候选回滚完全在 GPU 本地完成，使迁移与回滚作用于不相交状态区域，避免传输和清理将被拒绝候选的 KV。
- **批量化迁移**（式 5）：保留目标长度 $T$ 的 Active Tail，以粒度 $g$ 批量迁移：
  $$E = \max\left(H,\ g\left\lfloor \frac{\max(0, C_r - T)}{g} \right\rfloor\right)$$
  仅当 $E > H$ 时迁移 $[H, E)$，采用异步拷贝，拷贝完成确认后才推进边界并回收 GPU 空间。
- **回滚安全性**：轮次结束时接受前缀进入 Active Tail，后缀 $[C'_r, L_r)$ 由现有 GPU 回收流程释放；恒有 $H \le C_r \le C'_r$，故 $[C'_r, L_r) \cap [0, H) = \emptyset$。

### 2.2 多查询验证的 KV 流式执行（KV Streaming for Multi-Query Verification）

- **分块共享**：将当前层 Sealed History 按 token 位置切成 $J$ 个连续 chunk，查询矩阵 $Q \in \mathbb{R}^{q \times d_h}$，每个到达的 chunk 计算 $S_j = QK_j^T / \sqrt{d_h}$，**一次传输服务本轮全部 q 个查询**。
- **在线 softmax**（保持完整因果注意力）：
  - 维护每查询、每头三元组累加器 $(m, \ell, a)$，初始为 $(-\infty, 0, 0)$；
  - chunk 内局部状态：$m_j = \max(S_j)$，$\ell_j = \sum_k e^{S_{j,k}-m_j}$，$a_j = \sum_k e^{S_{j,k}-m_j} V_{j,k}$；
  - 合并：$m' = \max(m, m_j)$，$\alpha = e^{m-m'}$，$\beta = e^{m_j-m'}$，$\ell' = \alpha\ell + \beta\ell_j$，$a' = \alpha a + \beta a_j$；
  - 处理完 CPU 历史后继续处理 GPU 上的 Active Tail 与 Speculative Frontier（施加因果掩码），最终输出 $O = a/\ell$。
  - 该分块归约在实数算术下与一次性全 softmax 等价，仅改变 KV 到达与归约顺序。
- **流水线与预取**：双 GPU staging buffer + 独立传输/计算流，处理 chunk $j$ 时预取 $j+1$；相邻 chunk 合并为传输批次；当前层释放 buffer 后预取下一层历史，与当前层剩余注意力、输出投影、FFN 重叠。
- **Cohort 批处理**：将同层、同验证宽度、同数据类型、同 KV 头数/头维度/块大小的任务聚合，用批处理注意力核执行，各请求保留独立 KV 索引、绝对位置与在线 softmax 状态，摊销数据准备、同步与核启动开销。
- **I/O 感知动态验证宽度**：按每有效输出 token 的估计代价选择 $q^* = \arg\min_{q \in Q} \hat{T}_{round}(q)/\hat{U}(q)$，$Q = \{2,4,6,8\}$；基于近期传输、验证、Draft 生成与拒绝纠正成本估计，记录不足时有限采样，并设置切换阈值避免频繁抖动。

### 2.3 Target 优先的 GPU 内协同执行（Target-Priority Intra-GPU Co-Execution）

- **资源分配**：使用 NVIDIA MPS 让 Target 与 Draft 在独立进程并发；通过 **TPC mask** 限制 Draft 仅使用指定 TPC 子集（保留 Target 全部算力），但不隔离 L2 与内存带宽，故仍需运行时控制竞争。
- **离线标定**：测量不同 TPC 数下 Draft 单步时间 $t_D(x,n)$ 与 Target 验证延迟相对增幅 $\Delta T(x,n) = [T^{co}_T(x,n) - T^{alone}_T(x)] / T^{alone}_T(x)$，并扫描端到端吞吐选出默认分配 $n_0$（实验中为每 GPU 34 TPC）。
- **运行时准入条件**：估计剩余窗口 $\hat{S}$，仅当
  $$\hat{\Delta T}(x, n_0) \le \varepsilon_T \quad \text{且} \quad \hat{t}_D(x, n_0) + \delta \le \hat{S}$$
  时才提交新的并发步。
- **单 token 粒度调度**：每次仅准入一个完整 Draft 前向（生成 1 个 token），指令携带请求/轮次标识、执行序号、TPC 分配与最晚启动时间 $t_{latest} = t_0 + \hat{S} - \hat{t}_D - \delta$；过期或不匹配指令不执行；完成后返回 ACK，Target 收到 ACK 后才决定是否继续；每请求至多一个未完成 Draft 步。
- **回退机制**：若宽度、批大小或上下文变化导致 Target 延迟增幅超预算，则停止提交新并发步，待已启动计算完成后恢复 Target 独占执行；若 Target 已在等待候选 token，则回到原始 Draft 生成流程。
