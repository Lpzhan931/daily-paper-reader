## 摘要
投机解码通过使用轻量级草稿模型提出多个 token 以进行并行验证，从而加速自回归生成。然而，现有方法通常需要额外的草稿模型或权重表示，在资源受限设备上引入不可忽视的内存开销。自投机方法降低了这一开销，但仍面临草稿质量、目标质量和存储效率之间的权衡。我们提出 BitNest，一种比特嵌套投机解码框架，将低精度草稿直接嵌入到更高精度的目标表示中。BitNest 并非从预定义目标中导出草稿，而是先构建一个强大的低精度基础模型，再通过残差细化恢复更高精度的目标，从而使两个模型共享单一物理权重表示。BitNest 进一步将这种渐进式精度设计扩展到 KV 缓存，以支持长上下文推理。在多个 7B--8B 边缘友好型 LLM 和多样化工作负载上，BitNest 实现了 95.2% 的平均投机接受率，同时很好地保持了更高精度模型的质量，并相较 FP16 自回归解码取得 1.48--1.61 倍的端到端加速。在所有代表性自投机基线均支持的 LLaMA 模型上，BitNest 也实现了持续具有竞争力或更高的解码加速。

## Abstract
Speculative decoding accelerates autoregressive generation by using a lightweight draft to propose multiple tokens for parallel verification. However, existing methods often require an additional draft model or weight representation, introducing non-negligible memory overhead on resource-constrained devices. Self-speculative approaches reduce this overhead, yet still face trade-offs between draft quality, target quality, and storage efficiency. We propose BitNest, a bit-nested speculative decoding framework that embeds a low-precision draft directly into the higher-precision target representation. Instead of deriving a draft from a predefined target, BitNest first constructs a strong low-precision base and then recovers the higher-precision target through residual refinement, enabling both models to share a single physical weight representation. BitNest further extends this progressive-precision design to the KV cache for long-context inference. Across multiple 7B--8B edge-friendly LLMs and diverse workloads, BitNest achieves an average speculative acceptance rate of 95.2% while closely preserving higher-precision model quality, and delivers 1.48--1.61x end-to-end speedup over FP16 autoregressive decoding. On the LLaMA models supported by all representative self-speculative baselines, BitNest also achieves consistently competitive or higher decoding speedup.

# BitNest 论文中文总结

## 1. 核心问题与整体含义

- **背景**：LLM 自回归生成受限于高昂计算成本、庞大的模型与 KV 缓存内存占用，以及强烈的内存带宽需求，在单 GPU、消费级 GPU 和边缘设备等资源受限场景尤为突出。投机解码通过轻量草稿模型提出多个候选 token，再由目标模型并行验证，从而减少昂贵的逐 token 目标执行次数。
- **核心矛盾**：
  - 使用独立小模型作为草稿会带来额外模型存储，与目标模型和 KV 缓存争夺有限内存。例如 FP16 下 7B 模型已接近 16GB 设备内存容量。
  - EAGLE、DFlash 等虽提升草稿质量或效率，但仍需额外草稿网络、参数或专用表示。
  - 自投机解码虽避免独立草稿模型，却仍存在权衡：层跳过方法（Draft & Verify、LayerSkip、Kangaroo、SWIFT）将草稿效率与预测质量耦合；量化方法中 QSpec 将目标约束为共享低位表示，QuantSpec 保留额外的低精度草稿权重。
- **核心研究问题**：能否用单一模型表示同时支持轻量草稿与更高质量目标，不增加额外内存开销，同时保持足够高的草稿–目标一致性以获得高接受率？
- **整体含义**：提出 BitNest，将低精度草稿物理嵌套进高精度目标表示，使二者共享同一物理权重，从表示层面而非模型层面解决内存与质量的两难。

## 2. 方法论

### 2.1 核心思想

- 采用“**基座优先**”构造：先构建强 W4 基座作为草稿，再在不改变基座的前提下量化残差形成 W8 目标，从而保证草稿是高精度目标的精确子集，避免独立量化破坏嵌套关系。
- 用公式统一描述为：`W --R--> W' --QbW--> Wbase + rW-bit refinement --> Wtarget`，本文实例化 `bW = rW = 4`，即 W4 草稿视图与 W8 目标视图。
- 将嵌套原则独立扩展到 KV 缓存，记 `bKV = rKV = 4`，即草稿读 KV4、验证读 KV8。

### 2.2 权重构造细节

- **函数保持旋转**：先折叠 R1/R2 变换得到 `W' = Fuse(W; R1, R2)`（采用 SpinQuant 旋转以抑制激活离群值）。
- **W4 基座**：用 GPTQ（group size 128）量化得 `(q4, s4) = Quantize4,g=128(W')`，`q4 ∈ [-8, 7]`，草稿权重 `Wdraft = q4·s4`，之后 q4、s4 固定不变。
- **固定基座精修**：残差 `ΔW = W' − Wdraft`，精修尺度 `sref = s4/16`，4-bit 精修码 `qr = clip(round(ΔW/sref), ...)`。当 `q4 = −8` 时下界约束为 `[0, 7]`，防止组合整数码越过有符号 8-bit 下界。
- **目标恢复**：`Wtarget = q4·s4 + qr·sref = (16·q4 + qr)·sref`，从而在不修改 W4 基座的前提下得到 W8 目标。

### 2.3 双平面权重存储

- 现代内存按字节寻址，4-bit nibble 无法独立寻址。若基座与精修同字节存放，草稿仍会取回精修位，抵消低精度访存优势。
- 将基座与精修打包为两个独立 4-bit 位平面，各占 N/2 字节。草稿仅访问基座平面（4 bit/weight），验证访问两平面恢复 W8。
- 精修无需额外 scale 元数据，因 `sref = s4/16` 可由基座尺度推导。

### 2.4 上下文感知 KV 嵌套

- 在线逐 token、逐 KV head 对称 RTN 量化：`s = max|x|/7`，`q4 = clip(round(x/s), −8, 7)`，草稿表示 `x̂draft = q4·s`。
- 精修：`qr = clip(round((x − q4·s)/(s/16)), −8, 7)`，目标表示 `x̂target = (16·q4 + qr)·s/16`。
- 草稿仅读 KV4 基座，验证读两平面恢复 KV8；草稿阶段生成的候选 KV 状态临时保留，验证时重算，接受项保留、拒绝后缀丢弃。
- 短上下文时草稿与验证均用 KV8 以保持一致性；长上下文时切换为 KV4 草稿 + KV8 验证以降低 KV 访存。另支持 Recent-N 策略作为中间工作点。

## 6. 主要结论与发现

- **速度**：跨 4 个模型、6 个工作负载实现 **1.48–1.61× 端到端加速**（相对 FP16 自回归）。在 LLaMA 模型上相较 QSpec、QuantSpec、Draft & Verify 取得持续有竞争力或更高的加速。
- **质量保持**：性能接近 FP16 与独立 W8A8。例如 LLaMA-3-8B 上 GSM8K 达 49.8%，W8A8 为 50.0%。
- **接受率**：平均 **95.2%**（模型均值 94.8%–95.7%

），说明 W4 草稿视图与 W8 目标视图之间高度一致，嵌套表示有效抑制了草稿–目标分布漂移。
- **长上下文与内存**：随上下文从 4K 增至 32K，BitNest 相对 FP16 的加速比持续扩大，峰值内存增长显著低于 16-bit 基线。原因在于长上下文下 KV 缓存访存成为主导瓶颈，KV4 草稿视图将草稿阶段的 KV 读取量减半，而验证阶段按需恢复 KV8，兼顾带宽节省与质量。
- **边缘设备**：在 Jetson Orin NX 16GB/8GB 上，BitNest 在吞吐、能耗与最大可支持上下文方面均优于对比基线，使原本难以在 8GB 设备上运行的长上下文 7B 推理成为可能。
- **权重精度消融**：目标权重精度实验表明，BitNest 目标（W8A8）质量接近 FP16 与独立 W8A8，明显优于 W4A16/W4A8/W4A4，验证了"高精度目标视图由基座 + 精修恢复"这一构造的有效性。
- **KV 精度消融**：草稿 KV 精度对 MHA 与 GQA 架构影响不同，GQA 下降低草稿 KV 位宽的质量损失更小，说明 KV 嵌套收益与注意力头共享程度相关；目标 KV 保持 8-bit 对维持质量至关重要。
- **投机长度 γ**：γ 增大可提升理论加速上限，但接受率随 γ 增长而下降，端到端加速在中等 γ 处达到最优，存在明显的效率–质量折中拐点。
- **OpenVLA-7B**：在机器人操作任务上保持与基线相近的任务成功率，同时降低中位延迟，说明该方法可迁移至 VLA 等非纯文本生成场景。
- **总体判断**：BitNest 的核心贡献在于以"物理嵌套 + 双位平面访存"从表示层统一草稿与目标，在不增加额外模型内存的前提下同时获得高接受率与高质量目标，为资源受限场景下的投机解码提供了一条新路径。

## 7. 局限与不足

- **模型规模覆盖有限**：主实验集中在 7B–8B 区间，未验证在更大模型（如 13B/70B）或更小模型（<3B）上的可扩展性与收益稳定性。
- **基线对比不完整**：Qwen2/Qwen2.5 上多个基线为 N/A，导致跨模型的横向对比存在缺口，部分结论主要依赖 LLaMA 系列。
- **量化流程依赖外部组件**：方法建立在 SpinQuant 旋转与 GPTQ W4 基座之上，基座质量直接决定上限；若基座本身退化，精修难以完全弥补。
- **固定精修尺度**：`sref = s4/16` 为推导得到的固定值，未探索自适应或可学习精修尺度是否进一步提升目标质量。
- **KV 嵌套的上下文策略**：短上下文用 KV8、长上下文切 KV4 草稿属于启发式切换，切换阈值与 Recent-N 策略的普适性有待更系统研究。
- **训练开销未报告**：作为 PTQ 方法虽无需大规模训练，但旋转校准、GPTQ 量化与精修的具体时间/算力成本未量化，影响工程复现评估。
- **评测指标侧重**：以 PPL、任务准确率、吞吐与内存为主，未深入分析生成多样性、长程一致性等生成质量维度。

## 8. 潜在影响与启示

- **方法论层面**：提出"嵌套表示"这一新视角——同一组物理权重可同时暴露为低精度草稿视图与高精度目标视图，把草稿–目标的存储矛盾转化为位平面访存问题，可推广至其他需要多精度视图的场景（如分层推理、自适应精度服务）。
- **系统层面**：双 4-bit 位平面打包与自定义 Triton GEMM/flash decoding kernel，展示了在字节寻址硬件上实现 nibble 级按需访存的可行路径，对量化推理内核设计有借鉴意义。
- **应用层面**：显著降低峰值内存与长上下文 KV 访存，使 7B 级模型在消费级 GPU 与边缘设备上运行长上下文推理更具可行性，对端侧 LLM、机器人 VLA 等部署场景有直接价值。
- **未来方向**：可探索更大模型与更多量化位宽组合（如 W2/W4/W8 三级嵌套）、自适应精修尺度、以及与更先进草稿策略（如 EAGLE 类树形草稿）的结合。
