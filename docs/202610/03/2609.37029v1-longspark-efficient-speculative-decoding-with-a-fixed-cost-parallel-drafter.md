## 摘要
投机解码通过在单次目标模型前向传播中验证多个草稿 token 来加速自回归推理。然而，随着上下文增长，现有最先进的草稿器变得愈发昂贵，侵蚀了其本应提供的效率优势。我们认为这种随规模增长是不必要的。独立语言模型必须随其前缀增长，因为它要对其生成的每个 token 全权负责。相比之下，草稿器只提出候选；目标模型会在任何 token 被提交之前捕获并纠正每一个错误。因此，草稿器的解码成本可以完全独立于前缀长度。我们提出 LongSpark，一种块扩散草稿器，它通过从目标模型的验证过程中提取固定尺寸的多尺度视图来实现这一点，从而无需不断增长的持久状态。大量评估表明，LongSpark 在多种模型规模和真实服务条件下实现了最先进的端到端效率。值得注意的是，它在长上下文任务上实现了最低的每输出 token 时间，同时将草稿器的上下文状态减少了几个数量级。

## Abstract
Speculative decoding accelerates autoregressive inference by verifying multiple draft tokens in a single target forward pass. However, as the context grows, existing state-of-the-art drafters become increasingly expensive, eroding the very efficiency advantage they are designed to provide. We argue that this scaling is unnecessary. A standalone language model must grow with its prefix because it is solely responsible for every token it produces. A drafter, by contrast, only proposes candidates; the target catches and corrects every error before any token is committed. The drafter's decoding cost can therefore be made entirely independent of the prefix length. We introduce LongSpark, a block-diffusion drafter that achieves this by extracting fixed-size, multiscale views from the target's verification pass, thereby eliminating the need for a growing persistent state. Extensive evaluations demonstrate that LongSpark achieves state-of-the-art end-to-end efficiency across multiple model scales and realistic serving conditions. Notably, it delivers the lowest time-per-output-token on long-context tasks while reducing the drafter's context state by several orders of magnitude.

## 1. 核心问题与整体含义

- **背景**：投机解码（speculative decoding）通过轻量草稿器一次提出多个候选 token，由目标模型单次前向验证，从而加速自回归推理。其前提是草稿器必须显著便宜于目标模型。
- **核心问题**：现有草稿器的解码成本随上下文（前缀）长度增长，在前缀变长时反而成为效率瓶颈，侵蚀了投机解码本应带来的加速收益。
  - 自回归草稿器（如 EAGLE-3）的 KV cache 随前缀线性增长；
  - 窗口化方法（如 LongSpec）虽限制自身状态，仍需对目标模型全前缀 KV 做交叉注意力；
  - 块扩散草稿器（如 DFlash、DSpark）虽并行预测多位置，但每个草稿层仍注入全前缀的目标特征。
- **核心洞察（固定成本草稿，fixed-cost drafting）**：草稿器与目标模型存在本质不对称——目标模型必须完整、精确地表示前缀（否则产生错误输出），而草稿器只提出候选，验证环节会捕获并纠正所有错误。因此草稿器可以工作在压缩、有损的前缀视图上，其解码成本**无需**随前缀长度扩展。
- **整体含义**：把草稿设计目标从"提高提案质量"转向"单位草稿开销所产出的接受 token 数"，使草稿开销与前缀长度解耦。

## 2. 方法论

### 2.1 核心思想
- 提出 **LongSpark**，一种块扩散（block-diffusion）草稿器：从目标模型的验证过程中提取**固定尺寸的多尺度上下文视图**，使所有非验证操作（上下文提取、迭代精炼、草稿状态维护）均为相对前缀长度的 $O(1)$；目标验证是每轮唯一的全前缀遍历。

### 2.2 固定成本上下文接口（三种视图）
- **边界状态（boundary state）**：将解码边界处选定目标层 $\mathcal{L}$ 的隐状态 $\{h^\ell_t\}$ 融合为单个条件向量 $c_t$。
- **近期 KV 窗口（recent KV window）**：每选定层保留 $W=256$ 条 token 级细节，捕获局部邻域信息。
- **全局上下文摘要（global context summary）**：每层每头维护 $R=16$ 个可学习查询 $G\in\mathbb{R}^{R\times d}$，将整个前缀压缩为固定条目：
  $$M_t = \mathrm{Attn}(G, K_{1:t}, V_{1:t})$$
- **增量更新**：由于查询 $G$ 在推理时固定，历史注意力贡献保持有效，每轮只需吸收至多 $B+1$ 条新保留的 KV 行。采用 log-sum-exp 合并（式 10–11）：
  $$\eta=\log(\exp(\eta_A)+\exp(\eta_N)),\quad m=\exp(\eta_A-\eta)m_A+\exp(\eta_N-\eta)m_N$$
  使更新代价与存储状态均与 $t$ 无关。

### 2.3 提案模型
- $D=5$ 层 Transformer 并行处理 $B=7$ 个草稿位置；首槽编码已提交 token $a$，其余槽使用 mask embedding。
- 每个草稿层 $j$ 配对选定目标层 $\ell(j)$，注意力上下文为拼接形式：
  $$K=[K_b;K_w;G],\quad V=[V_b;V_w;M_t]$$
  即每头最多 $B+W+R$ 条条目，与前缀长度无关。
- 冻结目标模型的归一化与词表头生成基础 logits $z^{(0)}_i$，再用低秩**顺序马尔可夫校正**（DSpark 风格）引入 token 间依赖：
  $$z_i = z^{(0)}_i + W_c E_c(y_{i-1}),\quad i=1,\dots,B$$
  仅校正与采样串行，主干与词表投影完全并行。

### 2.4 训练与复杂度
- **训练**：冻结全部目标参数；联合训练草稿网络、边界融合、输入映射、摘要查询与顺序校正。教师强制下损失为加权和（$\lambda=0.1$，$w_i=\exp(-(i-1)/4)$）：
  $$\mathcal{L}_i = w_i[\lambda(-\log q_i(x_{t+1+i}))+(1-\lambda)\|q_i-p_i\|_1]$$
- **推理**：接受 $r$ 个候选后前缀推进 $r+1$，其 KV 行更新摘要与近期窗口，新边界隐状态更新 $c_t$；丢弃所有临时草稿 KV。
- **固定成本复杂度**：每轮 $O(B^2+BW+BR)$（全前缀草稿注意力为 $O(B^2+Bt)$）；持久摘要状态 $O(|\mathcal{L}|HRd)$，两者均独立于 $t$。

## 6. 主要结论与发现

- **端到端效率最优**：LongSpark 在 4B/8B/14B 上分别取得 **1.88×、1.99×、2.13×** 平均吞吐加速，且加速比随目标模型增大而提升。
- **接受长度 vs. 开销的权衡**：即使 DSpark 达到更长的接受长度 $\tau$，LongSpark 的吞吐仍更高，说明**严格有界的草稿开销比边际提案质量增益更重要**。
- **长上下文优势显著**：在 64K CodeSpan 上，平均 TPS 比 DSpark 高 29.1%，平均 TPOT 低 23.1%；三个长上下文任务均取得最低 TPOT。
- **草稿状态大幅缩减**：上下文从 32K→128K，DSpark 草稿时间由 6.3→13.8 ms、状态由 640→2560 MiB；LongSpark 分别稳定在约 3.5 ms 与 6.3 MiB，128K 时状态小 **406×**。
- **高并发优势扩大**：低并发时略逊于 DSpark，随并发上升反超并持续拉开，在并发 128 时领先明显。
- **消融结论**：近期 KV 窗口最关键（平均接受长度 4.69→3.71），全局摘要与边界状态为次要但非冗余；移除全局摘要会造成明显的训练损失瞬态尖峰，说明其还贡献训练稳定性。

- **核心贡献定位**：LongSpark 的贡献不在"更好的草稿器精度"，而在**重新定义了草稿器成本随前缀增长的约束**——把长上下文加速的瓶颈从"提案质量"转移到"草稿开销是否可常数化"，这是一条被此前工作系统性忽视的轴。
- **方法论启示**：其"验证器保证正确性 ⇒ 草稿器可工作在压缩视图"的不对称论证，可迁移到其他"低成本提案 + 高成本校验"的推理加速范式（如多候选重排序、级联推理、异步预取）。
- **工程价值**：草稿状态在 32K→128K 间稳定在约 6.3 MiB、时间稳定在约 3.5 ms，意味着服务端可把长上下文加速作为"恒定预算"能力来规划，而非随上下文长度线性增长的资源负担，这对高并发长上下文部署具有直接的调度意义。
- **适用边界**：最适合"长前缀 + 中高并发 + 可容忍少量提案质量损失"的服务场景；在短上下文、低并发或对接受长度极度敏感的场景，其相对 DSpark 的优势会收窄甚至反转。
- **总体判断**：论文问题定义清晰、技术方案自洽、实验覆盖较全面，结论方向明确；主要短板是算力信息缺失与超参敏感性未展开，属于"贡献扎实但复现透明度中等"的工作，其设计原则比具体实现更具长期参考价值。
