## 摘要
投机解码通过并行验证 Draft 模型生成的多个 token，减少了 Target 模型的串行调用次数。然而，KV Cache 的增长限制了受限 GPU 内存下的长上下文服务。将 KV 卸载到 CPU 内存可缓解这一压力。然而，现有卸载方案在注意力计算前会恢复完整的 KV 历史，未能充分利用一个验证轮次内跨查询的 KV 共享优势。现有并行投机解码方法还忽视了在受内存带宽限制的 Target 验证等待历史 KV 时闲置的 GPU 计算能力。我们提出 SpecStream，一种投机解码系统，它无需等待完整 KV 历史恢复便开始验证，并利用 KV 传输期间的计算空隙在同一批 GPU 上并发执行 Draft。它仅卸载 Target 已提交的历史，使候选回滚保留在 GPU 本地。每个流式传输的 KV 块服务于该轮次中的所有查询，并通过在线 softmax 保持完整注意力。Target 优先级调度在资源限制下控制 Draft 的并发执行，以约束其对 Target 验证的干扰。实验表明，SpecStream 在任务质量上接近 SGLang 投机解码，同时在有限 GPU 内存下支持更多并发请求。在不同数据集上，对于 Qwen3 和 InternLM2.5，其相较卸载基线分别实现了平均 1.41 倍和 1.32 倍的吞吐量加速。与在分离的 Target 和 Draft GPU 上进行的并行投机解码相比，SpecStream 将每 GPU 输出吞吐量平均提升 55.4%。

## Abstract
Speculative decoding reduces sequential Target model calls by verifying multiple tokens from the Draft model in parallel. Yet KV Cache growth limits long-context serving under constrained GPU memory. Offloading KV to CPU memory relieves this pressure. However, existing offloading schemes restore the full KV history before attention and fail to fully exploit the benefits of KV sharing across queries within a verification round. Existing parallel speculative decoding methods also overlook idle GPU compute capacity while memory-bandwidth-bound Target verification waits for historical KV. We present SpecStream, a speculative decoding system that begins verification without waiting for the full KV history to be restored and exploits compute bubbles during KV transfers for concurrent drafting on the same GPUs. It offloads only Target-committed history, keeping candidate rollback local to the GPUs. Each streamed KV chunk serves all queries in the round, with online softmax preserving full attention. Target-priority scheduling controls Draft concurrent execution under resource limits to constrain interference with Target verification. Experiments show that SpecStream maintains task quality close to SGLang speculative decoding while supporting more concurrent requests under limited GPU memory. Across different datasets, it achieves average throughput speedups of 1.41$\times$ and 1.32$\times$ over the offloading baseline for Qwen3 and InternLM2.5, respectively. Compared with parallel speculative decoding on separate Target and Draft GPUs, SpecStream improves output throughput per GPU by an average of 55.4%.

# SpecStream 论文详细总结

## 1. 核心问题与研究动机

- **背景**：长上下文 LLM 服务中，KV Cache 随序列长度线性增长，成为 GPU 显存的主要占用者。投机解码虽通过一次 Target 前向验证多个 Draft 候选 token 来减少串行调用，但并未消除每一轮验证对历史 KV 的依赖，反而因需同时驻留 Draft 模型权重与 KV，更容易触及显存上限。
- **现有卸载方案的不足**：
  - 将 KV 卸载到 CPU 内存可缓解显存压力，但现有方案（如 SD+Offload）在注意力计算前必须先将当前层完整 KV 历史恢复至 GPU，导致传输时间随上下文增长而延长，位于 Target 验证的关键路径上。
  - 未充分利用一个验证轮次内多个查询共享同一份已提交历史 KV 的特性，造成重复或低效传输。
  - 仅卸载已提交历史以避免为可能被拒绝的候选做无效迁移的思路尚未被系统化实现。
- **并行投机的资源盲区**：现有跨 GPU 并行投机方法（MineDraft、SPECTRE、SwiftSpec）虽能重叠 Draft 与 Target，但未利用 KV 卸载场景下 Target 等待 H2D 传输时产生的 GPU 计算气泡。这些气泡中拷贝引擎仍在工作，但计算单元空闲，恰好适合推进 Draft。
- **核心矛盾**：卸载引入的 H2D 传输气泡（`G ≈ max(0, TH2D − Tattn)`）与 Draft 的算力需求互补，但 Draft 资源分配过少会拉长单步时间，过多则干扰 Target 验证（如图 1 所示，吞吐先升后降，无限制并发甚至低于卸载基线）。因此需要在共享 GPU 上对 Draft 进行精细的时空调度。
- **整体含义**：论文提出 SpecStream，围绕投机解码完整步骤（Draft 生成 → Target 验证 → 提交/回滚）的状态与访问特征，联合设计 KV 历史管理、流式计算与共享 GPU 调度，在显存受限条件下同时提升并发能力与吞吐效率。

## 2. 方法论

### 2.1 总体架构

SpecStream 由三个组件构成：

- **提交感知 KV 分层管理器**：识别可迁移区间，协调异步拷贝与 GPU 空间回收。
- **多查询流式验证器**：让每个历史块服务整轮查询组，用在线 softmax 计算完整因果注意力。
- **Target 优先级调度器**：在选定 TPC 分配下控制 Draft 何时启动、推进多远。

### 2.2 提交感知、无回滚的 KV 分层

- **状态划分**（式 4）：将每个请求的 Target KV Cache 分为三段，满足 `0 ≤ H ≤ Cr ≤ Lr`：
  - **Sealed History** `[0, H)`：已确认完成迁移的已提交历史，驻留 CPU。
  - **Active Tail** `[H, Cr)`：最近已提交 KV，驻留 GPU。
  - **Speculative Frontier** `[Cr, Lr)`：待验证候选 KV，驻留 GPU。
- **迁移策略**：仅当 KV 越过 Target 提交边界 `Cr` 后才具备迁移资格，候选回滚与历史迁移作用于不相交的状态区域。回滚区间 `[C′r, Lr)` 与 CPU 历史 `[0, H)` 无交集，因此拒绝候选无需清理 CPU 副本或跨设备回滚。
- **批量迁移**（式 5）：保留目标长度为 `T` 的 Active Tail，迁移粒度 `g` token，迁移端点 `E = max(H, g·⌊max(0, Cr − T)/g⌋)`。仅当 `E > H` 时迁移 `[H, E)`，使用异步拷贝，完成后才推进边界 `H` 并回收 GPU 空间，以减少碎片化小传输。

### 2.3 多查询 KV 流式验证

- **分块与查询组共享**：将当前层 Sealed History 沿 token 位置切为 `J` 个连续块。查询矩阵 `Q ∈ R^{q×dh}`，当块 `(Kj, Vj)` 到达 GPU 后计算 `Sj = QKj^T/√dh`。一个块只需传输一次即可服务该层该轮全部 `q` 个验证查询；块处理完后暂存缓冲区可接收下一块，无需等待整层历史恢复。
- **在线 softmax 精确归约**：目标为 `O = softmax(Q[KH; KG]^T/√dh + M)[VH; VG]`（式 6）。若各块独立归一化再求和会改变相对权重，因此维护三个累加器 `(m, ℓ, a)`：`m` 为已处理位置的最大注意力分数，`ℓ` 为相对该最大值的指数和，`a` 为同权重的值加权和。初始为 `(−∞, 0, 0)`。
  - 块内局部状态：`mj = max(Sj)`，`ℓj = Σ_k e^{Sj,k − mj}`，`aj = Σ_k e^{Sj,k − mj} Vj,k`（式 7）。
  - 跨块合并：`m′ = max(m, mj)`，`α = e^{m − m′}`，`β = e^{mj − m′}`，更新 `ℓ′ = αℓ + βℓj`，`a′ = αa + βaj`（式 8）。
  - 处理完所有 CPU 历史块后，继续处理 GPU 上的 Active Tail 与 Speculative Frontier，对后者按绝对位置施加因果掩码。最终输出 `O = a/ℓ`，其分子分母均基于全部可见位置联合形成，与一次性全 softmax 等价（式 9），仅改变 KV 到达顺序与归约顺序。
- **流水线与预取**：使用两个 GPU 暂存缓冲区和独立传输/计算流，缓冲 A 计算块 `j` 时缓冲 B 接收块 `j+1`；相邻块合并为传输批次以摊销提交、同步和核启动开销；当前层释放缓冲后预取下一层历史，与当前层剩余注意力、输出投影和前馈计算重叠。
- **Cohort 批处理**：在当前调度批次内，将模型层、验证宽度、数据类型、KV 头数、头维度、块大小兼容的任务归为同一 Cohort，按组准备历史块和查询，用批注意力核执行。各请求保留独立 KV 索引、绝对位置和在线 softmax 状态，提升核并行度并摊销准备与同步成本。
- **I/O 感知动态验证宽度**：宽度 `q` 同时决定候选数量和历史复用粒度。控制器依据近期历史传输、验证、Draft 生成、拒绝纠正成本及实际提交 token 数，估计不同宽度下的单轮时间 `T̂round(q)` 与提交 token 数 `Û(q)`，选择 `q* = arg min_{q∈Q} (T̂round(q)/Û(q))`。记录不足时通过有限初始采样收集信息；仅在估计收益超过切换阈值时改变下一轮宽度，避免频繁切换。

### 2.4 Target 优先级 GPU 内协同执行

- **Draft 算力分配**：使用 NVIDIA MPS 实现 Target 与 Draft 两进程在同一 GPU 上核执行与拷贝重叠；通过 TPC 掩码将 Draft 限制在指定 SM 簇集合上，Target 保留全部 TPC。TPC 限制不隔离 L2 与内存带宽，仍需运行时控制竞争。
- **离线测量**：对模型对、批大小、上下文长度、验证宽度、执行阶段等运行时配置 `x`，测量 Draft 单步时间 `tD(x, n)` 和相对独占执行的 Target 验证延迟增幅 `∆T(x, n) = [T^co_T(x, n) − T^alone_T(x)] / T^alone_T(x)`，并比较端到端吞吐，选定默认 TPC 分配 `n0`（实验中为 34 TPC）。
- **运行时准入条件**：估计剩余可用窗口 `Ŝ`，要求同时满足 `∆̂T(x, n0) ≤ εT`（延迟增幅在可接受预算内）和 `t̂D(x, n0) + δ ≤ Ŝ`（单步时长加安全裕度可容纳）。仅当两者成立时提交并发步骤，否则推迟。
- **单 token 准入与 ACK 机制**：每次只允许一个完整 Draft 前向（单 token），限制不可立即撤销的在途工作。调度指令携带请求/投机轮标识、执行序号、TPC 分配和最晚启动时间 `tlatest = t0 + Ŝ − t̂D(x, n0) − δ`；启动前校验指令与当前请求/轮次匹配且未过期。完成后返回 ACK，Target 收到后才决定是否继续，保持每请求至多一个未完成 Draft 步骤。
- **降级策略**：当动态宽度 `q`、批大小或上下文长度变化时，读取新配置下默认分配的测量记录；若 Target 延迟增幅超预算，停止提交新并发步骤，待已启动 Draft 完成后恢复 Target 独占执行；若 Target 已在等待候选 token，则回退到原有 Draft 生成流程。
