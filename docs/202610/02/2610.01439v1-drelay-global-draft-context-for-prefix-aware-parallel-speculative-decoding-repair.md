## 摘要
并行草稿生成降低了大语言模型（LLM）投机解码的草稿开销，但其收益仍受限于被接受前缀的长度。即使候选池中存在正确 token，单个早期选择错误也会导致后续预测无法被使用。我们提出 DRelay，它利用来自整个草稿块的全局信息，在目标模型验证之前对候选选择进行前缀感知的选择性修复。DRelay 基于候选相关性和已选路径进行决策：全局读取器为每个候选提取跨位置的预测信息，而因果选择器则将全局读取所提取的候选级信息与前序位置选出的 token 相结合，以判断当前位置的原始选择是否与全局证据及已选前缀一致。随后，它决定保留还是替换该 token，从而修复早期错误并延长被接受的前缀。我们进一步联合训练草稿骨干网络和选择器，将候选支持学习与修复目标相结合，同时根据每个块位置对连续接受前缀的潜在贡献对修复损失进行加权。在 H800 GPU 上的八个多样化基准上，DRelay 在平均接受长度和端到端解码性能上均持续优于 DFlash、Domino 和 DSpark。在 SGLang 服务下，DRelay 相对 DFlash、Domino 和 DSpark 的平均端到端加速分别提升 14.7%-16.8%、8.7%-9.3% 和 8.1%-9.3%。

## Abstract
Parallel drafting reduces the drafting overhead of speculative decoding for large language models (LLMs), but its gains remain limited by the accepted prefix length. Even when the correct token is present in the candidate pool, a single early selection error prevents subsequent predictions from being used. We propose DRelay, which uses global information from the entire draft block to perform prefix-aware selective repair of candidate selections before target-model verification. DRelay bases its decisions on candidate correlations and the selected path: a global reader extracts predictive information across positions for each candidate. While a causal selector combines candidate-level information extracted by the global read with the tokens selected at preceding positions to determine whether the native choice at the current position is consistent with the global evidence and the selected prefix. It then decides whether to retain or replace the token, thereby repairing early errors and extending the accepted prefix. We further jointly train the draft backbone and the selector, combining candidate-support learning with a repair objective, while weighting the repair loss according to each block position's potential contribution to the consecutive accepted prefix. Across eight diverse benchmarks on an H800 GPU, DRelay consistently improves both average acceptance length and end-to-end decoding performance over DFlash, Domino, and DSpark. Under SGLang serving, DRelay improves average end-to-end speedup over DFlash, Domino, and DSpark by 14.7%-16.8%, 8.7%-9.3%, and 8.1%-9.3%, respectively.

# DRelay 论文中文总结

## 1. 核心问题与研究动机

- **背景**：投机解码（Speculative Decoding）通过廉价的草稿生成与批量验证，缓解大模型逐 token 自回归推理的开销；并行草稿（如 DFlash）进一步在单次前向中并行预测多个位置，降低草稿开销。
- **关键瓶颈**：验证阶段只能接受从草稿块首位开始的**连续正确前缀**。一旦早期位置出现选择错误，即使后续 token 预测正确，本轮也无法被提交；且后续预测会以错误 token 为条件，导致前缀偏离、后缀进一步受影响。
- **已有方法局限**：Domino、DSpark 通过 GRU 状态或前序 token 条件建模块内依赖，但依赖**前向因果**信息流，后续预测无法反向修正已做的早期选择。
- **被忽视的机会**：作者通过诊断发现——(a) 首次错误时正确 token 常仍在 top-16 候选池中（DFlash 94.0%、Domino 95.1%、Domino 实际草稿 88.8%）；(b) 后续预测蕴含对早期候选具有判别力的证据（真实后缀 vs 对照后缀提升 53.5/44.4 个百分点）；(c) 一次精确修复可恢复 1+R 个连续接受 token（one-edit oracle 平均增益 +1.65 / +1.22）。
- **核心思想**：让整个草稿块同时承担两个角色——在每位置**提出候选**，并为候选选择**提供全局上下文**，从而在验证前对早期选择做前缀感知的修复。

## 2. 方法论

### 2.1 总体架构
- 每个解码轮：并行草稿器接收目标模型确认的 anchor token 与历史特征，单次前向生成 H=15 个位置的隐状态与候选分布，每位置保留 top-K=16 候选。
- **Global Read** 聚合跨位置候选信息，为每个候选构建全局上下文。
- **Causal Selector** 结合全局上下文、严格已验证历史、已选前缀，逐位置决定 KEEP 或 REPAIR，输出单一路径交由目标模型验证。
- 修复后的 token 写入前缀记忆，供后续位置决策使用（因果传播）。

### 2.2 Global Read（全局读取）
- **Top-16 slot mixing**：用双向注意力–FFN 块对候选分布做软摘要，得到每个 slot 的共享解释 `u_i`。
- **Candidate reads**：候选特定注意力保留个体差异，注意力权重同时融合查询、草稿先验 log 概率与相对位置偏置 `b`；并引入零值 null key/value 允许"无内容读取"。
- 融合标量 `λ_i` 缩放全局 slot 残差与候选残差，标量在候选间共享但各候选的读取结果 `G_ik` 保持独立。
- **信息边界**：仅使用草稿侧隐状态与候选分布，绝不读取未经验证的未来 token 或教师提议 token。

### 2.3 Causal Selector（因果选择器）
- **地址化前缀记忆**：存储 anchor 与每个已选条目，键/值编码 `(h_j, z_j^global, E(x_j), g_a,j)`；位置 i 只能检索 j<i 的条目，最近已选 token 直接参与查询，避免压缩为单一循环状态。
- 另设对最近 64 个严格验证目标特征的候选特定读取，块内一次性预计算。
- **Rank 分支**：结合原生 log 概率、共享隐残差与候选特定修正，对非基候选打分排序。
- **Gate 分支**：判断"最佳修复是否值得偏离原生选择"，采用保守门控。
- **决策规则**（式 2）：`p_act(0)=σ(−g_i)`，`p_act(k)=σ(g_i)r_ik`；仅当 `g_i + log r_ik* > 0` 时替换，数值打平保留原生（KEEP）。
- 门控由原生池质量 log-odds 初始化（式 6），残差为零时退化为池内重归一化的原生分布。

### 2.4 联合训练
- **冻结**：目标模型、token embedding、词表 readout。
- **联合训练**：并行草稿骨干 + Global Read + Causal Selector。
- **选择损失**（式 3）：覆盖且基正确 → KEEP（BCE(g,0)）；覆盖且为替代候选 → REPAIR 及其身份（BCE(g,1)−log r）；池未覆盖 → 无有效动作，仅由稠密支持损失监督。
- **总损失**（式 4）：稠密词表监督 + α 加权的选择损失，公共有效 token 分母统一尺度。
- **前缀价值加权**（式 5）：`v_i` 由"可达性"（`∏_{j<i} p̄_j`）与"延续价值"（`1 + Σ ∏ p̄`）组成，块内归一化到均值 1、设均匀下限、上限 4，并 stop-gradient，避免长乘积主导。
- **训练数据混合**：均匀采样 anchor 与由无梯度教师前缀 scout 追踪的验证边界混合，native-anchor 比例从 30% 升至 50%，选择器系数从约 0.05 升至 1。

## 7. 优点

- **问题定位精准**：抓住并行投机解码"连续前缀约束"这一本质瓶颈，将后续预测从"待验证输出"重新诠释为"可用于早期决策的全局证据"。
- **信息边界严谨**：明确 Global Read 只读草稿侧表示与候选分布，不接触未验证 token 或教师提议，训练与推理边界清晰，附录专门定义诊断范围。
- **决策机制保守可控**：Gate + Rank 双分支、null key 允许无内容读取、打平保留原生、门控由原生 log-odds 初始化，降低过度修复风险。
- **训练目标有针对性**：前缀价值加权同时建模"可达性"与"延续价值"，带 stop-gradient 与有界归一化，避免长乘积主导；支持损失与选择损失联合、分工明确。
- **工程可行性**：选择器仅 35.06M 参数，Global Read 每轮只算一次，不重复全词表投影；延迟分解透明，即插即用于现有并行草稿框架。

## 8. 不足与局限

- **模型与规模覆盖有限**：仅评测 Qwen3-4B/8B 两个模型，未验证更大模型、MoE 架构或不同词表规模的泛化性。
- **训练成本未披露**：缺少训练时长、总 GPU 时与能耗数据，难以评估方法相对于基线的训练开销。
- **诊断与训练目标之间存在差距**：作者自己指出式 5 是"加权似然代理"，并非贪心接受长度的无偏梯度；one-edit oracle 增益是机会分析，不能直接预测 DRelay 实际收益。
- **选择器开销固定**：每轮 0.55 ms 的额外延迟在小批量或低并发下相对占比更高；论文未给出选择器开销随 H、K 变化的敏感性分析。
- **超参数依赖**：H=15、K=16、λ 融合、价值权重上限 4、native-anchor 比例调度等均需调参，跨任务/跨模型的最优配置可能不同。
- **偏差风险**：诊断中的 first-error 定位与正确性过滤仅用于离线分层，部署选择器无法观测；消融实验仅在单一目标/温度设置下报告，缺少跨设置稳健性验证。
- **应用限制**：方法依赖草稿块内候选分布的可读性与质量，若候选池覆盖率下降（如温度升高、任务更难），修复空间与收益可能显著缩水。
