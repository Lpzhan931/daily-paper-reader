## 摘要
投机解码通过在一次目标模型前向传播中验证多个草稿 token，从而加速自回归推理。然而，随着上下文增长，现有最先进的草稿器变得越来越昂贵，侵蚀了它们本应提供的效率优势。我们认为这种随规模增长是不必要的。独立的语言模型必须随其前缀增长，因为它要对其生成的每个 token 全权负责。相比之下，草稿器只提出候选；目标模型会在任何 token 被提交之前捕获并纠正每一个错误。因此，草稿器的解码成本可以做到完全独立于前缀长度。我们提出 LongSpark，一种块扩散草稿器，它通过从目标模型的验证过程中提取固定大小的多尺度视图来实现这一点，从而消除了对不断增长的持久状态的需求。大量评估表明，LongSpark 在多种模型规模和真实服务条件下实现了最先进的端到端效率。值得注意的是，它在长上下文任务上实现了最低的每输出 token 时间，同时将草稿器的上下文状态降低了几个数量级。

## Abstract
Speculative decoding accelerates autoregressive inference by verifying multiple draft tokens in a single target forward pass. However, as the context grows, existing state-of-the-art drafters become increasingly expensive, eroding the very efficiency advantage they are designed to provide. We argue that this scaling is unnecessary. A standalone language model must grow with its prefix because it is solely responsible for every token it produces. A drafter, by contrast, only proposes candidates; the target catches and corrects every error before any token is committed. The drafter's decoding cost can therefore be made entirely independent of the prefix length. We introduce LongSpark, a block-diffusion drafter that achieves this by extracting fixed-size, multiscale views from the target's verification pass, thereby eliminating the need for a growing persistent state. Extensive evaluations demonstrate that LongSpark achieves state-of-the-art end-to-end efficiency across multiple model scales and realistic serving conditions. Notably, it delivers the lowest time-per-output-token on long-context tasks while reducing the drafter's context state by several orders of magnitude.

## 1. 核心问题与整体含义（研究动机与背景）

- **投机解码的核心前提**：投机解码通过轻量草稿器（drafter）一次性提出多个候选 token，再由目标模型（target）在一次前向传播中并行验证，从而加速自回归推理。其加速成立的关键前提是——草稿器必须显著比目标模型便宜。
- **现有方法的系统性瓶颈**：当前主流草稿架构（自回归草稿器、窗口化方法、块扩散草稿器）的解码成本都随前缀长度增长：
  - 自回归草稿器的 KV 缓存随前缀线性增长；
  - 窗口化方法虽限制自身状态，但仍需对目标全前缀做遍历；
  - 块扩散草稿器通常将全前缀的目标特征注入每一层草稿层。
  - 结果是草稿器继承了目标模型的 O(t) 缩放行为，从“加速器”变成了新的“缩放瓶颈”。
- **核心洞察（草稿器与目标的不对称性）**：
  - 独立语言模型必须忠实表示完整前缀，因为它对生成的每个 token 负全部责任；
  - 草稿器只提出候选，目标模型会通过拒绝采样在提交前捕获并纠正所有错误，错误提案只增加一轮解码，绝不产生错误输出。
  - 因此草稿器可以工作在**压缩的、有损的前缀视图**上，其解码成本可以完全独立于前缀长度。
- **设计目标转变**：提出“**固定成本草稿（fixed-cost drafting）**”原则——效率的真正衡量标准是每单位草稿开销所产出的被接受 token 数，而非单纯的提案质量。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

LongSpark 是一种**块扩散（block-diffusion）草稿器**，其核心是：从目标模型的验证前向传播中提取**固定尺寸的多尺度上下文视图**，从而消除对不断增长的持久状态的需求。每轮中，目标验证是唯一的全前缀遍历，其余所有操作（上下文提取、迭代精修）均保持 O(1)。

### 2.2 固定成本上下文接口（三个固定尺寸视图）

- **边界状态（boundary state）**：将解码边界处的目标隐藏表示 {h_t^ℓ} 融合为单个条件向量 c_t（学习投影）。
- **近期 KV 窗口（recent KV window）**：每选定层保留 W 个条目，保存局部 token 级细节。
- **全局上下文摘要（global context summary）**：将整个前缀压缩为每层每头 R 个条目。
  - 每层每头维护一组 R 个可学习摘要查询 G ∈ ℝ^{R×d}，推理时固定不变；
  - 摘要值计算为 M_t = Attn(G, K_{1:t}, V_{1:t})；
  - 由于 G 固定，历史注意力贡献保持有效，只需增量吸收新保留的至多 B+1 行 KV；
  - 增量更新使用 log-sum-exp 合并（含 max 减法保证数值稳定）：
    - η = log(exp(η_A) + exp(η_N))
    - m = exp(η_A − η)·m_A + exp(η_N − η)·m_N
  - 草稿层将 (G, M_t) 分别作为摘要键和值读取。
- 所有视图均从**均匀间隔的目标层子集**（如 Qwen3-4B/8B 取 {0,9,18,26,35}，14B 取 {0,10,20,29,39}）提取。

### 2.3 提案模型

- **并行骨干**：D 层 Transformer 并行处理 B 个草稿位置，首槽编码已提交 token a，其余槽使用 mask token 嵌入；结合块内位置编码与边界状态 c_t。
- **注意力上下文**（固定尺寸）：每头至多 B + W + R 个条目
  - K = [K_b; K_w; G]，V = [V_b; V_w; M_t]
- **基础 logits**：由冻结的目标归一化与词表头并行生成。
- **顺序马尔可夫修正**：低秩顺序修正使每个位置条件于前驱 token：
  - z_i = z_i^(0) + W_c·E_c(y_{i−1})，i = 1,…,B，y_0 = a
  - 最终提案分解为 q(y_{1:B} | s) = ∏_{i=1}^{B} q_i(y_i | s, y_{i−1})
- **并行与顺序的边界**：Transformer 骨干与基础词表投影完全并行，仅修正与采样是顺序的。

### 2.4 训练与推理

- **训练**：目标模型全部参数冻结；联合训练草稿网络、边界融合、输入映射、摘要查询和顺序修正。
  - 损失（教师强制）：L_i = w_i·[λ·(−log q_i(x_{t+1+i})) + (1−λ)·‖q_i − p_i‖_1]
  - 其中 λ = 0.1，w_i = exp(−(i−1)/4)，按权重和归一化。
- **推理**：被接受的 r 个候选使前缀前进 r+1 个位置；其 KV 行更新全局摘要并推进近期窗口，新边界隐藏态产生更新的 c_t；丢弃所有瞬态草稿 KV。
- **固定成本复杂度**：
  - 每轮草稿层注意力成本 O(B² + BW + BR)，而非全前缀注意力的 O(B² + Bt)；
  - 摘要持久状态 O(|L|·H·R·d)，与 t 无关；
  - 全前缀处理仅限目标验证，全局摘要在 prefill 时初始化一次。

## 6. 主要结论与发现

- **端到端效率领先**：LongSpark 在所有模型规模上取得最高平均吞吐，4B→14B 的加速比分别为 1.88×、1.99×、2.13×，且加速比随目标模型增大而提升。
