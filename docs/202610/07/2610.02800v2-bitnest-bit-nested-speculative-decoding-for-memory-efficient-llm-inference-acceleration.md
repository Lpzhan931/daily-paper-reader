## 摘要
推测解码通过使用轻量级草稿模型提出多个token以供并行验证，从而加速自回归生成。然而，现有方法通常需要额外的草稿模型或权重表示，在资源受限设备上引入不可忽视的内存开销。自推测方法降低了这一开销，但仍面临草稿质量、目标质量与存储效率之间的权衡。我们提出BitNest，一种位嵌套推测解码框架，将低精度草稿直接嵌入更高精度的目标表示中。BitNest并非从预定义目标中导出草稿，而是首先构建强低精度基座，然后通过残差精修恢复更高精度目标，使两个模型共享单一物理权重表示。BitNest进一步将这种渐进精度设计扩展到KV缓存，以支持长上下文推理。在多个7B--8B边缘友好LLM和多样工作负载上，BitNest实现了95.2%的平均推测接受率，同时紧密保持更高精度模型的质量，并相较FP16自回归解码实现1.48--1.61倍的端到端加速。在所有代表性自推测基线均支持的LLaMA模型上，BitNest也实现了持续具有竞争力或更高的解码加速。

## Abstract
Speculative decoding accelerates autoregressive generation by using a lightweight draft to propose multiple tokens for parallel verification. However, existing methods often require an additional draft model or weight representation, introducing non-negligible memory overhead on resource-constrained devices. Self-speculative approaches reduce this overhead, yet still face trade-offs between draft quality, target quality, and storage efficiency. We propose BitNest, a bit-nested speculative decoding framework that embeds a low-precision draft directly into the higher-precision target representation. Instead of deriving a draft from a predefined target, BitNest first constructs a strong low-precision base and then recovers the higher-precision target through residual refinement, enabling both models to share a single physical weight representation. BitNest further extends this progressive-precision design to the KV cache for long-context inference. Across multiple 7B--8B edge-friendly LLMs and diverse workloads, BitNest achieves an average speculative acceptance rate of 95.2% while closely preserving higher-precision model quality, and delivers 1.48--1.61x end-to-end speedup over FP16 autoregressive decoding. On the LLaMA models supported by all representative self-speculative baselines, BitNest also achieves consistently competitive or higher decoding speedup.

- **推测解码的价值与瓶颈**：推测解码通过轻量草稿模型提议多个候选 token，再由目标模型并行验证，从而减少昂贵的逐 token 执行。但要让草稿既廉价又与目标高度对齐，本身存在矛盾。
- **现有方法的局限**：
  - 使用小模型作草稿：能力差距大，接受率低。
  - EAGLE、DFlash 等改进方案：仍需额外的草稿网络、参数或专用表示，在内存受限设备上与目标模型、KV-cache 争夺有限预算。例如 FP16 下 7B 模型已接近 16GB 设备容量。
  - 自推测方法（LayerSkip、Draft & Verify 等）虽避免独立草稿模型，但存在草稿效率、目标质量与存储开销之间的权衡。
  - 量化类方法中，QSpec 将目标约束在共享低位表示，QuantSpec 仍保留额外低精度草稿权重。
- **核心问题**：能否用**单一模型表示**同时支持轻量草稿与高质量目标，且不引入额外内存开销，同时保持足够的草稿–目标一致性以获得高接受率？论文据此提出"能否构造一个高精度表示，显式地包含一个强低精度模型作为可访问子集"。
- **整体含义**：BitNest 提出 **Bit-Nested Speculative Decoding（位嵌套推测解码）**，将低精度草稿物理嵌入高精度目标表示中，为内存高效的自推测解码提供新范式。

## 2. 方法论

### 2.1 核心思想

- 采用**基座优先（base-first）**构造：先优化一个强 W4 基座，再将其量化残差编码为精修位，形成 W8 目标，而不改变已优化的 W4 基座。
- 草稿与目标共享同一物理权重表示，草稿是目标的**精确子集**，无需存储多份模型副本。
- 同一嵌套原则进一步扩展到 KV cache，支持长上下文解码加速。

### 2.2 关键技术细节

- **函数保持旋转变换**：先对预训练权重应用旋转（如 SpinQuant 的 R1/R2）并折叠进权重，得到等价表示 W′。
- **W4 基座构造**：用 GPTQ（group size = 128）量化 W′，得到整数码 q4 与组尺度 s4，草稿权重 W_draft = q4·s4；构造后 q4 与 s4 固定不变。
- **固定基座残差精修**：残差 ΔW = W′ − W_draft；精修尺度 s_ref = s4/16；4-bit 精修码 q_r 通过 round(ΔW/s_ref) 并裁剪得到。对 q4 = −8 时采用非对称裁剪 [0,7]，避免组合码越界。
- **目标重建公式**：W_target = q4·s4 + qr·s_ref = (16·q4 + qr)·s_ref，即用 8-bit 组合整数恢复 W8 目标，同时保持 W4 草稿为精确子集。
- **双平面权重存储（Dual-Plane Weight Storage）**：
  - 现代内存按字节寻址，若基座与精修同存一个字节，草稿仍会取到精修位，丧失带宽优势。
  - BitNest 将基座与精修分别打包为两个独立的 4-bit 平面，各占 N/2 字节。
  - 草稿只读基座平面（4 bits/weight 流量），验证读取两个平面恢复 W8；精修无需额外尺度元数据，因 s_ref 由 s4 导出。
- **KV 嵌套（Context-Aware KV Nesting）**：
  - 对每个 KV 条目在线执行 per-token、per-head 的对称 RTN 量化：s = max|x|/7，q4 = clip(round(x/s), −8, 7)。
  - KV4 草稿视图 x̂_draft = q4·s；残差用尺度 s/16 的 4-bit 精修 qr 编码，KV8 目标 x̂_target = (16·q4 + qr)·s/16。
  - 草稿只读 KV4 基座，验证读双平面恢复 KV8；草稿阶段生成的候选 KV 为临时状态，验证时重算，保留接受项、丢弃拒绝后缀。
  - 短上下文时草稿与验证均用 KV8 以保一致性；长上下文切换为 KV4 草稿 + KV8 验证；还支持 Recent-N 策略（最近 N 条保留高精度视图）作为可调中间点。
- **实现**：主实验采用 W4A8 草稿 → W8A8 目标；激活为 per-token INT8；使用自定义 Triton 核实现双平面 GEMM 与 flash decoding。

### 2.3 算法流程（文字版）

1. 折叠旋转变换到预训练权重 → W′；
2. GPTQ 量化得到 W4 基座 (q4, s4)，固定；
3. 计算残差 ΔW，用 s_ref = s4/16 量化为 qr；
4. 双平面打包存储 base / refinement；
5. 推测解码：草稿只读基座 → 提议 token；验证读双平面 → 重建 W8 目标并并行验证；
6. KV 同理：草稿读 KV4，验证读 KV8。

## 6. 主要结论与发现

- **加速**：在四个 7B–8B 模型、六类负载上相对 16-bit 自回归实现 **1.48–1.61×** 端到端加速；在 LLaMA 模型上相较所有自推测基线持续具有竞争力或更优。
- **质量保持**：紧密保持高精度目标质量（如 LLaMA-3-8B 上 GSM8K 49.8% vs. W8A8 50.0%）。
- **接受率**：平均 **95.2%**，模型级平均 94.8%–95.7%，说明 W4A8 草稿与 W8A8 目标对齐良好。
- **长上下文**：草稿读 KV4、目标读 KV8 时，32K 上下文加速达 1.66×（对比 KV8→KV8 的 1.38×）；BitNest 在 32K 峰值内存最低（21.0 GiB vs. QSpec 24.0 GiB、QuantSpec 25.1 GiB）。
- **内存节省**：LLaMA-2-7B 嵌套权重 6.22 GiB，与独立 W8 模型相同；而独立 W4 草稿 + INT8 目标需 9.38 GiB。
- **边缘设备**：Jetson Orin NX 16GB 上 LLaMA-2-7B-32K 约 1.5× 加速，解码能耗从 1.52 降至 0.95 J/token，最大可执行上下文从 W8A8 AR 的 6K 扩展到 10K；NX8 上 Llama-3.2-3B 最高 1.57× 加速，能耗从 0.768 降至 0.46 J/token。
- **关键洞察**：
  - 低精度表示（W4/KV4）足以做草稿，但不足以做最终目标；保留精修对最终保真度至关重要（W4A8 在 LLaMA-3-8B 仅 41.4% GSM8K，而 BitNest 目标 49.8%）。
  - 高接受率本身不保证目标质量（KV4 草稿→KV4 目标时接受率 0.933，但 GSM8K 从 81.6% 降至 78.4%）。
  - 低精度草稿 KV 的收益高度依赖注意力架构：MHA（LLaMA-2）收益显著，GQA（Qwen2.5）收益很小。

## 7. 优点

- **思路新颖**：首次提出"位嵌套"表示级嵌套，让草稿成为目标的精确位子集，从根本上消除独立草稿模型的内存开销。
- **基座优先构造合理**：避免独立量化高精度模型破坏嵌套关系，保证 W4 草稿不被精修改变。
- **双平面存储设计务实**：针对字节寻址硬件的现实约束，让草稿真正只读 4-bit 平面，兑现带宽优势。
- **KV cache 一致扩展**：将嵌套原则自然延伸到 KV，并提出上下文感知切换与 Recent-N 策略，长上下文收益显著。
- **实验覆盖面广**：4 个 LLM + 长上下文模型 + VLA 模型，6 类负载，含质量、速度、内存、能耗、接受率多维指标；消融充分。
- **边缘部署验证扎实**：给出 Jetson 上的吞吐、能耗、峰值内存与最大上下文，说明实际部署价值。
- **工程实现透明**：公开 Triton 核优化细节与 GEMV 带宽分析（约 46→63 GB/s），并坦诚报告 OpenVLA prefill 的当前不足。

## 8. 不足与局限

- **未利用辅助草稿架构**：论文明确承认 BitNest 聚焦自推测，不利用扩散式等可提供更强候选并行度的辅助草稿器（如 DFlash），在可接受额外开销时可能弱于此类方法。
- **OpenVLA prefill 开销**：当前大 M 路径将权重量化反量化到 FP16 并用 cuBLAS，prefill 比 FP16 慢约 1.7×，导致每动作总延迟（212.7 ms）略高于 FP16 AR（201.5 ms），虽解码阶段有 1.35× 加速但被 prefill 抵消。
- **对比公平性受限**：Qwen 系列上多数基线官方实现不支持（N/A），BitNest 缺少直接对比；各基线精度配置不统一，速度对比需结合质量解读。
- **接受率定义差异**：沿用各方法原生接受率定义，跨方法直接比较可能不完全公平。

- **训练/校准开销与工程成本未量化**：论文以 PTQ + 闭式残差构造为主，理论上无需大规模训练，但未报告旋转折叠、GPTQ 校准、残差编码与双平面打包的具体耗时与显存峰值；对于需要频繁换模型或在线部署的场景，这一成本的实际影响难以评估。
- **对特定量化配置与旋转方案的依赖**：核心构造依赖函数保持旋转（如 SpinQuant R1/R2）与 GPTQ（group size = 128）的组合。旋转矩阵、分组粒度、裁剪策略（尤其 q4 = −8 时的非对称裁剪 [0,7]）都会影响 W4 基座质量，进而决定整体接受率与目标保真度；论文未系统给出这些超参的敏感性分析，通用性与可移植性仍需在更多量化管线中验证。
- **模型规模与架构覆盖有限**：实验集中在 7B–8B 区间（含 MHA 与 GQA），另有 3B 级边缘模型与 7B VLA 模型。对更小（<1B）或更大（>13B、MoE）模型的适用性未知，而位嵌套的收益可能随模型宽度、层数与专家结构显著变化。
- **批次与并发场景未验证**：主实验固定 batch size = 1、单卡 A6000。推测解码在批处理下草稿–验证的调度、双平面读取的带宽摊薄、KV 嵌套的临时状态管理都会呈现不同特征，论文未给出 batch > 1 或服务化并发下的吞吐/延迟结论。
- **精度天花板停留在 W8A8**：目标精度最高为 W8A8，未探索 W16 目标或"W4 草稿 → W8 目标 → W16 精修"的多级嵌套。若下游任务对数值保真度要求更高（如部分数学、代码长链推理），W8 目标可能仍与 FP16 存在差距，而多级嵌套的存储与带宽代价尚未讨论。
- **KV 嵌套的在线量化与重算开销**：KV4/KV8 视图需 per-token、per-head 在线量化，草稿阶段产生的候选 KV 在验证时需重算。该开销随上下文长度与推测长度增长，论文虽给出长上下文净收益，但未拆分量化/重算与读取带宽节省各自的贡献占比。
- **上下文切换策略与超参的调优空间**：短上下文用 KV8、长上下文切 KV4 + KV8、Recent-N 保留最近 N 条高精度视图——这些阈值与 N 的选取对加速比、质量与内存均有影响，论文未给出自动选择机制或敏感性曲线，实际部署需人工调参。
- **能耗与内存结论的硬件外推性**：Jetson Orin NX 的能耗（J/token）与最大上下文结论依赖具体内存带宽、功耗墙与散热条件，能否推广到其他边缘芯片（如高通、苹果、国产 NPU）尚不明确；A6000 上的加速比也未在多代数据中心 GPU 上交叉验证。
- **可复现性细节**：双平面 GEMM 与 flash decoding 依赖自定义 Triton 核，GEMV 带宽约 46→63 GB/s 的优化效果与具体核实现强相关；若缺少完整开源与版本信息，第三方复现加速比与接受率存在门槛。
- **与互补技术的正交性未充分探索**：BitNest 聚焦自推测，未验证其能否与 EAGLE/Medusa 式训练草稿头、DFlash 式并行候选、树状验证、投机采样温度校正等技术叠加，也未讨论与 KV 压缩、稀疏注意力、PagedAttention 等系统优化的兼容性。

## 9. 潜在改进方向（基于论文内容的合理延伸）

- **多级嵌套表示**：将"基座 + 精修"推广为 W4/W8/W16 的多层位平面，草稿按负载动态选择读取深度，目标按需重建更高精度视图，形成精度–带宽的连续可调谱。
- **自适应上下文与精度调度**：结合注意力架构（MHA/GQA）、序列位置、任务类型在线决定 KV 精度与 Recent-N，替代固定阈值，减少人工调参。
- **与辅助草稿器混合**：在内存允许时叠加轻量并行候选器（如扩散式草稿），在内存紧张时回退纯位嵌套，形成"预算感知"的混合推测策略。
- **训练侧协同**：在量化感知训练或后训练阶段显式优化"嵌套友好"的权重分布，使 W4 基座本身更接近最优草稿，同时让残差更易被 4-bit 精修捕获，进一步提升接受率。
- **系统层优化**：针对双平面存储设计专用内存布局、预取与核融合，降低在线 KV 量化与重算开销；面向批处理与服务化场景重构调度，验证并发下的收益。
- **更广的评估矩阵**：覆盖更大/更小模型、MoE 架构、多模态与 VLA 长序列任务，并在多款边缘与数据中心硬件上交叉验证能耗、内存与延迟结论。

## 10. 总体评价

BitNest 的核心贡献在于把"草稿–目标一致性"这一推测解码的关键难题，从**模型级/训练级**转移到**表示级**：通过"基座优先 + 固定基座残差精修"构造出位嵌套的 W4⊂W8 权重与 KV4⊂KV8 缓存，使草稿成为目标的精确位子集，从而在不增加模型副本内存的前提下获得高接受率（平均 95.2%）与稳定的 1.48–1.61× 加速。双平面存储直面字节寻址硬件的现实约束，KV 嵌套与上下文感知策略把收益延伸到 32K 长上下文，边缘设备与 VLA 实验则展示了实际部署价值。其方法简洁、构造闭式、与现有推理引擎兼容，工程实现透明，实验维度（质量、速度、内存、能耗、接受率）较为完整。

局限主要集中在**规模与场景覆盖**（7B–8B、batch=1）、**超参与量化配置的敏感性未系统刻画**、**精度上限止于 W8A8**、以及**与互补加速技术的正交性未验证**。总体而言，BitNest 为内存受限下的自推测解码提供了一条有说服力的新范式，其"表示级嵌套"思想有望进一步扩展到多级精度、混合草稿与系统协同优化中，是值得后续跟进与复现验证的方向。
