# ABSTRACT 

Long chain-of-thought reasoning increases sequential decoding cost while cre-ating a growing history of potentially reusable continuations. We investigate when this history supplies useful drafts and complements an existing drafter. Controlled source comparisons reveal trajectory-specific reuse, motivating our method Trajectory-Local Adaptive Retrieval (TLAR). TLAR retrieves approxi-mately matched continuations from the current trajectory and uses recent verifica-tion outcomes to adapt retrieval activation and candidate width. TLAR combines retrieved continuations with model-generated drafts in a shared candidate tree, preserving the target model’s output distribution through exact verification. Across code debugging, mathematics, and open-ended writing, our evaluation connects source reuse, incremental acceptance, and execution cost. Combining TLAR with strong retrieval baselines improves token acceptance under matched verification budgets and increases end-to-end throughput over the draft-model baseline. These findings support generated trajectories as runtime memory for adaptive inference. 

# 1 INTRODUCTION 

Large language models (LLMs) can improve their performance on difficult tasks by generating long chains of thought (CoT) before producing a final answer (Wei et al., 2022). Long-CoT reasoning is used in competition mathematics (Lightman et al., 2024; Brown et al., 2024; Muennighoff et al., 2025), program synthesis and debugging (Jimenez et al., 2024; Jain et al., 2025), and scientific reasoning (Rein et al., 2023). This benefit comes at a cost: a single response may contain thousands of reasoning tokens, as autoregressive models generate these tokens one at a time, each new token can be produced only after the preceding tokens are available (Leviathan et al., 2023). As reasoning traces grow longer, this sequential decoding cost accumulates, making efficient token generation increasingly important for practical long-CoT inference. A practical goal is to accelerate this process without changing the target model’s output distribution. Recently, speculative decoding does so by using a faster drafter to propose several future tokens, and the target model then verifies in parallel (Leviathan et al., 2023; Chen et al., 2023). Most methods use a smaller model or a lightweight prediction head trained to imitate the target model (Li et al., 2024b; Cai et al., 2024). Currently, some methods extend the same idea from individual tokens to complete reasoning steps (Pan et al., 2026; Wang et al., 2026; Shi et al., 2025). These methods can be effective, but they require an additional trained component. To avoid this requirement, retrieval-based methods construct drafts from existing text. They search the prompt, an external datastore, or tokens already generated by the target model, and use the continuations following a match as draft candidates (Somasundaram et al., 2025; He et al., 2024; Fu et al., 2024; Hu et al., 2025; Oliaro et al., 2026; Li et al., 2024a; Luo et al., 2025; Chen et al., 2025). Among these, we focus on the tokens generated earlier in the current trajectory. Similar contexts may appear more than once during long reasoning. When this happens, the tokens that followed an earlier context can be reused as a draft. However, using the current trajectory as a draft source raises three challenges. 

Challenge 1: Separating trajectory reuse from common text. Retrieval may succeed because reasoning traces share common text. Different reasoning traces may share common words, symbols, and formatting patterns, allowing retrieval to succeed even when the current history is not used. High acceptance can also result from a model repeating the same text without making progress. A fair test 1arXiv:2610.07350v1 [cs.AI] 5 Oct 2026 Preprint must compare the current trajectory with other retrieval sources while keeping the task, target model, and matching rule unchanged. 

Challenge 2: Finding tokens beyond a small draft model. Even if the current trajectory provides useful drafts, a small draft model may already predict the same tokens. In that case, adding retrieval does not increase the number of accepted tokens. So we must compare the combined system with the same small draft model used alone. 

Challenge 3: Controlling the cost of retrieval verification. Every retrieved candidate must be verified by the target model which adds computation, while reusable content does not appear at every position in a reasoning trace. An effective method should decide when to use retrieval and how many candidates to verify based only on results observed at earlier positions. We address these challenges through source comparisons and Trajectory-Local Adaptive Retrieval (TLAR). After defining acceptance and cost in Section 2, we compare current history with control sources and another rollout of the same problem in Section 3. These observations guide TLAR in Section 4: we find approximate context matches in generated history and combine their continuations with SmallDraft in a prefix-sharing tree. We retain the SmallDraft candidate and use earlier verification results to choose when to retrieve and how many candidates to include. Periodic probes check for new useful content, and the target model verifies every proposed token exactly. In Section 5, we test added acceptance over SmallDraft, added coverage under shared retrieval-node budgets, and the controller’s gain–cost trade-off separately. We summarize our contributions as follows: • Uncovering Trajectory-Specific Reuse. We test when the current history provides more accepted tokens than other sources, and use same-prompt controls to distinguish the effect of the trajectory from that of the problem. The advantage depends on model and task. • More Accepted Tokens Within the Same Budget. We measure how many additional tokens the target model accepts when TLAR is combined with a draft model compared with using the same draft model alone. We then combine TLAR with the strongest retrieval baseline under shared verification-node budgets. The union yields more accepted tokens than either source alone, showing the value of trajectory-local candidates within the budget. • An Adaptive Retrieval Method. We introduce TLAR, which searches the current trajectory and uses earlier verification results to decide when to retrieve and how many candidates to submit. Experiments across models, tasks, and verification budgets show when this approach is useful and how its gain changes with its cost. 

# 2 PRELIMINARIES 

Speculative Decoding and Token Verification. Given a prompt x, a target language model M

generates a token sequence y = ( y1, . . . , y T ). At position t, the tokens already generated form the history ht = ( y1, . . . , y t−1). In speculative decoding, a drafter uses this history to propose a sequence of future tokens c = ( c1, . . . , c L). The target model verifies these tokens in one forward pass and accepts the longest prefix that matches (yt, . . . , y t+L−1). We define the accepted length as 

a(c, t ) = max {ℓ : 0 ≤ ℓ ≤ L, c 1: ℓ = yt:t+ℓ−1}. Then we first generate one target sequence y for each prompt, and test every drafting method at the same positions in this sequence, so all methods are asked to predict the same next tokens. 

Model-Based and Retrieval-Based Drafting. The candidate c defined above can be produced in two ways. A model-based drafter uses a smaller language model Mdraft to predict the next tokens from the prompt and the current history (Li et al., 2024b; Cai et al., 2024). Let dt denote its draft at position t. Its accepted length is asmall (t) = a(dt, t ). A retrieval-based drafter constructs candidates from text that is already available (Somasundaram et al., 2025; He et al., 2024; Hu et al., 2025; Oliaro et al., 2026). It searches a text source for a context similar to the current one and uses the tokens following that context as a draft. In this work, we focus on retrieval from the current history ht. Let Rt

denote the set of candidates retrieved at position t. Its accepted length is aretr (t) = max r∈R t a(r, t ),with aretr (t) = 0 when no candidate is retrieved. 

Incremental Acceptance and Verification Cost. We now measure whether retrieval adds value beyond the small draft model. We first consider positions where the small draft model fails on its first token, so asmall (t) = 0 . The recovery rate is R = Pr( aretr (t) ≥ 1 | asmall (t) = 0) . # 3 AN EXPLORATORY STUDY 

Before testing whether retrieval can improve a small draft model, we first ask whether the current trajectory is a better retrieval source than other available text. We then ask whether any advantage remains when the alternative trajectory comes from the same problem, and whether successful retrieval is spread evenly through generation. 

Retrieval and controller settings. The default retrieval configuration uses context length c = 4 ,mismatch tolerance ϵ = 1 , history threshold τ = 512 , and continuation depth d = 4 . Fixed-width experiments use k = 4 . The adaptive controller uses kmin = 1 , kmax = 4 , ρmin = 0 .05 , half-life 

H = 32 , and probe interval P = 32 . Section 5.4 examines candidate configurations and controller components; Appendix E reports the half-life and probe-interval sweeps. 

Evaluation Protocol. We keep the target trajectory and acceptance rule fixed and compare four draft sources. Within searches the current generated history. Cross searches another trajectory from the same target model and dataset, restricted to the same available history length. Shuffled searches a block-shuffled version of the current history. Unigram uses token frequencies without matching the current context. Within, Cross, and Shuffled use the same matcher. We report the mean exactly accepted length, Eexact , for Qwen3-8B, Mistral-Small-3.2-24B-Instruct, and Llama-3.1-8B-Instruct. 

Finding 1: Current history helps more in code and mathematics. We find higher accepted lengths from Within than from each of the three controls for all three models in code debugging and mathematics (Figure 1). Changing the source changes acceptance even when the target tokens remain fixed. The effect is smaller in open-ended writing: Mistral’s Within advantage becomes smaller, and Qwen does not exceed Unigram. We also retain the Llama repeated-copying audit, since long matches caused by repeated text do not by themselves show useful reuse. These differences limit the claim to the models and tasks in which the source controls support it. 

Finding 2: The same problem need not provide the same drafts. Cross changes both the problem and the trajectory. To separate them, we compare two rollouts of each of 24 code-debugging problems with different random seeds. We show the paired source comparisons in Figure 2, comparing own and other history within each panel. Qwen and Mistral favor their own history over the other rollout, while Llama shows the opposite ordering. # 4 METHOD : TRAJECTORY -LOCAL ADAPTIVE RETRIEVAL 

TLAR adds a controlled history search to SmallDraft, as we show in Figure 3. We describe the method in four parts. First, we find approximate context matches in generated history, rank them by recency, and place their continuations in a prefix-sharing tree (Section 4.1). Next, we track earlier verified retrieval results in a running score (Section 4.2). We use this score, the last retrieval result, and periodic probes to choose when to retrieve and how many candidates to keep (Section 4.3). Finally, we combine these candidates with SmallDraft, remove duplicate prefixes, and verify the resulting tree with the target model (Section 4.4). 4.1 RETRIEVING CANDIDATES FROM THE CURRENT HISTORY 

At position t, TLAR searches only the generated history ht = ( y1, . . . , y t−1). This choice follows from Section 3, where the current history provides better candidates than the control sources in the settings where retrieval is useful. Let ut = ( yt−c, . . . , y t−1) be the most recent c tokens. For an earlier position j, let uj = ( yj−c, . . . , y j−1) be the context that appeared before yj . TLAR identifies earlier positions whose contexts match the current context within a Hamming distance of ϵ and whose next d tokens are fully contained in the generated history: 

Jt = {j : c + 1 ≤ j ≤ t − d, d Ham (ut, uj ) ≤ ϵ} . (1) where dHam counts the token differences between two contexts. The value ϵ is the largest number of differences allowed. The condition j ≤ t − d ensures that the continuation (yj , . . . , y j+d−1)

4Preprint is already contained in ht. TLAR cannot use current or future target tokens when constructing a candidate. For every j ∈ J t, TLAR takes the next d historical tokens rj = ( yj , . . . , y j+d−1) as a candidate. Allowing up to ϵ context differences prevents small changes in punctuation, formatting, or wording from removing an otherwise useful candidate. Approximate matching is used only to find candidate locations. The retrieved tokens are still accepted using the exact verification rule defined in Section 2. TLAR ranks the matching positions by recency and selects the first kt. Their continuations are inserted into a prefix-sharing tree. When two candidates begin with the same tokens, their shared prefix appears only once in the tree. The target model does not need to verify duplicate prefixes. Section 4.3 explains how TLAR chooses kt.4.2 TRACKING RECENT RETRIEVAL SUCCESS

ˆρt+1 =

When retrieval is not attempted, the second case gradually reduces the effect of older results. A larger ˆρt means that retrieval has worked more often at recent positions. The score uses only verification results observed before position t. It does not require another trained predictor, an external trajectory, or additional target-model outputs. We set α = 1 − 2−1/H , where H controls how quickly earlier results lose weight. We use H = 32 by default and test other values in Section 5.4. 4.3 CHOOSING WHEN AND HOW MUCH TO RETRIEVE 

TLAR uses recent verification feedback to allocate retrieval work along the generated trajectory. The controller first requires |ht| > τ , allowing historical contexts and their continuations to accumulate. Once the history passes this threshold, retrieval activation combines a running success score, the latest observed retrieval outcome, and periodic probes. These signals capture sustained reuse, respond to newly observed success, and discover reuse as generation enters new regions. Let qt ∈ { 0, 1}

indicate a probe position, and let s(t) < t denote the most recent retrieval attempt, with zs(t) = 0 

before the first attempt. The activation rule is gt = I[|ht| > τ ] I[ˆ ρt ≥ ρmin ∨ zs(t) = 1 ∨ qt = 1] .The running score sustains retrieval across regions with repeated success. The latest outcome allows a successful attempt to trigger retrieval at the next decision even while the running score remains below the threshold. During inactive periods, the score decays and periodic probes collect fresh verification feedback. A successful probe can reactivate retrieval as useful continuations become available. For each active decision, TLAR also allocates a candidate width. At an active non-probe position, it sets kt = clip( ⌈kmax ˆρt⌉, k min , k max ); at a probe position, it sets kt = kmin . This rule ties the search breadth to accumulated evidence of reuse: lower scores admit fewer historical continuations, while higher scores expand candidate coverage. The selected continuations enter a prefix-sharing tree, so their verification cost also depends on how many prefixes they share. Candidate width controls the proposed work, and the distinct-node count measures the resulting tree size. Activation and width form a feedback loop with target verification. Activation determines when to collect retrieval evidence; width determines how many continuations contribute candidates at that decision. After verification, the observed retrieval outcome updates the score used for subsequent decisions. Section 5.4 evaluates these components through activation and width ablations, probe removal, and parameter sensitivity experiments. 4.4 COMBINING TLAR WITH SMALL DRAFT 

At each position, SmallDraft produces the candidate dt defined in Section 2. If gt = 1 , TLAR also constructs a candidate tree from the current history. If gt = 0 , the TLAR candidate set is empty. The SmallDraft candidate and the TLAR candidates are inserted into one prefix-sharing tree. Duplicate prefixes are merged before verification, and the target model verifies the resulting tree. After verification, TLAR uses the retrieval result to update ˆρt+1 . We evaluate the combined system using the recovery rate R, added accepted tokens ∆, and verification cost C defined in Section 2. 5Preprint When TLAR is inactive, we set aretr (t) = 0 and Nretr (t) = 0 . The evaluation measures the complete method, including positions where its controller decides not to retrieve.

From acceptance to execution efficiency. Throughput depends on both the tokens committed per decoding event and the elapsed time per event. Additional accepted tokens increase progress, while retrieval, tree construction, verification, and memory movement contribute to execution time. Appendix G.4 formalizes this relationship, calculates net time savings from the measured runtimes, and examines the implementation’s resource demands and opportunities for overlap. It also develops a controlled component-evaluation framework linking candidate quality, execution cost, and serving performance, motivating retrieval policies that adapt to both recent reuse and system load. 

# 6 RELATED WORK 

Model-based drafting. Speculative decoding uses a faster drafter to propose tokens and a target model to verify them (Leviathan et al., 2023; Chen et al., 2023). EAGLE and Medusa improve proposal quality through trained drafting components (Li et al., 2024b; Cai et al., 2024), while SpecInfer, EAGLE-2, Sequoia, and OPT-Tree improve tree construction and parallel verification (Miao et al., 2023; Li et al., 2024c; Chen et al., 2024; Wang et al., 2025a). These methods improve how model-generated candidates are produced or verified, but do not test whether the generated trajectory provides a distinct candidate source beyond the same draft model. TLAR addresses this question by measuring the additional accepted tokens supplied by trajectory retrieval after SmallDraft has already proposed its candidates. 

Retrieval-based drafting. Retrieval methods obtain candidates from the prompt, external data, or generated text (Somasundaram et al., 2025; He et al., 2024; Fu et al., 2024; Hu et al., 2025; Oliaro et al., 2026). STAND exploits redundancy in reasoning trajectories (Song et al., 2025), and RASD combines retrieval and model-generated trees before verification (Quan et al., 2025). However, aggregate retrieval acceptance does not establish that useful tokens are specific to the current trajectory, and combining retrieval with a draft model does not show whether retrieval contributes candidates the drafter would otherwise miss. TLAR isolates trajectory-specific reuse through cross-trajectory, shuffled-history, and unigram controls, then measures its marginal contribution beyond SmallDraft and retrieval baselines under matched verification budgets. 

Adaptive speculative computation. Prior work adapts candidate length, lookahead, or draft-tree structure using predicted acceptance or draft-model confidence (Huang et al., 2024; Mamou et al., 2024; Xiong et al., 2025; Wang et al., 2025a). These policies optimize model-generated speculation, but do not use the realized marginal value of trajectory retrieval to decide whether retrieval should run or how many retrieved candidates should be verified. TLAR uses only causally available outcomes from earlier target verification to control later retrieval activation and width. It connects source identification, marginal utility beyond an existing drafter, and feedback-based allocation of verification work in one evaluation. 

# 7 CONCLUSION 

Generated trajectories serve as runtime memory for speculative decoding. Source comparisons reveal trajectory-specific reuse and temporal locality, motivating TLAR’s retrieval from generated history and adaptation through recent verification feedback. TLAR adds accepted tokens beyond a draft model and complements strong retrieval baselines under shared verification budgets. Its controller 9Preprint adjusts retrieval activation and candidate width to balance acceptance gains with verification cost. The complete adaptive union improves end-to-end throughput, with Qwen’s relative gains increasing over the tested output lengths. These results connect trajectory reuse, candidate complementarity, and adaptive resource allocation to efficient inference. 

# ETHICS STATEMENT 

TLAR accelerates language-model inference through reuse of generated text. Exact target-model verification preserves the target distribution, including its potential to produce biased, harmful, or inaccurate content. Deployments should retain appropriate safety safeguards as generation becomes faster. Generated trajectories may contain sensitive information; retrieval buffers should follow the access controls, retention policies, and deletion requirements applied to the original interaction. Our trajectory-local design keeps retrieval within the current generation. Resource use also warrants attention: throughput improvements can reduce execution time for a fixed workload, while energy consumption depends on hardware utilization and deployment scale. Responsible evaluation and release should document experimental conditions and protect sensitive data, credentials.

# A RELATED WORK AND RESEARCH MOTIVATION 

Section 6 places TLAR among speculative decoding methods. We develop that connection through the sequence that motivates the method: longer reasoning creates a decoding workload, speculative verification accelerates token generation, retrieval supplies candidate continuations, and feedback allocates verification work. A.1 REASONING LENGTH AND DECODING WORK 

Chain-of-thought prompting elicits intermediate reasoning steps (Wei et al., 2022). Self-consistency and repeated sampling allocate computation across reasoning paths (Wang et al., 2022; Brown et al., 2024), while test-time scaling extends the amount of reasoning used to produce an answer (Muen-nighoff et al., 2025). These approaches make the execution cost of long trajectories a central inference problem. Acceleration can act at several levels. SpecReason delegates selected reasoning steps using semantic acceptance (Pan et al., 2026). Speculative search and speculative chain-of-thought methods organize parallel reasoning exploration (Wang et al., 2025b; 2026; Shi et al., 2025); multi-sample speculative decoding shares work across sampled outputs (Li et al., 2025). TLAR acts at the token level, retrieving continuations and applying exact target verification. This choice connects reasoning trajectories to lossless decoding. A.2 DRAFT CONSTRUCTION AND EXACT VERIFICATION 

Blockwise decoding proposes several future tokens and retains a verified prefix (Stern et al., 2018). Speculative sampling combines a cheaper drafter with parallel target verification and a sampling correction that preserves the target distribution (Leviathan et al., 2023; Chen et al., 2023). Surveys organize the resulting design space around drafting and verification (Xia et al., 2024). Medusa introduces prediction heads (Cai et al., 2024); EAGLE and its successors use feature prediction and dynamic candidate trees (Li et al., 2024b;c; 2026b). SpecInfer verifies candidate trees (Miao et al., 2023), and Sequoia and OPT-Tree optimize tree structure for acceptance and hardware cost (Chen et al., 2024; Wang et al., 2025a). Ouroboros extends drafts phrase by phrase (Zhao et al., 2024); self-speculation, early exit, and layer skipping reuse the target model’s computation (Zhang et al., 2024; Elhoushi et al., 2024). Lookahead Decoding builds candidates through parallel Jacobi-style iteration (Fu et al., 2024). TLAR supplies an additional candidate source to this draft–verify architecture: continuations already present in the generated trajectory. A.3 TEXT SOURCES AS DRAFT MEMORY 

LLMA copies and verifies reference spans (Yang et al., 2023). REST retrieves from an external datastore (He et al., 2024), PLD+ exploits repeated prompt and generation text (Somasundaram et al., 2025), RAPID combines retrieval with long-context speculation (Chen et al., 2025), and NEST uses nearest-neighbor text for generation and attribution (Li et al., 2024a). Generated and cached sequences provide another memory source: SuffixDecoding uses suffix-tree statistics (Oliaro et al., 2026), SAM-Decoding uses suffix automata (Hu et al., 2025), Token Recycling reuses candidate transitions (Luo et al., 2025), and STAND uses stochastic n-gram statistics from reasoning trajectories (Song et al., 2025). These systems motivate a source-level question: which continuations become useful because they belong to the trajectory currently being generated? Section 3 addresses this question with cross-trajectory, shuffled-history, unigram, and same-prompt comparisons. Sections 5.2 and 5.3 then measure the extra acceptance supplied by that source alongside existing drafters. A.4 FEEDBACK AND THE ALLOCATION OF VERIFICATION WORK 

The benefit of a candidate depends on its acceptance and its verification cost. SpecDec++ predicts acceptance (Huang et al., 2024); DISCO adapts lookahead using draft-model signals (Mamou et al., 2024); EAGLE-2 and DySpec grow trees using draft confidence or distributional information (Li et al., 2024c; Xiong et al., 2025). OPT-Tree and Sequoia optimize expected acceptance and tree cost (Wang et al., 2025a; Chen et al., 2024), while token-driven calibration adapts speculation during execution (Gautam et al., 2025). TLAR uses completed target-verification events to control retrieval activation and width. Periodic probes refresh the signal after retrieval becomes inactive. The controller ablations in Appendix E connect this feedback to incremental acceptance, and Appendix F specifies how the feedback is generated along the executed decoding path. 15 Preprint A.5 TRAJECTORY STRUCTURE AND THE ROLE OF TLAR ReasonOps identifies recurring reasoning operations (Lee et al., 2026), and analyses of overthinking describe clustered backtracking (Rezazadeh & Davoodi, 2026). These observations motivate studying structure within a trajectory. TLAR measures that structure through context matches and exactly accepted continuations. Its verifier preserves the target distribution; speculative contrastive decoding and fuzzy speculation explore altered decoding objectives and accuracy–runtime trade-offs (Yuan et al., 2024; Holsman et al., 2025). RASD provides a closely related hybrid architecture: it prunes retrieval candidates using draft probabilities and merges retrieval and model-generated trees (Quan et al., 2025). Building on retrieval and tree verification, TLAR connects source identification, added acceptance, and feedback-driven resource allocation. F.2 EXACT TREE VERIFICATION AND DISTRIBUTION PRESERVATION 

At a committed prefix h, SmallDraft and retrieval supply child-token labels for a prefix-sharing tree. The target distribution is p(· | h). The verifier follows this target-coupled procedure: 1. Evaluate target logits at the candidate tree nodes in one masked forward pass. 2. Draw x = F −1

> p(·| h)

(u) using the next shared uniform u.3. If x labels a child, commit x, move to that child, and continue. 4. Otherwise, commit x as the correction token and end the event. At depth d, the event ends after the d accepted tree tokens. The reported implementation emits zero bonus tokens. Candidate labels determine which precomputed logits can be reused along the target-sampled path. 

Distribution preservation. For a tree constructed from the committed prefix and a sequence of uniforms, the emitted tokens equal those of target ancestral sampling driven by the same uniforms. At the root, both procedures apply the same inverse CDF to the same distribution and uniform, producing the same token. A token outside the tree is committed as a correction and ends the event. A token inside the tree extends both prefixes identically, allowing the argument to repeat at the child. Induction over committed tokens gives equality of the conditional and joint output distributions. Event termination determines the timing of the next target forward pass. □

Locating resource costs and overlap. The released implementation constructs history matches and candidate metadata on the CPU and verifies the tree on the GPU. Token IDs, positions, and masks cross the host–device boundary. Batched KV packing and accepted-path extraction move device tensors; unequal trees introduce padding. CPU time, transfer and cache-copy bytes, useful and padded nodes, target-kernel duration, and peak allocated memory provide corresponding resource measurements. Verification consumes the completed candidate tree, and subsequent retrieval uses committed tokens and observed outcomes. Drafting and history lookup share the same committed prefix, providing an opportunity for concurrent scheduling. A timeline can measure overlap and exposed waiting time. Concurrent GPU operations may compete for bandwidth and compute resources. Critical-path time and resource demand jointly determine the value of overlap; summing component durations counts overlapping intervals multiple times. 

A controlled component study. Hold prompts, checkpoints, candidates, precision, and target-sampling streams fixed while varying buffer reuse, metadata packing, KV compaction, and concurrent scheduling separately. Evaluate their combination to measure interactions. Record committed tokens, event count, critical-path duration, and complete-request time alongside resource counters. # H DISCUSSION : T RAJECTORY MEMORY AS AN INFERENCE RESOURCE 

The results connect three properties of generated text: it stores reusable continuations, those continua-tions can extend an existing drafter, and their value changes during decoding. This connection gives trajectory memory an operational role in inference. The research problem becomes how to identify, select, and verify useful parts of an evolving memory while accounting for the cost of maintaining and accessing it. The source tests, hybrid comparisons, controller ablations, causal audits, and runtime analysis each resolve one part of that problem. H.1 GENERATION CREATES A MEMORY WHOSE VALUE DEPENDS ON THE DRAFTER 

The source comparisons show that a generated trajectory contains continuations that can be recovered from recurring contexts. The same-prompt comparison adds a more specific observation: changing the rollout of a fixed problem changes the available drafts. Qwen and Mistral favor their own history, while Llama favors the other rollout (Table 12). A mechanistic hypothesis is that choices made during generation—such as notation, local phrasing, and the order of intermediate steps—create a continuation vocabulary that a matching history makes accessible. Paired analyses of these choices would connect the token-level source effect to the structure of reasoning. The value of this memory is also conditional on what the drafter already supplies. Mistral has stronger source acceptance in code than mathematics, yet its hybrid increment is larger in mathematics (Figure 4). SmallDraft coverage mediates the route from available reuse to additional accepted tokens. This reversal makes incremental coverage a useful design objective for memory-based inference: a memory should be evaluated through the predictions it adds to the system receiving it. A direct next experiment would vary draft-model capacity on fixed target trajectories and measure how source coverage, overlap, and marginal gain change together. H.2 A V ERIFICATION BUDGET MAKES CANDIDATE COMPOSITION CENTRAL 

The supplementary addition test identifies new accepted continuations from TLAR across retrieval sources (Table 19). The matched-budget test then requires both sources to share a fixed node allowance. Its union gains of 4.8% –16 .8% over the strongest single source (Table 18) show the value of composing candidates from different retrieval mechanisms. At B = 4 , Qwen’s increment rises from 0.168 to 0.191 ; at B = 8 , it rises from 0.184 to 0.215 .This result motivates selection based on the contribution of a candidate to the tree already chosen. For a fixed target continuation, adding a candidate changes accepted length through the longest accepted path. Two candidates that recover the same prefix overlap in value; a candidate that extends another path changes coverage. Prefix sharing also changes cost, because overlapping paths share verification nodes. Candidate selection couples these two forms of overlap. An ensuing research direction is to estimate the expected increase in accepted length per added tree node, conditional on the existing draft and retrieval branches. Such a selector could jointly choose the source, continuation depth, and branching width. The two-budget experiment provides an initial evaluation template: hold the node cap fixed, vary the selection rule, and record coverage, prefix sharing, and target latency. This would turn multi-source retrieval into an explicit resource-allocation problem. H.3 FEEDBACK SHOULD TRACK THE VALUE ADDED TO THE EXISTING SYSTEM 

Temporal dependence supplies a reason to adapt: next-position hit probabilities after a hit exceed the overall probabilities for all three targets (Appendix C.4). The controller ablations then reveal that the choice of feedback matters. At almost identical node costs, marginal-gain EMA has higher point 32 Preprint estimates than hit EMA, which in turn exceeds random activation (Table 23). Qwen progresses from 

0.096 under random activation to 0.127 under hit EMA and 0.136 under marginal-gain EMA. The feedback becomes more closely aligned with the hybrid’s acceptance objective along this sequence. Periodic probes expose a second property of adaptive memory access: the policy affects which outcomes it observes. An inactive retriever obtains its next reuse observation when it probes. Removing probes reduces Qwen’s gain from 0.1270 to 0.0079 , with reductions for Mistral and Llama as well (Table 22). Probing is part of information acquisition for the controller. Future policies could allocate probes according to uncertainty about local reuse and compare the recovered gain against the cost of gathering that information. Event-driven replay supplies the execution schedule for this experiment, ensuring that feedback corresponds to completed decoding events. H.4 EXACT VERIFICATION SUPPORTS FLEXIBLE MEMORY SEARCH 

Approximate matching and exact acceptance operate at successive stages. The matched-controller comparison shows higher increments with approximate contexts for each target (Table 24); the verifier still commits tokens through the target distribution. The distributional argument and 30,000 coupled trials in Appendix F.2 connect that rule to the implemented tree. The prefix reconstruction and event-driven audits complete the connection from available history to executed feedback. This separation creates a useful interface for future retrieval research. Context embeddings, com-pressed history indexes, and structured references to earlier reasoning steps could be studied as candidate generators feeding the same exact verifier. The research questions become how each representation affects candidate recall, incremental acceptance, lookup latency, and memory use. The existing source controls and shared-budget tests provide a common way to compare those representations while preserving the generation objective. H.5 LONGER REASONING CHANGES BOTH THE MEMORY AND ITS ECONOMICS 

The static grid shows that the highest total gain and the highest gain per node occur at different settings (Table 20). Runtime adds further costs: lookup, index maintenance, tree construction, and cache updates. The B200 measurements connect those costs to output length. At 512 tokens, controller and index overhead produce changes of −0.6% and −0.7% ; at 4,096 tokens, measured gains reach 

12 .4% and 10 .8% (Table 2). The length sweep describes an amortization process as more positions become eligible for retrieval. Long generation has two linked effects: it creates more history to search and more future decoding work over which to recover memory-access cost. This suggests jointly adapting retention, lookup effort, and verification width as a trajectory grows. A useful next study would measure the age and reuse frequency of retained spans alongside device latency, then evaluate eviction policies against full-history retrieval. Repeating the analysis across target–draft pairs, batch sizes, and hardware would connect memory policy to the actual serving objective of accepted tokens per unit time. H.6 AN EVALUATION CHAIN FOR MEMORY -B ASED INFERENCE 

The repetition audit gives the broader evaluation framework its first step: inspect what creates a strong reuse statistic. Removing seven looping Llama mathematics trajectories changes source acceptance from 7.03 to 2.2378 (Appendix C.2). Source identity, task progress, and accepted span length carry complementary information. The hybrid reversal for Mistral adds a second step: measure what the memory contributes beyond the current drafter. Shared-budget unions add resource control, controller ablations identify the feedback objective, and causal replay connects the policy to an executable decoder. Together, these steps provide a reusable methodology for studying inference-time memory: identify the source signal, measure incremental coverage, allocate a common resource budget, validate the execution path, and account for runtime. Future benchmarks can pair these measurements with task outcomes and actual device traces, with documented measurement procedures and reproducible execution settings. Appendix G.4 develops this evaluation into a component study that connects candidate coverage, committed progress, critical-path time, and serving performance. The central contribution of this perspective is a connection between reasoning content and computational schedul-ing.
