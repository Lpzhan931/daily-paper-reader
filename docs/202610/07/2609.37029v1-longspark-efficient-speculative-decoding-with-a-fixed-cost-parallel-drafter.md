## 摘要
投机解码通过在单次目标前向传播中验证多个草稿 token 来加速自回归推理。然而，随着上下文增长，现有最先进的草稿器变得日益昂贵，削弱了其本应提供的效率优势。我们认为这种随上下文扩展的成本增长是不必要的。独立语言模型必须随其前缀增长，因为它要对其生成的每个 token 负全部责任。相比之下，草稿器只提出候选；目标模型会在任何 token 被最终提交之前捕获并纠正每一个错误。因此，草稿器的解码成本可以完全独立于前缀长度。我们提出 LongSpark，一种块扩散草稿器，它通过从目标模型的验证过程中提取固定尺寸、多尺度的视图来实现这一点，从而无需不断增长的持久状态。大量评估表明，LongSpark 在多种模型规模和真实服务条件下均实现了最先进的端到端效率。值得注意的是，它在长上下文任务中提供了最低的每输出 token 时间，同时将草稿器的上下文状态减少了几个数量级。

## Abstract
Speculative decoding accelerates autoregressive inference by verifying multiple draft tokens in a single target forward pass. However, as the context grows, existing state-of-the-art drafters become increasingly expensive, eroding the very efficiency advantage they are designed to provide. We argue that this scaling is unnecessary. A standalone language model must grow with its prefix because it is solely responsible for every token it produces. A drafter, by contrast, only proposes candidates; the target catches and corrects every error before any token is committed. The drafter's decoding cost can therefore be made entirely independent of the prefix length. We introduce LongSpark, a block-diffusion drafter that achieves this by extracting fixed-size, multiscale views from the target's verification pass, thereby eliminating the need for a growing persistent state. Extensive evaluations demonstrate that LongSpark achieves state-of-the-art end-to-end efficiency across multiple model scales and realistic serving conditions. Notably, it delivers the lowest time-per-output-token on long-context tasks while reducing the drafter's context state by several orders of magnitude.

## 1. 核心问题与整体含义

- **背景**：投机解码（Speculative Decoding）通过轻量草稿器（drafter）一次性提出多个候选 token，再由目标模型（target）在单次前向中并行验证，从而加速自回归推理。其成立前提是草稿器必须显著比目标模型便宜，加速才有意义。
- **核心问题**：现有主流草稿器的解码成本随前缀（上下文）长度增长，恰好在其最需要发挥作用的场景中侵蚀了效率优势。这一缩放瓶颈是系统性的：
  - 自回归草稿器维护随前缀线性增长的 KV cache；
  - 复用目标表示（如 EAGLE 系列）能提升提议质量，但未消除增长的状态；
  - 窗口式方法（如 LongSpec）限制了自身 cache，但仍需对目标全前缀 KV 做交叉注意力；
  - 块扩散草稿器（DFlash 等）虽并行预测多个位置，却常把全前缀的目标特征注入每个草稿层。
- **核心洞察（草稿器—目标不对称性）**：独立语言模型必须忠实表示完整前缀，因为它对每个生成 token 负全部责任；而草稿器只负责"提议"，目标模型通过拒绝采样在任何 token 提交前捕获并纠正错误——一个错误提议只增加一轮解码，**永不产生错误输出**。因此草稿器可以工作在压缩的、有损的前缀视图之上。
- **整体含义**：论文提出"**固定成本草稿（fixed-cost drafting）**"原则——草稿器的解码成本可以完全独立于前缀长度；真正的效率度量不是接受长度本身，而是"每单位草稿开销所产生的被接受 token 数"。LongSpark 是这一原则的可行实现。

## 2. 方法论

### 2.1 核心思想
- 用**块扩散草稿器（block-diffusion drafter）**，从目标模型的验证前向过程中抽取**固定尺寸、多尺度**的上下文视图，彻底消除随前缀增长的持久状态。
- 每轮解码中，**目标验证是唯一一次全前缀遍历**；其余操作（上下文提取、迭代精炼、草稿状态）严格保持 \(O(1)\)（相对已确认前缀）。

### 2.2 固定成本上下文接口（三个互补视图）
从目标模型均匀间隔选定的层子集 \(\mathcal{L}\) 中提取：
1. **边界状态（boundary state）**：将解码边界处的目标隐藏表示 \(\{\boldsymbol{h}^{\ell}_t\}_{\ell\in\mathcal{L}}\) 通过学习的投影融合为单一条件向量 \(\boldsymbol{c}_t\)，锚定当前生成点。
2. **近期 KV 窗口（recent KV window）**：每选定层保留 \(W=256\) 个条目，保持局部 token 级细节。
3. **全局上下文摘要（global context summary）**：每选定层、每注意力头维护 \(R=16\) 个可学习摘要查询 \(\boldsymbol{G}\in\mathbb{R}^{R\times d}\)（推理时固定），计算
   \[
   \boldsymbol{M}_t=\mathrm{Attn}(\boldsymbol{G},\boldsymbol{K}_{1:t},\boldsymbol{V}_{1:t})
   \]
   由于 \(\boldsymbol{G}\) 固定，历史注意力贡献始终有效，每轮只需纳入至多 \(B+1\) 行新 KV 行。

### 2.3 增量摘要更新（关键工程细节）
- 对每个摘要查询，用 log-sum-exp 合并统计量：设 \(\eta_A=\log\sum_{j\in A}\exp(s_j)\)、\(\boldsymbol{m}_A=\sum_{j\in A}\exp(s_j-\eta_A)\boldsymbol{v}_j\)，新行集合 \(N\) 合并为
  \[
  \eta=\log(\exp(\eta_A)+\exp(\eta_N)),\quad
  \boldsymbol{m}=\exp(\eta_A-\eta)\boldsymbol{m}_A+\exp(\eta_N-\eta)\boldsymbol{m}_N
  \]
- 每查询仅需存一个值向量与一个对数归一化器，更新成本与存储均与 \(t\) 无关。

- **并行骨干**：\(D=|\mathcal{L}|=5\) 层 Transformer 同时处理 \(B=7\) 个草稿槽位（槽 0 编码已提交 token \(\boldsymbol{a}\)，其余为 mask 嵌入），结合块内位置编码与边界状态初始化。
- **固定尺寸注意力上下文**：每层注意力键值为
  \[
  \boldsymbol{K}=[\boldsymbol{K}_b;\boldsymbol{K}_w;\boldsymbol{G}],\quad
  \boldsymbol{V}=[\boldsymbol{V}_b;\boldsymbol{V}_w;\boldsymbol{M}_t]
  \]
  即块内双向注意力 + 近期窗口 + 全局摘要，每头最多 \(B+W+R\) 个条目。
- **冻结目标归一化与词表头**产生基础 logits \(\boldsymbol{z}_i^{(0)}\)。
- **低秩顺序修正（Markov correction）**：条件于前一个采样 token（\(y_0=\boldsymbol{a}\)）
  \[
  \boldsymbol{z}_i=\boldsymbol{z}_i^{(0)}+\boldsymbol{W}_c\boldsymbol{E}_c(y_{i-1})
  \]
  最终提议分解为 \(q(y_{1:B}\mid s)=\prod_{i=1}^{B}q_i(y_i\mid s,y_{i-1})\)。仅修正与采样是串行的，骨干与词表投影完全并行。
