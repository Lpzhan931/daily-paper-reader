## 摘要
长链思维链推理增加了顺序解码成本，同时产生了不断增长的、可能可复用的续写片段历史。我们研究这种历史何时能提供有用的草稿，并补充现有的草稿模型。受控来源比较揭示了轨迹特定的复用，这促使我们提出 Trajectory-Local Adaptive Retrieval (TLAR) 方法。TLAR 从当前轨迹中检索近似匹配的续写片段，并利用最近的验证结果来调整检索激活和候选宽度。TLAR 在共享候选树中将检索到的续写片段与模型生成的草稿相结合，通过精确验证保持目标模型的输出分布。在代码调试、数学和开放式写作中，我们的评估将来源复用、增量接受和执行成本联系起来。将 TLAR 与强检索基线相结合，在匹配的验证预算下提高了 token 接受率，并相较于草稿模型基线提升了端到端吞吐量。这些发现支持将生成的轨迹用作自适应推理的运行时记忆。

## Abstract
Long chain-of-thought reasoning increases sequential decoding cost while creating a growing history of potentially reusable continuations. We investigate when this history supplies useful drafts and complements an existing drafter. Controlled source comparisons reveal trajectory-specific reuse, motivating our method Trajectory-Local Adaptive Retrieval (TLAR). TLAR retrieves approximately matched continuations from the current trajectory and uses recent verification outcomes to adapt retrieval activation and candidate width. TLAR combines retrieved continuations with model-generated drafts in a shared candidate tree, preserving the target model's output distribution through exact verification. Across code debugging, mathematics, and open-ended writing, our evaluation connects source reuse, incremental acceptance, and execution cost. Combining TLAR with strong retrieval baselines improves token acceptance under matched verification budgets and increases end-to-end throughput over the draft-model baseline. These findings support generated trajectories as runtime memory for adaptive inference.

## 1. 核心问题与研究动机

- **背景**：长思维链（Long-CoT）推理（竞赛数学、程序调试、科学推理）显著提升模型能力，但单条回复可达数千 token；自回归逐 token 生成使顺序解码成本随轨迹长度累积，长 CoT 推理的效率问题变得关键。
- **现有做法**：推测解码（speculative decoding）用小模型或轻量预测头做草稿，再由目标模型并行验证，可在不改变目标分布的前提下加速；近期方法扩展到整段推理步骤，但**需要额外训练组件**。
- **替代路线**：基于检索的草稿方法从 prompt、外部数据存储或已生成文本中构造候选，无需训练。本文聚焦于**当前轨迹自身的历史 token**：长推理中相似上下文可能重复出现，早先上下文之后的续写可被复用为草稿。
- **核心问题**：模型自身的历史**何时**能提供有用草稿，并**真正补充**已有草稿模型（而不是与之重复）？
- **三大挑战**：
  1. **区分轨迹复用与公共文本**：检索成功可能只是共享词符/格式或模型重复输出（无进展），必须用同任务、同模型、同匹配规则的对照源比较。
  2. **找到小草稿模型之外的 token**：若小模型已能预测相同 token，检索不增加被接受 token 数，须与"同一小草稿模型单独使用"对比。
  3. **控制检索验证成本**：每个检索候选都要目标模型验证；可复用内容并非每个位置都出现，须仅依据**此前已观测到的验证结果**决定何时检索、检索多宽。
- **整体含义**：把"生成轨迹"视为推理时的**运行时记忆（runtime memory）**，研究如何识别、选择并验证其中有用的续写，同时计入维护与访问成本。

## 2. 方法论：Trajectory-Local Adaptive Retrieval (TLAR)

### 2.1 核心思想
- 在 SmallDraft（小草稿模型）之外，**额外**从当前生成历史中检索近似匹配的续写，与草稿模型候选合并到**同一前缀共享树**中，由目标模型做**精确验证**，从而保持目标输出分布不变。
- 用**因果可得**的近期验证反馈（而非额外训练预测器、外部轨迹或额外目标模型输出）自适应控制检索的"开关"与"宽度"。

### 2.2 关键技术细节

**（1）从当前历史检索候选（§4.1）**
- 仅搜索已生成历史 $h_t=(y_1,\dots,y_{t-1})$；当前上下文 $u_t=(y_{t-c},\dots,y_{t-1})$。
- 匹配集合：$J_t=\{j: c+1\le j\le t-d,\ d_{\mathrm{Ham}}(u_t,u_j)\le \epsilon\}$
  - 允许最多 $\epsilon$ 个 token 差异（容忍标点、格式、措辞的微小变化）；条件 $j\le t-d$ 保证续写 $(y_j,\dots,y_{j+d-1})$ 已完全包含在历史中（**不使用当前或未来 token**）。
- 每个 $j$ 取其后 $d$ 个历史 token 作为候选 $r_j$，按**新近度**排序，取前 $k_t$ 个，插入**前缀共享树**（共享前缀只出现一次，避免重复验证）。

**（2）跟踪近期检索成功（§4.2）**
- 令 $m_t\in\{0,1\}$ 表示是否尝试检索，$z_t=\mathbb{I}[a_{\text{retr}}(t)\ge 1]$ 表示是否至少接受 1 个检索 token。
- 运行分数（指数滑动平均）：
  - 检索时：$\hat\rho_{t+1}=(1-\alpha)\hat\rho_t+\alpha z_t$
  - 未检索时：$\hat\rho_{t+1}=(1-\alpha)\hat\rho_t$（衰减）
  - 其中 $\alpha=1-2^{-1/H}$，默认 $H=32$。

**（3）决定何时检索、检索多宽（§4.3）**
- 历史长度门限：需 $|h_t|>\tau$（默认 $\tau=512$）以积累上下文与续写。
- 激活规则：$g_t=\mathbb{I}[|h_t|>\tau]\cdot\mathbb{I}[\hat\rho_t\ge\rho_{\min}\ \vee\ z_{s(t)}=1\ \vee\ q_t=1]$
  - 三项分别对应：持续成功区域、最近一次成功即刻触发、周期性探针（probe，间隔 $P=32$）在失活期后重新发现复用。
- 候选宽度：非探针位置 $k_t=\mathrm{clip}(\lceil k_{\max}\hat\rho_t\rceil,k_{\min},k_{\max})$；探针位置 $k_t=k_{\min}$（默认 $k_{\min}=1,k_{\max}=4,\rho_{\min}=0.05$）。
- 形成"激活—宽度—验证结果—分数更新"的反馈闭环。

**（4）与 SmallDraft 融合（§4.4）**
- SmallDraft 候选 $d_t$ 与 TLAR 候选插入同一前缀共享树，**去重合并**后交目标模型验证。
- 若 $g_t=0$，TLAR 候选集为空（$a_{\text{retr}}(t)=0,\ N_{\text{retr}}(t)=0$），评价覆盖完整方法（含不检索的位置）。

### 2.3 评价指标（§2）
- 接受长度：$a(c,t)=\max\{\ell\le L: c_{1:\ell}=y_{t:t+\ell-1}\}$
- **恢复率** $R=\Pr(a_{\text{retr}}(t)\ge 1\mid a_{\text{small}}(t)=0)$
- **增量接受** $\delta(t)=\max\{a_{\text{small}}(t),a_{\text{retr}}(t)\}-a_{\text{small}}(t)$，平均 $\Delta$
- **验证成本** $C$：提交给目标模型的检索节点数（自适应重放中用"去重前缀节点数"）
- 评测协议：固定目标轨迹与接受规则，所有草稿方法在**相同位置**预测**相同**下一 token。
