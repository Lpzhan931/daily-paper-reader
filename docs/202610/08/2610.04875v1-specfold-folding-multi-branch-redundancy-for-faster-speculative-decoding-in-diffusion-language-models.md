## 摘要
扩散大语言模型（DLLMs）通过迭代式块去噪生成文本，而多分支推测解码通过在单次前向传播中同时验证一个主分支和多个草稿分支来加速这一过程。尽管此前的 DLLM 加速方法主要利用去噪步骤间的时间冗余，我们发现了每个推测验证步骤内一个互补的冗余维度：多分支计算冗余。在推测验证过程中，草稿分支从其父分支继承大部分 token，同时解掩码少量额外位置，导致大量隐藏状态在不同分支之间保持高度相似。我们提出 SpecFold，一种算法-系统协同设计，利用这种多分支冗余来降低多分支推测验证的成本。在算法层面，SpecFold 执行 token 级残差门控，并通过折叠注意力和 FFN 选择性复用父分支计算，同时保留残差隐藏状态。在系统层面，Triton 内核实现通过高效的稀疏多分支执行，将这种细粒度复用转化为端到端吞吐量提升。SpecFold 与时间缓存正交，并兼容现有的 DLLM 推测策略。在两大 DLLM 系列、五个模型和五个标准基准上，SpecFold 相比 Spiffy 实现高达 1.64 倍的吞吐量提升，相比原始解码高达 1.99 倍，同时保持相当的任务性能。

## Abstract
Diffusion large language models (DLLMs) generate text through iterative block denoising, and multi-branch speculative decoding accelerates this process by verifying a main branch together with multiple draft branches in a single forward pass. While prior DLLM acceleration methods primarily exploit temporal redundancy across denoising steps, we identify a complementary redundancy axis within each speculative verification step: multi-branch computational redundancy. During speculative verification, draft branches inherit most tokens from their parents while unmasking a small set of additional positions, causing large portions of hidden states to remain highly similar across branches. We propose SpecFold, an algorithm-system co-design that exploits this multi-branch redundancy to reduce the cost of multi-branch speculative verification. Algorithmically, SpecFold performs token-level residual gating and selectively reuses parent computation through folded attention and FFN while preserving residual hidden states. Systemically, a Triton kernel implementation translates this fine-grained reuse into end-to-end throughput gains through efficient sparse multi-branch execution. SpecFold is orthogonal to temporal caching and compatible with existing DLLM speculation strategies. Across two DLLM families, five models, and five standard benchmarks, SpecFold achieves up to 1.64x throughput over Spiffy and up to 1.99x over vanilla decoding, while maintaining comparable task performance.

- **现有加速路径**：
  - *时间冗余*：跨去噪步骤复用计算（块级解码、置信度解掩码、自适应缓存、层跳过等）。
  - *推测解码*：多分支推测解码在单次批前向中验证主分支 + B 个草稿分支，若草稿匹配后续主分支轨迹，则可跳过未来的去噪前向。
- **核心瓶颈**：论文将解码成本分解为：
  - 总成本 = 去噪前向次数（❶推测）× 单次前向成本（❷多分支执行）
  - 多分支推测降低 ❶，但**每个前向密集评估所有分支，使 ❷ 随分支数增长**。
- **关键观察（论文核心贡献）**：多分支推测验证步骤内部存在**新的冗余轴——多分支计算冗余**。草稿分支从父分支继承几乎所有 token，仅解掩码少量位置，因此大多数 token 的隐藏状态在父-子分支间高度相似。
  - 实证：在 Fast-dLLM-v2-7B 上，跨全部 28 层的 (draft, step, layer, position) 单元中，**72% 满足相对残差 ρ ≤ 0.1，88% 满足 ρ ≤ 0.3**，高发散区域集中在刚解掩码的位置。
- **整体含义**：SpecFold 首次针对"单个推测验证步骤内、草稿分支之间"的冗余进行折叠，与时间缓存、层跳过等方法正交，可与现有 DLLM 推测策略（如 Spiffy）组合使用。

## 2. 方法论

### 2.1 核心思想
- 算法-系统协同设计：算法层暴露细粒度跨分支复用机会，系统层（Triton 内核）将其转化为实际吞吐增益。
- 在每一 Transformer 层前，通过 **token 级父-子残差门控**判定折叠（fold）或重算（recompute）：
  - 折叠位置复用父分支的投影、FFN 与注意力状态；
  - 发散位置重算，保持分支多样性。

### 2.2 关键技术细节
- **相对残差门控**（Eq. 4）：
  - ρ = ‖H_child[n] − H_parent[n]‖ / ‖H_parent[n]‖
  - 若 ρ ≤ δ（重算阈值），位置 n 折叠；否则进入重算集 R。
  - 主分支 i=0 无父分支，全部位置重算。
- **折叠自注意力**（Appendix A.1）：
  - DLLM 注意力为双向，折叠位置不能简单复制输出。
  - 折叠位置继承父分支的 (q, k, v)，并复用父分支的流式 softmax 状态 (m, Z, O)。
  - 由于子分支表仅在 R 位置与父分支不同，可**精确地**把父状态转换为子状态：重标定最大值 m′ = max(m_parent, max_{e∈R} q·k_e/√d)，先减去父分支在 R 上的贡献，再加上子分支的贡献（Eq. 8）。
- **折叠 FFN**（Appendix A.2）：
  - FFN 是位置级运算，折叠位置直接复用父分支 FFN 输出表 F_parent[n]。
- **残差流永不折叠**：每个位置保留自身分支的残差流（H_child[n]），使跨分支多样性可逐层累积传播；当发散累积超过 δ 时，该位置自动转为重算。
- **折叠链解析**：折叠位置可能指向父分支中同样被折叠的位置，需沿草稿图逐跳解析到最近的"重算祖先"。
- **Triton 内核流水线**（每层 6 类内核）：
  1. `residual_delta_gate`：门控、源映射、紧凑化、RMSNorm 统计
  2. `src_resolve`：指针跳跃解析折叠链
  3. `ln_qkv_rope_scatter`：对重算位置做归一化 + 打包 QKV + RoPE
  4. `flash_attn`：仅对重算 query 行做 FlashAttention 流式计算，保留 (m, Z, O) 状态
  5. `chain_correction`：对折叠位置做精确注意力修正
  6. `ln_gateup_silu / down_residual_scatter`：重算行的融合 FFN + 残差散射
- **工程细节**：共享前缀 KV 缓存以零拷贝跨步视图扩展至所有分支；支持分组查询注意力（GQA）。

- **准确率保持**：SpecFold 在全部 5 基准上与 Vanilla/Spiffy 相当，偏差为双向小幅波动。
- **阈值鲁棒性**：δ 在 0–0.2 区间准确率保持 Vanilla 水平且已获 1.3–1.4× 加速；δ→0 时结果收敛至 Spiffy，验证实现正确性。

## 7. 优点

- **新颖的冗余维度**：首次识别并利用"单次推测验证步骤内、草稿分支之间"的冗余，与时间冗余正交，可叠加使用。
- **算法-系统协同设计完整**：不仅提出算法，还给出 Triton 内核级实现（6 类内核、折叠链解析、注意力精确修正），保证理论 FLOPs 节省能转化为端到端吞吐。
- **精确的注意力修正**：折叠位置的注意力状态通过减去父分支贡献、加上子分支贡献实现数学上精确的增量更新，而非近似复制，兼顾正确性与复用。
- **残差流保留设计巧妙**：残差永不折叠，使分支多样性可逐层累积，避免折叠过度导致草稿质量下降。
- **实验公平性**：与 Spiffy 共享草稿图与 NFE，剥离了草稿策略的影响；覆盖多模型家族、多规模、多任务域、多硬件。
- **超参数鲁棒**：δ 在 0–0.2 的宽区间内性能稳定，无需逐任务调参；对草稿图深度 D 不敏感。
- **兼容性好**：不修改草稿构建策略与模型权重，可直接与现有 DLLM 推测方法组合。

## 8. 不足与局限

- **硬件覆盖有限**：主实验仅在单张 H100 上完成，额外硬件消融仅限 A100；未报告多 GPU、其它厂商加速器或不同显存配置下的表现。

- **基线对比不完整**：未与其它 DLLM 推测解码方法（DiffuSpec、Self-Speculative Decoding 等）直接对比，也未与时间缓存/层跳过方法做组合实验验证正交性。
- **精度偏差风险**：虽然论文将 Spiffy/SpecFold 相对 Vanilla 的准确率漂移归因于 bf16 数值噪声并做了 serialized 验证，但该验证的范围与覆盖基准未详细披露；在准确率敏感场景下，这种数值漂移仍需谨慎对待。

- **大模型收益递减**：在 NLD-14B 上较 Spiffy 仅 1.07×、较 Vanilla 1.24×，说明模型越大、密集计算占比越高时，折叠带来的相对收益越小；论文未深入分析该缩放趋势的根因。
- **应用限制**：方法依赖草稿图结构与残差阈值 δ，对草稿构建质量有一定依赖；在草稿接受率低或分支差异大的场景，折叠率可能下降，收益受限。
