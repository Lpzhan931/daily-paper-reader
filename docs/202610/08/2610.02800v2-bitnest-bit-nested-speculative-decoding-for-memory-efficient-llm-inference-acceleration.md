## 摘要
投机解码通过使用轻量级草稿模型提议多个 token 以进行并行验证，从而加速自回归生成。然而，现有方法通常需要额外的草稿模型或权重表示，这会在资源受限设备上引入不可忽略的内存开销。自投机方法降低了这一开销，但仍面临草稿质量、目标模型质量和存储效率之间的权衡。我们提出 BitNest，一种比特嵌套投机解码框架，它将低精度草稿直接嵌入到更高精度的目标表示中。BitNest 并非从预定义目标中导出草稿，而是首先构建一个强大的低精度基础模型，然后通过残差精炼恢复更高精度的目标，从而使两个模型共享单一物理权重表示。BitNest 进一步将这种渐进式精度设计扩展到 KV 缓存，以支持长上下文推理。在多个 7B--8B 的面向边缘设备的 LLM 以及多样化工作负载上，BitNest 实现了 95.2% 的平均投机接受率，同时几乎保持了更高精度模型的质量，并在 FP16 自回归解码上实现了 1.48--1.61 倍的端到端加速。在所有代表性自投机基线均支持的 LLaMA 模型上，BitNest 也实现了持续具有竞争力或更高的解码加速。

## Abstract
Speculative decoding accelerates autoregressive generation by using a lightweight draft to propose multiple tokens for parallel verification. However, existing methods often require an additional draft model or weight representation, introducing non-negligible memory overhead on resource-constrained devices. Self-speculative approaches reduce this overhead, yet still face trade-offs between draft quality, target quality, and storage efficiency. We propose BitNest, a bit-nested speculative decoding framework that embeds a low-precision draft directly into the higher-precision target representation. Instead of deriving a draft from a predefined target, BitNest first constructs a strong low-precision base and then recovers the higher-precision target through residual refinement, enabling both models to share a single physical weight representation. BitNest further extends this progressive-precision design to the KV cache for long-context inference. Across multiple 7B--8B edge-friendly LLMs and diverse workloads, BitNest achieves an average speculative acceptance rate of 95.2% while closely preserving higher-precision model quality, and delivers 1.48--1.61x end-to-end speedup over FP16 autoregressive decoding. On the LLaMA models supported by all representative self-speculative baselines, BitNest also achieves consistently competitive or higher decoding speedup.

- **研究动机**：自回归生成是 LLM 推理的主要瓶颈，受限于高计算成本、模型与 KV 缓存的显存占用以及内存带宽需求，在单 GPU、消费级 GPU 和边缘设备等资源受限场景中尤为突出。
- **现有方案困境**：
  - 传统投机解码需要额外草稿模型（如 EAGLE、DFlash），引入不可忽略的草稿权重存储开销，在 16GB 设备上 7B 模型已逼近内存上限，草稿模型与目标模型、KV 缓存直接争抢有限内存。
  - 自投机解码（层跳过/早退、量化）虽避免了独立草稿模型，但存在草稿效率、目标质量与存储开销三者之间的权衡：
    - 层跳过（Draft & Verify、LayerSkip）将草稿效率与预测质量耦合；
    - QSpec 将目标限制在共享低比特表示；
    - QuantSpec 仍保留额外的低精度草稿表示。
- **核心问题**：能否用单一模型表示同时支持轻量级草稿与高质量目标，且无需额外内存开销，同时保持足够高的草稿-目标一致性？
- **整体含义**：提出 **Bit-Nested Speculative Decoding（比特嵌套投机解码）** 新范式，将低精度草稿物理嵌套在高精度目标表示内部，实现"一份物理权重、两种精度视图"，为内存受限设备提供了一种无需独立草稿模型的加速路径。

## 2. 方法论

### 2.1 核心思想

- 反转传统"从目标派生草稿"的思路，采用**基座优先（base-first）** 构造：先构建强低精度基座（W4），再将剩余量化误差编码为精修位（4-bit），合成高精度目标（W8）。
- 低精度草稿是高精度目标的**精确子集**，二者共享单一物理权重表示，推理时按需读取不同比特平面。

### 2.2 关键技术细节

- **函数保持旋转变换**：先对预训练权重 W 施加 R1/R2 旋转（如 SpinQuant），得到等价表示 W′，抑制激活离群值，提升低比特量化鲁棒性。
- **W4 基座构造**：使用 GPTQ（group size 128）量化 W′，得到整数码 q₄ 与组尺度 s₄，W_draft = q₄·s₄，此后 q₄、s₄ 固定不变。
- **固定基座残差精修**：
  - 量化误差 ΔW = W′ − W_draft；
  - 精修尺度 s_ref = s₄/16；
  - 精修码 q_r 为 4-bit 有符号整数（q₄=−8 时采用非对称裁剪 [0,7]，避免越过 INT8 下界）；
  - 目标权重重建：W_target = q₄s₄ + q_r·s_ref = (16q₄ + q_r)·s_ref。
- **双平面权重存储（Dual-Plane Weight Storage）**：
  - 由于现代内存按字节寻址，4-bit 半字节无法独立访问；若基座与精修混存于同一字节，草稿仍会取到精修位，丧失低精度访存优势。
  - 将基座与精修打包为两个独立的 4-bit 流，各占 N/2 字节；草稿仅读基座平面（4 bits/weight 流量），验证读两个平面恢复 W8。
  - 精修无需额外尺度元数据（s_ref 可由 s₄ 推导）。
- **上下文感知 KV 嵌套**：
  - 对 KV 缓存执行在线逐 token、逐 KV 头的对称 RTN 量化（head dim d=128），构造 KV4 基座 + 4-bit 精修 = KV8 目标。
  - 草稿仅读 KV4 基座，验证读两个平面恢复 KV8。
  - 短上下文时草稿与验证均用 KV8 以保持一致性；长上下文时切换为 KV4 草稿 + KV8 验证以降低 KV 流量。
  - 支持 Recent-N 策略：最近 N 个 KV 条目以高精度供草稿访问，旧条目走低精度基座，作为可调中间点。
  - 草稿阶段候选 token 的 KV 状态为临时，验证时重算，接受则保留、拒绝则丢弃。

## 6. 主要结论与发现

- **加速效果**：BitNest 在四个 7B–8B 模型上相对 16-bit 自回归实现 **1.48–1.61×** 端到端加速，跨工作负载表现一致。
- **高接受率**：平均投机接受率 **95.2%**（各模型平均 94.8%–95.7%），表明 W4A8 草稿与 W8A8 目标高度一致。
- **质量保持**：性能接近 FP16 与独立 W8A8。例如 LLaMA-3-8B GSM8K 达 49.8%（W8A8 为 50.0%）；而直接用 W4 作为目标仅 41.4%–41.8%。
- **长上下文优势**：KV8→KV8 时加速比从 4K 的 1.57× 降至 32K 的 1.38×；采用 KV4→KV8 时在 32K 达 **1.66×**，优于 QSpec（1.11×）与 QuantSpec（1.11–1.21×）。
- **显存节省**：LLaMA-2-7B 嵌套权重占 6.22 GiB，与独立 W8 相同；若独立存 W4 草稿 + INT8 目标需 9.38 GiB。32K 上下文下峰值显存 21.0 GiB（QSpec 24.0、QuantSpec 25.1）。
- **边缘设备**：Orin NX16 上 LLaMA-2-7B-32K 约 1.5× 加速，解码能耗从 1.52 降至 0.95 J/token；最大可执行上下文从 FP16 的 2K、W8A8 的 6K 扩展到 **10K**；NX8 上 Llama-3.2-3B 最高 1.57× 加速。
- **VLA 场景**：OpenVLA-7B 解码阶段 1.35× 加速，LIBERO Spatial 成功率 89%（FP16 为 86%，W4A8 为 80%）。
- **关键洞察**：
  - 高草稿-目标一致性并不保证目标保真度（KV4 目标接受率仍 0.933，但 GSM8K 从 81.6% 降至 78.4%）；
  - 低精度基座适合草稿，但最终生成需保留精修位；
  - 低精度草稿 KV 的收益强依赖于注意力架构：MHA（LLaMA-2）收益显著，GQA（Qwen2.5）收益有限。

## 7. 优点

- **范式创新**：提出"比特嵌套"这一表示层面的自投机新思路，从"派生草稿"转为"基座优先 + 残差精修"，使草稿成为目标的精确子集，概念简洁且优雅。
- **零额外草稿存储**：单一物理权重同时支持 W4 草稿视图与 W8 目标视图，从根本上消除独立草稿模型的显存开销，对边缘部署意义重大。
- **存储布局设计巧妙**：双平面存储解决了"逻辑 W4 无法转化为实际访存节省"的字节寻址难题，使草稿真正只读 4 bits/weight 流量。
- **KV 缓存同构扩展**：将嵌套原则一致地推广到 KV 缓存，并通过上下文感知切换（短上下文 KV8→KV8、长上下文 KV4→KV8）适配不同上下文长度。
- **实验覆盖面广**：4 个模型家族、6 类工作负载、多上下文长度、边缘设备、VLA 模型，且消融维度细致（γ、草稿 KV 精度、目标 KV/权重精度、注意力架构差异）。
- **公平性意识**：强调归一化到同一引擎的 16-bit AR 基线，保留各基线原生精度配置。
- **工程落地性**：提供 Triton kernel 实现与 GEMV 优化，边缘端实测有效带宽从 46 GB/s 提升至 63 GB/s。

## 8. 不足与局限

- **未利用辅助草稿架构**：论文自述不适用于扩散式草稿（如 DFlash）等可提供更强候选并行性的架构，未来需探索如何在不牺牲嵌套内存优势的前提下兼容此类草稿器。
- **Prefill 阶段开销**：OpenVLA 实验显示，当前大 M（M=288）prefill 路径需反量化到 FP16 走 cuBLAS，导致 prefill 比 FP16 慢约 1.7×，虽解码阶段加速 1.35×，但单动作总延迟（212.7 ms）略高于 FP16 AR（201.5 ms），整体端到端收益被抵消。
- **大 M prefill 缺乏专用 INT8 kernel**：论文将此列为未来工作，意味着当前实现在 prefill 主导场景（如长提示、批量推理）中优势有限。
- **基线覆盖不均衡**：Qwen2/Qwen2.5 上多个基线显示 N/A，缺乏同模型同引擎的直接对比，跨方法结论的说服力在非 LLaMA 模型上有所削弱。
- **批量与吞吐场景缺失**：所有主实验均为 batch size 1，未评估批量推理、多请求并发等实际服务场景下的表现。
- **精度组合较单一**：主要实例化为 W4/W8 与 KV4/KV8，未系统探索其他 (b, r) 比特组合或更激进的低比特设置。
- **接受率与目标保真度的张力**：论文自身指出高接受率不保证高质量，说明该框架的收益仍依赖目标精度选择，需要针对任务敏感度调参。
- **训练/构造成本未披露**：GPTQ 量化、旋转折叠、精修构造所需的校准数据量与计算开销未说明，影响可复现性与部署成本评估。
