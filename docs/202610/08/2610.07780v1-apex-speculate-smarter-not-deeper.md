## 摘要
推测解码通过在目标模型验证前草拟多个 token 来降低大语言模型推理延迟，但其效果取决于提议机制和草拟深度。固定配置无法响应生成过程中可预测性、重复性和接受率的变化，因此更深的草拟可能增加浪费的计算，却无法带来成比例的加速。我们提出 APEX，一种学习型控制器，通过请求级专家选择和块级深度自适应来平衡解码速度与草稿 token 浪费。APEX-Router 为每个请求在 EAGLE-3、n-gram 和草稿模型推测之间进行选择，而 APEX-Depth 利用因果解码信号和近期验证器反馈，在每个验证块处调整草拟长度。APEX 将接受的草稿长度建模为删失生存反馈，学习逐位置拒绝风险、块执行成本，以及平衡吞吐量、已接受进展和浪费 token 的动作效用。这使控制器能够自适应推测，同时保留目标模型的验证流程。我们将 APEX 集成到 vLLM 中，并使用 Qwen3-8B 在六个工作负载上进行评估，相比自回归解码实现了最高 5.24 倍加速。在总体评估中，APEX-S 实现了 4.27 倍加速，而 APEX-B 实现了 3.27 倍加速，与 k=16 的固定 n-gram 推测相比，浪费 token 百分比相对降低了 41.0%，为平衡加速与草稿 token 利用率提供了不同的工作点。

## Abstract
Speculative decoding reduces large language model inference latency by drafting multiple tokens before target-model verification, but its effectiveness depends on both the proposal mechanism and draft depth. Fixed configurations cannot respond to changes in predictability, repetition, and acceptance during generation, so deeper drafting can increase wasted computation without proportional speedup. We introduce APEX, a learned controller that balances decoding speed and draft-token waste through request-level expert selection and block-level depth adaptation. APEX-Router selects among EAGLE-3, n-gram, and draft-model speculation for each request, while APEX-Depth adjusts draft length at each verification block using causal decoding signals and recent verifier feedback. APEX models accepted draft length as censored survival feedback, learning position-wise rejection hazards, block execution costs, and an action utility that balances throughput, accepted progress, and wasted tokens. This allows the controller to adapt speculation while retaining the target model's verification procedure. We integrate APEX into vLLM and evaluate it with Qwen3-8B across six workloads, achieving up to 5.24X speedup over autoregressive decoding. Across the aggregate evaluation, APEX-S achieves 4.27X speedup, while APEX-B achieves 3.27X speedup with a 41.0% relative reduction in wasted-token percentage compared with fixed n-gram speculation at k=16, providing distinct operating points for balancing acceleration and draft-token utilization.

## 1. 核心问题与整体含义

- **研究背景**：大语言模型在代码生成、数学推理、长文生成、对话等场景中广泛部署，推理延迟直接影响用户体验与部署可行性。
- **投机解码（Speculative Decoding, SD）**：用廉价机制先草拟多个 token，再由目标模型并行验证，从而减少目标模型串行调用次数。其收益取决于草稿机制与草稿深度。
- **核心痛点**：固定草稿配置无法适应生成过程中可预测性、重复性、接受率与执行成本的变化。更深的草稿可能提高单次验证的潜在进展，但早期拒绝会导致大量草稿 token 被丢弃，出现“速度未成比例提升、浪费显著增加”的问题。
- **论文主张**：不应一味加深推测，而应“更智能地推测”（Speculate smarter, not deeper）。需要联合考虑提议机制、草稿深度、验证反馈与运行成本，最大化单位成本下的已验证进展。
- **整体含义**：APEX 将投机解码视为可学习的在线控制问题：请求级选择专家，块级调整深度，在保持目标模型验证语义的前提下，提供速度与草稿 token 利用率之间的可调工作点。

## 2. 方法论

- **核心思想**：APEX 是分层学习型控制器，包含：
  - **APEX-Router**：请求开始时选择投机专家与初始草稿深度。
  - **APEX-Depth**：每个验证块后根据因果状态与验证器反馈动态调整深度。
- **候选专家**：EAGLE-3、n-gram SD、Draft-SD 三类机制。机制选定后在整个请求内固定，深度可逐块变化。
- **状态表示**：
  - 请求级状态 \(s_0\)：prompt 嵌入、prompt 长度、重复/词法结构特征、熵/分布特征、解码配置。
  - 块级状态 \(s_t\)：请求级信息、生成进度、历史验证反馈 \(h_{t-1}\)、当前前缀统计 \(g_t\)。特征均为因果特征，不使用当前块结果预测当前块。
- **接受长度建模为删失生存反馈**：
  - 对草稿长度 \(k\)，定义首次拒绝位置 \(J_t\)。若 \(J_t \le k\)，接受长度为 \(J_t-1\)；若 \(J_t>k\)，整块接受，接受长度为 \(k\)，属于右删失。
  - 学习逐位置拒绝风险 \(\hat q_{t,j}(k)=P(J_t=j \mid J_t\ge j, s_t,m,k)\)。
  - 生存概率 \(\hat S_{t,j}(k)=\prod_{i=1}^j(1-\hat q_{t,i}(k))\)，期望接受长度 \(\hat E[L_t]=\sum_{j=1}^k \hat S_{t,j}(k)\)。
  - 对部分接受和全接受分别构造似然，全接受只提供“存活到 k”的证据，不强行假设 k+1 处拒绝。
- **APEX-Depth 多任务预测头**：
  - **Survival head**：预测逐位置拒绝风险，用删失似然训练。
  - **Cost head**：预测块执行 log 延迟，包括草拟与验证成本。
  - **Throughput head**：预测 \(\log(1+\text{TPS})\)。
  - **Utility head**：预测动作效用，用于部署时选择深度。
- **训练目标**：
  - 从离线投机解码 trace 中构造监督。观测块为 \((s_t,m_t,k_t)\rightarrow(L_t,R_t,W_t,C_t,\text{TPS}_t)\)。
  - 块级效用标签：  
    \(u_{D,t}=\log(\text{TPS}_t)+\alpha_A\log(L_t+\epsilon)-\alpha_W W_t-\alpha_G G_t-\alpha_M M_t\)。  
    其中 \(W_t\) 为浪费比例，\(G_t\)、\(M_t\) 分别为跨机制与同机制下相对最佳观测吞吐的归一化 regret。
  - 总损失：生存损失、成本损失、吞吐损失、效用回归损失、候选排序损失加权组合。默认权重为 \((1.00,0.20,0.30,1.00,1.00)\)。
- **三种操作 profile**：
  - APEX-S：偏速度，强调吞吐竞争力。
  - APEX-B：平衡速度、接受进展与浪费。
  - APEX-E：偏效率，加大浪费惩罚。但论文指出权重不保证其始终最低浪费。
- **在线部署流程**：
  - Router 用 \(s_0\) 对 \((m,k_0)\) 打分，选最高分动作；机制固定。
  - 第一个块使用初始深度 \(k_0^*\)。
  - 之后每个块用 APEX-Depth 对候选深度打分，选 utility 最高者。
  - 执行 SpeculateAndVerify，得到输出与观测，更新历史状态；网络参数推理时固定。
